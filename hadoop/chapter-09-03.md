# §9.3 Экспорт из HDFS в БД

В [§9.2](chapter-09-02.md) мы разобрали импорт данных из реляционной БД в HDFS. **Экспорт** — обратное направление: чтение данных из файлов в HDFS и **запись в таблицу целевой БД**. Используется для загрузки результатов обработки (агрегаты, витрины, отчёты) в операционную БД или в хранилище отчётности. В этом разделе — команда **sqoop export**, указание каталога в HDFS и целевой таблицы, **соответствие столбцов** и формата файлов, при необходимости режим обновления. Связь с Hive и Oozie — в [§9.4](chapter-09-04.md). См. [Глоссарий](glossary.md).

---

## 9.3.1. Базовая команда sqoop export

Экспорт выполняется командой **sqoop export**. Обязательные параметры: **подключение к БД** (--connect, --username, --password), **каталог в HDFS** с исходными файлами (--export-dir) и **целевая таблица** (--table). Sqoop читает файлы из каталога (параллельно мапперами), парсит строки по разделителям и вставляет записи в таблицу через JDBC. См. [Глоссарий](glossary.md).

Пример:

```bash
sqoop export \
  --connect jdbc:mysql://dbhost:3306/reports \
  --username user \
  --password pass \
  --table daily_agg \
  --export-dir /data/output/agg \
  -m 4
```

- **--export-dir** — каталог в HDFS, из которого читаются файлы (обычно результат предыдущего шага пайплайна: Hive INSERT, Pig STORE, MapReduce output). Читаются все файлы в каталоге (в т.ч. в подкаталогах, если не задано иначе).
- **--table** — имя таблицы в БД; таблица должна существовать, схема (столбцы и типы) должна соответствовать данным в файлах.
- **-m** — число мапперов; каждый маппер читает часть файлов и выполняет INSERT в БД (batch insert для снижения числа round-trip).

По умолчанию Sqoop ожидает текстовые файлы с полями, разделёнными запятой; если формат другой, нужно указать разделители (см. ниже).

## 9.3.2. Соответствие столбцов и формат файлов

Порядок полей в файлах HDFS должен соответствовать порядку столбцов в таблице БД (или нужно явно задать соответствие). Sqoop по умолчанию подставляет значения из полей файла в INSERT в том порядке, в каком столбцы объявлены в метаданных таблицы. Если в файле столбцов меньше или порядок другой, задаётся **--columns** — список столбцов таблицы в нужном порядке; поля файла сопоставляются с этим списком по позиции. См. [Глоссарий](glossary.md).

Пример (в файле три поля: user_id, date, total; в таблице те же столбцы):

```bash
sqoop export --connect ... --table daily_agg --export-dir /data/output/agg \
  --columns "user_id,dt,total"
```

**Формат файлов:** по умолчанию поля разделены запятой. Если при записи в HDFS использовался другой разделитель (например, табуляция в Hive), нужно указать:

- **--input-fields-terminated-by '\t'** — разделитель полей;
- **--input-lines-terminated-by** — разделитель строк (по умолчанию \n).

Иначе Sqoop неправильно разобьёт строки и возможны ошибки вставки или неверные данные.

## 9.3.3. Режимы: INSERT и UPDATE

По умолчанию Sqoop выполняет **INSERT**: каждая строка из файла превращается в новую запись в таблице. Подходит для загрузки снимка агрегатов в пустую или дополняемую таблицу. См. [Глоссарий](glossary.md).

Режим **update** (обновление существующих строк по ключу) задаётся опцией **--update-key**: указывается столбец (или список столбцов), по которому определяется строка для обновления. Sqoop тогда генерирует UPDATE вместо INSERT для строк с совпадающим ключом (поведение может отличаться в зависимости от версии: update-only или insert-or-update). Пример:

```bash
sqoop export --connect ... --table daily_agg --export-dir /data/output/agg \
  --update-key user_id,dt
```

Если таблица имеет первичный ключ (user_id, dt), то при совпадении ключа строка обновляется, иначе вставляется новая (при поддержке **--update-mode allowinsert**). Использование update увеличивает нагрузку на БД (поиск по ключу для каждой строки или батча).

## 9.3.4. Транзакции и целостность

Экспорт выполняется мапперами параллельно; каждый маппер открывает своё соединение с БД и вставляет батчи. По умолчанию коммит происходит по батчу (или по числу строк); при сбое части мапперов в таблице могут оказаться частичные данные. Для критичных загрузок целевая таблица часто создаётся пустой или очищается перед экспортом (отдельным шагом или скриптом), а экспорт пишет полный снимок за период. Либо экспорт пишет во временную таблицу, после успешного завершения данные переносятся в основную (переименование таблиц или INSERT ... SELECT в одной транзакции на стороне БД). См. [Глоссарий](glossary.md).

Опция **--staging-table** позволяет писать во временную таблицу, а затем копировать данные в целевую одной операцией на стороне БД, что уменьшает окно неконсистентности.

## 9.3.5. Типичные ошибки при экспорте

- **Несовпадение формата:** разделители в файлах не указаны (--input-fields-terminated-by), поля «склеиваются» или смещаются — неверные значения в БД или ошибки приведения типов.
- **Несовпадение числа/порядка столбцов:** в файле больше или меньше полей, чем в таблице, или порядок другой — задать --columns или привести вывод предыдущего шага (Hive, Pig) к нужной схеме.
- **Целевая таблица не создана:** таблица должна существовать; типы столбцов должны допускать вставку (даты, числа, строки в ожидаемом формате).
- **Дубликаты по первичному ключу:** при INSERT в таблицу с PK повторное значение ключа даёт ошибку; решают очисткой таблицы перед экспортом, записью во временную таблицу без PK или использованием update-mode.

---

## Ключевое

- **sqoop export** — загрузка данных из каталога HDFS в таблицу БД: --connect, --table, --export-dir, -m.
- **Столбцы:** порядок полей в файлах должен соответствовать столбцам таблицы; при необходимости --columns; разделители — --input-fields-terminated-by, --input-lines-terminated-by.
- **Режимы:** по умолчанию INSERT; --update-key для обновления по ключу; при необходимости --update-mode allowinsert.
- **Целостность:** учёт параллельной записи и сбоев; временная таблица (--staging-table) или полная перезапись целевой таблицы за период.
