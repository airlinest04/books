# §6.4 DML в Hive: запросы и загрузка данных

В [§6.3](chapter-06-03.md) мы разобрали DDL — создание таблиц с заданной схемой, форматом и партициями. **DML** (Data Manipulation Language) в Hive — выборка данных (SELECT), соединения (JOIN), агрегация и **загрузка** данных в таблицы (LOAD, INSERT). В этом разделе — основные конструкции запросов, загрузка из HDFS и результат запроса в таблицу, а также **просмотр плана выполнения** и логи. Партиционирование и загрузка в партиции — в [§6.5](chapter-06-05.md). См. [Глоссарий](glossary.md).

---

## 6.4.1. SELECT: выборка и фильтрация

**SELECT** возвращает набор строк из одной или нескольких таблиц. Базовый вид:

```sql
SELECT [ALL | DISTINCT] столбец1, столбец2, ...
FROM таблица [псевдоним]
[WHERE условие]
[GROUP BY столбцы]
[HAVING условие_по_агрегатам]
[ORDER BY столбец [ASC | DESC], ...]
[LIMIT N];
```

- **Список столбцов** — перечисление полей или выражения (например, `event_type, COUNT(*)` при группировке). `*` — все столбцы таблицы.
- **WHERE** — фильтр по строкам до группировки; выполняется на уровне чтения данных (при поддержке формата — предикат pushdown, [§5.3](chapter-05-03.md)); для партиционированных таблиц условие по столбцу партиции отсекает целые партиции (partition pruning).
- **ORDER BY** — сортировка результата; на больших объёмах может приводить к одному Reduce-заданию и узкому месту; LIMIT ограничивает число строк в выводе.

Пример:

```sql
SELECT user_id, event_type, ts
FROM events
WHERE dt = '2024-01-15' AND event_type = 'click'
ORDER BY ts DESC
LIMIT 100;
```

Результат можно вывести в консоль (CLI, Beeline) или записать в таблицу/файл через INSERT (см. ниже).

## 6.4.2. JOIN и агрегация

**JOIN** соединяет строки двух (или более) таблиц по условию. В Hive поддерживаются INNER JOIN, LEFT/RIGHT/FULL OUTER JOIN, а также map-side join при подходящем размере одной из таблиц. Синтаксис:

```sql
SELECT ...
FROM таблица1 [AS a]
[JOIN | INNER JOIN | LEFT OUTER JOIN | ...] таблица2 [AS b] ON a.col = b.col
[WHERE ...];
```

Выполнение JOIN на больших таблицах — тяжёлая операция: данные перераспределяются по ключу соединения (shuffle); при неравномерном распределении ключей возможны перекос (data skew) и медленные задачи. Подробности оптимизации (размер таблиц, порядок джойнов) зависят от версии Hive и движка (Tez/Spark).

**Агрегация** — группировка и вычисление итогов по группам:

```sql
SELECT столбец_группы, SUM(столбец), COUNT(*), AVG(столбец)
FROM таблица
WHERE ...
GROUP BY столбец_группы
HAVING COUNT(*) > 10;
```

- **GROUP BY** — строки с одинаковым значением указанных столбцов объединяются в группу; в SELECT допустимы только столбцы группы и агрегатные функции (SUM, COUNT, AVG, MIN, MAX и т.д.).
- **HAVING** — фильтр по результатам агрегации (применяется после GROUP BY).

Такой запрос компилируется в план с этапами: чтение таблицы, (фильтр), группировка и агрегация (часто в Reduce), при необходимости сортировка и ограничение вывода.

## 6.4.3. Загрузка данных: LOAD DATA

Данные в таблицу можно загрузить **без преобразования формата** командой **LOAD DATA**: Hive перемещает или копирует файлы в каталог таблицы (или партиции) и регистрирует их в метаданных. Данные должны уже соответствовать схеме и формату таблицы (разделители для текста, структура для Parquet/ORC). См. [Глоссарий](glossary.md).

Синтаксис:

```sql
LOAD DATA [LOCAL] INPATH 'путь' [OVERWRITE] INTO TABLE таблица
[PARTITION (партиция1=значение1, ...)];
```

- **LOCAL** — путь на локальной файловой системе клиента; без LOCAL — путь в HDFS. При LOCAL файлы копируются в HDFS в каталог таблицы; при пути в HDFS по умолчанию файлы **перемещаются** (исходный каталог опустошается).
- **OVERWRITE** — перед загрузкой удалить существующие файлы в каталоге таблицы (или указанной партиции); без OVERWRITE данные добавляются к существующим.
- **PARTITION** — загрузка в конкретную партицию; партиция должна быть объявлена в таблице (PARTITIONED BY); при необходимости партиция создаётся.

Пример (файлы из HDFS в таблицу без партиций):

```sql
LOAD DATA INPATH '/data/landing/events_20240115.csv' OVERWRITE INTO TABLE events;
```

Пример с партицией:

```sql
LOAD DATA INPATH '/data/events/dt=2024-01-15/' INTO TABLE events_part PARTITION (dt='2024-01-15');
```

LOAD DATA не меняет формат данных: если таблица в формате TEXTFILE с разделителем табуляции, загружаемые файлы должны быть в том же формате.

## 6.4.4. Запись результата запроса: INSERT

Результат SELECT можно **записать в таблицу** (или в каталог в HDFS). Два основных варианта:

**INSERT OVERWRITE TABLE** — перезаписать целевую таблицу (или указанные партиции) результатом запроса. Существующие данные в целевой области удаляются.

```sql
INSERT OVERWRITE TABLE результат
SELECT user_id, event_type, COUNT(*) AS cnt
FROM events
WHERE dt = '2024-01-15'
GROUP BY user_id, event_type;
```

**INSERT INTO TABLE** — добавить строки к существующим данным в таблице (или в партиции); данные не удаляются.

Для партиционированных таблиц можно указывать партиции явно:

```sql
INSERT OVERWRITE TABLE events_agg PARTITION (dt='2024-01-15')
SELECT user_id, event_type, COUNT(*)
FROM events
WHERE dt = '2024-01-15'
GROUP BY user_id, event_type;
```

Множественная вставка (несколько INSERT из одного набора подзапросов) возможна через синтаксис `FROM ... INSERT OVERWRITE ... SELECT ... INSERT OVERWRITE ... SELECT ...` и уменьшает число проходов по исходным данным.

Формат и расположение целевой таблицы заданы при CREATE TABLE; INSERT пишет данные в каталог таблицы в этом формате (Parquet, ORC и т.д.).

## 6.4.5. Выполнение запроса и просмотр плана

После отправки запроса (в CLI или через Beeline) Hive компилирует его в план и запускает job на кластере (MapReduce, Tez или Spark). На экран выводятся логи запуска задач, прогресс и в конце — результат SELECT (если запрос — выборка) или сообщение о завершении загрузки/вставки.

**EXPLAIN** — вывод **логического плана** выполнения запроса без запуска job:

```sql
EXPLAIN SELECT user_id, COUNT(*) FROM events WHERE dt = '2024-01-15' GROUP BY user_id;
```

В выводе — дерево операторов (Scan, Filter, Group By, Reduce и т.д.). **EXPLAIN EXTENDED** даёт более подробный план с путями к данным и атрибутами операторов.

**EXPLAIN** помогает понять: какие таблицы и партиции читаются, есть ли фильтр по партиции, как устроены этапы Map/Reduce. Для анализа производительности также смотрят логи приложения на YARN (через веб-интерфейс ResourceManager или командой `yarn logs -applicationId <id>`) и время выполнения отдельных задач.

## 6.4.6. Типичные ошибки при DML

- **Несоответствие формата при LOAD:** загружаемые файлы должны соответствовать ROW FORMAT и типу таблицы (TEXTFILE и т.д.); иначе при чтении таблицы — ошибки парсинга или неверные данные.
- **INSERT в партицию без указания партиции:** для партиционированной таблицы при INSERT OVERWRITE/INTO в конкретную партицию нужно указывать PARTITION (col=value), иначе Hive может писать в каталог по умолчанию или потребуется динамическое партиционирование (включённое настройкой).
- **Игнорирование перекоса при JOIN/GROUP BY:** при сильном перекосе по ключу одна или несколько Reduce-задач обрабатывают большую часть данных; стоит смотреть на распределение ключей и при необходимости разбивать запрос или использовать техники снижения перекоса.

---

## Ключевое

- **SELECT** — выборка с WHERE, GROUP BY, HAVING, ORDER BY, LIMIT; JOIN и агрегация компилируются в план с Map/Reduce (или Tez/Spark).
- **LOAD DATA** — загрузка файлов из HDFS (или локально) в каталог таблицы/партиции без смены формата; OVERWRITE перезаписывает, PARTITION задаёт партицию.
- **INSERT OVERWRITE/INTO TABLE** — запись результата SELECT в таблицу; OVERWRITE заменяет данные, INTO добавляет; для партиционированных таблиц указывают PARTITION.
- **EXPLAIN** — просмотр плана без выполнения; логи YARN — для анализа времени выполнения и ошибок.

В [§6.5](chapter-06-05.md) разберём партиционирование и bucketing подробнее: как они ускоряют запросы и как загружать данные в партиции.
