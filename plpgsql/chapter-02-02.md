# §2.2 Объявление переменных

В [§2.1](chapter-02-01.md) мы разобрали структуру блока и место секции DECLARE. В этом разделе рассмотрим **объявление переменных** в DECLARE: общий синтаксис (имя, тип, начальное значение), типы данных PostgreSQL, используемые в PL/pgSQL, и специальные конструкции **%TYPE** (тип по столбцу или по переменной) и **%ROWTYPE** (переменная «строка таблицы»), а также тип **RECORD** для строк с неизвестной структурой. Присваивание и SELECT ... INTO — в [§2.3](chapter-02-03.md), константы и параметры — в [§2.4](chapter-02-04.md). См. [Глоссарий](glossary.md).

---

## 2.2.1. Общий синтаксис объявления

Все переменные, используемые в блоке, должны быть объявлены в секции DECLARE этого блока. Исключения: переменная цикла FOR по диапазону целых объявляется автоматически как integer; переменная цикла FOR по курсору — как record (подробнее гл. 3). См. [Глоссарий](glossary.md).

Общий синтаксис объявления переменной (по документации PostgreSQL):

```
имя [ CONSTANT ] тип [ COLLATE имя_сравнения ] [ NOT NULL ] [ { DEFAULT | := | = } выражение ];
```

- **имя** — идентификатор переменной (правила как в SQL: без кавычек приводится к нижнему регистру).
- **тип** — любой тип данных SQL, поддерживаемый PostgreSQL (integer, varchar(n), numeric(p,s), date, timestamp, jsonb и т.д.), или конструкция %TYPE, %ROWTYPE, или RECORD (см. ниже).
- **CONSTANT** — переменная не может быть изменена после присваивания начального значения; значение постоянно в пределах блока.
- **COLLATE** — задаёт правило сравнения для строковых типов; при необходимости см. документацию по collation.
- **NOT NULL** — присваивание NULL приводит к ошибке времени выполнения. Для переменной с NOT NULL обязательно задать ненулевое начальное значение (DEFAULT или :=).
- **DEFAULT**, **:=** или **=** — начальное значение; выражение вычисляется при **каждом входе в блок** (не один раз при компиляции). Если начальное значение не задано, переменная инициализируется SQL NULL.

Примеры:

```sql
quantity integer DEFAULT 32;
url varchar := 'http://mysite.com';
transaction_time CONSTANT timestamptz := now();
```

Знак `=` допустим наряду с `:=` для совместимости с PL/SQL.

## 2.2.2. Типы данных PostgreSQL в объявлениях

В DECLARE можно использовать **любой SQL-тип**, доступный в текущей базе: встроенные типы PostgreSQL и пользовательские типы (в том числе домены и составные типы). См. [Глоссарий](glossary.md).

Часто используемые встроенные типы:

| Тип | Описание | Пример объявления |
|-----|----------|-------------------|
| integer, bigint, smallint | Целые числа | `cnt integer;` |
| numeric(p,s), decimal(p,s) | Числа с заданной точностью | `amount numeric(10,2);` |
| real, double precision | Числа с плавающей точкой | `ratio double precision;` |
| varchar(n), char(n), text | Строки (text — без ограничения длины) | `name varchar(100);` `comment text;` |
| boolean | Логический тип | `flag boolean DEFAULT true;` |
| date, time, timestamp, timestamptz | Дата и время | `created_at timestamptz := now();` |
| json, jsonb | JSON | `payload jsonb;` |
| uuid | Уникальный идентификатор | `id uuid;` |

Имя типа задаётся так же, как в SQL (например, в CREATE TABLE). Для массивов после типа указывают `[]`, например `integer[]`, `text[]`. Пользовательские составные типы и домены используют имя типа; для строки таблицы удобно использовать %ROWTYPE (см. ниже).

## 2.2.3. %TYPE — тип по столбцу или по переменной

**%TYPE** позволяет объявить переменную с тем же типом, что у столбца таблицы (или представления), или у другой переменной. Синтаксис: `таблица.столбец%TYPE` или `переменная%TYPE`. См. [Глоссарий](glossary.md).

Пример по столбцу:

```sql
user_id users.user_id%TYPE;
email    users.email%TYPE;
```

Переменные `user_id` и `email` получают типы столбцов `user_id` и `email` таблицы `users`. Если в схеме изменится тип столбца (например, `user_id` станет bigint), перекомпилированная функция будет использовать новый тип без правки объявлений.

Пример по переменной (удобно в полиморфных функциях и когда тип сложный):

```sql
DECLARE
  first_val some_table.some_column%TYPE;
  second_val first_val%TYPE;  -- тот же тип, что у first_val
```

После %TYPE можно указать массив: `users.user_id%TYPE[]` — массив того же типа, что и столбец.

---

## 2.2.4. %ROWTYPE — переменная «строка таблицы»

**%ROWTYPE** задаёт тип переменной как **строка таблицы (или представления)**: переменная может хранить целую строку результата SELECT или цикла FOR. Синтаксис: `имя_таблицы%ROWTYPE` или имя составного типа. Отдельные поля доступны через точку: `переменная.имя_поля`. См. [Глоссарий](glossary.md).

Пример:

```sql
DECLARE
  rec users%ROWTYPE;
BEGIN
  SELECT * INTO rec FROM users WHERE id = 1;
  RAISE NOTICE 'Имя: %', rec.name;
  -- rec содержит все столбцы таблицы users
END;
```

Такая переменная имеет столько полей, сколько столбцов в таблице (или представлении); имена полей совпадают с именами столбцов. Форма с %ROWTYPE переносима и явно привязывает объявление к структуре таблицы; можно также использовать имя составного типа (в PostgreSQL у таблицы есть одноимённый составной тип). Для массивов строк: `users%ROWTYPE[]`.

## 2.2.5. RECORD — строка с неизвестной структурой

Переменная типа **RECORD** не имеет фиксированной структуры: она принимает структуру строки при присваивании (SELECT ... INTO, FETCH, цикл FOR по запросу). После присваивания к полям обращаются через точку. До первого присваивания структура неизвестна; обращение к полю до присваивания приводит к ошибке времени выполнения. См. [Глоссарий](glossary.md).

Пример:

```sql
DECLARE
  r RECORD;
BEGIN
  FOR r IN SELECT id, name FROM users LOOP
    RAISE NOTICE '%: %', r.id, r.name;
  END LOOP;
END;
```

RECORD удобен, когда одна и та же переменная может получать строки из разных запросов с разным набором столбцов. Тип RECORD — не тип в смысле каталога типов, а «заполнитель»; для возврата набора строк из функции с переменной структурой используется объявление RETURNS record у функции (гл. 5, 7).

## 2.2.6. Начальное значение и порядок объявлений

Начальное значение (DEFAULT или :=) вычисляется **при каждом входе в блок**, а не при создании функции. Например, `created timestamptz := now();` при каждом вызове функции даёт текущее время вызова.

В одном блоке объявления обрабатываются по порядку; в выражении начального значения можно ссылаться на **ранее объявленные в том же блоке** переменные:

```sql
DECLARE
  x integer := 1;
  y integer := x + 1;
BEGIN
  ...
END;
```

Так можно строить зависимости между начальными значениями. Порядок объявлений в DECLARE не должен создавать циклических зависимостей (например, a := b; b := a;).

Если ни DEFAULT, ни := не указаны, переменная инициализируется значением NULL (если тип не NOT NULL). Использование неинициализированной переменной в выражениях даёт NULL; в некоторых контекстах это может приводить к неочевидному поведению, поэтому явная инициализация часто предпочтительна.

---

## Ключевое

- Все переменные блока объявляются в DECLARE; синтаксис: **имя [ CONSTANT ] тип [ NOT NULL ] [ DEFAULT | := | = выражение ]**.
- Начальное значение вычисляется при каждом входе в блок; без него переменная инициализируется NULL (если допустимо).
- В объявлениях можно использовать **любые SQL-типы** PostgreSQL (integer, varchar(n), numeric, date, timestamptz, jsonb и т.д.).
- **%TYPE** — тип по столбцу (`таблица.столбец%TYPE`) или по переменной (`переменная%TYPE`); удобно для согласования с таблицей и при изменении схемы.
- **%ROWTYPE** — переменная «строка таблицы»; поля доступны как `переменная.поле`; подходит для SELECT * INTO и циклов по таблице.
- **RECORD** — строка без фиксированной структуры; структура определяется при присваивании; до присваивания обращение к полям даёт ошибку.

В [§2.3](chapter-02-03.md) мы разберём присваивание (:= и =) и выборку одной строки (SELECT ... INTO).
