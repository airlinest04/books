# §6.1 CREATE PROCEDURE

В [§5.6](chapter-05-06.md) мы завершили главу о функциях. С этой главы — **процедуры** в PostgreSQL: создание, OUT-параметры и транзакции внутри процедуры. В этом разделе разберём **CREATE PROCEDURE**: чем процедура отличается от функции (не возвращает значение в выражении), синтаксис создания и вызов оператором **CALL**. OUT-параметры и получение результатов вызова — в [§6.2](chapter-06-02.md), COMMIT/ROLLBACK внутри процедуры — в [§6.3](chapter-06-03.md). См. [Глоссарий](glossary.md).

---

## 6.1.1. Процедура и функция: главное отличие

**Функция** (CREATE FUNCTION) возвращает одно значение или набор строк; её вызывают **в выражении** (в SELECT, в условии WHERE, в присваивании). **Процедура** (CREATE PROCEDURE) **не возвращает значение в выражении**: её нельзя подставить в SELECT или в правую часть присваивания. Процедуру вызывают отдельным оператором **CALL**. См. [Глоссарий](glossary.md).

По документации PostgreSQL процедура может иметь **OUT**- и **INOUT**-параметры; при вызове CALL возвращается одна строка с значениями этих параметров. Таким образом, «возврат» из процедуры — через выходные параметры, а не через RETURNS. Для логики без возвращаемого значения (например, массовое обновление, отправка уведомления) процедура подходит так же, как функция с RETURNS void; различие в способе вызова: CALL вместо SELECT.

---

## 6.1.2. Синтаксис CREATE PROCEDURE

Команда **CREATE PROCEDURE** определяет процедуру в текущей схеме (или в указанной). Синтаксис (сокращённо по документации PostgreSQL):

```
CREATE [ OR REPLACE ] PROCEDURE имя
  ( [ [ argmode ] [ argname ] argtype [ { DEFAULT | = } выражение ] [, ...] ] )
  LANGUAGE lang_name
  AS 'определение'
```

**OR REPLACE** — замена существующей процедуры с тем же именем и типами аргументов; имя и типы аргументов при замене менять нельзя. Владелец и права сохраняются. См. [Глоссарий](glossary.md).

У процедуры **нет предложения RETURNS**: возвращаемый тип не задаётся. Режимы параметров: **IN** (по умолчанию), **OUT**, **INOUT**, **VARIADIC** — как у функций ([§5.2](chapter-05-02.md)). Язык для PL/pgSQL: **LANGUAGE plpgsql**. Определение — строка с телом (один блок PL/pgSQL); обычно **AS $$ ... $$** (долларовые кавычки). Допустимы **SECURITY INVOKER** / **SECURITY DEFINER** и **SET** параметров; нюансы для SECURITY DEFINER и транзакций — в [§5.6](chapter-05-06.md) и [§6.3](chapter-06-03.md).

## 6.1.3. Пример процедуры на PL/pgSQL

Процедура без выходных параметров: выполняет действия (например, логирование или обновление таблицы) и завершается. Вызов — только через CALL.

```sql
CREATE PROCEDURE cleanup_old_logs()
LANGUAGE plpgsql
AS $$
BEGIN
  DELETE FROM app.event_log WHERE created_at < current_date - interval '90 days';
  RAISE NOTICE 'Old logs deleted.';
END;
$$;
```

Вызов:

```sql
CALL cleanup_old_logs();
```

Процедура выполняется в текущей транзакции; при необходимости COMMIT/ROLLBACK внутри процедуры см. [§6.3](chapter-06-03.md). См. [Глоссарий](glossary.md).

---

## 6.1.4. Вызов процедуры: CALL

Оператор **CALL** выполняет процедуру (по документации PostgreSQL):

```
CALL имя_процедуры ( [ аргумент [, ...] ] )
```

Имя может быть квалифицировано схемой. Аргументы передаются по позиции или по имени (`имя => значение`), как при вызове функции. Для всех параметров без значения по умолчанию (включая OUT) нужно указать аргумент; для OUT при вызове обычно передают **NULL** (значение не используется, слот нужен для совместимости с синтаксисом). Получение значений OUT при вызове из PL/pgSQL — в [§6.2](chapter-06-02.md). См. [Глоссарий](glossary.md).

Право на вызов: у вызывающего должна быть привилегия **EXECUTE** на процедуру. Вызывать функцию оператором CALL нельзя; функцию вызывают через SELECT или в выражении.

---

## Ключевое

- **Процедура** не возвращает значение в выражении; её вызывают оператором **CALL**, а не SELECT.
- **CREATE PROCEDURE** — имя, параметры (IN/OUT/INOUT), LANGUAGE plpgsql, AS $$ тело $$; предложения RETURNS нет.
- **CALL имя(аргументы)** — выполнение процедуры; при наличии OUT возвращается строка с их значениями; для OUT в списке аргументов обычно передают NULL.
- Для логики без возвращаемого значения процедура и функция с RETURNS void близки по смыслу; различие — синтаксис вызова (CALL vs SELECT).

В [§6.2](chapter-06-02.md) разберём **OUT-параметры процедур**: объявление, присваивание в теле и получение результатов при вызове CALL (в том числе из блока PL/pgSQL).
