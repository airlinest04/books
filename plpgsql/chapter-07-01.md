# §7.1 Выполнение одного запроса

В [§6.3](chapter-06-03.md) мы завершили главу о процедурах. Глава 7 посвящена **работе с SQL внутри PL/pgSQL**: выполнение запросов, курсоры, динамический SQL и возврат наборов из функций. В этом разделе — **выполнение одного запроса**: напоминание о **SELECT ... INTO** и DML с RETURNING INTO ([§2.3](chapter-02-03.md)), выполнение DML **без** RETURNING (INSERT, UPDATE, DELETE) и получение **количества затронутых строк** через **GET DIAGNOSTICS** и переменную **FOUND**. Выполнение запроса без сохранения результата — **PERFORM**. Курсоры и циклы по наборам строк — в [§7.2](chapter-07-02.md), динамический SQL — в [§7.3](chapter-07-03.md). См. [Глоссарий](glossary.md).

---

## 7.1.1. SELECT ... INTO и DML с RETURNING INTO (кратко)

Когда нужно **получить одну строку** результата в переменные, в PL/pgSQL используется **SELECT ... INTO** (и аналогично **INSERT/UPDATE/DELETE/MERGE ... RETURNING ... INTO**). Синтаксис, STRICT, поведение при нуле и нескольких строках и переменная **FOUND** разобраны в [§2.3](chapter-02-03.md). Напоминание: цель — переменная записи, переменная строки или список переменных; без STRICT в переменные попадает первая строка или NULL; FOUND показывает, была ли присвоена хотя бы одна строка. См. [Глоссарий](glossary.md).

В этом разделе акцент — на случаях, когда **результат запроса не нужен**: выполнить запрос «ради эффекта» или проверить наличие строк, а также получить **число затронутых строк** после DML.

---

## 7.1.2. PERFORM — выполнить запрос и отбросить результат

Если нужно **выполнить запрос, возвращающий строки, но не сохранять результат** (например, проверить существование строки или вызвать функцию с побочным эффектом), в PL/pgSQL используют **PERFORM** (по документации PostgreSQL, раздел 41.5.2). Пишут запрос как обычный SELECT, но вместо ключевого слова **SELECT** подставляют **PERFORM**. Запрос выполняется, результат отбрасывается. Переменная **FOUND** устанавливается в true, если была получена хотя бы одна строка, и в false, если строк не было. См. [Глоссарий](glossary.md).

Пример: проверка существования записи перед вставкой:

```sql
PERFORM 1 FROM users WHERE login = p_login;
IF FOUND THEN
  RAISE EXCEPTION 'Логин % уже занят', p_login;
END IF;
INSERT INTO users (login, name) VALUES (p_login, p_name);
```

Для запросов WITH (CTE) используют **PERFORM** и заключают запрос в скобки; в этом случае запрос может вернуть не более одной строки. Один только SELECT без INTO в теле функции/процедуры не допускается — PL/pgSQL выдаст ошибку; допустимы только SELECT ... INTO или PERFORM.

---

## 7.1.3. Выполнение DML без RETURNING

Команды **INSERT**, **UPDATE**, **DELETE** и **MERGE** без предложения RETURNING **не возвращают строк**; их можно писать в теле PL/pgSQL как обычные SQL-команды (по документации PostgreSQL, раздел 41.5.2). Подстановка переменных PL/pgSQL в команду выполняется автоматически. После выполнения такой команды можно узнать, затронута ли хотя бы одна строка, по переменной **FOUND** (true — да, false — нет) и **количество затронутых строк** — через **GET DIAGNOSTICS** (раздел 41.5.5). См. [Глоссарий](glossary.md).

Пример:

```sql
UPDATE orders SET status = 'shipped' WHERE id = p_order_id;
IF NOT FOUND THEN
  RAISE EXCEPTION 'Заказ % не найден', p_order_id;
END IF;
```

Здесь FOUND достаточно для проверки «был ли обновлён хотя бы один ряд». Когда нужно именно **число** строк (например, для логирования или ветвления по количеству), сразу после DML вызывают **GET DIAGNOSTICS** и сохраняют **ROW_COUNT** в переменную.

---

## 7.1.4. GET DIAGNOSTICS и ROW_COUNT

Команда **GET DIAGNOSTICS** (или GET CURRENT DIAGNOSTICS) возвращает **текущие** показатели выполнения последней SQL-команды в этом блоке. Синтаксис (по документации PostgreSQL):

```
GET [ CURRENT ] DIAGNOSTICS переменная { = | := } элемент [ , ... ];
```

Один из элементов — **ROW_COUNT** (тип bigint): **число строк, обработанных последней SQL-командой** (SELECT INTO, INSERT, UPDATE, DELETE, MERGE, FETCH и т.д.). Значение нужно сохранить в переменную сразу после выполнения команды, потому что следующая SQL-команда перезапишет это значение. См. [Глоссарий](glossary.md).

Пример:

```sql
DECLARE
  updated_count bigint;
BEGIN
  UPDATE items SET stock = stock - p_qty WHERE id = p_item_id AND stock >= p_qty;
  GET DIAGNOSTICS updated_count = ROW_COUNT;
  IF updated_count = 0 THEN
    RAISE EXCEPTION 'Товар % не найден или недостаточно на складе', p_item_id;
  END IF;
  -- ...
END;
```

Кроме ROW_COUNT, GET DIAGNOSTICS может возвращать, например, **PG_CONTEXT** (текст стека вызовов) и **PG_ROUTINE_OID**. Не путать с **GET STACKED DIAGNOSTICS**, который используется в обработчике EXCEPTION для получения данных об ошибке ([§4.3](chapter-04-03.md)).

---

## Ключевое

- **SELECT ... INTO** и **DML ... RETURNING ... INTO** для одной строки результата — см. [§2.3](chapter-02-03.md).
- **PERFORM** — выполнить запрос (как SELECT) и отбросить результат; **FOUND** показывает, была ли хотя бы одна строка.
- **INSERT/UPDATE/DELETE/MERGE** без RETURNING выполняются как обычные команды; **FOUND** — true, если затронута хотя бы одна строка.
- **GET DIAGNOSTICS** переменная = **ROW_COUNT** — число строк, обработанных последней SQL-командой; вызывать сразу после команды.

В [§7.2](chapter-07-02.md) разберём **курсоры**: объявление CURSOR, OPEN, FETCH, CLOSE и цикл FOR по курсору для построчной обработки результата запроса.
