# §2.3 Присваивание

В [§2.2](chapter-02-02.md) мы разобрали объявление переменных в DECLARE. В этом разделе рассмотрим **присваивание** значений переменным: оператор присваивания (:= и =), приведение типов при присваивании и **SELECT ... INTO** для записи одной строки результата запроса в переменные. Динамический SQL (EXECUTE ... INTO) и циклы по набору строк — в гл. 7 и 3; здесь — только статический запрос с одним результатом. Константы и параметры — в [§2.4](chapter-02-04.md). См. [Глоссарий](glossary.md).

---

## 2.3.1. Оператор присваивания := и =

Присваивание значения переменной PL/pgSQL записывается так (по документации PostgreSQL):

```
переменная { := | = } выражение;
```

Выражение вычисляется (через внутренний SQL SELECT) и должно давать одно значение; при присваивании в переменную строки или записи — составное значение. Целевая **переменная** может быть: простая переменная (при необходимости с квалификатором метки блока), поле строки или записи (`переменная_строки.поле`), элемент или срез массива (`массив[индекс]`, `массив[низ:верх]`). Знак **=** допустим вместо **:=** для совместимости с PL/SQL. См. [Глоссарий](glossary.md).

Примеры:

```sql
tax := subtotal * 0.06;
my_record.user_id := 20;
my_array[j] := 20;
my_array[1:3] := ARRAY[1, 2, 3];
```

Присваивание выполняется в порядке операторов: каждое следующее присваивание перезаписывает значение переменной. Переменная с атрибутом CONSTANT не может быть целью присваивания после инициализации в DECLARE.

---

## 2.3.2. Приведение типа при присваивании

Если тип результата выражения не совпадает с типом переменной, PostgreSQL пытается привести значение к типу переменной. Сначала используется **присваивающее приведение** (assignment cast), если оно определено для пары типов. Если нет — интерпретатор PL/pgSQL пробует **текстовое преобразование**: вывод результата в строку (output-функция типа результата) и ввод строки в тип переменной (input-функция типа переменной). Если строка недопустима для типа переменной, возникает ошибка времени выполнения. См. документацию PostgreSQL, раздел 10.4 (Type Conversion).

Поэтому присваивание, например, `integer` в `numeric` или `text` в `varchar(n)` обычно выполняется без явного приведения; при несовместимых типах может потребоваться явный CAST или оператор приведения `::`.

## 2.3.3. SELECT ... INTO — одна строка в переменные

Когда нужно сохранить **результат запроса, возвращающий не более одной строки**, в PL/pgSQL используется форма **SELECT ... INTO** (и аналогично для других команд с RETURNING). Запрос пишется как обычный SQL, но добавляется предложение **INTO** с целью: переменная записи (RECORD), переменная строки (%ROWTYPE) или список скалярных переменных и полей записи через запятую. См. [Глоссарий](glossary.md).

Синтаксис (по документации PostgreSQL):

```sql
SELECT список_выражений INTO [ STRICT ] цель FROM ...;
INSERT ... RETURNING ... INTO [ STRICT ] цель;
UPDATE ... RETURNING ... INTO [ STRICT ] цель;
DELETE ... RETURNING ... INTO [ STRICT ] цель;
MERGE ... RETURNING ... INTO [ STRICT ] цель;
```

**Цель (target)** — одна переменная записи/строки или список переменных. Количество и типы столбцов результата должны соответствовать цели: при списке переменных — по порядку и по типам; при переменной RECORD структура подстраивается под результат автоматически; при переменной %ROWTYPE структура должна совпадать с таблицей запроса.

Пример с одной переменной и списком переменных:

```sql
DECLARE
  user_id integer;
  user_name text;
  rec users%ROWTYPE;
BEGIN
  SELECT id, name INTO user_id, user_name FROM users WHERE id = 1;
  -- или вся строка в запись:
  SELECT * INTO rec FROM users WHERE id = 1;
END;
```

INTO можно размещать в разных местах команды (например, сразу после списка выражений в SELECT или в конце команды); рекомендуется придерживаться общепринятого порядка: в SELECT — после списка выражений или в конце, в RETURNING — в конце. Подробнее о RETURNING INTO — в следующем подразделе.

## 2.3.4. Поведение при отсутствии строк и при нескольких строках. STRICT и FOUND

Без ключевого слова **STRICT** в INTO: запрос может вернуть ноль, одну или несколько строк. В переменные попадает **первая строка** (если строк нет — в цель записываются NULL). Остальные строки игнорируются. Узнать, была ли возвращена хотя бы одна строка, можно по специальной переменной **FOUND**: после SELECT ... INTO она устанавливается в true, если строка была присвоена, и в false, если строк не было. См. [Глоссарий](glossary.md).

Пример проверки через FOUND:

```sql
SELECT * INTO myrec FROM emp WHERE empname = myname;
IF NOT FOUND THEN
  RAISE EXCEPTION 'Сотрудник % не найден', myname;
END IF;
```

Если указан **STRICT** (INTO STRICT цель), команда **обязана** вернуть ровно одну строку. Иначе возникает ошибка: **NO_DATA_FOUND** при отсутствии строк или **TOO_MANY_ROWS** при двух и более строках. Эти ошибки можно перехватить в блоке EXCEPTION (гл. 4):

```sql
BEGIN
  SELECT * INTO STRICT myrec FROM emp WHERE empname = myname;
EXCEPTION
  WHEN NO_DATA_FOUND THEN
    RAISE EXCEPTION 'Сотрудник % не найден', myname;
  WHEN TOO_MANY_ROWS THEN
    RAISE EXCEPTION 'Сотрудник % не единственный', myname;
END;
```

При успешном выполнении команды с STRICT переменная FOUND устанавливается в true. STRICT соответствует поведению SELECT INTO в Oracle PL/SQL.

Для **INSERT/UPDATE/DELETE/MERGE** с RETURNING INTO при возврате более одной строки PL/pgSQL выдаёт ошибку даже без STRICT (нет неоднозначности «какую строку взять», как при SELECT без ORDER BY).

## 2.3.5. INSERT, UPDATE, DELETE, MERGE с RETURNING INTO

Команды **INSERT**, **UPDATE**, **DELETE** и **MERGE** могут возвращать строки с помощью предложения **RETURNING**. В PL/pgSQL к такой команде добавляется **INTO** (и при необходимости **STRICT**), и результат одной строки записывается в указанные переменные. См. [Глоссарий](glossary.md).

Пример:

```sql
INSERT INTO logs (action, created_at)
VALUES ('login', now())
RETURNING id, created_at INTO new_id, created_ts;
```

Если RETURNING возвращает несколько строк (например, при массовом INSERT с RETURNING), движок выдаёт ошибку: в INTO можно принять только одну строку. Для обработки нескольких строк используется цикл FOR по запросу (гл. 3, 7).

---

## 2.3.6. Замечание: SELECT INTO в PL/pgSQL и в SQL

В обычном SQL команда **SELECT INTO** в PostgreSQL создаёт **новую таблицу** по результату запроса (результат запроса сохраняется как таблица). В PL/pgSQL **SELECT ... INTO** всегда трактуется как присваивание в переменные: INTO указывает на переменные блока, а не на таблицу. Если внутри функции или процедуры нужно создать таблицу по результату SELECT, используйте **CREATE TABLE ... AS SELECT** (или эквивалент), а не SELECT INTO. См. документацию PostgreSQL, раздел 41.5.3.

---

## Ключевое

- **Присваивание:** `переменная := выражение` или `= выражение`; цель — простая переменная, поле записи/строки, элемент или срез массива.
- При несовпадении типов выполняется приведение (assignment cast или текстовое преобразование); при несовместимости возможна ошибка или нужен явный CAST.
- **SELECT ... INTO цель** — результат запроса (одна строка) записывается в переменную записи, переменную строки или список переменных; то же для **INSERT/UPDATE/DELETE/MERGE ... RETURNING ... INTO**.
- Без **STRICT**: берётся первая строка или NULL при отсутствии строк; **FOUND** показывает, была ли присвоена строка.
- С **STRICT**: при нуле или более одной строки — ошибки NO_DATA_FOUND или TOO_MANY_ROWS; удобно для строгой проверки «ровно одна строка».
- В PL/pgSQL SELECT INTO всегда означает присваивание в переменные; для создания таблицы из SELECT используйте CREATE TABLE ... AS SELECT.
