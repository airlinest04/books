# §5.4 VOLATILITY и параллелизм

В [§5.3](chapter-05-03.md) мы разобрали RETURN и возврат набора строк. В этом разделе рассмотрим атрибуты функции, влияющие на **оптимизатор** и **параллельное выполнение** запросов: **VOLATILE**, **STABLE**, **IMMUTABLE** (категории изменчивости) и **PARALLEL** (допустимость выполнения в параллельных воркерах). Вызов функции — в [§5.5](chapter-05-05.md), SECURITY DEFINER — в [§5.6](chapter-05-06.md). См. [Глоссарий](glossary.md).

---

## 5.4.1. Зачем нужны категории изменчивости

Оптимизатор PostgreSQL должен решать: можно ли заменить несколько вызовов функции одним, вычислить функцию один раз при константных аргументах, использовать результат в условиях индекса и т.д. Для этого он опирается на **категорию изменчивости (volatility)** функции. Если функция объявлена строже, чем ведёт себя на самом деле, возможны неверные результаты; если мягче — теряются оптимизации. См. [Глоссарий](glossary.md).

Указывается не более одной из трёх: **VOLATILE**, **STABLE**, **IMMUTABLE**. Если ни одна не указана, по умолчанию принимается **VOLATILE**.

---

## 5.4.2. IMMUTABLE

**IMMUTABLE** означает: функция **не изменяет базу данных** и при **одинаковых аргументах всегда возвращает один и тот же результат** — не использует данные из таблиц, текущее время, настройки сессии и т.п. Только аргументы влияют на результат. См. [Глоссарий](glossary.md).

При таких условиях оптимизатор может **подставить результат заранее**, если аргументы — константы: вызов с константами вычисляется один раз (при планировании или при первом обращении), а не при каждой строке. Пример: функция `add(a int, b int) RETURN a + b` — IMMUTABLE; в запросе `WHERE x = add(1, 2)` выражение может быть заменено на `WHERE x = 3`.

**Ошибка** — пометить как IMMUTABLE функцию, которая обращается к таблицам или вызывает now(), random() и т.д.: оптимизатор может закэшировать «результат» и вернуть неверные данные.

---

## 5.4.3. STABLE

**STABLE** означает: функция **не изменяет базу данных** и в пределах **одной команды** (одного скана) при одинаковых аргументах возвращает один и тот же результат. Между разными командами или разными строками результат может меняться (например, из-за now(), current_user, чтения таблиц). См. [Глоссарий](glossary.md).

Оптимизатор может **свести несколько вызовов с одинаковыми аргументами к одному** в рамках одной команды; функцию допустимо использовать в условиях индекса (например, в WHERE). Примеры: функции, читающие таблицы по аргументу; функции, использующие current_timestamp (в одной транзакции значение не меняется в рамках одной команды). Для триггеров AFTER, которые обращаются к изменённым строкам, STABLE может быть неуместен — см. документацию.

---

## 5.4.4. VOLATILE

**VOLATILE** (по умолчанию) означает: результат может **меняться от вызова к вызову** даже при одинаковых аргументах и в пределах одной команды — например, random(), currval(), timeofday(), или любая функция с побочными эффектами (запись в БД, setval()). См. [Глоссарий](glossary.md).

Оптимизатор **не** объединяет вызовы и **не** выносит вычисление «за скобки»; функция выполняется каждый раз, когда её результат нужен. Любая функция с побочными эффектами должна быть помечена VOLATILE, иначе оптимизатор может «выкинуть» вызовы. Для PL/pgSQL-функций по умолчанию принимается VOLATILE — безопасный выбор, если вы не уверены.

## 5.4.5. PARALLEL — безопасность для параллельных запросов

Отдельно от изменчивости задаётся **допустимость выполнения в параллельных воркерах** (параллельные планы запросов). Атрибут **PARALLEL** (по документации PostgreSQL):

- **PARALLEL UNSAFE** (по умолчанию для пользовательских функций) — функция не должна выполняться в параллельном воркере; при её использовании параллельный план для запроса может быть запрещён.
- **PARALLEL RESTRICTED** — функция может выполняться только в процессе-лидере параллельной группы, не в воркерах (например, доступ к временным таблицам, курсорам, состоянию сессии).
- **PARALLEL SAFE** — функцию можно выполнять в воркерах без ограничений.

Функции, которые изменяют БД, меняют состояние транзакции, обращаются к последовательностям (currval и т.д.) или к настройкам, должны быть **PARALLEL UNSAFE**. Функции, использующие временные таблицы, состояние соединения, курсоры, — как минимум **PARALLEL RESTRICTED**. Только «чистые» функции без такого доступа можно пометить PARALLEL SAFE для максимального параллелизма. См. [Глоссарий](glossary.md).

Пример указания в CREATE FUNCTION:

```sql
CREATE FUNCTION my_func(x int) RETURNS int
AS $$ ... $$ LANGUAGE plpgsql
STABLE
PARALLEL SAFE;
```

---

## Ключевое

- **IMMUTABLE** — не меняет БД, один и тот же результат при одних и тех же аргументах всегда; оптимизатор может подставлять результат при константных аргументах.
- **STABLE** — не меняет БД, один и тот же результат в пределах одной команды при одних аргументах; можно объединять вызовы в команде и использовать в условиях индекса.
- **VOLATILE** (по умолчанию) — результат может меняться от вызова к вызову или есть побочные эффекты; оптимизатор не оптимизирует вызовы; помечайте так функции с записью в БД, random(), currval() и т.п.
- **PARALLEL UNSAFE | RESTRICTED | SAFE** — допустимость выполнения в параллельных воркерах; по умолчанию UNSAFE; для параллельных запросов нужны SAFE или RESTRICTED в зависимости от доступа к состоянию.
