# §6.3 Транзакции внутри процедуры

В [§6.2](chapter-06-02.md) мы разобрали OUT-параметры и вызов CALL из PL/pgSQL. В этом разделе — **управление транзакциями** внутри процедуры: в отличие от функции, процедура (и блок DO) может выполнять **COMMIT** и **ROLLBACK**; когда это допустимо и когда бывает нужно. Ограничения: вызов должен быть «на верхнем уровне» транзакции, без вмешательства других команд в стеке вызовов. См. [Глоссарий](glossary.md).

---

## 6.3.1. Функция и процедура: различие по транзакциям

**Функция** (CREATE FUNCTION) выполняется в рамках **одной транзакции** вызывающего. Внутри функции нельзя выполнять COMMIT или ROLLBACK: они завершают текущую транзакцию, а контекст функции не допускает этого. Любые изменения, сделанные функцией, будут зафиксированы или отменены вместе с транзакцией вызывающего. См. [Глоссарий](glossary.md).

**Процедура** (CREATE PROCEDURE), вызываемая оператором **CALL**, а также **анонимный блок** (DO) при определённых условиях могут завершать транзакцию командами **COMMIT** и **ROLLBACK** (по документации PostgreSQL, раздел 41.8). После COMMIT или ROLLBACK автоматически начинается **новая** транзакция; отдельной команды START TRANSACTION не требуется. Это нужно, когда одна процедура должна зафиксировать часть работы и продолжить в новой транзакции (например, пакетная обработка с фиксацией по шагам).

---

## 6.3.2. Когда процедура может выполнять COMMIT/ROLLBACK

Транзакционное управление внутри процедуры или DO **разрешено только если** вызов выполняется в **собственной транзакции** (по документации PostgreSQL). То есть **CALL** не должен находиться внутри уже открытого транзакционного блока. Если клиент выполнил, например, `BEGIN; ... CALL my_proc();`, то внутри `my_proc` команды COMMIT и ROLLBACK **не допускаются** — будет ошибка. Если же CALL выполняется отдельно (как единственная команда в режиме autocommit или без предшествующего BEGIN), процедура может завершать и начинать транзакции. См. [Глоссарий](glossary.md).

Дополнительное условие (раздел 41.8): управление транзакциями возможно только при вызове **с верхнего уровня** или при **вложенных** вызовах CALL/DO **без других команд между ними**. Например, цепочка `CALL proc1()` → `CALL proc2()` → `CALL proc3()` допускает COMMIT/ROLLBACK в proc2 и proc3. Но если в цепочке есть вызов функции через SELECT, например `CALL proc1()` → `SELECT func2()` → `CALL proc3()`, то процедура proc3 **не может** выполнять COMMIT/ROLLBACK из‑за «чужой» команды SELECT в стеке вызовов.

## 6.3.3. COMMIT и ROLLBACK в процедуре; COMMIT AND CHAIN

В теле процедуры (или DO) можно писать **COMMIT** и **ROLLBACK** как обычные SQL-команды. После выполнения текущая транзакция завершается (фиксация или отмена), и **автоматически начинается новая** транзакция с характеристиками по умолчанию. См. [Глоссарий](glossary.md).

Пример (по документации PostgreSQL): процедура в цикле вставляет строки и по условию делает COMMIT или ROLLBACK — каждая итерация может завершать свою транзакцию и начинать следующую.

```sql
CREATE PROCEDURE transaction_test1()
LANGUAGE plpgsql
AS $$
BEGIN
  FOR i IN 0..9 LOOP
    INSERT INTO test1 (a) VALUES (i);
    IF i % 2 = 0 THEN
      COMMIT;
    ELSE
      ROLLBACK;
    END IF;
  END LOOP;
END;
$$;

CALL transaction_test1();
```

Чтобы новая транзакция наследовала параметры предыдущей (уровень изоляции и т.п.), используют **COMMIT AND CHAIN** и **ROLLBACK AND CHAIN**: завершают текущую транзакцию и сразу открывают новую с теми же характеристиками.

## 6.3.4. Ограничения: подтранзакции и курсоры

В PL/pgSQL **не поддерживаются** команды **SAVEPOINT**, **ROLLBACK TO SAVEPOINT** и **RELEASE SAVEPOINT**. Вместо отката к точке сохранения обычно используют блок с **EXCEPTION** (гл. 4): такой блок образует подтранзакцию, и при ошибке откатывается только он. При этом **завершать транзакцию (COMMIT/ROLLBACK) внутри блока с EXCEPTION нельзя** — управление транзакцией возможно только на уровне процедуры или DO без обработчика. См. [Глоссарий](glossary.md).

Если в процедуре цикл **FOR по курсору** (результату запроса) и внутри цикла выполняется COMMIT или ROLLBACK, курсор при первом таком выполнении становится **удерживаемым** (holdable): все строки читаются и материализуются, после COMMIT/ROLLBACK блокировки запроса курсора снимаются. Для постраничной обработки с фиксацией это может означать большой расход памяти. В циклах по курсорам, управляемых **не только чтением** (например, UPDATE ... RETURNING), транзакционные команды в PL/pgSQL **не допускаются** (по документации PostgreSQL). См. [Глоссарий](glossary.md).

---

## Ключевое

- **Процедура** (и DO) может выполнять **COMMIT** и **ROLLBACK**; **функция** — нет; все изменения функции принадлежат одной транзакции вызывающего.
- COMMIT/ROLLBACK в процедуре допустимы только если **CALL выполняется не внутри транзакционного блока** (не после BEGIN у клиента) и в стеке вызовов нет «чужих» команд (только вложенные CALL/DO).
- После COMMIT или ROLLBACK **автоматически начинается новая транзакция**; **COMMIT AND CHAIN** / **ROLLBACK AND CHAIN** сохраняют параметры транзакции для следующей.
- В PL/pgSQL нет SAVEPOINT; для частичного отката используют блок с EXCEPTION; внутри такого блока COMMIT/ROLLBACK выполнять нельзя. В цикле по курсору с COMMIT/ROLLBACK курсор становится удерживаемым.
