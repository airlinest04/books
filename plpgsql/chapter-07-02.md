# §7.2 Курсор

В [§7.1](chapter-07-01.md) мы разобрали выполнение одного запроса и получение одной строки (SELECT ... INTO, DML). Когда нужно **обрабатывать результат запроса по строкам**, не загружая весь набор в память сразу, в PL/pgSQL используют **курсор**: объект, инкапсулирующий запрос и текущую позицию в результате. В этом разделе — объявление переменной курсора (**refcursor**, **CURSOR FOR** запрос), **OPEN**, **FETCH** и **CLOSE**, а также цикл **FOR** по курсору. Динамический SQL (OPEN FOR EXECUTE) — в [§7.3](chapter-07-03.md). См. [Глоссарий](glossary.md).

---

## 7.2.1. Объявление курсора

Доступ к курсору в PL/pgSQL осуществляется через **переменные типа refcursor** (по документации PostgreSQL, раздел 41.7). Два варианта объявления. См. [Глоссарий](glossary.md).

**Непривязанный (unbound) курсор** — переменная типа **refcursor** без привязки к запросу; запрос задаётся при открытии (OPEN FOR ...):

```sql
DECLARE
  cur refcursor;
```

**Привязанный (bound) курсор** — запрос задаётся при объявлении; при открытии подставляются только аргументы (если есть). Синтаксис:

```
имя [ [ NO ] SCROLL ] CURSOR [ ( аргументы ) ] FOR запрос;
```

Ключевое слово **FOR** можно заменить на **IS** (совместимость с Oracle). **SCROLL** — курсор допускает движение назад (FETCH PRIOR, LAST и т.д.); **NO SCROLL** — только вперёд. Если не указано, возможность прокрутки зависит от запроса. **Аргументы** — список пар `имя тип` (например, `key integer`); значения передаются при OPEN. Примеры:

```sql
DECLARE
  cur_orders CURSOR FOR SELECT id, total FROM orders WHERE status = 'new';
  cur_by_id  CURSOR (p_id integer) FOR SELECT * FROM orders WHERE id = p_id;
BEGIN
  -- ...
END;
```

SCROLL нельзя использовать, если в запросе есть FOR UPDATE/SHARE. См. [Глоссарий](glossary.md).

---

## 7.2.2. OPEN — открытие курсора

Перед чтением строк курсор нужно **открыть**. При открытии создаётся портал (portal) с состоянием выполнения запроса. См. [Глоссарий](glossary.md).

**Непривязанный курсор:** запрос задаётся в OPEN.

```sql
OPEN cur FOR SELECT * FROM orders WHERE created_at > p_since;
```

Для динамического запроса (строка формируется в переменной) — **OPEN ... FOR EXECUTE** с **USING** ([§7.3](chapter-07-03.md)).

**Привязанный курсор:** запрос уже задан в DECLARE; в OPEN передают только аргументы (если есть).

```sql
OPEN cur_orders;
OPEN cur_by_id(42);
OPEN cur_by_id(p_id => order_id);
```

Привязанный курсор можно также не открывать вручную, а использовать в цикле **FOR** — цикл сам откроет и закроет его (см. ниже). Значения переменных PL/pgSQL, подставляемые в запрос (для привязанного курсора — переменные, объявленные **до** объявления курсора), берутся **в момент OPEN**; последующие изменения переменных не влияют на уже открытый курсор.

## 7.2.3. FETCH и FOUND

**FETCH** читает следующую (или указанную) строку из открытого курсора в переменные (по документации PostgreSQL):

```
FETCH [ направление { FROM | IN } ] курсор INTO цель;
```

**Цель** — переменная записи (RECORD), переменная строки (%ROWTYPE) или список переменных через запятую, как в SELECT INTO. Если строки нет, в цель записываются NULL. Переменная **FOUND** устанавливается в true, если строка получена, и в false, если нет. См. [Глоссарий](glossary.md).

**Направление** (опционально): **NEXT** (по умолчанию), **PRIOR**, **FIRST**, **LAST**, **ABSOLUTE** count, **RELATIVE** count, **FORWARD**, **BACKWARD**. Движение назад возможно только для курсора, объявленного или открытого с **SCROLL**. Примеры:

```sql
FETCH cur_orders INTO rec;
FETCH cur_orders INTO o_id, o_total;
FETCH LAST FROM cur_orders INTO rec;
```

Типичный цикл вручную:

```sql
OPEN cur_orders;
LOOP
  FETCH cur_orders INTO rec;
  EXIT WHEN NOT FOUND;
  -- обработка rec
END LOOP;
CLOSE cur_orders;
```

**MOVE** — переместить позицию курсора без чтения строки: `MOVE [ направление ] FROM курсор;` — после выполнения FOUND показывает, была ли строка для перехода.

## 7.2.4. CLOSE и цикл FOR по курсору

**CLOSE** закрывает портал курсора и освобождает ресурсы; переменную курсора после этого можно открыть заново. Портал также закрывается неявно в конце транзакции. См. [Глоссарий](glossary.md).

```sql
CLOSE cur_orders;
```

**Цикл FOR по привязанному курсору** (по документации PostgreSQL, раздел 41.7.4) избавляет от явных OPEN/FETCH/CLOSE: курсор открывается при входе в цикл и закрывается при выходе. Синтаксис:

```sql
FOR переменная_записи IN имя_курсора [ ( аргументы ) ] LOOP
  операторы
END LOOP;
```

Переменная цикла автоматически объявляется как тип **record** и существует только внутри цикла. Пример:

```sql
DECLARE
  cur CURSOR FOR SELECT id, total FROM orders WHERE status = 'new';
  r RECORD;
BEGIN
  FOR r IN cur LOOP
    RAISE NOTICE 'Order %, total %', r.id, r.total;
    -- обработка r
  END LOOP;
END;
```

Для непривязанного курсора цикл FOR по имени не предусмотрен; либо открывать и вручную FETCH в LOOP, либо использовать цикл **FOR по запросу** (FOR r IN SELECT ... LOOP), который внутренне использует курсор ([§3.4](chapter-03-04.md)).

## 7.2.5. UPDATE/DELETE WHERE CURRENT OF

Если курсор позиционирован на строке таблицы (запрос без группировки; предпочтительно с **FOR UPDATE**), текущую строку можно обновить или удалить по ссылке на курсор (по документации PostgreSQL):

```sql
UPDATE orders SET status = 'processed' WHERE CURRENT OF cur_orders;
DELETE FROM orders WHERE CURRENT OF cur_orders;
```

Ограничения и детали — в документации по DECLARE (SQL). См. [Глоссарий](glossary.md).

---

## Ключевое

- **Курсор** — переменная типа **refcursor**; привязанный (CURSOR FOR запрос) или непривязанный (refcursor, запрос в OPEN).
- **OPEN** — открыть курсор (для привязанного — с аргументами при необходимости); **FETCH** — прочитать строку в переменные; **FOUND** показывает, была ли строка; **CLOSE** — закрыть.
- Цикл **FOR** переменная **IN** привязанный_курсор **LOOP** сам открывает и закрывает курсор; переменная цикла — record.
- **UPDATE/DELETE ... WHERE CURRENT OF** курсор — изменение или удаление текущей строки курсора.

В [§7.3](chapter-07-03.md) разберём **динамический SQL**: построение строки запроса в переменной, **EXECUTE ... USING** и защита от SQL-инъекций.
