# §6.2 OUT-параметры процедур

В [§6.1](chapter-06-01.md) мы ввели CREATE PROCEDURE и вызов через CALL. Процедура не имеет RETURNS; «вернуть» данные вызывающему можно через **OUT-** и **INOUT-**параметры. В этом разделе — объявление таких параметров, присваивание им значений в теле процедуры и получение результатов при вызове: из обычного SQL (CALL возвращает строку) и из блока PL/pgSQL (переменные получают значения выходных параметров). Транзакции внутри процедуры (COMMIT/ROLLBACK) — в [§6.3](chapter-06-03.md). См. [Глоссарий](glossary.md).

---

## 6.2.1. Объявление OUT и INOUT

В списке параметров процедуры (как и у функции, [§5.2](chapter-05-02.md)) допускаются режимы **OUT** и **INOUT**. **OUT** — только выход: вызывающий не обязан передавать осмысленное значение, в теле процедуре присваивает параметру результат. **INOUT** — и вход, и выход: при вызове передаётся значение, в теле его можно читать и изменять; после вызова вызывающий получает итоговое значение. Имена OUT/INOUT задают имена столбцов в строке результата при вызове CALL из SQL. См. [Глоссарий](glossary.md).

Пример объявления:

```sql
CREATE PROCEDURE get_stats(
  p_from date,
  p_to   date,
  OUT row_count bigint,
  OUT min_val   numeric,
  OUT max_val   numeric
)
LANGUAGE plpgsql
AS $$
BEGIN
  SELECT count(*), min(amount), max(amount)
    INTO row_count, min_val, max_val
    FROM sales WHERE sale_date BETWEEN p_from AND p_to;
END;
$$;
```

В теле **OUT-** и **INOUT-**параметры ведут себя как переменные: им присваивают значения через `:=` или `INTO`. По завершении процедуры вызывающему возвращаются финальные значения этих параметров (по документации PostgreSQL). Явный RETURN в процедуре не обязан быть; для досрочного выхода пишут **RETURN** без выражения.

## 6.2.2. Вызов из SQL: CALL и строка результата

При вызове процедуры из **обычного SQL** (например, в psql или из клиента) оператор **CALL** возвращает **одну строку** с полями по OUT- и INOUT-параметрам. Для каждого такого параметра в списке аргументов CALL нужно указать место: по документации PostgreSQL аргументы для OUT при вызове обычно передают как **NULL** (они не оцениваются). См. [Глоссарий](glossary.md).

Пример (процедура из предыдущего подраздела):

```sql
CALL get_stats('2024-01-01'::date, '2024-12-31'::date, NULL, NULL, NULL);
```

В интерактивной сессии результат отобразится как строка с столбцами `row_count`, `min_val`, `max_val`. Получить значения в переменные SQL-клиента можно, если клиент поддерживает привязку выходных параметров; в общем случае CALL из SQL даёт одну результирующую строку.

---

## 6.2.3. Вызов из PL/pgSQL: переменные получают значения OUT

В блоке PL/pgSQL (функция, процедура или **DO**) вызов **CALL** обрабатывается иначе (по документации PostgreSQL, раздел 41.6.3). Каждому **OUT-** и **INOUT-**параметру должна соответствовать **переменная** в списке вызова; после возврата из процедуры в эти переменные **присваиваются** возвращённые значения. То есть вы передаёте переменные в CALL, а не NULL, и по завершении вызова они содержат результат. См. [Глоссарий](glossary.md).

Пример (по документации PostgreSQL):

```sql
CREATE PROCEDURE triple(INOUT x int)
LANGUAGE plpgsql
AS $$
BEGIN
  x := x * 3;
END;
$$;

DO $$
DECLARE
  myvar int := 5;
BEGIN
  CALL triple(myvar);
  RAISE NOTICE 'myvar = %', myvar;  -- выведет 15
END;
$$;
```

Здесь `myvar` передаётся как единственный аргумент (INOUT); процедура умножает его на 3 и «возвращает» через тот же параметр; после CALL переменная `myvar` равна 15. Для процедуры с несколькими OUT в DECLARE объявляют переменные и передают их в CALL по порядку; после вызова они будут заполнены. В качестве аргумента может быть простая переменная или поле составного типа; элементом массива — нельзя (ограничение текущей реализации).

Пример с несколькими OUT:

```sql
DO $$
DECLARE
  cnt bigint;
  mn  numeric;
  mx  numeric;
BEGIN
  CALL get_stats('2024-01-01'::date, '2024-12-31'::date, cnt, mn, mx);
  RAISE NOTICE 'count=%, min=%, max=%', cnt, mn, mx;
END;
$$;
```

---

## Ключевое

- **OUT** и **INOUT** в CREATE PROCEDURE задают выходные параметры; в теле им присваивают значения; по завершении процедуры эти значения возвращаются вызывающему.
- При вызове **CALL из SQL** возвращается одна строка с полями по OUT/INOUT; для слотов OUT в аргументах обычно передают NULL.
- При вызове **CALL из PL/pgSQL** каждому OUT/INOUT должна соответствовать переменная в списке вызова; после возврата из процедуры в эти переменные записываются результаты.
- Для досрочного выхода из процедуры используют **RETURN** без выражения; при наличии OUT возвращаются текущие значения выходных параметров.

В [§6.3](chapter-06-03.md) разберём **транзакции внутри процедуры**: когда процедура может выполнять COMMIT и ROLLBACK и как это связано с вызовом CALL.
