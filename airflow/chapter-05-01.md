# §5.1 Линейные и параллельные ветки

В [§4.4](chapter-04-04.md) мы ввели зависимости через `>>`, цепочки и списки задач. Здесь те же конструкции разбираются как **паттерны графа**: линейная последовательность, параллельные ветки и их сведение. Понимание этих паттернов помогает проектировать пайплайны загрузки данных (несколько источников → общая витрина) и предсказывать порядок выполнения. Расписание (schedule_interval) и логическая дата — в [§5.2](chapter-05-02.md) и [§5.3](chapter-05-03.md).

---

## 5.1.1. Линейная последовательность (A >> B >> C)

**Линейная цепочка** — все задачи идут одна за другой: A → B → C. Каждая задача имеет ровно одного предшественника и ровно одного преемника (кроме первой и последней). Планировщик ставит B в очередь только после успеха A, C — только после успеха B. Параллельного выполнения нет: в одном run задачи выполняются строго по очереди (при одном воркере — так и по времени).

Пример: извлечение → преобразование → загрузка.

```python
extract >> transform >> load
```

Такой граф подходит, когда каждый шаг зависит от результата предыдущего и параллелить нечего. См. [§6.1](chapter-06-01.md) (практика загрузки данных).

---

## 5.1.2. Параллельные ветки (A → B и A → C)

Если после одной задачи должны запуститься **несколько независимых** задач, задайте несколько преемников:

```python
task_a >> [task_b, task_c]
```

Граф: A → B и A → C. После успешного завершения A планировщик ставит в очередь и B, и C. Они **не зависят друг от друга** по графу, поэтому при наличии свободных воркеров могут выполняться **параллельно**. Типичный сценарий: одна задача «подготовка» или «проверка», за ней несколько загрузок из разных источников или расчётов по разным витринам.

---

## 5.1.3. Сведение веток (B и C → D)

Чтобы следующая задача запускалась только после **обеих** (или всех) веток, задайте несколько предшественников:

```python
[task_b, task_c] >> task_d
```

Задача D попадёт в очередь только когда и B, и C успешно завершены. Если одна из веток упадёт, D не запустится в этом run до исправления и повторного успешного выполнения B или C.

Полный паттерн «развилка и сведение»:

```python
task_a >> [task_b, task_c]
[task_b, task_c] >> task_d
```

Читается как: сначала A, затем параллельно B и C, затем D. Так часто строят пайплайны с несколькими источниками и одной общей витриной (как в [§2.2](chapter-02-02.md)).

---

## 5.1.4. Комбинирование цепочек и веток

Можно комбинировать линейные участки и развилки. Пример: две параллельные цепочки, затем общий финальный шаг.

```python
# Ветка 1: A1 -> A2
task_a1 >> task_a2
# Ветка 2: B1 -> B2
task_b1 >> task_b2
# Старт запускает обе ветки
start >> [task_a1, task_b1]
# Сведение в финал
[task_a2, task_b2] >> finish
```

Порядок выполнения: start → (параллельно A1 и B1) → (после A1 выполнится A2, после B1 — B2) → после A2 и B2 выполнится finish. Важно: граф остаётся ациклическим; циклов быть не должно.

---

## 5.1.5. Когда что использовать

| Паттерн | Когда использовать |
|--------|---------------------|
| Линейная цепочка A >> B >> C | Один поток работы: каждый шаг зависит от предыдущего (ETL по одному источнику). |
| Параллельные ветки A >> [B, C] | Одна задача порождает несколько независимых (несколько источников, несколько витрин после одной проверки). |
| Сведение [B, C] >> D | Нужен общий шаг после нескольких веток (агрегация, отправка отчёта, загрузка общей витрины). |

В [§5.2](chapter-05-02.md) разберём, как задать расписание запусков такого графа: cron, timedelta и значение None.

---

## Ключевое

- **Линейная последовательность** A >> B >> C — один за другим; параллелизма нет.
- **Параллельные ветки** A >> [B, C] — после A выполняются B и C независимо; при нескольких воркерах — параллельно.
- **Сведение** [B, C] >> D — D запускается только после успешного завершения и B, и C.
- Паттерн «развилка и сведение» типичен для пайплайнов с несколькими источниками и одной общей задачей (витрина, нотификация).

В [§5.2](chapter-05-02.md) — schedule_interval: cron-выражения, timedelta и запуск только вручную (None).
