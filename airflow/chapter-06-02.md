# §6.2 Таски: извлечение

В [§6.1](chapter-06-01.md) мы сформулировали постановку: источник (файл или БД), назначение (Raw/Staging), идемпотентность. Шаг **извлечения (extract)** — первая задача пайплайна: прочитать данные из источника и сделать их доступными для следующего шага (файл на диске, путь к файлу, выборка в памяти или в промежуточной таблице). В этом разделе — как реализовать таск извлечения: **BashOperator** или **PythonOperator** для запуска скрипта, при необходимости **Hook** для подключения к источнику, и кратко **передача данных между тасками через XCom**. Подробнее операторы и хуки — в [главе 7](chapter-07-01.md); преобразование и загрузка — в [§6.3](chapter-06-03.md).

---

## 6.2.1. Вариант: запуск скрипта (BashOperator / PythonOperator)

Извлечение можно вынести в отдельный скрипт (shell или Python), который по аргументам (например, дата из `--date 2025-02-14`) читает источник и сохраняет результат: в файл, в промежуточную таблицу или в stdout для последующей обработки. В Airflow таск извлечения тогда — это **запуск этого скрипта** с подстановкой даты из контекста run.

**BashOperator:** подходит, если скрипт вызывается из командной строки. Дата передаётся через шаблон Jinja (например, `{{ ds }}` — логическая дата в формате YYYY-MM-DD).

```python
from airflow.operators.bash import BashOperator

extract = BashOperator(
    task_id="extract",
    bash_command="python /path/to/scripts/extract_sales.py --date {{ ds }}",
    dag=dag,
)
```

Скрипт `extract_sales.py` получает `--date 2025-02-14`, читает источник за эту дату и пишет, например, во временный файл или в Raw-таблицу. Путь к скрипту и к выходному файлу лучше задавать через переменные или конфиг, а не хардкодить.

**PythonOperator:** извлечение можно выполнить прямо в callable: подключиться к БД через Hook или прочитать файл, обработать и записать результат. Удобно, когда логика простая и не хочется выносить её в отдельный скрипт. Пример загрузки из файла по пути с датой:

```python
from airflow.operators.python import PythonOperator

def extract_from_file(**context):
    ds = context["ds"]
    path = f"/data/incoming/sales_{ds}.csv"
    # чтение, при необходимости запись во временный файл или в Raw
    # при необходимости вернуть путь или ключ для следующей задачи
    return path

extract = PythonOperator(
    task_id="extract",
    python_callable=extract_from_file,
    dag=dag,
)
```

Возвращаемое значение callable при необходимости передаётся следующей задаче через **XCom** (см. ниже и [§7.4](chapter-07-04.md)).

## 6.2.2. Вариант: подключение к источнику через Hook

Если источник — БД или API, в PythonOperator удобно использовать **Hook** ([§7.3](chapter-07-03.md)): Hook инкапсулирует подключение (учётные данные берутся из Airflow Connections), а задача вызывает метод чтения. Например, **PostgresHook** для чтения из PostgreSQL:

```python
from airflow.providers.postgres.hooks.postgres import PostgresHook
from airflow.operators.python import PythonOperator

def extract_from_db(**context):
    ds = context["ds"]
    hook = PostgresHook(postgres_conn_id="source_db")
    conn = hook.get_conn()
    # выполнить SELECT за дату ds, записать во временную таблицу или файл
    # ...
    return "path_or_key"  # для следующей задачи при необходимости

extract = PythonOperator(
    task_id="extract",
    python_callable=extract_from_db,
    dag=dag,
)
```

Подключение `source_db` настраивается в Airflow Connections ([§7.5](chapter-07-05.md)). Для HTTP-источников используется **HttpHook** или аналоги; для облачных хранилищ — провайдерские хуки (S3, GCS). Детали — в [§7.3](chapter-07-03.md).

## 6.2.3. Передача данных следующей задаче: XCom (кратко)

Если задача извлечения должна передать следующей задаче **небольшой артефакт** (путь к файлу, имя таблицы, ключ, количество строк), в Airflow для этого используется **XCom** (cross-communication). Callable в PythonOperator может **вернуть** значение — оно автоматически записывается в XCom; следующая задача может прочитать его через контекст или метод `xcom_pull`. Подробнее ограничения по размеру и практика — в [§7.4](chapter-07-04.md).

Рекомендация: не передавать через XCom большие объёмы данных (целые датафреймы или большие строки). Лучше передавать **путь к файлу**, **имя таблицы** или **идентификатор** и пусть следующая задача сама читает данные по этому пути/ключу. Тогда таск извлечения, например, пишет в `/data/staging/sales_{{ ds }}.csv` и возвращает этот путь; таск преобразования/загрузки по пути читает файл.

## 6.2.4. Подстановка даты в команды и пути

В BashOperator и в шаблонируемых полях других операторов можно использовать **Jinja-шаблоны** с переменными контекста run. Основные:

- **`{{ ds }}`** — логическая дата в формате YYYY-MM-DD.
- **`{{ data_interval_start }}`**, **`{{ data_interval_end }}`** — границы data interval (в версиях, где они доступны).

Пример пути к файлу в PythonOperator через контекст уже приведён выше (`context["ds"]`). В BashOperator:

```python
BashOperator(
    task_id="extract",
    bash_command="echo 'Processing {{ ds }}' && python script.py --date {{ ds }}",
    dag=dag,
)
```

Так каждая run обрабатывает свою логическую дату без хардкода.

---

## Ключевое

- Таск **извлечения** можно реализовать **BashOperator** (запуск скрипта с `{{ ds }}`) или **PythonOperator** (callable с чтением файла/БД или вызовом Hook).
- Для чтения из БД или API удобно использовать **Hook** в PythonOperator; учётные данные — в Airflow Connections.
- Между задачами небольшие артефакты передаются через **XCom**; большие данные — через путь к файлу или ключ в БД, не через XCom.
- Дату run подставляйте из контекста (`ds`) или шаблонов (`{{ ds }}`), чтобы пайплайн был привязан к логической дате.

В [§6.3](chapter-06-03.md) — таски преобразования и загрузки: PythonOperator с Pandas/SQL, загрузка в целевую БД с учётом идемпотентности.
