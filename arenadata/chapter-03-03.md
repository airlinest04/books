# §3.3 Конфигурация кластера

В [§3.2](chapter-03-02.md) мы установили ADCM и выполнили первый вход в веб-интерфейс. В этом разделе описывается **конфигурация кластера** Arenadata DB в ADCM до запуска установки: создание кластера на базе загруженного бандла, добавление сервисов (ADB, Chrony, PXF, при необходимости ADB Control и ADBM), **добавление хостов** (с предварительной настройкой хостпровайдера), **определение Master и Segments** через распределение компонентов (Mapping), а также настройка параметров кластера и сервисов (репозитории, Docker, Java, при необходимости конфиг-группы и шаблоны). Без завершённого Mapping и при необходимости без заполненных конфигураций действие Install не выполнится корректно. Запуск установки и проверка кластера — в [§3.4](chapter-03-04.md). См. [Глоссарий](glossary.md).

---

## 3.3.1. Создание кластера и добавление сервисов

Кластер в ADCM — это набор сервисов, развёрнутых на группе хостов. Дистрибутивы поставляются в виде **бандлов** (архивы с логикой развёртывания). По [документации по созданию кластера ADB](https://docs.arenadata.io/ru/ADB/current/get-started/online-install/adb-install/cluster-creation.html):

**Шаг 1. Загрузка бандла.** Бандл ADB скачивается с [network.arenadata.io](https://network.arenadata.io/) (выбор продукта Arenadata DB и нужной версии). Для Enterprise бандл можно получить у поддержки Arenadata и пропустить загрузку с сайта.

**Шаг 2. Загрузка бандла в ADCM.** В левом меню выбрать **Bundles** → **Upload bundle** → выбрать файл бандла. После успешной загрузки бандл отображается на странице Bundles.

**Шаг 3. Создание кластера.** На этапе создания в ADCM только регистрируется запись о кластере; установка сервисов на хосты ещё не выполняется. В меню **Clusters** нажать **Create cluster**. В диалоге указать: **Product** — загруженный бандл ADB; **Product version** — версию бандла; **Cluster name** — имя кластера; **Description** — при необходимости; для Enterprise — установить флаг **I accept Terms of Agreement**. Нажать **Create**. Кластер появится в списке Clusters в состоянии `created`.

**Добавление сервисов.** Открыть кластер (клик по имени) → вкладка **Services** → **Add service**. В открывшемся окне выбрать сервисы для добавления в кластер. По [документации по сервисам ADB](https://docs.arenadata.io/ru/ADB/current/get-started/online-install/adb-install/add-services.html):

| Сервис | Обязательность | CE/EE | Назначение |
|--------|----------------|-------|------------|
| **ADB** | Обязателен | CE/EE | Основной сервис MPP-СУБД (Greengage DB). |
| **Chrony** | Опционален | CE/EE | Синхронизация времени на хостах; не нужен, если уже используется аналог. |
| **PXF** | Опционален | CE/EE | Взаимодействие ADB с внешними источниками данных. |
| **ADB Control** | Опционален | EE | Мониторинг запросов; только при offline-установке. |
| **ADBM** | Опционален | EE | Управление бинарными бэкапами; только при offline-установке. |
| **ADB ClickHouse Connector**, **Kafka to ADB**, **ADB to Kafka**, **ADB to ADB** | Опционален | EE | Коннекторы; для части требуется PXF. |

Минимально для запуска кластера добавляют сервис **ADB**; для синхронизации времени рекомендуется **Chrony**. Опциональные сервисы можно добавить позже к уже развёрнутому кластеру. После выбора нажать **Add**.

## 3.3.2. Хостпровайдер и добавление хостов

Хосты, на которых будет развёрнут кластер, должны быть заведены в ADCM через **хостпровайдер** (Hostprovider). Хостпровайдер определяет тип и параметры доступа к хостам (SSH, облако и т.д.). По [документации по хостпровайдерам](https://docs.arenadata.io/ru/ADCM/current/how-to/hostproviders.html), ADCM поддерживает типы: **SSH** (общий SSH-доступ к серверам), **Yandex Cloud**, **VCloud (VMware)**, **Cloud.ru Advanced**, **CROC Cloud**, **ADB Cloud Bundle**, **ADQM Cloud Bundle**. Для развёртывания на собственных серверах по SSH используется хостпровайдер типа **SSH**: перед его созданием загружается **инфраструктурный бандл** (Infrastructure Bundle) для SSH; затем на вкладке **Hostproviders** нажимают **Create hostprovider**, выбирают тип SSH и заполняют параметры (список хостов или способ их получения, учётные данные, ключи). Детали создания SSH-хостпровайдера — в [документации HP SSH](https://docs.arenadata.io/ru/hp-ssh/current/get-started/install.html). После настройки хостпровайдера выполняют действие **Create hosts** (если хосты создаются динамически) или хосты появляются по конфигурации — в зависимости от типа провайдера. В результате на вкладке Hostproviders (и в деталях хостпровайдера) отображаются доступные хосты.

**Добавление хостов в кластер.** Открыть страницу кластера → вкладка **Hosts** → **Add hosts**. В диалоге выбрать один или несколько хостов из списка (хосты, заведённые через хостпровайдеры) и нажать **Add**. Добавленные хосты отображаются на вкладке Hosts с указанием хостпровайдера и состояния. Без добавления хостов нельзя перейти к распределению компонентов.

## 3.3.3. Определение Master и Segments: распределение компонентов (Mapping)

В ADCM **компонент** — часть сервиса, которая разворачивается на одном или нескольких хостах. У сервиса ADB компоненты: **ADB Master**, **ADB Standby**, **ADB Segment** и др. Изначально компоненты не размещены на хостах; распределение выполняется **вручную** на вкладке **Mapping**. Без назначения обязательных компонентов в нужном количестве сохранение схемы распределения невозможно. По [документации по добавлению компонентов ADB](https://docs.arenadata.io/ru/ADB/current/get-started/online-install/adb-install/add-components.html):

**Типовая схема распределения (Enterprise-версия ADB):**

| Хост | Сервис | Компонент | Примечание |
|------|--------|-----------|------------|
| Хост координатора | ADB | **ADB Master** | Обязательно на одном хосте (координатор). |
| | Chrony | NTP Master | Рекомендуется на координаторе. |
| Хост standby | ADB | **ADB Standby** | Обязательно на одном хосте (резервный мастер). |
| | Chrony | NTP Secondary | На хосте standby. |
| Сегмент-хосты (1..N) | ADB | **ADB Segment** | Обязательно на каждом сегмент-хосте. |
| | Chrony | NTP Slave | На каждом сегмент-хосте. |
| | PXF | PXF | На сегмент-хостах; опционально на координаторе. |

**Порядок действий на вкладке Mapping:** открыть кластер → вкладка **Mapping** → для каждого компонента нажать **Add hosts** и выбрать хосты. Обязательные компоненты подсвечены красным; ADCM показывает, сколько экземпляров каждого обязательного компонента нужно разместить. После размещения всех обязательных компонентов нажать **Save**. Альтернативный режим — **Hosts mode** (переключатель): отображается список хостов, для каждого хоста кнопка **Add components**; удобно назначать компоненты «от хоста». Режим доступен в ADCM начиная с версии 2.2.0.

В итоге: один хост получает роль **Master** (ADB Master), при использовании standby — другой хост роль **Standby** (ADB Standby), остальные хосты — **ADB Segment**. От этого распределения зависит, на каких узлах установится координатор, резервный координатор и сегменты при запуске Install.

## 3.3.4. Настройка параметров кластера и сервисов

После создания кластера и распределения компонентов при необходимости настраивают конфигурационные параметры. В большинстве случаев достаточно значений по умолчанию. По [документации по настройке кластера ADB](https://docs.arenadata.io/ru/ADB/current/get-started/online-install/adb-install/config-cluster.html):

**Вкладка Configuration кластера** содержит подразделы: **Primary configuration**, **Configuration groups**, **Ansible settings**.

**Primary configuration** (основные параметры):

- **Репозитории:** для каждой ОС (Alt Linux, Astra, РЕД ОС, Ubuntu) — включение и URL репозиториев Arenadata (Set up Arenadata repo, Arenadata repo url), при необходимости кастомный Enterprise-репозиторий и репозиторий мониторинга. Хосты кластера должны иметь доступ к этим URL при online-установке.
- **Use existing docker** — использовать уже установленный на хостах Docker (не устанавливать Docker при установке ADB). Нужен при особых настройках Docker или rootless; с ADB 6.27.1.56 ADB Control перезаписывает `/etc/docker/daemon.json`, поэтому при своих настройках этот флаг рекомендуется включить.
- **Use custom registry** — кастомный Container Registry (URL, prefix, самоподписанный сертификат при необходимости).
- **Use custom JAVA_HOME for cluster** — путь к Java 17 на хостах кластера (для PXF, ADB Control, ADBM). В Astra Linux заполнение JAVA_HOME обязательно с определённой версии ADB; пути по умолчанию для ОС указаны в документации.
- **Timeout to unlock package manager** — параметры повторных попыток при блокировке DNF (retries, delay).
- **Parameter archiving** — выгрузка конфигурации по расписанию (cron).
- **Vault integration** — интеграция с HashiCorp Vault для хранения секретов (адрес, порт, аутентификация, mount point и т.д.); опционально.

Изменения сохраняют кнопкой **Save**. Параметры можно задавать и на уровне **сервисов** (страница кластера → Services → выбор сервиса → вкладки Primary configuration, Configuration groups и др.) — для ADB, Chrony, PXF, ADB Control, ADBM и т.д. описание параметров приведено в справочниках конфигурации ADCM и в руководствах по продуктам.

**Ansible settings** (на уровне кластера): например, **forks** — число параллельных процессов Ansible при работе с удалёнными хостами (по умолчанию 5). Вкладка доступна в ADCM с версии 2.2.0.

## 3.3.5. Configuration groups и шаблоны

**Configuration groups** (вкладка Configuration → Configuration groups) позволяют задавать разные значения параметров для разных групп хостов или компонентов. Например, одни параметры — для координатора, другие — для сегментов. Подробнее механизм конфиг-групп описан в [документации ADCM](https://docs.arenadata.io/ru/ADCM/current/tutorials/config-groups.html). Для типового первого развёртывания конфиг-группы можно не использовать.

**Шаблоны:** в контексте ADCM «шаблоны» могут относиться к предзаданным схемам конфигурации или к шаблонам бандлов (прототипы сервисов в описании бандла). При создании кластера из бандла ADB доступный набор сервисов и компонентов определяется бандлом; пользователь выбирает сервисы и распределяет компоненты по хостам, как описано выше. Готовых «шаблонов размещения» в виде одного клика в документации не описывается — схема Master/Standby/Segments задаётся вручную на Mapping.

## 3.3.6. Типичные ошибки при конфигурации кластера

- **Добавлять хосты до создания хостпровайдера:** хосты берутся из хостпровайдеров; сначала создаётся хостпровайдер (и при необходимости выполняются действия по созданию хостов), затем хосты добавляются в кластер.
- **Запускать Install до завершения Mapping:** все обязательные компоненты (ADB Master, ADB Segment, при выборе standby — ADB Standby, при добавлении Chrony — NTP Master/Secondary/Slave) должны быть размещены на хостах; без этого сохранение на Mapping недоступно или установка завершится ошибкой.
- **Не сохранить Mapping после расстановки компонентов:** после выбора хостов для каждого компонента нужно нажать **Save** на вкладке Mapping; иначе изменения не применятся.
- **Забыть про репозитории при offline-установке:** при offline используется хост Enterprise Tools и свои URL; при online обязательно указать доступные с хостов Arenadata repo url (и при необходимости Monitoring repo url) в конфигурации кластера.
- **Игнорировать JAVA_HOME для Astra Linux:** в этой ОС путь к Java 17 нужно явно задать в конфигурации кластера (Use custom JAVA_HOME for cluster), иначе установка может завершиться ошибкой.

## Ключевое

- **Создание кластера:** загрузка бандла ADB с network.arenadata.io (или от поддержки) → Bundles → Upload bundle → Clusters → Create cluster (Product, version, name, при EE — Terms) → состояние `created`. Добавление сервисов: Services → Add service (ADB обязательно; Chrony, PXF, ADB Control, ADBM и коннекторы — по необходимости).
- **Хостпровайдер и хосты:** загрузка инфраструктурного бандла при необходимости → Hostproviders → Create hostprovider (тип SSH или облако) → создание/настройка хостов → в кластере вкладка Hosts → Add hosts, выбор хостов из списка.
- **Mapping (Master и Segments):** вкладка Mapping → для каждого компонента Add hosts. Обязательно: ADB Master на одном хосте (координатор), ADB Segment на каждом сегмент-хосте; при standby — ADB Standby на отдельном хосте. Chrony: NTP Master на координаторе, NTP Secondary на standby, NTP Slave на сегментах. PXF — на сегмент-хостах (и опционально на координаторе). Сохранить Mapping (Save).
- **Настройка:** Configuration → Primary configuration (репозитории, Use existing docker, JAVA_HOME при необходимости, таймауты, опционально Vault); параметры сервисов — в соответствующих сервисах. Configuration groups — для разных значений по группам хостов. В большинстве случаев достаточно значений по умолчанию.

В [§3.4](chapter-03-04.md) мы разберём процесс развёртывания кластера: запуск действия Install, проверка установки, первый запуск и доступ к кластеру Arenadata DB.
