# §3.2 Установка ADCM

В [§3.1](chapter-03-01.md) мы разобрали подготовку окружения: требования к оборудованию, ОС, предварительную настройку, пользователей и SSH. В этом разделе описывается **установка Arenadata Cluster Manager (ADCM)**: получение дистрибутива (Docker-образ или архив для offline), создание и запуск контейнера ADCM, проверка установки и **первый запуск веб-интерфейса** (вход, смена пароля администратора, настройка URL ADCM). Рассмотрены два варианта: **online-установка** с использованием Docker-образа из реестра Arenadata и **offline-установка** (Enterprise); упомянут **ADCM Installer** как способ развёртывания ADCM с встроенной или внешней базой данных. Требования к хосту для ADCM (ОС, Docker, ресурсы) приведены в [§2.1](chapter-02-01.md) и [§3.1](chapter-03-01.md). После успешной установки ADCM можно переходить к конфигурации кластера и развёртыванию Arenadata DB ([§3.3](chapter-03-03.md), [§3.4](chapter-03-04.md)). См. [Глоссарий](glossary.md).

---

## 3.2.1. Получение дистрибутива ADCM

**Online-установка:** дистрибутив ADCM — это **Docker-образ**, который загружается из реестра Arenadata. По [документации по установке ADCM](https://docs.arenadata.io/ru/ADCM/current/get-started/install.html), образ скачивается командой:

```bash
$ sudo docker pull hub.arenadata.io/adcm/adcm:<версия>
```

где `<версия>` — тег образа в одном из форматов:

- **`<мажор>.<минор>.<патч>`** — конкретный патч (например, `2.7.1`);
- **`<мажор>.<минор>`** — последний патч в рамках выбранной версии (например, `2.7`).

Тег `latest` с версии 2.0.0 не поддерживается. Список доступных образов можно посмотреть в [репозитории ADCM на Docker Hub](https://hub.docker.com/r/arenadata/adcm/tags) или в реестре Arenadata. Для установки кластера ADB минимальная версия ADCM — **2.6.0** (по программным требованиям ADB). Хост должен иметь доступ в интернет к `hub.arenadata.io` (или к корпоративному зеркалу реестра).

**Offline-установка (Enterprise):** при отсутствии доступа к интернету используется offline-установка. По документации она доступна в **Enterprise Edition**. Команда поддержки Arenadata предоставляет архив с расширением **sh.xz**, содержащий установочный shell-скрипт. Архив размещается на хосте, распаковывается; скрипт загружает Docker-образ в локальное хранилище (локальный Container Registry). Пример запуска:

```bash
$ sudo bash <имя_скрипта>
```

например `adcm_2.5.0.sh`. После успешного выполнения в локальном реестре появляется образ `hub.arenadata.io/adcm/adcm:<версия>`, и контейнер создаётся уже из локального образа (без `docker pull` из интернета).

**Скачивание бандлов продуктов:** для развёртывания кластера Arenadata DB через ADCM дополнительно потребуется **бандл ADB** (архив с конфигурациями и Ansible-сценариями). Бандлы скачиваются с портала [network.arenadata.io](https://network.arenadata.io/) (после регистрации/авторизации) и загружаются в ADCM через веб-интерфейс (Bundles → Upload bundle). Это выполняется после установки ADCM и входа в интерфейс ([§3.3](chapter-03-03.md)).

## 3.2.2. Установка ADCM: создание и запуск контейнера

Данные ADCM хранятся в каталоге `/adcm/data` внутри контейнера. Чтобы не терять их при пересоздании контейнера, к `/adcm/data` **монтируют том** (Docker volume) или директорию хоста; рекомендуется настраивать бэкапы этого тома. По [документации](https://docs.arenadata.io/ru/ADCM/current/get-started/install.html):

**Создание контейнера (с внешней БД PostgreSQL):** минимальная версия PostgreSQL для ADCM с 2.5.0 — **14**. Переменные окружения задают подключение к БД: `DB_HOST`, `DB_PORT`, `DB_USER`, `DB_NAME`, `DB_PASS`, опционально `DB_OPTIONS` (sslmode и др.). Пример:

```bash
$ sudo docker create --name adcm -p 8000:8000 \
  -v /opt/adcm:/adcm/data \
  -e DB_HOST="<хост_БД>" -e DB_PORT="<порт>" \
  -e DB_USER="<пользователь>" -e DB_NAME="<имя_БД>" \
  -e DB_PASS="<пароль>" -e DB_OPTIONS="<опции>" \
  hub.arenadata.io/adcm/adcm:<версия>
```

Порт **8000** хоста сопоставляется с портом 8000 контейнера (веб-интерфейс ADCM). Путь `/opt/adcm` на хосте монтируется в `/adcm/data` контейнера; при необходимости замените на свою директорию или именованный том. При использовании **SELinux** для тома указывают суффикс `:Z`:

```bash
-v /opt/adcm:/adcm/data:Z
```

**Опционально** при создании контейнера задают переменную **DEFAULT_ADCM_URL** — URL, по которому к ADCM будут обращаться кластеры (например, `http://<IP_хоста>:8000/`). Если не задать, URL нужно будет указать вручную в Settings после первого входа. Другие переменные (LOG_LEVEL и специализированные уровни логов, MIGRATION_MODE, параметры Consul и т.д.) описаны в [документации по установке](https://docs.arenadata.io/ru/ADCM/current/get-started/install.html).

**Запуск и остановка:**

```bash
$ sudo docker start adcm
$ sudo docker stop adcm
```

Автозапуск при сбое контейнера:

```bash
$ sudo docker update --restart=on-failure adcm
```

Если у пользователя настроен доступ к Docker без root, `sudo` можно опустить.

**ADCM Installer:** альтернативный способ установки — утилита **ADCM Installer** (adi). Она упрощает развёртывание ADCM с использованием Docker Compose и позволяет поднять **встроенную базу данных PostgreSQL** (Arenadata Postgres, ADPG) для ADCM одной командой. Установка adi: загрузка бинарника в `/usr/local/bin`, например:

```bash
$ sudo wget -O /usr/local/bin/adi https://github.com/arenadata/adcm-installer/releases/latest/download/adi
$ sudo chmod +x /usr/local/bin/adi
```

Инициализация конфигурации с встроенной БД PostgreSQL:

```bash
$ adi init --adpg <имя_инсталляции>
```

с флагом `-i` (или `--interactive`) для интерактивного ввода параметров. Затем развёртывание:

```bash
$ sudo adi apply
```

При этом создаются контейнеры ADCM и ADPG, база данных инициализируется, секреты хранятся в зашифрованном виде (age). Подробнее параметры init, apply, list, delete и работа с секретами — в [документации по ADCM Installer](https://docs.arenadata.io/ru/ADCM/current/get-started/use-adcm-installer.html). Для быстрого старта и тестового окружения Installer удобен; для продакшена часто используют внешнюю PostgreSQL, развёрнутую отдельно.

## 3.2.3. Проверка установки

После запуска контейнера проверяют его статус и доступность веб-интерфейса.

**Статус контейнера:**

```bash
$ sudo docker container ls
```

В столбце `STATUS` должно быть значение `Up`; в столбце `PORTS` — `0.0.0.0:8000->8000/tcp` (или указанный вами порт).

**Порт 8000:** убедиться, что порт слушается. В Ubuntu 22.04 для `netstat` может понадобиться пакет `net-tools`:

```bash
$ sudo netstat -ntpl | grep 8000
```

или проверка через curl:

```bash
$ curl http://localhost:8000
```

В ответе должна вернуться HTML-страница с заголовком «Arenadata Cluster Manager». При доступе с другого хоста подставляют IP или имя хоста вместо localhost (и при необходимости проверяют firewall и сеть).

## 3.2.4. Первый запуск веб-интерфейса: вход и настройка

Веб-интерфейс ADCM доступен по адресу **http://<хост>:8000/** (или по порту, указанному при создании контейнера). При первой установке автоматически создаётся пользователь с правами администратора. По [документации](https://docs.arenadata.io/ru/ADCM/current/get-started/install.html):

- **Логин:** `admin`
- **Пароль:** `admin`

**Смена пароля:** после первого входа рекомендуется сразу сменить пароль: открыть профиль пользователя в левом меню → ввести текущий пароль (Current password) → указать новый (New password) и подтвердить (Confirm password) → Save. Требования к паролю могут задаваться в настройках безопасности ADCM.

**Установка URL ADCM:** для корректного обмена данными между ADCM и развёрнутыми кластерами (отправка статусов компонентов в ADCM) должен быть задан **внешний URL ADCM**. Если при создании контейнера не была указана переменная **DEFAULT_ADCM_URL**, URL задают вручную: в левом меню выбрать **Settings** → раскрыть узел **Global Options** → нажать на значение поля **ADCM's URL** → в открывшемся окне ввести URL в формате `http://<IP_или_имя_хоста>:8000/` → Apply → Save. Этот URL должен быть доступен с хостов кластеров (по нему они отправляют heartbeat и события в ADCM).

После входа в интерфейсе доступны разделы: Clusters (список кластеров), Bundles (загрузка и управление бандлами), Hostproviders (хостпровайдеры для добавления хостов), Settings и др. Следующий шаг — загрузить бандл Arenadata DB, создать хостпровайдер и кластер, добавить хосты и выполнить Mapping и установку ([§3.3](chapter-03-03.md), [§3.4](chapter-03-04.md)).

## 3.2.5. Типичные ошибки при установке ADCM

- **Не монтировать том для /adcm/data:** при пересоздании контейнера без тома все данные ADCM (конфигурации кластеров, бандлы, состояние) будут потеряны. Всегда использовать `-v` с каталогом хоста или именованным томом и при необходимости настраивать бэкапы.
- **Использовать тег latest:** с ADCM 2.0.0 тег `latest` не поддерживается; указывать явную версию (например, `2.7.1` или `2.7`).
- **Забыть указать ADCM's URL:** если кластеры не могут достучаться до ADCM по умолчанию (разные сети, NAT, другое имя хоста), статусы компонентов не будут обновляться. Задать URL в Settings → Global Options после первого входа.
- **Не сменить пароль admin:** оставшийся пароль `admin` создаёт риски при доступе к веб-интерфейсу из сети; сменить его сразу после первого входа.
- **Не проверить доступность порта 8000 с хостов кластеров:** если ADCM за firewall или на другом сегменте сети, убедиться, что с будущих сегмент-хостов и координатора доступен URL ADCM (curl или браузер).

## Ключевое

- **Дистрибутив:** Docker-образ `hub.arenadata.io/adcm/adcm:<версия>` (online); для offline (Enterprise) — архив со скриптом от поддержки Arenadata; бандлы продуктов (в т.ч. ADB) — с [network.arenadata.io](https://network.arenadata.io/), загружаются в ADCM после установки.
- **Установка:** `docker pull` → `docker create` с `-p 8000:8000`, `-v /opt/adcm:/adcm/data`, переменными для внешней БД (DB_HOST, DB_PORT, DB_USER, DB_NAME, DB_PASS); при SELinux — `:Z` для тома; затем `docker start`. Альтернатива — ADCM Installer (`adi init --adpg`, `adi apply`) с встроенной PostgreSQL.
- **Проверка:** `docker container ls` (STATUS Up), `netstat`/`curl` по порту 8000, доступ к http://<хост>:8000/.
- **Первый вход:** логин `admin`, пароль `admin`; сменить пароль в профиле; при необходимости задать **ADCM's URL** в Settings → Global Options (`http://<хост>:8000/`) для корректной работы кластеров с ADCM.

В [§3.3](chapter-03-03.md) мы разберём конфигурацию кластера в ADCM: добавление хостов, определение Master и Segments, настройка параметров и шаблоны перед развёртыванием.
