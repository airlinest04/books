# §8.3 Преобразование и загрузка в Hive

В [§8.2](chapter-08-02.md) мы настроили извлечение из Parquet/ORC. В этом разделе добавляются **преобразования** в потоке (Spark SQL, Join, Aggregation при необходимости) и **приёмник Hive**: запись результата в таблицу Staging. Получается полная цепочка «источник → трансформации → приёмник» для сценария главы 8; в [§8.4](chapter-08-04.md) соберём Workflow и проверку результатов. См. [Глоссарий](glossary.md).

## 8.3.1. Преобразования в потоке

После источника (DataFrame из Parquet/ORC) в поток подключаются **трансформации** — элементы, меняющие данные по шагам. Выбор типа трансформации зависит от задачи ([§4.1](chapter-04-01.md)–[§4.3](chapter-04-03.md)):

- **Фильтрация** — отбор строк по условию (валидные записи, отсечение по дате, дедупликация при необходимости). Реализуется элементом «Фильтр» (условие) или в Spark SQL через WHERE.
- **Маппинг полей** — переименование столбцов, приведение типов, вычисляемые поля (выражения, формулы). Элемент «Выражение» или «Маппинг»; при сложной логике — Spark SQL с SELECT и выражениями.
- **Spark SQL** — один SQL-запрос над входным DataFrame: фильтр, проекция, вычисляемые столбцы, при необходимости GROUP BY и агрегация. Удобно, когда логика укладывается в один запрос; вход регистрируется как temp view, запрос выполняется через `spark.sql(...)` ([§4.1](chapter-04-01.md)).
- **Join** — соединение с другим набором данных (справочник, другая таблица). В потоке добавляется второй источник (например, Hive-таблица справочника) или читается из предыдущего шага; элемент Join задаёт ключи и тип соединения (inner, left и т.д.) ([§4.2](chapter-04-02.md)).
- **Aggregation** — группировка и агрегатные функции (sum, count, max и т.д.). Используется, когда в Staging нужны не построчные данные, а сводки; для построчной загрузки агрегация не требуется.

Для типового сценария «Raw → Staging» часто достаточно: фильтрация невалидных строк, маппинг имён/типов под целевую схему, при необходимости один Join со справочником и один блок Spark SQL для расчётных полей. Агрегация — если целевая таблица витрина (агрегаты по измерениям). Порядок элементов в дизайнере задаёт порядок выполнения: источник → фильтр → маппинг или Spark SQL → при необходимости Join → приёмник.

## 8.3.2. Spark SQL, Join и Aggregation для сценария

**Spark SQL** в нашем пайплайне можно использовать для: отбора полей и переименования; фильтрации по условию (например, `WHERE status IS NOT NULL AND amount >= 0`); вычисляемых полей (`CASE WHEN`, функции дат, приведение типов). Входной DataFrame из источника регистрируется как временное представление; в запросе указывается целевая схема и логика. Итог — DataFrame с полями, совместимыми с целевой Hive-таблицей. Детали синтаксиса и поддержки — [§4.1](chapter-04-01.md).

**Join** нужен, когда данные из Raw нужно обогатить справочником (например, код региона → название региона). Справочник читается из второго источника (Hive-таблица или файл); в дизайнере добавляется элемент Join с указанием ключей соединения и типа (inner/left). Результат Join — DataFrame с полями из основного потока и из справочника; лишние столбцы при необходимости отбрасываются в следующей трансформации или в Spark SQL. Если обогащение не требуется, Join не добавляется.

**Aggregation** — если целевая таблица Staging должна содержать не построчные записи, а сводки (например, суммы по дням и регионам). Добавляется элемент Aggregation: указываются ключи группировки (GROUP BY) и агрегатные функции по мерным полям (sum, count, max и т.д.). Выход — сгруппированный DataFrame; схема приёмника должна соответствовать полям после агрегации. Для построчной загрузки «как есть» с лёгкой очисткой агрегация не используется. Подробнее Join и Aggregation в дизайнере — [§4.2](chapter-04-02.md).

## 8.3.3. Настройка приёмника Hive

**Приёмник Hive** — последний элемент потока: запись результата трансформаций в Hive-таблицу ([§3.4](chapter-03-04.md)). В дизайнере добавляется элемент «Приёмник» типа Hive и настраивается:

- **Подключение к Hive** — используется конфигурация кластера (Hive Metastore); при необходимости в настройках приёмника указывается база данных (schema).
- **Имя таблицы** — в формате `database.table`, например `staging.events`. Таблица может существовать заранее (схема должна совпадать с полями выходящего DataFrame) или создаваться при первой записи, если платформа и Spark это поддерживают.
- **Режим записи** — **overwrite** (перезапись) или **append** (добавление). Для партиционированных по дате таблиц типично: перезапись одной партиции (партиция за дату среза) или добавление новой партиции; при перезаписи всей таблицы данные за все даты будут заменены. Выбор зависит от политики обновления Staging.
- **Партиционирование** — если таблица партиционирована (например, по `date`), указывается столбец партиции; запись создаёт или обновляет партицию с соответствующим значением. Поле партиции должно присутствовать в выходном DataFrame (оно могло прийти из источника как партиционный столбец или добавлено в трансформации).

Сгенерированный код использует `df.write.format("hive")` (или запись через Spark в Hive-таблицу в зависимости от конфигурации) с указанием режима и партиционирования. После настройки приёмника поток замкнут: источник → трансформации → приёмник Hive. Сборка проекта и запуск — по главе 7; следующий шаг — оформить этот поток как этап Workflow и добавить проверку ([§8.4](chapter-08-04.md)).

## Ключевое

- **Преобразования:** фильтрация, маппинг, Spark SQL (очистка, вычисляемые поля), при необходимости Join со справочником и Aggregation для сводок; порядок элементов задаёт порядок выполнения в потоке.
- **Spark SQL, Join, Aggregation** — типовые инструменты для слоя Staging; выбор зависит от требований (построчная загрузка vs сводки, наличие обогащения справочниками).
- **Приёмник Hive:** база и таблица (например, `staging.events`), режим записи (overwrite/append), партиционирование по полю; схема выхода потока должна совпадать с целевой таблицей.

В [§8.4](chapter-08-04.md) мы соберём Workflow: последовательность этапов (при необходимости несколько потоков), запуск и сверка данных.
