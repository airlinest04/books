# §4.2 Реляционная алгебра: Join, Sort, Aggregation

В [§4.1](chapter-04-01.md) мы разобрали Spark SQL как трансформацию в потоке. В этом разделе рассматриваются операции **реляционной алгебры** в визуальном представлении Neoflex Datagram: **Join** (соединение), **Sort** (сортировка) и **Aggregation** (агрегация). Эти операции — базовые строительные блоки ETL: объединение потоков по ключу, упорядочивание и группировка с вычислением итогов. В дизайнере они задаются отдельными элементами с настройкой ключей, порядка и агрегатных функций; генератор производит соответствующие вызовы Spark (join, orderBy, groupBy/agg). В [§4.3](chapter-04-03.md) мы перейдём к маппингу и преобразованию полей. См. [Глоссарий](glossary.md).

---

## 4.2.1. Join (соединение)

**Join** (соединение) — операция объединения двух наборов данных по **ключу** или по **условию**: каждая строка одного набора сопоставляется со строками другого, удовлетворяющими условию; результат содержит комбинации строк (или подмножество при фильтрации). В реляционной алгебре и в Spark различают типы соединений по тому, какие строки сохраняются при отсутствии совпадения:

| Тип | Описание | Результат |
|-----|----------|-----------|
| **Inner** | Только совпадающие строки | Строки из левого и правого набора, где условие выполнено |
| **Left (Left Outer)** | Все строки левого набора | Совпадения + строки левого без совпадения (правые поля — null) |
| **Right (Right Outer)** | Все строки правого набора | Совпадения + строки правого без совпадения (левые поля — null) |
| **Full (Full Outer)** | Все строки обоих наборов | Совпадения + несовпадающие слева и справа (соответствующие поля — null) |

В дизайнере трансформаций элемент **Join** имеет два входа (левый и правый поток) и один выход. Настраиваются: **ключи соединения** — столбцы или выражения левого и правого набора, по которым выполняется сравнение (равенство или иное условие); **тип соединения** (inner, left, right, full). При равенстве по одному или нескольким столбцам ключи задаются списком пар (left_col, right_col) или одним именем, если имена совпадают. В сгенерированном коде это соответствует `left_df.join(right_df, join_condition, join_type)` в Spark (например, `"inner"`, `"left"`, `"left_outer"`). Имена столбцов в результате при совпадении могут быть квалифицированы префиксом или переименованы в последующей трансформации маппинга ([§4.3](chapter-04-03.md)).

Типичное использование: обогащение основного потока справочником (lookup) по ключу; слияние двух выгрузок по идентификатору; объединение потоков из разных источников перед агрегацией. При больших справочниках возможна оптимизация (broadcast join) — настройки зависят от платформы и конфигурации Spark.

## 4.2.2. Sort (сортировка)

**Sort** (сортировка) — упорядочивание строк набора данных по одному или нескольким **ключам сортировки** в порядке возрастания (ASC) или убывания (DESC). В Spark операция реализуется через `orderBy` или `sort`; при распределённом выполнении данные могут быть перераспределены (shuffle) по ключам сортировки, чтобы гарантировать глобальный порядок, либо сортировка выполняется внутри партиций (менее затратно, но порядок только локальный — в зависимости от API).

В дизайнере элемент **Sort** имеет один вход и один выход. Задаётся список столбцов (или выражений) и для каждого — направление (ASC/DESC). Порядок столбцов в списке определяет приоритет: сначала по первому ключу, при равенстве — по второму и т.д. Сгенерированный код: `df.orderBy(col1.asc, col2.desc, ...)` или эквивалент в Spark SQL. Сортировка часто применяется перед агрегацией с окном (оконные функции) или перед записью в приёмник, когда нужен определённый порядок строк (например, для детерминированной выборки «первых N по группе» через последующую трансформацию).

Ограничение: полная глобальная сортировка больших данных требует shuffle и может быть дорогой; при необходимости сортировки только внутри партиций используется иной подход (партиционирование по ключу и sortWithinPartitions). Поддержка таких опций в дизайнере уточняйте в документации Neoflex.

## 4.2.3. Aggregation (агрегация)

**Aggregation** (агрегация) — группировка строк по одному или нескольким **ключевым полям** и вычисление **агрегатных функций** (SUM, AVG, COUNT, MIN, MAX и др.) по группам. Результат: одна строка на группу с ключами группы и вычисленными значениями. В реляционной алгебре это операция группировки (GROUP BY); в Spark — `groupBy(...).agg(...)` или Spark SQL с GROUP BY.

В дизайнере элемент **Aggregation** имеет один вход и один выход. Настраиваются: **ключи группировки** — столбцы, по которым строки объединяются в группы; **агрегатные выражения** — для каждого результата указываются функция (SUM, AVG, COUNT, MIN, MAX, при поддержке — стандартное отклонение, коллекции и т.д.) и исходный столбец (или выражение). Имена результирующих столбцов задаются в настройках или формируются по шаблону. Сгенерированный код: `df.groupBy("key1", "key2").agg(sum("amount"), avg("value"), count("*"))` или эквивалент в SQL. Типичное использование: расчёт итогов по периодам, регионам, категориям; сводные таблицы для витрин; дедупликация по ключу с выбором одной записи (например, max(version)).

Комбинация Join и Aggregation — частый паттерн: обогащение потока справочником (Join), затем агрегация по ключам для получения показателей по измерениям.

## 4.2.4. Визуальное представление и соответствие Spark

В графе потока дизайнера элементы **Join**, **Sort** и **Aggregation** отображаются как блоки с входами и выходом. Join имеет два входящих связи (левый и правый поток); Sort и Aggregation — по одному входу. Выход каждого элемента подключается к следующей трансформации или к приёмнику. Схема на выходе (список полей и типов) определяется типом операции: Join даёт объединённые столбцы обоих входов (с возможными дубликатами имён); Sort сохраняет схему входа; Aggregation — ключи группировки плюс столбцы агрегатных функций. Lineage ([§5.2](chapter-05-02.md)) позволяет проследить происхождение полей после соединения и агрегации.

Соответствие элементам Spark API:

| Элемент Datagram | Типичный код Spark |
|------------------|--------------------|
| Join (inner/left/right/full) | `left.join(right, condition, "inner"|"left"|"right"|"full")` |
| Sort | `df.orderBy(col1.asc, col2.desc)` |
| Aggregation | `df.groupBy(keyCols).agg(expr1, expr2, ...)` |

Детали имён столбцов, обработки null и тонкости типов соединения (например, cross join при отсутствии условия) зависят от настроек в дизайнере и от шаблонов генератора. При построении потока с join и агрегацией для закрепления материала см. задание в TOC главы 4: построить поток с join и агрегацией.

## Ключевое

- **Join** — объединение двух потоков по ключу или условию; типы inner, left, right, full. В дизайнере: два входа, настройка ключей и типа соединения; код — `DataFrame.join(...)`.
- **Sort** — упорядочивание по одному или нескольким ключам (ASC/DESC). Один вход; код — `orderBy`/`sort`. Глобальная сортировка может требовать shuffle.
- **Aggregation** — группировка по ключевым полям и вычисление агрегатных функций (SUM, AVG, COUNT, MIN, MAX и др.). Один вход; код — `groupBy(...).agg(...)`.
- **Визуальное представление:** Join — два входа, один выход; Sort и Aggregation — один вход, один выход. Схема выхода определяется операцией; lineage отражает происхождение полей.

В [§4.3](chapter-04-03.md) мы разберём маппинг и преобразование полей: переименование, вычисляемые выражения и фильтрация в визуальных элементах потока.
