# §7.4 Представления и материализованные представления

В [§7.3](chapter-07-03.md) мы рассмотрели иерархические запросы (CONNECT BY). **Представление (VIEW)** — сохранённый в базе именованный запрос SELECT; при обращении к нему выполняется этот запрос, результат выглядит как таблица. **Материализованное представление** хранит результат запроса в виде данных (таблицы); данные обновляются по расписанию или по требованию (REFRESH). В этом разделе — **CREATE VIEW**, обновляемые и только для чтения представления, затем **CREATE MATERIALIZED VIEW**, обновление (REFRESH) и типичное применение. Глава 7 на этом завершается; далее [глава 8](chapter-08-01.md): транзакции и целостность. См. [Глоссарий](glossary.md).

---

## 7.4.1. Представление (VIEW)

**Представление** — объект базы данных (VIEW): именованный запрос SELECT, сохранённый в словаре. При выборке из представления (SELECT * FROM имя_представления) Oracle подставляет определение запроса и выполняет его над базовыми таблицами; данные не копируются — каждый раз результат вычисляется заново. Представление упрощает сложные запросы, ограничивает набор столбцов и строк для прав доступа, сохраняет единую точку изменения логики. См. [Глоссарий](glossary.md).

Синтаксис создания:

```sql
CREATE [OR REPLACE] VIEW [схема.]имя_представления [(столбец1, столбец2, ...)] AS
  подзапрос
  [WITH READ ONLY]
  [WITH CHECK OPTION [CONSTRAINT имя]];
```

**OR REPLACE** — пересоздать представление, если оно уже существует. Список столбцов после имени задаёт имена колонок результата; если не указывать, используются имена из подзапроса. **WITH READ ONLY** — запрет DML через представление (только SELECT). **WITH CHECK OPTION** — при INSERT/UPDATE через представление проверять, что новые строки попадают в результат подзапроса (иначе операция отклоняется). См. [Глоссарий](glossary.md).

Пример: представление «подтверждённые заказы с суммой больше 100»:

```sql
CREATE OR REPLACE VIEW confirmed_big_orders AS
  SELECT order_id, customer_id, order_date, total
    FROM orders
   WHERE status = 'CONFIRMED' AND total > 100;
```

Далее: `SELECT * FROM confirmed_big_orders`. Удаление: **DROP VIEW имя_представления**. Среда: Oracle Database.

## 7.4.2. Обновление через представление и ограничения

Если представление построено на одной таблице (или на соединении с определёнными правилами) и не содержит группировки, DISTINCT, агрегатов, подзапросов в SELECT и т.п., через него может быть разрешён **INSERT**, **UPDATE** или **DELETE**: изменения переводятся в операции над базовыми таблицами. Такие представления называют **обновляемыми**. В сложных случаях (несколько таблиц, агрегаты, JOIN) Oracle часто не позволяет DML через представление; тогда создают **INSTEAD OF**-триггер (в PL/SQL) или работают с базовыми таблицами. См. [Глоссарий](glossary.md).

**WITH CHECK OPTION** гарантирует: строки, вставленные или изменённые через представление, после операции останутся видимыми при SELECT из этого представления. Иначе пользователь мог бы вставить строку с status != 'CONFIRMED' и она не попала бы в результат представления. **WITH READ ONLY** полностью отключает DML — представление только для чтения.

## 7.4.3. Материализованное представление

**Материализованное представление** — объект Oracle, хранящий **результат запроса как данные** в своей сегментной структуре (как таблица). Запрос выполняется при создании и при обновлении (REFRESH); в остальное время выборка из материализованного представления читает уже сохранённые данные, без повторного выполнения сложного запроса. Применяется для отчётов, денормализации, кэширования агрегатов и ускорения тяжёлых запросов. См. [Глоссарий](glossary.md).

Синтаксис (упрощённо):

```sql
CREATE MATERIALIZED VIEW [схема.]имя
  [BUILD IMMEDIATE | BUILD DEFERRED]
  [REFRESH [FAST | COMPLETE | FORCE] [ON DEMAND | ON COMMIT]]
  [ON PREBUILT TABLE]
  AS подзапрос;
```

- **BUILD IMMEDIATE** (по умолчанию) — заполнить при создании; **BUILD DEFERRED** — при первом REFRESH.
- **REFRESH** — способ обновления данных. **COMPLETE** — полное перевыполнение запроса и перезапись данных. **FAST** — инкрементальное обновление (требует журналов материализованного представления, не для всех запросов). **FORCE** — на усмотрение Oracle (FAST при возможности, иначе COMPLETE). **ON DEMAND** — обновление по вызову (REFRESH вручную или по расписанию). **ON COMMIT** — обновление при COMMIT в базовых таблицах (ограничения по типу запроса).
- После создания обновление: **DBMS_MVIEW.REFRESH('имя')** или **EXEC DBMS_MVIEW.REFRESH('имя')**; для расписания — **DBMS_SCHEDULER** или **DBMS_JOB**. См. [Глоссарий](glossary.md).

Пример: сводка по отделам (сумма зарплат), обновление по требованию:

```sql
CREATE MATERIALIZED VIEW mv_dept_salary AS
  SELECT department_id, SUM(salary) AS total_sal, COUNT(*) AS emp_cnt
    FROM employees
   GROUP BY department_id
   REFRESH FORCE ON DEMAND;
```

Первый REFRESH (или при BUILD IMMEDIATE) заполнит данные. Далее: `EXEC DBMS_MVIEW.REFRESH('mv_dept_salary');` — данные пересчитаются. Среда: Oracle Database.

## 7.4.4. Когда использовать VIEW и когда материализованное представление

**VIEW** — когда нужен актуальный результат «на сейчас», запрос выполняется приемлемо быстро или важен единый источник прав и логики. Не занимает место под копию данных (кроме метаданных).

**Материализованное представление** — когда запрос тяжёлый (агрегация по большим таблицам, сложные соединения), а допустима некоторая задержка актуальности. Данные хранятся, выборка быстрая; обновление — по расписанию или по событию. Учитывайте место на диске и время REFRESH.

Для отчётов с агрегацией по истории часто создают материализованное представление с REFRESH ON DEMAND по ночи; днём пользователи читают уже готовые данные. См. [Глоссарий](glossary.md).

---

## Ключевое

- **Представление (VIEW)** — сохранённый именованный запрос SELECT; при обращении запрос выполняется над базовыми таблицами, данные не хранятся отдельно. CREATE VIEW ... AS подзапрос; WITH READ ONLY, WITH CHECK OPTION. См. [Глоссарий](glossary.md).
- **Материализованное представление** — результат запроса хранится как данные; обновляется через REFRESH (COMPLETE, FAST, FORCE; ON DEMAND или ON COMMIT). Ускоряет тяжёлые запросы при допустимой задержке актуальности. См. [Глоссарий](glossary.md).
- VIEW не копирует данные; материализованное представление занимает место и требует периодического REFRESH. Выбор зависит от требований к актуальности и производительности.
