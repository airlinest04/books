# §4.3 Подзапросы в FROM

В [§4.2](chapter-04-02.md) мы разобрали подзапросы в WHERE: скалярный подзапрос, IN, EXISTS, сравнения с подзапросом. Подзапрос можно использовать и в **FROM**: вместо имени таблицы указать **запрос в скобках**, результат которого внешний запрос трактует как **источник строк** (как таблицу). Такой подзапрос называют **встроенным представлением (inline view)** или производной таблицей. В этом разделе рассмотрим синтаксис подзапроса в FROM, **обязательный псевдоним** в Oracle и типичные сценарии использования. Подзапросы в списке SELECT — в [§4.4](chapter-04-04.md). См. [Глоссарий](glossary.md).

---

## 4.3.1. Подзапрос как источник строк

В предложении **FROM** можно указать не только таблицу или представление, но и **подзапрос в скобках** — запрос SELECT, результат которого используется как набор строк. Внешний запрос обращается к столбцам этого набора по именам столбцов подзапроса (или по псевдонимам, заданным в подзапросе). См. [Глоссарий](glossary.md).

Синтаксис:

```sql
SELECT ... FROM (подзапрос) псевдоним [JOIN ...] [WHERE ...];
```

В Oracle **псевдоним для подзапроса в FROM обязателен**. Без него возникает ошибка. Псевдоним задаётся после закрывающей скобки подзапроса (через пробел или AS). Далее к столбцам обращаются через этот псевдоним: **псевдоним.имя_столбца**. Пример:

```sql
SELECT t.order_id, t.total
  FROM (SELECT order_id, customer_id, total FROM orders WHERE status = 'CONFIRMED') t
 WHERE t.total > 100;
```

Внутренний запрос возвращает подмножество заказов (подтверждённые); внешний фильтрует их по сумме. Подзапрос в FROM даёт «временную» таблицу с результатом внутреннего запроса; у неё нет имени в словаре данных — только псевдоним в рамках запроса.

## 4.3.2. Зачем использовать подзапрос в FROM

Типичные случаи:

- **Фильтрация по результату агрегации:** например, «клиенты, у которых количество заказов больше 5». Сначала подзапрос считает количество заказов по клиентам (GROUP BY customer_id), затем внешний запрос отбирает тех, у кого это число > 5. Условие по результату групповой функции (COUNT, SUM и т.д.) в SQL нельзя задать в WHERE той же таблицы — только через подзапрос в FROM или HAVING в том же уровне GROUP BY (HAVING применяется к группам; для сложной логики удобен подзапрос).
- **Пошаговая логика:** разбить сложный запрос на шаги: внутренний запрос готовит данные (соединения, вычисления, отбор), внешний — дополнительно фильтрует, сортирует или соединяет с другими таблицами.
- **Ограничение доступа к данным:** подзапрос возвращает только нужные столбцы и строки; внешний запрос работает уже с этим набором.
- **Обход ограничений:** в части ситуаций нельзя ссылаться на псевдоним столбца в WHERE того же уровня; подзапрос создаёт новый уровень, и к его столбцам можно обращаться по псевдониму во внешнем WHERE.

См. [Глоссарий](glossary.md).

## 4.3.3. Пример: агрегация в подзапросе и фильтр снаружи

Запрос: категории товаров, у которых средняя цена выше 50.

Средняя цена по категории считается агрегатной функцией (AVG), значит, нужен GROUP BY category_id. Отбор по условию «средняя цена > 50» делается уже по результату группировки. Подзапрос считает среднюю цену по категориям; внешний запрос отбирает строки по условию:

```sql
SELECT cat_id, avg_price
  FROM (SELECT category_id AS cat_id, AVG(price) AS avg_price
          FROM products
         GROUP BY category_id) sub
 WHERE sub.avg_price > 50;
```

В подзапросе заданы псевдонимы столбцов (cat_id, avg_price), чтобы во внешнем запросе было удобно на них ссылаться. Псевдоним подзапроса — sub; обращение sub.avg_price в WHERE корректно. Без подзапроса условие WHERE avg_price > 50 на уровне таблицы products было бы неверным (avg_price там нет). См. [Глоссарий](glossary.md).

## 4.3.4. Подзапрос в FROM и JOIN

Подзапрос в FROM можно **соединять** с другими таблицами или с другими подзапросами через JOIN ... ON. Псевдоним подзапроса используется в условии ON и в списке SELECT. См. [Глоссарий](glossary.md).

Пример: заказы с суммой выше средней по клиенту; средняя по клиенту считается в подзапросе, затем происходит соединение с таблицей заказов:

```sql
SELECT o.order_id, o.customer_id, o.total, sub.avg_total
  FROM orders o
  JOIN (SELECT customer_id, AVG(total) AS avg_total
          FROM orders
         GROUP BY customer_id) sub
    ON o.customer_id = sub.customer_id
 WHERE o.total > sub.avg_total;
```

Подзапрос sub даёт для каждого customer_id среднюю сумму заказа; внешний запрос соединяет заказы с этим набором по customer_id и оставляет только те заказы, где total больше средней по данному клиенту.

## 4.3.5. Несколько подзапросов в FROM

В одном FROM можно перечислить несколько подзапросов и соединить их через запятую (старый стиль) или через JOIN. Каждому подзапросу нужен свой псевдоним. См. [Глоссарий](glossary.md).

Пример с JOIN:

```sql
SELECT a.id, a.name, b.cnt
  FROM (SELECT id, name FROM customers WHERE status = 'ACTIVE') a
  JOIN (SELECT customer_id, COUNT(*) AS cnt FROM orders GROUP BY customer_id) b
    ON a.id = b.customer_id;
```

Первый подзапрос — активные клиенты, второй — количество заказов по клиентам; соединение по id/customer_id.

## 4.3.6. Типичные ошибки при использовании подзапроса в FROM

- **Забыть псевдоним в Oracle:** в Oracle подзапрос в FROM обязан иметь псевдоним. Иначе ошибка «ORA-00933: SQL command not properly ended» или аналогичная. Всегда указывайте имя после закрывающей скобки.
- **Обращаться к столбцу без псевдонима при нескольких источниках:** если в FROM два и более источника (таблицы или подзапроса), имена столбцов могут совпадать. Нужно указывать псевдоним.столбец.
- **Путать уровни WHERE:** условие, относящееся к данным **до** группировки (фильтр по строкам таблицы), задаётся в WHERE внутри подзапроса; условие по **результату** группировки (по агрегату) — в WHERE внешнего запроса или в HAVING внутри подзапроса.
- **Считать подзапрос материализованным:** оптимизатор может переписать запрос и не материализовать подзапрос отдельно. С точки зрения результата подзапрос в FROM ведёт себя как источник строк с заданными именами столбцов и псевдонимом.

## Ключевое

- **Подзапрос в FROM** — запрос SELECT в скобках на месте таблицы; его результат используется как набор строк. В Oracle такому подзапросу **обязательно** задаётся **псевдоним** после скобки.
- Обращение к столбцам результата подзапроса — по именам столбцов (или псевдонимам столбцов из подзапроса) с префиксом псевдонима: **псевдоним.столбец**.
- Подзапрос в FROM используют для: фильтрации по результату агрегации (GROUP BY внутри, условие по агрегату снаружи), пошаговой логики, соединения с другими таблицами или подзапросами через JOIN.
- Условие по строкам исходных данных — в WHERE подзапроса; условие по результату группировки — в HAVING подзапроса или в WHERE внешнего запроса по столбцам подзапроса.
- Подзапрос в FROM можно соединять с таблицами и другими подзапросами; каждому источнику в FROM нужен псевдоним при неоднозначности имён.

В [§4.4](chapter-04-04.md) мы разберём подзапросы в списке SELECT: скалярный подзапрос в качестве столбца (одна строка, один столбец).
