# §1.2 Подключение к базе

В [§1.1](chapter-01-01.md) мы разобрали экосистему Oracle: сервер (СУБД), схемы и пользователи, табличные пространства и клиенты. Чтобы выполнять SQL и PL/SQL, нужно установить соединение с сервером под учётной записью пользователя. В этом разделе мы разберём, как формируется **строка подключения** (хост, порт, имя службы или SID), какие способы задания подключения поддерживает Oracle (в том числе **Easy Connect** без файлов конфигурации), а также какие **роли и привилегии** нужны пользователю для входа в базу и работы с объектами своей схемы. После этого вы сможете подключаться через SQL*Plus или SQL Developer и перейти к просмотру объектов схемы в [§1.3](chapter-01-03.md). См. [Глоссарий](glossary.md).

---

## 1.2.1. Что нужно для подключения

Для установления соединения клиент должен передать серверу Oracle следующее.

1. **Сетевой адрес сервера:** хост (имя или IP) и порт, на котором слушает **Oracle Net Listener** (по умолчанию порт 1521). Listener принимает входящие подключения и перенаправляет их к экземпляру базы данных.
2. **Идентификатор базы:** имя службы (**service name**) или **SID** (System Identifier) экземпляра. В современных установках обычно используется service name; он регистрируется в listener при старте базы. Без правильного service name или SID подключение к нужной базе не установится.
3. **Учётные данные:** имя пользователя и пароль (или иной способ аутентификации, если настроен администратором).

Совокупность параметров, задающих, *куда* подключаться (хост, порт, service name/SID), часто называют **строкой подключения** или **connect string** (идентификатор подключения). Учётные данные (логин/пароль) могут входить в одну команду или запрос вместе со строкой подключения либо запрашиваться отдельно. См. [Глоссарий](glossary.md).

---

## 1.2.2. Строка подключения: Easy Connect

Способ **Easy Connect** (лёгкое подключение) позволяет указать хост, порт и имя службы прямо в одной строке, без создания файлов `tnsnames.ora` или иной конфигурации имён. Он подходит для простых окружений по TCP/IP и по умолчанию поддерживается клиентами Oracle. См. [Глоссарий](glossary.md).

По документации Oracle ([Configuring Naming Methods](https://docs.oracle.com/en/database/oracle/oracle-database/19/netag/configuring-naming-methods.html)) синтаксис Easy Connect имеет вид:

```
[//]host[:port][/service_name]
```

- **host** — обязательный: имя хоста или IP-адрес сервера базы данных.
- **port** — необязательный: порт listener’а. По умолчанию используется **1521**.
- **service_name** — необязательный: имя службы базы (например, имя базы при установке в типичном режиме). Если не указано, listener может использовать службу по умолчанию из своей конфигурации; при отсутствии такой настройки потребуется явно указать service name.

Префикс `//` допустим (часто используется в URL-подобных строках и в JDBC); для SQL*Plus и обычного CONNECT он не обязателен.

**Примеры (логин и пароль вводятся отдельно или после @):**

- Подключение по имени хоста с портом и службой:
  ```
  username@dbserver:1521/ORCL
  ```
  Здесь `dbserver` — хост, `1521` — порт, `ORCL` — имя службы.

- Только хост (порт 1521 и служба по умолчанию у listener’а):
  ```
  username@dbserver
  ```

- С префиксом `//` (эквивалентно по смыслу):
  ```
  username@//dbserver:1521/ORCL
  ```

В **SQL*Plus** подключение задаётся так:

```bash
sqlplus username@dbserver:1521/ORCL
```

После запроса пароль вводится с клавиатуры. Вариант с паролем в командной строке (менее безопасный):

```bash
sqlplus username/password@dbserver:1521/ORCL
```

В **SQL Developer** при создании соединения в полях «Host», «Port», «Service name» указываются те же значения: хост, 1521 (или другой порт), имя службы. Внутренне формируется та же строка подключения.

Если подключение не устанавливается, типичные причины: неверный хост или порт (listener не достижим), неверное имя службы (служба не зарегистрирована в listener), сетевые ограничения ( firewall ), неверный пользователь или пароль. Хост, порт и имя службы обычно сообщает администратор базы или можно посмотреть в конфигурации listener’а на сервере.

## 1.2.3. Строка подключения: TNS и tnsnames.ora

В более сложных или корпоративных окружениях используется **локальный способ имён (Local Naming)**: в файле **tnsnames.ora** задаётся короткое **сетевое имя (net service name)** и соответствующий ему **connect descriptor** — полное описание адреса и службы. См. [Глоссарий](glossary.md).

Пример записи в `tnsnames.ora`:

```
ORCL =
  (DESCRIPTION =
    (ADDRESS = (PROTOCOL = TCP)(HOST = dbserver)(PORT = 1521))
    (CONNECT_DATA =
      (SERVICE_NAME = ORCL)
    )
  )
```

Здесь сетевое имя — `ORCL`; при подключении клиент подставляет описание (протокол TCP, хост, порт, SERVICE_NAME). Подключение в SQL*Plus тогда выглядит так:

```bash
sqlplus username/password@ORCL
```

То есть вместо `host:port/service_name` указывается только имя из `tnsnames.ora`. Файл `tnsnames.ora` может находиться в каталоге, заданном переменной окружения `TNS_ADMIN`, или в стандартном месте установки Oracle (например, `$ORACLE_HOME/network/admin`).

**Когда уместен TNS:** несколько баз или сложная топология (несколько адресов, резервирование), единая конфигурация для многих клиентов, необходимость параметров, которые Easy Connect не покрывает. Для обучения и простого доступа к одной базе обычно достаточно Easy Connect. В этой книге мы опираемся на Easy Connect; при наличии готового `tnsnames.ora` можно использовать сетевое имя из него так же, как в примере выше.

## 1.2.4. Service name и SID

**Service name** (имя службы) — логическое имя службы базы данных, под которым она регистрируется в listener’е. Одна база может регистрировать несколько служб (например, для разных приложений или для RAC). Клиент подключается к *службе*, а не к экземпляру напрямую. В типичной установке с одной базой имя службы часто совпадает с именем базы (например, `ORCL`, `XEPDB1` в контейнерной архитектуре 12c+). См. [Глоссарий](glossary.md).

**SID** (System Identifier) — идентификатор экземпляра Oracle. В конфигурациях с одним экземпляром на сервере SID часто совпадает с именем базы. Раньше подключение часто задавали через SID; в connect descriptor это выглядело как `(SID = ORCL)` вместо `(SERVICE_NAME = ORCL)`. В современных версиях Oracle и при использовании динамической регистрации служб в listener предпочтительно указывать **SERVICE_NAME**; SID используется в отдельных сценариях (например, подключение к конкретному экземпляру в RAC). Если администратор дал вам «имя базы» или «имя службы» — в Easy Connect и в tnsnames.ora обычно подставляется именно service name.

Узнать имена зарегистрированных служб на сервере можно запросом к listener’у (`lsnrctl status`) или из представлений словаря данных при уже установленном подключении (например, `SELECT name FROM v$services;`). Для повседневной работы достаточно знать service name, который выдал администратор.

## 1.2.5. Роли и привилегии: что нужно для входа и работы

Подключиться к базе может только пользователь, которому предоставлено право **создавать сессию**. Это право даёт привилегия **CREATE SESSION**. Без неё при попытке входа Oracle вернёт ошибку вроде «ORA-01045: user ... lacks CREATE SESSION privilege». См. [Глоссарий](glossary.md).

**Привилегия** — право выполнять определённое действие (подключиться, создать таблицу, выбрать данные из таблицы другого пользователя и т.д.). **Роль** — именованный набор привилегий; пользователю выдают роль, и он получает все привилегии этой роли. См. [Глоссарий](glossary.md).

Предопределённые роли Oracle, часто используемые для обычных пользователей:

| Роль | Содержимое (кратко) | Назначение |
|------|----------------------|------------|
| **CONNECT** | В современных версиях (10.2 и позже) — по сути только **CREATE SESSION** (в 12.1+ добавлен SET CONTAINER для контейнеров). | Возможность подключиться к базе. |
| **RESOURCE** | Привилегии на создание объектов в своей схеме (CREATE TABLE, CREATE SEQUENCE, CREATE PROCEDURE и др.) и **UNLIMITED TABLESPACE** (использование табличных пространств без квоты). | Разработка: создание таблиц, последовательностей, процедур в своей схеме. |

Исторически роль CONNECT включала больше привилегий (CREATE TABLE, CREATE VIEW и т.д.); начиная с Oracle 10.2 Oracle сузил её до минимума, необходимого для входа. Поэтому для работы не только «подключиться», но и создавать объекты, пользователю обычно выдают и **CONNECT**, и **RESOURCE** (или эквивалентный набор привилегий вручную). Роль **DBA** даёт очень широкие права (администрирование, доступ ко всем объектам) и для рядового разработчика не рекомендуется; принцип наименьших привилегий предписывает выдавать только нужные роли и привилегии.

**Типичный минимум для обучения и разработки в своей схеме:**

- **CREATE SESSION** — чтобы войти в базу.
- **RESOURCE** (или отдельно: CREATE TABLE, CREATE SEQUENCE, CREATE VIEW, CREATE PROCEDURE и т.д. плюс квота на табличное пространство или UNLIMITED TABLESPACE) — чтобы создавать таблицы, представления, процедуры, последовательности в своей схеме.

Администратор выдаёт роли так (пример):

```sql
GRANT CONNECT, RESOURCE TO myuser;
```

Либо только привилегии:

```sql
GRANT CREATE SESSION TO myuser;
GRANT CREATE TABLE TO myuser;
-- и квота на табличное пространство, например:
ALTER USER myuser QUOTA UNLIMITED ON USERS;
```

Если после успешного подключения вы не можете создать таблицу или выполнить запрос к своей таблице — скорее всего, не хватает привилегий на создание объектов или на использование табличного пространства; это настраивается администратором. Доступ к объектам *другой* схемы требует дополнительных привилегий (например, SELECT на таблицу другого пользователя); обзор представлений словаря данных, в том числе списка привилегий, — в [§1.3](chapter-01-03.md).

## 1.2.6. Подключение в SQL Developer по шагам

В Oracle SQL Developer новое соединение создаётся так (кратко):

1. В панели «Connections» нажать «+» (New Connection) или выбрать меню с созданием соединения.
2. Заполнить:
   - **Connection Name** — произвольное имя для отображения (например, «Учебная база»).
   - **Username** — имя пользователя Oracle.
   - **Password** — пароль (можно сохранить в зашифрованном виде в конфигурации).
   - **Connection Type** — обычно «Basic».
   - **Hostname** — хост или IP сервера.
   - **Port** — порт listener’а (часто 1521).
   - **Service name** — имя службы (например, `ORCL`). Либо вместо Service name выбрать SID и указать SID, если так принято в вашей среде.
3. Нажать «Test» для проверки подключения; при успехе статус «Status: Success».
4. Сохранить соединение и нажать «Connect» для входа.

После подключения в левой панели можно раскрыть соединение и просматривать объекты схемы (Tables, Views, Procedures и т.д.); редактор запросов позволяет выполнять SQL и PL/SQL. Подробнее работа с объектами и первый запрос — в [§1.3](chapter-01-03.md) и [§1.4](chapter-01-04.md).

## 1.2.7. Типичные ошибки при подключении

- **Указать только хост без service name там, где listener требует службу:** в части установок при отсутствии service name в строке подключения listener не сможет выбрать базу и вернёт ошибку. Всегда уточняйте у администратора host, port и service name (или сетевое имя из tnsnames.ora).
- **Путать SID и service name:** в Easy Connect после слэша указывается service name: `host:port/service_name`. Подстановка SID вместо service name может привести к отказу подключения, если listener настроен на приём по service name.
- **Считать, что CONNECT даёт право создавать таблицы:** в актуальных версиях Oracle CONNECT даёт в основном CREATE SESSION. Для создания объектов нужна роль RESOURCE или явные привилегии (CREATE TABLE и др.) и квота на табличное пространство.
- **Хранить пароль в командной строке в скриптах:** `sqlplus user/pass@...` оставляет пароль в истории команд и в процессах. Безопаснее вызывать `sqlplus user@...` и вводить пароль интерактивно или использовать защищённые механизмы (wallet, переменные окружения с ограниченным доступом).
- **Игнорировать сеть и firewall:** если порт 1521 закрыт или listener слушает на другом порту, подключение не установится. Нужны правильные хост и порт и открытый доступ с клиентской машины к серверу.

## Ключевое

- Для подключения нужны: **хост**, **порт** listener’а (обычно 1521), **service name** (или SID), **имя пользователя** и **пароль**.
- **Easy Connect:** строка вида `host[:port][/service_name]` без tnsnames.ora. Пример: `username@dbserver:1521/ORCL`. Подходит для простых TCP/IP-окружений.
- **TNS / tnsnames.ora:** сетевое имя сопоставляется с connect descriptor (хост, порт, SERVICE_NAME). Подключение: `username@net_service_name`.
- **Service name** — логическое имя службы базы в listener’е; **SID** — идентификатор экземпляра. В современных настройках в строке подключения обычно указывают service name.
- Для входа необходима привилегия **CREATE SESSION** (часто даётся ролью **CONNECT**). Для создания объектов в своей схеме — роль **RESOURCE** или явные привилегии (CREATE TABLE и др.) и квота на табличное пространство.
- В **SQL Developer** соединение задаётся полями Hostname, Port, Service name (или SID) и учётными данными; перед сохранением полезно нажать «Test».

В [§1.3](chapter-01-03.md) мы рассмотрим основные объекты схемы: таблицы, представления, синонимы, последовательности и каталог данных (представления USER_*, ALL_*, DBA_*), чтобы вы могли ориентироваться в объектах после подключения.
