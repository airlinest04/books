# §8.3 SAVEPOINT

В [§8.2](chapter-08-02.md) мы разобрали уровни изоляции. **ROLLBACK** отменяет всю текущую транзакцию. Иногда нужно откатить только **часть** изменений, оставив предыдущие шаги в силе. **SAVEPOINT** задаёт именованную точку внутри транзакции; **ROLLBACK TO SAVEPOINT** откатывает все изменения после этой точки, не завершая транзакцию. В этом разделе — синтаксис SAVEPOINT и ROLLBACK TO SAVEPOINT, несколько точек сохранения и типичное применение. План выполнения запроса (EXPLAIN PLAN) — в [§8.4](chapter-08-04.md). См. [Глоссарий](glossary.md).

---

## 8.3.1. Синтаксис SAVEPOINT и ROLLBACK TO SAVEPOINT

**SAVEPOINT** — именованная точка внутри транзакции. После выполнения DML можно сохранить текущее состояние и позже откатиться к нему, не отменяя всю транзакцию. См. [Глоссарий](glossary.md).

Синтаксис:

```sql
SAVEPOINT имя_точки;

-- позже, при необходимости:
ROLLBACK [WORK] TO [SAVEPOINT] имя_точки;
```

**имя_точки** — идентификатор (например, `before_update`, `sp1`). В одной транзакции можно создать несколько SAVEPOINT с разными именами; при повторном использовании того же имени предыдущая одноимённая точка «перезаписывается» (откат пойдёт к последней такой точке). **ROLLBACK TO SAVEPOINT** отменяет все DML после указанной точки; сама точка остаётся (можно снова откатиться к ней, если создать новые SAVEPOINT с тем же именем — не рекомендуется для ясности). Транзакция после ROLLBACK TO SAVEPOINT **не завершается** — можно продолжать выполнять команды и в конце сделать COMMIT или полный ROLLBACK. См. [Глоссарий](glossary.md).

Пример: обновить строку, сохранить точку, вставить строку; при ошибке откатиться к точке (вставка отменена, обновление остаётся).

```sql
UPDATE products SET price = 25.00 WHERE id = 10;
SAVEPOINT after_update;

INSERT INTO audit_log (action, table_name, key_id) VALUES ('UPDATE', 'products', 10);
-- если что-то пошло не так:
ROLLBACK TO SAVEPOINT after_update;
-- иначе продолжаем и в конце:
COMMIT;
```

Среда: Oracle Database.

## 8.3.2. Несколько SAVEPOINT и порядок отката

Можно создать несколько точек подряд: `SAVEPOINT a;` ... DML ... `SAVEPOINT b;` ... DML ... `SAVEPOINT c;`. **ROLLBACK TO SAVEPOINT b** отменит только изменения после точки `b` (включая всё до `c`). Откат к более ранней точке неявно «уничтожает» более поздние SAVEPOINT: после ROLLBACK TO SAVEPOINT a точки b и c больше недоступны для отката (они были после a). Новые SAVEPOINT после отката создавать можно. См. [Глоссарий](glossary.md).

**COMMIT** и полный **ROLLBACK** (без TO SAVEPOINT) завершают транзакцию; все SAVEPOINT этой транзакции перестают существовать. В следующей транзакции старые имена SAVEPOINT использовать можно заново.

---

## 8.3.3. Типичное применение

SAVEPOINT полезен, когда транзакция состоит из нескольких логических шагов и при ошибке в одном из них нужно отменить только этот шаг (или несколько последних), не трогая уже выполненные. Примеры: импорт данных (после каждой группы вставок — SAVEPOINT; при ошибке в следующей группе — ROLLBACK TO SAVEPOINT и повтор или пропуск); многошаговая обработка (шаг 1 — SAVEPOINT, шаг 2 — при неудаче откат к SAVEPOINT и повтор шага 2 с другими параметрами). См. [Глоссарий](glossary.md).

Не используйте SAVEPOINT вместо явного проектирования транзакций: если логика сложная, лучше разбить на отдельные транзакции (COMMIT после успешного блока) или обрабатывать ошибки в коде (PL/SQL), а не полагаться на множество вложенных откатов.

---

## Ключевое

- **SAVEPOINT имя** — именованная точка внутри транзакции. **ROLLBACK TO SAVEPOINT имя** отменяет все изменения после этой точки; транзакция не завершается. См. [Глоссарий](glossary.md).
- Можно создать несколько SAVEPOINT; откат к более ранней точке делает недоступными более поздние точки (их имена можно использовать заново после отката).
- COMMIT и полный ROLLBACK завершают транзакцию и снимают все SAVEPOINT.
- SAVEPOINT удобен для частичного отката при многошаговой логике (импорт, пошаговая обработка); не заменяет продуманное разбиение на транзакции.
