# §2.2 Типы данных

В [§2.1](chapter-02-01.md) мы разобрали CREATE TABLE и правила именования столбцов. Каждый столбец должен иметь **тип данных** — он определяет, какие значения можно хранить и как Oracle их обрабатывает. В этом разделе рассмотрены основные встроенные типы Oracle: **NUMBER**, **VARCHAR2**, **CHAR**, **DATE**, **TIMESTAMP**, а также типы для больших объёмов текста и бинарных данных **CLOB** и **BLOB**. Отдельно разберём **различие VARCHAR и VARCHAR2** и почему в Oracle рекомендуется использовать VARCHAR2. Ограничения целостности (NOT NULL, PRIMARY KEY и т.д.) добавляются к столбцам и таблицам в [§2.3](chapter-02-03.md). См. [Глоссарий](glossary.md).

---

## 2.2.1. NUMBER: числа с заданной точностью и масштабом

Тип **NUMBER** хранит числовые значения с произвольной точностью в десятичном представлении. Синтаксис:

```sql
NUMBER [ (precision [, scale]) ]
```

- **precision** — общее число значащих десятичных цифр (1–38). Если не указано, допускается любое число в пределах возможностей хранения (до 22 байт на значение).
- **scale** — число цифр **после** десятичной запятой. Может быть от -84 до 127. Отрицательный scale означает округление влево от десятичной точки (например, NUMBER(10,-2) хранит с точностью до сотен). Если scale не указан, по умолчанию 0 (целые числа). См. [Глоссарий](glossary.md).

Примеры:

| Определение      | Значения (примеры)                    |
|------------------|----------------------------------------|
| NUMBER           | Любое число в пределах точности Oracle |
| NUMBER(10)       | Целые до 10 цифр (например, 1234567890) |
| NUMBER(10,2)     | Числа с двумя знаками после запятой (например, 99999999.99) |
| NUMBER(5,-2)     | Округление до сотен (например, 12300) |

Для целочисленных идентификаторов и счётчиков часто используют NUMBER без параметров или NUMBER(10), для денег и измерений — NUMBER(p,2) или NUMBER(p,s) с нужным scale. Подтипы INTEGER, FLOAT, DECIMAL в Oracle по сути задают варианты NUMBER с фиксированной семантикой; тип BINARY_FLOAT и BINARY_DOUBLE — отдельные типы для чисел с плавающей точкой по стандарту IEEE (4 и 8 байт).

## 2.2.2. VARCHAR2: строка переменной длины

**VARCHAR2** — тип для символьных строк **переменной длины** в кодировке базы данных. Длина задаётся в байтах или в символах (в зависимости от семантики). См. [Глоссарий](glossary.md).

Синтаксис:

```sql
VARCHAR2(size [BYTE | CHAR])
```

- **size** — максимальная длина. Минимум 1. Максимум при стандартной настройке (**MAX_STRING_SIZE = STANDARD**) — **4000** байт или символов; при расширенной (**MAX_STRING_SIZE = EXTENDED**) — до 32767 (ограничения по версии и настройке базы).
- **BYTE** — семантика по байтам: size задаёт максимальное число байт.
- **CHAR** — семантика по символам: size задаёт максимальное число символов (точек кода). В многобайтовых кодировках один символ может занимать несколько байт.

Если BYTE/CHAR не указаны, используется параметр сессии NLS_LENGTH_SEMANTICS (обычно BYTE). Oracle хранит только фактическую длину строки, без дополнения пробелами; при сравнении используется семантика без дополнения (non-padded). Для имён, короткого текста, кодов обычно задают VARCHAR2(100), VARCHAR2(200) и т.д.; при необходимости явно указывают CHAR: VARCHAR2(100 CHAR).

---

## 2.2.3. CHAR: строка фиксированной длины

**CHAR** — тип для символьных строк **фиксированной длины**. Синтаксис:

```sql
CHAR [ (size [BYTE | CHAR]) ]
```

**size** по умолчанию 1; максимум 2000 байт или символов. Если вставленное значение короче size, Oracle **дополняет его пробелами справа** до длины size; при сравнении в части контекстов учитывается дополнение. CHAR удобен, когда все значения должны иметь одну и ту же длину (коды фиксированного формата); для произвольного текста и имён обычно предпочтительнее VARCHAR2. См. [Глоссарий](glossary.md).

---

## 2.2.4. DATE и TIMESTAMP: дата и время

**DATE** в Oracle хранит **дату и время** (год, месяц, день, час, минута, секунда) в 7 байтах. Дробных секунд и часового пояса нет. Диапазон дат: от 1 января 4712 г. до н.э. до 31 декабря 9999 г. Формат отображения задаётся параметром NLS_DATE_FORMAT или NLS_TERRITORY. В запросах даты задают строкой в формате, распознаваемом сессией, или функцией TO_DATE. См. [Глоссарий](glossary.md).

**TIMESTAMP** расширяет DATE **дробными секундами** (от 0 до 9 цифр, по умолчанию 6). Размер 7 или 11 байт в зависимости от точности. Варианты:

- **TIMESTAMP [(fractional_seconds_precision)]** — дата и время с дробными секундами, без часового пояса.
- **TIMESTAMP WITH TIME ZONE** — то же плюс смещение часового пояса (фиксированный размер 13 байт).
- **TIMESTAMP WITH LOCAL TIME ZONE** — при хранении нормализуется в часовой пояс базы, при выборке отображается в часовом поясе сессии.

Для большинства приложений без требований к часовым поясам достаточно DATE; при необходимости дробных секунд или учёта пояса используют TIMESTAMP или TIMESTAMP WITH TIME ZONE / WITH LOCAL TIME ZONE. См. [Глоссарий](glossary.md).

## 2.2.5. CLOB и BLOB: большие объекты

Когда объёма VARCHAR2 недостаточно (например, текст длиннее 4000 символов при STANDARD или нужны бинарные данные произвольного размера), используют типы **LOB** (Large Object). См. [Глоссарий](glossary.md).

- **CLOB** (Character Large Object) — символьные данные в кодировке базы. Максимальный размер зависит от размера блока базы: (4 ГБ − 1) × размер_блока. Подходит для длинного текста, XML, JSON в виде строки.
- **BLOB** (Binary Large Object) — бинарные данные (изображения, файлы, сериализованные объекты). Максимальный размер тот же, что у CLOB.

В таблице столбец типа CLOB/BLOB хранит **локатор** (указатель на данные); сами данные могут храниться внутри таблицы (inline) или в отдельном сегменте. Работа с LOB в запросах и в PL/SQL имеет особенности (функции DBMS_LOB, ограничения в некоторых операциях); для простых вставок и выборки целого значения синтаксис аналогичен работе с длинными строками в части сценариев. Тип **LONG** и **LONG RAW** устарели; для нового кода используют CLOB и BLOB. См. [Глоссарий](glossary.md).

## 2.2.6. VARCHAR и VARCHAR2: почему использовать VARCHAR2

В Oracle тип **VARCHAR** формально существует и на текущий момент часто трактуется как синоним VARCHAR2, однако документация Oracle явно рекомендует **не использовать VARCHAR** и везде применять **VARCHAR2**. См. [Глоссарий](glossary.md).

Причины (по документации Oracle, Oracle Database SQL Language Reference, Data Types):

1. **Поведение в будущем:** VARCHAR запланировано переопределить как отдельный тип с **другой семантикой сравнения**. Чтобы не зависеть от возможных изменений, в новом коде используют VARCHAR2.
2. **Пустая строка и NULL:** в текущей реализации пустая строка ('') в Oracle приравнивается к NULL (в том числе в столбцах VARCHAR2). Исторически VARCHAR мог иметь отличия в трактовке пустых строк; VARCHAR2 гарантирует стабильную семантику, совместимую с тем, как Oracle обрабатывает символьные типы сейчас.
3. **Рекомендация Oracle:** в разделе «VARCHAR Data Type» документации указано: «Do not use the VARCHAR data type. Use the VARCHAR2 data type instead.»

Итого: для любых столбцов с символьными строками переменной длины в Oracle следует указывать **VARCHAR2**, а не VARCHAR. Существующие объекты с типом VARCHAR при необходимости можно постепенно переводить на VARCHAR2 при изменении схемы (ALTER TABLE ... MODIFY). См. [§2.4](chapter-02-04.md).

## 2.2.7. Сводная таблица типов и пример определения таблицы

| Тип | Назначение | Основные параметры / примечания |
|-----|------------|----------------------------------|
| NUMBER(p,s) | Числа | p — точность (1–38), s — масштаб (-84..127). Без параметров — произвольная точность в пределах хранения. |
| VARCHAR2(n) | Строка переменной длины | n до 4000 (STANDARD) или 32767 (EXTENDED). BYTE/CHAR. |
| CHAR(n) | Строка фиксированной длины | n до 2000, по умолчанию 1; дополнение пробелами. |
| DATE | Дата и время | 7 байт, без дробных секунд и пояса. |
| TIMESTAMP [(p)] | Дата и время с дробными секундами | p — цифры дробной части (0–9). Варианты WITH TIME ZONE, WITH LOCAL TIME ZONE. |
| CLOB | Большой текст | Символьный LOB, до (4 ГБ − 1) × размер_блока. |
| BLOB | Бинарные данные | Бинарный LOB, тот же максимум. |

Пример таблицы с разными типами:

```sql
CREATE TABLE samples (
  id          NUMBER(10),
  code        VARCHAR2(20),
  description VARCHAR2(400),
  amount      NUMBER(12,2),
  created     DATE,
  notes       CLOB
);
```

Типы столбцов можно уточнять при необходимости: NUMBER(10) для целых идентификаторов, NUMBER(12,2) для денег, VARCHAR2(100 CHAR) при работе с многобайтовыми символами, TIMESTAMP(3) для дробных секунд. Подробнее преобразование и форматирование дат (TO_CHAR, TO_DATE) — в [§3.1](chapter-03-01.md).

## 2.2.8. Типичные ошибки при выборе типов данных

- **Использовать VARCHAR вместо VARCHAR2:** в Oracle для символьных столбцов переменной длины всегда указывайте VARCHAR2; VARCHAR не рекомендуется и может изменить семантику в будущих версиях.
- **Задать VARCHAR2 без размера:** размер обязателен, например VARCHAR2(100). Иначе ошибка синтаксиса.
- **Путать CHAR и VARCHAR2:** CHAR дополняет значение пробелами до фиксированной длины и может влиять на сравнение; VARCHAR2 хранит только введённые символы. Для имён и текста переменной длины — VARCHAR2.
- **Ожидать от DATE только дату без времени:** тип DATE в Oracle всегда содержит и время (часы, минуты, секунды). Если время не задано, по умолчанию 00:00:00. Для отображения только даты используют TO_CHAR с форматом.
- **Хранить числа с плавающей точкой в NUMBER без масштаба для денег:** для денежных сумм лучше явно задавать scale (например, NUMBER(12,2)), чтобы избежать ошибок округления. BINARY_FLOAT/BINARY_DOUBLE не подходят для точных денежных расчётов.
- **Использовать LONG/LONG RAW в новом коде:** эти типы устарели. Используйте CLOB и BLOB.

## Ключевое

- **NUMBER(p,s)** — числа с точностью p и масштабом s; без параметров — произвольная точность в пределах хранения.
- **VARCHAR2(size [BYTE|CHAR])** — строка переменной длины, максимум 4000 байт (STANDARD) или 32767 (EXTENDED). Хранится без дополнения пробелами.
- **CHAR(size)** — строка фиксированной длины, дополняется пробелами; максимум 2000.
- **DATE** — дата и время в 7 байтах, без дробных секунд и пояса. **TIMESTAMP** — с дробными секундами; варианты WITH TIME ZONE, WITH LOCAL TIME ZONE.
- **CLOB** — большой символьный объект; **BLOB** — большой бинарный объект. Используются при объёме больше лимита VARCHAR2.
- **VARCHAR в Oracle не рекомендуется;** везде используйте **VARCHAR2**. VARCHAR может изменить семантику в будущих версиях.

В [§2.3](chapter-02-03.md) мы разберём ограничения целостности: NOT NULL, PRIMARY KEY, UNIQUE, CHECK, FOREIGN KEY и именование ограничений.
