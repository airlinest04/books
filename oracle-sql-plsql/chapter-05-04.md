# §5.4 MERGE

В [§5.3](chapter-05-03.md) мы рассмотрели DELETE и TRUNCATE. Часто возникает задача: для каждой строки из источника либо **вставить** её в целевую таблицу (если такой строки ещё нет), либо **обновить** существующую (если совпадение по ключу найдено). Оператор **MERGE** объединяет INSERT и UPDATE в одном запросе и избавляет от громоздких конструкций «проверить EXISTS — если нет, INSERT, иначе UPDATE». В этом разделе — синтаксис MERGE, предложения **WHEN MATCHED** и **WHEN NOT MATCHED**, типичное применение для загрузки и синхронизации данных. См. [Глоссарий](glossary.md).

---

## 5.4.1. Назначение MERGE

**MERGE** (слияние) — оператор DML, который по результату соединения целевой таблицы с источником (подзапрос или другая таблица) решает для каждой строки источника: выполнить **UPDATE** в целевой таблице, если найдено совпадение по условию, или **INSERT**, если совпадения нет. Таким образом реализуется типичный сценарий «upsert» (update or insert): одна команда заменяет несколько отдельных INSERT/UPDATE и упрощает ETL и синхронизацию справочников. См. [Глоссарий](glossary.md).

Пример сценария: есть таблица-приёмник `products_target` и поток данных из `products_staging`. По полю `product_id` нужно: если строка с таким id уже есть в приёмнике — обновить её поля из staging; если нет — вставить новую строку. Без MERGE пришлось бы писать отдельный UPDATE (по подзапросу или циклом) и отдельный INSERT для «новых» id; с MERGE это один оператор.

---

## 5.4.2. Синтаксис MERGE

Общая форма (упрощённо):

```sql
MERGE INTO целевая_таблица [псевдоним_цели]
USING источник [псевдоним_источника]
   ON (условие_совпадения)
WHEN MATCHED THEN
   UPDATE SET столбец1 = выражение1 [, столбец2 = выражение2, ...]
   [WHERE условие_для_update]
WHEN NOT MATCHED THEN
   INSERT [(столбец1, столбец2, ...)]
   VALUES (выражение1, выражение2, ...)
   [WHERE условие_для_insert];
```

- **INTO** — таблица (или обновляемое представление), в которую сливаются данные.
- **USING** — источник строк: таблица, представление или подзапрос. Для каждой строки источника проверяется условие **ON**.
- **ON (условие)** — условие соединения источника с целью (например, `target.id = source.id`). По нему Oracle определяет, есть ли «совпадение»: если для строки источника найдена строка цели, выполняется ветка **WHEN MATCHED**; если не найдена — **WHEN NOT MATCHED**.
- **WHEN MATCHED THEN UPDATE** — какие столбцы цели обновить и какими выражениями (часто из псевдонима источника). Опционально **WHERE** сужает круг обновляемых строк (например, обновлять только если что-то реально изменилось).
- **WHEN NOT MATCHED THEN INSERT** — вставка новой строки в целевую таблицу; список столбцов и **VALUES** задают значения (как правило, из полей источника).

Оба предложения WHEN не обязаны присутствовать одновременно: можно только **WHEN MATCHED** (тогда MERGE работает как условный UPDATE по соединению) или только **WHEN NOT MATCHED** (условный INSERT по соединению). В Oracle допустимо также **WHEN NOT MATCHED BY SOURCE** (обработка строк цели, которых нет в источнике — например, DELETE или пометка). Среда: Oracle Database; синтаксис поддерживается с Oracle 9i, расширения — в более поздних версиях.

---

## 5.4.3. WHEN MATCHED и WHEN NOT MATCHED

**WHEN MATCHED** срабатывает, когда для текущей строки источника в целевой таблице по условию ON найдена строка. В этой ветке доступны столбцы и цели, и источника (через псевдонимы). В **UPDATE SET** нельзя присваивать столбцам цели значения из цели же (только из источника или из выражений), чтобы не создавать неоднозначность. Обычно пишут: `SET target.col1 = source.col1, target.col2 = source.col2`.

**WHEN NOT MATCHED** срабатывает, когда для строки источника в цели по ON совпадения нет. Выполняется вставка в целевую таблицу; в **INSERT** и **VALUES** обычно подставляют значения из источника (`INSERT (col1, col2) VALUES (source.col1, source.col2)`). Дополнительное **WHERE** в WHEN NOT MATCHED отфильтрует часть «новых» строк (вставка только при выполнении условия).

Пример полного MERGE: синхронизация таблицы `dept_target` из таблицы `dept_source` по первичному ключу `deptno`.

```sql
MERGE INTO dept_target t
USING dept_source s
   ON (t.deptno = s.deptno)
WHEN MATCHED THEN
   UPDATE SET t.dname = s.dname, t.loc = s.loc
WHEN NOT MATCHED THEN
   INSERT (deptno, dname, loc)
   VALUES (s.deptno, s.dname, s.loc);
```

Здесь для каждой строки `dept_source`: при совпадении `deptno` обновляются `dname` и `loc` в `dept_target`; при отсутствии совпадения вставляется новая строка с полями из источника.

## 5.4.4. Типичное применение: загрузка и синхронизация

MERGE широко используется в ETL и загрузке данных: перенос из staging-таблицы в целевую с правилом «если ключ есть — обновить, иначе — вставить». Источником часто выступает подзапрос (результат преобразований, джойнов с другими таблицами). Условие ON обычно строится по бизнес-ключу (например, код справочника, натуральный ключ).

Рекомендации:

- Задавайте **ON** по стабильному ключу (первичный или уникальный ключ цели), чтобы не получить несколько совпадений для одной строки источника (в Oracle при нескольких совпадениях MERGE обновит соответствующую строку цели один раз по правилам реализации).
- В **UPDATE SET** перечисляйте только те столбцы, которые действительно должны обновляться из источника; столбцы вроде `created_at` при необходимости не трогайте или обновляйте отдельной логикой.
- При массовой загрузке учитывайте размер транзакции и блокировки: один MERGE по большой таблице держит блокировки до COMMIT; при необходимости разбивайте загрузку по партиям (например, по диапазону ключа).

Пример с подзапросом в USING: обновить/вставить цены в `product_prices` из последней загрузки `price_feed`, ключ — `product_id`.

```sql
MERGE INTO product_prices t
USING (
   SELECT product_id, price, valid_from
   FROM price_feed
   WHERE load_id = (SELECT MAX(load_id) FROM price_feed)
) s ON (t.product_id = s.product_id)
WHEN MATCHED THEN
   UPDATE SET t.price = s.price, t.valid_from = s.valid_from
WHEN NOT MATCHED THEN
   INSERT (product_id, price, valid_from)
   VALUES (s.product_id, s.price, s.valid_from);
```

## Ключевое

- **MERGE** — оператор DML, объединяющий в одном запросе вставку и обновление: по условию ON для каждой строки источника либо выполняется UPDATE в целевой таблице (**WHEN MATCHED**), либо INSERT (**WHEN NOT MATCHED**). См. [Глоссарий](glossary.md).
- Синтаксис: **MERGE INTO** цель **USING** источник **ON** (условие) **WHEN MATCHED THEN UPDATE SET ...** [WHERE ...] **WHEN NOT MATCHED THEN INSERT ... VALUES ...** [WHERE ...]. Можно использовать только одну из веток WHEN.
- Условие **ON** задаёт соответствие между источником и целью (обычно по первичному или бизнес-ключу). В UPDATE SET и в INSERT/VALUES используют значения из источника (псевдоним).
- Типичное применение — загрузка и синхронизация: staging → целевая таблица, «если ключ есть — обновить, иначе — вставить»; источник может быть подзапросом.
- MERGE выполняется в транзакции; для фиксации — COMMIT. Учитывайте блокировки при больших объёмах.
