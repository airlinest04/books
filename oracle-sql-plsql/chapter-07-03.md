# §7.3 Иерархические запросы

В [§7.2](chapter-07-02.md) мы разобрали операции над множествами (UNION, INTERSECT, MINUS). Данные часто организованы в **иерархию**: сотрудник — начальник, категория — родительская категория, узел — родительский узел. В Oracle для обхода такого дерева используется синтаксис **CONNECT BY**: запрос возвращает строки уровня за уровнем от корня к листьям (или наоборот). В этом разделе — **START WITH** и **CONNECT BY**, псевдостолбец **LEVEL**, сортировка **ORDER SIBLINGS BY**, а также **NOCYCLE** и **SYS_CONNECT_BY_PATH**. Альтернатива в стандартном SQL — рекурсивный CTE ([§7.1](chapter-07-01.md)). Представления — в [§7.4](chapter-07-04.md). См. [Глоссарий](glossary.md).

---

## 7.3.1. Иерархия и синтаксис CONNECT BY

**Иерархический запрос** — запрос, который обходит строки таблицы как дерево: у каждой строки есть «родитель» (ссылка на другую строку той же или другой таблицы). Oracle задаёт иерархию предложениями **START WITH** (какие строки считать корневыми) и **CONNECT BY** (как связаны родитель и потомок). См. [Глоссарий](glossary.md).

Общая форма:

```sql
SELECT [столбцы,] LEVEL, ...
  FROM таблица [псевдоним]
 WHERE [условие_на_строки]
 START WITH условие_корня
 CONNECT BY [NOCYCLE] [PRIOR столбец_потомка = столбец_родителя]
 ORDER SIBLINGS BY столбец [, ...];
```

- **START WITH** — условие отбора корневых строк (например, manager_id IS NULL или employee_id = 100). С этих строк начинается обход.
- **CONNECT BY** — связь родитель–потомок. **PRIOR** ставится у столбца со стороны родителя: обычно `CONNECT BY PRIOR child.id = parent.parent_id` или в одной таблице `CONNECT BY PRIOR employee_id = manager_id` (текущая строка — потомок, её manager_id указывает на родителя).
- **LEVEL** — псевдостолбец Oracle: номер уровня глубины (1 для корня, 2 для его детей и т.д.). См. [Глоссарий](glossary.md).
- **ORDER SIBLINGS BY** — сортировка среди братьев (одного уровня под одним родителем); сохраняет древовидный порядок вывода.
- **NOCYCLE** — не уходить в цикл: если потомок снова ведёт к уже пройденному предку, ветка обрывается, ошибки нет.

Пример: таблица employees с полем manager_id (ссылка на employee_id начальника). Вывести подчинённых от руководителя с employee_id = 100:

```sql
SELECT employee_id, last_name, manager_id, LEVEL
  FROM employees
 START WITH employee_id = 100
 CONNECT BY PRIOR employee_id = manager_id
 ORDER SIBLINGS BY last_name;
```

Здесь PRIOR employee_id = manager_id читается так: «текущая строка (потомок) подключается, когда её manager_id равен employee_id родителя». То есть родитель — тот, чей employee_id совпадает с нашим manager_id. Среда: Oracle Database.

## 7.3.2. LEVEL и порядок обхода

**LEVEL** возвращает 1 для строк, отобранных START WITH, 2 — для их непосредственных потомков по CONNECT BY, 3 — для потомков потомков и т.д. Его удобно использовать для отступа в отчёте (LPAD(' ', (LEVEL-1)*2) || last_name) или для фильтрации по глубине (WHERE LEVEL <= 3 — не глубже трёх уровней). См. [Глоссарий](glossary.md).

Обход по умолчанию — **в глубину** (depth-first): сначала вся ветка от корня до листа, затем следующая ветка. Порядок среди дочерних строк одной родительской можно задать **ORDER SIBLINGS BY**; без него порядок не гарантирован. Обычный ORDER BY в иерархическом запросе «разрушает» древовидную структуру вывода (сортирует весь результат как плоский список), поэтому для порядка внутри дерева используют именно ORDER SIBLINGS BY.

Пример: дерево от корня (manager_id IS NULL) с отступом по уровню и сортировкой по фамилии среди братьев:

```sql
SELECT LPAD(' ', (LEVEL - 1) * 2) || last_name AS name, employee_id, LEVEL
  FROM employees
 START WITH manager_id IS NULL
 CONNECT BY PRIOR employee_id = manager_id
 ORDER SIBLINGS BY last_name;
```

## 7.3.3. NOCYCLE и циклы в данных

Если в данных есть цикл (например, сотрудник A указывает начальником B, B — C, C — A), запрос без **NOCYCLE** может уйти в бесконечный цикл или привести к ошибке. С указанием **NOCYCLE** Oracle обнаруживает повторное появление строки в пути и прекращает раскручивать эту ветку; строка, создающая цикл, в результат не попадёт. Одновременно доступен псевдостолбец **CONNECT_BY_ISCYCLE**: 1 для строки, у которой потомок уже был в пути, 0 для остальных. См. [Глоссарий](glossary.md).

Пример:

```sql
SELECT employee_id, last_name, LEVEL, CONNECT_BY_ISCYCLE AS is_cycle
  FROM employees
 START WITH manager_id IS NULL
 CONNECT BY NOCYCLE PRIOR employee_id = manager_id;
```

**CONNECT_BY_ISLEAF** — псевдостолбец: 1, если строка лист (нет потомков в результате запроса), 0 иначе. Полезно для выделения конечных узлов.

## 7.3.4. SYS_CONNECT_BY_PATH и обход снизу вверх

**SYS_CONNECT_BY_PATH(столбец, разделитель)** — функция Oracle: возвращает строку с путём от корня до текущей строки; значения столбца на пути объединены через разделитель. Например, путь имён от корня до текущего сотрудника для отображения «ветки». См. [Глоссарий](glossary.md).

Пример:

```sql
SELECT employee_id, last_name, LEVEL,
       SYS_CONNECT_BY_PATH(last_name, ' / ') AS path
  FROM employees
 START WITH manager_id IS NULL
 CONNECT BY PRIOR employee_id = manager_id;
```

Обход **снизу вверх** (от сотрудника к начальникам): корень задаётся START WITH для конкретного сотрудника, а в CONNECT BY связь разворачивают так, чтобы родитель был «текущий», потомок — «предыдущий» в иерархии. Например, «все начальники до корня» для employee_id = 206:

```sql
SELECT employee_id, last_name, manager_id, LEVEL
  FROM employees
 START WITH employee_id = 206
 CONNECT BY PRIOR manager_id = employee_id;
```

Здесь PRIOR manager_id = employee_id: у текущей строки берётся manager_id и ищется строка с таким employee_id (начальник); затем та же логика от начальника вверх.

---

## Ключевое

- **Иерархический запрос** в Oracle: **START WITH** задаёт корневые строки, **CONNECT BY PRIOR** — связь родитель–потомок (PRIOR у столбца родителя). См. [Глоссарий](glossary.md).
- **LEVEL** — псевдостолбец: глубина уровня (1 — корень, 2 — дети и т.д.). **ORDER SIBLINGS BY** — сортировка среди узлов одного уровня без разрушения дерева.
- **NOCYCLE** в CONNECT BY предотвращает зациливание при циклах в данных. **CONNECT_BY_ISCYCLE**, **CONNECT_BY_ISLEAF** — псевдостолбцы для анализа пути.
- **SYS_CONNECT_BY_PATH(столбец, разделитель)** — путь от корня до текущей строки. Обход снизу вверх задаётся сменой сторон в PRIOR (START WITH потомок, CONNECT BY PRIOR parent_col = child_col).
