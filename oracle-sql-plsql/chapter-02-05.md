# §2.5 Последовательности (SEQUENCE)

В [§2.4](chapter-02-04.md) мы разобрали изменение структуры таблицы. Для столбцов первичного ключа часто нужны уникальные числовые значения, генерируемые автоматически. В Oracle для этого служит объект **последовательность (SEQUENCE)** — счётчик, выдающий следующее значение по запросу. В этом разделе рассмотрим **создание последовательности (CREATE SEQUENCE)**, псевдостолбцы **NEXTVAL** и **CURRVAL**, а также **использование последовательности при вставке** строк (в том числе для первичного ключа). В Oracle 12c и новее доступны также столбцы **IDENTITY** (автоинкремент); здесь мы фокусируемся на классическом способе с SEQUENCE. Дальше — глава 3: выборка и фильтрация (SELECT, WHERE). См. [Глоссарий](glossary.md).

---

## 2.5.1. Что такое последовательность и зачем она нужна

**Последовательность (sequence)** — объект схемы Oracle, хранящий текущее значение счётчика и при обращении выдающий следующее число. Последовательность не привязана к одной таблице: одну и ту же последовательность можно использовать для нескольких таблиц или столбцов (хотя для первичных ключей обычно создают отдельную последовательность на таблицу). Значения гарантированно уникальны в рамках последовательности и возрастают (или убывают, если задан отрицательный шаг); возможны пропуски номеров из‑за отката транзакций или кэширования. См. [Глоссарий](glossary.md).

Типичное применение — подстановка уникального идентификатора при вставке:

```sql
INSERT INTO products (id, name, price) VALUES (products_seq.NEXTVAL, 'Item', 99.00);
```

Вместо ручного подсчёта максимума или риска коллизий при параллельных вставках приложение или скрипт просто вызывает NEXTVAL и получает новое число.

## 2.5.2. CREATE SEQUENCE: создание последовательности

Синтаксис (основные параметры):

```sql
CREATE SEQUENCE имя_последовательности
  [START WITH n]
  [INCREMENT BY k]
  [MINVALUE m | NOMINVALUE]
  [MAXVALUE M | NOMAXVALUE]
  [CYCLE | NOCYCLE]
  [CACHE n | NOCACHE]
  [ORDER | NOORDER];
```

- **START WITH n** — начальное значение при создании (по умолчанию 1 для возрастающей и -1 для убывающей). Следующий вызов NEXTVAL вернёт это значение (если CACHE не изменил текущее положение).
- **INCREMENT BY k** — шаг: следующее значение = текущее + k. По умолчанию 1; отрицательное k даёт убывающую последовательность.
- **MINVALUE / NOMINVALUE**, **MAXVALUE / NOMAXVALUE** — границы значений. По умолчанию NOMINVALUE (для возрастающей — 1), NOMAXVALUE (для возрастающей — очень большое число).
- **CYCLE / NOCYCLE** — при достижении границы: CYCLE перезапускает с MINVALUE (или MAXVALUE для убывающей), NOCYCLE выдаёт ошибку. По умолчанию NOCYCLE.
- **CACHE n** — сколько значений заранее выделять в память для ускорения; при сбое сервера эти значения теряются (появляются пропуски). **NOCACHE** — каждое значение запрашивается у базы; по умолчанию CACHE 20 (зависит от версии). Для строгой последовательности без пропусков используют NOCACHE (с потерей производительности при частых вставках).
- **ORDER / NOORDER** — в RAC гарантировать строгий порядок выдачи (ORDER) или нет (NOORDER). Для одной инстанции не влияет.

Минимальный пример:

```sql
CREATE SEQUENCE products_seq START WITH 1 INCREMENT BY 1;
```

Последовательность создаётся в текущей схеме; список последовательностей — в USER_SEQUENCES. Текущее значение (последнее выданное в этой сессии) и параметры можно посмотреть там же. См. [Глоссарий](glossary.md).

## 2.5.3. NEXTVAL и CURRVAL

Обращение к последовательности выполняется через **псевдостолбцы** (pseudocolumns):

- **имя_последовательности.NEXTVAL** — увеличивает счётчик (на INCREMENT BY) и **возвращает новое значение**. Каждый вызов NEXTVAL даёт новое число; повторный вызов в одной сессии не возвращает то же значение.
- **имя_последовательности.CURRVAL** — возвращает **последнее значение**, полученное в **текущей сессии** при вызове NEXTVAL. CURRVAL нельзя вызвать до первого NEXTVAL в сессии; иначе ошибка ORA-08002 (sequence ... not yet defined in this session).

Пример в одной сессии:

```sql
SELECT products_seq.NEXTVAL FROM DUAL;  -- например, 1
SELECT products_seq.NEXTVAL FROM DUAL;  -- например, 2
SELECT products_seq.CURRVAL FROM DUAL;  -- 2
```

CURRVAL полезен, когда нужно вставить одну и ту же сгенерированную величину в несколько столбцов или в дочернюю таблицу в той же транзакции (см. ниже). См. [Глоссарий](glossary.md).

## 2.5.4. Использование последовательности при вставке (INSERT)

В операторе **INSERT** в списке значений можно указать **последовательность.NEXTVAL** — при вставке подставится следующее значение последовательности. Так обычно заполняют столбец первичного ключа.

Пример:

```sql
CREATE TABLE products (
  id    NUMBER(10)   PRIMARY KEY,
  name  VARCHAR2(200) NOT NULL,
  price NUMBER(10,2)
);

CREATE SEQUENCE products_seq START WITH 1 INCREMENT BY 1;

INSERT INTO products (id, name, price) VALUES (products_seq.NEXTVAL, 'Keyboard', 29.99);
INSERT INTO products (id, name, price) VALUES (products_seq.NEXTVAL, 'Mouse', 19.99);
```

В таблице окажутся строки с id = 1 и 2 (или следующие свободные номера, если последовательность уже использовалась). В одном INSERT можно использовать NEXTVAL в нескольких местах — каждое обращение даёт одно и то же значение в рамках **одной строки** одного оператора. Например, вставить один и тот же id в основную и дочернюю таблицу в одной транзакции удобнее так: сначала INSERT с NEXTVAL в основную таблицу, затем в той же сессии использовать CURRVAL при вставке в дочернюю (или один INSERT с подзапросом/возвращающим выражением, если применимо). См. [Глоссарий](glossary.md).

В **Oracle до 12c** нельзя задать в определении столбца DEFAULT seq.NEXTVAL (такой синтаксис не поддерживается). Поэтому значение подставляют явно в INSERT или через триггер BEFORE INSERT. В **Oracle 12c и новее** для автоинкрементального столбца можно использовать **IDENTITY** (GENERATED BY DEFAULT AS IDENTITY ...) — столбец сам получает значение при вставке без указания столбца; при этом SEQUENCE по-прежнему широко используется и даёт контроль над именем последовательности и параметрами.

## 2.5.5. Одна последовательность на таблицу и просмотр в словаре

На практике часто создают одну последовательность для первичного ключа одной таблицы и называют её, например, **имя_таблицы_seq** (products_seq, orders_seq). Так проще поддерживать скрипты и не путать счётчики. Для составного первичного ключа обычно один из столбцов делают счётчиком (например, order_id из orders_seq, item_no — отдельный счётчик в рамках заказа или константа).

Просмотр последовательностей своей схемы и их параметров:

```sql
SELECT sequence_name, last_number, min_value, max_value, increment_by, cache_size
  FROM user_sequences;
```

**LAST_NUMBER** в USER_SEQUENCES — следующее значение, которое будет выдано (или верхняя граница кэша; точная семантика зависит от CACHE). Для сброса последовательности на новое начальное значение в Oracle нет одной команды; можно использовать **ALTER SEQUENCE ... RESTART** (в поддерживаемых версиях) или DROP SEQUENCE и CREATE SEQUENCE заново (при этом теряются все настройки, кроме тех, что укажете снова). См. [Глоссарий](glossary.md).

---

## 2.5.6. ALTER SEQUENCE и DROP SEQUENCE

**ALTER SEQUENCE** позволяет изменить параметры существующей последовательности (INCREMENT BY, MINVALUE, MAXVALUE, CYCLE, CACHE и т.д.). Нельзя изменить START WITH для уже созданной последовательности (текущее положение задаётся уже выданными значениями). Пример:

```sql
ALTER SEQUENCE products_seq INCREMENT BY 2 CACHE 10;
```

**DROP SEQUENCE** удаляет последовательность. Объекты (таблицы, триггеры), которые использовали её в коде, перестанут работать при следующем вызове NEXTVAL/CURRVAL; определения столбцов с DEFAULT на последовательность в старых версиях нет, поэтому обычно «ломается» только код вставки и триггеры. См. [Глоссарий](glossary.md).

```sql
DROP SEQUENCE products_seq;
```

## 2.5.7. Типичные ошибки при работе с последовательностями

- **Вызвать CURRVAL до NEXTVAL в сессии:** в новой сессии сначала нужно хотя бы один раз обратиться к последовательности через NEXTVAL (в любом операторе), иначе CURRVAL выдаст ошибку.
- **Ожидать строгую непрерывность номеров:** при CACHE > 1 или при откате транзакции после NEXTVAL возможны пропуски. Если нужна непрерывная нумерация без пропусков, используют NOCACHE и не вызывают NEXTVAL без последующей фиксации вставки (но это не гарантирует непрерывность при сбоях).
- **Использовать NEXTVAL в DEFAULT столбца в старых версиях:** в Oracle до 12c в определении столбца нельзя написать DEFAULT seq.NEXTVAL. Решение — явно указывать NEXTVAL в INSERT или использовать триггер (или IDENTITY в 12c+).
- **Одна последовательность для нескольких независимых таблиц:** технически возможно, но значения будут общими (например, id в таблице A и в таблице B не будут разделены по диапазонам). Обычно для каждой таблицы со своим первичным ключом создают отдельную последовательность.
- **Удалить последовательность, используемую в триггерах или в коде:** после DROP SEQUENCE все вызовы NEXTVAL/CURRVAL этой последовательности начнут выдавать ошибку. Перед удалением проверьте триггеры и приложение.

---

## Ключевое

- **Последовательность (SEQUENCE)** — объект схемы, генерирующий уникальные числа. **CREATE SEQUENCE** с параметрами START WITH, INCREMENT BY, CACHE, CYCLE и др.
- **NEXTVAL** — получить следующее значение и сдвинуть счётчик. **CURRVAL** — текущее значение в сессии (доступно только после хотя бы одного NEXTVAL в этой сессии).
- При **INSERT** для первичного ключа указывают **имя_последовательности.NEXTVAL** в списке значений. В одной строке INSERT несколько обращений к NEXTVAL дают одно и то же значение.
- В определениях столбцов до 12c нельзя использовать DEFAULT seq.NEXTVAL; в 12c+ можно использовать столбцы IDENTITY. Для явной подстановки ключа SEQUENCE + NEXTVAL в INSERT подходит во всех версиях.
- Список последовательностей — **USER_SEQUENCES**. **ALTER SEQUENCE** меняет параметры; **DROP SEQUENCE** удаляет последовательность.
