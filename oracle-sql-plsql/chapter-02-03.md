# §2.3 Ограничения

В [§2.2](chapter-02-02.md) мы разобрали типы данных столбцов. Помимо типа, можно задать **ограничения целостности (constraints)** — правила, которым должны удовлетворять данные в таблице. Oracle поддерживает ограничения **NOT NULL**, **PRIMARY KEY**, **UNIQUE**, **CHECK** и **FOREIGN KEY**. В этом разделе мы рассмотрим каждое из них, способы объявления (в строке столбца и отдельно по таблице), а также **именование ограничений** — зачем давать им имена и как Oracle называет их при отсутствии явного имени. Добавление и удаление ограничений после создания таблицы — в [§2.4](chapter-02-04.md). См. [Глоссарий](glossary.md).

---

## 2.3.1. NOT NULL: запрет пустого значения

Ограничение **NOT NULL** запрещает столбцу содержать значение NULL: в каждой строке в этом столбце должно быть непустое значение. Объявляется **только в строке столбца** (inline), после типа данных. См. [Глоссарий](glossary.md).

Пример:

```sql
CREATE TABLE users (
  id    NUMBER(10)    NOT NULL,
  login VARCHAR2(50)  NOT NULL,
  email VARCHAR2(100)
);
```

Столбцы `id` и `login` обязательны для заполнения; `email` может быть NULL (по умолчанию столбец допускает NULL, если не указано NOT NULL). При попытке вставить строку без значения в столбец с NOT NULL Oracle вернёт ошибку ORA-01400 (cannot insert NULL into ...). NOT NULL часто сочетают с первичным ключом: все столбцы первичного ключа по определению не могут быть NULL.

---

## 2.3.2. PRIMARY KEY: первичный ключ

Ограничение **PRIMARY KEY** объявляет столбец (или набор столбцов) **первичным ключом** таблицы: значения в этом столбце (или комбинации столбцов) должны быть **уникальны** и **не NULL**. В таблице может быть только один первичный ключ. Oracle автоматически создаёт уникальный индекс по столбцам первичного ключа для проверки уникальности. См. [Глоссарий](glossary.md).

**Объявление в строке столбца (inline):**

```sql
CREATE TABLE products (
  id    NUMBER(10)   PRIMARY KEY,
  name  VARCHAR2(200) NOT NULL,
  price NUMBER(10,2)
);
```

**Объявление отдельно (out-of-line)** — в конце списка столбцов, с перечислением столбцов. Так удобно задавать **составной (композитный) первичный ключ** из нескольких столбцов:

```sql
CREATE TABLE order_items (
  order_id   NUMBER(10)   NOT NULL,
  item_no    NUMBER(5)    NOT NULL,
  product_id NUMBER(10)   NOT NULL,
  qty        NUMBER(10)   NOT NULL,
  PRIMARY KEY (order_id, item_no)
);
```

Первичный ключ — пара (order_id, item_no); комбинация должна быть уникальной, оба столбца не могут быть NULL. Имя ограничения можно задать явно (см. подраздел 2.3.6):

```sql
PRIMARY KEY (order_id, item_no)
-- или
CONSTRAINT pk_order_items PRIMARY KEY (order_id, item_no)
```

## 2.3.3. UNIQUE: уникальность значений

Ограничение **UNIQUE** требует, чтобы в столбце (или комбинации столбцов) не было двух одинаковых значений. В отличие от первичного ключа, **NULL допускается**: несколько строк могут содержать NULL в столбце с UNIQUE (в Oracle NULL не считается равным NULL при проверке уникальности). Таблица может иметь несколько ограничений UNIQUE. Oracle создаёт уникальный индекс для проверки. См. [Глоссарий](glossary.md).

Примеры:

```sql
CREATE TABLE employees (
  id     NUMBER(10)    PRIMARY KEY,
  email  VARCHAR2(100) UNIQUE NOT NULL,
  phone  VARCHAR2(20)  UNIQUE
);
```

Имя столбца `email` должно быть уникальным и не пустым; `phone` — уникальным, но может быть NULL (несколько сотрудников без телефона). Составное UNIQUE объявляют out-of-line:

```sql
UNIQUE (col_a, col_b)
```

## 2.3.4. CHECK: проверка по условию

Ограничение **CHECK** задаёт условие (логическое выражение), которому должна удовлетворять каждая строка. Если условие ложно для вставляемой или обновляемой строки, операция завершается ошибкой. Условие может ссылаться на один или несколько столбцов той же таблицы; подзапросы и вызовы недетерминированных функций (SYSDATE, USER и т.д.) в CHECK в Oracle **не допускаются**. См. [Глоссарий](glossary.md).

Примеры:

```sql
CREATE TABLE orders (
  id        NUMBER(10)   PRIMARY KEY,
  status    VARCHAR2(20) NOT NULL,
  total     NUMBER(12,2) NOT NULL,
  CONSTRAINT chk_status CHECK (status IN ('NEW', 'CONFIRMED', 'SHIPPED', 'CANCELLED')),
  CONSTRAINT chk_total  CHECK (total >= 0)
);
```

Inline (только для одного столбца):

```sql
total NUMBER(12,2) CHECK (total >= 0)
```

Out-of-line позволяет ссылаться на несколько столбцов, например:

```sql
CONSTRAINT chk_dates CHECK (start_date <= end_date)
```

## 2.3.5. FOREIGN KEY: ссылочная целостность

Ограничение **FOREIGN KEY** связывает столбец (или группу столбцов) с первичным ключом или уникальным ключом другой таблицы (или той же). Значения в столбце-внешнем ключе должны либо совпадать со значением в родительской таблице, либо быть NULL (если столбец допускает NULL). Родительская таблица должна существовать, а ссылаться нужно на столбцы с ограничением PRIMARY KEY или UNIQUE. См. [Глоссарий](glossary.md).

**Синтаксис (out-of-line):**

```sql
FOREIGN KEY (столбец_ребёнка [, ...]) REFERENCES родительская_таблица [(столбец_родителя [, ...])]
```

Если не указать столбцы родителя, подразумевается первичный ключ родительской таблицы. Пример:

```sql
CREATE TABLE orders (
  id         NUMBER(10)  PRIMARY KEY,
  customer_id NUMBER(10) NOT NULL,
  order_date DATE       NOT NULL,
  CONSTRAINT fk_orders_customer FOREIGN KEY (customer_id) REFERENCES customers (id)
);
```

Таблица `customers` должна иметь столбец `id` (обычно первичный ключ). В `orders` в `customer_id` можно вставить только значение, существующее в `customers.id`, или NULL, если столбец допускает NULL.

**ON DELETE:** при удалении строки из родительской таблицы поведение по умолчанию — запрет удаления, если на неё ссылаются дочерние строки. Можно задать:

- **ON DELETE CASCADE** — при удалении родительской строки Oracle удаляет все дочерние строки, ссылающиеся на неё.
- **ON DELETE SET NULL** — внешний ключ в дочерних строках устанавливается в NULL (столбец должен допускать NULL).

Пример:

```sql
CONSTRAINT fk_orders_customer FOREIGN KEY (customer_id)
  REFERENCES customers (id) ON DELETE SET NULL
```

Inline для одного столбца:

```sql
customer_id NUMBER(10) REFERENCES customers (id)
```

Составной внешний ключ и ссылка на составной уникальный ключ задаются только out-of-line с перечислением столбцов в том же порядке, что и в родителе.

## 2.3.6. Именование ограничнений

Любое ограничение можно назвать явно с помощью **CONSTRAINT имя_ограничения** перед ключевым словом типа ограничения. Имя должно удовлетворять правилам идентификаторов Oracle (до 30 байт, буквы, цифры, _, $, #); в каталоге данных ограничения видны в USER_CONSTRAINTS, ALL_CONSTRAINTS, DBA_CONSTRAINTS. См. [Глоссарий](glossary.md).

Примеры с именами:

```sql
CREATE TABLE products (
  id    NUMBER(10)   CONSTRAINT pk_products PRIMARY KEY,
  name  VARCHAR2(200) NOT NULL,
  code  VARCHAR2(20) CONSTRAINT uq_products_code UNIQUE
);
```

Если имя не задано, Oracle присваивает ограничению системное имя вида **SYS_Cnnnnnn** (уникальное число). Системные имена затрудняют поиск ограничения в скриптах и при разборе ошибок (сообщение об ошибке содержит имя ограничения). Поэтому для важных ограничений рекомендуется задавать осмысленные имена, например: `pk_имя_таблицы` для первичного ключа, `fk_дочерняя_таблица_родительская` для внешнего ключа, `chk_имя_таблицы_назначение` для CHECK, `uq_имя_таблицы_столбец` для UNIQUE.

Список ограничений своей таблицы:

```sql
SELECT constraint_name, constraint_type, search_condition
  FROM user_constraints
 WHERE table_name = 'PRODUCTS';
```

Тип ограничения: P — PRIMARY KEY, U — UNIQUE, R — FOREIGN KEY (referential), C — CHECK или NOT NULL. Текст условия CHECK хранится в SEARCH_CONDITION.

## 2.3.7. Типичные ошибки при работе с ограничениями

- **Объявить NOT NULL out-of-line:** NOT NULL допускается только в определении столбца (inline). Иначе синтаксическая ошибка.
- **Два первичных ключа в одной таблице:** в таблице может быть только один PRIMARY KEY. Второй набор уникальных обязательных столбцов задайте как UNIQUE NOT NULL.
- **FOREIGN KEY на несуществующую таблицу или столбец:** родительская таблица должна существовать, а ссылаться нужно на столбцы с PRIMARY KEY или UNIQUE. Типы и порядок столбцов дочернего и родительского ключа должны совпадать.
- **Удалить родительскую строку при наличии дочерних без ON DELETE:** по умолчанию удаление родительской строки, на которую ссылаются дочерние, запрещено. Нужно либо сначала удалить/обновить дочерние, либо задать ON DELETE CASCADE или ON DELETE SET NULL при создании ограничения.
- **Использовать в CHECK подзапрос или SYSDATE:** условие CHECK не может содержать подзапросы и недетерминированные функции. Проверки, зависящие от других таблиц или от текущего времени, реализуют триггерами или в приложении.
- **Не именовать ограничения:** при ошибке целостности Oracle выводит системное имя (SYS_C...). По осмысленному имени проще найти ограничение в скриптах и в словаре данных.

---

## Ключевое

- **NOT NULL** — запрет NULL в столбце; объявляется только inline (в строке столбца).
- **PRIMARY KEY** — уникальность и запрет NULL; один на таблицу; можно inline или out-of-line; составной ключ — только out-of-line. Oracle создаёт уникальный индекс.
- **UNIQUE** — уникальность значений; NULL допускается (несколько NULL в одном столбце возможно). Несколько ограничений UNIQUE на таблицу.
- **CHECK (условие)** — каждое значение (строка) должно удовлетворять условию. Нельзя подзапросы и недетерминированные функции.
- **FOREIGN KEY ... REFERENCES** — значения столбца(ов) должны существовать в родительской таблице (или быть NULL). **ON DELETE CASCADE** — удалять дочерние при удалении родителя; **ON DELETE SET NULL** — обнулять внешний ключ в дочерних.
- Именование: **CONSTRAINT имя** перед типом ограничения. Без имени Oracle присваивает SYS_Cnnnnnn. Осмысленные имена упрощают отладку и скрипты. Список ограничений — USER_CONSTRAINTS.

В [§2.4](chapter-02-04.md) мы разберём ALTER TABLE: добавление и удаление столбцов и ограничений, изменение типа столбца и связанные ограничения.
