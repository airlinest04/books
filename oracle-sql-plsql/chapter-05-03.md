# §5.3 DELETE

В [§5.2](chapter-05-02.md) мы разобрали обновление строк (UPDATE). Оператор **DELETE** удаляет строки из таблицы. В этом разделе рассмотрим синтаксис **DELETE** с условием **WHERE**, использование **подзапроса в WHERE** для отбора удаляемых строк, а также кратко **TRUNCATE** — команду полной очистки таблицы (DDL), отличающуюся от DELETE по поведению и откату. MERGE (вставка или обновление в одном операторе) — в [§5.4](chapter-05-04.md). См. [Глоссарий](glossary.md).

---

## 5.3.1. Синтаксис DELETE

Общая форма:

```sql
DELETE FROM имя_таблицы [псевдоним] [WHERE условие];
```

**DELETE FROM таблица** без WHERE удаляет **все строки** таблицы. Таблица остаётся (структура и метаданные), но данных в ней не остаётся. С **WHERE** удаляются только те строки, для которых условие истинно. Условие может быть любым допустимым в SQL: сравнения, IN, EXISTS, подзапросы и т.д. См. [Глоссарий](glossary.md).

Примеры:

```sql
DELETE FROM orders WHERE order_id = 100;

DELETE FROM products WHERE status = 'DISCONTINUED';

DELETE FROM order_items WHERE order_id IN (SELECT order_id FROM orders WHERE status = 'CANCELLED');
```

В третьем примере в WHERE используется подзапрос: удаляются позиции заказов, которые помечены как отменённые. DELETE не удаляет столбцы и не меняет структуру таблицы — только строки.

---

## 5.3.2. Подзапрос в WHERE при DELETE

Условие WHERE может содержать **подзапросы**: IN (подзапрос), EXISTS, сравнение со скалярным подзапросом. Это позволяет удалять строки по сложным правилам (например, «удалить заказы, у которых нет ни одной позиции в order_items» или «удалить товары, не встречающиеся ни в одном заказе»). См. [Глоссарий](glossary.md).

Пример: удалить клиентов, у которых нет заказов:

```sql
DELETE FROM customers c
 WHERE NOT EXISTS (SELECT 1 FROM orders o WHERE o.customer_id = c.customer_id);
```

Пример с IN:

```sql
DELETE FROM products WHERE id IN (SELECT product_id FROM order_items GROUP BY product_id HAVING COUNT(*) = 0);
```

(Здесь подзапрос должен возвращать список id товаров без заказов; логику подзапроса при необходимости корректируют под реальную схему.) Важно: при удалении проверяйте ограничения целостности — если на таблицу ссылается внешний ключ из другой таблицы, удаление может быть запрещено или каскадно затронет дочерние строки (в зависимости от ON DELETE). См. [§2.3](chapter-02-03.md).

---

## 5.3.3. DELETE и транзакция

DELETE — операция DML (Data Manipulation Language). Она выполняется в рамках **транзакции**: до **COMMIT** изменения не видны другим сессиям и могут быть отменены **ROLLBACK**. После COMMIT удалённые строки вернуть стандартным откатом нельзя. Рекомендуется перед массовым DELETE проверять количество строк (SELECT COUNT(*) ... с тем же WHERE) или выполнить DELETE в тестовой транзакции и сделать ROLLBACK. См. [Глоссарий](glossary.md) и [§8.1](chapter-08-01.md).

---

## 5.3.4. TRUNCATE (кратко)

**TRUNCATE TABLE имя_таблицы** — команда **DDL** (Data Definition Language), которая **удаляет все строки** таблицы. В отличие от DELETE, TRUNCATE не допускает условия WHERE: таблица очищается полностью. См. [Глоссарий](glossary.md).

Основные отличия от DELETE:

- **TRUNCATE** не является DML: в стандартной конфигурации его **нельзя откатить** откатом транзакции (в Oracle после TRUNCATE обычно выполняется неявный COMMIT; откат предыдущих операций в той же транзакции тоже может быть зафиксирован). DELETE откатывается ROLLBACK до COMMIT.
- **TRUNCATE** освобождает место, выделенное под данные таблицы (в зависимости от настроек табличного пространства и реализации), и сбрасывает высокую отметку сегмента. DELETE помечает строки как удалённые и может оставлять место занятым до последующей операций по сжатию/реорганизации.
- **TRUNCATE** быстрее на больших таблицах при полной очистке, так как не пишет построчное удаление в журнал отката в том же объёме, что и DELETE.
- **Ограничения:** на таблицу с TRUNCATE не должны ссылаться внешние ключи из других таблиц (или нужно использовать опции вроде CASCADE в тех СУБД, где они поддерживаются). В Oracle TRUNCATE не сбрасывает последовательности (в отличие от части других СУБД); триггеры на удаление при TRUNCATE, как правило, не выполняются.

Когда использовать: полная очистка таблицы с сохранением структуры, например перед загрузкой новых данных. Когда нужны выборочное удаление или возможность отката в рамках транзакции — используют **DELETE** с WHERE. См. [Глоссарий](glossary.md).

## 5.3.5. Типичные ошибки при использовании DELETE

- **Забыть WHERE:** удаляются все строки таблицы. Перед выполнением убедитесь, что условие задано и верно. Проверьте число строк: `SELECT COUNT(*) FROM таблица WHERE ...`.
- **Нарушение внешнего ключа:** при удалении строки, на которую ссылаются дочерние таблицы, Oracle вернёт ошибку (ORA-02292), если для внешнего ключа не задано ON DELETE CASCADE или ON DELETE SET NULL. Сначала удалите или обновите дочерние строки либо спроектируйте каскады при создании ограничений.
- **Путать DELETE и TRUNCATE:** DELETE — DML, с WHERE, откатывается ROLLBACK. TRUNCATE — DDL, без WHERE, полная очистка, откат в обычном смысле недоступен. Не подменяйте одно другим.
- **Удалять в «неправильном» порядке:** при каскадном удалении данных из связанных таблиц удаляйте сначала дочерние строки (те, что ссылаются на другие), затем родительские. Или используйте ON DELETE CASCADE на внешнем ключе.
- **Не учитывать блокировки:** длинный DELETE блокирует строки (и при необходимости блоки таблицы); другие сессии могут ждать. На больших таблицах иногда удаляют порциями (по частям с COMMIT) или выполняют в окне обслуживания.

## Ключевое

- **DELETE FROM таблица [WHERE условие]** — удаление строк из таблицы. Без WHERE удаляются **все** строки. Условие может содержать подзапросы (IN, EXISTS и т.д.).
- DELETE — операция **DML**; выполняется в транзакции. Для сохранения изменений — **COMMIT**; для отмены — **ROLLBACK** (до коммита).
- **TRUNCATE TABLE таблица** — **DDL**: полная очистка таблицы без условия WHERE. Обычно не откатывается; освобождает место под данные; быстрее DELETE при полной очистке. Использовать для «очистить всю таблицу»; для выборочного удаления — DELETE.
- При удалении учитывайте **внешние ключи**: удаление родительской строки при наличии ссылок возможно только при ON DELETE CASCADE/SET NULL или после удаления/обновления дочерних строк.
- Перед массовым DELETE проверяйте условие WHERE (SELECT с тем же WHERE) и при необходимости выполняйте в тестовой транзакции с ROLLBACK.
