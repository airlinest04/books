# §2.4 ALTER TABLE

В [§2.3](chapter-02-03.md) мы разобрали ограничения целостности при создании таблицы. Структуру таблицы можно менять и после создания: добавлять и удалять столбцы, добавлять и удалять ограничения, изменять тип или атрибуты столбца. Для этого служит оператор **ALTER TABLE**. В этом разделе рассмотрены основные варианты: **добавление столбцов (ADD)**, **удаление столбцов (DROP COLUMN)**, **изменение столбца (MODIFY)**, а также **добавление и удаление ограничений**. Отдельно разберём **ограничения при изменении типа** и данных в таблице. Последовательности (SEQUENCE) и их использование для первичных ключей — в [§2.5](chapter-02-05.md). См. [Глоссарий](glossary.md).

---

## 2.4.1. Добавление столбца (ADD)

К существующей таблице можно добавить один или несколько столбцов с помощью **ADD**. Синтаксис для одного столбца:

```sql
ALTER TABLE имя_таблицы ADD (имя_столбца тип_данных [DEFAULT выражение] [ограничения_столбца]);
```

Скобки вокруг определения столбца обязательны. Новый столбец появляется в конце списка столбцов (порядок столбцов в физическом хранении в Oracle не задаётся явно; для выборки порядок определяется списком в SELECT или метаданными). Если указан **DEFAULT**, то для всех уже существующих строк в новом столбце подставляется это значение; без DEFAULT в существующих строках в новом столбце будет NULL (если столбец допускает NULL). См. [Глоссарий](glossary.md).

Примеры:

```sql
ALTER TABLE products ADD (created_at DATE DEFAULT SYSDATE);

ALTER TABLE products ADD (
  updated_at DATE,
  description VARCHAR2(1000)
);
```

В первом случае добавлен один столбец с значением по умолчанию; во втором — два столбца за один оператор. К новому столбцу можно сразу добавить ограничение NOT NULL только если задан DEFAULT или если таблица пуста; иначе Oracle не сможет заполнить значения в существующих строках.

## 2.4.2. Удаление столбца (DROP COLUMN)

Столбец удаляется предложением **DROP COLUMN** или **DROP (список_столбцов)**. Синтаксис:

```sql
ALTER TABLE имя_таблицы DROP COLUMN имя_столбца [CASCADE CONSTRAINTS];
```

**CASCADE CONSTRAINTS** — удалить все ограничения (в том числе в других таблицах), которые ссылаются на этот столбец. Например, если на столбец ссылается внешний ключ из другой таблицы или по столбцу построен уникальный/первичный ключ, без CASCADE CONSTRAINTS операция может завершиться ошибкой; с CASCADE CONSTRAINTS Oracle удалит зависимые ограничения (внешние ключи, ссылающиеся на этот столбец, и т.д.). Удаление нескольких столбцов за раз:

```sql
ALTER TABLE products DROP (col_a, col_b);
```

Либо по одному столбцу в нескольких предложениях DROP COLUMN. После удаления столбца данные в нём теряются; откатить операцию можно только восстановлением из резервной копии или повторным ADD с загрузкой данных. См. [Глоссарий](glossary.md).

## 2.4.3. Изменение столбца (MODIFY)

Предложение **MODIFY** меняет тип данных, размер, значение по умолчанию или ограничение NOT NULL у существующего столбца. Синтаксис:

```sql
ALTER TABLE имя_таблицы MODIFY (имя_столбца [тип_данных] [DEFAULT выражение] [NOT NULL | NULL]);
```

Не обязательно указывать все атрибуты: можно изменить только размер VARCHAR2, только DEFAULT или только NULL/NOT NULL. Ограничения при изменении типа и размера:

- **Увеличение размера** (например, VARCHAR2(100) → VARCHAR2(200)) обычно допускается, если новые значения вмещают существующие данные.
- **Уменьшение размера** или смена типа возможны только если существующие данные укладываются в новый тип и размер; иначе Oracle вернёт ошибку.
- **Добавление NOT NULL** к столбцу возможно только если в таблице нет строк с NULL в этом столбце. Предварительно обновите NULL-значения или задайте DEFAULT.

Примеры:

```sql
-- увеличить длину столбца
ALTER TABLE products MODIFY (description VARCHAR2(2000));

-- задать значение по умолчанию
ALTER TABLE orders MODIFY (status VARCHAR2(20) DEFAULT 'NEW');

-- сделать столбец обязательным (если NULL уже нет)
ALTER TABLE users MODIFY (email VARCHAR2(100) NOT NULL);
```

Изменить имя столбца можно отдельной командой **RENAME COLUMN** (см. ниже). См. [Глоссарий](glossary.md).

---

## 2.4.4. Переименование столбца (RENAME COLUMN)

Чтобы переименовать столбец без изменения типа и данных:

```sql
ALTER TABLE имя_таблицы RENAME COLUMN старое_имя TO новое_имя;
```

Oracle обновит метаданные; зависимости (представления, синонимы, ограничения внутри таблицы) могут потребовать проверки. Представления и объекты, ссылающиеся на старый имя столбца, станут невалидными и при обращении могут выдавать ошибку до пересоздания или перекомпиляции. См. [Глоссарий](glossary.md).

## 2.4.5. Добавление ограничения (ADD constraint)

Ограничения можно добавлять к уже созданной таблице с помощью **ADD** и синтаксиса ограничения (как out-of-line в CREATE TABLE). Таблица и данные должны удовлетворять добавляемому ограничению: например, при добавлении PRIMARY KEY в столбце не должно быть дубликатов и NULL.

Примеры:

```sql
-- первичный ключ
ALTER TABLE products ADD CONSTRAINT pk_products PRIMARY KEY (id);

-- уникальность
ALTER TABLE users ADD CONSTRAINT uq_users_login UNIQUE (login);

-- внешний ключ
ALTER TABLE orders ADD CONSTRAINT fk_orders_customer
  FOREIGN KEY (customer_id) REFERENCES customers (id) ON DELETE SET NULL;

-- проверка
ALTER TABLE orders ADD CONSTRAINT chk_orders_total CHECK (total >= 0);

-- NOT NULL (через MODIFY)
ALTER TABLE users MODIFY (login VARCHAR2(50) NOT NULL);
```

NOT NULL добавляется не ADD CONSTRAINT, а **MODIFY** столбца с указанием NOT NULL (см. выше). Для добавления первичного или уникального ключа Oracle создаёт индекс, если подходящего ещё нет. См. [Глоссарий](glossary.md).

---

## 2.4.6. Удаление ограничения (DROP CONSTRAINT)

Ограничение удаляется по имени:

```sql
ALTER TABLE имя_таблицы DROP CONSTRAINT имя_ограничения [CASCADE];
```

**CASCADE** сбрасывает зависимые ограничения (например, внешние ключи из других таблиц, ссылающиеся на данный первичный или уникальный ключ). Без CASCADE при наличии таких зависимостей операция завершится ошибкой. Удаление первичного или уникального ключа, созданного с системным индексом, приводит к удалению этого индекса; если использовался существующий индекс — индекс остаётся. См. [Глоссарий](glossary.md).

Пример:

```sql
ALTER TABLE orders DROP CONSTRAINT fk_orders_customer;
ALTER TABLE products DROP CONSTRAINT pk_products CASCADE;
```

Имя ограничения можно посмотреть в USER_CONSTRAINTS (см. §2.3).

## 2.4.7. Ограничения при изменении типа и размера

При **MODIFY** столбца с изменением типа или размера Oracle проверяет совместимость с существующими данными:

- Нельзя уменьшить размер VARCHAR2/NUMBER так, чтобы часть существующих значений не помещалась (например, строка длиной 150 символов при сокращении до VARCHAR2(100)).
- Нельзя сменить тип на несовместимый (например, VARCHAR2 на DATE при произвольных строках). Допустимые неявные преобразования определяются правилами Oracle.
- Расширение VARCHAR2, увеличение точности NUMBER обычно допустимы. Добавление дробной части к NUMBER (увеличение scale) при наличии данных возможно с ограничениями; лучше проверять в документации для конкретной версии.

Если таблица большая, ALTER TABLE ... MODIFY может занять время и блокировать таблицу; в части сценариев применяют создание новой таблицы с нужной структурой, перенос данных и переименование. Для учебных и небольших таблиц MODIFY по одному столбцу обычно достаточен. См. [Глоссарий](glossary.md).

## 2.4.8. Типичные ошибки при ALTER TABLE

- **Добавить NOT NULL к столбцу с NULL без DEFAULT:** если в таблице уже есть строки с NULL, добавление NOT NULL через MODIFY приведёт к ошибке. Сначала обновите NULL на значение или задайте DEFAULT и затем MODIFY ... NOT NULL.
- **Удалить столбец, на который ссылается ограничение:** используйте DROP COLUMN ... CASCADE CONSTRAINTS или сначала удалите зависимые ограничения (внешние ключи в других таблицах, ссылающиеся на этот столбец).
- **Уменьшить размер столбца при наличии длинных данных:** проверьте максимальную длину данных в столбце (например, SELECT MAX(LENGTH(column)) FROM table) и задайте размер не меньше этого значения.
- **Удалить ограничение по неверному имени:** без явного имени ограничения получают вид SYS_Cnnnnnn; имя можно посмотреть в USER_CONSTRAINTS. При ошибке «constraint not found» проверьте имя и схему таблицы.
- **Добавить PRIMARY KEY при дубликатах или NULL:** перед ADD CONSTRAINT pk ... PRIMARY KEY убедитесь, что в столбце(ах) нет повторяющихся значений и NULL. Иначе операция не выполнится.
- **Забыть CASCADE при DROP CONSTRAINT для первичного ключа:** если на первичный ключ ссылаются внешние ключи в других таблицах, нужно либо сначала удалить их, либо использовать DROP CONSTRAINT ... CASCADE (при этом удалятся и зависимые внешние ключи).

---

## Ключевое

- **ADD (столбец ...)** — добавление одного или нескольких столбцов; можно задать DEFAULT и ограничения. Существующие строки получают NULL или DEFAULT в новом столбце.
- **DROP COLUMN** / **DROP (col1, col2)** — удаление столбца(ов). **CASCADE CONSTRAINTS** удаляет ограничения, зависящие от этого столбца.
- **MODIFY (столбец тип|DEFAULT|NOT NULL|NULL)** — изменение типа, размера, значения по умолчанию или признака NULL/NOT NULL. Уменьшение размера и смена типа возможны только при совместимости с существующими данными.
- **RENAME COLUMN** старое TO новое — переименование столбца.
- **ADD CONSTRAINT** ... — добавление ограничения (PK, UNIQUE, FK, CHECK). NOT NULL добавляется через MODIFY.
- **DROP CONSTRAINT** имя **[CASCADE]** — удаление ограничения по имени; CASCADE сбрасывает зависимые ограничения (например, внешние ключи на этот ключ).
- При изменении типа/размера данные должны соответствовать новому определению; иначе Oracle вернёт ошибку.

В [§2.5](chapter-02-05.md) мы разберём последовательности (SEQUENCE): создание, NEXTVAL, CURRVAL и использование для генерации значений первичного ключа.
