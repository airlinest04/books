# §1.3 Основные объекты

В [§1.2](chapter-01-02.md) мы разобрали подключение к базе: строку подключения, Easy Connect, роли и привилегии. После входа под своим пользователем вы работаете в контексте **схемы** — набора объектов, принадлежащих этому пользователю. В этом разделе мы даём обзор **основных объектов** схемы, с которыми вы будете сталкиваться постоянно: **таблицы**, **представления (views)**, **синонимы (synonyms)** и **последовательности (sequences)**. Затем разберём **каталог данных (data dictionary)** Oracle — системные представления **USER_\***, **ALL_\*** и **DBA_\***, с помощью которых можно просматривать список объектов, их структуру и метаданные без выхода из SQL. Это позволит уверенно ориентироваться в схеме и подготовиться к первому запросу в [§1.4](chapter-01-04.md). См. [Глоссарий](glossary.md).

---

## 1.3.1. Таблицы

**Таблица (table)** — основной объект хранения данных в реляционной модели: строки (записи) и столбцы (атрибуты). В Oracle каждая таблица принадлежит одной схеме и хранится в табличном пространстве (по умолчанию — DEFAULT TABLESPACE пользователя). Данные таблицы физически размещаются в сегментах; к таблице обращаются по имени (в своей схеме — просто `имя_таблицы`, в чужой — `схема.имя_таблицы`). См. [Глоссарий](glossary.md).

Создание таблиц (CREATE TABLE), типы данных столбцов и ограничения целостности мы подробно разберём в [главе 2](chapter-02-01.md). Здесь достаточно понимать: таблица — это объект схемы, в котором хранятся данные; список своих таблиц и их метаданные можно посмотреть в представлениях словаря данных (см. подраздел 1.3.5). В SQL Developer в панели соединения под схемой отображается ветка «Tables» со списком таблиц; в SQL*Plus для просмотра структуры таблицы служит команда `DESCRIBE имя_таблицы` (или `DESC`).

## 1.3.2. Представления (views)

**Представление (view)** — именованный запрос SELECT, сохранённый в базе как объект схемы. При обращении к представлению Oracle выполняет лежащий в его основе запрос и возвращает результат как «виртуальную таблицу»: данные не хранятся в представлении отдельно, они всегда берутся из базовых таблиц (или других представлений). См. [Глоссарий](glossary.md).

Зачем нужны представления:

- **Упрощение запросов:** сложный JOIN или подзапрос задаётся один раз в определении представления; пользователи обращаются к нему как к таблице (`SELECT * FROM my_view`).
- **Ограничение доступа к данным:** в представлении можно выбрать только нужные столбцы и строки (WHERE), не давая прямого доступа к полной таблице.
- **Логическая независимость:** при изменении структуры базовых таблиц можно подправить определение представления так, чтобы прежние запросы к представлению продолжали работать.

Представления создаются командой `CREATE VIEW имя AS SELECT ...`; изменение определения — `CREATE OR REPLACE VIEW`. Подробнее создание и использование представлений — в [§7.4](chapter-07-04.md). Список представлений своей схемы доступен в словаре данных: USER_VIEWS, ALL_VIEWS, DBA_VIEWS.

## 1.3.3. Синонимы (synonyms)

**Синоним (synonym)** — альтернативное имя для объекта (таблицы, представления, последовательности, процедуры и т.д.). Синоним может ссылаться на объект в той же схеме или в другой; обращение к синониму эквивалентно обращению к объекту, на который он указывает. См. [Глоссарий](glossary.md).

Различают:

- **Приватный синоним (private synonym):** создаётся в схеме пользователя и виден только ему. Удобно, чтобы не писать длинное имя или префикс схемы: например, синоним `EMP` на `HR.EMPLOYEES`.
- **Публичный синоним (public synonym):** принадлежит «общедоступному» пространству имён; к нему могут обращаться все пользователи (при наличии привилегий на целевой объект). Создаётся обычно администратором.

Пример создания приватного синонима в своей схеме:

```sql
CREATE SYNONYM emp FOR HR.EMPLOYEES;
```

После этого запрос `SELECT * FROM emp` (при наличии привилегии SELECT на HR.EMPLOYEES) будет обращаться к таблице HR.EMPLOYEES. Без синонима пришлось бы писать `SELECT * FROM HR.EMPLOYEES`. Синонимы не хранят данных — это только ссылка на объект; список синонимов можно посмотреть в USER_SYNONYMS, ALL_SYNONYMS, DBA_SYNONYMS.

---

## 1.3.4. Последовательности (sequences)

**Последовательность (sequence)** — объект схемы, генерирующий последовательные числовые значения. Используется часто для уникальных идентификаторов (первичные ключи): при вставке новой строки подставляют следующее значение последовательности (NEXTVAL). См. [Глоссарий](glossary.md).

Создание и использование (NEXTVAL, CURRVAL) мы разберём в [§2.5](chapter-02-05.md). Здесь важно знать: последовательность — это объект схемы, отдельный от таблиц; список последовательностей отображается в USER_SEQUENCES, ALL_SEQUENCES, DBA_SEQUENCES. В SQL Developer они отображаются в ветке «Sequences» под схемой.

## 1.3.5. Каталог данных: представления USER_*, ALL_*, DBA_*

**Каталог данных (data dictionary)** Oracle — набор системных таблиц и представлений, в которых хранится метаинформация о базе: объекты схем, столбцы таблиц, привилегии, ограничения и т.д. Доступ к этой информации для прикладных запросов осуществляется в основном через **представления словаря данных (data dictionary views)**. По соглашению имена многих из них имеют префикс **USER_**, **ALL_** или **DBA_**, что задаёт область видимости. См. [Глоссарий](glossary.md).

| Префикс | Область видимости |
|---------|-------------------|
| **USER_** | Объекты, **принадлежащие текущему пользователю** (его схеме). Нет столбца OWNER — владелец подразумевается. |
| **ALL_** | Объекты, **доступные текущему пользователю**: свои плюс объекты других схем, на которые выданы привилегии. Есть столбец OWNER (схема-владелец). |
| **DBA_** | **Все объекты в базе** независимо от владельца. Доступно только пользователям с привилегиями DBA (например, роль DBA или SELECT ANY DICTIONARY). |

Типичные представления (для каждого префикса есть своя версия, где это применимо):

| Представление | Содержимое |
|---------------|------------|
| USER_TABLES / ALL_TABLES / DBA_TABLES | Таблицы (имя, табличное пространство, число строк и др.). |
| USER_VIEWS / ALL_VIEWS / DBA_VIEWS | Представления и текст запроса (VIEW_TYPE, TEXT). |
| USER_SEQUENCES / ALL_SEQUENCES / DBA_SEQUENCES | Последовательности (текущее значение, инкремент и т.д.). |
| USER_SYNONYMS / ALL_SYNONYMS / DBA_SYNONYMS | Синонимы (имя, объект, на который ссылаются, схема объекта). |
| USER_OBJECTS / ALL_OBJECTS / DBA_OBJECTS | Сводка объектов: имя, тип (TABLE, VIEW, SEQUENCE, SYNONYM, PROCEDURE и т.д.), дата создания, статус. |
| USER_TAB_COLUMNS / ALL_TAB_COLUMNS / DBA_TAB_COLUMNS | Столбцы таблиц (и представлений): имя столбца, тип данных, длина, nullable. |

Примеры запросов к словарю данных (после подключения под своим пользователем):

Список таблиц своей схемы:

```sql
SELECT table_name FROM user_tables ORDER BY table_name;
```

Список всех объектов своей схемы с типом:

```sql
SELECT object_name, object_type FROM user_objects ORDER BY object_type, object_name;
```

Столбцы таблицы (замените `MY_TABLE` на имя таблицы):

```sql
SELECT column_name, data_type, data_length, nullable
  FROM user_tab_columns
 WHERE table_name = 'MY_TABLE'
 ORDER BY column_id;
```

Список таблиц, доступных текущему пользователю (свои и чужие, на которые есть права), с указанием владельца:

```sql
SELECT owner, table_name FROM all_tables ORDER BY owner, table_name;
```

Имена представлений словаря данных обычно в верхнем регистре; имена объектов в запросах (например, имена таблиц в USER_TABLES) хранятся в верхнем регистре, если при создании не использовались кавычки. Поэтому в условиях удобно использовать `UPPER(table_name) = 'MY_TABLE'` или писать имена в верхнем регистре. Подробнее об именах и регистре — в [§2.1](chapter-02-01.md).

Использование словаря данных помогает: проверить, какие объекты есть в схеме; посмотреть структуру таблицы (столбцы, типы); выяснить, к каким объектам других схем есть доступ; отладить права доступа. Представления DBA_* требуют повышенных привилегий и используются в основном администраторами.

## 1.3.6. Где смотреть объекты в SQL Developer и SQL*Plus

В **SQL Developer** после подключения в левой панели «Connections» раскройте соединение: под ним отображаются узлы «Tables», «Views», «Synonyms», «Sequences», «Procedures» и др. Раскрытие узла показывает список объектов выбранной схемы. Двойной щелчок по таблице открывает структуру и данные; по представлению или синониму — определение или целевой объект. Имя текущей схемы совпадает с именем пользователя, под которым вы подключились.

В **SQL*Plus** для просмотра структуры таблицы используется:

```text
DESC[RIBE] имя_таблицы
```

Вывод — список столбцов с типами и признаком NULL. Список таблиц или других объектов удобно получать запросами к USER_TABLES, USER_OBJECTS и т.д., как в примерах выше. Команда `SHOW USER` выводит имя текущего подключённого пользователя (схемы).

## 1.3.7. Типичные ошибки при работе с объектами схемы

- **Обращаться к объекту другой схемы без префикса или без синонима:** в своей схеме объект вызывается по имени; объект из схемы HR — как `HR.имя_объекта` (при наличии привилегий). Иначе Oracle ищет объект в своей схеме и выдаёт «table or view does not exist».
- **Путать USER_* и ALL_*:** USER_TABLES показывает только ваши таблицы; ALL_TABLES — ваши плюс таблицы других схем, на которые вам дали права. Если нужны «все мои объекты» — используйте USER_OBJECTS; если «все доступные мне таблицы с указанием владельца» — ALL_TABLES.
- **Искать объект в DBA_* без прав:** представления DBA_* доступны только при наличии привилегий уровня DBA (или SELECT_CATALOG_ROLE и т.п.). Обычному пользователю достаточно USER_* и ALL_*.
- **Считать представление копией данных:** представление не хранит данные; при каждом обращении к нему выполняется лежащий в основе SELECT. Большие или сложные представления могут выполняться долго; для «снимка» данных используется материализованное представление ([§7.4](chapter-07-04.md)).
- **Забывать про регистр имён в словаре:** имена объектов в словаре по умолчанию в верхнем регистре. При сравнении в WHERE используйте верхний регистр или UPPER(column).

## Ключевое

- **Таблица** — объект хранения данных (строки и столбцы); принадлежит схеме, создаётся и изменяется в главе 2.
- **Представление (view)** — сохранённый запрос SELECT; при обращении данные подставляются из базовых таблиц; упрощает запросы и ограничивает доступ.
- **Синоним (synonym)** — альтернативное имя для объекта (своей или другой схемы); приватный — в своей схеме, публичный — для всех.
- **Последовательность (sequence)** — объект для генерации последовательных чисел (NEXTVAL/CURRVAL); подробнее в §2.5.
- **Каталог данных (data dictionary)** — системные представления с метаданными. **USER_*** — объекты своей схемы; **ALL_*** — объекты, доступные текущему пользователю (есть OWNER); **DBA_*** — все объекты базы (требуются привилегии DBA).
- Полезные представления: USER_TABLES, USER_OBJECTS, USER_TAB_COLUMNS, ALL_TABLES. В SQL*Plus структура таблицы — `DESC имя_таблицы`; в SQL Developer — дерево объектов по типам под соединением.

В [§1.4](chapter-01-04.md) мы выполним первый запрос SELECT в SQL*Plus или SQL Developer и настроим базовое форматирование вывода.
