# §6.2 UPDATE

В [§6.1](chapter-06-01.md) мы рассмотрели INSERT. **UPDATE** изменяет значения столбцов в существующих строках таблицы. В этом разделе разберём синтаксис SET, условие WHERE, обновление нескольких столбцов, использование выражений и DEFAULT, UPDATE с FROM и RETURNING. Опасность UPDATE без WHERE рассматривается в [§6.4](chapter-06-04.md). См. [документацию UPDATE](https://www.postgresql.org/docs/current/sql-update.html).

---

## 6.2.1. Базовый синтаксис

По [документации](https://www.postgresql.org/docs/current/sql-update.html):

```sql
UPDATE имя_таблицы
SET столбец1 = выражение1 [, столбец2 = выражение2, ...]
[WHERE условие];
```

Меняются только строки, для которых условие WHERE даёт TRUE. Столбцы, не указанные в SET, сохраняют прежние значения.

Пример:

```sql
UPDATE products SET price = 99.99 WHERE id = 5;
UPDATE orders SET status = 'shipped', shipped_at = now() WHERE id = 100;
```

---

## 6.2.2. WHERE обязателен по смыслу

Без предложения WHERE обновляются **все** строки таблицы. Обычно это ошибка. Всегда проверяйте условие перед выполнением UPDATE; для критичных операций — в транзакции с последующей проверкой и при необходимости ROLLBACK (см. [§6.4](chapter-06-04.md)).

---

## 6.2.3. Несколько столбцов

В SET можно перечислить несколько присваиваний через запятую:

```sql
UPDATE users SET name = 'Иванов И.И.', email = 'new@example.com', updated_at = now()
WHERE id = 1;
```

Альтернативный синтаксис — список столбцов и список значений в скобках:

```sql
UPDATE users SET (name, email) = ('Иванов И.И.', 'new@example.com')
WHERE id = 1;
```

---

## 6.2.4. Выражения в SET

В правой части присваивания может быть не только константа, но и выражение, в том числе с использованием текущих значений столбцов:

```sql
UPDATE products SET price = price * 1.1 WHERE category_id = 1;
UPDATE orders SET total = total - 10 WHERE id = 5 AND total >= 10;
UPDATE logs SET count = count + 1 WHERE id = 42;
```

Выражения вычисляются до присваивания; ссылки на столбцы в правой части — это старые (до обновления) значения.

---

## 6.2.5. DEFAULT

Ключевое слово **DEFAULT** в SET восстанавливает значение по умолчанию для столбца:

```sql
UPDATE orders SET status = DEFAULT WHERE id = 10;
UPDATE users SET phone = DEFAULT WHERE id = 5;
```

Для столбца с `DEFAULT now()` будет подставлена текущая дата и время в момент выполнения.

---

## 6.2.6. UPDATE с подзапросом

Значение для столбца может задаваться подзапросом. Подзапрос должен возвращать не более одной строки; при отсутствии строк подставляется NULL:

```sql
UPDATE accounts
SET (contact_first_name, contact_last_name) =
  (SELECT first_name, last_name FROM employees WHERE employees.id = accounts.sales_person)
WHERE sales_person IS NOT NULL;
```

---

## 6.2.7. UPDATE ... FROM

Предложение **FROM** позволяет подключить другие таблицы и использовать их столбцы в SET и WHERE. Целевая таблица соединяется с таблицами из FROM; обновляются строки целевой таблицы, участвующие в соединении:

```sql
UPDATE orders o
SET status = 'processed'
FROM shipments s
WHERE o.id = s.order_id AND s.delivered_at IS NOT NULL;
```

Или обновление на основе данных из другой таблицы:

```sql
UPDATE products p
SET price = p.price * (1 + c.tax_rate / 100)
FROM categories c
WHERE p.category_id = c.id;
```

При использовании FROM важно, чтобы соединение давало не более одной строки на каждую обновляемую строку; иначе результат может быть неочевидным. Подробнее — в документации.

---

## 6.2.8. RETURNING

Предложение **RETURNING** возвращает обновлённые строки (по умолчанию — новые значения):

```sql
UPDATE products SET price = price * 1.1 WHERE category_id = 1
RETURNING id, name, price;
```

Можно вернуть старые значения через OLD:

```sql
UPDATE orders SET status = 'shipped' WHERE id = 5
RETURNING OLD.status AS old_status, status AS new_status;
```

RETURNING полезен для проверки результата или для получения обновлённых данных без отдельного SELECT.

---

## 6.2.9. Число обновлённых строк

PostgreSQL возвращает сообщение вида `UPDATE n`, где `n` — количество обновлённых строк. В приложениях это значение часто доступно через API (например, `rowCount`). Строки, для которых новое значение совпадает со старым, всё равно считаются обновлёнными.

---

## 6.2.10. Ограничения при обновлении

При UPDATE проверяются ограничения таблицы (NOT NULL, UNIQUE, CHECK, FOREIGN KEY и т.д.). Нарушение ограничения приводит к ошибке и откату команды. При обновлении столбца, участвующего во внешнем ключе, действуют правила ON UPDATE (см. [§2.3](chapter-02-03.md)).

---

## 6.2.11. Типичные ошибки

- **UPDATE без WHERE** — обновляются все строки; почти всегда нежелательно.
- **Неточное условие WHERE** — обновляются не те строки; перед массовым UPDATE полезно выполнить `SELECT ... WHERE ...` и проверить результат.
- **Подзапрос возвращает несколько строк** — ошибка; подзапрос должен возвращать не более одной строки.
- **FROM с дубликатами** — при нескольких строках соединения для одной целевой строки результат неоднозначен; следите за уникальностью соединения.

---

## Ключевое

- **UPDATE таблица SET столбец = значение [WHERE условие]** — изменение существующих строк.
- Без WHERE обновляются все строки таблицы; условие обычно обязательно.
- В SET допустимы выражения (в том числе ссылки на текущие значения столбцов) и DEFAULT.
- **UPDATE ... FROM** — обновление с использованием данных из других таблиц.
- **RETURNING** — возврат обновлённых строк (новых или старых через OLD).
- Перед массовым UPDATE проверяйте выборку через SELECT.

В [§6.3](chapter-06-03.md) рассмотрим DELETE — удаление строк из таблицы.
