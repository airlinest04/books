# §6.1 INSERT

В [§5.3](chapter-05-03.md) мы завершили раздел о сортировке и ограничении результатов. **INSERT** добавляет новые строки в таблицу. В этом разделе разберём синтаксис INSERT с VALUES, вставку нескольких строк, использование DEFAULT, вставку из запроса (INSERT ... SELECT) и предложение RETURNING. ON CONFLICT (UPSERT) рассматривается в [§6.5](chapter-06-05.md). См. [документацию INSERT](https://www.postgresql.org/docs/current/sql-insert.html).

---

## 6.1.1. Базовый синтаксис

По [документации](https://www.postgresql.org/docs/current/sql-insert.html):

```sql
INSERT INTO имя_таблицы [ (столбец1 [, столбец2, ...] ) ]
VALUES (значение1 [, значение2, ...]);
```

Список столбцов можно опустить — тогда значения связываются с столбцами таблицы в порядке их объявления. Рекомендуется явно указывать столбцы: запрос понятнее и устойчивее к изменению структуры таблицы.

Пример:

```sql
INSERT INTO users (id, name, email) VALUES (1, 'Иванов', 'ivan@example.com');
INSERT INTO products (name, price) VALUES ('Товар А', 99.99);
```

---

## 6.1.2. Соответствие значений и столбцов

Значения в VALUES сопоставляются столбцам слева направо. Число значений должно совпадать с числом столбцов (явно указанных или неявных). Типы должны быть совместимы; при необходимости PostgreSQL выполняет приведение.

Столбцы, не указанные в списке, получают значение по умолчанию (DEFAULT) или NULL, если DEFAULT не задан (см. [§2.3](chapter-02-03.md)).

---

## 6.1.3. DEFAULT

Ключевое слово **DEFAULT** в VALUES подставляет значение по умолчанию для соответствующего столбца (serial, now(), константа из DEFAULT и т.п.):

```sql
INSERT INTO orders (customer_id, total, status, created_at)
VALUES (10, 150.00, DEFAULT, DEFAULT);
```

Для столбца с `DEFAULT now()` будет подставлена текущая дата и время. Для serial — следующее значение последовательности.

---

## 6.1.4. DEFAULT VALUES

Чтобы вставить одну строку, где все столбцы получают значения по умолчанию:

```sql
INSERT INTO таблица DEFAULT VALUES;
```

Список столбцов не указывается. Для таблицы без DEFAULT хотя бы у одного столбца возникнет ошибка (нельзя подставить NULL в NOT NULL без DEFAULT).

---

## 6.1.5. Несколько строк за один INSERT

Можно вставить несколько строк одной командой, перечислив группы значений через запятую:

```sql
INSERT INTO users (name, email) VALUES
  ('Иванов', 'ivan@example.com'),
  ('Петров', 'petr@example.com'),
  ('Сидорова', 'sidorova@example.com');
```

Каждая скобочная группа — одна строка. Число и типы значений в каждой группе должны совпадать.

---

## 6.1.6. INSERT ... SELECT

Вместо VALUES можно использовать результат запроса. Строки из SELECT вставляются в таблицу:

```sql
INSERT INTO таблица_назначения [ (столбец1, столбец2, ...) ]
SELECT столбец1, столбец2, ... FROM источник [WHERE ...];
```

Число и типы столбцов в SELECT должны соответствовать списку столбцов таблицы назначения. Пример — копирование данных:

```sql
INSERT INTO orders_archive (id, customer_id, total, created_at)
SELECT id, customer_id, total, created_at
FROM orders
WHERE created_at < '2023-01-01';
```

Или вставка из другой таблицы с преобразованием:

```sql
INSERT INTO products (name, price, category_id)
SELECT name, price * 1.1, 1 FROM imported_products WHERE validated = true;
```

---

## 6.1.7. RETURNING

Предложение **RETURNING** возвращает строки, фактически вставленные (или обновлённые при ON CONFLICT DO UPDATE). Синтаксис как у SELECT — список выражений или `*`:

```sql
INSERT INTO users (name, email) VALUES ('Новый', 'new@example.com')
RETURNING id, name, created_at;
```

RETURNING особенно полезен для столбцов с DEFAULT (serial, now() и т.п.) — можно сразу получить сгенерированные значения без отдельного запроса.

Пример — вставка с возвратом сгенерированного id:

```sql
INSERT INTO orders (customer_id, total) VALUES (5, 200.00)
RETURNING id;
```

---

## 6.1.8. Ограничения и ошибки вставки

При вставке проверяются ограничения таблицы: NOT NULL, UNIQUE, PRIMARY KEY, CHECK, FOREIGN KEY. Нарушение ограничения приводит к ошибке и откату команды (в пределах текущей транзакции).

Для обработки конфликтов по уникальности используется ON CONFLICT (см. [§6.5](chapter-06-05.md)).

---

## 6.1.9. Типичные ошибки

- **Несоответствие числа значений и столбцов** — ошибка; проверяйте список столбцов и VALUES.
- **Нарушение NOT NULL** — столбец с NOT NULL без DEFAULT должен получить явное значение.
- **Нарушение UNIQUE/PRIMARY KEY** — дублирующееся значение; при необходимости — ON CONFLICT.
- **Нарушение FOREIGN KEY** — вставляемое значение не найдено в ссылаемой таблице.
- **Опущен список столбцов при изменённой структуре** — порядок столбцов мог измениться; явный список надёжнее.

---

## Ключевое

- **INSERT INTO таблица (столбцы) VALUES (значения)** — вставка одной или нескольких строк.
- Неуказанные столбцы получают DEFAULT или NULL.
- **DEFAULT** в VALUES — подстановка значения по умолчанию для столбца.
- **DEFAULT VALUES** — вставка одной строки со всеми значениями по умолчанию.
- **INSERT ... SELECT** — вставка строк из результата запроса.
- **RETURNING** — возврат вставленных строк (в том числе сгенерированных значений).

В [§6.2](chapter-06-02.md) рассмотрим UPDATE — изменение существующих строк.
