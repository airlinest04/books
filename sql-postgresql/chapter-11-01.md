# §11.1 Транзакция

В [§10.4](chapter-10-04.md) мы завершили главу об операциях над множествами. **Транзакция** — логическая единица работы: группа SQL-команд выполняется атомарно — либо все изменения применяются, либо ни одно. В этом разделе разберём BEGIN, COMMIT, ROLLBACK, режим autocommit и неявное завершение в psql. Целостность чтения при параллельных сессиях — в [§11.2](chapter-11-02.md). См. [документацию BEGIN](https://www.postgresql.org/docs/current/sql-begin.html), [COMMIT](https://www.postgresql.org/docs/current/sql-commit.html), [ROLLBACK](https://www.postgresql.org/docs/current/sql-rollback.html) и [туториал по транзакциям](https://www.postgresql.org/docs/current/tutorial-transactions.html).

---

## 11.1.1. Что такое транзакция

Транзакция объединяет несколько шагов в одну операцию «всё или ничего». Промежуточные состояния не видны другим сессиям; при сбое или явном откате ни один шаг не сохраняется.

Пример: перевод суммы между счетами — списание с одного и зачисление на другой. Оба UPDATE должны выполниться вместе: иначе либо деньги исчезнут, либо появятся «из воздуха».

---

## 11.1.2. BEGIN, COMMIT, ROLLBACK

- **BEGIN** — начало транзакции. Все последующие команды выполняются в одной транзакции.
- **COMMIT** — подтверждение: изменения становятся постоянными и видны другим сессиям.
- **ROLLBACK** — отмена: все изменения после BEGIN отбрасываются, база возвращается к состоянию до BEGIN.

```sql
BEGIN;

UPDATE accounts SET balance = balance - 100 WHERE id = 1;
UPDATE accounts SET balance = balance + 100 WHERE id = 2;

-- Проверка результата
SELECT id, balance FROM accounts WHERE id IN (1, 2);

COMMIT;   -- применить
-- или ROLLBACK;  -- отменить
```

После COMMIT откат невозможен. После ROLLBACK транзакция завершена; следующая команда начнёт новую транзакцию (в режиме autocommit — неявно).

---

## 11.1.3. Режим autocommit

По умолчанию PostgreSQL работает в **autocommit**: каждая команда выполняется в отдельной транзакции и при успехе сразу подтверждается. Неявный COMMIT после каждой команды.

При явном **BEGIN** autocommit отключается для сессии до COMMIT или ROLLBACK. Затем autocommit снова действует.

В psql можно проверить состояние: `\echo :TRANSNO` — номер транзакции (увеличивается при каждом BEGIN). Вне транзакции показывает 0.

---

## 11.1.4. Неявное завершение в psql

Если сессия завершается (закрытие psql, обрыв соединения) **до COMMIT**, текущая транзакция **откатывается**. Незакоммиченные изменения теряются.

При нормальном завершении psql (`\q`) клиент отключается; сервер выполняет ROLLBACK для незавершённой транзакции. Это важно помнить: забытый COMMIT при выходе из psql означает потерю всех изменений в текущей транзакции.

---

## 11.1.5. Ошибка внутри транзакции

При ошибке выполнения команды PostgreSQL переводит транзакцию в состояние **aborted**. Последующие команды (кроме ROLLBACK) будут отклоняться с сообщением о прерванной транзакции. Нужно выполнить **ROLLBACK**, чтобы вернуться к рабочему состоянию.

```text
ERROR:  current transaction is aborted, commands ignored until end of transaction block
```

После ROLLBACK можно начинать новую транзакцию.

---

## 11.1.6. SAVEPOINT (кратко)

Для частичного отката внутри транзакции используются **SAVEPOINT** и **ROLLBACK TO**:

```sql
BEGIN;
UPDATE accounts SET balance = balance - 100 WHERE id = 1;
SAVEPOINT sp1;
UPDATE accounts SET balance = balance + 100 WHERE id = 2;
-- Ошибка: нужен другой счёт
ROLLBACK TO sp1;
UPDATE accounts SET balance = balance + 100 WHERE id = 3;
COMMIT;
```

Откат к SAVEPOINT отменяет только изменения после него; транзакция продолжается. Подробнее — в документации [SAVEPOINT](https://www.postgresql.org/docs/current/sql-savepoint.html).

---

## Ключевое

- **Транзакция** — атомарная единица работы: все изменения применяются (COMMIT) или отменяются (ROLLBACK).
- **BEGIN** — начало, **COMMIT** — подтверждение, **ROLLBACK** — отмена.
- По умолчанию **autocommit** — каждая команда в своей транзакции.
- При завершении сессии без COMMIT транзакция откатывается.
- При ошибке транзакция переходит в aborted; нужен ROLLBACK.

В [§11.2](chapter-11-02.md) рассмотрим изоляцию — как параллельные транзакции видят изменения друг друга.
