# §9.2 Подзапросы в SELECT и WHERE

В [§9.1](chapter-09-01.md) мы рассмотрели подзапросы в FROM. Подзапросы в **SELECT** и **WHERE** используются иначе: в SELECT — как скалярное выражение (одно значение на строку), в WHERE — в IN, EXISTS, сравнениях. В этом разделе разберём скалярный подзапрос, подзапросы в WHERE (IN, EXISTS, сравнение), коррелированные подзапросы и ловушку NOT IN при NULL. Вложенные агрегаты — в [§9.3](chapter-09-03.md). См. [документацию Subquery Expressions](https://www.postgresql.org/docs/current/functions-subquery.html).

---

## 9.2.1. Скалярный подзапрос в SELECT

**Скалярный подзапрос** возвращает одну строку и один столбец. Его результат можно использовать в SELECT как обычное выражение — для каждой строки внешнего запроса подзапрос вычисляется отдельно (если он коррелированный) или один раз (если нет).

Пример — заказы с именем клиента (из [§4.4](chapter-04-04.md)):

```sql
SELECT o.id, o.total,
  (SELECT c.name FROM customers c WHERE c.id = o.customer_id) AS customer_name
FROM orders o;
```

Подзапрос ссылается на `o.customer_id` — это **коррелированный** подзапрос: он выполняется для каждой строки `orders`. Результат — одно значение (имя клиента) или NULL, если клиент не найден.

Подзапрос должен возвращать не более одной строки. Иначе PostgreSQL выдаёт ошибку «more than one row returned by a subquery used as an expression».

---

## 9.2.2. IN с подзапросом

Подзапрос в **IN** должен возвращать один столбец. Проверяется, входит ли значение левой части в множество значений подзапроса. По [документации](https://www.postgresql.org/docs/current/functions-subquery.html):

```sql
expression IN (подзапрос)
```

Примеры (часть уже была в [§3.3](chapter-03-03.md), [§4.4](chapter-04-04.md)):

```sql
-- Клиенты с хотя бы одним заказом
SELECT id, name FROM customers
WHERE id IN (SELECT customer_id FROM orders);

-- Товары, которые есть в заказах
SELECT * FROM products
WHERE id IN (SELECT product_id FROM order_items);
```

Подзапрос обычно **некоррелированный** — не ссылается на внешний запрос; выполняется один раз.

---

## 9.2.3. EXISTS и NOT EXISTS

**EXISTS (подзапрос)** возвращает TRUE, если подзапрос возвращает хотя бы одну строку; иначе FALSE. Содержимое строк не важно, поэтому часто пишут `EXISTS (SELECT 1 FROM ... WHERE ...)`.

**NOT EXISTS** — отрицание: TRUE, если подзапрос не возвращает ни одной строки.

Пример — клиенты с заказами (коррелированный подзапрос):

```sql
SELECT id, name FROM customers c
WHERE EXISTS (SELECT 1 FROM orders o WHERE o.customer_id = c.id);
```

Клиенты без заказов:

```sql
SELECT id, name FROM customers c
WHERE NOT EXISTS (SELECT 1 FROM orders o WHERE o.customer_id = c.id);
```

EXISTS может завершиться при первой найденной строке; для задачи «есть ли совпадение» часто эффективнее IN при больших объёмах. NOT EXISTS не имеет проблем с NULL в отличие от NOT IN.

---

## 9.2.4. Сравнение с подзапросом

Подзапрос, возвращающий одну строку и один столбец, можно использовать в сравнении (=, <, >, <=, >=, <>):

```sql
-- Города с максимальной минимальной температурой (из туториала PostgreSQL)
SELECT city FROM weather
WHERE temp_lo = (SELECT max(temp_lo) FROM weather);
```

Подзапрос должен возвращать ровно одну строку. Ноль строк даёт NULL в сравнении; несколько строк — ошибку.

---

## 9.2.5. ANY и ALL

**expression operator ANY (подзапрос)** — TRUE, если сравнение с хотя бы одной строкой подзапроса даёт TRUE. `IN` эквивалентен `= ANY`.

**expression operator ALL (подзапрос)** — TRUE, если сравнение со всеми строками подзапроса даёт TRUE. `NOT IN` эквивалентен `<> ALL` при отсутствии NULL.

Примеры:

```sql
-- Товары дороже любого товара категории 1
SELECT * FROM products
WHERE price > ALL (SELECT price FROM products WHERE category_id = 1);

-- Товары дороже хотя бы одного товара категории 1
SELECT * FROM products
WHERE price > ANY (SELECT price FROM products WHERE category_id = 1);
```

При пустом подзапросе: `> ALL (пусто)` даёт TRUE; `> ANY (пусто)` — FALSE.

---

## 9.2.6. NOT IN и NULL

При **NOT IN** с подзапросом: если подзапрос возвращает NULL в одной из строк, результат всего выражения может быть NULL (не TRUE и не FALSE), и строка отфильтровывается. Подробнее — в [§3.3](chapter-03-03.md).

Пример: `x NOT IN (1, 2, NULL)` при `x = 3` — сравнение с NULL даёт NULL; итог NULL. Строки с таким результатом в WHERE отбрасываются.

**Рекомендация:** при возможных NULL в результате подзапроса использовать **NOT EXISTS** вместо NOT IN:

```sql
-- Безопаснее при возможных NULL:
SELECT * FROM customers c
WHERE NOT EXISTS (SELECT 1 FROM orders o WHERE o.customer_id = c.id);

-- Рискованно, если customer_id может быть NULL:
-- WHERE id NOT IN (SELECT customer_id FROM orders)
```

---

## 9.2.7. Коррелированные и некоррелированные подзапросы

**Некоррелированный** подзапрос не ссылается на столбцы внешнего запроса. Выполняется один раз, результат кэшируется.

**Коррелированный** подзапрос ссылается на столбец внешнего запроса (например, `o.customer_id`). Выполняется для каждой строки внешнего запроса. Может быть медленным на больших таблицах; при необходимости проверяйте план через EXPLAIN.

---

## Ключевое

- **Скалярный подзапрос в SELECT** — возвращает одно значение на строку; может быть коррелированным; должен возвращать не более одной строки.
- **IN (подзапрос)** — проверка вхождения в множество; подзапрос возвращает один столбец.
- **EXISTS / NOT EXISTS** — проверка наличия строк; NOT EXISTS не имеет проблем с NULL в отличие от NOT IN.
- **Сравнение с подзапросом** — подзапрос должен возвращать одну строку и один столбец.
- **ANY, ALL** — сравнение с каждой строкой подзапроса; IN = ANY, NOT IN = ALL при отсутствии NULL.
- При возможных NULL в подзапросе предпочтительнее NOT EXISTS вместо NOT IN.

В [§9.3](chapter-09-03.md) вернёмся к вложенным агрегатам — агрегат от результата агрегации через подзапрос.
