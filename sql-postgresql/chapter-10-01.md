# §10.1 UNION и UNION ALL

В [§9.3](chapter-09-03.md) мы завершили главу о подзапросах и вложенных агрегатах. **UNION** объединяет результаты двух или более SELECT в один набор строк. Это операции над множествами — в отличие от JOIN, строки не соединяются по условию, а складываются одна под другой. В этом разделе разберём синтаксис UNION и UNION ALL, требования к совместимости столбцов и различие по дубликатам. INTERSECT и EXCEPT — в [§10.2](chapter-10-02.md) и [§10.3](chapter-10-03.md). См. [документацию SELECT](https://www.postgresql.org/docs/current/sql-select.html).

---

## 10.1.1. Синтаксис

```sql
запрос1
UNION [ALL]
запрос2
[UNION [ALL] запрос3 ...]
[ORDER BY ...]
[LIMIT ...];
```

Каждый из `запрос1` и `запрос2` — полноценный SELECT (с FROM, WHERE и т.д.). Результат — строки из первого запроса, затем из второго (и далее). Имена столбцов берутся из первого запроса.

Пример: объединение списка имён клиентов и имён сотрудников:

```sql
SELECT name FROM customers
UNION
SELECT name FROM employees
ORDER BY name;
```

---

## 10.1.2. UNION и UNION ALL: дубликаты

- **UNION** (по умолчанию эквивалентно UNION DISTINCT) — дубликаты **устраняются**. Результат — множество строк.
- **UNION ALL** — дубликаты **сохраняются**. Все строки из обоих запросов остаются в результате.

Если дубликатов нет или их сохранение не важно, **UNION ALL** обычно быстрее: PostgreSQL не выполняет проверку на уникальность.

Пример: клиенты и сотрудники с именем «Иван» — при UNION только одна строка, при UNION ALL — столько, сколько найдено:

```sql
SELECT name FROM customers WHERE name = 'Иван'
UNION
SELECT name FROM employees WHERE name = 'Иван';
-- Одна строка «Иван», даже если есть и в customers, и в employees

SELECT name FROM customers WHERE name = 'Иван'
UNION ALL
SELECT name FROM employees WHERE name = 'Иван';
-- Две строки «Иван», если имя есть в обеих таблицах
```

---

## 10.1.3. Совместимость по числу и типам столбцов

Оба запроса должны возвращать **одинаковое число столбцов**, и типы соответствующих столбцов должны быть **совместимыми** (PostgreSQL приведёт их, если возможно).

Ошибка при разном числе столбцов:

```text
ERROR:  each UNION query must have the same number of columns
```

Если типы несовместимы (например, text и integer без приведения), будет ошибка приведения типа.

Выравнивание по типам часто делают через приведение и константы:

```sql
SELECT id::text, name, 'customer' AS source FROM customers
UNION ALL
SELECT id::text, name, 'employee' AS source FROM employees;
```

Здесь `id` в одной таблице мог быть integer — приведение `id::text` выравнивает типы. Третий столбец-константа добавлен для пометки источника.

---

## 10.1.4. ORDER BY и LIMIT

ORDER BY и LIMIT относятся к **общему** результату объединения, а не к отдельному запросу. Их пишут в конце:

```sql
SELECT name FROM customers
UNION ALL
SELECT name FROM employees
ORDER BY name
LIMIT 10;
```

Чтобы отсортировать или ограничить только один из запросов, используйте подзапрос:

```sql
(SELECT name FROM customers ORDER BY name LIMIT 5)
UNION ALL
SELECT name FROM employees;
```

Скобки обязательны — иначе ORDER BY/LIMIT применятся ко всему UNION. Обратите внимание: порядок внутри подзапроса может не сохраниться в финальном результате без внешнего ORDER BY.

---

## 10.1.5. Пример: объединение отчётов

Типичный сценарий — сводка из разных таблиц с общей структурой. Например, все транзакции (покупки и возвраты) в одном списке:

```sql
SELECT order_id, amount, 'sale' AS type FROM sales
UNION ALL
SELECT order_id, -amount, 'refund' AS type FROM refunds
ORDER BY order_id, type;
```

UNION ALL уместен, если дубликаты по смыслу невозможны (одна и та же строка не может быть и продажей, и возвратом одновременно).

---

## Ключевое

- **UNION** объединяет результаты запросов в один набор; строки идут одна под другой.
- **UNION** устраняет дубликаты; **UNION ALL** сохраняет все строки (часто быстрее).
- Число и типы столбцов в запросах должны быть совместимы.
- ORDER BY и LIMIT в конце относятся ко всему результату; для одного запроса — подзапрос в скобках.

В [§10.2](chapter-10-02.md) рассмотрим INTERSECT — пересечение множеств строк.
