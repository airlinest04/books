# §6.3 DELETE

В [§6.2](chapter-06-02.md) мы рассмотрели UPDATE. **DELETE** удаляет строки из таблицы. В этом разделе разберём синтаксис DELETE, условие WHERE, удаление по данным из других таблиц (USING и подзапрос), RETURNING и связь с внешними ключами. Опасность DELETE без WHERE рассматривается в [§6.4](chapter-06-04.md). См. [документацию DELETE](https://www.postgresql.org/docs/current/sql-delete.html).

---

## 6.3.1. Базовый синтаксис

По [документации](https://www.postgresql.org/docs/current/sql-delete.html):

```sql
DELETE FROM имя_таблицы
[WHERE условие];
```

Удаляются только строки, для которых условие WHERE даёт TRUE. Без WHERE удаляются **все** строки таблицы.

Примеры:

```sql
DELETE FROM orders WHERE id = 100;
DELETE FROM logs WHERE created_at < '2023-01-01';
DELETE FROM users WHERE status = 'inactive';
```

---

## 6.3.2. WHERE обязателен по смыслу

Без WHERE команда DELETE удаляет все строки таблицы. Обычно это ошибка. Перед выполнением всегда проверяйте условие; для критичных операций — в транзакции с проверкой и при необходимости ROLLBACK (см. [§6.4](chapter-06-04.md)).

---

## 6.3.3. DELETE с подзапросом

Условие WHERE может содержать подзапрос. Пример — удаление заказов клиента по его email:

```sql
DELETE FROM orders
WHERE customer_id IN (SELECT id FROM customers WHERE email = 'old@example.com');
```

Или удаление дубликатов (оставляя строку с минимальным id):

```sql
DELETE FROM users a
WHERE a.id > (SELECT min(b.id) FROM users b WHERE b.email = a.email);
```

---

## 6.3.4. DELETE ... USING

Предложение **USING** позволяет подключать другие таблицы и использовать их столбцы в WHERE. Строки целевой таблицы, участвующие в соединении и удовлетворяющие условию, удаляются.

Пример — удаление фильмов заданного производителя:

```sql
DELETE FROM films
USING producers
WHERE films.producer_id = producers.id AND producers.name = 'Студия X';
```

Эквивалентная форма с подзапросом:

```sql
DELETE FROM films
WHERE producer_id IN (SELECT id FROM producers WHERE name = 'Студия X');
```

USING полезен, когда условие удобнее выразить через соединение.

---

## 6.3.5. RETURNING

Предложение **RETURNING** возвращает удалённые строки:

```sql
DELETE FROM orders WHERE id = 5
RETURNING id, customer_id, total;
```

Или все столбцы:

```sql
DELETE FROM tasks WHERE status = 'DONE'
RETURNING *;
```

RETURNING полезен для логирования, архивирования или проверки результата без отдельного SELECT перед удалением.

---

## 6.3.6. Внешние ключи и ON DELETE

При удалении строки, на которую ссылаются другие таблицы через FOREIGN KEY, поведение задаётся **ON DELETE** (см. [§2.3](chapter-02-03.md)):

- **RESTRICT** (по умолчанию) — удаление запрещено, если есть ссылающиеся строки; возникает ошибка.
- **CASCADE** — ссылающиеся строки удаляются вместе с родительской.
- **SET NULL** — столбец внешнего ключа в ссылающихся строках устанавливается в NULL.
- **SET DEFAULT** — устанавливается значение по умолчанию.

Порядок удаления при каскаде: сначала дочерние строки, затем родительские. При нарушении ограничений команда завершается с ошибкой.

---

## 6.3.7. Число удалённых строк

PostgreSQL возвращает сообщение вида `DELETE n`, где `n` — количество удалённых строк. В приложениях это значение часто доступно через API. При `n = 0` никакие строки не были удалены (ошибкой это не считается).

---

## 6.3.8. TRUNCATE вместо DELETE для всей таблицы

Если нужно удалить **все** строки таблицы, **TRUNCATE** обычно быстрее, чем `DELETE FROM таблица`: он не проходит по строкам и не пишет WAL для каждой из них. TRUNCATE сбрасывает счётчики последовательностей и не вызывает триггеры ON DELETE.

```sql
TRUNCATE TABLE logs;
```

TRUNCATE требует привилегию TRUNCATE. При наличии внешних ключей может потребоваться CASCADE. Подробнее — в документации по TRUNCATE.

---

## 6.3.9. Типичные ошибки

- **DELETE без WHERE** — удаляются все строки; почти всегда нежелательно.
- **Неточное условие WHERE** — удаляются не те строки; перед массовым DELETE выполняйте `SELECT * FROM таблица WHERE ...` и проверяйте результат.
- **Игнорирование внешних ключей** — при RESTRICT удаление может завершиться с ошибкой; учитывайте ON DELETE и порядок удаления.
- **USING с дубликатами** — при нескольких строках соединения для одной целевой строки результат может быть неочевидным; обеспечивайте уникальность соединения.

---

## Ключевое

- **DELETE FROM таблица [WHERE условие]** — удаление строк; без WHERE удаляются все строки.
- Условие WHERE обычно обязательно; перед массовым DELETE проверяйте выборку через SELECT.
- **DELETE ... USING** — удаление с использованием данных из других таблиц.
- **RETURNING** — возврат удалённых строк.
- Внешние ключи и ON DELETE определяют поведение при удалении ссылаемых строк.
- Для полной очистки таблицы часто удобнее **TRUNCATE**.

В [§6.4](chapter-06-04.md) рассмотрим опасность UPDATE и DELETE без WHERE — как избежать случайной потери данных.
