# §4.5 Соединение таблицы с собой (self-join)

В [§4.4](chapter-04-04.md) мы сравнили JOIN и подзапросы. **Self-join** (соединение таблицы с собой) — это соединение, в котором одна и та же таблица участвует дважды под разными псевдонимами. Используется для иерархических структур (сотрудник — руководитель), пар строк, сравнений внутри таблицы. В этом разделе разберём, когда нужен self-join, обязательность псевдонимов и типичные примеры. Сортировка и ограничение результатов — в гл. 5. См. [документацию SELECT — FROM](https://www.postgresql.org/docs/current/sql-select.html#SQL-FROM).

---

## 4.5.1. Зачем соединять таблицу с собой

Связи бывают не только между разными таблицами, но и **внутри одной**: строка ссылается на другую строку той же таблицы. Типичные случаи:

- **Иерархия:** сотрудники и руководители — у каждого сотрудника `manager_id`, указывающий на `id` другого сотрудника.
- **Пары:** найти дубликаты, пары элементов с общим признаком.
- **Сравнение:** строки, где один столбец больше другого в той же таблице.

Для таких задач таблицу нужно «разыграть» как две роли и соединить их по условию — то есть выполнить self-join.

---

## 4.5.2. Псевдонимы обязательны

При self-join одна таблица фигурирует дважды в FROM. Без псевдонимов имена столбцов неразличимы. Псевдонимы задают две «копии» таблицы с разными ролями:

```sql
FROM employees emp
JOIN employees mgr ON emp.manager_id = mgr.id
```

Здесь `emp` — сотрудник, `mgr` — его руководитель. Условие связывает `emp.manager_id` с `mgr.id`. Без псевдонимов выражение `employees.manager_id` было бы неоднозначным.

---

## 4.5.3. Иерархия: сотрудники и руководители

Таблица сотрудников с ссылкой на руководителя:

```sql
-- Структура: id, name, manager_id
-- manager_id ссылается на id другого сотрудника
```

Список сотрудников с именами руководителей:

```sql
SELECT emp.id, emp.name AS employee, mgr.name AS manager
FROM employees emp
LEFT JOIN employees mgr ON emp.manager_id = mgr.id;
```

LEFT JOIN нужен, чтобы включить сотрудников без руководителя (директор, у которого `manager_id` = NULL). INNER JOIN оставит только тех, у кого руководитель задан.

Руководители без подчинённых (листья иерархии):

```sql
SELECT mgr.id, mgr.name
FROM employees mgr
LEFT JOIN employees emp ON emp.manager_id = mgr.id
WHERE emp.id IS NULL;
```

---

## 4.5.4. Сравнение строк внутри таблицы

Self-join удобен, когда нужно сравнить строки одной таблицы между собой. Пример: пары товаров с одинаковой ценой (каждый товар — один раз в паре):

```sql
SELECT a.name AS product_a, b.name AS product_b, a.price
FROM products a
JOIN products b ON a.price = b.price AND a.id < b.id;
```

Условие `a.id < b.id` исключает дубликаты (пару (1,2) и (2,1)) и пары строки с собой (a.id = b.id).

---

## 4.5.5. Поиск дубликатов

Найти строки с повторяющимся значением столбца (например, одинаковый email):

```sql
SELECT a.id, a.name, a.email
FROM users a
JOIN users b ON a.email = b.email AND a.id > b.id;
```

Для каждой пары дубликатов остаётся одна строка (с большим `id`). Альтернатива — GROUP BY и HAVING (см. гл. 7).

---

## 4.5.6. Цепочка: несколько уровней

Для иерархии в несколько уровней self-join повторяют. Пример: сотрудник, его руководитель и руководитель руководителя:

```sql
SELECT emp.name AS employee,
       mgr1.name AS manager,
       mgr2.name AS manager_of_manager
FROM employees emp
LEFT JOIN employees mgr1 ON emp.manager_id = mgr1.id
LEFT JOIN employees mgr2 ON mgr1.manager_id = mgr2.id;
```

Для произвольной глубины удобнее рекурсивные запросы (WITH RECURSIVE), см. документацию.

---

## 4.5.7. Типичные ошибки

- **Забыли псевдонимы** — при self-join без алиасов обращение к столбцам становится неоднозначным.
- **Дубликаты пар** — при сравнении строк условие `a.id < b.id` (или `>`) убирает обратные пары и пару с собой.
- **Использовали INNER вместо LEFT** — при иерархии верхний уровень (без родителя) теряется; для полного дерева часто нужен LEFT JOIN.

---

## Ключевое

- **Self-join** — соединение таблицы с собой; одна таблица участвует дважды под разными псевдонимами.
- Псевдонимы обязательны, чтобы различать «роли» (сотрудник и руководитель, первая и вторая строка).
- Применяется к иерархиям (руководитель — подчинённый), парам строк, сравнению значений внутри таблицы.
- Для исключения дубликатов пар используют условие вида `a.id < b.id`.
- Для иерархии с вершинами без родителя — LEFT JOIN.

В [§5.1](chapter-05-01.md) рассмотрим ORDER BY — сортировку результата запроса.
