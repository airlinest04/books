# §8.3 Вложенные агрегаты

В [§8.2](chapter-08-02.md) мы рассмотрели фильтрацию по агрегату. **Вложенные агрегаты** — ситуация, когда один агрегат используется как аргумент другого (например, `max(count(*))`). В одном уровне запроса это запрещено. В этом разделе разберём ошибку, где агрегаты допустимы (SELECT с GROUP BY, HAVING), где нет, и как получить «агрегат от агрегата» через подзапрос. Подзапросы в FROM и вложенная агрегация подробнее — в гл. 9. См. [документацию SELECT](https://www.postgresql.org/docs/current/sql-select.html).

---

## 8.3.1. Ошибка вложенных агрегатов

PostgreSQL не допускает **агрегат в качестве аргумента другого агрегата** на одном уровне запроса. Типичная ошибка:

```sql
SELECT max(count(*)) FROM orders GROUP BY customer_id;
```

Сообщение:

```text
ERROR:  aggregate function calls cannot be nested
LINE 1: SELECT max(count(*)) FROM orders GROUP BY customer_id;
```

Аналогично: `avg(sum(amount))`, `sum(count(*))` и любые комбинации, где аргумент внешнего агрегата — результат внутреннего на том же уровне.

---

## 8.3.2. Где агрегаты допустимы

Агрегатная функция разрешена в:

- **SELECT** — при наличии GROUP BY или когда вся таблица считается одной группой;
- **HAVING** — после группировки, для фильтрации групп.

Аргументом агрегата могут быть столбцы, выражения, константы — но не другой агрегат на том же уровне.

---

## 8.3.3. Где вложенные агрегаты запрещены

Нельзя писать:

- `sum(count(*))`, `max(avg(price))` и т.п. в SELECT;
- `avg(sum(x))` в HAVING;
- любой агрегат, чей аргумент — агрегат того же уровня.

Смысл ограничения: внутренний агрегат вычисляется по группам; внешнему нужен уже готовый набор значений. На одном уровне запроса такого набора нет — он появляется только как результат подзапроса.

---

## 8.3.4. Решение: подзапрос

Чтобы получить «агрегат от агрегата», вычисления разбивают на два уровня: внутренний запрос считает первый агрегат, внешний — второй.

Пример: максимальное количество заказов у одного клиента:

```sql
-- Ошибочно:
SELECT max(count(*)) FROM orders GROUP BY customer_id;  -- ошибка

-- Правильно:
SELECT max(order_count) AS max_orders
FROM (
  SELECT customer_id, count(*) AS order_count
  FROM orders
  GROUP BY customer_id
) sub;
```

Внутренний запрос возвращает по одной строке на клиента с `order_count`; внешний берёт `max(order_count)` по этим строкам.

---

## 8.3.5. Дополнительные примеры

Среднее от сумм по группам:

```sql
SELECT avg(category_total) AS avg_category_revenue
FROM (
  SELECT category_id, sum(price * quantity) AS category_total
  FROM order_items oi
  JOIN products p ON p.id = oi.product_id
  GROUP BY category_id
) sub;
```

Минимальное и максимальное количество заказов на клиента:

```sql
SELECT min(cnt) AS min_orders, max(cnt) AS max_orders
FROM (
  SELECT customer_id, count(*) AS cnt
  FROM orders
  GROUP BY customer_id
) sub;
```

---

## Ключевое

- Агрегат не может быть аргументом другого агрегата на одном уровне запроса (ошибка «aggregate function calls cannot be nested»).
- Агрегаты допустимы в SELECT (с GROUP BY) и в HAVING.
- Для «агрегата от агрегата» используется **подзапрос**: внутренний считает первый агрегат по группам, внешний — второй по результату.
- Аналогично можно использовать CTE (WITH) — см. гл. 13.

В [§9.1](chapter-09-01.md) рассмотрим подзапросы в FROM подробнее — как источник данных для внешнего запроса.
