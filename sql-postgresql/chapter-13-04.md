# §13.4 CTE и изменение данных

В [§13.3](chapter-13-03.md) мы рассмотрели рекурсивные CTE. В PostgreSQL в предложении **WITH** можно использовать не только SELECT, но и **INSERT**, **UPDATE**, **DELETE**, **MERGE**. Это даёт возможность выполнять несколько изменений в одном запросе и передавать результат одного в другой через RETURNING. См. [документацию WITH Queries](https://www.postgresql.org/docs/current/queries-with.html#QUERIES-WITH-DML).

---

## 13.4.1. Идея

Изменяющая команда в WITH возвращает строки через **RETURNING**. Эти строки образуют временную таблицу, на которую может ссылаться основной запрос или другие CTE. Без RETURNING CTE не возвращает данные и на него нельзя ссылаться — команда всё равно выполнится.

WITH привязывается к **главной** команде (SELECT, INSERT, UPDATE, DELETE, MERGE), а не к подзапросу внутри неё.

---

## 13.4.2. Перенос строк между таблицами

Типичный пример: удалить строки из одной таблицы и вставить их в другую (архив, лог):

```sql
WITH moved_rows AS (
  DELETE FROM products
  WHERE created_at >= '2024-01-01' AND created_at < '2024-02-01'
  RETURNING *
)
INSERT INTO products_archive
SELECT * FROM moved_rows;
```

DELETE удаляет указанные строки; RETURNING возвращает их содержимое. INSERT вставляет эти строки в `products_archive`. Операция атомарна — в одной транзакции.

---

## 13.4.3. UPDATE с использованием результата

Результат UPDATE через RETURNING можно использовать в основном запросе:

```sql
WITH updated AS (
  UPDATE orders
  SET status = 'shipped'
  WHERE status = 'pending' AND ship_date <= current_date
  RETURNING id, customer_id, total
)
SELECT customer_id, sum(total) AS shipped_total
FROM updated
GROUP BY customer_id;
```

Сначала обновляются заказы; затем по обновлённым строкам считается сумма по клиентам. RETURNING нужен, чтобы основной запрос получил к ним доступ.

---

## 13.4.4. Порядок выполнения и снимок

По [документации](https://www.postgresql.org/docs/current/queries-with.html) подзапросы в WITH выполняются **параллельно** друг с другом и с основным запросом, в одном снимке данных. Это означает:

- Одна команда в WITH **не видит** изменения другой в той же инструкции — все работают с одним и тем же снимком.
- Связь между командами — только через RETURNING: выход одной CTE передаётся в следующую или в основной запрос.

---

## 13.4.5. Ограничения

- Одну и ту же строку **нельзя** изменять дважды в одной инструкции (разными CTE или CTE и основной командой). Результат непредсказуем.
- Изменяющие команды в WITH выполняются **ровно один раз и до конца**, даже если основной запрос читает не все строки. Для SELECT в WITH такое поведение может отличаться.
- Рекурсивная самореференция в изменяющих командах **не поддерживается**. Можно использовать рекурсивный SELECT в WITH и по его результату делать DELETE или UPDATE в основной команде.

---

## Ключевое

- В WITH можно указывать **INSERT**, **UPDATE**, **DELETE**, **MERGE**; для доступа к результату нужен **RETURNING**.
- Результат RETURNING используется как временная таблица для основного запроса или следующих CTE.
- Типичное применение — перенос строк (DELETE ... RETURNING, затем INSERT) в одной транзакции.
- Все подзапросы в WITH выполняются в одном снимке; одна команда не видит изменения другой.
- Нельзя изменять одну и ту же строку дважды в одной инструкции.
