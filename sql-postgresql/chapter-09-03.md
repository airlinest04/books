# §9.3 Вложенные агрегаты

В [§9.2](chapter-09-02.md) мы рассмотрели подзапросы в SELECT и WHERE. **Вложенная агрегация** — когда нужен агрегат от результата другого агрегата (например, максимум из количества заказов по клиентам). В стандартном SQL это запрещено на одном уровне; решение — подзапрос в FROM. В этом разделе закрепим подход из [§8.3](chapter-08-03.md), добавим паттерн «доля группы в общем итоге» и использование CTE. Глава 10 — операции над множествами ([§10.1](chapter-10-01.md)). См. [документацию SELECT](https://www.postgresql.org/docs/current/sql-select.html).

---

## 9.3.1. Повторение: правило и решение

В одном уровне запроса **агрегат не может быть аргументом другого агрегата**. Ошибка «aggregate function calls cannot be nested». Решение — подзапрос в FROM: внутренний запрос считает первый агрегат по группам, внешний — второй по результату. Подробнее в [§8.3](chapter-08-03.md).

---

## 9.3.2. Доля группы в общем итоге

Частая задача: доля каждой группы в общем итоге (например, выручка категории в процентах от общей). Здесь два агрегата: `sum` по группе и `sum` по всей таблице. Они не вложены друг в друга, но оба нужны в одном выражении.

Используем **скалярный подзапрос** для общего итога:

```sql
SELECT category_id,
  sum(price * quantity) AS category_revenue,
  round(100.0 * sum(price * quantity) / (SELECT sum(price * quantity) FROM order_items oi2 JOIN products p2 ON p2.id = oi2.product_id), 2) AS pct_of_total
FROM order_items oi
JOIN products p ON p.id = oi.product_id
GROUP BY category_id;
```

Подзапрос `(SELECT sum(...) FROM ...)` возвращает одно значение — общую выручку. В выражении для каждой группы используется своя `sum(price * quantity)` и общий знаменатель. Это не «агрегат от агрегата»: числитель — агрегат внешнего запроса, знаменатель — результат отдельного скалярного подзапроса.

---

## 9.3.3. Группы выше среднего

Отбор групп, у которых агрегат выше среднего по всем группам. В HAVING нужны и агрегат группы, и среднее по группам. Среднее получаем подзапросом:

```sql
SELECT customer_id, count(*) AS order_count
FROM orders
GROUP BY customer_id
HAVING count(*) > (
  SELECT avg(cnt) FROM (SELECT count(*) AS cnt FROM orders GROUP BY customer_id) sub
);
```

Внутренний подзапрос даёт количество заказов по клиентам; внешний скалярный подзапрос считает их среднее. В HAVING это среднее сравнивается с `count(*)` каждой группы.

---

## 9.3.4. CTE вместо вложенного подзапроса

Сложные вложенные агрегаты удобнее записывать через **CTE (WITH)** — см. гл. 13. Пример из [§8.3](chapter-08-03.md) в виде CTE:

```sql
WITH customer_orders AS (
  SELECT customer_id, count(*) AS order_count
  FROM orders
  GROUP BY customer_id
)
SELECT max(order_count) AS max_orders, avg(order_count) AS avg_orders
FROM customer_orders;
```

Логика та же: первый уровень — группировка и агрегат, второй — агрегат по результату. CTE упрощает чтение и позволяет переиспользовать промежуточный результат.

---

## 9.3.5. Три уровня агрегации

При необходимости можно добавить третий уровень — подзапрос от подзапроса:

```sql
SELECT max(avg_orders) AS max_of_avg
FROM (
  SELECT category_id, avg(order_count) AS avg_orders
  FROM (
    SELECT customer_id, category_id, count(*) AS order_count
    FROM orders o
    JOIN order_items oi ON oi.order_id = o.id
    JOIN products p ON p.id = oi.product_id
    GROUP BY customer_id, category_id
  ) per_customer_category
  GROUP BY category_id
) per_category;
```

Внутренний запрос — заказы по парам (клиент, категория); средний уровень — среднее по категориям; внешний — максимум этих средних. Структура та же: каждый уровень агрегирует результат предыдущего через подзапрос в FROM.

---

## Ключевое

- Вложенная агрегация: агрегат от результата агрегата; на одном уровне запрещена; решение — подзапрос в FROM.
- **Доля группы в общем итоге** — скалярный подзапрос для общего итога в знаменателе.
- **Группы выше среднего** — подзапрос, возвращающий среднее по группам, в HAVING.
- **CTE (WITH)** упрощает запись многоуровневой агрегации.
- Любое число уровней — через цепочку подзапросов в FROM.
