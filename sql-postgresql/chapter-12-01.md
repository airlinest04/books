# §12.1 Зачем оконные функции

В [§11.3](chapter-11-03.md) мы завершили главу о транзакциях и уровнях изоляции. **Оконные функции** позволяют выполнять расчёты по наборам строк, связанных с текущей, **без свёртки** результата — в отличие от GROUP BY каждая строка сохраняется, к ней добавляется вычисленное значение. В этом разделе разберём, зачем нужны оконные функции и чем они отличаются от агрегации с GROUP BY. Синтаксис OVER — в [§12.2](chapter-12-02.md). См. [туториал Window Functions](https://www.postgresql.org/docs/current/tutorial-window.html) и [документацию Window Functions](https://www.postgresql.org/docs/current/functions-window.html).

---

## 12.1.1. Ограничение GROUP BY

При **GROUP BY** строки группируются, и в результате остаётся **по одной строке на группу**. Агрегаты (SUM, AVG, COUNT и т.д.) вычисляются по группе. Исходные строки «схлопываются».

Пример: средняя зарплата по отделам:

```sql
SELECT depname, avg(salary) AS avg_salary
FROM employees
GROUP BY depname;
```

Результат — одна строка на отдел. Информация о конкретных сотрудниках теряется. Чтобы увидеть **каждого сотрудника** и при этом **среднюю по его отделу**, одного GROUP BY недостаточно: либо теряем детали (только агрегат), либо нужен обходной путь.

---

## 12.1.2. Задача: расчёт без потери строк

Типичная задача: для каждой строки вычислить значение, зависящее от «соседних» — от всех строк отдела, от предыдущих по времени, от всех строк таблицы. При этом **каждая строка должна остаться** в результате.

Примеры:

- Для каждого сотрудника — его зарплата и средняя зарплата по отделу.
- Для каждого заказа — дата и сумма всех заказов клиента нарастающим итогом.
- Для каждой строки — порядковый номер внутри группы (первый, второй, третий по продажам в регионе).

GROUP BY здесь не подходит: он уменьшает число строк. Нужен другой механизм.

---

## 12.1.3. Оконные функции: идея

**Оконная функция** вычисляет значение по набору строк — **окну** — связанному с текущей строкой. Строки не группируются: каждая остаётся в выводе, к ней добавляется результат функции.

Синтаксис: после вызова функции указывается **OVER** с описанием окна:

```sql
SELECT depname, empno, salary,
  avg(salary) OVER (PARTITION BY depname) AS avg_in_dept
FROM employees;
```

`PARTITION BY depname` — разбить строки на группы по отделу. Для каждой строки `avg(salary)` считается по **её** отделу. Все строки сохраняются; в каждой добавлен столбец со средним по отделу.

---

## 12.1.4. GROUP BY и оконные функции

| GROUP BY | Оконные функции |
|----------|-----------------|
| Уменьшает число строк (по одной на группу) | Все строки сохраняются |
| Агрегат без OVER | Функция с OVER |
| HAVING фильтрует группы | Фильтрация — через подзапрос (WHERE по результату оконной функции) |

Оконные функции выполняются **после** WHERE, GROUP BY, HAVING — на наборе строк, который уже получен. Их нельзя использовать в WHERE или GROUP BY; можно — в SELECT и ORDER BY.

---

## 12.1.5. Краткий пример

По [примеру из документации](https://www.postgresql.org/docs/current/tutorial-window.html): сотрудники с зарплатой и средней по отделу:

```sql
SELECT depname, empno, salary,
  avg(salary) OVER (PARTITION BY depname) AS avg_salary
FROM empsalary;
```

В выводе — все строки таблицы; в `avg_salary` — среднее по отделу текущей строки. Один и тот же отдел — одно и то же среднее во всех его строках.

---

## Ключевое

- **GROUP BY** свёртывает строки; **оконные функции** сохраняют каждую строку и добавляют вычисленное значение.
- Оконная функция вызывается с **OVER** — указывает, по какому набору строк считать.
- Окно можно задавать по всей таблице или по частям (PARTITION BY); порядок — через ORDER BY внутри OVER.
- Оконные функции допустимы в SELECT и ORDER BY; в WHERE и GROUP BY — нет.

В [§12.2](chapter-12-02.md) разберём синтаксис OVER, PARTITION BY и ORDER BY внутри окна.
