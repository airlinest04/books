# §4.2 INNER JOIN

В [§4.1](chapter-04-01.md) мы выяснили, зачем нужны соединения. **INNER JOIN** возвращает только те строки, для которых в обеих таблицах найдено совпадение по условию. В этом разделе разберём синтаксис `JOIN ... ON`, краткую форму `USING`, соединение нескольких таблиц и псевдонимы. Внешние соединения (LEFT, RIGHT, FULL) рассматриваются в [§4.3](chapter-04-03.md). См. [документацию SELECT — FROM](https://www.postgresql.org/docs/current/sql-select.html#SQL-FROM).

---

## 4.2.1. Синтаксис INNER JOIN

Базовый синтаксис соединения по условию:

```sql
SELECT столбцы
FROM таблица1
[INNER] JOIN таблица2 ON условие_соединения
[WHERE фильтр];
```

Ключевое слово **INNER** можно опустить — `JOIN` по умолчанию означает INNER JOIN. Условие в **ON** — логическое выражение, чаще всего равенство ключей. По [документации](https://www.postgresql.org/docs/current/sql-select.html#SQL-FROM):

```sql
FROM таблица1 JOIN таблица2 ON таблица1.ключ = таблица2.ключ
```

Пример — заказы с именами клиентов:

```sql
SELECT o.id, o.total, c.name AS customer_name
FROM orders o
JOIN customers c ON o.customer_id = c.id
WHERE o.total > 100;
```

Строки `orders` и `customers` объединяются там, где `orders.customer_id = customers.id`. Заказы без клиента и клиенты без заказов в результат не попадают.

---

## 4.2.2. Псевдонимы таблиц

При соединении столбцы из разных таблиц могут иметь одинаковые имена (`id`, `name` и т.п.). Чтобы различать их, используют **псевдонимы таблиц** (алиасы):

```sql
FROM orders o
JOIN customers c ON o.customer_id = c.id
```

Далее в запросе `o` и `c` заменяют полные имена: `o.id`, `o.total`, `c.name`. Псевдонимы задаются через `AS` или просто пробелом: `orders AS o` или `orders o`.

---

## 4.2.3. USING: совпадающие имена столбцов

Если столбцы связи называются одинаково в обеих таблицах (например, `customer_id`), можно использовать **USING**:

```sql
SELECT o.id, o.total, c.name
FROM orders o
JOIN customers c USING (customer_id);
```

По [документации](https://www.postgresql.org/docs/current/sql-select.html#SQL-FROM) `USING (customer_id)` эквивалентно `ON o.customer_id = c.customer_id`. При этом в результате столбец `customer_id` выводится один раз, а не два. Для нескольких пар столбцов:

```sql
JOIN order_items oi USING (order_id, product_id);
```

---

## 4.2.4. NATURAL JOIN

**NATURAL JOIN** автоматически соединяет по всем столбцам с одинаковыми именами в обеих таблицах:

```sql
FROM orders o
NATURAL JOIN customers c
```

Эквивалентно `USING` со списком всех общих столбцов. Если общих имён нет, получается `ON TRUE` — декартово произведение. NATURAL JOIN удобен при полностью совпадающей схеме связи, но при изменении таблиц поведение может измениться неожиданно, поэтому его используют редко. Предпочтительнее явный `ON` или `USING`.

---

## 4.2.5. Условие ON и фильтр WHERE

Условие соединения в **ON** определяет, какие строки из двух таблиц считаются парой. Фильтр в **WHERE** отсекает строки уже из соединённого результата.

Семантически разница такая:

- **ON** — часть соединения: «как связывать таблицы».
- **WHERE** — фильтрация результата: «какие строки оставить».

На практике для INNER JOIN часто можно перенести часть условий из ON в WHERE и получить тот же результат. Но для LEFT/RIGHT/FULL JOIN это не так — ON и WHERE ведут себя по-разному (см. [§4.3](chapter-04-03.md)). Рекомендуется: условия связи — в ON, бизнес-фильтры — в WHERE.

Пример:

```sql
SELECT o.id, c.name
FROM orders o
JOIN customers c ON o.customer_id = c.id
WHERE o.total > 100 AND c.name ILIKE '%иванов%';
```

---

## 4.2.6. Несколько INNER JOIN в одном запросе

В одном запросе можно соединить три и более таблиц. Каждое следующее соединение применяется к результату предыдущего:

```sql
SELECT o.id, c.name AS customer, p.name AS product, oi.quantity
FROM orders o
JOIN customers c ON o.customer_id = c.id
JOIN order_items oi ON oi.order_id = o.id
JOIN products p ON oi.product_id = p.id
WHERE o.created_at >= '2024-01-01';
```

Порядок JOIN при INNER JOIN обычно не меняет результат (при неизменных условиях), но может влиять на план выполнения. Планировщик PostgreSQL сам выбирает порядок соединений; при необходимости его можно подсказать через подзапросы.

---

## 4.2.7. Старый синтаксис: FROM с запятой и WHERE

Классический способ — перечислить таблицы через запятую и условие соединения вынести в WHERE:

```sql
SELECT o.id, c.name
FROM orders o, customers c
WHERE o.customer_id = c.id;
```

Для INNER JOIN это эквивалентно `JOIN ... ON`. Но смешивать в WHERE условия соединения и фильтрации сложнее читать и сопровождать. Современный стиль — явный `JOIN ... ON` с разделением логики соединения и фильтрации.

---

## 4.2.8. Сложные условия в ON

В ON может стоять не только простое равенство, но и сложное выражение:

```sql
SELECT *
FROM orders o
JOIN shipments s ON s.order_id = o.id AND s.status = 'delivered';
```

Или сравнение по диапазону:

```sql
SELECT *
FROM events e
JOIN schedules s ON e.start_time >= s.valid_from AND e.start_time < s.valid_to;
```

Любое булево выражение допустимо; важно, чтобы оно однозначно определяло пары строк.

---

## 4.2.9. Дубликаты при «один ко многим»

При соединении таблицы «один» с таблицей «многие» (например, заказ и позиции заказа) одна строка из «одной» таблицы повторяется для каждой связанной строки из «многих»:

```sql
SELECT o.id AS order_id, oi.product_id, oi.quantity
FROM orders o
JOIN order_items oi ON oi.order_id = o.id;
```

Один заказ с тремя позициями даст три строки с одним и тем же `order_id`. Если нужны уникальные заказы — используйте `DISTINCT` или подзапрос (см. [§3.4](chapter-03-04.md), [§4.4](chapter-04-04.md)).

---

## 4.2.10. Строки без соответствия не попадают в результат

INNER JOIN отбрасывает:

- строки левой таблицы, для которых нет подходящей строки в правой;
- строки правой таблицы, для которых нет подходящей строки в левой.

Например, заказы с `customer_id`, которого нет в `customers`, не появятся в результате. Клиенты без заказов тоже не появятся. Если нужны все заказы, включая «битые» ссылки, или все клиенты, включая без заказов, используйте LEFT JOIN (см. [§4.3](chapter-04-03.md)).

---

## 4.2.11. Комбинированный пример

```sql
SELECT
  o.id AS order_id,
  o.created_at,
  c.name AS customer_name,
  p.name AS product_name,
  oi.quantity,
  oi.quantity * p.price AS line_total
FROM orders o
JOIN customers c ON o.customer_id = c.id
JOIN order_items oi ON oi.order_id = o.id
JOIN products p ON oi.product_id = p.id
WHERE o.status = 'completed'
  AND o.created_at BETWEEN '2024-01-01' AND '2024-01-31';
```

(Среда: PostgreSQL 14+, psql)

## 4.2.12. Типичные ошибки

- **Забыто условие ON** — `JOIN table2` без ON при разных именах столбцов приведёт к ошибке; при совпадающих — к неявному NATURAL JOIN.
- **Неправильный ключ** — соединение по неверной паре столбцов даёт неверные или лишние строки; проверяйте схему связей.
- **Дубликаты из-за «многие»** — при связи один-ко-многим одна строка «одной» таблицы дублируется; если нужна уникальность — DISTINCT или группировка.
- **Перепутан ON и WHERE** — для INNER JOIN часто безразлично, но для LEFT JOIN различие критично; приучайтесь к разделению.
- **Смешение запятой и JOIN** — не смешивайте `FROM a, b JOIN c` без скобок; при нескольких таблицах лучше последовательная цепочка JOIN.

---

## Ключевое

- **INNER JOIN** возвращает только строки с совпадением в обеих таблицах; ключевое слово INNER можно опустить.
- Синтаксис: `таблица1 JOIN таблица2 ON условие`; условие — булево выражение, обычно равенство ключей.
- **USING (столбец)** — краткая форма, когда имена столбцов связи совпадают; столбец выводится один раз.
- **NATURAL JOIN** — соединение по всем общим столбцам; использовать с осторожностью.
- Условие связи — в ON, фильтры — в WHERE.
- При связи «один ко многим» строки «одной» таблицы повторяются; для уникальности — DISTINCT или группировка.
- Строки без соответствия в INNER JOIN не попадают в результат.

В [§4.3](chapter-04-03.md) рассмотрим LEFT JOIN, RIGHT JOIN и FULL JOIN — как включать строки без совпадений.
