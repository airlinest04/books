# §2.1 Таблицы и столбцы

В [§1.4](chapter-01-04.md) мы выполнили первый запрос к уже существующей таблице. Чтобы работать со своими данными, нужно **создавать таблицы** — описывать их структуру: имя, столбцы и типы данных. В этом разделе мы разберём оператор `CREATE TABLE`, правила именования таблиц и столбцов, работу кавычек и регистра, а также создание таблицы в указанной схеме. Типы данных подробно рассмотрены в [§2.2](chapter-02-02.md), ограничения (NOT NULL, PRIMARY KEY и др.) — в [§2.3](chapter-02-03.md).

---

## 2.1.1. Что такое таблица

**Таблица** — основной объект хранения данных в реляционной СУБД. Таблица состоит из **столбцов** (columns) и **строк** (rows). Каждый столбец имеет имя и тип данных; каждая строка содержит одно значение для каждого столбца. Структура таблицы (имена и типы столбцов) задаётся при создании и может быть изменена командой `ALTER TABLE` (см. [§2.4](chapter-02-04.md)). См. [Глоссарий](glossary.md).

В рамках одной схемы имя таблицы должно быть уникальным среди таблиц, представлений, последовательностей и других объектов, использующих общее пространство имён.

---

## 2.1.2. Базовая форма CREATE TABLE

Минимальный синтаксис создания таблицы:

```sql
CREATE TABLE имя_таблицы (
  имя_столбца1 тип_данных,
  имя_столбца2 тип_данных,
  ...
);
```

Таблица создаётся в **текущей схеме** (первой в `search_path`). Обычно это схема `public`, если путь не меняли. Чтобы указать схему явно:

```sql
CREATE TABLE схема.имя_таблицы (
  ...
);
```

Пример простой таблицы:

```sql
CREATE TABLE users (
  id integer,
  name text,
  email text
);
```

(Среда: PostgreSQL 14+, psql)

Таблица `users` создана с тремя столбцами: `id` (целое число), `name` и `email` (текст). Подробнее о типах `integer` и `text` — в [§2.2](chapter-02-02.md).

Проверка структуры в psql:

```sql
\d users
```

Вывод:

```
                     Table "public.users"
 Column |  Type   | Collation | Nullable | Default
--------+---------+-----------+----------+---------
 id     | integer |           |          |
 name   | text    |           |          |
 email  | text    |           |          |
```

## 2.1.3. Имена таблиц

Имя таблицы — **идентификатор** SQL. Правила (см. [§1.4.5](chapter-01-04.md) и [документацию](https://www.postgresql.org/docs/current/sql-syntax-lexical.html#SQL-SYNTAX-IDENTIFIERS)):

- Может начинаться с буквы (включая латиницу с диакритикой) или подчёркивания `_`.
- Допустимые символы: буквы, цифры, подчёркивание, знак доллара `$`.
- Без кавычек — приводится к нижнему регистру; `Users`, `USERS`, `users` воспринимаются как одно и то же имя.
- В двойных кавычках — регистр сохраняется; `"Users"` и `"users"` — разные имена.

Рекомендуемые соглашения:

- Нижний регистр, слова через подчёркивание: `user_profiles`, `order_items`.
- Избегать кавычек — тогда не нужно помнить о регистре при каждом обращении.
- Не использовать имена, начинающиеся с `pg_` — они зарезервированы для системных объектов.

---

## 2.1.4. Имена столбцов

Правила для имён столбцов совпадают с правилами для имён таблиц: буквы, цифры, подчёркивание; без кавычек — нижний регистр. В одной таблице имена столбцов должны быть уникальны.

Примеры допустимых имён: `id`, `user_name`, `created_at`, `price_eur`.

Имена, совпадающие с ключевыми словами SQL (например, `select`, `from`, `order`), лучше не использовать. Если всё же нужны — заключайте в двойные кавычки: `"order"`, `"user"`. Подробнее — в [приложении по ключевым словам](https://www.postgresql.org/docs/current/sql-keywords-appendix.html).

---

## 2.1.5. Кавычки и регистр при создании

При создании таблицы `CREATE TABLE MyTable` без кавычек PostgreSQL сохранит её как `mytable`. Обращаться можно так:

```sql
SELECT * FROM mytable;
SELECT * FROM MyTable;
SELECT * FROM MYTABLE;
```

Все варианты эквивалентны. Если же таблица создана с кавычками:

```sql
CREATE TABLE "MyTable" (id integer);
```

то обратиться к ней можно только с учётом регистра:

```sql
SELECT * FROM "MyTable";   -- корректно
SELECT * FROM MyTable;     -- интерпретируется как mytable, ошибка
```

То же относится к столбцам. Рекомендация: не использовать кавычки при создании таблиц и столбцов — это упрощает работу.

---

## 2.1.6. Запятая между столбцами

Столбцы в определении таблицы разделяются **запятыми**. Частая ошибка — лишняя запятая после последнего столбца:

```sql
-- Ошибка: лишняя запятая после email
CREATE TABLE users (
  id integer,
  name text,
  email text,   -- запятая здесь вызовет синтаксическую ошибку
);
```

В PostgreSQL (как и в стандарте SQL) после последнего элемента списка запятая не ставится. Завершающая запятая (trailing comma) в `CREATE TABLE` не допускается.

---

## 2.1.7. IF NOT EXISTS

Если таблица с таким именем уже существует, `CREATE TABLE` выдаст ошибку. Чтобы избежать этого, используйте `IF NOT EXISTS`:

```sql
CREATE TABLE IF NOT EXISTS users (
  id integer,
  name text,
  email text
);
```

Если таблица `users` уже есть, команда не выполнит ничего и вернёт подсказку (notice), а не ошибку. При этом структура существующей таблицы не меняется — даже если у неё другие столбцы. См. [документацию CREATE TABLE](https://www.postgresql.org/docs/current/sql-createtable.html).

---

## 2.1.8. Таблица в указанной схеме

По умолчанию таблица создаётся в первой схеме из `search_path`. Чтобы явно задать схему:

```sql
CREATE TABLE myschema.users (
  id integer,
  name text
);
```

Таблица `users` будет создана в схеме `myschema`. Для обращения к ней нужно указать полное имя или добавить схему в `search_path`:

```sql
SELECT * FROM myschema.users;
-- или
SET search_path TO myschema, public;
SELECT * FROM users;
```

---

## 2.1.9. Временные таблицы (TEMPORARY)

Таблицу можно объявить **временной** — она будет видна только в текущей сессии и удалится при её завершении:

```sql
CREATE TEMPORARY TABLE temp_data (
  id integer,
  value text
);
```

Допустимы сокращения `TEMP` и `CREATE TEMP TABLE`. Временные таблицы создаются в специальной схеме (обычно `pg_temp_N`), которая в `search_path` имеет приоритет перед постоянными таблицами. Временные таблицы не участвуют в репликации и не записываются в WAL; они удобны для промежуточных вычислений и тестов. Подробнее — в [документации](https://www.postgresql.org/docs/current/sql-createtable.html).

---

## 2.1.10. DROP TABLE: удаление таблицы

Чтобы удалить таблицу:

```sql
DROP TABLE имя_таблицы;
```

Удаляются и все данные в таблице. Если таблицы нет, будет ошибка. Вариант с проверкой существования:

```sql
DROP TABLE IF EXISTS users;
```

Если нужно удалить таблицу и зависящие от неё объекты (представления, внешние ключи и т.д.):

```sql
DROP TABLE users CASCADE;
```

`CASCADE` удаляет зависимые объекты; использовать осторожно. См. [документацию DROP TABLE](https://www.postgresql.org/docs/current/sql-droptable.html).

---

## 2.1.11. Пример: таблица заказов

Практический пример таблицы для хранения заказов:

```sql
CREATE TABLE orders (
  id integer,
  user_id integer,
  created_at timestamp,
  total numeric(10, 2),
  status text
);
```

(Среда: PostgreSQL 14+, psql)

Типы `timestamp`, `numeric` рассматриваются в [§2.2](chapter-02-02.md). Пока достаточно понимать: `timestamp` — дата и время, `numeric(10, 2)` — число с фиксированной точностью (10 цифр, 2 после запятой).

Проверка:

```sql
\d orders
```

---

## 2.1.12. Типичные ошибки

- **Завершающая запятая:** после последнего столбца запятая не ставится.
- **Кавычки и регистр:** при создании с кавычками (`"MyTable"`) обращение без кавычек приведёт к поиску `mytable` и ошибке.
- **Дублирование имени таблицы:** в одной схеме не может быть двух таблиц с одинаковым именем; перед повторным созданием удалите старую таблицу или используйте `IF NOT EXISTS` (с учётом того, что структура не обновляется).
- **Имя столбца как ключевое слово:** `order`, `user`, `select` и т.п. лучше не использовать; при необходимости — в кавычках: `"order"`.
- **Забыть схему:** при работе с несколькими схемами проверяйте `search_path` или используйте полное имя `схема.таблица`.

---

## Ключевое

- **CREATE TABLE имя (столбец тип, ...)** — создание таблицы в текущей схеме; тип данных обязателен для каждого столбца.
- Имена таблиц и столбцов без кавычек приводятся к нижнему регистру; в кавычках сохраняют регистр.
- Столбцы разделяются запятыми; после последнего столбца запятая не ставится.
- **CREATE TABLE IF NOT EXISTS** — создание только если таблицы ещё нет; структура существующей таблицы не меняется.
- **схема.таблица** — явное указание схемы при создании и обращении.
- **CREATE TEMPORARY TABLE** — временная таблица на время сессии.
- **DROP TABLE имя** — удаление таблицы; **DROP TABLE IF EXISTS** — без ошибки при отсутствии таблицы.

В [§2.2](chapter-02-02.md) мы разберём типы данных PostgreSQL: целые числа, строки, даты, логический тип, JSON и другие варианты выбора типа для столбцов.
