# §2.1 Значения и переменные

В [§1.4](chapter-01-04.md) мы написали первую программу и научились её запускать. Этот раздел открывает главу о синтаксисе: мы разберём, как связать имя с данными в Scala — через **val** (значение, неизменяемое) и **var** (переменная, изменяемое), почему в идиоматичном Scala предпочитают val, и как работает вывод типа. В [§2.2](chapter-02-02.md) мы перейдём к основным типам: Int, Double, Boolean, String и другим.

---

## 2.1.1. val — неизменяемое значение

**val** (от value — значение) объявляет имя, связанное с результатом выражения. Связь устанавливается один раз и **не может быть изменена**: повторное присваивание тому же имени запрещено. См. [Глоссарий](glossary.md).

Синтаксис:

```scala
val имя: Тип = выражение
val имя = выражение   // тип выводится компилятором
```

Примеры:

```scala
val x: Int = 10
val name: String = "Alice"
val temperature = 36.6   // тип Double выводится автоматически
```

После объявления `x` всегда ссылается на `10`; попытка написать `x = 20` приведёт к ошибке компиляции: `reassignment to val`. То же для `name` и `temperature`.

**Почему «значение»**

В Scala термин **значение** (value) подчёркивает, что имя привязано к конкретному результату и не будет перенаправлено. Это соответствует функциональному стилю и иммутабельности ([§1.1](chapter-01-01.md)): меньше состояний, которые могут неожиданно измениться, проще рассуждать о коде и тестировать его.

## 2.1.2. var — изменяемая переменная

**var** (от variable — переменная) объявляет имя, которое **можно переназначить** на другое значение того же типа. Синтаксис аналогичен val:

```scala
var имя: Тип = начальное_значение
var имя = начальное_значение
```

Примеры:

```scala
var count = 0
count = count + 1   // теперь count равно 1
count = count + 1   // теперь 2
```

С `var` допустимы повторные присваивания. Тип при этом **не меняется**: если `count` объявлен как `Int`, ему нельзя присвоить строку или другой тип — компилятор выдаст ошибку.

```scala
var x = 10
x = 20       // OK
x = "hello"  // Ошибка: type mismatch
```

---

## 2.1.3. val и var: сравнение

| Аспект        | val                           | var                                |
|---------------|-------------------------------|------------------------------------|
| Повторное присваивание | Запрещено                     | Разрешено                          |
| Тип           | Выводится или задаётся явно   | Выводится или задаётся явно        |
| Идиоматичность | Предпочтителен в Scala       | Используется, когда нужна мутабельность |

**Семантика присваивания**

И для val, и для var присваивание **связывает имя с объектом** (или примитивным значением). При `val list = List(1, 2, 3)` имя `list` всегда указывает на этот список. Сам список неизменяем (List в Scala immutable), поэтому содержимое нельзя изменить через `list`. Если бы использовалась изменяемая коллекция (`Array`, `mutable.Buffer`), то содержимое коллекции можно было бы менять через `list(0) = 10`, но сама связь `list` с этим объектом при val остаётся неизменной. Подробнее об изменяемых и неизменяемых коллекциях — в [§5.1](chapter-05-01.md).

## 2.1.4. Рекомендация: предпочитать val

В идиоматичном Scala **рекомендуется использовать val по умолчанию** и прибегать к var только когда изменение значения действительно необходимо. Причины:

1. **Надёжность** — нельзя случайно перезаписать имя; логика проще для анализа.
2. **Параллелизм** — неизменяемые ссылки безопасны при многопоточном доступе: несколько потоков могут читать одно и то же значение без блокировок.
3. **Рефакторинг** — при изменении кода меньше риск побочных эффектов от переиспользования имени для другого значения.
4. **Функциональный стиль** — преобразования строятся как цепочки: каждое выражение создаёт новое значение, а не мутирует старое.

**Когда var допустим**

- Счётчики в простых циклах (хотя часто можно обойтись `for` или `fold`).
- Накопление результата в императивном стиле, если переписать на функциональный нецелесообразно.
- Взаимодействие с Java-библиотеками, ожидающими изменяемые поля.

В пайплайнах данных и преобразованиях коллекций обычно достаточно val: каждая стадия создаёт новую структуру, а не изменяет имеющуюся.

## 2.1.5. Вывод типа

Scala — статически типизированный язык, но во многих случаях компилятор **выводит тип** автоматически. Писать тип явно не обязательно, если он однозначно определяется по правой части:

```scala
val x = 42           // x: Int
val s = "hello"      // s: String
val list = List(1, 2, 3)   // list: List[Int]
```

Явное указание типа полезно:

- для документации и читаемости (особенно в публичном API);
- когда правую часть хотят оставить более общим типом (например, `val x: Any = ...`);
- когда компилятор не может вывести тип однозначно.

В REPL можно проверить выведенный тип: после ввода `val x = 42` будет показано `val x: Int = 42`. Команда `:type выражение` выводит тип без вычисления.

## 2.1.6. Имена и правила

**Правила имён**

- Буквы (в том числе Unicode), цифры, символ подчёркивания `_`.
- Имя не может начинаться с цифры.
- Регистр учитывается: `total` и `Total` — разные имена.

**Стиль (соглашения)**

- Имена переменных и значений — в camelCase: `userName`, `itemCount`, `totalSum`.
- Константы (значения, не меняющиеся в программе) часто пишут в верхнем регистре через подчёркивание или в camelCase: `MaxSize`, `DEFAULT_TIMEOUT`.
- Избегайте однобуквенных имён, кроме общепринятых (`i`, `j` в циклах, `x` для аргументов функций).

Зарезервированные слова (`val`, `var`, `def`, `if`, `for`, `match` и др.) использовать в качестве имён нельзя.

---

## 2.1.7. Ленивые значения (lazy val)

Помимо `val` и `var`, в Scala есть **lazy val**: значение вычисляется **при первом обращении**, а не в момент объявления. Это полезно для тяжёлых инициализаций, которые могут не понадобиться:

```scala
lazy val bigData = loadFromFile("huge.csv")   // loadFromFile вызовется только при первом использовании bigData
```

В контексте данных `lazy val` может отложить загрузку конфигурации или подключения к хранилищу. Подробнее — в главе о классах и объектах ([§6.2](chapter-06-02.md)); здесь достаточно знать, что такая возможность есть.

---

## Ключевое

- **val** — неизменяемое значение: присваивание один раз, повторное присваивание запрещено. Рекомендуется по умолчанию.
- **var** — изменяемая переменная: допустимы повторные присваивания; тип при этом не меняется.
- В идиоматичном Scala предпочитают val; var используют только когда необходимо явно менять значение.
- Компилятор выводит тип по правой части; явная аннотация типа опциональна, но полезна для ясности.
- Имена — camelCase; зарезервированные слова использовать нельзя. **lazy val** откладывает вычисление до первого обращения.
