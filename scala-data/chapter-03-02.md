# §3.2 Сопоставление с образцом (match)

В [§3.1](chapter-03-01.md) мы разобрали условие if. **Сопоставление с образцом** (pattern matching) — конструкция `match`, которая проверяет значение на соответствие нескольким образцам и выполняет соответствующий блок. В Scala match часто предпочтительнее цепочек if-else: он выразительнее, возвращает значение и позволяет разбирать Option, типы и структуры данных. В [§3.3](chapter-03-03.md) перейдём к циклу for.

---

## 3.2.1. Синтаксис match

Выражение `match` состоит из проверяемого значения, ключевого слова `match` и одного или нескольких блоков `case`:

```scala
выражение match {
  case образец1 => результат1
  case образец2 => результат2
  case _       => результат_по_умолчанию
}
```

Проверяемое значение последовательно сопоставляется с образцами сверху вниз. Выполняется блок при **первом** совпавшем образце; остальные не проверяются. Результат всего match — значение выполненной ветки.

Пример:

```scala
val x = 2
val result = x match {
  case 1 => "один"
  case 2 => "два"
  case 3 => "три"
  case _ => "другое"
}
// result: String = "два"
```

**Подстановочный образец `_`** — совпадает с любым значением; обычно ставится в конце как ветка по умолчанию.

---

## 3.2.2. match как выражение

match — **выражение**: у него есть тип и значение. Тип результата — общий супертип всех веток. Все ветки должны возвращать совместимые типы (или компилятор выведет общий, например Any).

```scala
val n = 5
val desc = n match {
  case 0 => "ноль"
  case 1 | 2 | 3 => "мало"
  case 4 | 5 | 6 => "средне"
  case _ => "много"
}
```

**Несколько значений в одном case** — через `|` (логическое ИЛИ образцов):

```scala
case 1 | 2 | 3 => "мало"
```

---

## 3.2.3. Связывание переменной: case x =>

В образце можно **связать** значение с переменной и использовать её справа от `=>`:

```scala
val x = 10
x match {
  case 0 => "ноль"
  case n => s"число $n"
}
```

Здесь `n` — любое значение, не равное 0; в правой части `n` содержит фактическое значение. Переменная в образце видна только в этой ветке.

---

## 3.2.4. Guard (охраняющее условие)

**Guard** — дополнительное условие `if` после образца. Ветка срабатывает только если образец совпал **и** условие истинно:

```scala
val x = 15
x match {
  case n if n < 0  => "отрицательное"
  case n if n < 10 => "однозначное"
  case n if n < 100 => "двузначное"
  case _ => "большое"
}
```

Синтаксис: `case образец if условие => результат`. Условие должно быть Boolean. Несколько условий можно объединять через `&&` или `||`.

Guard заменяет вложенные if и позволяет комбинировать проверку образца с произвольной логикой:

```scala
val s = "hello"
s match {
  case x if x.length > 5 => "длинная строка"
  case x if x.isEmpty => "пустая"
  case _ => "короткая непустая"
}
```

---

## 3.2.5. Сопоставление Option

Option удобно разбирать через match ([§2.5](chapter-02-05.md)):

```scala
val opt: Option[Int] = Some(42)
opt match {
  case Some(x) => println(s"Значение: $x")
  case None    => println("Значения нет")
}
```

В `case Some(x)` переменная `x` получает значение из Option. Для None отдельная ветка. Компилятор может предупредить о неполном сопоставлении, если ветка для None отсутствует и тип — Option.

```scala
val result = opt match {
  case Some(n) => n * 2
  case None    => 0
}
```

---

## 3.2.6. Сопоставление по типу

Можно сопоставлять значение по **типу**:

```scala
def describe(x: Any): String = x match {
  case i: Int    => s"целое: $i"
  case s: String => s"строка: $s"
  case d: Double => s"дробное: $d"
  case _         => "другой тип"
}
```

Синтаксис: `case переменная: Тип =>`. Переменная будет приведена к указанному типу в правой части (компилятор считает, что внутри ветки тип известен). Типы, проверяемые во время выполнения, должны учитывать стирание типов JVM (например, для generics есть ограничения).

---

## 3.2.7. Замена цепочки if-else

Многие цепочки if-else естественно переписываются в match:

**До (if-else):**

```scala
val grade = if (score >= 90) "A"
  else if (score >= 80) "B"
  else if (score >= 70) "C"
  else "D"
```

**После (match с guard):**

```scala
val grade = score match {
  case s if s >= 90 => "A"
  case s if s >= 80 => "B"
  case s if s >= 70 => "C"
  case _ => "D"
}
```

Для простых проверок на конкретные значения match обычно читается лучше; для сложных условий выбор между if и match — вопрос стиля.

---

## 3.2.8. Исчерпываемость и предупреждения компилятора

Компилятор Scala проверяет **исчерпываемость** (exhaustiveness) match для sealed-типов и enum. Если обрабатываются не все варианты, выдаётся предупреждение. Для Option достаточно веток `Some` и `None`; для собственных sealed-типов (см. [§6.3](chapter-06-03.md)) компилятор подскажет недостающие case.

Ветка `case _` перехватывает все остальные случаи и устраняет предупреждение, но может скрыть неполную обработку. Использовать её осознанно.

---

## 3.2.9. Типичные ошибки

- **Забыть ветку по умолчанию** — при значении, не совпадающем ни с одним образцом, будет `MatchError` во время выполнения. Для известного набора вариантов добавьте `case _` или обработайте все варианты явно.
- **Порядок case** — более общий образец (например, `case n =>`) до более частного «съест» все значения; ставьте частные образцы выше.
- **Использование `=` вместо `=>`** — в case пишется `=>`, не `=`.

---

## Ключевое

- **match** — сопоставление значения с образцами: `expr match { case образец => результат; case _ => default }`.
- match — **выражение**; возвращает значение выполненной ветки.
- **Связывание:** `case x =>` — переменная `x` получает значение. **Несколько значений:** `case 1 | 2 | 3 =>`.
- **Guard:** `case x if условие =>` — дополнительная проверка после совпадения образца.
- Option разбирают через `case Some(x)` и `case None`.
- Сопоставление по типу: `case x: Тип =>`. match часто предпочтительнее цепочек if-else.
