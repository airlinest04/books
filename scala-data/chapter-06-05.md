# §6.5 Иммутабельность и чистые функции

В [§6.4](chapter-06-04.md) мы разобрали трейты. Завершаем главу об объектно-ориентированном и функциональном стиле двумя связанными темами: **иммутабельностью** (неизменяемостью структур) и **чистыми функциями** (функциями без побочных эффектов). В идиоматичном Scala предпочитают оба подхода; они упрощают рассуждения о коде, тестирование и параллельное выполнение. В [§7.1](chapter-07-01.md) начнём главу о работе с данными: чтение файлов. См. [Глоссарий](glossary.md).

---

## 6.5.1. Предпочтение неизменяемых структур

**Иммутабельность** — свойство значения или структуры данных не изменяться после создания. В Scala по умолчанию используют:

- **val** вместо var — связь имени с значением устанавливается один раз;
- **List, Map, Set, Vector** — неизменяемые коллекции; операции создают новые структуры;
- **case class** с полями val — модели данных без мутации.

```scala
val list = List(1, 2, 3)
val extended = list :+ 4   // новый список; list не изменился

case class User(id: Int, name: String)
val u = User(1, "Alice")
val u2 = u.copy(name = "Bob")   // новый экземпляр; u не изменился
```

При необходимости изменений результат присваивают новой переменной или переиспользуют имя в локальной области. Изменяемые структуры (`var`, `mutable.ListBuffer`, `mutable.Map`) применяют осознанно, когда это действительно нужно (кэш, накопление в цикле).

---

## 6.5.2. Чистые функции

**Чистая функция** (pure function) — функция, которая:

1. Для одних и тех же аргументов всегда возвращает один и тот же результат;
2. Не имеет **побочных эффектов**: не изменяет внешнее состояние (файлы, переменные, база данных), не выполняет ввод-вывод, не бросает исключения, зависящие от внешнего окружения.

Пример чистой функции:

```scala
def add(a: Int, b: Int): Int = a + b
def doubleList(xs: List[Int]): List[Int] = xs.map(_ * 2)
```

Функции с побочными эффектами:

```scala
var counter = 0
def increment(): Int = { counter += 1; counter }   // мутирует внешнее состояние

def readFromFile(path: String): String = ...       // I/O
def log(msg: String): Unit = println(msg)          // вывод
```

Чистые функции не заменяют I/O и логирование — те необходимы. Но бизнес-логику, преобразования данных, вычисления лучше держать чистыми и выносить эффекты на границы (main, обработчики событий).

---

## 6.5.3. Связь с надёжностью

Иммутабельность и чистые функции упрощают понимание кода:

- **Детерминированность** — при тех же входах результат предсказуем; нет скрытых зависимостей от глобального состояния.
- **Ссылочная прозрачность** — вызов чистой функции можно заменить её результатом без изменения поведения программы.
- **Локальность** — для анализа функции достаточно смотреть только на её аргументы и возвращаемое значение, а не на «всё приложение».

Ошибки, связанные с неожиданным изменением shared state, в таком стиле встречаются реже.

---

## 6.5.4. Связь с тестированием

Чистые функции легко тестировать: достаточно передать аргументы и проверить результат. Не нужно настраивать моки, базу данных, файловую систему или глобальные переменные:

```scala
def parseAmount(s: String): Option[Double] =
  scala.util.Try(s.trim.replace(",", ".").toDouble).toOption

// Тест: parseAmount("10.5") == Some(10.5), parseAmount("x") == None
```

Код с мутацией и побочными эффектами требует изоляции окружения, сброса состояния между тестами и более сложной настройки.

---

## 6.5.5. Параллелизм

Неизменяемые структуры безопасны при параллельном доступе: несколько потоков или узлов кластера могут читать одни и те же данные без блокировок. Мутация shared state требует синхронизации (locks, атомарные операции), что усложняет код и создаёт риск deadlock и состояний гонки.

Spark RDD и Dataset построены на принципе неизменяемости: преобразования создают новые RDD/Dataset, что позволяет распределённое выполнение без общего изменяемого состояния.

---

## 6.5.6. Практические рекомендации

- Предпочитать **val**, неизменяемые коллекции и case class с val-полями.
- Выделять **чистую логику** (преобразования, вычисления) и **эффекты** (I/O, логирование); эффекты сосредоточивать на границах.
- Использовать **copy** для case class вместо мутации полей.
- Для накопления в цикле — `foldLeft` с неизменяемым аккумулятором или, при необходимости, `mutable.Buffer` в локальной области.

---

## Ключевое

- **Иммутабельность** — предпочтение val, неизменяемых коллекций (List, Map, Set) и case class; операции создают новые структуры.
- **Чистая функция** — одинаковые аргументы дают одинаковый результат; нет побочных эффектов (I/O, мутация внешнего состояния).
- Чистые функции и иммутабельность упрощают рассуждения о коде, тестирование и параллельное выполнение.
- Бизнес-логику и преобразования данных держать чистыми; эффекты выносить на границы (main, API).
