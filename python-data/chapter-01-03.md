# §1.3 Запуск кода

Теперь разберём три способа выполнить код: интерактивную оболочку (REPL), запуск файла с расширением .py и среду Jupyter для пошагового анализа. После этого в [§1.4](chapter-01-04.md) мы установим пакеты (NumPy, Pandas и др.) через pip и зафиксируем зависимости в requirements.txt.

## 1.3.1. Интерактивная оболочка (REPL)

**REPL** (Read–Eval–Print Loop) — режим работы интерпретатора, в котором вы вводите одно или несколько выражений, нажимаете Enter, интерпретатор вычисляет результат и сразу выводит его. Удобно проверять синтаксис, вызывать функции и смотреть тип переменной без написания отдельного скрипта. См. [Глоссарий](glossary.md).

**Запуск:** в терминале выполните `python3` (или `python`, если в вашей системе так запускается третья версия) без аргументов. Рекомендуется делать это **в активированном виртуальном окружении**, чтобы использовался нужный интерпретатор и доступны были установленные пакеты.

```bash
source .venv/bin/activate   # Linux/macOS; на Windows — .venv\Scripts\activate
python3
```

Появится приглашение вида `>>>`. Введите выражение и нажмите Enter:

```python
>>> 2 + 2
4
>>> len("hello")
5
```

Интерпретатор читает ввод (**R**ead), вычисляет (**E**val), печатает результат (**P**rint) и снова ждёт ввода (**L**oop). Результат последнего выражения в интерактивном режиме автоматически выводится даже без `print()`.

**Многострочный ввод:** при вводе конструкции, требующей продолжения (например, тело цикла или функции), после первой строки приглашение сменится на `...` — вводите следующие строки с тем же отступом. Пустая строка завершает блок и запускает выполнение.

**Выход из REPL:** команда `exit()` или нажатие Ctrl+D (Linux/macOS), на Windows — Ctrl+Z и Enter. Можно также ввести `quit()`.

REPL не сохраняет введённый код; для повторного использования логику переносят в файл .py или в ячейки Jupyter.

## 1.3.2. Запуск файла .py (скрипт)

Код, сохранённый в файле с расширением **.py**, выполняется как программа: интерпретатор читает файл сверху вниз и выполняет инструкции. Так пишут скрипты автоматизации, пайплайны обработки данных и приложения.

**Запуск из терминала:**

```bash
python3 script.py
```

Здесь `script.py` — путь к файлу (относительный или абсолютный). Запуск лучше выполнять из каталога проекта и с активированным виртуальным окружением, чтобы подтягивались установленные в нём пакеты.

**Пример содержимого файла** (например, `hello.py`):

```python
print("Hello, world!")
x = 10
print(x * 2)
```

Выполнение `python3 hello.py` выведет две строки: `Hello, world!` и `20`. В отличие от REPL, здесь для вывода нужно явно вызывать `print()`; просто выражение `x * 2` в файле не печатает результат.

**Практические советы:**

- Имена файлов скриптов обычно пишут в нижнем регистре, слова разделяют подчёркиванием (например, `load_data.py`). Расширение — обязательно `.py`.
- Кодировка по умолчанию — UTF-8; если в исходнике есть символы не из ASCII, убедитесь, что файл сохранён в UTF-8 (в большинстве редакторов это настройка по умолчанию).
- Запуск с аргументами командной строки и передача их в программу рассматриваются в главе о модулях ([§4.4](chapter-04-04.md)); там же — использование `if __name__ == '__main__':` для кода, который должен выполняться только при прямом запуске файла.

Для обучения и экспериментов часто удобнее сначала проверить идею в REPL или в Jupyter, а затем перенести рабочий код в .py для повторного запуска и версионирования.

## 1.3.3. Jupyter Notebook и JupyterLab (краткий обзор)

**Jupyter** — среда для интерактивных документов, в которых чередуются ячейки с кодом, вывод (текст, таблицы, графики) и поясняющий текст в разметке (Markdown). Широко используется в аналитике данных и машинном обучении: можно загрузить данные, посмотреть срез таблицы, построить график и тут же описать шаги. См. [Глоссарий](glossary.md).

**Установка:** Jupyter не входит в стандартную поставку Python. Его ставят в виртуальное окружение через pip (подробнее про pip — в [§1.4](chapter-01-04.md)):

```bash
pip install jupyter
```

или для JupyterLab (расширенный интерфейс с вкладками и файловым менеджером):

```bash
pip install jupyterlab
```

**Запуск:**

- Классический Jupyter Notebook: в терминале из каталога проекта (с активированным окружением) выполните `jupyter notebook`. Откроется браузер с веб-интерфейсом; там можно создать новый ноутбук (.ipynb) или открыть существующий.
- JupyterLab: команда `jupyter lab` — откроется интерфейс с боковой панелью (файлы, запущенные ядра, команды).

**Работа в ноутбуке:** документ состоит из ячеек. В ячейке с кодом вы вводите одну или несколько строк Python и запускаете их сочетанием клавиш (например, Shift+Enter). Результат выводится под ячейкой; переменные сохраняются в общем сеансе (kernel), поэтому следующая ячейка может использовать результат предыдущей. Ячейки Markdown содержат текст и формулы — для заметок и отчёта. Порядок выполнения можно менять и повторять ячейки, что удобно для итеративной обработки данных.

**Когда использовать:** Jupyter удобен для разведки данных, построения графиков и пошаговых экспериментов. Для воспроизводимых пайплайнов и продакшен-скриптов код обычно переносят в .py и запускают через `python3 script.py` или оркестратор; ноутбуки же часто используют для отчётов и документации анализа.

В этой книге примеры в основном приводятся в виде кода, который можно выполнять и в REPL, и в файле, и в ячейке Jupyter — по вашему выбору.

## Ключевое

- **REPL** — интерактивная оболочка: запуск командой `python3` без аргументов; ввод выражений и немедленный вывод результата; выход — `exit()` или Ctrl+D (Ctrl+Z на Windows). Удобно для быстрых проверок; лучше использовать внутри активированного venv.
- **Скрипт .py** — выполнение файла: `python3 script.py`; код выполняется сверху вниз; для вывода нужен явный вызов `print()`. Подходит для повторяемых скриптов и пайплайнов.
- **Jupyter** — среда с ячейками кода и Markdown; установка через `pip install jupyter` или `pip install jupyterlab`; запуск — `jupyter notebook` или `jupyter lab`. Удобен для пошагового анализа и отчётов; для воспроизводимого кода часто переносят логику в .py.

В [§1.4](chapter-01-04.md) мы установим пакеты (pip, numpy, pandas) и зафиксируем список зависимостей в requirements.txt.
