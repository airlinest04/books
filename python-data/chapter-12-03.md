# §12.3 Валидация и переобучение

В [§12.2](chapter-12-02.md) мы разобрали подготовку данных для ML и утечку целевой переменной. Одна разбивка train/test даёт одну оценку метрики и может быть неудачной из-за случайного разбиения. В этом разделе — **кросс-валидация** (cross_val_score) для более устойчивой оценки и кратко **переобучение** и **регуляризация**. В [§13.1](chapter-13-01.md) перейдём к обзору фреймворков глубокого обучения: когда нужны нейросети и чем они отличаются от классического ML.

---

## 12.3.1. Кросс-валидация (cross_val_score)

**cross_val_score(estimator, X, y, cv=None, scoring=None)** из **sklearn.model_selection** выполняет **кросс-валидацию**: данные разбиваются на **cv** частей (складок); по очереди одна часть используется как тест, остальные — как обучение; модель обучается и оценивается **cv** раз. Результат — массив из **cv** значений метрики (по одному на складку). Среднее и стандартное отклонение этого массива дают более устойчивую оценку качества, чем один запуск train_test_split.

- **estimator** — модель (например, LinearRegression(), LogisticRegression()); не обученная, cross_val_score сама вызывает fit и predict внутри каждой складки.
- **X, y** — признаки и целевая переменная (целиком; разбиение делает кросс-валидация).
- **cv** — число складок (целое, например 5) или итератор разбиений. По умолчанию 5 (стратифицированная для классификации при cv=int).
- **scoring** — имя метрики: для регрессии — 'neg_mean_squared_error', 'r2' и др.; для классификации — 'accuracy', 'f1' и др. Для MSE в cross_val_score используют 'neg_mean_squared_error' (знак минус: больше — лучше, как в остальных метриках sklearn).

Важно: внутри каждой складки предобработка (scaler, encoder) должна подгоняться только по обучающей части этой складки; для этого удобно объединять шаги в **Pipeline** (в книге не разбирается). Без пайплайна кросс-валидация на «сырых» данных даёт приближённую оценку.

```python
from sklearn.model_selection import cross_val_score
from sklearn.linear_model import LinearRegression

model = LinearRegression()
scores = cross_val_score(model, X, y, cv=5, scoring="neg_mean_squared_error")
# scores — массив из 5 значений (отрицательный MSE по складкам)
import numpy as np
mse_mean = -np.mean(scores)
mse_std = np.std(scores)
```

## 12.3.2. Переобучение

**Переобучение** (overfitting) — модель слишком хорошо подстраивается под обучающую выборку (в том числе под шум) и плохо обобщает на новые данные. На train метрика высокая (ошибка низкая), на тесте — заметно хуже. При недообучении (underfitting) и train, и test дают плохой результат (модель слишком простая).

Признаки переобучения: большая разница между метрикой на train и на test (train значительно лучше); при увеличении сложности модели (больше параметров, дерево глубже) качество на train растёт, на test — падает или колеблется. Решения: упростить модель, добавить **регуляризацию**, увеличить объём данных, уменьшить число признаков или использовать отбор признаков. Кросс-валидация помогает увидеть разброс качества и не полагаться на одну случайную разбивку.

---

## 12.3.3. Регуляризация (кратко)

**Регуляризация** — штраф за сложность модели (большие веса), чтобы уменьшить переобучение. В линейных моделях часто используют:

- **Ridge** (L2): штраф за сумму квадратов весов; все веса остаются ненулевыми.
- **Lasso** (L1): штраф за сумму модулей весов; часть весов может обнулиться (отбор признаков).

В Scikit-learn: **Ridge**, **Lasso** из sklearn.linear_model; гиперпараметр **alpha** задаёт силу регуляризации (чем больше alpha, тем сильнее штраф). Подбор alpha обычно делают по кросс-валидации (GridSearchCV, в книге не разбирается).

Для нейросетей к регуляризации относят также dropout, early stopping (остановка по качеству на валидации). Идея общая: ограничить сложность или «запоминание» обучающей выборки.

---

## Ключевое

- **cross_val_score(model, X, y, cv=5, scoring=...)** — кросс-валидация: модель обучается и оценивается **cv** раз на разных разбиениях; результат — массив метрик; среднее даёт устойчивую оценку. Для регрессии scoring='neg_mean_squared_error'.
- **Переобучение** — модель хорошо описывает train, плохо — новые данные; признак — метрика на train сильно лучше, чем на test. Регуляризация и упрощение модели помогают снизить переобучение.
- **Регуляризация** — штраф за большие веса (Ridge — L2, Lasso — L1); гиперпараметр alpha; в Scikit-learn — Ridge, Lasso.

В [§13.1](chapter-13-01.md) рассмотрим, когда нужны глубокие нейросети и чем они отличаются от классического машинного обучения.
