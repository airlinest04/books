# §4.6 Обработка исключений

В [§4.5](chapter-04-05.md) мы кратко рассмотрели модули os, sys, datetime и json. Завершаем главу о функциях и модулях **обработкой исключений**: при работе с файлами, API и «сырыми» данными ошибки неизбежны — файл не найден, неверный формат, сеть недоступна. Конструкция **try/except** позволяет перехватывать такие ситуации и реагировать по-разному: залогировать, подставить значение по умолчанию или пробросить исключение выше. В [§5.1](chapter-05-01.md) мы перейдём к структурам данных — спискам.

---

## 4.6.1. try и except

Код, в котором может возникнуть ошибка (исключение), помещают в блок **try**. Обработчик — блок **except**: указывают тип исключения и инструкции, которые выполнятся при его перехвате.

```python
try:
    x = int("not a number")
except ValueError:
    print("Не удалось преобразовать в число")
```

Если внутри try возникло исключение типа **ValueError**, выполнение блока try прерывается и управление переходит в блок except. Если исключения не было, блок except не выполняется. После try/except выполнение продолжается дальше.

**Без указания типа** перехватываются все исключения (не рекомендуется без необходимости — можно скрыть серьёзные ошибки):

```python
try:
    risky_operation()
except:
    print("Что-то пошло не так")
```

Лучше указывать конкретный тип: **except ValueError:**, **except KeyError:** и т.д. — тогда обрабатываются только ожидаемые ошибки.

**Несколько типов в одном except** (с Python 3): перечисление в скобках:

```python
except (ValueError, TypeError):
    print("Ошибка типа или значения")
```

**Блок else** (необязательный) выполняется, если в try не возникло исключения; **блок finally** выполняется всегда (и после исключения, и без него) — обычно там размещают освобождение ресурсов (закрытие файла). Подробности — в документации; для начала достаточно try и except.

## 4.6.2. Типичные типы исключений

При работе с данными часто встречаются следующие исключения.

**ValueError** — неверное значение: число или строка в неподходящем формате. Например: `int("abc")`, `float("")`, неверный формат даты в strptime.

**TypeError** — неверный тип аргумента или операция между несовместимыми типами. Например: сложение числа и строки, вызов с неправильным числом аргументов.

**KeyError** — обращение к несуществующему ключу словаря: `d["missing"]`, когда ключа `"missing"` нет. Обход — метод **.get(key, default)** ([§5.2](chapter-05-02.md)) или проверка `key in d` перед доступом.

**IndexError** — индекс списка или строки вне допустимого диапазона: `lst[10]` при длине списка меньше 11.

**FileNotFoundError** (подкласс **OSError**) — файл не найден при открытии. При работе с путями и файлами ([глава 6](chapter-06-01.md)) это типичная ситуация: неверный путь, файл удалён или ещё не создан.

**IOError** в Python 3 объединён с **OSError**; при ошибках ввода-вывода (диск, сеть) обычно ловят **OSError** или конкретный подкласс (FileNotFoundError, PermissionError).

**Exception** — базовый класс для многих встроенных исключений. Перехват **except Exception:** ловит почти всё, кроме системного выхода (SystemExit) и KeyboardInterrupt; использовать имеет смысл для общего «лога и проброс» в верхнем уровне, не для подавления любых ошибок в мелком блоке.

## 4.6.3. Обработка по типу и порядок except

Можно написать несколько блоков **except** подряд — каждый для своего типа. Интерпретатор сопоставляет исключение с блоками **сверху вниз**; выполняется первый подходящий блок:

```python
try:
    value = data[key]
except KeyError:
    value = None
except TypeError:
    value = 0
```

Порядок важен: если поставить **except Exception:** первым, он перехватит все исключения и более конкретные except ниже никогда не выполнятся. Сначала обрабатывают более конкретные типы, затем при необходимости общий Exception.

## 4.6.4. raise: проброс и создание исключения

**raise** — явно вызвать исключение. Используют, когда функция обнаружила ошибочную ситуацию и хочет сообщить о ней вызывающему коду:

```python
def set_age(age):
    if not 0 <= age <= 150:
        raise ValueError("Возраст должен быть от 0 до 150")
    ...
```

**Проброс перехваченного исключения** — **raise** без аргументов внутри except: исключение перебрасывается дальше без изменения (удобно для логирования и повторного выброса):

```python
try:
    process_file(path)
except OSError as e:
    log_error(f"Ошибка при обработке {path}: {e}")
    raise
```

Переменная **as e** сохраняет объект исключения; у него есть атрибут **e.args** (кортеж аргументов) и часто **str(e)** для текста сообщения. После логирования **raise** передаёт то же исключение выше по стеку.

## 4.6.5. Зачем в пайплайнах данных и при работе с API/файлами

При загрузке данных из файлов, баз и API возможны:

- **Отсутствующий или битый файл** — FileNotFoundError, ошибки чтения; обработка позволяет пропустить файл, записать в лог и продолжить со следующим.
- **Неверный формат данных** — лишние поля, неверный тип в ячейке, сломанный JSON; ValueError, KeyError, json.JSONDecodeError. Можно обработать строку/запись, подставить значение по умолчанию или пропустить запись и залогировать.
- **Сетевые ошибки** — таймаут, 5xx от API; после перехвата часто делают повторную попытку (retry) или откладывают задачу.

Обработка исключений не заменяет проверку данных (валидацию), но дополняет её: критические ошибки (нет файла, нет сети) перехватывают, логируют и по возможности обрабатывают; некритичные (одна плохая строка в CSV) позволяют продолжить обработку остальных данных. В продакшен-пайплайнах типично логировать исключение (модуль **logging**) и либо пробрасывать его выше, либо завершать шаг с ненулевым кодом выхода (sys.exit(1)), чтобы оркестратор зафиксировал сбой.

---

## Ключевое

- **try:** — блок, в котором может возникнуть исключение. **except Тип:** — перехват указанного типа; выполняется при совпадении типа исключения. Указывать конкретный тип предпочтительнее, чем общий except.
- Типичные типы: **ValueError** (неверное значение), **TypeError** (неверный тип), **KeyError** (нет ключа в словаре), **IndexError** (индекс вне диапазона), **FileNotFoundError** / **OSError** (файл, ввод-вывод).
- Несколько **except** подряд — порядок важен; более конкретные типы обрабатывают раньше **Exception**. **raise** — выброс исключения; **raise** без аргументов в except — проброс перехваченного исключения.
- В пайплайнах данных и при работе с API/файлами try/except нужен для устойчивости: отсутствующие файлы, неверный формат, сетевые сбои; типично логировать и пробрасывать или завершать шаг с ошибкой.
