# §4.3 Область видимости

В [§4.2](chapter-04-02.md) мы разобрали позиционные и именованные аргументы и *args/**kwargs. Теперь — **область видимости** (scope): где видны переменные, что такое локальные и глобальные имена и как правильно работать с ними. Понимание области видимости помогает избежать ошибок при присваивании внутри функций и упрощает отладку. В [§4.4](chapter-04-04.md) перейдём к модулям и импорту.

---

## 4.3.1. Локальные переменные

Переменные, которым **присваивают значение внутри функции**, а также **параметры** функции считаются **локальными** для этой функции: они существуют только во время выполнения функции и недоступны снаружи.

```python
def calc():
    x = 10
    y = 20
    return x + y
calc()   # 30
print(x) # NameError: name 'x' is not defined
```

После выхода из функции локальные переменные уничтожаются. При следующем вызове той же функции локальные переменные создаются заново. Имена локальных переменных не пересекаются с именами в других функциях или на уровне модуля: в другой функции может быть своя переменная с тем же именем — это другой объект.

---

## 4.3.2. Глобальные переменные и чтение

**Глобальные переменные** — переменные, объявленные на уровне модуля (на верхнем уровне файла, вне функций и классов). Они видны во всём модуле и **внутри функций их можно читать** без дополнительных объявлений:

```python
config = {"encoding": "utf-8"}

def read_file(path):
    enc = config["encoding"]   # чтение глобальной переменной
    ...
```

Интерпретатор ищет имя сначала среди локальных имён функции, затем среди глобальных (и при необходимости встроенных). Поэтому обращение к глобальной переменной по имени внутри функции при **чтении** работает.

---

## 4.3.3. Присваивание и локальная тень

Если внутри функции выполняется **присваивание** имени, то это имя считается **локальным** для всей функции. Даже если до присваивания есть только чтение, интерпретатор при разборе функции помечает имя как локальное, и обращение к нему до присваивания приведёт к ошибке:

```python
x = 100

def bad():
    print(x)   # UnboundLocalError: local variable 'x' referenced before assignment
    x = 5

bad()
```

Причина: `x = 5` создаёт локальную переменную `x`; Python считает `x` локальной во всей функции, поэтому в строке `print(x)` ожидается локальная переменная, которая к этому моменту ещё не присвоена.

Чтобы **присвоить значение глобальной переменной** внутри функции, нужно явно объявить её глобальной (см. ниже). Без этого присваивание создаёт или обновляет только локальную переменную; глобальная не изменится:

```python
count = 0

def increment_wrong():
    count = count + 1   # UnboundLocalError: count локальная, до присваивания не определена

def increment_ok():
    global count
    count = count + 1
```

---

## 4.3.4. Инструкция global

Инструкция **global имя** (или **global a, b, c** для нескольких имён) объявляет, что перечисленные имена внутри функции относятся к **глобальной области видимости**. Тогда присваивание изменяет глобальную переменную, а не создаёт локальную:

```python
counter = 0

def increment():
    global counter
    counter += 1

increment()
increment()
print(counter)   # 2
```

**global** нужно писать в начале функции (до использования имени); достаточно одного объявления на имя в функции. Читать глобальную переменную можно и без global; global нужен именно для **присваивания** (и для del, что редко используется).

Злоупотребление глобальными переменными усложняет код: функции становятся зависимыми от внешнего состояния, их сложнее тестировать и переиспользовать. Обычно лучше **передавать данные аргументами** и **возвращать результат** через return.

---

## 4.3.5. Лучшие практики

- **Передавать данные в функцию через аргументы** и возвращать результат через **return**. Так функция явно зависит только от переданных параметров и не опирается на скрытое глобальное состояние.
- **Не изменять глобальные переменные** внутри функций без явной необходимости; если всё же нужно — объявлять их через **global** и делать это осознанно (например, счётчики, флаги в скриптах).
- **Константы** (например, пути, кодировки, лимиты) часто держат в переменных на уровне модуля и только читают внутри функций — без присваивания им не нужен global. По соглашению имена констант пишут в верхнем регистре (UPPER_CASE).
- **Избегать совпадения имён** локальных переменных с глобальными, если не используете global: так проще читать код и не путать области видимости.

При работе с данными типичный стиль: путь к файлу, параметры подключения и т.п. передавать аргументами или читать из конфигурации (файл, переменные окружения); результат обработки возвращать из функции. Глобальные переменные оставлять для редких случаев (например, общий кэш или настройки, заданные один раз при старте).

---

## Ключевое

- **Локальные переменные** — создаются при присваивании внутри функции (параметры тоже локальны); видны только внутри функции и существуют только во время её выполнения.
- **Глобальные переменные** — объявлены на уровне модуля; их можно **читать** внутри функции без объявления. **Присваивание** имени внутри функции по умолчанию создаёт локальную переменную; глобальная при этом не меняется.
- **global имя** — объявление, что имя относится к глобальной области; после этого присваивание внутри функции изменяет глобальную переменную.
- Лучшая практика: передавать данные аргументами и возвращать результат; не опираться на изменение глобального состояния без необходимости. Константы уровня модуля допустимы (только чтение).
