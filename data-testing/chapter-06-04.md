# §6.4 Граничные случаи и null

В [§6.3](chapter-06-03.md) мы разобрали тестирование фильтрации и джойнов. Завершаем главу о тестировании преобразований разбором **граничных случаев** и **обработки null**: пустой вход, null в полях, граничные значения (ноль, минимум, максимум) и деление на ноль. На этих сценариях запросы и формулы чаще всего ведут себя иначе или падают; отдельные тесты на границы снижают риск сюрпризов в проде.

---

## 6.4.1. Пустой вход

**Пустой вход** — таблица-источник или результат предыдущего шага содержит 0 строк. Ожидание: запрос не падает с ошибкой; результат агрегации или выборки предсказуем.

Что проверять:

- **SELECT без агрегации:** результат — 0 строк. Запрос выполняется, возвращается пустой набор. Assertion: COUNT(*) = 0.
- **Агрегаты:** в SQL SUM, AVG, MIN, MAX по пустому набору дают NULL (в большинстве СУБД); COUNT(*) даёт 0. Тест с пустой фикстурой проверяет: запрос с GROUP BY и SUM выполняется, результат — 0 строк (групп нет) или одна строка с NULL/0 в агрегатах — в зависимости от того, возвращает ли запрос строку при отсутствии групп. Важно зафиксировать ожидаемое поведение (например, «при пустом входе возвращаем 0 строк» или «возвращаем одну строку с total = NULL»), чтобы при изменении логики тест отреагировал.
- **Джойн с пустой таблицей:** LEFT JOIN с пустой правой таблицей даёт все строки левой с NULL в полях правой; INNER JOIN даёт 0 строк. Тест проверяет отсутствие падения и ожидаемое количество строк.

Типичная ошибка: в приложении или в следующем шаге пайплайна результат пустого запроса не обрабатывается (обращение к первой строке без проверки, деление на сумму по пустому набору). Тест с пустым входом выявляет необходимость явной обработки «нет данных». См. [Глоссарий](glossary.md) в контексте граничных случаев.

---

## 6.4.2. Null в полях

**NULL** в SQL — отсутствие значения; сравнения и арифметика с NULL дают NULL или UNKNOWN, строки с NULL в ключевом поле могут по-разному участвовать в джойнах и группировках. Тесты должны явно проверять поведение при null во входных полях.

Что покрывать:

- **Агрегаты:** SUM, AVG, MIN, MAX игнорируют NULL; COUNT(column) не считает NULL, COUNT(*) считает строки. Фикстура с несколькими строками, у части из которых в агрегируемой колонке NULL: тест проверяет, что результат агрегации совпадает с ожиданием (например, SUM только по не-NULL значениям).
- **Фильтр:** условие `WHERE col = 1` не включает строки с col IS NULL (сравнение с NULL даёт UNKNOWN, строка отфильтровывается). Если по бизнесу «неизвестно» должно обрабатываться отдельно, в запросе нужна ветка IS NULL или COALESCE; тест с null в фильтруемой колонке проверяет, что такие строки попадают или не попадают в результат согласно спецификации.
- **Маппинг и вычисления:** COALESCE(col, 0), NVL(col, default) — тест с null во входном поле проверяет, что на выходе подставлено ожидаемое значение по умолчанию. Выражение типа col_a / col_b при col_b = NULL даёт NULL; при col_b = 0 — деление на ноль (ошибка или NULL в зависимости от СУБД). Тест с null в делителе фиксирует текущее поведение.
- **Джойн:** при равенстве по ключу NULL = NULL в SQL не истина; строка с NULL в ключе джойна не совпадает ни с чем. Если в данных возможны null в ключе, тест проверяет: такие строки не размножают результат (не создают декартово произведение) и при LEFT JOIN остаются с NULL в полях правой таблицы.

Отдельный тест «все значения в колонке NULL» проверяет агрегаты (SUM = NULL или 0, COUNT(column) = 0) и отсутствие падения.

## 6.4.3. Граничные значения

**Граничные значения** — минимум, максимум, ноль, пустая строка, максимальная длина — часто меняют поведение формул и условий.

Что проверять:

- **Ноль:** amount = 0 при условии amount > 0 исключается; при делении 0 / positive = 0; при расчёте доли ноль в числителе даёт 0%. Фикстура с нулём в ключевых полях; assertion — результат не падает и значение совпадает с ожиданием (включён/исключён, 0 или NULL).
- **Отрицательные числа:** если по бизнесу они недопустимы, тест с отрицательным значением может проверять либо отсечение фильтром, либо срабатывание проверки/ошибки. Если допустимы — проверяем, что они не теряются и не искажаются в формулах.
- **Большие числа:** переполнение типа (INT, SMALLINT); округление при приведении к типу с меньшей точностью. Тест с числом на границе типа проверяет отсутствие переполнения или явную обработку.
- **Даты:** минимальная/максимальная дата, граница периода (первый и последний день месяца). Фильтр по периоду (BETWEEN, >= и <) должен однозначно включать или исключать граничные даты; тест с датой ровно на границе фиксирует ожидание.
- **Пустая строка:** '' vs NULL; в сравнениях и в длине они ведут себя по-разному. Если в источнике возможна пустая строка, тест проверяет маппинг и фильтрацию (не путать с NULL).

Перечислять все границы не обязательно; достаточно выбрать критичные для домена (деньги не отрицательные, дата не из будущего, ключевые поля не пустая строка где не допускается) и покрыть их отдельными кейсами.

## 6.4.4. Деление на ноль

**Деление на ноль** в SQL и в формулах даёт ошибку или NULL (в зависимости от СУБД и настроек). Если в расчёте есть деление (доля, процент, среднее как sum/count), делитель может оказаться нулём при пустой группе или при нулевой сумме.

Что делать в тестах:

- **Ожидаемое поведение зафиксировать:** запрос с делением при делителе = 0 либо возвращает NULL, либо вызывает ошибку. Тест с фикстурой (одна строка с нулём в знаменателе или группа с нулевой суммой) проверяет: запрос выполняется без падения (если в коде есть NULLIF(denominator, 0) или CASE) и результат NULL или 0 по правилам; либо тест ожидает исключение и проверяет, что оно возникает.
- **Защита в запросе:** использование NULLIF(column, 0) в знаменателе даёт при 0 результат NULL и избегает ошибки. Тест с нулём в знаменателе проверяет, что результат NULL (или подставленное по правилам значение), а не падение.
- **Агрегат с делением:** например, AVG как SUM/COUNT при COUNT=0 — деление на ноль. Пустая группа или пустой вход; тест проверяет, что запрос не падает и для таких групп возвращается NULL или явное значение по умолчанию.

Один тест «делитель = 0» часто достаточен для каждой формулы с делением; при изменении логики (добавили защиту или изменили поведение) тест обновляют. В [§7.1](chapter-07-01.md) мы начнём главу о проверке полноты и целостности ETL: сравнение row count источник vs приёмник.

---

## Ключевое

- **Пустой вход:** запрос не падает; результат — 0 строк для выборки; для агрегатов — 0 или NULL по правилам СУБД. Тест фиксирует ожидание (0 строк или одна строка с NULL/0), чтобы не было неопределённости при пустом наборе.
- **Null в полях:** агрегаты игнорируют NULL; фильтр с col = value не включает NULL; маппинг с COALESCE/NVL проверять на null во входе; джойн по ключу с NULL — осторожность (NULL = NULL не истина). Отдельный тест «все значения NULL» и тесты с частичным null в ключевых полях.
- **Граничные значения:** ноль, отрицательные, большие числа, граничные даты, пустая строка — выбирать критичные для домена и покрывать тестами; фиксировать включение/исключение границы и отсутствие переполнения.
- **Деление на ноль:** зафиксировать ожидание (NULL или ошибка); при защите в запросе (NULLIF и т.п.) тест с нулём в знаменателе проверяет отсутствие падения и результат NULL или по правилам.

В [§7.1](chapter-07-01.md) мы начнём главу о проверке полноты и целостности ETL: сравнение количества строк источник vs приёмник, допуски и причины расхождений.
