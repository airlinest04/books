# §6.2 Ключи сверки и контрольные суммы

В [§6.1](chapter-06-01.md) мы разобрали этапы пайплайна подготовки отчёта: извлечение, расчёты, заполнение формы, проверки и сдача. Проверки опираются на **сверку** показателей отчёта с источниками и на **контрольные итоги**. В этом разделе — **ключи сверки** с бухгалтерией и операционными системами, **контрольные суммы** внутри формы и **перекрёстные проверки** между формами. Валидация по правилам ЦБ и алерты — в [§6.3](chapter-06-03.md). См. [Глоссарий](glossary.md).

---

## 6.2.1. Сверка с бухгалтерией

**Сверка с бухгалтерией** — сопоставление показателей регуляторной формы с остатками и оборотами по счетам бухучёта на ту же отчётную дату и за тот же период. Цель — убедиться, что отчёт построен на тех же данных, что и бухучёт, и что расчёты не исказили значения. См. [§4.3](chapter-04-03.md), [§5.3](chapter-05-03.md).

**Ключи сверки с бухучётом:**

- **Счёт (номер счёта или account_id).** Поле формы, заполняемое из «остаток по счёту» или «оборот по счёту», сверяется с остатком/оборотом по этому счёту в бухучёте на отчётную дату (или за период). Маппинг формы задаёт, какое поле отчёта соответствует какому счёту или группе счетов; для сверки берётся тот же набор счетов и та же дата (дата валютирования). См. [§5.3](chapter-05-03.md), [§4.3](chapter-04-03.md).

- **Дата (отчётная дата, период).** Остатки — на одну дату; обороты — за один и тот же интервал (день, месяц). Бухучёт и форма должны использовать одну и ту же отчётную дату и один и тот же способ учёта даты (дата валютирования). См. [§4.3](chapter-04-03.md).

- **Валюта и единица измерения.** Суммы в форме и в бухучёте сравниваются в одной валюте (рубли, пересчёт по курсу ЦБ при необходимости). Разрез по валюте в форме должен соответствовать разбивке в учёте. См. [§3.4](chapter-03-04.md).

- **Агрегат по группе счетов.** Если поле формы = сумма остатков по нескольким счетам (например, по коду счёта или по признаку), то для сверки считается та же сумма по тем же счетам в бухучёте на ту же дату. Ключ — список счетов (или правило отбора) + дата. См. [§1.4](chapter-01-04.md), [§4.2](chapter-04-02.md).

Процесс: после заполнения формы для выбранных полей (или для всех, где источник — бухучёт) извлекаются эталонные остатки/обороты из бухучёта по тем же ключам; сравниваются с значениями в форме; расхождение выше допустимого порога — повод для разбора (ошибка маппинга, задержка проводки, разная отчётная дата). См. [§6.1](chapter-06-01.md), [§6.4](chapter-06-04.md).

## 6.2.2. Сверка с операционными системами и витринами

Показатели формы могут браться из витрин DWH (портфель кредитов, просрочка, транзакции, платежи), а витрины в свою очередь строятся из Core и операционных систем. **Сверка с операционными системами и витринами** — проверка, что значение в форме совпадает с агрегатом из витрины (или из операционной системы) по тем же ключам. См. [§4.4](chapter-04-04.md), [§6.1](chapter-06-01.md).

**Ключи:**

- **Договор, карта, счёт (продукт).** Для форм по кредитам: остаток по форме по группе договоров vs сумма остатков по витрине «портфель кредитов» на ту же дату по тем же фильтрам (продукт, сегмент, филиал). Для форм по картам — витрина «портфель карт», «обороты по картам»; ключ — договор/карта, период, продукт. См. [§1.4](chapter-01-04.md), [§2.4](chapter-02-04.md).

- **Платёж (UETR или внутренний ID).** Для отчётности по платежам сверка с платёжной системой и с бухучётом по оборотам: список платежей за период с UETR, суммой, датой валютирования; сумма исполненных платежей за период должна совпадать с оборотом по корсчёту (или с агрегатом из витрины платежей). Ключ сверки одной операции — UETR (или EndToEndId). См. [§3.4](chapter-03-04.md), [Глоссарий](glossary.md).

- **Дата среза и период.** Витрины строятся на дату среза; форма должна использовать ту же отчётную дату. Обороты за период — тот же интервал (дата валютирования от и до). См. [§4.1](chapter-04-01.md), [§6.1](chapter-06-01.md).

При расхождении «форма vs витрина» проверяется: актуальность витрины на отчётную дату; корректность маппинга (те же фильтры и группировки); наличие отложенных загрузок. См. [§6.4](chapter-06-04.md).

## 6.2.3. Контрольные итоги

**Контрольные итоги** — проверки внутри одной формы: сумма составляющих равна итогу, сумма по подразделам равна итогу раздела, арифметические соотношения между строками (например, «итого = сумма строк 1–N»). См. [Глоссарий](glossary.md).

Типичные проверки:

- **Сумма строк = итог.** Поле «Итого» по разделу должно равняться сумме заполненных строк этого раздела (с учётом округления). Если форма задаёт такое соотношение, его проверяют до сдачи автоматически или вручную.
- **Субтотали.** Итог по группе строк (например, по валютам) должен совпадать с суммой этих строк; итог по форме — с суммой субтоталей.
- **Баланс.** В формах, отражающих баланс (актив = пассив), сумма активных статей должна равняться сумме пассивных; расхождение — ошибка заполнения или расчёта.
- **Проценты и доли.** Если в форме есть «доля в %», проверяется: сумма долей по группе = 100% (или заданная база); пересчёт доли от базы даёт то же значение.

Контрольные итоги задаются спецификацией формы ЦБ; банк может добавить внутренние проверки (дополнительные субтотали по своим разрезам для отладки). При падении проверки заполнение или расчёты корректируются до устранения расхождения. См. [§6.1](chapter-06-01.md), [§6.3](chapter-06-03.md).

## 6.2.4. Перекрёстные проверки между формами

**Перекрёстные проверки между формами** — сопоставление связанных показателей из разных форм отчётности: один и тот же остаток или оборот может входить в несколько форм в одном и том же разрезе; значения должны совпадать. См. [§5.1](chapter-05-01.md), [§5.3](chapter-05-03.md).

Примеры:

- **Остаток по счёту (баланс).** Показатель «остаток по счёту на дату» может фигурировать в балансовой форме и в расшифровке другой формы; источник один — бухучёт; значения должны быть одинаковыми (счёт, дата, валюта).
- **Резервы и ссудная задолженность.** Сумма резерва по портфелю в форме по рискам и сумма резерва в форме по балансу (по счетам резервов) должны согласовываться; то же для ссудной задолженности — форма по кредитам и баланс.
- **Обороты за период.** Оборот по счёту за месяц в одной форме и тот же оборот в отчёте за тот же месяц в другой форме — один источник (бухучёт или витрина), значения совпадают.
- **Количество и объёмы.** Число договоров, карт, платёжных операций в одной форме и в другой (если считаются по одним и тем же правилам и на одну дату) — перекрёстная проверка по объёмам.

Ключи для перекрёстной проверки: **отчётная дата**, **период**, **счёт или группа счетов (код статьи)**, **валюта**. Реестр форм и маппингов помогает выявить, какие поля разных форм должны совпадать; при изменении форм перечень перекрёстных проверок обновляется. См. [§5.4](chapter-05-04.md), [§6.3](chapter-06-03.md).

## 6.2.5. Реализация: что хранить и как проверять

Для автоматизации сверки и контрольных итогов целесообразно:

- **Реестр ключей сверки** по форме: для каждого поля (или группы полей), сверяемого с бухучётом, — источник (счёт, список счетов, витрина, запрос), дата/период, допустимое расхождение (например, ноль или порог из-за округления). См. [§5.3](chapter-05-03.md).
- **Спецификация контрольных итогов** по форме: перечень соотношений «сумма строк = итог», «актив = пассив», «доли = 100%» и т.п.; при обновлении формы ЦБ спецификация актуализируется. См. [§5.4](chapter-05-04.md).
- **Матрица перекрёстных проверок:** пара (форма A, поле/показатель) — (форма B, поле/показатель); условие совпадения (дата, период, счёт). Запуск проверок после заполнения всех задействованных форм (или по мере готовности при известных зависимостях). См. [§6.1](chapter-06-01.md).

Проверки выполняются в пайплайне после шага «заполнение формы»; при расхождении пайплайн может останавливаться, писать алерт и передавать управление ответственному; после исправления проверки перезапускаются. См. [§6.3](chapter-06-03.md), [§6.4](chapter-06-04.md).

---

## Ключевое

- **Сверка с бухгалтерией:** ключи — счёт (или группа счетов), отчётная дата/период, валюта; показатели формы, заполненные из бухучёта, сравниваются с остатками/оборотами по тем же ключам.
- **Сверка с витринами и операционными системами:** ключи — продукт (договор, карта), дата среза, период; для платежей — UETR, сумма, дата валютирования; форма должна совпадать с агрегатами из витрины при тех же фильтрах.
- **Контрольные итоги:** внутри формы — сумма строк = итог, субтотали, баланс (актив = пассив), проверка долей; задаются спецификацией формы, проверяются до сдачи.
- **Перекрёстные проверки между формами:** связанные показатели (остаток по счёту, резерв, оборот) в разных формах должны совпадать при одинаковых дате, периоде и разрезе; реестр ключей и матрица перекрёстных проверок поддерживаются при изменении форм.

В [§6.3](chapter-06-03.md) мы разберём валидацию и проверки перед сдачей: встроенные проверки ЦБ, внутренние проверки банка и алерты при расхождениях.
