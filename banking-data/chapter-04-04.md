# §4.4 Источники данных и слои загрузки

В [§4.3](chapter-04-03.md) мы разобрали связь продукт — счёт — проводка и ключи для джойнов. Завершающий раздел главы 4 — **источники данных** банка (операционные системы, бухгалтерия, внешние провайдеры) и **слои загрузки** в DWH: Raw, Staging, Core, Mart применительно к кредитам, картам и платежам. Материал связывает части I–III книги и задаёт контекст для глав по регуляторной отчётности (гл. 5–6) и пайплайнам подготовки отчётов. См. [Глоссарий](glossary.md), [§2.4](chapter-02-04.md), [§6.1](chapter-06-01.md).

---

## 4.4.1. Операционные системы как источники

**Операционные системы** — системы, в которых фиксируются текущие операции банка: выдача кредитов, обслуживание карт, проведение платежей, учёт договоров и клиентов. Они являются первичным источником событий и справочников для DWH. См. [§1.1](chapter-01-01.md), [§2.1](chapter-02-01.md), [§3.1](chapter-03-01.md).

Типичные источники по продуктам:

| Продукт / область | Операционная система (обобщённо) | Что поставляет в DWH |
|-------------------|----------------------------------|------------------------|
| Кредиты | Кредитная система (ядро кредитования) | Договоры, клиенты, выдачи, платежи, графики, связь договор — счёт; расчёт остатка, DPD, категории качества, резерва |
| Карты | Карточное ядро (эмиссия, транзакции) | Карты, договоры, счета, события жизненного цикла, транзакции (авторизация, клиринг); связь карта — договор — счёт |
| Платежи | Платёжная система, модуль переводов | Платежи (внутренние и внешние), статусы, история статусов; разобранные сообщения SWIFT/ISO 20022, UETR |
| Клиенты | CRM, справочник клиентов | Клиенты (ID, тип, сегмент, атрибуты для идентификации); используется во всех витринах по разрезу «клиент» |
| Справочники | Продуктовые и общебанковские справочники | Продукты, филиалы, валюты, коды MCC и т.д. |

Данные из операционных систем выгружаются по расписанию (ежедневно, ежечасно) или передаются потоково (события, сообщения). Формат выгрузки — таблицы в БД, файлы (CSV, XML, JSON), API. При загрузке в DWH сохраняются ключи источника (ID договора, ID транзакции, ID платежа) для идемпотентности и трассировки. См. подраздел 4.4.5 и [§6.1](chapter-06-01.md).

---

## 4.4.2. Бухгалтерия как источник

**Бухгалтерия** (учётная система банка) — источник проводок, остатков и оборотов по счетам. Для сверки с продуктовыми данными и для регуляторной отчётности в DWH загружают. См. [§1.4](chapter-01-04.md), [§4.3](chapter-04-03.md).

- **Проводки** за период: дата валютирования, дебет-счёт, кредит-счёт, сумма, документ/операция (при наличии — ссылка на продуктовую операцию). По проводкам считаются обороты по счёту и остатки на дату.
- **Остатки по счетам** на дату (если система отдаёт готовые срезы): счёт, дата среза, остаток, при необходимости обороты за период.
- **План счетов** (справочник): код счёта, наименование, тип; используется для маппинга и отчётности.

Загрузка выполняется по тому же расписанию, что и продуктовые данные (например, после закрытия операционного дня), чтобы срезы и обороты в DWH соответствовали одному и тому же состоянию бухучёта. Связь проводки с продуктом — через счёт (договор/карта → счёт) и при наличии через идентификатор документа/операции. См. [§4.3](chapter-04-03.md), [§6.2](chapter-06-02.md).

---

## 4.4.3. Внешние провайдеры

**Внешние провайдеры** — системы вне банка, от которых банк получает данные для учёта и сверки. См. [§3.1](chapter-03-01.md), [§3.2](chapter-03-02.md).

- **Платёжные системы (ЦБ, SWIFT и др.):** выписки по корреспондентским счетам, списки проведённых платежей с UETR и статусами, при необходимости детализация сообщений. Используются для сверки с данными банка по платежам и по корсчетам. См. [§3.4](chapter-03-04.md), [§6.2](chapter-06-02.md).
- **Платёжные сети (карты):** при необходимости — данные клиринга, коды ответов, сверка объёмов с эквайером и сетью. См. [§2.2](chapter-02-02.md).
- **Внешние справочники:** курсы валют (ЦБ, биржа), коды БИК, справочники MCC и т.д.; загружаются для обогащения витрин и отчётности.

Данные от внешних провайдеров приходят в виде выгрузок, выписок или API; при загрузке в DWH сохраняются идентификаторы (UETR, номер выписки) и даты для сопоставления с внутренними данными. См. [§6.1](chapter-06-01.md).

## 4.4.4. Слои загрузки: Raw, Staging, Core, Mart

Слои DWH задают последовательность преобразований от «сырых» данных к витринам для отчётности и аналитики. Ниже — применительно к банку. См. [Глоссарий](glossary.md), книгу «Проектирование и архитектура хранилищ данных» ([../dwh/](../dwh/)).

**Raw (сырой слой).** Данные в том виде, в каком получены из источника: выгрузки таблиц, файлы, дампы сообщений. Минимальная обработка: сохранение под исходным именем или по правилу именования (источник_дата_тип), при необходимости парсинг в структурированные поля. Цель — сохранить возможность перезагрузки и аудита «как пришло». Срок хранения Raw может быть ограничен (например, 30–90 дней) с последующей архивацией. См. [§6.1](chapter-06-01.md).

**Staging (промежуточный слой).** Данные, приведённые к единой структуре для загрузки в Core: единые имена полей, типы данных, ключи. Дубликаты по ключу источника отбрасываются или помечаются (идемпотентность); проверяются обязательные поля. Staging — слой «очищенных» выгрузок перед объединением с другими источниками и бизнес-правилами.

**Core (ядро).** Нормализованные сущности и факты с привязкой ко времени: договоры, карты, счета, клиенты; выдачи, платежи по кредитам, транзакции, платежи; связь продукт — счёт; при необходимости снимки на дату (портфель, остатки). В Core применяются бизнес-правила: расчёт остатка, DPD, категории качества, резерва; обогащение из справочников (клиент, продукт, филиал). Core — единый источник правды для витрин; из него строятся агрегаты и снимки. См. [§4.1](chapter-04-01.md), [§4.2](chapter-04-02.md), [§4.3](chapter-04-03.md).

**Mart (витрины).** Слой для потребления отчётностью и аналитикой: витрины «портфель кредитов», «движения», «просрочка»; «портфель карт», «транзакции», «обороты по картам»; «платежи», «обороты по платежам». Гранулярность и состав полей заданы под конкретные отчёты и дашборды; данные могут быть денормализованы для ускорения запросов. Витрины питаются из Core (и при необходимости из Staging для оперативных срезов). См. [§4.2](chapter-04-02.md), [§5.3](chapter-05-03.md), [§6.1](chapter-06-01.md).

Схема потока: Источники → Raw → Staging → Core → Mart. Отдельные витрины могут строиться напрямую из Core без отдельного физического слоя Mart. См. [§6.1](chapter-06-01.md).

## 4.4.5. Идемпотентность и расписание загрузки

**Идемпотентность** — свойство загрузки: повторный запуск с теми же входными данными не приводит к дублированию и не искажает результат. Достигается за счёт ключа уникальности: при вставке в Core и Mart используется ключ (ID транзакции, ID платежа, договор + дата среза и т.д.); при совпадении ключа запись обновляется или пропускается, а не добавляется вторая раз. См. [§2.4](chapter-02-04.md), [§3.4](chapter-03-04.md).

**Расписание загрузки** задаётся потребностями отчётности и доступностью данных: после закрытия операционного дня — полная загрузка проводок и продуктовых событий за день; для оперативных витрин — частые инкрементальные загрузки (каждый час, каждые 15 минут). Порядок загрузки важен: сначала справочники (клиенты, продукты, счета), затем факты (выдачи, платежи, транзакции, проводки), затем расчёт снимков и витрин, чтобы при построении витрин уже были актуальные связи договор — счёт, карта — договор. См. [§6.1](chapter-06-01.md).

## 4.4.6. Сводка: источники и слои по продуктам

| Продукт | Основные источники | Raw / Staging | Core | Mart |
|---------|--------------------|---------------|------|------|
| Кредиты | Кредитная система, бухучёт | Выгрузки договоров, выдач, платежей, проводок | Договоры, выдачи, платежи, связь договор — счёт; расчёт остатка, DPD, резерва | Портфель, движения, просрочка |
| Карты | Карточное ядро, бухучёт | Выгрузки карт, договоров, транзакций, проводок | Карты, договоры, транзакции, связь карта — договор — счёт | Портфель карт, транзакции, обороты |
| Платежи | Платёжная система, бухучёт, выписки ЦБ/SWIFT | Выгрузки платежей, проводок, выписок | Платежи (поля из сообщений), связь платёж — счета | Платежи, обороты по платежам |

Справочники (клиенты, продукты, филиалы, план счетов) загружаются в Raw/Staging и затем в Core; используются при построении витрин во всех продуктах. См. [§4.2](chapter-04-02.md), [§4.3](chapter-04-03.md).

## 4.4.7. Типичные ошибки

- **Загружать факты без справочников:** витрины требуют разрезы (клиент, продукт, филиал); при отсутствии справочников в Core джойны не сработают или дадут пустые значения. Порядок: сначала справочники, потом факты.
- **Отсутствие идемпотентности:** повторный прогон из-за сбоя или ручного перезапуска дублирует транзакции и проводки; обороты и остатки завышаются. Ключ загрузки должен быть явно задан для каждой таблицы фактов.
- **Разные даты среза в Core и в бухучёте:** снимки остатков и портфеля в DWH должны строиться на ту же дату, что и выгрузка проводок/остатков из бухучёта; иначе сверка даёт ложные расхождения.
- **Игнорировать внешние источники для сверки:** без выписок платёжной системы и ЦБ нельзя провести полноценную сверку по платежам и корсчетам; внешние данные должны загружаться и сопоставляться по UETR и дате.

## Ключевое

- **Источники:** операционные системы (кредиты, карты, платежи, клиенты, справочники), бухгалтерия (проводки, остатки, план счетов), внешние провайдеры (платёжные системы, выписки ЦБ/SWIFT, справочники).
- **Слои:** Raw (сырые выгрузки) → Staging (очистка, единая структура, идемпотентность по ключу) → Core (сущности, факты, связь продукт — счёт, расчёт остатков и показателей) → Mart (витрины по продуктам и разрезам).
- **Идемпотентность** загрузки по ключу (ID транзакции, ID платежа, договор + дата среза) обязательна; **расписание** — после закрытия дня или чаще для оперативных витрин; порядок — справочники, затем факты, затем витрины.
- По продуктам: кредиты, карты и платежи питаются из своих операционных систем и бухучёта; Core объединяет данные и связи; витрины строятся из Core для отчётности и сверки.

В [§5.1](chapter-05-01.md) мы переходим к части II — регуляторной отчётности: основные формы отчётности в ЦБ, их назначение и связь с бухгалтерскими данными.
