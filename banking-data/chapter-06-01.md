# §6.1 Этапы подготовки регуляторного отчёта

Глава 6 посвящена **пайплайну** от данных до сданного отчёта в ЦБ. В этом разделе — **этапы подготовки** регуляторного отчёта: **извлечение** данных из DWH и операционных систем, **расчёты** по правилам формы, **заполнение** формы, **проверки** и **сдача**. Материал опирается на источники и маппинг из [§5.3](chapter-05-03.md), на календарь сдачи из [§5.2](chapter-05-02.md) и на слои данных из [§4.4](chapter-04-04.md). Ключи сверки, валидация и обработка ошибок — в [§6.2](chapter-06-02.md)–[§6.4](chapter-06-04.md). См. [Глоссарий](glossary.md).

---

## 6.1.1. Пайплайн подготовки отчёта: общая схема

**Пайплайн подготовки регуляторного отчёта** — последовательность шагов от готовности исходных данных до представления формы в ЦБ. См. [Глоссарий](glossary.md).

Типичная цепочка:

1. **Готовность данных** — закрытие бухучёта на отчётную дату (при необходимости), завершение загрузки в DWH (витрины, остатки, проводки на отчётную дату). Без этого следующий шаг выполнять рано.
2. **Извлечение** — чтение данных из источников (витрины, бухучёт, Core) по маппингу формы.
3. **Расчёты** — применение правил расчёта к извлечённым данным (агрегаты, группировки, формулы по указанию ЦБ).
4. **Заполнение формы** — перенос рассчитанных значений в поля формы (файл или система сдачи ЦБ).
5. **Проверки** — сверка с бухучётом, контрольные суммы, встроенные проверки ЦБ, внутренние валидации. См. [§6.2](chapter-06-02.md), [§6.3](chapter-06-03.md).
6. **Сдача** — отправка формы в ЦБ в установленные сроки; при ошибке — исправление и пересдача. См. [§6.4](chapter-06-04.md).

Пайплайн может быть автоматизирован (скрипты, оркестратор, система отчётности) или выполняться с ручными шагами; в любом случае порядок этапов и зависимости (сначала данные, потом извлечение, потом расчёты и т.д.) должны быть зафиксированы. Запуск пайплайна привязан к календарю сдачи и к факту готовности данных. См. [§5.2](chapter-05-02.md), [§5.3](chapter-05-03.md).

---

## 6.1.2. Извлечение из DWH и операционных систем

**Извлечение** — получение данных из таблиц и витрин в соответствии с маппингом «поле отчёта — источник». См. [§5.3](chapter-05-03.md).

Источники: витрины в DWH (портфель кредитов, просрочка, транзакции, платежи, обороты), таблицы бухучёта (остатки по счетам, проводки за период, план счетов), при необходимости Core и операционные системы напрямую. Запросы формулируются по маппингу: для каждого поля формы — запрос к указанной таблице/витрине с фильтрами (отчётная дата, период, код счёта, категория качества и т.д.) и агрегацией (сумма, count, остаток на дату). Результат извлечения — набор значений (или промежуточная таблица), который подаётся на шаг расчётов. См. [§4.2](chapter-04-02.md), [§4.4](chapter-04-04.md).

Важно: извлечение выполняется **после** того, как данные на отчётную дату загружены и витрины/остатки актуализированы. Если пайплайн запускается по расписанию, в расписании должна быть учтена зависимость «сначала загрузка DWH и закрытие бухучёта, затем пайплайн отчёта». См. [§4.4](chapter-04-04.md), [§5.2](chapter-05-02.md).

---

## 6.1.3. Расчёты

**Расчёты** — применение к извлечённым данным правил, заданных формой ЦБ: формулы, группировки, пересчёт в другие единицы, округление. См. [§5.3](chapter-05-03.md), книгу «Финансовые расчёты в DWH и SQL» ([../financial-calculations-dwh/](../financial-calculations-dwh/)).

Часть полей формы заполняется напрямую из источника (остаток по счёту, сумма оборотов); часть требует расчёта: например, итог по группе счетов, доля в процентах, норматив по формуле ЦБ. Правила расчёта задаются в маппинге или в отдельной спецификации формы. Расчёты выполняются в том же пайплайне (скрипт, модуль системы отчётности) после извлечения; результат — значения для всех полей формы, готовые к переносу в форму. См. [§5.1](chapter-05-01.md), [§6.2](chapter-06-02.md) (контрольные суммы для проверки расчётов).

---

## 6.1.4. Заполнение формы

**Заполнение формы** — перенос рассчитанных значений в структуру отчёта: файл установленного формата (XML, XBRL, CSV и т.д. по требованиям ЦБ) или ввод в веб-форму/систему сдачи ЦБ. См. [Глоссарий](glossary.md).

Технически заполнение может быть: генерация файла по шаблону с подстановкой значений; запись в базу системы отчётности с последующим экспортом в формат ЦБ; API системы ЦБ при автоматической сдаче. Для каждого поля формы используется значение, полученное на шаге расчётов, по маппингу. Версия формы и дата отчётности записываются в метаданные отчёта. После заполнения форма готова к проверкам. См. [§5.4](chapter-05-04.md), [§6.3](chapter-06-03.md).

---

## 6.1.5. Проверки перед сдачей

Перед сдачей выполняются **проверки** двух типов. См. [§6.2](chapter-06-02.md), [§6.3](chapter-06-03.md).

**Внутренние проверки банка:** сверка показателей формы с источниками (остатки по форме vs остатки по бухучёту; сумма по витрине vs значение в форме); контрольные итоги (сумма строк равна итогу); перекрёстные проверки между формами (согласованность связанных показателей). При расхождении заполнение или источники корректируются до устранения ошибки. См. [§6.2](chapter-06-02.md).

**Проверки ЦБ:** многие формы при приёме проходят встроенные проверки (контрольные соотношения, допустимые значения); при ошибке система ЦБ может отклонить файл или выдать предупреждение. Банк может заранее запускать аналогичные проверки у себя (по описанию ЦБ или по известным правилам), чтобы не отправлять заведомо неверный отчёт. См. [§6.3](chapter-06-03.md).

Проверки выполняются в пайплайне после заполнения формы; при падении проверки пайплайн может останавливаться с алертом или переходить в режим «на согласование» для ручного решения. См. [§6.4](chapter-06-04.md).

---

## 6.1.6. Сдача

**Сдача** — представление формы в ЦБ в установленный срок через предусмотренный канал (портал ЦБ, система электронной отчётности, иное по указаниям). См. [§5.2](chapter-05-02.md), [Глоссарий](glossary.md).

После успешной проверок файл (или данные) отправляется в ЦБ; фиксируются дата и время сдачи, идентификатор отчёта при наличии. Сданный отчёт сохраняется в архиве банка с привязкой к версии формы и маппинга ([§5.4](chapter-05-04.md)). При отклонении или необходимости исправления выполняется пересдача по регламенту; процесс исправления и пересдачи — в [§6.4](chapter-06-04.md).

---

## 6.1.7. Зависимости и порядок выполнения

Порядок этапов и зависимости:

- **Данные готовы** (бухучёт закрыт, DWH загружен на отчётную дату) → можно запускать пайплайн.
- **Извлечение** → зависит от маппинга и доступности источников; при нескольких формах, использующих одни и те же витрины, извлечение может быть общим, а расчёт и заполнение — по форме.
- **Расчёты** → на входе извлечённые данные; на выходе — значения полей.
- **Заполнение формы** → на входе рассчитанные значения; на выходе — заполненная форма.
- **Проверки** → на входе заполненная форма и при необходимости исходные данные для сверки; при успехе — форма готова к сдаче.
- **Сдача** → после успешных проверок, в срок по календарю.

Зависимости между формами: если форма B использует итоги формы A, то сначала готовится и при необходимости сдаётся форма A, затем форма B. Календарь сдачи и регламент банка задают порядок форм при нескольких сдачах в один день. См. [§5.2](chapter-05-02.md), [§5.3](chapter-05-03.md).

## 6.1.8. Типичные ошибки

- **Запуск пайплайна до готовности данных:** витрины или бухучёт ещё не обновлены на отчётную дату — форма заполняется неверными или неполными данными; нужна проверка готовности (чек по дате закрытия бухучёта, по дате среза витрин) перед стартом.
- **Жёстко заданный порядок полей без маппинга:** при изменении формы код заполнения ломается; заполнение должно опираться на маппинг (конфиг, таблица), а не на захардкоженные индексы полей.
- **Отсутствие проверок в пайплайне:** сдача без сверки с бухучётом и без контрольных соотношений повышает риск сдать ошибочный отчёт; проверки должны быть автоматизированы и блокировать сдачу при падении (или эскалировать на ответственного).
- **Нет логирования этапов:** при сбое или пересдаче сложно выяснить, на каком шаге произошла ошибка и какие данные использовались; в пайплайне целесообразно логировать шаги, версию формы, дату извлечения и хеш/контрольную сумму результата.

## Ключевое

- **Пайплайн подготовки отчёта:** готовность данных → извлечение из источников по маппингу → расчёты по правилам формы → заполнение формы → проверки (внутренние и при возможности проверки ЦБ) → сдача. Сдача в срок по календарю; сданный отчёт хранится с версией формы и маппинга.
- **Извлечение** — чтение из DWH (витрины, Core) и бухучёта по маппингу полей формы; выполняется после актуализации данных на отчётную дату.
- **Расчёты** — применение формул и правил ЦБ к извлечённым данным; результат — значения для всех полей формы.
- **Заполнение** — перенос значений в форму (файл или система ЦБ); **проверки** — сверка с источниками и контрольные соотношения до сдачи; **сдача** — представление в ЦБ, фиксация и архивирование.
- Зависимости: данные готовы до старта; порядок этапов фиксирован; при нескольких формах учитывается порядок и зависимости между формами.

В [§6.2](chapter-06-02.md) мы разберём ключи сверки и контрольные суммы: как сверять отчёт с бухгалтерией и операционными системами и какие перекрёстные проверки выполнять между формами.
