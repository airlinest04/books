# §4.2 Витрины по продуктам и разрезы

В [§4.1](chapter-04-01.md) мы ввели принципы событий и снимков и выбор гранулярности. Теперь систематизируем **витрины по продуктам** банка — кредиты, карты, платежи — и **разрезы**, по которым строятся отчёты: клиент, филиал, продукт. Материал опирается на главы 1–3 и связывает витрины, уже описанные там, с общей моделью данных и с подходами книги по DWH. См. [Глоссарий](glossary.md), [../dwh/](../dwh/).

---

## 4.2.1. Витрина «Кредиты»: портфель, движения, просрочка

По кредитам в банке обычно выделяют три витрины (или три типа представлений в одной витрине). См. [§1.4](chapter-01-04.md), [§4.1](chapter-04-01.md).

**Портфель кредитов (снимок на дату).** Гранулярность: договор × дата среза. Поля: договор, клиент, продукт, филиал, счёт учёта, дата выдачи, срок, лимит, ставка, валюта, остаток долга на дату, статус договора, DPD, просроченная сумма, категория качества, сумма резерва. Источник: справочники договоров и клиентов, события (выдачи, платежи) для расчёта остатка, график и расчёт DPD/категории/резерва. Используется для отчётов «портфель на дату», агрегатов по продукту, филиалу, сегменту клиента, для форм ЦБ. См. [§1.4](chapter-01-04.md), [§5.3](chapter-05-03.md).

**Движения по кредитам (события за период).** Гранулярность: одна запись на выдачу или на платёж. Поля: дата, договор, тип операции (выдача / платёж), сумма, разбивка на тело/проценты при платеже, связь с продуктом/клиентом/филиалом через договор. Источник: таблицы событий (выдачи, платежи) из Core. Используется для отчётов о движении портфеля, сверки с оборотами по счёту ссудной задолженности. См. [§1.4](chapter-01-04.md).

**Просрочка (снимок на дату).** Гранулярность: договор × дата среза (часто подмножество витрины «портфель» или отдельная выборка). Поля: договор, дата среза, DPD, просроченная сумма, категория качества, сумма резерва. Используется для риск-отчётности и форм ЦБ по качеству ссуд. См. [§1.3](chapter-01-03.md), [§1.4](chapter-01-04.md).

Общие разрезы по всем витринам кредитов: **клиент** (сегмент, тип), **продукт** (вид кредита), **филиал** (подразделение выдачи). Связь с измерениями: договор → клиент, продукт, филиал; договор → счёт учёта для сверки с бухучётом. См. [§4.3](chapter-04-03.md).

## 4.2.2. Витрина «Карты»: портфель, транзакции, обороты

По картам выделяют витрины портфеля, фактов транзакций и агрегатов оборотов. См. [§2.4](chapter-02-04.md), [§4.1](chapter-04-01.md).

**Портфель карт (снимок на дату).** Гранулярность: карта × дата среза (или договор × дата). Поля: карта, договор, клиент, продукт (дебетовая/кредитная), филиал, счёт, статус карты, дата выпуска, при необходимости остаток по счёту (или ссудная задолженность по кредитной карте). Источник: справочники карт, договоров, счетов; события жизненного цикла (эмиссия, блокировка). Используется для отчётов «активные карты на дату», «портфель по продуктам». См. [§2.1](chapter-02-01.md), [§2.4](chapter-02-04.md).

**Транзакции (события).** Гранулярность: одна запись на проведённую транзакцию. Поля: ID транзакции, дата авторизации, дата валютирования, карта, договор, счёт, сумма, валюта, тип операции, мерчант, MCC, канал, статус. Источник: карточное ядро, при необходимости бухучёт. Используется для аналитики, антифрода, детализации оборотов. См. [§2.2](chapter-02-02.md), [§2.3](chapter-02-03.md), [§2.4](chapter-02-04.md).

**Обороты по картам (агрегат за период).** Гранулярность: договор × период (или продукт × период, MCC × период и т.д.). Поля: период (день/месяц), объект (договор, продукт, MCC, канал), количество транзакций, сумма оборотов, при необходимости сумма возвратов. Строится из витрины транзакций. Используется для отчётов по обороту, среднего чека, сегментации. См. [§2.3](chapter-02-03.md), [§2.4](chapter-02-04.md).

Разрезы: **клиент** (через договор), **продукт** (тип карты), **филиал**, **MCC**, **канал** (POS, ATM, e-commerce). См. подраздел 4.2.4.

## 4.2.3. Витрина «Платежи»

По платежам (переводы внутри банка и между банками) — витрины фактов и агрегатов. См. [§3.4](chapter-03-04.md), [§4.1](chapter-04-01.md).

**Платежи (факты).** Гранулярность: одна запись на платёж. Поля: ID платежа, UETR (или аналог), сумма, валюта, дата создания, дата валютирования, плательщик (счёт, банк), получатель (счёт, банк), назначение, платёжная система, статус, причина отказа при отклонении. Источник: операционные системы платежей, разобранные сообщения SWIFT/ISO 20022. Используется для сверки с контрагентами и ЦБ, для детализации оборотов. См. [§3.2](chapter-03-02.md), [§3.4](chapter-03-04.md).

**Обороты по платежам (агрегат за период).** Гранулярность: период × направление (входящие/исходящие) × тип (внутренние/внешние) × валюта (и при необходимости платёжная система, банк-контрагент). Поля: период, разрезы, количество платежей, сумма. Строится из витрины платежей по дате валютирования и статусу «исполнен». Используется для отчётности и сверки с бухучётом по корреспондентским и клиентским счетам. См. [§3.4](chapter-03-04.md).

Разрезы: **банк плательщика/получателя**, **валюта**, **платёжная система**, при необходимости **клиент** (по счёту плательщика/получателя) и **филиал** (если учёт ведётся в разрезе подразделений). См. подраздел 4.2.4.

## 4.2.4. Разрезы по клиенту, филиалу, продукту

**Разрез** — измерение, по которому агрегируют или фильтруют данные в витринах и отчётах. Общие для многих витрин разрезы в банке: клиент, филиал, продукт. См. [Глоссарий](glossary.md).

| Разрез | Источник в данных | Применение |
|--------|-------------------|------------|
| **Клиент** | Договор → клиент; счёт → клиент; карта → договор → клиент | Агрегаты по клиенту (портфель, обороты), сегментация, отчёты по сегментам, 115-ФЗ |
| **Филиал** | Договор/карта: филиал выдачи, подразделение; счёт: привязка к филиалу | Внутренняя отчётность по подразделениям, территориальные отчёты |
| **Продукт** | Договор: тип продукта (вид кредита, дебетовая/кредитная карта); платёж: тип (внутренний/внешний) | Отчёты по продуктам, тарифы, регуляторика |

В витринах измерения хранятся либо в самой записи факта/снимка (договор, карта, платёж уже содержат ссылки на клиента, продукт, филиал), либо в отдельных справочниках (измерениях); джойн по ключу (contract_id → client_id, product_id, branch_id). Схема «звезда» в DWH: факты (выдачи, платежи, транзакции, снимки) в центре, измерения (клиент, продукт, филиал, счёт) — по периметру. См. книгу «Проектирование и архитектура хранилищ данных» ([../dwh/](../dwh/)), [§4.3](chapter-04-03.md).

## 4.2.5. Связь с книгой по DWH

Подходы к витринам и слоям данных в банке согласуются с общими принципами хранилищ данных. См. [../dwh/](../dwh/).

- **Факты и измерения:** витрины «движения», «транзакции», «платежи» — таблицы фактов; клиент, продукт, филиал, счёт — измерения. Ключи фактов ссылаются на ключи измерений для джойнов.
- **Снимки на дату:** периодические снимки остатков и портфеля соответствуют типу «снимок состояния» (snapshot) в DWH; ключ — бизнес-объект + дата среза.
- **Слои:** Raw/Staging (сырые выгрузки) → Core (нормализованные сущности и факты) → Mart (витрины по продуктам и разрезам). Загрузка из операционных систем и бухучёта — в [§4.4](chapter-04-04.md).
- **Единый источник правды:** для аналитики и отчётности витрины питаются из Core; правила расчёта остатков, DPD, категорий задаются один раз и применяются единообразно. См. [§1.4](chapter-01-04.md), [§6.2](chapter-06-02.md).

Детали схем «звезда» и «снежинка», зависимые и независимые витрины, место витрин в архитектуре — в книге по DWH; здесь зафиксированы состав витрин по продуктам банка и разрезы для отчётности. См. [../dwh/](../dwh/).

## 4.2.6. Типичные ошибки

- **Дублировать логику расчёта в нескольких витринах:** расчёт остатка, DPD, категории качества должен выполняться в одном месте (Core или единый расчётный слой); витрины потребляют готовые показатели, иначе риск расхождений между отчётами.
- **Витрина без явных разрезов:** если в витрине нет полей «клиент», «продукт», «филиал» (или ключей к измерениям), нельзя строить отчёты по этим разрезам без джойнов к сырым данным; разрезы должны быть в витрине или в одном джойне с измерением.
- **Смешивать гранулярности в одной таблице без разделения:** факты (одна запись на событие) и агрегаты за период (одна запись на договор × месяц) лучше хранить в разных таблицах или явно различать по типу записи.
- **Игнорировать связь витрина — счёт:** для сверки с бухучётом в витринах движений, транзакций и платежей должна быть связь со счётом (договор → счёт, карта → счёт, платёж → счета плательщика/получателя). См. [§4.3](chapter-04-03.md).

## Ключевое

- **Кредиты:** витрины «портфель» (снимок договор × дата), «движения» (события выдачи/платежи), «просрочка» (снимок с DPD, категорией, резервом). Разрезы: клиент, продукт, филиал.
- **Карты:** витрины «портфель карт» (снимок), «транзакции» (факты), «обороты по картам» (агрегат за период). Разрезы: клиент, продукт, филиал, MCC, канал.
- **Платежи:** витрины «платежи» (факты), «обороты по платежам» (агрегат за период). Разрезы: валюта, платёжная система, банк, при необходимости клиент, филиал.
- **Разрезы:** клиент (через договор/счёт), филиал (подразделение), продукт (тип кредита/карты); хранятся в записи факта или в измерениях; джойны по ключам.
- Связь с DWH: факты и измерения, снимки на дату, слои Raw → Core → Mart; единый источник правды и единые правила расчёта для витрин.

В [§4.3](chapter-04-03.md) мы разберём связь продукт — счёт — проводка: как продуктовая сущность (договор, карта) связана с бухгалтерскими счетами и проводками и какие ключи использовать для джойнов и сверки.
