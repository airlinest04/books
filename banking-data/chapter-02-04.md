# §2.4 Связь с планом счетов и DWH

В [§2.1](chapter-02-01.md)–[§2.3](chapter-02-03.md) мы разобрали карточные продукты, транзакции (авторизация, клиринг), данные для отчётности и антифрода. Завершающий раздел главы 2 — как карточные операции отражаются **проводками** в бухучёте, по каким **счетам** ведётся учёт, и как данные **загружаются в DWH** и строятся **витрины**. Логика аналогична главе 1 ([§1.4](chapter-01-04.md)): связь карта — договор — счёт обеспечивает сверку продуктовых данных с бухучётом. См. [Глоссарий](glossary.md).

---

## 2.4.1. Проводки по операциям по дебетовой карте

При оплате **дебетовой картой** списание идёт с расчётного (текущего) счёта клиента. Банк-эмитент списывает сумму со счёта держателя и переводит средства эквайеру (банку мерчанта) через платёжную систему. В бухучёте эмитента это отражается так. См. [§2.1](chapter-02-01.md), [§2.2](chapter-02-02.md).

Типовая проводка при проведении операции по дебетовой карте (после клиринга, на дату валютирования):

| Дебет | Кредит | Смысл |
|-------|--------|--------|
| Счёт клиента (расчётный/текущий) | Счёт расчётов с платёжной системой (или корреспондентский, счёт расчётов с эквайером) | Списание со счёта клиента в пользу расчётов по карточной операции |

Конкретные счета задаются планом счетов кредитной организации. Счёт клиента — пассивный (средства клиента): по дебету отражается уменьшение остатка (списание). Одна проведённая транзакция = одна или несколько проводок с датой валютирования. В данных для сверки нужны: транзакция (ID, дата валютирования, сумма, карта, договор, счёт клиента), проводки по этому счёту за ту же дату. Оборот по дебету счёта клиента за период по карточным операциям должен совпадать с суммой проведённых транзакций по дебетовым картам, привязанным к этому счёту. См. [§1.4](chapter-01-04.md), книгу «Бухгалтерия для программистов» ([../accounting-for-programmers/](../accounting-for-programmers/)).

---

## 2.4.2. Проводки по операциям по кредитной карте

При оплате **кредитной картой** банк не списывает средства со счёта клиента, а увеличивает ссудную задолженность по карте. В бухучёте эмитента при проведении операции (после клиринга): См. [§2.1](chapter-02-01.md), [§1.4](chapter-01-04.md).

| Дебет | Кредит | Смысл |
|-------|--------|--------|
| Счёт учёта ссудной задолженности по кредитным картам | Счёт расчётов с платёжной системой (корр. счёт, расчёты с эквайером) | Рост задолженности клиента по карте; перевод средств эквайеру |

Счёт ссудной задолженности — активный: по дебету увеличение (операции по карте), по кредиту — уменьшение (платежи клиента в погашение). Погашение задолженности по кредитной карте отражается так же, как по обычному кредиту: дебет счёта расчётов (поступление от клиента), кредит счёта ссудной задолженности (тело), кредит счёта доходов по процентам (проценты). Связь транзакция — договор — счёт ссудной задолженности позволяет сверять обороты по счёту с суммой транзакций и с суммой платежей в погашение. См. [§1.4](chapter-01-04.md).

---

## 2.4.3. Счета учёта: связь карта — договор — счёт

Для каждой **карты** в данных должна быть однозначная связь с **договором** и со **счётом** бухучёта: по дебетовой карте — расчётный (текущий) счёт клиента; по кредитной — счёт учёта ссудной задолженности по карте. См. [§2.1](chapter-02-01.md), [Глоссарий](glossary.md).

Зачем это нужно:

- **Проводки:** карточный модуль или бухгалтерия формируют проводки по счёту на основе транзакций; ключ — счёт, привязанный к карте/договору.
- **Сверка:** обороты по счёту за период (дебет для расчётного счёта — списания; дебет для ссудной задолженности — рост операций, кредит — погашения) должны совпадать с оборотами из таблицы транзакций и платежей по этому договору/счёту.
- **Загрузка в DWH:** при загрузке транзакций и проводок связь «транзакция — карта — договор — счёт» позволяет джойнить данные продукта и бухучёта и строить витрины в единых разрезах.

Если карта перевыпущена, договор и счёт обычно не меняются; все карты по одному договору относятся к одному счёту. При смене продукта (например, с дебетовой на кредитную) меняется и счёт — в данных должна храниться актуальная на дату транзакции связь. См. [§2.1](chapter-02-01.md), [§6.2](chapter-06-02.md).

## 2.4.4. Загрузка в DWH: источники и слои

Данные по картам и транзакциям для витрин и отчётности загружаются в хранилище данных из операционных систем. См. [§4.4](chapter-04-04.md), [Глоссарий](glossary.md).

**Источники:**

- **Карточная система (ядро карт):** справочники карт, договоров, счетов; события жизненного цикла (эмиссия, перевыпуск, блокировка); транзакции (авторизация, клиринг, статус).
- **Бухгалтерия:** проводки по счетам клиентов и ссудной задолженности; остатки и обороты по счетам на дату.
- При необходимости — **платёжная система** или процессинг: детали транзакций, коды ответов, данные для сверки с сетью.

**Слои загрузки (обобщённо):**

- **Raw / Staging:** сырые или минимально преобразованные данные из источников (выгрузки транзакций, проводок, справочников) с сохранением ключей и дат.
- **Core:** нормализованные сущности (карта, договор, счёт, клиент) и факты (транзакции) с привязкой ко времени; связь транзакция — карта — договор — счёт; при необходимости снимки на дату.
- **Mart (витрины):** агрегаты для отчётности — обороты по картам за период ([§2.3](chapter-02-03.md)), снимки портфеля карт на дату, витрина транзакций с полными атрибутами для аналитики и антифрода.

Загрузка выполняется по расписанию (ежедневно, ежечасно) или потоково; при пакетной загрузке важна идемпотентность по ключу (ID транзакции, ID проводки), чтобы не дублировать записи при повторном прогоне. См. [§4.4](chapter-04-04.md), [§6.1](chapter-06-01.md).

## 2.4.5. Витрины по картам

На основе загруженных в DWH данных строятся витрины, необходимые для отчётности и аналитики. См. [§2.3](chapter-02-03.md), [§4.2](chapter-04-02.md).

**Витрина «Портфель карт» (снимок на дату):** по каждой карте или договору — продукт, клиент, счёт, статус карты, дата выпуска, при необходимости остаток по счёту (для дебетовой — остаток средств, для кредитной — ссудная задолженность). Используется для отчётов «количество активных карт на дату», «портфель по продуктам», сверки с бухучётом по счетам.

**Витрина «Транзакции» (факты):** полный набор полей по каждой проведённой транзакции (ID, даты авторизации и валютирования, карта, договор, счёт, сумма, валюта, тип, мерчант, MCC, канал, статус). Источник для витрины оборотов, среднего чека, сегментации и антифрода. См. [§2.2](chapter-02-02.md), [§2.3](chapter-02-03.md).

**Витрина «Обороты по картам»:** агрегаты за период (день, месяц) в разрезе договора, продукта, MCC, канала — количество транзакций, сумма оборотов, при необходимости сумма возвратов. Строится из витрины транзакций или из Core; используется для отчётов и дашбордов. См. [§2.3](chapter-02-03.md).

Связь витрин с бухучётом: обороты по витрине «Транзакции» (или «Обороты») в разрезе счёта за период должны совпадать с оборотом по соответствующему счёту из бухучёта; остатки по витрине «Портфель карт» (если хранятся остатки по счёту) — с остатками по счетам. См. [§6.2](chapter-06-02.md).

## 2.4.6. Типичные ошибки

- **Отсутствие связи транзакция — счёт в загрузке:** без неё нельзя сверять обороты по витрине с проводками; связь должна подтягиваться из карточного ядра (карта → договор → счёт) и сохраняться в Core и витринах.
- **Разные даты в транзакциях и в проводках:** проводки формируются по дате валютирования; транзакции в DWH должны иметь ту же дату валютирования для сверки. Если в источнике есть только дата авторизации, дата зачёта должна быть получена из клиринга или из бухучёта.
- **Загрузка без идемпотентности:** повторный запуск пайплайна не должен дублировать транзакции и проводки; ключ обновления — ID транзакции (и при необходимости версия/дата изменения).
- **Витрина оборотов без учёта возвратов:** возвраты должны уменьшать обороты или учитываться отдельным показателем; иначе расхождение с бухучётом (где возврат — обратная проводка) и завышение оборотов в отчётах.

## Ключевое

- **Дебетовая карта:** при проведении операции — дебет счёта клиента (расчётный/текущий), кредит счёта расчётов с платёжной системой (эквайером). **Кредитная карта:** дебет счёта ссудной задолженности по карте, кредит счёта расчётов. Погашение по кредитной карте — как по кредиту: дебет расчётов, кредит ссудной задолженности и счёта доходов по процентам.
- Связь **карта — договор — счёт** обязательна для проводок, сверки оборотов с бухучётом и загрузки в DWH; счёт для дебетовой — расчётный клиента, для кредитной — счёт ссудной задолженности.
- **Загрузка в DWH:** источники — карточное ядро, бухгалтерия; слои Raw/Staging → Core (сущности, транзакции с привязкой к счёту) → витрины (портфель карт, транзакции, обороты). Идемпотентность по ID транзакции.
- **Витрины:** портфель карт (снимок на дату), транзакции (факты с полными полями), обороты по картам (агрегаты за период). Сверка оборотов и остатков по витринам с бухучётом по счетам.

В [§3.1](chapter-03-01.md) мы переходим к платежам и переводам: внутренние и внешние платежи, платёжная система, участники и данные для сверки и отчётности.
