# §10.1 Apache MADlib

В [§9.4](chapter-09-04.md) мы завершили главу о внешних данных (PXF, внешние таблицы). Глава 10 посвящена **in-database аналитике**: выполнение алгоритмов машинного обучения и статистики **внутри** кластера Greenplum, без выгрузки данных во внешние системы. **Apache MADlib** — открытая библиотека масштабируемой аналитики в СУБД; в Greenplum она поставляется как расширение и даёт SQL-функции для регрессии, классификации, кластеризации, описательной и инференциальной статистики, графовых алгоритмов и при необходимости глубокого обучения. В этом разделе — что такое MADlib, **установка** пакета (gppkg) и **включение** в базе (CREATE EXTENSION или madpack), **совместимость** с версиями Greenplum и обзор возможностей. Конкретные алгоритмы и примеры — в [§10.2](chapter-10-02.md) и [§10.3](chapter-10-03.md). По [Tanzu Greenplum 7 — Machine Learning and Deep Learning using MADlib](https://techdocs.broadcom.com/us/en/vmware-tanzu/data-solutions/tanzu-greenplum/7/greenplum-database/analytics-madlib.html), [Apache MADlib — Installation Guide](https://cwiki.apache.org/confluence/display/MADLIB/Installation+Guide).

## 10.1.1. Что такое MADlib и зачем он в Greenplum

**Apache MADlib** — библиотека для **масштабируемой аналитики внутри СУБД**: алгоритмы вызываются через SQL, вычисления выполняются в том же кластере, где хранятся данные. Данные не копируются во внешние системы (R, Python на отдельном сервере); параллелизм обеспечивается движком БД — в Greenplum это MPP: функции MADlib выполняются на сегментах над локальными частями данных. См. [§1.2](chapter-01-02.md), [§1.4](chapter-01-04.md), [Глоссарий](glossary.md).

MADlib входит в «ткань» БД: это не отдельный демон или внешний сервис, а расширение (extension), устанавливаемое в кластер. Администратор разворачивает один раз; пользователи вызывают функции из SQL. Поддерживаются: преобразование и инжиниринг признаков, описательная и инференциальная статистика, контролируемое и неконтролируемое обучение (регрессия, классификация, кластеризация), графовые алгоритмы, кросс-валидация и метрики качества предсказаний. В ряде конфигураций доступны глубокое обучение (Keras, TensorFlow) и интеграция с R через пакет PivotalR. См. документацию MADlib и Greenplum.

Преимущества для больших объёмов: полный параллелизм на всех сегментах, масштабирование добавлением узлов, работа с полным датасетом без выгрузки; интерфейс — привычный SQL. См. [§10.2](chapter-10-02.md), [§10.3](chapter-10-03.md).

## 10.1.2. Совместимость с Greenplum

Поддерживаемые комбинации версий MADlib и Greenplum (и PostgreSQL) приведены в [MADlib FAQ](https://cwiki.apache.org/confluence/display/MADLIB/FAQ) (раздел о поддерживаемых платформах и матрице обновлений). Для Greenplum обычно доступны пакеты MADlib под конкретную мажорную версию (например, MADlib 2.2.0 для Greenplum 7). Перед установкой сверьте совместимость по официальной документации или порталу поставщика. См. документацию Greenplum и MADlib.

**Зависимости:** MADlib требует макропроцессор **m4** (версия 1.4.13 или выше) на каждом хосте кластера. Начиная с MADlib 2.0.0, требуется **Python 3**; он обычно уже устанавливается вместе с Greenplum. Для MADlib 2.2.0 и выше в базе создаётся расширение **plpython3u** (CASCADE при создании расширения madlib). Для глубокого обучения и отдельных модулей (XGBoost, KNN и др.) могут требоваться дополнительные Python-библиотеки; см. документацию MADlib. См. документацию Greenplum.

## 10.1.3. Установка пакета MADlib в кластер

Установка выполняется в два этапа: **установка пакета на все хосты** кластера и **включение функций в каждой базе**, где будет использоваться MADlib.

**Этап 1 — установка пакета.** В Greenplum расширения устанавливаются утилитой **gppkg**. Пакет MADlib (архив вида madlib-2.2.0-gp7-rhel8-x86_64.gppkg.tar.gz или аналог) скачивают с портала поставщика (Broadcom Support Portal для Tanzu Greenplum) для нужной версии Greenplum и ОС. Копируют на хост координатора, под пользователем **gpadmin** выполняют (после source greenplum_path.sh и при заданных GPHOME, COORDINATOR_DATA_DIRECTORY):

```bash
gppkg install ./madlib-2.2.0-gp7-rhel8-x86_64/madlib-2.2.0-gp7-rhel8-x86_64.gppkg.tar.gz
```

gppkg устанавливает пакет на все хосты кластера. Список установленных пакетов: `gppkg --query`. См. документацию Greenplum по gppkg.

**Этап 2 — включение в базе.** Способ зависит от версии MADlib.

- **MADlib 2.2.0 и выше:** в каждой базе, где нужен MADlib, выполняют **CREATE EXTENSION**:

```sql
CREATE EXTENSION madlib CASCADE;
```

CASCADE подтягивает зависимость plpython3u. После этого функции MADlib доступны в схеме **madlib** (например, madlib.linregr_train). См. документацию Greenplum.

- **MADlib 2.1.0 (legacy):** используют утилиту **madpack** (каталог $GPHOME/madlib/bin):

```bash
madpack -s madlib -p greenplum -c gpadmin@mdw:5432/testdb install
```

Опция -s задаёт схему (например, madlib), -p — платформу (greenplum), -c — строку подключения (пользователь@хост:порт/база). Установку проверяют: `madpack -s madlib -p greenplum -c ... install-check`. См. документацию MADlib и Greenplum.

После установки **права:** суперпользователь должен выдать привилегии на схему madlib пользователям, которые будут вызывать функции (GRANT USAGE ON SCHEMA madlib TO роль; GRANT SELECT ON ALL FUNCTIONS IN SCHEMA madlib TO роль; при необходимости ALL PRIVILEGES). Без прав при обращении к функциям MADlib возникает ошибка «permission denied for schema madlib». См. документацию Greenplum.

## 10.1.4. Обзор модулей и пример вызова

MADlib предоставляет набор модулей (групп функций) для разных задач. Основные направления (по документации):

- **Регрессия** — линейная (linregr_train, linregr_predict), логистическая и др.
- **Классификация** — наивный Байес (create_nb_prepared_data_tables, create_nb_classify_view), деревья решений, случайный лес и др.
- **Кластеризация** — k-means и др.
- **Описательная и инференциальная статистика** — сводки, корреляции, тесты.
- **Ассоциативные правила** — assoc_rules (анализ рыночной корзины и т.п.).
- **Графовые алгоритмы** — обход графов, кратчайшие пути и др.
- **Выбор модели** — кросс-валидация, метрики предсказаний.
- **Глубокое обучение** (при установке соответствующих зависимостей) — Keras с бэкендом TensorFlow; опционально с GPU. См. документацию MADlib.

Пример **линейной регрессии** (по документации Greenplum): таблица с зависимой переменной y и признаками x1, x2; обучение модели и сохранение коэффициентов в таблицу; предсказание и остатки:

```sql
-- Таблица с данными
CREATE TABLE regr_example (id int, y int, x1 int, x2 int);
INSERT INTO regr_example VALUES (1, 5, 2, 3), (2, 10, 7, 2), (3, 6, 4, 1), (4, 8, 3, 4);

-- Обучение: модель в regr_example_model
SELECT madlib.linregr_train('regr_example', 'regr_example_model', 'y', 'ARRAY[1, x1, x2]');

-- Предсказание и остатки
SELECT regr_example.*,
       madlib.linregr_predict(ARRAY[1, x1, x2], m.coef) AS predict,
       y - madlib.linregr_predict(ARRAY[1, x1, x2], m.coef) AS residual
FROM regr_example, regr_example_model m;
```

Константа 1 в массиве признаков задаёт свободный член (intercept). Подробнее о регрессии, классификации и статистике — в [§10.2](chapter-10-02.md) и [§10.3](chapter-10-03.md). См. [MADlib User Documentation](http://madlib.apache.org/docs/latest/index.html).

## 10.1.5. PivotalR и удаление MADlib

**PivotalR** — R-пакет для работы с данными в Greenplum и вызова MADlib из R: код на R транслируется в SQL и выполняется в кластере; данные остаются в БД. Удобно для аналитиков, привыкших к R, но с объёмами данных, превышающими возможности одной машины. Требуется установленный MADlib в Greenplum. См. документацию MADlib по PivotalR и CRAN.

**Удаление:** в MADlib 2.2.0+ в базе выполняют `DROP EXTENSION madlib CASCADE;`. В legacy-установках — `madpack -s madlib -p greenplum -c ... uninstall`. Пакет с хостов удаляют: `gppkg remove madlib-2.2.0-gp7-rhel8-x86_64` (имя и версия по факту), затем перезапуск кластера (gpstop -r). Объекты (таблицы, представления), созданные с использованием функций MADlib, после удаления расширения перестанут работать. См. документацию Greenplum.

## Ключевое

- **Apache MADlib** — библиотека in-database аналитики и ML; вызов через SQL, вычисления параллельно на сегментах Greenplum без выгрузки данных.
- **Установка:** пакет через **gppkg** на все хосты; в базе — **CREATE EXTENSION madlib CASCADE** (MADlib 2.2.0+) или **madpack install** (legacy 2.1.0). Требуются m4, Python 3 (2.0+); после установки выдать права на схему madlib.
- **Модули:** регрессия, классификация, кластеризация, статистика, ассоциативные правила, графы, кросс-валидация; опционально глубокое обучение (Keras/TensorFlow). Пример — madlib.linregr_train / linregr_predict.

В [§10.2](chapter-10-02.md) мы разберём **машинное обучение в кластере**: линейная и логистическая регрессия, k-means, распределённое выполнение и хранение моделей.
