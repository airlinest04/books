# §4.3 Утилиты администратора

В [§4.2](chapter-04-02.md) мы разобрали восстановление сегментов (gprecoverseg). Для повседневного управления кластером нужны утилиты **просмотра состояния** и **изменения конфигурации**. В этом разделе — **gpstate** (состояние кластера и сегментов, mirror’ы, Standby), **gpconfig** (просмотр и изменение параметров postgresql.conf на всех инстансах) и кратко **gpcheck** (проверка окружения). Мониторинг и логи — в [§4.4](chapter-04-04.md). По [Tanzu Greenplum 7 — gpstate](https://techdocs.broadcom.com/us/en/vmware-tanzu/data-solutions/tanzu-greenplum/7/greenplum-database/utility_guide-ref-gpstate.html), [gpconfig](https://techdocs.broadcom.com/us/en/vmware-tanzu/data-solutions/tanzu-greenplum/7/greenplum-database/utility_guide-ref-gpconfig.html).

---

## 4.3.1. Общие сведения об утилитах

Утилиты администратора Greenplum находятся в **$GPHOME/bin** и выполняются на **хосте Master** под пользователем **gpadmin** при заданных **GPHOME** и **MASTER_DATA_DIRECTORY** (или COORDINATOR_DATA_DIRECTORY в новых версиях). Они подключаются к Master, читают топологию из системного каталога и при необходимости выполняют действия на сегментах по SSH. Логи по умолчанию пишутся в **~/gpAdminLogs**. Список и описание всех утилит см. в разделе «About the Greenplum Database Utilities» в документации вашего дистрибутива.

---

## 4.3.2. gpstate: просмотр состояния кластера

**gpstate** выводит состояние кластера Greenplum: Master, сегменты, mirror’ы, Standby Master. Полезен для проверки после gpstart/gpstop, для поиска упавших сегментов и для контроля ресинхронизации после gprecoverseg. По [Tanzu Greenplum 7 — gpstate](https://techdocs.broadcom.com/us/en/vmware-tanzu/data-solutions/tanzu-greenplum/7/greenplum-database/utility_guide-ref-gpstate.html).

Основные опции:

| Опция | Назначение |
|-------|------------|
| **-b** (по умолчанию) | Краткая сводка: кластер работает или нет, число сегментов up/down. |
| **-s** | Подробный статус: хосты, каталоги, порты, роли (primary/mirror), preferred role, Mirror Status (Synchronized / Not in Sync), байты до синхронизации и т.д. |
| **-Q** | Быстрая проверка: только данные из системного каталога на Master, без опроса сегментов; подходит для быстрой проверки на down. |
| **-e** | Сегменты с проблемами mirror: пары «не в sync», упавшие сегменты, пары не в предпочтительных ролях. Не показывает пары, уже синхронизированные. Используется после gprecoverseg для контроля ресинхронизации. См. [§4.2](chapter-04-02.md). |
| **-m** | Список mirror-сегментов и их текущая роль. |
| **-c** | Соответствие primary → mirror (маппинг пар). |
| **-f** | Информация о Standby Master (хост, каталог, порт, статус репликации WAL). |
| **-i** | Версия Greenplum на каждом инстансе. |
| **-p** | Список портов, используемых в кластере. |

Примеры:

```bash
gpstate -s    # подробный статус
gpstate -Q    # быстрая проверка по каталогу (есть ли down)
gpstate -e    # проблемы с mirror (Not in Sync, down, не preferred role)
gpstate -f    # Standby Master
```

Если кластер остановлен, gpstate работает в **offline**-режиме и читает данные из файла gpsegconfig_dump; информация может быть неактуальной. См. документацию gpstate.

## 4.3.3. gpconfig: просмотр и изменение параметров

**gpconfig** управляет параметрами **postgresql.conf** на всех инстансах кластера (Master, Standby, сегменты, mirror’ы): просмотр текущих значений, установка и удаление параметров. Изменения записываются в postgresql.conf на каждом узле; для применения части параметров достаточно **перезагрузки конфигурации** (gpstop -u), для остальных нужен **перезапуск** (gpstop -r). По [Tanzu Greenplum 7 — gpconfig](https://techdocs.broadcom.com/us/en/vmware-tanzu/data-solutions/tanzu-greenplum/7/greenplum-database/utility_guide-ref-gpconfig.html).

**Просмотр значения параметра:**

```bash
gpconfig -s parameter_name
```

Вывод показывает значение на координаторе и на сегментах. Значения читаются из БД (текущие действующие), а не только из файла. Для просмотра того, что записано в postgresql.conf (значение после перезапуска), используется опция **--file**:

```bash
gpconfig -s parameter_name --file
```

**Установка параметра:**

```bash
gpconfig -c parameter_name -v value
```

Значение **value** применяется ко всем сегментам, mirror’ам и к Master (и Standby). Для параметров, которые на Master должны отличаться от сегментов (например, **max_connections**), задают отдельное значение для координатора опцией **-m** (или **--coordinatorvalue**):

```bash
gpconfig -c max_connections -v 100 -m 10
```

Только координатор (и Standby) изменить можно опцией **--coordinatoronly** (в сочетании с -c и -v). Список параметров, которыми управляет gpconfig, выводится командой **gpconfig -l**. Параметры вроде **port** или пути к каталогам данных не меняются через gpconfig (они задаются при инициализации). После изменения примените перезагрузку или перезапуск: **gpstop -u** или **gpstop -r** в зависимости от параметра. См. [§4.1](chapter-04-01.md).

**Удаление параметра (восстановление значения по умолчанию):**

```bash
gpconfig -r parameter_name
```

Параметр в postgresql.conf закомментируется на всех инстансах. См. документацию Greenplum по параметрам конфигурации.

## 4.3.4. gpcheck: проверка окружения

Утилита **gpcheck** проверяет окружение кластера: ОС, параметры ядра, сеть, права, наличие необходимых пакетов и т.д. Запускается с указанием hostfile (**-f**) или конкретного хоста (**-h**); может сохранять собранные данные в архив (**--zipout**) и затем проверять другой хост по этому эталону (**--zipin**). Используется при развёртывании и при диагностике расхождений конфигурации между хостами. В части версий Greenplum (например, 6+) **gpcheck помечена как устаревшая** (deprecated) и может быть удалена в будущих релизах; наличие и поведение уточняйте в документации вашей версии. См. справочник утилит вашего дистрибутива.

## 4.3.5. Другие утилиты (кратко)

В $GPHOME/bin есть и другие утилиты, упомянутые в книге или полезные администратору:

- **gpssh**, **gpscp** — выполнение команд и копирование файлов на несколько хостов по hostfile ([§3.1](chapter-03-01.md), [§3.2](chapter-03-02.md)).
- **gpssh-exkeys** — обмен SSH-ключами между хостами для беспарольного доступа ([§3.1](chapter-03-01.md)).
- **gpinitsystem**, **gpstart**, **gpstop**, **gprecoverseg** — инициализация, запуск, остановка, восстановление сегментов (гл. 3, [§4.1](chapter-04-01.md), [§4.2](chapter-04-02.md)).
- **gpexpand** — расширение кластера (добавление хостов/сегментов); см. документацию.
- **gpconfig** — см. выше.

Полный список и опции — в разделе «Utility Guide» документации Greenplum.

## 4.3.6. Типичные ошибки

- **Запускать gpstate/gpconfig не с Master или без MASTER_DATA_DIRECTORY:** утилиты не найдут конфигурацию кластера; задайте переменные и выполняйте на хосте Master.
- **Ожидать немедленного применения параметра после gpconfig -c:** нужно выполнить **gpstop -u** (reload) или **gpstop -r** (restart); иначе старые значения останутся в памяти.
- **Путать gpconfig -s и gpconfig -s --file:** -s показывает текущее действующее значение (из БД), --file — значение в postgresql.conf (которое будет после перезапуска).

## Ключевое

- **gpstate** — состояние кластера: **-b** (кратко), **-s** (подробно), **-Q** (быстро по каталогу), **-e** (проблемы с mirror, Not in Sync), **-m** (mirror’ы), **-c** (primary–mirror маппинг), **-f** (Standby Master).
- **gpconfig** — управление параметрами postgresql.conf на всех инстансах: **-s** (показать), **-c -v** (установить), **-m** (значение только для координатора), **-r** (удалить). После изменения — **gpstop -u** или **gpstop -r**.
- **gpcheck** — проверка окружения (ОС, сеть, пакеты); в ряде версий помечена как устаревшая.

В [§4.4](chapter-04-04.md) мы разберём мониторинг и логи: расположение логов, разбор ошибок и интеграцию с внешним мониторингом.
