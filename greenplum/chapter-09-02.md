# §9.2 Доступ к HDFS и облачным хранилищам

В [§9.1](chapter-09-01.md) мы ввели PXF, коннекторы, серверы и профили. Для работы с внешними данными администратор настраивает **серверы PXF** под каждый источник: HDFS, S3, Azure Blob, Google Cloud Storage, MinIO и др. В этом разделе — **доступ к HDFS** (коннектор, профили, путь в LOCATION, настройка), **доступ к объектным хранилищам** (S3, Azure, GCS, MinIO; профили и обязательный SERVER), и общие принципы **настройки серверов** (конфигурационные файлы, синхронизация). Примеры CREATE EXTERNAL TABLE — в [§9.4](chapter-09-04.md). По [Tanzu Greenplum PXF — Accessing Hadoop](https://techdocs.broadcom.com/us/en/vmware-tanzu/data-solutions/tanzu-greenplum-platform-extension-framework/6-10/gp-pxf/access_hdfs.html), [Accessing Azure, GCS, and S3-Compatible Object Stores](https://techdocs.broadcom.com/us/en/vmware-tanzu/data-solutions/tanzu-greenplum-platform-extension-framework/6-10/gp-pxf/access_objstore.html), [Configuring PXF Servers](https://techdocs.broadcom.com/us/en/vmware-tanzu/data-solutions/tanzu-greenplum-platform-extension-framework/6-10/gp-pxf/cfg_server.html).

## 9.2.1. Коннектор HDFS и профили

PXF поставляется с коннектором к **Hadoop (HDFS)**. Он совместим с дистрибутивами Cloudera, Hortonworks (HDP) и с обычным Apache Hadoop. Доступ к данным в HDFS выполняется так: сегмент обращается к PXF Service на своём хосте; PXF запрашивает метаданные файла у **NameNode** (HDFS Java API), выделяет воркеру «долю» данных на основе gp_segment_id и блоков файла, читает данные с **DataNode**(ов) и передаёт строки сегменту. Несколько сегментов работают параллельно, каждый со своей частью данных. См. документацию PXF.

**Профили для HDFS** задают формат данных. Имена в виде **hdfs:***формат*. Основные:

- **hdfs:text**, **hdfs:csv** — текст с разделителем (одна строка — одна запись); чтение и запись.
- **hdfs:parquet**, **hdfs:orc**, **hdfs:avro** — колоночные и бинарные форматы; чтение и запись. См. [§9.3](chapter-09-03.md).
- **hdfs:json**, **hdfs:fixedwidth**, **hdfs:text:multi**, **hdfs:SequenceFile**, **hdfs:AvroSequenceFile** и др. — по документации PXF.

В **LOCATION** для HDFS указывают **абсолютный путь** к файлу или каталогу в HDFS, например: `pxf://data/pxf_examples/file.txt?PROFILE=hdfs:text`. Для HDFS можно использовать сервер **default** (если он настроен на кластер Hadoop), тогда SERVER= в LOCATION можно не указывать. Для таблиц **Hive** используются профили **hive**, **hive:text**, **hive:orc**, **hive:rc** и др.; в пути указывают имя таблицы Hive (схема.таблица). Для **HBase** — профиль **hbase**. См. документацию PXF по Hadoop.

**Предварительные условия:** синхронизация времени между хостами Greenplum и Hadoop; при включённом **user impersonation** (по умолчанию для Hadoop) каждому пользователю Greenplum должны быть выданы права на чтение (и при записи — на запись) соответствующих путей в HDFS от имени этого пользователя; иначе доступ под учётной записью gpadmin. Конфигурация Hadoop (core-site.xml, hdfs-site.xml и при необходимости yarn-site.xml, mapred-site.xml) копируется с кластера Hadoop в каталог сервера PXF — модифицировать шаблоны PXF для Hadoop не предполагается. См. подраздел 9.2.3 и документацию PXF по настройке Hadoop-коннектора.

## 9.2.2. Объектные хранилища: S3, Azure, GCS, MinIO

PXF включает коннекторы к **объектным хранилищам**:

- **AWS S3** и S3-совместимые (MinIO, Dell ECS);
- **Azure Blob Storage** (профили **wasbs:***формат*);
- **Azure Data Lake** (профили **adl:***формат*);
- **Google Cloud Storage** (профили **gs:***формат*).

Поддерживаемые форматы те же, что для HDFS: текст, CSV, Parquet, ORC, Avro, JSON, SequenceFile и др. Для каждого хранилища в документации приведена таблица профилей (например, s3:text, s3:parquet, wasbs:text, gs:orc). См. документацию PXF.

**Важно:** при обращении к объектному хранилищу в LOCATION внешней таблицы **необходимо указывать SERVER=** — имя настроенного сервера PXF. Сервер по умолчанию (default) для объектных хранилищ тоже нужно явно настроить и тогда указывать SERVER=default при желании использовать его.

**Путь в LOCATION** зависит от хранилища:

- **S3:** бакет и префикс/путь к объекту, например `pxf://my-bucket/dir/file.parquet?PROFILE=s3:parquet&SERVER=s3srvcfg`.
- **Azure Blob (wasbs):** контейнер и учётная запись в виде `контейнер@учётная_запись.blob.core.windows.net/путь/к/объекту`.
- **Azure Data Lake (adl):** имя учётной записи ADL и путь: `учётная_запись.azuredatalakestore.net/путь/к/файлу`.
- **GCS:** путь к объекту в бакете (профиль gs:*, сервер с конфигурацией GCS).

Учётные данные (ключи доступа, токены) задаются в конфигурации **сервера** (см. ниже); для S3 часть параметров можно переопределять опциями в LOCATION (accesskey, secretkey и др. — по документации). См. документацию PXF по объектным хранилищам.

## 9.2.3. Настройка серверов PXF

**Сервер PXF** — это именованный каталог в **$PXF_BASE/servers/***имя_сервера*/. В нём лежат конфигурационные файлы в формате **-site.xml** (например, s3-site.xml, wasbs-site.xml, core-site.xml для HDFS). Набор свойств зависит от коннектора. См. [Глоссарий](glossary.md) (Сервер PXF).

**Шаблоны** конфигов поставляются в каталоге **templates/** при установке PXF (adl-site.xml, core-site.xml, gs-site.xml, hdfs-site.xml, s3-site.xml, wasbs-site.xml и др.). Для **объектных хранилищ** и **JDBC** администратор копирует нужный шаблон в каталог нового сервера и подставляет значения (ключи доступа, URL, имена учётных записей). Для **Hadoop** шаблоны не подставляют «как есть»: конфиги **копируют с кластера Hadoop** (core-site.xml, hdfs-site.xml и т.д.) в каталог сервера PXF. См. документацию PXF.

Пример для **S3**: в s3-site.xml задают `fs.s3a.access.key`, `fs.s3a.secret.key` (и при необходимости endpoint для S3-совместимых хранилищ). Для **Azure Blob** в wasbs-site.xml — параметры учётной записи и доступа. Для **Azure Data Lake** в adl-site.xml — OAuth2-параметры (client id, refresh URL, credential). Учётные данные в файлах хранятся в открытом виде; права на каталог серверов должны ограничивать доступ. См. документацию PXF по безопасности.

**Файл pxf-site.xml** в каталоге сервера задаёт параметры самого PXF: базовый путь к файлам (pxf.fs.basePath), **user impersonation** (pxf.service.user.impersonation), при работе с Kerberos — principal и keytab. Для HDFS при включённом impersonation запросы к внешней таблице выполняются от имени пользователя Greenplum; для объектных хранилищ и NFS эти опции не применяются. См. документацию PXF.

После добавления или изменения конфигурации сервера конфигурацию **синхронизируют** на все хосты кластера командой **pxf cluster sync** (или аналогом в вашей версии PXF). До синхронизации новые или изменённые серверы на сегментах не видны. См. руководство по PXF.

**Пользовательская конфигурация** (per-user): в каталоге сервера можно создать файл *имя_пользователя_GREENPLUM*-user.xml с переопределением учётных данных или параметров для конкретной роли Greenplum. Это удобно для JDBC (разные логины к внешней БД) и при необходимости разных ключей к одному хранилищу. Приоритет: опции в LOCATION внешней таблицы перекрывают настройки сервера; настройки в *-user.xml перекрывают настройки по умолчанию в сервере. См. документацию PXF.

## 9.2.4. Общие требования и типичные ошибки

- **Синхронизация времени:** между хостами Greenplum и внешней системой (Hadoop, S3, Azure) время должно быть синхронизировано (NTP и т.п.), иначе аутентификация и подпись запросов могут отклоняться.
- **Права доступа:** для HDFS при user impersonation пользователь БД должен иметь права на чтение/запись путей в HDFS; для объектных хранилищ ключи и роли должны разрешать доступ к бакету/контейнеру и объектам по указанному пути.
- **Указание SERVER для объектных хранилищ:** в LOCATION для S3, Azure, GCS обязательно указывать SERVER=; иначе запрос к внешней таблице завершится ошибкой.
- **Пересинхронизация после изменения серверов:** после правки файлов в $PXF_BASE/servers/ выполнять pxf cluster sync (или перезапуск PXF по документации), иначе сегменты будут использовать старую конфигурацию.

## Ключевое

- **HDFS:** коннектор PXF, профили hdfs:text, hdfs:parquet, hdfs:orc и др.; в LOCATION — абсолютный путь в HDFS; конфиги копируют с кластера Hadoop; при user impersonation нужны права пользователя Greenplum в HDFS.
- **Объектные хранилища (S3, Azure, GCS, MinIO):** профили s3:*, wasbs:*, adl:*, gs:*; в LOCATION **обязательно** SERVER=; учётные данные и параметры — в конфигурации сервера (*-site.xml в $PXF_BASE/servers/имя/).
- **Настройка сервера:** каталог $PXF_BASE/servers/имя/, конфиги *-site.xml (из шаблонов или с Hadoop); после изменений — **pxf cluster sync**.

В [§9.3](chapter-09-03.md) мы разберём **форматы данных**: Parquet, ORC, Avro — чтение колоночных форматов, predicate pushdown и выбор формата.
