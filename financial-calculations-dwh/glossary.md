# Глоссарий

Термины книги «Финансовые расчёты в DWH и SQL» в порядке появления.

---

**Округление суммы** (rounding of sum) — способ получения итога: сначала вычисляется сумма всех слагаемых (с полной или внутренней точностью), затем **один раз** округляется полученная сумма до заданного знака (например, до копеек). См. [§1.1](chapter-01-01.md).

**Сумма округлённых** (sum of rounded) — способ получения итога: каждое слагаемое **сначала** округляется до заданной точности, затем складываются уже округлённые значения. Итог может не совпадать с округлением суммы. См. [§1.1](chapter-01-01.md).

**Расхождение** (в контексте округления) — разница между суммой округлённых значений и округлением суммы по тем же данным; следствие накопления погрешностей округления по строкам. См. [§1.1](chapter-01-01.md).

**DWH** (Data Warehouse, хранилище данных) — система хранения и обработки данных для отчётности и аналитики; в контексте книги — место, где хранятся и агрегируются финансовые данные (обороты, остатки, витрины). См. [§1.1](chapter-01-01.md).

**Отчёт с округлением по строкам** — отчёт, в котором каждая строка выводится с ограниченной точностью (до копеек, до целых и т.д.); итог, посчитанный как сумма этих видимых значений (сумма округлённых), может не совпадать с округлением общей суммы. См. [§1.2](chapter-01-02.md).

**Допустимая погрешность** — зафиксированная в правилах граница расхождения (например, не более 1 коп. на документ или не более 0,01% от итога), в пределах которой расхождение между суммой округлённых и округлением суммы считается приемлемым; используется при сверках и алертах. См. [§1.3](chapter-01-03.md).

**Бизнес-правило** (в контексте округления и погрешности) — явно сформулированное правило: как считается итог, где и как округляются значения, какая погрешность допускается и что делать при сверке; закладывается в расчёты, тесты и регламенты. См. [§1.3](chapter-01-03.md).

**Стратегия округления** — выбранный способ получения итога: округление только итога (итог = округление суммы) или округление по строкам (итог = сумма округлённых); от стратегии зависят реализация расчётов и правила сверки. См. [§1.4](chapter-01-04.md).

**Компенсация** (погрешности округления) — приём распределения расхождения между суммой округлённых по строкам и заданным итогом по одной или нескольким строкам (например, добавление копейки к последней строке), чтобы сумма округлённых в точности совпала с итогом. См. [§1.4](chapter-01-04.md), [§3.4](chapter-03-04.md).

**NUMERIC / DECIMAL** — типы данных с точным десятичным представлением и фиксированной точностью (precision) и масштабом (scale); используются для денежных сумм и процентов, чтобы избежать погрешности двоичного представления. В стандарте SQL и в СУБД обычно эквивалентны. См. [§2.1](chapter-02-01.md).

**Точность (precision)** — для NUMERIC/DECIMAL: общее число значащих десятичных цифр (до и после запятой). См. [§2.1](chapter-02-01.md).

**Масштаб (scale)** — для NUMERIC/DECIMAL: число десятичных знаков после запятой; задаёт минимальный шаг (например, 0,01 при scale = 2 для копеек). См. [§2.1](chapter-02-01.md).

**FLOAT / DOUBLE (DOUBLE PRECISION)** — типы данных с двоичным представлением с плавающей точкой (IEEE 754); ограниченная разрядность мантиссы приводит к тому, что многие десятичные дроби (0,1; 0,2; 0,01) не представимы точно. Для денежных сумм не используются. См. [§2.2](chapter-02-02.md).

**NUMBER** (Oracle) — тип данных Oracle с точным десятичным представлением; синтаксис NUMBER(precision, scale). Эквивалентен NUMERIC/DECIMAL в PostgreSQL по смыслу; при миграции заменяется на NUMERIC(p, s). См. [§2.4](chapter-02-04.md).

**Арифметическое округление** — округление до ближайшего значения с заданной точностью (до целых, до N знаков после запятой); при дробной части ровно 0,5 применяется дополнительное правило (половинка вверх или к чётному). См. [§3.1](chapter-03-01.md).

**ROUND** — функция SQL для арифметического округления; ROUND(value, n) — до n знаков после запятой (n может быть отрицательным). В Oracle (NUMBER) и PostgreSQL (NUMERIC) половинка округляется от нуля (вверх у положительных). См. [§3.1](chapter-03-01.md), [§8.1](chapter-08-01.md).

**Банковское округление** (round half to even) — правило для 0,5: округлять к ближайшему чётному; в Oracle используется для ROUND над BINARY_FLOAT/BINARY_DOUBLE; для денег в NUMERIC/NUMBER в Oracle и PostgreSQL по умолчанию — половинка вверх. См. [§3.1](chapter-03-01.md).

**TRUNC** — функция SQL: отсечение дробной части в сторону нуля (без округления); может задаваться число знаков после запятой. TRUNC(−2.5) = −2. См. [§3.2](chapter-03-02.md), [§8.1](chapter-08-01.md).

**FLOOR** — функция SQL: округление вниз до ближайшего меньшего или равного целого. FLOOR(−2.5) = −3. См. [§3.2](chapter-03-02.md).

**CEIL / CEILING** — функция SQL: округление вверх до ближайшего большего или равного целого. В Oracle — CEIL, в PostgreSQL — CEILING. См. [§3.2](chapter-03-02.md).

**Остаток на последнюю строку** — приём компенсации при распределении суммы по строкам с округлением: первым \(n-1\) строкам присваивается округлённая базовая доля, последней (в заданном порядке) — значение, при котором сумма по строкам в точности равна общей сумме. См. [§3.3](chapter-03-03.md).

**Остаток (при компенсации)** — разница между целевой суммой \(S\) и суммой округлённых долей по строкам (в копейках, целое число); распределяется по выбранному правилу компенсации (одной строке, по приоритету, итеративно). См. [§3.4](chapter-03-04.md).

**Оборот за период** — сумма проводок (движений) по счёту за заданный интервал дат; отдельно считают оборот по дебету и оборот по кредиту; используется для расчёта остатков и отчётности. См. [§4.1](chapter-04-01.md).

**Остаток на дату (сальдо на дату)** — состояние счёта на выбранную дату: начальное сальдо плюс оборот за период от начальной даты до целевой; для знакового сальдо используют дебет минус кредит (или наоборот по типу счёта). См. [§4.2](chapter-04-02.md).

**Нарастающий итог** (cumulative sum, running total) — сумма числового поля по текущей и всем предыдущим строкам в заданном порядке; в SQL реализуется оконной функцией SUM(...) OVER (PARTITION BY ... ORDER BY ...). См. [§4.3](chapter-04-03.md).

**Оконная функция** — агрегатная или ранжирующая функция с предложением OVER (PARTITION BY ... ORDER BY ... [рамка]); не сводит строки, а добавляет колонку со значением по «окну». Используется для нарастающего итога, остатков по проводкам, оборотов с накоплением. См. [§4.4](chapter-04-04.md), [§8.4](chapter-08-04.md).

**Процент от суммы** — расчёт по формуле база × ставка (ставка в долях или в % с делением на 100); база и ставка в NUMERIC; округление применяют к результату (сумме в деньгах), выбор момента округления (по строкам или только итог) — по стратегии из главы 1. См. [§5.1](chapter-05-01.md).

**Комиссия** — плата за операцию: фиксированная сумма или процент от объёма; может ограничиваться минимумом и максимумом; хранится и считается в NUMERIC, округление до копеек по регламенту. См. [§5.2](chapter-05-02.md).

**Удержание** — сумма, удерживаемая из выплаты (налог, комиссия и т.д.); расчёт как база × ставка или фиксированная сумма; округление и эталон итога согласуют с регламентом. См. [§5.2](chapter-05-02.md).

**Налог (расчёт в DWH)** — сумма налога = база × ставка; база и ставка хранятся в NUMERIC; округление результата — по правилам законодательства (до копеек или до целых рублей). Итог по документу может считаться от общей базы или как сумма округлённых по строкам. См. [§5.3](chapter-05-03.md).

**Сходимость итогов** — согласованность суммы рассчитанных по строкам значений (проценты, комиссии, налог) с расчётной суммой (общая база × ставка, округление один раз); проверка — сравнение с допустимой погрешностью; при превышении порога — алерт или разбор. См. [§5.4](chapter-05-04.md).

**Звёздная схема** (star schema) — модель данных DWH: фактовая таблица в центре, таблицы измерений связаны с ней по ключам; запросы строятся от факта с JOIN к измерениям. См. [§6.1](chapter-06-01.md).

**Схема «снежинка»** (snowflake) — вариант звёздной схемы с нормализованными измерениями (иерархии в отдельных таблицах); больше JOIN, меньше дублирования. См. [§6.1](chapter-06-01.md).

**Фактовая таблица** — таблица фактов в DWH: строки — события или операции (например, проводки); колонки — ключи измерений и меры (суммы, количества). См. [§6.1](chapter-06-01.md), [§6.2](chapter-06-02.md).

**Измерение** (dimension) — справочник в DWH (счёт, контрагент, дата, продукт и т.д.), связанный с фактом по ключу; используется для группировки, фильтрации и вывода атрибутов. См. [§6.1](chapter-06-01.md), [§6.3](chapter-06-03.md).

**Транзакционный факт** — таблица фактов, в которой одна строка = одно событие (проводка, операция); append-only. Источник для расчёта оборотов и остатков. См. [§6.2](chapter-06-02.md).

**Периодический снимок** (periodic snapshot) — таблица фактов: одна строка = состояние на конец периода (например, остаток по счёту на дату); заполняется регулярно. См. [§6.2](chapter-06-02.md).

**Накопительный снимок** (accumulating snapshot) — таблица фактов: одна строка = один объект, обновляется при смене этапов жизненного цикла; для оборотов/остатков по счетам применяется редко. См. [§6.2](chapter-06-02.md).

**SCD** (Slowly Changing Dimension) — приёмы хранения истории изменений атрибутов измерения: Type 1 (обновление на месте), Type 2 (новая строка с valid_from/valid_to), Type 3 (текущее и предыдущее значение). Для счёта и контрагента часто используют Type 2. См. [§6.3](chapter-06-03.md).

**Raw** — слой DWH: неизменённая копия данных из источника; проводки попадают сюда первыми; не используется для расчётов. См. [§6.4](chapter-06-04.md).

**Staging** — слой DWH: подготовка к загрузке в Core (приведение типов, очистка, NUMERIC для денег); обороты и остатки не считают. См. [§6.4](chapter-06-04.md).

**Core** — слой DWH: факт проводок, снимки, измерения; здесь считаются обороты и остатки; источник истины. См. [§6.4](chapter-06-04.md).

**Mart** (витрина) — слой DWH: данные для отчётов, денормализованы под отчётность; читаются из Core; не эталон при сверке. См. [§6.4](chapter-06-04.md).

**Сверка** (reconciliation, реконсиляция) — сравнение двух наборов данных по ключам и мерам с целью убедиться в согласованности или зафиксировать расхождения; выполняется между системами, между способами расчёта или между срезами данных. См. [§7.1](chapter-07-01.md).

**Ключи сверки** — набор полей, по которым сопоставляют записи между двумя источниками (например, posting_id, document_id + line_no, период + счёт для агрегатов); должны быть стабильными и общими для обеих сторон. См. [§7.2](chapter-07-02.md).

**Проверка баланса** — проверка равенства суммы дебетов и суммы кредитов по выборке проводок (период, документ); нарушение указывает на ошибку в данных. См. [§7.3](chapter-07-03.md).

**Контрольная сумма** — агрегат по выборке (COUNT, SUM поля, хеш) для проверки целостности или совпадения с эталоном; при расхождении — алерт. См. [§7.3](chapter-07-03.md).

**Алертинг** — автоматическое уведомление (email, мессенджер, тикет) при срабатывании условия (расхождение выше порога, нарушение баланса); содержание и получатели задаются регламентом. См. [§7.4](chapter-07-04.md).

**Эскалация** — передача инцидента (расхождение при сверке) на следующий уровень при невозможности устранить или объяснить в рамках первичного разбора; правила и фиксация результата — в регламенте. См. [§7.4](chapter-07-04.md).

**Идемпотентность** (пайплайна загрузки) — свойство: повторный прогон с теми же входными параметрами (период, ключи) даёт тот же результат и не создаёт дублей записей и не искажает итоги; достигается за счёт UPSERT по ключу и фиксированных границ периода. См. [§9.3](chapter-09-03.md).

**UPSERT** — операция «вставка или обновление»: при совпадении ключа строка обновляется, при отсутствии — вставляется; в PostgreSQL — INSERT ... ON CONFLICT ... DO UPDATE, в Oracle — MERGE; используется при загрузке в витрину и в Core для идемпотентности. См. [§9.3](chapter-09-03.md).

**Пайплайн** (в контексте DWH) — цепочка шагов загрузки и обработки данных (Raw → Staging → Core → Mart); в книге — пайплайн финансовых расчётов: загрузка проводок, расчёт оборотов и остатков, загрузка в витрину, сверка. См. [§9.1](chapter-09-01.md).
