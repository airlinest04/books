# §3.2 TRUNC, FLOOR, CEIL и банковское округление

В [§3.1](chapter-03-01.md) мы разобрали арифметическое округление (ROUND) и правило для половинки. Иногда нужно не «ближайшее», а **жёстко отсечь** дробную часть, **округлить вниз** или **вверх**. Для этого в SQL служат функции **TRUNC** (отсечение), **FLOOR** (вниз) и **CEIL**/CEILING (вверх). Здесь мы разберём их поведение, в том числе для отрицательных чисел, когда какую применять и как при необходимости **реализовать банковское округление** (round half to even) вручную. Синтаксис в Oracle и PostgreSQL — в [§8.1](chapter-08-01.md).

---

## 3.2.1. TRUNC: отсечение дробной части

**TRUNC** (truncate) — отсечение дробной части **в сторону нуля**: дробная часть отбрасывается без округления. Результат по модулю не превышает исходное число.

Для положительных чисел TRUNC совпадает с округлением вниз до целого: TRUNC(2.7) = 2, TRUNC(2.3) = 2. Для отрицательных — с округлением «вверх» по оси: TRUNC(−2.7) = −2, TRUNC(−2.3) = −2 (ближе к нулю, а не «вниз» в математическом смысле).

Во многих СУБД TRUNC допускает второй аргумент — число знаков после запятой: отсекаются знаки **после** указанной позиции. Например, TRUNC(33.336, 2) = 33.33 (не 33.34: именно отсечение, без округления). Это полезно, когда по правилу нужно **не округлять**, а отбрасывать лишние разряды (например, расчёт по ставке с точностью до 4 знаков, а в отчёт — только 2 знака без округления). См. [Глоссарий](glossary.md).

| Значение | TRUNC(..., 0) | ROUND(..., 0) |
|----------|---------------|---------------|
| 2.3      | 2             | 2             |
| 2.5      | 2             | 3             |
| 2.7      | 2             | 3             |
| −2.5     | −2            | −3 (от нуля)  |

---

## 3.2.2. FLOOR: округление вниз

**FLOOR** — округление **до ближайшего меньшего или равного целого** (вниз по числовой оси). Для положительных: FLOOR(2.7) = 2, FLOOR(2.3) = 2. Для отрицательных: FLOOR(−2.3) = −3, FLOOR(−2.7) = −3 (вниз — в сторону минус бесконечности).

FLOOR не путать с TRUNC для отрицательных чисел: FLOOR(−2.3) = −3, TRUNC(−2.3) = −2.

Применение: когда нужно «не больше X» в целых единицах (например, число полных периодов), деление с округлением вниз (целочисленное деление), расчёт порогов «не более N». В PostgreSQL для округления вниз до N знаков после запятой используют, например, FLOOR(value * 100) / 100 для двух знаков; в Oracle есть FLOOR для числа, для знаков после запятой — комбинация с умножением/делением на степень 10 или TRUNC. См. [§8.1](chapter-08-01.md).

---

## 3.2.3. CEIL / CEILING: округление вверх

**CEIL** (в Oracle) и **CEILING** (в PostgreSQL и стандарте SQL) — округление **до ближайшего большего или равного целого** (вверх по числовой оси). CEIL(2.3) = 3, CEIL(2.7) = 3; CEIL(−2.3) = −2, CEIL(−2.7) = −2.

Применение: «не менее N» в целых единицах, расчёт «сколько нужно блоков» (например, 2.1 блока → 3), верхние границы. Для округления до копеек вверх иногда используют формулу через CEIL: например, CEIL(value * 100) / 100 — но нужно учитывать поведение с отрицательными суммами (комиссия, удержание): по бизнес-правилу может требоваться «вверх по модулю» или разное поведение для знака.

---

## 3.2.4. Сравнение TRUNC, FLOOR, CEIL для отрицательных чисел

Для положительных чисел TRUNC и FLOOR до целого дают один результат; для отрицательных — разный.

| Значение | TRUNC | FLOOR | CEIL/CEILING | ROUND |
|----------|-------|-------|--------------|-------|
| 2.5      | 2     | 2     | 3            | 3     |
| −2.5     | −2    | −3    | −2           | −3 (Oracle/PostgreSQL: от нуля) |

При расчётах с отрицательными суммами (возвраты, удержания, кредитовые остатки в знаковой конвенции) важно зафиксировать в бизнес-правиле: округляем «от нуля», «вниз» или «отсекаем» — и выбирать ROUND, FLOOR или TRUNC соответственно.

---

## 3.2.5. Когда что применять

| Задача | Функция | Пример |
|--------|---------|--------|
| Округлить до копеек «к ближайшему», половинка вверх | ROUND(x, 2) | Суммы в отчёте по общему правилу |
| Отбросить дробную часть без округления (до целых или до N знаков) | TRUNC(x [, n]) | Промежуточный расчёт без накопления округления |
| Округлить вниз до целого (или до N знаков через умножение/деление) | FLOOR(x) | Число полных периодов, целочисленное деление |
| Округлить вверх до целого (или до N знаков) | CEIL/CEILING(x) | «Не менее N единиц» |
| Банковское округление (половинка к чётному) | Нет встроенной в Oracle/PostgreSQL для NUMERIC; реализовать выражением | По отраслевому стандарту |

В финансовых расчётах чаще всего используют **ROUND(..., 2)** для итоговых сумм в копейках; **TRUNC(..., 2)** — когда нужно явно отсечь лишние знаки без округления. FLOOR и CEIL — по требованию (расчёт периодов, пороги, специальные правила для комиссий). См. [§5.2](chapter-05-02.md), [§8.1](chapter-08-01.md).

## 3.2.6. Реализация банковского округления (round half to even)

В Oracle для NUMBER и в PostgreSQL для NUMERIC встроенная ROUND даёт «половинка вверх», а не «к чётному». Если по регламенту требуется **банковское округление** (round half to even) до N знаков, его нужно реализовать явно.

Идея: округлить до N знаков; если отброшенная часть ровно 0,5 (5·10⁻⁽ⁿ⁺¹⁾) и результат после обычного ROUND даёт нечётную цифру в последнем разряде — «откатить» на один шаг вниз (для положительных). Упрощённый вариант до целых: если дробная часть = 0.5 и FLOOR(x) нечётный, то результат FLOOR(x); иначе ROUND(x). Для произвольного N выражение сложнее; часто используют логику:

- Вычислить ROUND(x, n) и промежуточное «сырое» значение с лишним знаком.
- Проверить, попали ли мы ровно в «половинку» (остаток ровно 0,5·10⁻ⁿ) и чётна ли последняя сохраняемая цифра; при нечётной и половинке заменить на округление вниз для этого разряда.

Пример для округления до целых (PostgreSQL, идея; для отрицательных и до N знаков логику расширяют):

```sql
-- Упрощённо: банковское до целых для положительных
CASE
  WHEN x - FLOOR(x) = 0.5 AND MOD(FLOOR(x)::int, 2) = 1
  THEN FLOOR(x)  -- нечётное и половинка -> вниз
  ELSE ROUND(x)
END
```

В реальных запросах учитывают отрицательные числа и масштаб (умножение на 10^n, работа с целыми, деление обратно). Если банковское округление требуется только в части отчётов, часто выносят его в одну функцию (PL/SQL или PL/pgSQL) и вызывают из SQL. См. [Глоссарий](glossary.md) (банковское округление).

## 3.2.7. Типичные ошибки

- **Путать TRUNC и FLOOR для отрицательных:** при отрицательных суммах (возвраты, кредит) результат разный; выбирать по правилу.
- **Считать, что CEIL везде «добавить копейку»:** для отрицательных CEIL(−1.1) = −1; для «комиссии вверх до копеек» нужно явно формулировать правило (по модулю вверх или по знаку).
- **Подразумевать банковское округление по умолчанию:** в Oracle/PostgreSQL для NUMERIC ROUND даёт половинку вверх; банковское — только для Oracle BINARY_FLOAT/DOUBLE или при явной реализации.

---

## Ключевое

- **TRUNC** — отсечение дробной части в сторону нуля (без округления); может быть до N знаков после запятой; для отрицательных TRUNC(−2.5) = −2.
- **FLOOR** — округление вниз (к меньшему целому); FLOOR(−2.5) = −3; **CEIL/CEILING** — вверх; CEIL(−2.5) = −2.
- Для **денег** чаще всего ROUND(..., 2) или TRUNC(..., 2); FLOOR/CEIL — когда правило явно требует «вниз»/«вверх» (периоды, пороги, комиссии).
- **Банковское округление** (round half to even) в Oracle/PostgreSQL для NUMERIC нет встроенного; при необходимости реализуют выражением или функцией; в Oracle по умолчанию оно только для BINARY_FLOAT/BINARY_DOUBLE.

В [§3.3](chapter-03-03.md) мы разберём задачу распределения суммы по строкам с округлением (например, 100 на 3 строки по 33.33) и порядок строк.
