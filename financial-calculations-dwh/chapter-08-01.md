# §8.1 ROUND, TRUNC, CEIL, FLOOR

В [§7.4](chapter-07-04.md) мы завершили главу о сверке и алертах. В главе 8 собраны **SQL-паттерны** для финансовых расчётов в Oracle и PostgreSQL. Здесь — **синтаксис функций округления**: ROUND, TRUNC, CEIL, FLOOR в обеих СУБД, округление до N знаков после запятой и до целых (включая десятки, сотни при отрицательном втором аргументе). Семантика и выбор стратегии округления разобраны в [§3.1](chapter-03-01.md) и [§3.2](chapter-03-02.md). Агрегация с округлением — в [§8.2](chapter-08-02.md). См. [Глоссарий](glossary.md).

---

## 8.1.1. ROUND в Oracle и PostgreSQL

**Oracle:** `ROUND(n [, m])` — n число, m целое: число десятичных знаков. Если m опущен, m = 0 (до целых). При m &lt; 0 округление влево от запятой: ROUND(12345, -2) = 12300.

**PostgreSQL:** `ROUND(x [, n])` или с двумя аргументами для типа numeric — `ROUND(x, n)`. x — выражение, n — число знаков после запятой (по умолчанию 0). Отрицательное n — округление до десятков, сотен: ROUND(12345, -2) = 12300.

Для денег до копеек: **ROUND(сумма, 2)** в обеих СУБД. Тип аргумента — NUMERIC (или NUMBER в Oracle); результат того же типа. Половинка округляется от нуля ([§3.1](chapter-03-01.md)). Среда: Oracle 21c, PostgreSQL 15.

Примеры (одинаковая логика):

```sql
-- Oracle
SELECT ROUND(33.335, 2) FROM DUAL;   -- 33.34
SELECT ROUND(33.334, 2) FROM DUAL;   -- 33.33
SELECT ROUND(12345.67, -2) FROM DUAL; -- 12300

-- PostgreSQL
SELECT ROUND(33.335::numeric, 2);    -- 33.34
SELECT ROUND(33.334::numeric, 2);    -- 33.33
SELECT ROUND(12345.67::numeric, -2); -- 12300
```

## 8.1.2. TRUNC в Oracle и PostgreSQL

**Oracle:** `TRUNC(n [, m])` — отсечение без округления. m — число знаков после запятой (по умолчанию 0). TRUNC(33.336, 2) = 33.33; TRUNC(33.336, 0) = 33. TRUNC(-2.5, 0) = -2 (к нулю).

**PostgreSQL:** `TRUNC(x [, n])` — то же: отсечение до n знаков. TRUNC(33.336, 2) = 33.33. Для отрицательных: TRUNC(-2.5, 0) = -2.

В обеих СУБД второй аргумент может быть отрицательным: TRUNC(12345.67, -2) = 12300 (отсечение до сотен). См. [§3.2](chapter-03-02.md).

Примеры:

```sql
-- Oracle
SELECT TRUNC(33.336, 2) FROM DUAL;  -- 33.33
SELECT TRUNC(-2.5, 0) FROM DUAL;   -- -2

-- PostgreSQL
SELECT TRUNC(33.336::numeric, 2);  -- 33.33
SELECT TRUNC(-2.5::numeric, 0);    -- -2
```

## 8.1.3. FLOOR и CEIL / CEILING

**FLOOR(x)** — округление вниз до целого (или до целого в типе). В Oracle и PostgreSQL синтаксис один: FLOOR(число). Для округления вниз до двух знаков: FLOOR(x * 100) / 100 (в обеих СУБД при работе с numeric).

**CEIL / CEILING:** в **Oracle** функция называется **CEIL**; в **PostgreSQL** и стандарте SQL — **CEILING**. Обе возвращают наименьшее целое >= аргумента. CEIL(2.3) = 3, CEIL(-2.3) = -2.

Примеры:

```sql
-- Oracle
SELECT FLOOR(2.7) FROM DUAL;    -- 2
SELECT CEIL(2.3) FROM DUAL;     -- 3

-- PostgreSQL
SELECT FLOOR(2.7);              -- 2
SELECT CEILING(2.3);            -- 3
```

Округление до копеек вверх (для комиссий «не менее»): в PostgreSQL CEILING(amount * 100) / 100; в Oracle CEIL(amount * 100) / 100. См. [§3.2](chapter-03-02.md), [§5.2](chapter-05-02.md).

---

## 8.1.4. Отрицательный второй аргумент (округление до разряда)

При **втором аргументе &lt; 0** ROUND и TRUNC округляют/отсекают **влево от запятой**: до десятков (-1), сотен (-2), тысяч (-3) и т.д.

| Выражение           | ROUND(..., -2) | TRUNC(..., -2) |
|---------------------|----------------|----------------|
| 12345.67            | 12300          | 12300          |
| 12545.67            | 12600          | 12500          |

В финансовых отчётах иногда требуется округление до рублей (т.е. до 0 знаков после запятой) или до тысяч: ROUND(сумма, 0), ROUND(сумма, -3). В Oracle и PostgreSQL поведение согласовано для NUMERIC/NUMBER. См. [§2.4](chapter-02-04.md).

---

## 8.1.5. Сводка синтаксиса

| Функция    | Oracle              | PostgreSQL     | До N знаков (N ≥ 0)     | До целых / разряда (N ≤ 0) |
|------------|---------------------|----------------|--------------------------|----------------------------|
| ROUND      | ROUND(n [, m])      | ROUND(x [, n]) | Второй аргумент = N      | Второй аргумент = 0 или отрицательный |
| TRUNC      | TRUNC(n [, m])      | TRUNC(x [, n]) | То же                    | То же                      |
| FLOOR      | FLOOR(n)            | FLOOR(x)       | Через FLOOR(x*10^N)/10^N | По умолчанию              |
| CEIL/CEILING | CEIL(n)           | CEILING(x)     | Через CEIL(x*10^N)/10^N  | По умолчанию              |

Для денег в копейках достаточно ROUND(..., 2) или TRUNC(..., 2); типы операндов — NUMERIC/NUMBER ([§2.3](chapter-02-03.md), [§2.4](chapter-02-04.md)). См. [Глоссарий](glossary.md).

---

## 8.1.6. Типичные ошибки

- **Путать CEIL и CEILING между СУБД:** в Oracle только CEIL, в PostgreSQL только CEILING; при миграции заменить имя функции.
- **Передавать FLOAT в ROUND/TRUNC для денег:** результат может быть с погрешностью; сначала привести к NUMERIC: ROUND(amount::numeric, 2) в PostgreSQL, ROUND(CAST(amount AS NUMBER(18,2)), 2) в Oracle при amount из float-колонки.
- **Забыть приведение типа в PostgreSQL:** литерал 33.335 по умолчанию может быть double precision; для предсказуемого округления использовать 33.335::numeric или колонку типа numeric.

---

## Ключевое

- **ROUND(x, n)** в Oracle и PostgreSQL: округление до n знаков (n &gt; 0 — после запятой, n &lt; 0 — до десятков/сотен); половинка от нуля. Для копеек: ROUND(сумма, 2).
- **TRUNC(x, n)** — отсечение без округления; синтаксис совпадает с ROUND по второму аргументу в обеих СУБД.
- **FLOOR** — вниз, **CEIL** (Oracle) / **CEILING** (PostgreSQL) — вверх; для округления до N знаков используют умножение/деление на 10^N.
- Операнды для денег — NUMERIC/NUMBER; при миграции Oracle → PostgreSQL заменить CEIL на CEILING.

В [§8.2](chapter-08-02.md) мы разберём агрегацию с округлением: SUM(ROUND(...)) vs ROUND(SUM(...)) и когда что применять.
