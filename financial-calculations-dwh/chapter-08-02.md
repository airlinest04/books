# §8.2 Агрегация с округлением

В [§8.1](chapter-08-01.md) мы разобрали синтаксис ROUND, TRUNC, CEIL, FLOOR. При расчёте **итогов по группе** (оборот по счёту, сумма процентов по документу) важно, **где** применяется округление: к каждой строке до суммирования или к итогу после SUM. Здесь мы разберём разницу между **SUM(ROUND(...))** и **ROUND(SUM(...))**, когда какой вариант даёт нужный результат и как сочетать с GROUP BY. Связь с темой «сумма округлённых vs округление суммы» — в [§1.1](chapter-01-01.md); полный пример распределения по строкам — в [§8.3](chapter-08-03.md). См. [Глоссарий](glossary.md).

---

## 8.2.1. SUM(ROUND(...)) — сумма округлённых

Если округление применяется **к каждой строке**, а затем считается сумма, в SQL это выражается как **SUM(ROUND(выражение, 2))** (или с подзапросом/CTE, где в подзапросе уже округлённая колонка). Результат — **сумма округлённых** по строкам группы. См. [§1.1](chapter-01-01.md).

Пример: процент от суммы по строкам, итог = сумма округлённых процентов.

```sql
-- PostgreSQL
SELECT
    document_id,
    SUM(ROUND(amount * 0.12, 2)) AS total_pct_sum_of_rounded
FROM lines
GROUP BY document_id;
```

В Oracle то же: SUM(ROUND(amount * 0.12, 2)). Итог может на копейку отличаться от ROUND(SUM(amount * 0.12), 2) по той же группе. Выбор стратегии — по регламенту ([§1.4](chapter-01-04.md), [§5.1](chapter-05-01.md)). Среда: Oracle 21c, PostgreSQL 15.

---

## 8.2.2. ROUND(SUM(...)) — округление суммы

Если нужно **сначала просуммировать**, затем **один раз округлить** итог, в SQL пишут **ROUND(SUM(выражение), 2)**. Результат — **округление суммы** по группе. См. [§1.1](chapter-01-01.md).

Пример: итог процентов по документу как округление общей суммы процентов.

```sql
-- PostgreSQL
SELECT
    document_id,
    ROUND(SUM(amount * 0.12), 2) AS total_pct_round_of_sum
FROM lines
GROUP BY document_id;
```

Такой итог совпадает с ROUND(общая_база_по_документу * 0.12, 2), если общая база по документу = SUM(amount) по той же группе. Для сверки с «процентом от общей базы» эталоном часто берут именно ROUND(SUM(...), 2). См. [§5.4](chapter-05-04.md).

---

## 8.2.3. Когда что даёт

| Цель итога                         | Выражение в SQL              | Результат          |
|------------------------------------|------------------------------|--------------------|
| Сумма округлённых по строкам       | SUM(ROUND(expr, 2))          | Сумма округлённых  |
| Округление суммы по группе         | ROUND(SUM(expr), 2)          | Округление суммы   |
| Оба в одном запросе (для сверки)   | SUM(ROUND(...)), ROUND(SUM(...)) | Оба значения, сравнить |

Не смешивать в одном поле: в одной колонке SELECT должен быть либо SUM(ROUND(...)), либо ROUND(SUM(...)), в зависимости от выбранной стратегии ([§1.4](chapter-01-04.md)). Для проверки сходимости можно вывести обе величины и разницу в одном запросе. См. [§5.4](chapter-05-04.md).

---

## 8.2.4. Группировка и округление

При **GROUP BY** каждая группа даёт одну строку; агрегат (SUM, ROUND(SUM(...)) или SUM(ROUND(...))) считается **внутри группы**. Округление до копеек по группе — всегда явное: либо ROUND(SUM(...), 2), либо SUM(ROUND(..., 2)). Округление **по строкам внутри группы** перед суммированием — SUM(ROUND(..., 2)); округление **только итога группы** — ROUND(SUM(..., 2)). См. [§4.1](chapter-04-01.md) (обороты за период), [§4.4](chapter-04-04.md).

Пример: обороты по счёту за месяц, итог в копейках (округление суммы по счёту).

```sql
-- PostgreSQL
SELECT
    account_id,
    ROUND(SUM(amount_dt), 2) AS turnover_dt,
    ROUND(SUM(amount_ct), 2) AS turnover_ct
FROM core.fact_postings
WHERE post_date >= DATE '2025-01-01'
  AND post_date <= DATE '2025-01-31'
GROUP BY account_id;
```

Если бы хранили округлённые по каждой проводке суммы и хотели «сумму округлённых», использовали бы SUM(ROUND(amount_dt, 2)); обычно проводки хранят в копейках, и SUM уже даёт точную сумму; ROUND(SUM(...), 2) тогда совпадает с SUM при точном хранении. См. [§2.3](chapter-02-03.md).

---

## 8.2.5. Типичные ошибки

- **Путать порядок:** ROUND(SUM(...)) и SUM(ROUND(...)) дают разный результат; выбирать по регламенту и не подставлять одно вместо другого «для красоты».
- **Округлять дважды:** например, ROUND(SUM(ROUND(..., 2)), 2) — внутреннее округление уже ограничило точность; второе округление избыточно, если не задано особое правило.
- **Считать, что SUM(ROUND(..., 2)) всегда «неправильно»:** для отчётов с самосогласованностью (итог = сумма видимых по строкам) как раз нужна сумма округлённых; «неправильно» — несоответствие выбранной стратегии.

---

## Ключевое

- **SUM(ROUND(expr, 2))** — сумма округлённых по строкам группы; итог может на копейку отличаться от округления суммы.
- **ROUND(SUM(expr), 2)** — округление суммы по группе; один раз округлённый итог.
- Выбор по стратегии ([§1.4](chapter-01-04.md)): самосогласованный отчёт (сумма по строкам = итог) → SUM(ROUND(...)); эталон «процент от общей базы» → ROUND(SUM(...)).
- В одном запросе можно вычислить оба варианта для проверки сходимости ([§5.4](chapter-05-04.md)); при группировке округление применяют явно к агрегату или к выражению внутри SUM.

В [§8.3](chapter-08-03.md) мы разберём полный пример: распределение суммы по строкам с округлением и остатком на последнюю строку (CTE, оконные функции).
