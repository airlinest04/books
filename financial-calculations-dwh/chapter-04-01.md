# §4.1 Обороты за период

В [§3.4](chapter-03-04.md) мы завершили главу об округлении и компенсации. Теперь переходим к **финансовым агрегациям в SQL**: обороты, остатки и нарастающий итог. В этом разделе — **обороты за период**: что такое оборот по дебету и кредиту, как считать их суммой проводок за выбранный период и как строить запросы с GROUP BY по счёту и периоду с фильтрацией по дате. Остатки на дату и нарастающий итог — в [§4.2](chapter-04-02.md) и [§4.3](chapter-04-03.md); паттерны и оконные функции — в [§4.4](chapter-04-04.md).

---

## 4.1.1. Что такое оборот за период

**Оборот за период** — это сумма **движений** (проводок) по счёту (или по группе счетов, контрагентов и т.д.) за заданный интервал времени: с даты начала по дату конца периода включительно. В бухгалтерском учёте обычно разделяют **оборот по дебету** и **оборот по кредиту**: сумма проводок, прошедших по дебету счёта, и сумма проводок по кредиту. Разница между ними (дебет минус кредит или наоборот в зависимости от типа счёта) участвует в расчёте **остатка** на конец периода. См. [Глоссарий](glossary.md).

В DWH проводки чаще всего хранятся в таблице фактов: каждая строка — одна проводка с полями «счёт», «дата», «сумма дебет», «сумма кредит» (или «сумма» и «признак дебет/кредит»). Оборот за период по счёту — это SUM(сумма) по строкам, попадающим в период и в выбранную группу (счёт, контрагент, продукт и т.д.), с разбивкой по дебету/кредиту при необходимости.

---

## 4.1.2. Модель данных: проводки и периоды

Типичная структура для расчёта оборотов:

- **Таблица проводок (фактов):** идентификатор счёта (или счёт + контрагент + продукт), дата проводки, сумма по дебету, сумма по кредиту. Иногда одна колонка «сумма» и признак «тип» (дебет/кредит) или знак (положительный = дебет, отрицательный = кредит).
- **Период:** интервал дат (например, с 2025-01-01 по 2025-01-31 для января). Оборот считается только по проводкам, у которых дата **в пределах** этого интервала (включительно или по правилу «день открытия/закрытия» — зависит от регламента).

Пример схемы (минимально):

| Поле        | Тип         | Описание                    |
|-------------|-------------|-----------------------------|
| account_id  | INT / VARCHAR | Счёт (или ключ измерения)   |
| post_date   | DATE        | Дата проводки               |
| amount_dt   | NUMERIC(18,2) | Сумма по дебету             |
| amount_ct   | NUMERIC(18,2) | Сумма по кредиту            |

По регламенту может быть: одна проводка — одна строка с ненулевым дебетом или кредитом; либо одна строка с обоими полями. Для оборотов важна сумма по каждому направлению за период. Денежные поля — NUMERIC, см. [§2.1](chapter-02-01.md)–[§2.3](chapter-02-03.md).

## 4.1.3. Оборот по счёту за период: GROUP BY

Оборот по каждому счёту за период получают агрегацией: группировка по счёту (и при необходимости по периоду, если период задан параметром) и суммирование дебета и кредита.

Пример (PostgreSQL, среда: таблица `ledger.postings` с полями `account_id`, `post_date`, `amount_dt`, `amount_ct`):

```sql
SELECT
    account_id,
    SUM(amount_dt) AS turnover_dt,
    SUM(amount_ct) AS turnover_ct
FROM ledger.postings
WHERE post_date >= DATE '2025-01-01'
  AND post_date <= DATE '2025-01-31'
GROUP BY account_id;
```

Параметры периода можно передавать переменными (bind-параметры, подстановка в ETL). В Oracle синтаксис дат свой (`TO_DATE`, интервалы); логика та же: фильтр по дате, GROUP BY по счёту, SUM по дебету и кредиту. См. [§8.4](chapter-08-04.md) для вариантов с оконными функциями.

Если период задаётся не датами, а, например, номером месяца и годом, в запросе добавляют фильтр по году и месяцу:

```sql
WHERE EXTRACT(YEAR FROM post_date) = 2025
  AND EXTRACT(MONTH FROM post_date) = 1
```

или по предвычисленному полю `period_id` (год-месяц), если оно есть в таблице. Группировка по периоду внутри запроса (чтобы получить обороты по нескольким периодам сразу) — добавить в GROUP BY поле периода (например, `DATE_TRUNC('month', post_date)` в PostgreSQL или аналог в Oracle).

## 4.1.4. Оборот по периоду и по группировкам

Часто нужны обороты **по нескольким периодам** (все месяцы года) и по счёту. Тогда в GROUP BY включают и счёт, и период.

Пример (PostgreSQL): обороты по счёту по месяцам 2025 года.

```sql
SELECT
    account_id,
    DATE_TRUNC('month', post_date)::DATE AS period_month,
    SUM(amount_dt) AS turnover_dt,
    SUM(amount_ct) AS turnover_ct
FROM ledger.postings
WHERE post_date >= DATE '2025-01-01'
  AND post_date <  DATE '2026-01-01'
GROUP BY account_id, DATE_TRUNC('month', post_date)
ORDER BY account_id, period_month;
```

В Oracle аналог для «начало месяца»: `TRUNC(post_date, 'MM')`. Итог: каждая строка — один счёт и один месяц, обороты по дебету и кредиту за этот месяц. Агрегация по дате выполняется один раз; для расчёта остатков и нарастающего итога по этим оборотам см. [§4.2](chapter-04-02.md) и [§4.3](chapter-04-03.md).

---

## 4.1.5. Фильтрация по дате и границы периода

Правило «включительно» или «исключительно» для границ периода нужно зафиксировать. Часто используют:

- **Включительно обе границы:** `post_date >= :date_from AND post_date <= :date_to` — проводки за оба крайних дня входят в оборот.
- **Включительно начало, исключительно конец:** `post_date >= :date_from AND post_date < :date_to + INTERVAL '1 day'` (или `post_date < :date_to_next`) — удобно при задании периода «месяц» как первого и последнего дня: не нужно думать о числе дней в месяце.

Учёт времени (timestamp): если поле хранит время, проводка с датой 2025-01-31 23:59 может относиться к январю или к февралю по регламенту. Обычно для оборотов используют **дату** (DATE), без времени, или явно определяют «дата проводки = календарная дата операции». Консистентность с витринами и отчётами — в регламенте.

---

## 4.1.6. Округление оборотов

Суммы проводок в DWH должны храниться в NUMERIC с масштабом до копеек ([§2.3](chapter-02-03.md)). Оборот — сумма таких полей; при SUM в SQL результат остаётся в том же типе, округление не применяется автоматически. Если в отчёте или витрине нужны обороты **округлённые** до копеек (или до рублей), округление делают явно при выборке: `ROUND(SUM(amount_dt), 2)`. При этом помним про разницу «сумма округлённых» и «округление суммы» ([§1.1](chapter-01-01.md)): если проводки уже в копейках, SUM даёт точную сумму; округлять итог нужно по выбранной стратегии ([§1.4](chapter-01-04.md)).

---

## 4.1.7. Типичные ошибки

- **Дублирование проводок:** если одна и та же проводка попадает в выборку дважды (из-за JOIN без ограничения уникальности), оборот завысится. Проверять ключ таблицы фактов и условия JOIN.
- **Разные границы периода в разных местах:** в одном отчёте период «включительно», в другом «исключительно конец» — обороты за один и тот же месяц могут различаться на граничный день. Фиксировать правило в регламенте.
- **Использование FLOAT для сумм проводок:** приводит к погрешности при SUM; см. [§2.2](chapter-02-02.md), [§2.3](chapter-02-03.md).

---

## Ключевое

- **Оборот за период** — сумма проводок (движений) по счёту за заданный интервал дат; отдельно считают оборот по дебету и по кредиту.
- В SQL обороты получают **GROUP BY** по счёту (и при необходимости по периоду), **SUM** по полям дебет/кредит и **фильтр по дате** (BETWEEN или >= / <= с учётом включения границ).
- Границы периода (включительно/исключительно) и тип поля даты (DATE vs timestamp) нужно зафиксировать в регламенте для согласованности с остатками и отчётами.
- Суммы проводок и оборотов хранить и считать в **NUMERIC**; округление итога — по бизнес-правилу, явно (ROUND при выводе).

В [§4.2](chapter-04-02.md) мы разберём расчёт остатков на дату: сальдо на конец периода через начальное сальдо и обороты.
