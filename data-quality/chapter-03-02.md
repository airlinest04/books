# §3.2 Статистики и распределения

В [§3.1](chapter-03-01.md) мы ввели профилирование данных и разделили анализ на структуру и содержимое. Содержимое описывается **статистиками** (агрегаты по полям) и **распределениями** (как значения размазаны по диапазону или по категориям). В этом разделе мы разберём базовый набор показателей для профиля: COUNT, MIN, MAX, AVG для числовых полей; гистограммы и разбиение на интервалы; частоту значений (кардинальность, топ значений); паттерны и длину строк. Примеры запросов даны для PostgreSQL; логика применима к другим СУБД. Детекция null, дубликатов и выбросов — в [§3.3](chapter-03-03.md); сводные запросы профилирования — в [§3.4](chapter-03-04.md).

---

## 3.2.1. Базовые агрегаты: COUNT, MIN, MAX, AVG

Для **числовых** полей профиль обычно включает:

| Агрегат | Назначение |
|---------|------------|
| **COUNT(*)** | Общее число строк в таблице или срезе. |
| **COUNT(column)** | Число не-null значений по полю; разница с COUNT(*) даёт число пропусков (см. §3.3). |
| **MIN(column), MAX(column)** | Минимальное и максимальное значение; задают фактический диапазон данных и помогают выявить выбросы (значения далеко от основной массы). |
| **AVG(column)** | Среднее арифметическое; ориентир для сравнения с типичным значением; при сильных выбросах среднее может быть нерепрезентативным. |

Дополнительно при необходимости: **SUM(column)** для суммовых полей (сверка с ожидаемым итогом); **STDDEV(column)** или **VAR_POP(column)** для разброса (высокий разброс и большие отклонения от среднего — повод проверить выбросы). Для **даты** — MIN/MAX задают фактический временной диапазон; разница между MAX и текущей датой даёт «возраст» последних данных.

Пример: сводка по числовому полю `amount` и полю даты `order_date` (PostgreSQL):

```sql
SELECT COUNT(*) AS total_rows,
       COUNT(amount) AS amount_filled,
       MIN(amount) AS amount_min,
       MAX(amount) AS amount_max,
       AVG(amount) AS amount_avg,
       MIN(order_date) AS date_min,
       MAX(order_date) AS date_max
FROM staging.orders
WHERE load_date = CURRENT_DATE - 1;
```

По результату видно объём среза, заполненность `amount`, фактический диапазон сумм и дат; отклонения MIN/MAX/AVG от ожиданий подсказывают, где искать аномалии. См. [Глоссарий](glossary.md).

## 3.2.2. Гистограммы и разбиение на интервалы

**Гистограмма** — разбиение диапазона значений на интервалы (корзины, buckets) и подсчёт числа значений в каждом интервале. Показывает **форму распределения**: сосредоточены ли данные в одном участке, есть ли длинный хвост, несколько пиков. Для профилирования гистограмму строят запросом: задают границы интервалов (или вычисляют их от MIN/MAX) и считают COUNT по группам.

Пример: разбить `amount` на интервалы 0–1000, 1001–10000, 10001–100000, > 100000 (PostgreSQL):

```sql
SELECT CASE
         WHEN amount <= 1000 THEN '0-1000'
         WHEN amount <= 10000 THEN '1001-10000'
         WHEN amount <= 100000 THEN '10001-100000'
         ELSE '100001+'
       END AS bucket,
       COUNT(*) AS cnt
FROM staging.orders
WHERE load_date = CURRENT_DATE - 1 AND amount IS NOT NULL
GROUP BY 1
ORDER BY MIN(amount);
```

По результату видно, в каких диапазонах сосредоточены суммы; пустые или аномально большие корзины указывают на выбросы или особенности данных. Границы интервалов можно задать по домену (например, типичные суммы операций) или вычислить от MIN/MAX с равной шириной (width_bucket в PostgreSQL или аналог в других СУБД). Гистограмма по датам (по дням, неделям) показывает распределение активности по времени и пропуски периодов.

## 3.2.3. Частота значений и кардинальность

Для **категориальных** и **строковых** полей (коды, статусы, регионы) важны:

- **Кардинальность** — число уникальных значений в поле: `COUNT(DISTINCT column)`. Низкая кардинальность при большом числе строк (например, 3 значения на 1 млн строк) — мало категорий; высокая (близко к COUNT(*)) — почти каждое значение уникально (идентификаторы, хеши).
- **Частота значений** — сколько раз встречается каждое значение: GROUP BY column, COUNT(*). Топ-N самых частых и самые редкие значения показывают доминирующие коды и возможные опечатки или «мусорные» значения.
- **Доля по значению** — COUNT(*) по значению / COUNT(*) по таблице в процентах; помогает оценить баланс категорий и выявить значения с аномально малой долей.

Пример: топ-10 значений по полю `status` и число уникальных статусов (PostgreSQL):

```sql
SELECT status, COUNT(*) AS cnt,
       ROUND(100.0 * COUNT(*) / SUM(COUNT(*)) OVER (), 2) AS pct
FROM staging.orders
WHERE load_date = CURRENT_DATE - 1
GROUP BY status
ORDER BY cnt DESC
LIMIT 10;
```

Отдельно — общая кардинальность:

```sql
SELECT COUNT(DISTINCT status) AS distinct_statuses
FROM staging.orders
WHERE load_date = CURRENT_DATE - 1;
```

Редкие значения (низкий cnt или малая pct) могут быть легитимными (редкий статус) или ошибочными (опечатка, тестовое значение); их перечень полезен для принятия решений о валидации и справочниках (глава 4). См. [Глоссарий](glossary.md).

## 3.2.4. Паттерны и длина строк

Для **строковых** полей кроме частоты значений полезно анализировать **паттерны** и **длину**:

- **Длина строки:** MIN(LENGTH(column)), MAX(LENGTH(column)), AVG(LENGTH(column)) — выявление пустых строк (длина 0 при не-null), аномально длинных или коротких значений, единообразие длины (например, коды фиксированной длины).
- **Паттерн (шаблон):** группировка по признаку формата — например, «только цифры», «буквы и цифры», «содержит пробелы». В PostgreSQL можно использовать упрощённые проверки: `column ~ '^[0-9]+$'` (только цифры), `column ~ '^[A-Z]{3}$'` (ровно 3 заглавные буквы). Подсчёт по группам «соответствует шаблону / не соответствует» даёт долю значений в ожидаемом формате.
- **Начальные/конечные пробелы:** COUNT(*) WHERE LENGTH(column) <> LENGTH(TRIM(column)) — число значений с лишними пробелами; такие значения могут мешать сопоставлению и джойнам.

Пример: длина и доля «только цифры» для поля `contract_no` (PostgreSQL):

```sql
SELECT COUNT(*) AS total,
       MIN(LENGTH(contract_no)) AS len_min,
       MAX(LENGTH(contract_no)) AS len_max,
       COUNT(*) FILTER (WHERE contract_no ~ '^[0-9]+$') AS digits_only_cnt,
       ROUND(100.0 * COUNT(*) FILTER (WHERE contract_no ~ '^[0-9]+$') / NULLIF(COUNT(*), 0), 2) AS digits_only_pct
FROM staging.contracts
WHERE load_date = CURRENT_DATE - 1 AND contract_no IS NOT NULL;
```

Результат помогает сформулировать правило валидации (формат, максимальная длина) и решить, нужна ли очистка (TRIM, приведение регистра) в ETL. Подробнее правила формата — в [§4.2](chapter-04-02.md).

## 3.2.5. Сводка показателей для профиля

В таблице ниже сведены типы показателей и для каких полей они обычно применяются.

| Показатель | Числовые | Даты | Строки/категории |
|------------|----------|------|-------------------|
| COUNT(*), COUNT(column) | да | да | да |
| MIN, MAX, AVG | да | да (мин/макс даты) | да (длина: MIN/MAX/AVG LENGTH) |
| Гистограмма (интервалы) | да | да (по дням/неделям) | по длине или по категориям |
| Кардинальность (COUNT DISTINCT) | при необходимости | при необходимости | да |
| Частота значений (GROUP BY, топ-N) | при небольшой кардинальности | по дате/периоду | да |
| Паттерны (regex, TRIM) | — | формат даты | да |

Комбинация этих показателей даёт содержательный профиль содержимого; на его основе задают правила полноты, валидности и диапазоны для проверок. В §3.4 мы соберём примеры сводных запросов профилирования по таблице целиком.

## 3.2.6. Типичные ошибки

- **Опираться только на AVG при асимметричном распределении:** при выбросах среднее смещено; дополнительно смотреть MIN, MAX и гистограмму, при необходимости медиану или перцентили.
- **Не учитывать null при подсчёте долей:** доля «валидных» по формату считать от COUNT(column) или явно оговаривать, что знаменатель — все строки; иначе проценты могут вводить в заблуждение.
- **Задавать интервалы гистограммы без учёта домена:** равные по ширине интервалы могут дать пустые корзины или одну переполненную; для профилирования часто полезнее доменные границы (типичные диапазоны сумм, периодов).
- **Игнорировать длину и паттерны строк:** без проверки длины и формата можно пропустить смешение форматов (дата в разных видах, код с лишними символами) и не заложить правила валидации.

## Ключевое

- **Базовые статистики** для профиля: COUNT(*), COUNT(column), MIN, MAX, AVG по полям; для дат — диапазон MIN/MAX; при необходимости SUM, STDDEV.
- **Гистограммы** — разбиение на интервалы и подсчёт по корзинам; показывают форму распределения и выявляют выбросы и пустые диапазоны.
- **Частота значений:** кардинальность (COUNT DISTINCT), топ-N по частоте, доля по значению; для категориальных и кодов — основа для справочников и выявления редких/аномальных значений.
- **Паттерны и длина строк:** MIN/MAX/AVG LENGTH, доля значений по шаблону (regex), подсчёт записей с пробелами (TRIM); используются для правил формата и очистки.
- Набор показателей выбирается по типу поля (число, дата, строка); результат профиля — вход для правил валидации (глава 4) и для анализа null, дубликатов и выбросов (§3.3).

В [§3.3](chapter-03-03.md) мы разберём **null, дубликаты и выбросы**: доля null по полям, детекция дубликатов по ключу и выявление выбросов (статистических и доменных).
