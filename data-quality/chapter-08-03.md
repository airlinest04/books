# §8.3 Связь со сверкой и реконсиляцией

В [§8.2](chapter-08-02.md) мы разобрали проверки на каждом слое и деградацию качества по цепочке. Проверки «совпадает ли результат с ожиданием» опираются на **сверку** (сравнение агрегатов и при необходимости ключей или строк между двумя наборами данных) и в предметной области учёта и финансов — на **реконсиляцию**. В этом разделе мы покажем **связь качества данных в DWH со сверкой и реконсиляцией**: сверка между слоями, сверка источник — витрина и отсылку к книге серии по финансовым расчётам. Качество витрин и отчётов — в [§8.4](chapter-08-04.md). См. [Глоссарий](glossary.md).

---

## 8.3.1. Сверка между слоями

**Сверка между слоями** — сравнение агрегатов (и при необходимости списков ключей) на границах соседних слоёв: убедиться, что при переходе Raw → Staging → Core → Mart не произошло потерь или искажений в объёме и суммах. На каждой границе есть «источник» (данные, ушедшие из предыдущего слоя или переданные на загрузку) и «приёмник» (данные после загрузки в следующий слой); контрольные итоги источника фиксируются и сравниваются с итогами приёмника ([§5.1](chapter-05-01.md), [§5.3](chapter-05-03.md), [§5.4](chapter-05-04.md)).

Типичные точки сверки:

| Граница | Эталон | Что сравниваем в приёмнике | Выявляет |
|---------|--------|----------------------------|----------|
| Raw → Staging | Row count (и при необходимости суммы) по принятому срезу в Raw | Row count после чтения из Raw и преобразования; при наличии отклонений эталон для загрузки в Staging — число валидных записей ([§5.2](chapter-05-02.md)). | Потерю записей при чтении или преобразовании; эталон для следующей границы. |
| Staging → Core | Row count и суммы по валидным записям, переданным на загрузку в Core | Row count и суммы в таблицах Core после загрузки. | Потерю или дублирование при загрузке в Core. |
| Core → Mart | Агрегаты по Core (или регламентные эталоны) для витрины | Контрольные итоги витрины (Mart). | Ошибки при построении витрины; расхождение витрины с Core. |

Сверка между слоями — это те же контрольные итоги и сравнение с эталоном ([§4.4](chapter-04-04.md)), применённые на границах DWH. Эталон на каждой границе должен быть зафиксирован в момент «выхода» данных из предыдущего слоя (или после валидации на Staging); при расхождении — алерт и разбор. См. [Глоссарий](glossary.md).

## 8.3.2. Сверка источник — витрина

**Сверка источник — витрина** — сравнение данных в витрине (Mart) с данными в **системе-источнике** за один и тот же срез (дата, партиция, ключ выгрузки). Цель — убедиться, что цепочка от источника до витрины не внесла потерь и искажений с точки зрения бизнеса: объём, суммы, ключевые агрегаты совпадают.

Эталон для такой сверки — агрегаты, полученные **по источнику** в момент извлечения (или по согласованному срезу источника). С ними сравнивают агрегаты по витрине за тот же срез. Уровни сверки те же, что в [§5.4](chapter-05-04.md): агрегаты (COUNT, SUM), при необходимости — множества ключей (пропущенные или лишние в витрине), при расследовании — построчное сравнение. Важно: сравнивать нужно **один и тот же срез** и **один и тот же момент** эталона (эталон, зафиксированный при извлечении, а не «текущее состояние источника», которое могло измениться). При наличии отклонений при преобразовании (часть записей в кварантине) эталон для витрины — не исходный объём источника, а объём и суммы **после валидации** ([§5.4](chapter-05-04.md)); иначе расхождение будет смешано с ожидаемой разницей из‑за отклонённых записей. См. [Глоссарий](glossary.md).

## 8.3.3. Реконсиляция и книга серии по финансовым расчётам

**Реконсиляция** (reconciliation) в узком смысле — процесс сопоставления двух наборов данных (например, оборотов и остатков по счетам между учётной системой и DWH или между двумя системами) с выявлением расхождений и их разбором. В контексте качества данных те же приёмы: контрольные итоги, сверка по агрегатам и ключам, фиксация эталона и реакция на расхождение. В **финансовой и регуляторной** отчётности реконсиляция — обязательный элемент контроля: регламентные сроки, допустимые расхождения, отчётность по несовпадениям, связь с первичными документами и балансом дебет/кредит.

В серии предусмотрены книги по **финансовым расчётам в DWH** и по **сверке (реконсиляции)**. В них подробно разбираются:

- Регламентная сверка: периодичность, объём (счета, операции), эталоны и допустимые расхождения.
- Реконсиляция по счетам и проводкам: сопоставление оборотов и остатков между системами.
- Контрольные итоги в учёте: баланс дебет/кредит, сверка с первичными документами, связь с регуляторикой.
- Автоматизация сверки и отчётность по расхождениям.

Здесь, в книге по качеству данных, мы используем **общие приёмы** (контрольные суммы, сверка между слоями, источник — витрина) как часть проверок в ETL и по слоям DWH; углубление в предметную область учёта и реконсиляции — в указанных книгах серии. См. [Глоссарий](glossary.md).

## 8.3.4. Типичные ошибки

- **Сверять по разным срезам или в разное время:** эталон источника и выборка по приёмнику должны относиться к одному срезу (дата, партиция); эталон — зафиксированный на момент извлечения, иначе расхождение может быть из‑за обновления источника ([§5.4](chapter-05-04.md)).
- **Сравнивать витрину с полным объёмом источника при наличии отклонений на Staging:** эталон для витрины — объём и суммы после валидации (валидные записи); иначе «расхождение» включает ожидаемую разницу из‑за кварантина.
- **Не документировать правила сверки:** какие поля входят в контрольную сумму, какой допуск, периодичность и ответственные — должны быть зафиксированы в регламенте.

## Ключевое

- **Сверка между слоями** — сравнение контрольных итогов на границах Raw → Staging → Core → Mart; эталон на каждой границе фиксируется при «выходе» из предыдущего слоя (после валидации на Staging); при расхождении — алерт и разбор.
- **Сверка источник — витрина** — сравнение агрегатов витрины с эталоном по источнику за один срез; эталон — на момент извлечения; при отклонениях на Staging эталон для витрины — итоги по валидным записям.
- **Реконсиляция** — сопоставление двух наборов с выявлением расхождений; в учёте и финансах — регламентный процесс; приёмы те же (контрольные суммы, сверка); детали — в книгах серии по финансовым расчётам и по сверке.

В [§8.4](chapter-08-04.md) мы разберём **качество витрин и отчётов**: проверки перед потреблением, контрольные итоги и регрессию.
