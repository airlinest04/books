# §8.3 Распределение суммы по строкам (пример)

В [§8.2](chapter-08-02.md) мы разобрали агрегацию с округлением. Здесь — **полный пример на SQL**: распределить заданную сумму (например, 100) по строкам с округлением до копеек так, чтобы сумма по строкам **в точности** равнялась общей сумме. Используем приём «остаток на последнюю строку» из [§3.3](chapter-03-03.md): первые \(n-1\) строк получают округлённую базовую долю, последняя — остаток. Реализация на **CTE** и **оконных функциях** (ROW_NUMBER, COUNT) в PostgreSQL и Oracle. Алгоритмы компенсации в общем виде — в [§3.4](chapter-03-04.md). См. [Глоссарий](glossary.md).

---

## 8.3.1. Постановка

Дано: таблица строк (например, позиции документа) с уникальным ключом для порядка (id); общая сумма \(S = 100\). Требуется: каждой строке присвоить сумму в копейках (до двух знаков), сумма по строкам = 100. Равное распределение: базовая доля \(S/n\), округлённая до копеек; остаток на последнюю строку в заданном порядке. См. [§3.3](chapter-03-03.md).

---

## 8.3.2. Алгоритм в одном запросе

1. Нумеруем строки **детерминированно** (ORDER BY id): ROW_NUMBER() OVER (ORDER BY id).
2. Считаем число строк в наборе: COUNT(*) OVER () — одно и то же значение во всех строках.
3. Базовая доля: \(d_0 = \mathrm{ROUND}(S / n, 2)\) (в SQL: ROUND(100.00 / n, 2), тип numeric).
4. Для строк с номером &lt; n присваиваем \(d_0\); для строки с номером n присваиваем \(S - (n - 1) \cdot d_0\).

Сумма первых \(n-1\) строк = \((n-1) \cdot d_0\); последняя строка = \(S - (n-1) \cdot d_0\); итого = \(S\). См. [§3.3](chapter-03-03.md).

---

## 8.3.3. Пример: PostgreSQL

Таблица-источник `doc_lines(id, line_no)` — три строки. Распределяем 100 руб. по ним.

```sql
WITH
params AS (
    SELECT 100.00::numeric AS total
),
ordered AS (
    SELECT
        id,
        line_no,
        ROW_NUMBER() OVER (ORDER BY id) AS rn,
        COUNT(*) OVER () AS n
    FROM doc_lines
),
base_share AS (
    SELECT
        id,
        line_no,
        rn,
        n,
        (SELECT total FROM params) AS total,
        ROUND((SELECT total FROM params) / n, 2) AS share
    FROM ordered
)
SELECT
    id,
    line_no,
    rn,
    CASE
        WHEN rn < n THEN share
        ELSE total - (n - 1) * share
    END AS amount
FROM base_share
ORDER BY rn;
```

Результат: строки 1 и 2 — по 33,33; строка 3 — 33,34; сумма = 100,00. Среда: PostgreSQL 15; типы — numeric. См. [§8.1](chapter-08-01.md).

---

## 8.3.4. Пример: Oracle

Та же логика; в Oracle нет CTE с подзапросом в SELECT для params, поэтому общую сумму можно передать bind-переменной или подставить литерал.

```sql
WITH
ordered AS (
    SELECT
        id,
        line_no,
        ROW_NUMBER() OVER (ORDER BY id) AS rn,
        COUNT(*) OVER () AS n
    FROM doc_lines
),
base_share AS (
    SELECT
        id,
        line_no,
        rn,
        n,
        ROUND(100.00 / n, 2) AS share
    FROM ordered
)
SELECT
    id,
    line_no,
    rn,
    CASE
        WHEN rn < n THEN share
        ELSE 100.00 - (n - 1) * share
    END AS amount
FROM base_share
ORDER BY rn;
```

Среда: Oracle 21c; 100.00 интерпретируется как NUMBER. Для параметризованного запроса использовать bind :total и подставлять :total вместо 100.00 в обоих местах. См. [§8.1](chapter-08-01.md).

---

## 8.3.5. Проверка суммы

В том же запросе можно добавить проверку: сумма колонки amount по всем строкам должна равняться 100. Для этого обернуть выборку в подзапрос и вывести SUM(amount) и ожидаемый total:

```sql
-- PostgreSQL: обёртка для проверки
SELECT
    SUM(amount) AS total_distributed,
    100.00::numeric AS total_expected,
    SUM(amount) - 100.00 AS diff
FROM (
    -- здесь запрос из §8.3.3 без ORDER BY в наружном SELECT
) t;
```

Ожидаем diff = 0. Аналогично в Oracle. См. [§5.4](chapter-05-04.md), [§7.3](chapter-07-03.md).

---

## 8.3.6. Распределение по весам (опционально)

Если доли заданы весами \(w_i\) (например, проценты по контракту), базовая доля строки \(i\): \(d_i = S \cdot w_i / \sum w_j\). Округляем \(d_i\) до копеек; сумма округлённых может не совпадать с \(S\). Остаток распределяем на одну строку (например, с максимальным весом или последнюю по ORDER BY): вычислить остаток \(R = S - \sum \mathrm{ROUND}(d_i, 2)\) и прибавить \(R\) к выбранной строке. В SQL это делают через оконные функции (SUM(ROUND(...)) OVER (), ROW_NUMBER для выбора строки остатка) или двумя проходами. Детали — по [§3.3](chapter-03-03.md), [§3.4](chapter-03-04.md). См. [Глоссарий](glossary.md).

---

## 8.3.7. Типичные ошибки

- **Не фиксировать ORDER BY:** при разном порядке «последняя» строка меняется; в ROW_NUMBER() OVER (ORDER BY ...) указать однозначный порядок (id, line_no).
- **Использовать целочисленное деление:** 100 / 3 в некоторых настройках даёт 33; нужно 100.00 / 3 или явный cast к numeric, чтобы получить 33.333…
- **Считать последнюю строку через RANK вместо ROW_NUMBER:** при равных значениях ORDER BY RANK даст одинаковый ранг нескольким строкам; для «ровно одна последняя» нужен ROW_NUMBER.

---

## Ключевое

- Распределение суммы по строкам с **остатком на последнюю**: ROW_NUMBER() и COUNT(*) OVER () для номера и числа строк; базовая доля ROUND(S/n, 2); последней строке присвоить S - (n-1)*доля.
- В **PostgreSQL** и **Oracle** реализация на CTE и оконных функциях; общая сумма — литерал или параметр; тип numeric/NUMBER для точности.
- Порядок строк задаётся в ORDER BY внутри ROW_NUMBER(); он должен быть детерминированным (например, ORDER BY id).
- Проверка: SUM(amount) по результату должна равняться S; при весах логика та же с долей по весу и компенсацией остатка на одну строку.

В [§8.4](chapter-08-04.md) мы разберём оконные функции для оборотов и остатков: SUM() OVER (PARTITION BY account ORDER BY date), рамка окна и производительность.
