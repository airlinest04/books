# Глоссарий: тестирование данных и пайплайнов

- **Контрольная сумма** (checksum) — значение, полученное детерминированно из набора данных (SUM, COUNT, хеш и т.д.), для сравнения с эталоном при регрессионных и интеграционных проверках. См. [§2.3](chapter-02-03.md).

- **Полнота** — свойство загрузки: все строки среза источника присутствуют в приёмнике; ничего не потеряно при извлечении, преобразовании и загрузке. Проверяется row 
count и при необходимости охватом по ключу. См. [§7.4](chapter-07-04.md).

- **CI/CD** (Continuous Integration / Continuous Delivery или Deployment) — практика частой сборки, тестирования и доставки изменений до окружения; для данных включает 
тесты до деплоя и smoke-тесты после. См. [§1.4](chapter-01-04.md).

- **Интеграционный тест** (для ETL) — проверка пайплайна «источник → ETL → приёмник» на тестовых данных; проверяются полнота (row count, охват) и целостность в приёмнике. 
См. [§2.2](chapter-02-02.md).

- **Assertion** (утверждение) — явное условие над данными (количество строк, значения полей, агрегаты, уникальность), при невыполнении которого тест или проверка 
проваливается. См. [§5.1](chapter-05-01.md).

- **Бизнес-правило** (в контексте данных) — инвариант предметной области (дебет = кредит, баланс, сумма строк = итог и т.д.), проверяемый запросом; assertion — «нарушений 
0». См. [§5.4](chapter-05-04.md).

- **Анонимизация** — преобразование данных, исключающее идентификацию субъекта; в тестах часто применяется вместе с маскированием к копиям продовых данных. См. [§3.3]
(chapter-03-03.md).

- **Идемпотентность** (пайплайна) — свойство: повторный запуск с теми же входными данными и параметрами даёт тот же результат в приёмнике; необходимо для безопасного 
повтора при сбое. См. [§8.1](chapter-08-01.md).

- **Доверие к данным** — уверенность потребителей в том, что данные в витринах и отчётах полные, согласованные и пригодны для решений; подрыв доверия ведёт к ручным 
перепроверкам и дублированию расчётов. См. [§1.2](chapter-01-02.md).

- **ETL** (Extract, Transform, Load) — процесс извлечения данных из источников, их преобразования и загрузки в назначение (хранилище, витрина). См. [§1.1](chapter-01-01.
md).

- **Мониторинг качества данных** — непрерывный (или регулярный) контроль данных в продуктивной среде: полнота, своевременность, согласованность, метрики качества; цель — 
рано обнаружить деградацию и сбои. См. [§1.3](chapter-01-03.md).

- **Маскирование данных** (data masking) — замена чувствительных значений на неправдоподобные с сохранением формата и типа; применяется к копиям продовых данных перед 
использованием в тестовых средах. См. [§3.3](chapter-03-03.md).

- **Маппинг** — соответствие полей источника полям целевой таблицы или витрины; правила преобразования (тип, единицы, коды) при переносе данных. См. [§6.1](chapter-06-01.
md).

- **MDM** (Master Data Management, управление мастер-данными) — практика ведения эталонных справочных данных (контрагенты, номенклатура, коды); пайплайны используют их 
при маппинге и джойнах. См. [§11.4](chapter-11-04.md).

- **Пайплайн данных** (data pipeline) — повторяемая последовательность шагов, по которой данные перемещаются от источника(ов) к потребителю(ам); типичные шаги — 
извлечение, преобразование, загрузка. См. [§1.1](chapter-01-01.md).

- **Smoke-тест** (дымовой тест) — быстрая проверка после деплоя: пайплайн запускается, ключевые шаги выполняются, базовые метрики в разумных границах; цель — быстро 
обнаружить критические сбои. См. [§1.4](chapter-01-04.md).

- **Сирота** (orphan) — запись в дочерней таблице, у которой значение внешнего ключа не найдено в родительской таблице; нарушение референциальной целостности. См. [§5.3]
(chapter-05-03.md).

- **Синтетические данные** — данные, сгенерированные программно для тестов (объём, граничные случаи), без использования продовых данных; воспроизводимость обеспечивается 
фиксированным seed. См. [§3.2](chapter-03-02.md).

- **Санитарная проверка** (sanity check) — быстрая проверка «данные в разумных пределах» (row count, нет отрицательных значений, нет массовых null и т.д.) без сравнения с 
эталоном; часто часть smoke-теста или шаг после прогона загрузки. См. [§2.4](chapter-02-04.md).

- **Row count** (количество строк) — число записей в выборке или таблице за срез; базовая проверка полноты: row count в источнике и приёмнике за один срез должны 
совпадать (или следовать явному правилу). См. [§7.1](chapter-07-01.md).

- **Референциальная целостность** — свойство данных: для каждого значения внешнего ключа в дочерней таблице существует запись в родительской; нарушение — наличие «сирот». 
См. [§5.3](chapter-05-03.md).

- **Регрессионный тест** (для отчётов) — сравнение текущих ключевых метрик витрины/отчёта с сохранённым эталоном; при расхождении — провал теста (регрессия). См. [§2.3]
(chapter-02-03.md).

- **Регрессия** (в контексте данных) — ухудшение результата пайплайна после изменения кода, конфигурации или окружения: ранее корректные данные становятся неверными или 
пропадают. См. [§2.3](chapter-02-03.md).

- **Точность** — свойство загрузки: значения в приёмнике соответствуют значениям в источнике; нет искажений при маппинге, приведении типов и расчётах. Проверяется 
контрольными суммами и выборочной сверкой. См. [§7.4](chapter-07-04.md).

- **Тестовая среда** — окружение (отдельная БД, схема, контейнер) для выполнения тестов, изолированное от продовой среды; состояние сбрасывается к известному перед 
прогоном. См. [§3.4](chapter-03-04.md).

- **Тестирование** (в контексте данных) — проверка корректности пайплайна до релиза на фикстурах и тестовой среде: логика, полнота ETL, регрессии, smoke после деплоя. См. 
[§1.3](chapter-01-03.md).

- **Фикстура** (fixture) — предопределённый набор данных (таблицы, файлы), загружаемый в тестовое окружение как вход для теста; обеспечивает воспроизводимость и контроль 
сценария. См. [§3.1](chapter-03-01.md).

- **Эталон** (baseline, golden reference) — сохранённое значение метрик или контрольных сумм, с которым сравнивается текущий результат при регрессионном тесте. См. [§2.3]
(chapter-02-03.md).

- **Unit-тест** (для данных/SQL) — изолированная проверка одного запроса или преобразования при фиксированном входе с сравнением результата с ожидаемым; быстрый, 
детерминированный. См. [§2.1](chapter-02-01.md).

- **Точка отказа** — место в пайплайне (шаг или операция), где процесс может упасть, зависнуть или выдать неверный результат. См. [§1.1](chapter-01-01.md).
