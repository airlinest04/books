# §2.4 Команды и API HDFS

В [§2.3](chapter-02-03.md) мы разобрали репликацию: фактор, размещение реплик и выбор при чтении. Чтобы работать с данными в HDFS, нужны способы создавать каталоги, загружать и скачивать файлы, просматривать содержимое и проверять метаданные (в том числе репликацию). В этом разделе рассматриваются **команды файловой оболочки** `hdfs dfs` (и эквивалент `hadoop fs`) и кратко — другие способы доступа (Java API, WebHDFS). Ограничения HDFS при выборе сценариев использования — в [§2.5](chapter-02-05.md). См. [Глоссарий](glossary.md).

---

## 2.4.1. hdfs dfs и hadoop fs

Работа с HDFS из командной строки выполняется через подкоманду **`hdfs dfs`** (или устаревшую, но по-прежнему поддерживаемую **`hadoop fs`**). Обе формы принимают одни и те же аргументы: команда и опции, затем пути в HDFS или локальные пути. См. [Глоссарий](glossary.md).

Синтаксис:

```bash
hdfs dfs -<команда> [опции] <аргументы>
# или
hadoop fs -<команда> [опции] <аргументы>
```

Пути в HDFS задаются с префиксом, например `hdfs://localhost:9000/user/name/file` или кратко `/user/name/file`, если в конфигурации задан адрес по умолчанию (fs.defaultFS). Локальные пути указываются без префикса или с `file:///`. Команды выполняются от имени пользователя, под которым запущена оболочка; права доступа в HDFS проверяются так же, как в POSIX-подобной файловой системе (владелец, группа, права на чтение/запись/выполнение).

**Среда:** команды рассчитаны на окружение с установленным Hadoop (HADOOP_HOME в PATH или вызов из каталога установки). Для псевдо-распределённого или полностью распределённого кластера должны быть запущены NameNode и DataNode; иначе команды завершатся ошибкой подключения.

## 2.4.2. Просмотр содержимого каталога: ls

**`-ls`** — вывод списка файлов и каталогов по указанному пути. См. [Глоссарий](glossary.md).

```bash
hdfs dfs -ls /user
hdfs dfs -ls /user/hadoop
```

Без пути выводится содержимое домашнего каталога пользователя (как правило, `/user/<имя_пользователя>`).

**Подробный вывод** (длинный формат) — с `-ls` по умолчанию показываются права, владелец, группа, размер, дата и имя:

```
-rw-r--r--   3 hadoop supergroup    1234567 2024-01-15 10:00 /user/hadoop/data.log
drwxr-xr-x   - hadoop supergroup          0 2024-01-15 10:00 /user/hadoop/results
```

Первое поле для файла — число **реплик** (например, 3); для каталога — минус. Рекурсивный обход вложенных каталогов:

```bash
hdfs dfs -ls -R /user/hadoop
```

---

## 2.4.3. Создание каталогов: mkdir

**`-mkdir`** — создание одного или нескольких каталогов. Родительские каталоги при необходимости создаются с опцией **`-p`**. См. [Глоссарий](glossary.md).

```bash
hdfs dfs -mkdir /user/hadoop
hdfs dfs -mkdir -p /user/hadoop/input /user/hadoop/output
```

Без `-p` команда завершится ошибкой, если какой-либо родительский каталог не существует. После создания каталоги можно использовать как цель для загрузки файлов (`-put`) или как рабочие пути для приложений (MapReduce, Hive и т.д.).

---

## 2.4.4. Загрузка файлов в HDFS: put

**`-put`** (или **`-copyFromLocal`**) — копирование одного или нескольких локальных файлов (или локального каталога) в HDFS. См. [Глоссарий](glossary.md).

```bash
hdfs dfs -put localfile.txt /user/hadoop/input/
hdfs dfs -put file1.txt file2.txt /user/hadoop/input/
hdfs dfs -put -f localdir /user/hadoop/input/
```

- Если указан один локальный файл и путь в HDFS — файл копируется по этому пути (имя файла сохраняется или задаётся путём).
- Несколько локальных файлов: последний аргумент должен быть каталогом в HDFS; файлы копируются в него с теми же именами.
- Опция **`-f`** — перезаписать цель, если она уже существует (по умолчанию при существующем файле может быть ошибка в зависимости от версии).

При загрузке файл разбивается на блоки согласно размеру блока HDFS; репликация выполняется по политике из [§2.3](chapter-02-03.md). Фактор репликации по умолчанию берётся из конфигурации; задать его для конкретного файла при копировании можно через опцию **`-D dfs.replication=N`** (в части версий) или после загрузки — через API/другие средства.

---

## 2.4.5. Скачивание файлов из HDFS: get

**`-get`** (или **`-copyToLocal`**) — копирование файлов или каталогов из HDFS на локальную файловую систему. См. [Глоссарий](glossary.md).

```bash
hdfs dfs -get /user/hadoop/output/result.txt ./
hdfs dfs -get /user/hadoop/output ./local_output
```

- Один файл в HDFS — копируется в указанный локальный путь (файл или каталог).
- Каталог в HDFS — копируется рекурсивно в указанный локальный каталог. Опция **`-ignoreCrc`** не проверять контрольные суммы (не рекомендуется без веской причины).

После выполнения заданий MapReduce, Hive или Pig результаты часто лежат в каталогах HDFS; `-get` позволяет забрать их для просмотра или дальнейшей обработки на клиенте.

---

## 2.4.6. Просмотр содержимого файла: cat и head

**`-cat`** — вывести содержимое файла в HDFS на стандартный вывод (целиком). Подходит для небольших файлов или для передачи в конвейер. См. [Глоссарий](glossary.md).

```bash
hdfs dfs -cat /user/hadoop/output/part-00000
hdfs dfs -cat /user/hadoop/output/part-* | head -20
```

**`-head`** — вывести начало файла (первые килобайты или строки, в зависимости от версии):

```bash
hdfs dfs -head /user/hadoop/logs/large.log
```

Для очень больших файлов `-cat` передаёт много данных по сети; предпочтительнее обрабатывать их задачами на кластере (MapReduce, Hive, Spark) или смотреть только нужную часть через `-head` или выборочное чтение в приложении.

---

## 2.4.7. Удаление: rm и rmr

**`-rm`** — удаление файла или пустого каталога. См. [Глоссарий](glossary.md).

```bash
hdfs dfs -rm /user/hadoop/input/oldfile.txt
hdfs dfs -rm -r /user/hadoop/old_dir
```

Опция **`-r`** (или **`-R`**) — рекурсивное удаление каталога и всего содержимого. **`-skipTrash`** — не перемещать в «корзину» (если включена), а удалять сразу. Удаление освобождает блоки на DataNode; NameNode обновляет метаданные.

**Устаревшая форма** **`-rmr`** (рекурсивное удаление) в новых версиях может быть заменена на `-rm -r`.

---

## 2.4.8. Проверка репликации и метаданных: stat и ls

Узнать **фактор репликации** и другие метаданные файла можно с помощью **`-stat`** или по выводу **`-ls`**. См. [Глоссарий](glossary.md).

**Статус в формате шаблона:**

```bash
hdfs dfs -stat "%r" /user/hadoop/data/file.txt
```

Спецификатор `%r` — число реплик. Другие варианты: `%b` (размер в байтах), `%n` (имя), `%o` (размер блока) и т.д.; точный набор зависит от версии (см. документацию `hdfs dfs -stat`).

**По выводу `-ls`:** в длинном формате первое числовое поле для файла — количество реплик:

```bash
hdfs dfs -ls /user/hadoop/data
```

Пример вывода: `-rw-r--r-- 3 hadoop supergroup ...` — три реплики.

Проверка репликации полезна после загрузки данных и после сбоев: убедиться, что у файлов достигнут нужный фактор репликации и нет блоков с пониженным числом реплик (такое видно по отчётам NameNode и по утилитам мониторинга).

## 2.4.9. Дополнительные полезные команды

| Команда | Назначение |
|---------|------------|
| `-cp` | Копирование внутри HDFS (источник → приёмник). |
| `-mv` | Перемещение/переименование внутри HDFS. |
| `-du` | Размер файлов и каталогов (в байтах или человекопонятно с `-h`). |
| `-df` | Свободное/занятое место в HDFS (аналог df на дисках). |
| `-chmod`, `-chown` | Изменение прав и владельца (как в POSIX). |
| `-count` | Число каталогов, файлов и байт по пути. |

Примеры:

```bash
hdfs dfs -cp /user/hadoop/a.txt /user/hadoop/backup/
hdfs dfs -du -h /user/hadoop
hdfs dfs -df -h /
```

Полный список команд и опций: **`hdfs dfs -help`** или **`hadoop fs -help`**; для конкретной команды — **`hdfs dfs -help -rm`** и т.п.

## 2.4.10. Программный доступ: Java API и WebHDFS

Помимо командной строки, с HDFS можно работать программно. См. [Глоссарий](glossary.md).

**Java API:** класс **`org.apache.hadoop.fs.FileSystem`** и связанные классы (`Path`, `FSDataInputStream`, `FSDataOutputStream`) позволяют из приложения (в том числе MapReduce, Hive, Spark) открывать файлы, читать и писать данные, создавать каталоги, получать метаданные. Конфигурация кластера (адрес NameNode и т.д.) задаётся через `Configuration`; приложение получает экземпляр `FileSystem` и выполняет операции по путям в HDFS. Детали API см. в документации Apache Hadoop и в примерах в исходниках.

**WebHDFS** и **HttpFS:** REST-интерфейс к HDFS: операции выполняются через HTTP (GET/PUT и др.). Удобно для интеграции с внешними системами без установки Hadoop-клиента; поддержка аутентификации и прав доступа зависит от настройки кластера.

Для типичных сценариев «загрузить данные, запустить job, забрать результат» достаточно команд `hdfs dfs`; для автоматизации и встроенной логики в приложениях используют Java API или REST.

## 2.4.11. Типичные ошибки при работе с командами

- **Путь без ведущего слэша:** в HDFS абсолютные пути начинаются с `/` (например, `/user/hadoop`, а не `user/hadoop`). Относительные пути трактуются относительно домашнего каталога пользователя.
- **Путать локальный путь и HDFS:** в `-put` первый аргумент — локальный, последний (или единственный путь назначения) — в HDFS; в `-get` наоборот. Перепутывание ведёт к ошибке или записи не туда.
- **Удаление без -r:** `-rm` без `-r` не удалит непустой каталог; нужна опция `-r` для рекурсивного удаления.
- **Игнорирование прав и владельца:** в многопользовательском кластере созданные файлы и каталоги имеют владельца и права; при совместном доступе может потребоваться `-chmod` или `-chown`. Запуск от root без настройки может создавать файлы, недоступные другим пользователям.

---

## Ключевое

- **`hdfs dfs`** и **`hadoop fs`** — эквивалентные команды для работы с HDFS из командной строки; синтаксис: `hdfs dfs -<команда> [опции] <аргументы>`.
- **Основные команды:** `-ls` (список), `-mkdir -p` (каталоги), `-put` (загрузка в HDFS), `-get` (скачивание из HDFS), `-cat` / `-head` (просмотр), `-rm -r` (удаление).
- **Репликация:** в выводе `-ls` первое число для файла — число реплик; детальнее — `-stat "%r" <путь>`.
- **Дополнительно:** `-cp`, `-mv`, `-du`, `-df`, `-chmod`, `-chown`, `-count`; полный список — `hdfs dfs -help`.
- **Программный доступ:** Java API (FileSystem, Path и др.) и REST (WebHDFS/HttpFS) для интеграции и приложений.

В [§2.5](chapter-02-05.md) мы разберём ограничения HDFS: когда HDFS не подходит (малые файлы, произвольный доступ, множественные записи в один файл, требования к низкой латентности).
