# §7.2 Основные конструкции Pig Latin

В [§7.1](chapter-07-01.md) мы разобрали назначение Pig и место языка Pig Latin в ETL. Каждый оператор Pig Latin работает с **отношением** (набором кортежей) и порождает новое отношение или выполняет вывод. В этом разделе — основные операторы: **LOAD**, **FILTER**, **FOREACH**, **GROUP**, **JOIN**, **ORDER BY**, **STORE** — и **типы данных** (скаляры, кортежи, баги). Выполнение скрипта (режимы, компиляция в MapReduce) — в [§7.3](chapter-07-03.md); полный пример пайплайна — в [§7.4](chapter-07-04.md). См. [Глоссарий](glossary.md).

---

## 7.2.1. LOAD: загрузка данных

**LOAD** читает данные из файла (обычно в HDFS) и создаёт отношение — набор кортежей. Синтаксис:

```pig
relation = LOAD 'path' [USING function] [AS schema];
```

- **path** — путь к файлу или каталогу (например, `'/user/data/events.csv'`). В распределённом режиме путь обычно в HDFS.
- **USING** — функция загрузки (например, `PigStorage('\t')` для текста с разделителем табуляции); по умолчанию `PigStorage` с табуляцией.
- **AS** — схема: имена и типы полей. Если схема не задана, поля имеют тип `bytearray` и к ним обращаются по позиции (`$0`, `$1`).

Пример с явной схемой:

```pig
events = LOAD '/data/events.log' USING PigStorage('\t')
  AS (user_id: int, event_type: chararray, ts: long);
```

После LOAD переменная `events` — отношение; его можно передавать в FILTER, FOREACH, GROUP и т.д.

---

## 7.2.2. FILTER: фильтрация строк

**FILTER** оставляет в отношении только те кортежи, для которых условие истинно. Синтаксис:

```pig
filtered = FILTER relation BY condition;
```

Условие — логическое выражение над полями: сравнения (`==`, `!=`, `>`, `<`, `>=`, `<=`), логические связки `AND`, `OR`, `NOT`. Пример:

```pig
clicks = FILTER events BY event_type == 'click' AND user_id > 0;
```

Результат — новое отношение с той же схемой, без «отфильтрованных» строк.

---

## 7.2.3. FOREACH: проекция и преобразование полей

**FOREACH** применяет к каждому кортежу отношения выражение и порождает новое отношение: можно выбрать часть полей (проекция), вычислить новые поля, вызвать функции. Синтаксис:

```pig
result = FOREACH relation GENERATE expression [, expression ...];
```

В GENERATE перечисляются поля (по имени или по позиции) и выражения. Пример — оставить два поля и вычислить третье:

```pig
projected = FOREACH events GENERATE user_id, event_type, ts / 1000 AS ts_sec;
```

Вложенный FOREACH (FOREACH ... GENERATE вложенный в другой FOREACH) используется для обработки полей типа bag после GROUP. Пример с флаттеном вложенной структуры: `flattened = FOREACH grouped GENERATE group, FLATTEN(bag);`.

---

## 7.2.4. GROUP: группировка по ключу

**GROUP** собирает все кортежи с одинаковым значением ключа в одну группу; результат — отношение, в котором каждую строку составляет ключ (поле `group`) и **баг** (bag) — набор кортежей этой группы. Синтаксис:

```pig
grouped = GROUP relation BY key_expression [PARALLEL n];
```

- **BY key_expression** — выражение от полей (поле, кортеж полей или выражение). Все кортежи с одинаковым значением попадают в одну группу.
- **PARALLEL n** — подсказка по числу Reduce-задач (аналог числа редукторов в MapReduce).

Пример:

```pig
by_user = GROUP events BY user_id;
-- Результат: (group = user_id, events = bag of tuples)
```

После GROUP типично идёт FOREACH с агрегацией по багу (COUNT, SUM и т.д.) или FLATTEN для дальнейшей обработки.

---

## 7.2.5. JOIN: соединение отношений

**JOIN** объединяет два отношения по ключу: кортежи с совпадающим значением ключа из обоих отношений образуют результирующие кортежи. Синтаксис:

```pig
joined = JOIN relation1 BY key1, relation2 BY key2 [USING 'replicated' | 'skewed' | ...];
```

Ключи могут быть полями или выражениями. В результате каждое поле обоих отношений присутствует; для различения при совпадении имён используют префиксы `relation1::field` и `relation2::field`. Пример:

```pig
events_with_names = JOIN events BY user_id, users BY user_id;
```

JOIN в Pig компилируется в MapReduce (или Tez) join; большие отношения приводят к shuffle по ключу. Для маленькой одной из таблиц возможен replicated join (копирование на каждый маппер).

---

## 7.2.6. ORDER BY и LIMIT

**ORDER BY** сортирует отношение по указанным полям. Синтаксис:

```pig
sorted = ORDER relation BY field [ASC|DESC], field2 [ASC|DESC], ... [PARALLEL n];
```

Сортировка глобальная (все данные проходят через один или несколько редьюсеров). **LIMIT** обрезает отношение до первых N кортежей:

```pig
top10 = LIMIT sorted 10;
```

ORDER BY на больших данных — дорогая операция; LIMIT уменьшает объём вывода.

---

## 7.2.7. STORE: запись результата

**STORE** записывает отношение в каталог в HDFS (или в другое хранилище при использовании соответствующей функции). Синтаксис:

```pig
STORE relation INTO 'path' [USING function];
```

- **path** — каталог вывода; обычно в HDFS. Pig создаёт в нём файлы (часть-00000 и т.д.); каталог не должен существовать до STORE (или будет ошибка, в зависимости от версии и настроек).
- **USING** — функция записи (по умолчанию PigStorage с табуляцией).

Пример:

```pig
STORE result INTO '/data/output/events_agg';
```

STORE — **триггер выполнения**: до него Pig может откладывать вычисления (ленивое выполнение); при встрече STORE выполняется весь план до записи этого отношения.

---

## 7.2.8. Типы данных: скаляры, кортежи, баги

Данные в Pig Latin типизированы. Схема может задаваться в LOAD (AS) или выводиться из операций. См. [Глоссарий](glossary.md).

**Скалярные типы:** `int`, `long`, `float`, `double`, `chararray` (строка), `bytearray` (произвольные байты), `boolean`, `datetime`. Используются для полей кортежа.

**Кортеж (tuple)** — упорядоченный набор полей с типами. Одна строка отношения — кортеж; поля обращаются по позиции (`$0`, `$1`) или по имени из схемы.

**Баг (bag)** — неупорядоченная коллекция кортежей (с одной и той же схемой). Появляется после GROUP: поле группы — баг кортежей. К багу применимы функции: `COUNT`, `SUM`, `AVG`, `MIN`, `MAX` (в контексте FOREACH над сгруппированным отношением), а также `FLATTEN` для «разворачивания» бага в отдельные кортежи.

**Map** — ассоциативный массив (ключ–значение); используется реже при загрузке из структурных форматов.

Пример типа после GROUP:

```pig
-- by_user: (group: int, events: bag {(user_id: int, event_type: chararray, ts: long)})
-- В FOREACH можно: FOREACH by_user GENERATE group, COUNT(events) AS cnt;
```

---

## Ключевое

- **LOAD** — чтение из пути с опциональной схемой (AS) и функцией (USING); результат — отношение.
- **FILTER** — отбор строк по условию; **FOREACH GENERATE** — проекция и вычисление полей.
- **GROUP BY** — группировка по ключу; результат содержит поле `group` и баг кортежей; далее — агрегация или FLATTEN.
- **JOIN** — соединение двух отношений по ключу; **ORDER BY** — сортировка; **LIMIT** — обрезка вывода.
- **STORE** — запись отношения в каталог; запускает выполнение плана.
- **Типы:** скаляры (int, long, chararray и т.д.), кортеж (строка отношения), баг (набор кортежей, в т.ч. после GROUP).

В [§7.3](chapter-07-03.md) разберём выполнение скриптов Pig: локальный и распределённый режим, преобразование в MapReduce под капотом.
