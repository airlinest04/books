# §1.2 PowerCenter и Informatica Cloud

В [§1.1](chapter-01-01.md) мы ввели Informatica как корпоративную ETL-платформу и упомянули два основных направления: **PowerCenter** (on-premise) и **Informatica Cloud** (IICS). В этом разделе мы детально сравним эти продукты, разберём критерии выбора между ними и опишем гибридные сценарии, когда организации используют оба подхода одновременно. Вы научитесь понимать, когда выбирать on-premise, когда облако, и как планировать переход или сосуществование. Подробнее архитектура компонентов PowerCenter — в [§1.3](chapter-01-03.md). См. [Глоссарий](glossary.md).

---

## 1.2.1. PowerCenter: on-premise ETL-платформа

**PowerCenter** — корпоративная ETL-платформа Informatica для развёртывания **on-premise** (в собственных центрах обработки данных организации). Все компоненты — Repository Server, Integration Service, клиентские приложения (Designer, Workflow Manager, Workflow Monitor) — устанавливаются на серверах под контролем заказчика. Данные при выполнении ETL-сессий проходят через инфраструктуру организации; при необходимости данные не покидают периметр.

Ключевые характеристики PowerCenter:

| Характеристика | Описание |
|----------------|----------|
| **Размещение** | Серверы в ЦОД заказчика; полный контроль над инфраструктурой и размещением данных. |
| **Архитектура** | Клиент-серверная: толстые клиенты (Designer, Workflow Manager) подключаются к Repository Server; Integration Service выполняет сессии на выделенных узлах. |
| **Модель лицензирования** | Традиционно — по количеству процессоров (CPU) или по мощности (capacity-based); единовременные и ежегодные платежи. |
| **Масштабирование** | Ручное: добавление узлов в Grid, наращивание ресурсов серверов; требует планирования и закупок. |
| **Источники и приёмники** | Широкий набор коннекторов к реляционным БД, файлам, legacy-системам; поддержка облачных хранилищ через дополнительные коннекторы, но изначально ориентирован на on-premise. |

PowerCenter — зрелый продукт с многолетней историей; тысячи организаций используют его для критичных загрузок в DWH. Знание PowerCenter остаётся востребованным: многие проекты интеграции данных продолжают работать на этой платформе. См. [§1.3](chapter-01-03.md).

## 1.2.2. Informatica Cloud (IICS): облачная платформа

**Informatica Intelligent Cloud Services (IICS)** — облачная платформа интеграции данных Informatica. Развёртывается в облаке Informatica (или в инфраструктуре заказчика при гибридной модели); пользователи работают через веб-интерфейс, не устанавливая толстые клиенты. **Cloud Data Integration (CDI)** — сервис ETL/ELT в рамках IICS; поддерживает маппинги, задачи (Tasks), расписание и мониторинг.

Ключевые характеристики Informatica Cloud:

| Характеристика | Описание |
|----------------|----------|
| **Размещение** | SaaS: управление и выполнение в облаке Informatica; данные могут обрабатываться в облаке или через агенты на стороне заказчика (Secure Agent) для доступа к on-premise источникам. |
| **Архитектура** | Микросервисная, API-driven; веб-интерфейс; серверная обработка (в т.ч. serverless Spark) для тяжёлых нагрузок. |
| **Модель лицензирования** | Подписка (subscription); оплата по использованию (consumption-based) или по объёму обрабатываемых данных; нет единовременных затрат на инфраструктуру. |
| **Масштабирование** | Эластичное: кластеры масштабируются по нагрузке; автоматическое выключение после завершения задач; не требуется ручное добавление серверов. |
| **Источники и приёмники** | Нативные коннекторы к облачным DWH (Snowflake, BigQuery, Redshift, Azure Synapse, Databricks), SaaS (Salesforce, SAP и др.), файловым хранилищам (S3, Azure Blob); pushdown-оптимизация для выполнения логики в целевой СУБД. |

По данным Informatica: облачная интеграция данных обеспечивает **гибкость** (быстрое развёртывание новых паттернов, подключение on-premise и облачных источников), **скорость** (шаблоны, переиспользуемые маппинги, построение интеграций за часы или минуты) и **масштабируемость** (serverless-движок, динамическое масштабирование). Источник: [What is Cloud Data Integration](https://www.informatica.com/resources/articles/what-is-cloud-data-integration.html).

## 1.2.3. Сравнение: PowerCenter vs Informatica Cloud

| Критерий | PowerCenter (on-premise) | Informatica Cloud (IICS) |
|----------|-------------------------|--------------------------|
| **Размещение данных** | Данные остаются в периметре заказчика | Данные могут обрабатываться в облаке; Secure Agent для доступа к on-premise без выноса данных |
| **Инфраструктура** | Заказчик управляет серверами, ОС, обновлениями | Informatica управляет инфраструктурой; заказчик платит за использование |
| **Масштабирование** | Ручное, требует закупок и настройки | Автоматическое, по требованию |
| **Облачные DWH** | Коннекторы есть, но не нативная среда | Нативная поддержка Snowflake, BigQuery, Databricks, Redshift и др. |
| **SaaS и API** | Ограниченная поддержка; часто требуются кастомные решения | Широкий набор коннекторов к SaaS, REST API, потоковым источникам |
| **Реальное время** | Пакетная обработка; CDC и репликация через отдельные компоненты | Поддержка потоковой обработки, массовой загрузки, multi-latency |
| **Интерфейс** | Толстые клиенты (Designer, Workflow Manager) | Веб-интерфейс; доступ из браузера |
| **Миграция маппингов** | — | Инструменты миграции PowerCenter → IICS; переиспользование до 100% логики при конвертации |

PowerCenter оптимален для организаций с устоявшейся on-premise инфраструктурой, строгими требованиями к размещению данных и интеграцией преимущественно с legacy-системами. IICS предпочтителен для новых проектов, облачных DWH, интеграции SaaS и сценариев, требующих гибкости и быстрого масштабирования.

## 1.2.4. Когда выбирать PowerCenter (on-premise)

Выбирайте **PowerCenter**, если:

- **Требования к размещению данных:** регуляторные или внутренние политики требуют, чтобы данные не покидали физическую инфраструктуру организации (например, персональные данные, финансовая отчётность, госсектор).
- **Существующие инвестиции:** организация уже использует PowerCenter; накоплены сотни маппингов и workflow; команда знакома с платформой; миграция в облако не запланирована в ближайшей перспективе.
- **Интеграция с legacy:** основные источники и приёмники — on-premise БД (Oracle, SQL Server, DB2 и др.), файловые системы, мейнфреймы; облачные системы играют второстепенную роль.
- **Сложные трансформации:** нужен детальный контроль над ETL-процессами; используются специфичные трансформации PowerCenter; требования к тонкой настройке производительности (партиционирование, кеш Lookup и т.п.).
- **Стабильная нагрузка:** объёмы и расписание загрузок предсказуемы; нет необходимости в резком масштабировании; текущая инфраструктура справляется с нагрузкой.

Ограничения PowerCenter: отсутствие нативной поддержки API и веб-сервисов для оркестрации извне; ограниченная поддержка облачных DWH без дополнительных коннекторов; масштабирование требует ручного добавления узлов и закупок; более высокие совокупные затраты на владение (TCO) при необходимости частого обновления инфраструктуры.

---

## 1.2.5. Когда выбирать Informatica Cloud (IICS)

Выбирайте **Informatica Cloud**, если:

- **Облачная стратегия:** целевое хранилище — Snowflake, BigQuery, Databricks, Redshift, Azure Synapse; данные или часть из них уже в облаке; организация движется в сторону cloud-first.
- **Новый проект:** нет legacy PowerCenter; можно сразу строить интеграции в облачной среде с гибким масштабированием и подписочной моделью.
- **Интеграция SaaS и API:** требуется подключение к Salesforce, Workday, SAP Cloud, REST API, потоковым источникам; IICS предоставляет широкий набор коннекторов и паттернов.
- **Гибкость и скорость:** нужны быстрые изменения, масштабирование по требованию, снижение операционной нагрузки на инфраструктуру; предпочтительна модель подписки без капитальных затрат.
- **Мультиоблачность:** данные распределены по AWS, Azure, GCP и on-premise; требуется единая платформа для интеграции без привязки к одному провайдеру.

Преимущества миграции с PowerCenter в IICS (по данным Informatica): ускорение развёртывания (до 8 раз быстрее); переиспользование до 100% активов PowerCenter при конвертации; снижение затрат до 50%; возможность поэтапной миграции. Источник: [PowerCenter to Cloud Modernization](https://www.informatica.com/products/data-integration/powercenter.html).

## 1.2.6. Гибридные сценарии

**Гибридный сценарий** — одновременное использование PowerCenter и Informatica Cloud в одной организации. Типичные ситуации:

**Сосуществование по слоям:**

- PowerCenter — загрузка из on-premise источников в промежуточный слой (например, на серверы в ЦОД или в гибридное хранилище).
- IICS — загрузка из промежуточного слоя в облачный DWH (Snowflake, BigQuery, Databricks); или интеграция с SaaS и облачными приложениями.

**Сосуществование по доменам:**

- PowerCenter — критичные загрузки из core-систем (ERP, транзакционные БД), где данные не должны покидать периметр.
- IICS — аналитические витрины в облаке, интеграция с маркетинговыми платформами, загрузка в облачное озеро данных.

**Поэтапная миграция:**

- Организация постепенно переносит маппинги с PowerCenter в IICS; часть workflow остаётся на PowerCenter до завершения миграции.
- Инструменты Informatica поддерживают конвертацию маппингов и переиспользование бизнес-логики; миграция может выполняться без полной переработки.

**Secure Agent для доступа к on-premise:**

- IICS использует **Secure Agent** — агент, устанавливаемый в периметре заказчика; через него IICS получает доступ к on-premise БД и файлам без выноса данных в облако Informatica.
- Данные читаются агентом на стороне заказчика и передаются в целевое облачное хранилище; или преобразования выполняются в агенте (pushdown) при необходимости.

При гибридном подходе важно учитывать: единые стандарты именования и организации объектов; согласованные правила доступа и credentials; мониторинг и оркестрация (возможно, через внешний оркестратор, например Apache Airflow, который запускает и PowerCenter workflow, и IICS задачи). См. [главу 13](chapter-13-01.md).

## 1.2.7. PowerCenter Cloud Edition и варианты миграции

**PowerCenter Cloud Edition** — вариант PowerCenter, развёртываемый в облаке (AWS, Azure, GCP) на инфраструктуре заказчика или в managed-режиме. Сохраняет знакомую модель разработки (Designer, маппинги, workflow), но работает в облачной среде; подходит для организаций, которые хотят сохранить навыки PowerCenter и при этом уйти от физических серверов.

Варианты перехода с PowerCenter:

| Вариант | Описание |
|---------|----------|
| **PowerCenter Cloud Edition** | PowerCenter в облаке; минимальные изменения в маппингах и процессах; инфраструктура в облаке заказчика. |
| **Миграция в IICS** | Конвертация маппингов в формат Cloud Data Integration; полный переход на облачную платформу; переиспользование логики при конвертации. |
| **Гибрид** | Часть остаётся на PowerCenter, часть переходит в IICS; сосуществование по слоям или доменам. |

Выбор зависит от сроков, бюджета, требований к данным и готовности команды к освоению новой среды. Подробнее миграция и pushdown в облачных DWH — в [главе 13](chapter-13-01.md).

## 1.2.8. Типичные ошибки при выборе платформы

- **Игнорировать облачное направление при новом проекте:** если целевой DWH — Snowflake, BigQuery или Databricks, IICS часто эффективнее PowerCenter; не стоит автоматически выбирать PowerCenter «по привычке».
- **Считать, что PowerCenter «устарел»:** множество организаций продолжают использовать PowerCenter для критичных нагрузок; продукт поддерживается; знание PowerCenter востребовано для поддержки и миграции.
- **Путать «данные в облаке» и «обработка в облаке»:** при использовании Secure Agent данные могут не покидать периметр; IICS может читать on-premise источники через агента и загружать в облачный DWH, не храня данные в Informatica Cloud.
- **Планировать «big bang» миграцию:** поэтапный переход снижает риски; гибридный режим позволяет мигрировать по частям.

## Ключевое

- **PowerCenter** — on-premise ETL-платформа; полный контроль над инфраструктурой и данными; оптимален при требованиях к размещению данных, legacy-источниках и существующих инвестициях в PowerCenter.
- **Informatica Cloud (IICS)** — облачная платформа; эластичное масштабирование, нативная поддержка облачных DWH и SaaS, подписочная модель; оптимален для новых проектов, облачной стратегии и интеграции с SaaS.
- **Критерии выбора:** размещение данных, инфраструктура, источники (legacy vs cloud/SaaS), потребность в масштабировании, модель лицензирования.
- **Гибридные сценарии:** сосуществование PowerCenter и IICS по слоям или доменам; поэтапная миграция; Secure Agent для доступа к on-premise из IICS.
- **PowerCenter Cloud Edition** — PowerCenter в облаке; вариант для сохранения модели разработки при переходе с физических серверов.

В [§1.3](chapter-01-03.md) мы разберём архитектуру PowerCenter: Repository Server, Integration Service, Designer, Workflow Manager, Workflow Monitor и потоки данных между компонентами.
