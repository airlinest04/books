# §4.1 Что такое Mapping

В [§3.1](chapter-03-01.md)–[§3.4](chapter-03-04.md) мы определили источники и приёмники. **Mapping** (маппинг) — объект Designer, описывающий **поток данных** от источников через трансформации к приёмникам; это визуальное представление ETL-логики. Integration Service при выполнении Session использует инструкции маппинга для чтения, преобразования и записи данных. В этом разделе мы разберём определение Mapping, обязательные компоненты (Source, Transformation, Target, Links), принцип «один маппинг — один поток», связь с этапами ETL и отличие Mapping от Session. Создание маппинга — в [§4.2](chapter-04-02.md). См. [Глоссарий](glossary.md).

---

## 4.1.1. Определение Mapping

**Mapping** (маппинг) — набор определений источников (Source definitions) и приёмников (Target definitions), связанных объектами трансформаций (Transformations), которые задают правила преобразования данных. Маппинг описывает **поток данных** (data flow) между источниками и приёмниками. Источник: [Mappings Overview](https://docs.informatica.com/data-integration/powercenter/10-5/designer-guide/mappings/mappings-overview.html).

При запуске Session Integration Service читает метаданные маппинга из репозитория и выполняет инструкции: подключается к источникам, извлекает данные, применяет трансформации, записывает в приёмники. Маппинг — это **декларативное описание** того, *что* делать; Session — *как* выполнять (Connection, параметры, партиционирование). См. [§1.4](chapter-01-04.md), [§9.2](chapter-09-02.md).

---

## 4.1.2. Обязательные компоненты маппинга

Каждый маппинг должен содержать следующие компоненты. Источник: [Mappings Overview](https://docs.informatica.com/data-integration/powercenter/10-5/designer-guide/mappings/mappings-overview.html).

| Компонент | Описание |
|-----------|----------|
| **Source definition** | Описывает структуру источника (таблица БД, flat file). Импортируется из Source Analyzer; добавляется в маппинг. |
| **Transformation** | Изменяет данные перед записью в приёмник. Минимум одна трансформация — **Source Qualifier**, связывающая Source с потоком. Дополнительно: Expression, Filter, Lookup, Joiner, Aggregator и др. |
| **Target definition** | Описывает структуру приёмника (таблица БД, flat file). Импортируется из Target Designer; добавляется в маппинг. |
| **Links** (связи) | Соединяют источники, трансформации и приёмники; задают направление потока данных. Связи выполняются через **порты** (ports) — входные и выходные поля объектов. |

Без любого из этих компонентов маппинг невалиден. Source Qualifier — обязательная трансформация для реляционного или flat file источника: она «подключает» Source к потоку и генерирует запрос (или читает файл). См. [§6.1](chapter-06-01.md).

---

## 4.1.3. Опциональные компоненты: Mapplet

Маппинг может содержать один или несколько **Mapplet** — наборов трансформаций, созданных в Mapplet Designer и переиспользуемых в нескольких маппингах. Mapplet добавляется в маппинг как единый блок; внутри — группа связанных трансформаций. Подробнее — в [§8.4](chapter-08-04.md).

---

## 4.1.4. Оркестрация потока данных

Маппинг **оркестрирует** поток данных: задаёт порядок, в котором данные проходят через объекты. Связи (Links) определяют направление: выходной порт одного объекта соединяется с входным портом другого. Integration Service движет данные по этим связям, применяя логику каждой трансформации.

**Правила связывания** (кратко). Источник: [Rules and Guidelines for Connecting Mapping Objects](https://docs.informatica.com/data-integration/powercenter/10-5/designer-guide/mappings/connecting-mapping-objects/rules-and-guidelines-for-connecting-mapping-objects.html).

- Принимающий порт — Input или Input/Output; исходящий — Output или Input/Output.
- Нельзя связывать Input с Input или Output с Output.
- Минимум один порт входной группы должен быть связан с вышестоящей трансформацией.
- Минимум один порт выходной группы — с нижестоящей трансформацией или target.
- Типы данных портов должны быть совместимы.
- Source связывается **только** с Source Qualifier; Source Qualifier — с target или другими трансформациями.
- Нельзя подключать несколько активных трансформаций к одному входу нижестоящей трансформации; пассивные — можно.

Подробнее связи и разветвлённые потоки — в [§4.3](chapter-04-03.md).

---

## 4.1.5. Один маппинг — один поток

Принцип: **один маппинг описывает один логический поток данных**. Один маппинг может иметь несколько источников (объединённых через Joiner или Union) и несколько приёмников (разные ветки Router ведут в разные targets), но это единый поток с одной точкой входа (Source Qualifier для основного источника) и одной или несколькими точками выхода.

Для разных ETL-сценариев (например, загрузка разных витрин) создают **отдельные маппинги**. Каждый маппинг — отдельная Session в Workflow. Переиспользование логики — через Mapplets и переиспользуемые трансформации.

---

## 4.1.6. Mapping Designer: виды отображения

Mapping Designer отображает объекты в трёх режимах. Источник: [Mappings Overview](https://docs.informatica.com/data-integration/powercenter/10-5/designer-guide/mappings/mappings-overview.html).

| Режим | Описание |
|-------|----------|
| **Iconized** | Иконка объекта с именем. Компактный вид. |
| **Normal** | Колонки в портах, индикаторы Input/Output. Режим для связывания объектов. |
| **Edit** | Свойства объекта, вкладки для настройки. Редактирование выражений, условий. |

Переключение между режимами — через контекстное меню или панель инструментов. Связывание портов выполняется в Normal view.

## 4.1.7. Связь Mapping с этапами ETL

| Этап ETL | В маппинге |
|----------|------------|
| **Extract** | Source + Source Qualifier. Source Qualifier генерирует SELECT (или читает файл). |
| **Transform** | Трансформации между Source Qualifier и Target: Expression, Filter, Lookup, Joiner, Aggregator и др. |
| **Load** | Target. Integration Service записывает данные в приёмник по структуре target. |

Mapping — это визуальная реализация трёх этапов в одном объекте. Connection (доступ к БД/файлам) и режим записи (Insert/Update/Bulk) задаются в Session, не в маппинге. См. [§1.4](chapter-01-04.md).

---

## 4.1.8. Mapping vs Session

| Аспект | Mapping | Session |
|--------|---------|---------|
| **Где создаётся** | Designer | Workflow Manager |
| **Что описывает** | Логика ETL: источники, трансформации, приёмники, связи | Параметры выполнения: Connection, пути к файлам, партиционирование |
| **Хранится** | Repository | Repository |
| **Выполняет** | — | Integration Service (читает маппинг и выполняет) |

Session **ссылается** на Mapping. Один маппинг может использоваться в нескольких Session (например, с разными Connection для dev и prod). Mapping не знает о Connection; Session привязывает маппинг к конкретным источникам и приёмникам через Connection. См. [§9.2](chapter-09-02.md).

## 4.1.9. Типичные ошибки

- **Считать, что маппинг выполняется сам:** маппинг — метаданные; выполнение — через Session в Workflow, Integration Service.
- **Добавлять Connection в маппинг:** Connection — объект Workflow Manager, указывается в Session.
- **Связывать Source напрямую с Target:** Source должен быть связан с Source Qualifier; Source Qualifier — с target или трансформациями.
- **Несколько активных трансформаций в один вход:** например, два Filter в один Aggregator — недопустимо; объединить через Union или изменить логику.
- **Несовместимые типы портов:** Designer не даст связать несовместимые типы; при изменении типа после связывания — проверить валидность.

---

## Ключевое

- **Mapping** — набор Source, Transformation, Target, связанных Links; описывает поток данных от источников к приёмникам.
- **Обязательные компоненты:** Source definition, Transformation (минимум Source Qualifier), Target definition, Links через порты.
- **Mapplet** — опционально; переиспользуемая группа трансформаций.
- **Один маппинг — один поток:** несколько источников и приёмников возможны, но в рамках единого потока.
- **Mapping vs Session:** Mapping — что делать (логика); Session — как выполнять (Connection, параметры). Integration Service выполняет Session, используя маппинг.
- **Связь с ETL:** Extract (Source, Source Qualifier), Transform (трансформации), Load (Target).

В [§4.2](chapter-04-02.md) мы разберём создание маппинга: Mapping Designer, добавление источников, трансформаций и целей, связывание портов.
