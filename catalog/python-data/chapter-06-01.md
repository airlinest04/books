# §6.1 Открытие файла

В [§5.5](chapter-05-05.md) мы разобрали list comprehensions. Теперь переходим к **чтению и записи данных**: файлы, CSV, JSON. Работа с файлом начинается с его **открытия** встроенной функцией **open()**. В этом разделе — аргументы open(), **режимы** доступа ('r', 'w', 'a'), **кодировка** и **контекстный менеджер with**, который гарантирует закрытие файла даже при ошибке. В [§6.2](chapter-06-02.md) рассмотрим чтение и запись текстового содержимого.

---

## 6.1.1. Функция open()

**open(file, mode='r', encoding=None, ...)** открывает файл и возвращает **файловый объект** (stream), через который выполняется чтение или запись. См. [Глоссарий](glossary.md).

**file** — путь к файлу: строка (относительный или абсолютный путь) или объект, поддерживающий протокол файла. В Windows пути с обратными слэшами можно задавать как `"C:\\data\\file.txt"` или как сырую строку `r"C:\data\file.txt"`; для кроссплатформенности удобен **os.path.join** ([§4.5](chapter-04-05.md)).

**mode** — режим доступа: чтение, запись, дополнение и т.д. (см. ниже).

**encoding** — кодировка для текстового режима (например, **'utf-8'**). В текстовом режиме без указания encoding используется кодировка по умолчанию ОС, что может привести к ошибкам при переносе файлов между системами; для данных обычно явно задают **encoding='utf-8'**.

После работы файл нужно **закрыть** (метод **.close()** или контекстный менеджер with), чтобы освободить ресурсы и сбросить буфер записи на диск.

---

## 6.1.2. Режимы доступа: 'r', 'w', 'a'

Режим задаётся строкой в втором аргументе open().

**'r'** (read) — **чтение**. Файл должен существовать; иначе **FileNotFoundError**. Режим по умолчанию: **open(path)** эквивалентно **open(path, 'r')**.

**'w'** (write) — **запись**. Если файл существует, его содержимое **удаляется**; если не существует — создаётся. После открытия запись идёт с начала файла.

**'a'** (append) — **дополнение**. Запись в **конец** существующего файла; если файла нет — он создаётся. Содержимое не стирается.

**'x'** (exclusive create) — создание нового файла; если файл уже есть — **FileExistsError**. Удобно, когда перезапись существующего файла недопустима.

Режимы могут комбинироваться с **'b'** (binary) для бинарного режима — тогда читаются/пишутся байты без преобразования кодировки; для текстовых данных (CSV, JSON, логи) используют текстовый режим без 'b' и с указанием encoding.

**'r+'**, **'w+'**, **'a+'** — режимы чтения и записи одновременно; применяются реже, когда нужно и читать, и писать в один и тот же открытый файл.

---

## 6.1.3. Кодировка encoding='utf-8'

В **текстовом режиме** (без 'b') данные при чтении декодируются из байтов в строки, при записи — кодируются из строк в байты. Кодировка задаётся аргументом **encoding**:

```python
f = open("data.txt", "r", encoding="utf-8")
```

**UTF-8** — распространённая кодировка для обмена данными и хранения текста: поддерживает все символы Unicode, совместима с ASCII для английского текста. Если файл создан в другой кодировке (например, Windows-1251 для кириллицы в старых системах), нужно указать её: **encoding='cp1251'** или **encoding='windows-1251'**. Неверная кодировка при чтении приводит к **UnicodeDecodeError** или к «кракозябрам» в строках.

При записи по умолчанию используется **errors='strict'**: при невозможности закодировать символ возникает **UnicodeEncodeError**. Можно задать **errors='replace'** (некодируемый символ заменяется маркером) или **errors='ignore'** — подробности в документации.

---

## 6.1.4. Контекстный менеджер with

Рекомендуемый способ работы с файлом — **контекстный менеджер with**. После блока with файл **автоматически закрывается** (вызывается .close()), даже если внутри блока произошло исключение. Это избегает утечки дескрипторов и гарантирует сброс буфера записи.

Синтаксис:

```python
with open("data.txt", "r", encoding="utf-8") as f:
    content = f.read()
# здесь f уже закрыт
```

Переменная после **as** (здесь **f**) ссылается на открытый файловый объект; в блоке with выполняются операции чтения/записи. Выход из блока (нормальный или из-за исключения) всегда приводит к закрытию файла.

**Несколько файлов** в одном with (начиная с Python 3.10 можно писать в одной строке):

```python
with open("input.txt", "r", encoding="utf-8") as fin, \
     open("output.txt", "w", encoding="utf-8") as fout:
    for line in fin:
        fout.write(line.upper())
```

Без with закрытие нужно обеспечивать вручную (f.close()) или в блоке finally; при исключении до close() файл может остаться открытым. См. [Глоссарий](glossary.md) для термина «контекстный менеджер».

---

## 6.1.5. Закрытие файла и типичные ошибки

Если файл открыт без with, его нужно закрыть вызовом **f.close()**. После закрытия обращаться к файлу нельзя — операции чтения/записи вызовут **ValueError**.

**Типичные ошибки:**

- **FileNotFoundError** — файл не найден по указанному пути при режиме 'r' или при открытии несуществующего файла в режиме, требующем его наличия. Проверить путь (текущий каталог, опечатки), при необходимости **os.path.exists(path)**.
- **Открытие без with и без close()** при исключении — файл остаётся открытым. Всегда использовать **with open(...) as f** для работы с файлами.
- **Режим 'w' перезаписывает файл** — при повторном открытии того же файла на запись прежнее содержимое теряется. Для дополнения использовать 'a'.
- **Кодировка:** не указана encoding при работе с не-ASCII — возможны ошибки декодирования или неверное отображение символов. Явно задавать **encoding='utf-8'** (или нужную кодировку источника).

---

## Ключевое

- **open(path, mode, encoding)** — открытие файла; **mode**: 'r' — чтение (файл должен существовать), 'w' — запись с очисткой, 'a' — дополнение в конец. Для текста задавать **encoding='utf-8'**.
- **Контекстный менеджер with open(...) as f:** гарантирует закрытие файла после блока (в том числе при исключении). Рекомендуется вместо ручного open/close.
- Несколько файлов: **with open(...) as f1, open(...) as f2:**. После выхода из with обращаться к файлу нельзя.
- Типичные ошибки: FileNotFoundError при неверном пути; не закрытый файл при отсутствии with; перезапись при 'w'; проблемы с кодировкой без явного encoding.
