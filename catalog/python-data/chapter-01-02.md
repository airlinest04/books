# §1.2 Установка Python

В [§1.1](chapter-01-01.md) мы обсудили, зачем использовать Python для работы с данными. Теперь нужно установить интерпретатор и подготовить среду: выбрать версию Python 3.x, установить её с официального сайта или через пакетный менеджер ОС и создать виртуальное окружение (venv), чтобы зависимости проекта не смешивались с системным Python. В этом разделе даны пошаговые варианты установки и проверки; в [§1.3](chapter-01-03.md) мы перейдём к запуску кода — REPL, файлы и Jupyter.

---

## 1.2.1. Какую версию Python использовать

Для новой разработки и обучения следует использовать **Python 3**. Ветка Python 2 достигла конца жизненного цикла (EOL) в 2020 году; безопасность и исправления больше не выпускаются. Все современные библиотеки для данных (NumPy, Pandas, Scikit-learn) ориентированы на Python 3.

В рамках линейки 3.x обычно берут **последнюю стабильную версию** (например, 3.11 или 3.12 на момент выхода книги). Она доступна на [python.org](https://www.python.org/downloads/). Старые минорные версии (3.8, 3.9) могут понадобиться, если вы поддерживаете проект с жёстко зафиксированной версией или разворачиваете код на сервере, где установлена только она. Для прохождения этой книги подойдёт любая актуальная 3.x (3.9 и новее).

В некоторых системах команда для запуска интерпретатора — `python`, в других — `python3` (чтобы не путать с устаревшим Python 2). В разделе ниже приведены команды с `python3`; если у вас по умолчанию запускается третья версия по команде `python`, подставляйте её вместо `python3`.

## 1.2.2. Установка с официального сайта (Windows, macOS)

Официальный источник дистрибутивов — сайт [python.org](https://www.python.org/). В разделе «Downloads» выбирают операционную систему и скачивают установщик.

**Windows:** скачивают исполняемый установщик (например, «Windows installer (64-bit)»). При установке полезно включить опцию **«Add Python to PATH»**: тогда команды `python` и `pip` будут доступны из любой папки в командной строке. После установки перезапускают терминал (или открывают новый) и проверяют: `python --version` или `py --version` (лаунчер `py` на Windows позволяет выбирать версию, если установлено несколько).

**macOS:** на сайте доступен установщик в виде пакета (.pkg). Он ставит Python в каталог, не конфликтующий с системным Python, поставляемым macOS. После установки в терминале должны быть доступны `python3` и `pip3`. Системный Python в macOS трогать не рекомендуется: он может использоваться системными утилитами.

**Проверка:** в терминале выполните:

```bash
python3 --version
```

(или `python --version` в Windows, если Python добавлен в PATH.) Должна отобразиться строка вида `Python 3.11.x` или `Python 3.12.x`.

## 1.2.3. Установка через пакетный менеджер (Linux и macOS)

На Linux и части дистрибутивов macOS (Homebrew) Python часто ставят через пакетный менеджер. Так вы получаете версию, совместимую с репозиторием ОС, и обновления через стандартные механизмы.

**Debian / Ubuntu:**

```bash
sudo apt update
sudo apt install python3 python3-venv python3-pip
```

Пакет `python3-venv` нужен для создания виртуальных окружений (см. ниже), `python3-pip` — для установки пакетов из PyPI ([§1.4](chapter-01-04.md)).

**Fedora / RHEL и производные:**

```bash
sudo dnf install python3 python3-pip
```

Модуль `venv` входит в стандартную поставку Python 3 в современных Fedora/RHEL.

**macOS (Homebrew):** если установлен [Homebrew](https://brew.sh/):

```bash
brew install python
```

Обычно после этого команда `python3` указывает на версию из Homebrew; `pip3` тоже будет доступен.

Проверка — как и выше: `python3 --version`, при необходимости `which python3`, чтобы убедиться, что используется нужный интерпретатор.

---

## 1.2.4. Проверка установки и расположение интерпретатора

После установки убедитесь, что интерпретатор запускается и что вы вызываете именно ту версию, которую поставили.

- **Версия:**

```bash
python3 --version
```

- **Путь к исполняемому файлу** (чтобы не перепутать с другим Python в системе):

```bash
which python3
```

(В Windows аналог — `where python`.)

- **Краткая интерактивная проверка:** запустите `python3` без аргументов — откроется REPL (подробнее в [§1.3](chapter-01-03.md)). Введите, например, `2 + 2` и нажмите Enter; должно вывестись `4`. Выход из REPL — команда `exit()` или сочетание Ctrl+D (Linux/macOS) / Ctrl+Z и Enter (Windows).

Если версия отображается корректно и REPL реагирует на простые выражения, среда готова к следующему шагу — созданию виртуального окружения.

---

## 1.2.5. Виртуальное окружение (venv)

**Виртуальное окружение** (virtual environment) — изолированный каталог, в котором установлены свой интерпретатор (или ссылка на системный) и отдельный набор пакетов. Проект A может использовать Pandas 1.5, проект B — Pandas 2.0; конфликтов не будет, потому что пакеты ставятся внутрь окружения, а не в общую системную директорию. Для работы с данными и обучением по этой книге рекомендуется завести отдельное окружение под примеры и эксперименты. См. [Глоссарий](glossary.md).

В Python 3 для создания такого окружения используется встроенный модуль **venv**. Дополнительные программы (virtualenv, conda) не обязательны для старта; venv входит в стандартную библиотеку.

**Создание окружения**

Перейдите в каталог вашего проекта (или создайте его) и выполните:

```bash
python3 -m venv .venv
```

Здесь `.venv` — имя каталога окружения (часто используют именно `.venv` или `venv`; точка в начале скрывает папку в Unix). Внутри появятся подкаталоги `bin` (в Windows — `Scripts`), `lib` и др.; там будут копия (или симлинк) интерпретатора и каталог для установки пакетов.

**Активация окружения**

Пока окружение не активировано, команда `python3` в терминале по-прежнему указывает на системный (или глобально установленный) Python. После активации команды `python` и `pip` в этом терминале будут ссылаться на интерпретатор и менеджер пакетов внутри окружения.

**Linux и macOS (bash/zsh):**

```bash
source .venv/bin/activate
```

**Windows (Command Prompt):**

```cmd
.venv\Scripts\activate.bat
```

**Windows (PowerShell):**

```powershell
.venv\Scripts\Activate.ps1
```

После активации в начале строки приглашения обычно появляется префикс `(.venv)` (или другое имя окружения). Тогда:

- `python` запускает интерпретатор из окружения;
- `pip install ...` ставит пакеты только в это окружение.

**Деактивация**

В том же терминале выполните:

```bash
deactivate
```

Префикс исчезнет, снова будет использоваться системный (или другой) Python.

**Типичные ошибки**

- Забыть активировать окружение перед установкой пакетов — тогда `pip install` может поставить их в систему или в другое окружение; всегда проверяйте префикс в приглашении или путь: `which python` после активации должен указывать внутрь `.venv`.
- Создавать venv не той версией Python: если нужна именно 3.11, вызывайте `python3.11 -m venv .venv` (при наличии установленного python3.11).
- Добавлять каталог окружения (`.venv`) в систему контроля версий (Git): его обычно добавляют в `.gitignore` и воссоздают по инструкции в README или по `requirements.txt` ([§1.4](chapter-01-04.md)).

## Ключевое

- Для обучения и новой разработки используйте Python 3 (рекомендуется актуальная стабильная версия, например 3.11 или 3.12); Python 2 снят с поддержки.
- Установить Python можно с [python.org](https://www.python.org/downloads/) (Windows/macOS) или через пакетный менеджер ОС (apt, dnf, Homebrew); на Windows при установке с python.org полезно включить «Add Python to PATH».
- Проверка: `python3 --version`, при необходимости `which python3`; запуск REPL без аргументов (`python3`) и простой ввод `2 + 2` подтверждают работоспособность.
- Виртуальное окружение (venv) изолирует пакеты проекта от системы; создание: `python3 -m venv .venv`; активация: `source .venv/bin/activate` (Linux/macOS) или `.venv\Scripts\activate.bat` / `Activate.ps1` (Windows); деактивация: `deactivate`.
- Перед установкой пакетов окружение нужно активировать; каталог окружения (например, `.venv`) обычно не коммитить в Git.

В [§1.3](chapter-01-03.md) мы разберём способы запуска кода: интерактивная оболочка (REPL), выполнение файла с расширением .py и кратко — Jupyter Notebook/Lab для интерактивного анализа.
