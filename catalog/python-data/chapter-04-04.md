# §4.4 Модули

В [§4.3](chapter-04-03.md) мы разобрали область видимости. Теперь — **модули**: любой файл с расширением **.py** является модулем; в нём можно держать функции, классы и переменные и подключать их в других файлах через **import**. В этом разделе — синтаксис **import** и **from ... import**, а также использование **__name__ == '__main__'**, чтобы код выполнялся только при прямом запуске файла, а не при импорте. В [§4.5](chapter-04-05.md) кратко рассмотрим модули стандартной библиотеки (os, sys, datetime, json).

---

## 4.4.1. Что такое модуль

**Модуль** в Python — это файл с расширением **.py**. Имя модуля совпадает с именем файла без расширения: файл `utils.py` — модуль `utils`. В одном модуле могут быть определения функций, классов, константы и исполняемый код на верхнем уровне. См. [Глоссарий](glossary.md).

При первом **импорте** модуля интерпретатор выполняет весь код в файле сверху вниз; определения (def, class и т.д.) создают объекты и связывают их с именами в пространстве имён модуля. Повторный import того же модуля не выполняет файл заново — используется уже загруженный объект модуля (кэш в `sys.modules`).

Организация кода по модулям позволяет разбивать проект на части, переиспользовать функции в нескольких скриптах и избегать слишком длинных файлов.

---

## 4.4.2. import module

Инструкция **import имя_модуля** загружает модуль (если ещё не загружен) и вносит его имя в текущее пространство имён. Обращение к объектам модуля — через точку: **модуль.имя**.

```python
import math
x = math.sqrt(4)      # 2.0
y = math.pi
```

Имя модуля — это переменная, ссылающаяся на объект модуля; у него есть атрибуты (функции, переменные, определённые в модуле). Так всегда явно видно, откуда взято имя (math.sqrt, os.path.join), что уменьшает путаницу при многих импортах.

**Псевдоним:** **import модуль as псевдоним** — обращаться к модулю по короткому имени:

```python
import numpy as np
a = np.array([1, 2, 3])
```

Несколько модулей в одной строке (стилистически допустимо, но часто лучше по одному импорту на строку):

```python
import os, sys
```

## 4.4.3. from module import name

Форма **from имя_модуля import имя** загружает модуль и вносит в текущее пространство имён указанное имя (функцию, класс, переменную) из модуля. Обращаться можно напрямую, без префикса модуля:

```python
from math import sqrt, pi
x = sqrt(4)   # 2.0
y = pi
```

**from module import \*** — импортирует все публичные имена модуля (те, что не начинаются с подчёркивания). Использовать не рекомендуется: непонятно, откуда пришло имя, возможны перезаписи имён. Лучше импортировать явно перечисленные имена или весь модуль.

**Псевдоним при импорте имени:** **from module import name as alias**:

```python
from pandas import read_csv as load_csv
```

Импорт выполняется один раз при первом обращении; порядок импортов в начале файла по соглашению (PEP 8): сначала стандартная библиотека, затем сторонние пакеты, затем локальные модули; между группами — пустая строка.

## 4.4.4. __name__ == '__main__'

При выполнении кода Python устанавливает специальную переменную **__name__** в каждом модуле. Если файл **запущен напрямую** (например, `python script.py`), в этом файле **__name__** равно строке **'__main__'**. Если файл **импортирован** как модуль, **__name__** равно **имени модуля** (имя файла без .py).

Это используют, чтобы отделить код «запуска» от определений: тесты, демо-вызовы или основной пайплайн выполняются только при прямом запуске файла, а при импорте модуль только определяет функции и классы, не запуская скрипт.

Типичный шаблон в конце файла:

```python
def main():
    # основной код: парсинг аргументов, вызов функций, вывод
    path = "data.csv"
    result = process(path)
    print(result)

if __name__ == "__main__":
    main()
```

При запуске `python script.py` выполнится `main()`; при `import script` в другом файле блок под `if __name__ == "__main__":` не выполнится.

Аргументы командной строки, переданные при запуске (`sys.argv`), удобно обрабатывать именно в таком блоке или в функции main(); подробнее про sys — в [§4.5](chapter-04-05.md).

## 4.4.5. Путь поиска модулей и типичные ошибки

Интерпретатор ищет модули в списке путей (переменная **sys.path**): сначала каталог с запущенным скриптом, затем каталоги из переменной окружения PYTHONPATH, затем каталоги установки Python и стандартной библиотеки. Модуль из того же каталога, что и запускаемый файл, подхватывается по имени файла.

**Типичные ошибки:**

- **ModuleNotFoundError / ImportError:** модуль не найден — проверить имя файла, расширение .py, текущий каталог и что пакет установлен (pip install) или путь добавлен в sys.path/PYTHONPATH.
- **Циклический импорт:** модуль A импортирует B, а B импортирует A; при загрузке может возникнуть обращение к ещё не до конца инициализированному модулю. Решают перестройкой зависимостей (вынести общий код в третий модуль) или отложенным импортом внутри функции.
- Код на верхнем уровне модуля (не в def и не под `if __name__ == '__main__'`) выполняется при любом import — побочные эффекты при импорте (печать, запись в файл) обычно нежелательны; такой код лучше переносить в блок `if __name__ == "__main__":` или в вызываемую функцию.

---

## Ключевое

- **Модуль** — файл .py; имя модуля совпадает с именем файла без расширения. При первом import код модуля выполняется, определения попадают в пространство имён модуля.
- **import module** — загрузка модуля, обращение к объектам через **module.имя**. **import module as alias** — псевдоним модуля.
- **from module import name** — импорт конкретного имени в текущее пространство; обращение без префикса. **from module import name as alias** — псевдоним для имени.
- **__name__ == '__main__'** — истинно только при прямом запуске файла (`python file.py`); при импорте __name__ равно имени модуля. Код запуска/тестов помещают в блок **if __name__ == "__main__":**, чтобы он не выполнялся при импорте.
