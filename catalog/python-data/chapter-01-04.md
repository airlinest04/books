# §1.4 Установка пакетов

В [§1.3](chapter-01-03.md) мы разобрали способы запуска кода — REPL, скрипты .py и Jupyter. Чтобы пользоваться NumPy, Pandas и другими библиотеками, их нужно установить. В этом разделе речь пойдёт о **pip** — стандартном менеджере пакетов Python: откуда берутся пакеты, как ставить один или несколько, как зафиксировать зависимости проекта в файле requirements.txt. После этого среда готова к изучению синтаксиса Python: в [§2.1](chapter-02-01.md) мы начнём с переменных и присваивания.

---

## 1.4.1. pip и PyPI

**pip** — программа для установки пакетов Python из репозитория **PyPI** (Python Package Index). Обычно pip поставляется вместе с Python; в виртуальном окружении после активации доступны команды `pip` и `pip3`. См. [Глоссарий](glossary.md).

PyPI — публичный каталог проектов: авторы публикуют туда пакеты (исходники или «колёса» — бинарные дистрибутивы), а пользователи устанавливают их командой `pip install имя_пакета`. NumPy, Pandas, Scikit-learn, Jupyter и тысячи других библиотек распространяются через PyPI.

**Важно:** всегда устанавливайте пакеты **в активированное виртуальное окружение**. Тогда они попадут в каталог этого окружения и не смешаются с системным Python или другими проектами. Перед установкой проверьте префикс в приглашении терминала (например, `(.venv)`) или выполните `which pip` (Linux/macOS) / `where pip` (Windows) — путь должен указывать внутрь каталога окружения.

## 1.4.2. Установка одного и нескольких пакетов

**Один пакет:**

```bash
pip install numpy
```

pip загрузит пакет и его зависимости с PyPI и установит их в текущее окружение. Имя пакета указывают в нижнем регистре (на PyPI приняты такие имена).

**Несколько пакетов за один раз** — перечислите их через пробел:

```bash
pip install numpy pandas
```

**Конкретная версия:** чтобы зафиксировать версию (например, для воспроизводимости окружения):

```bash
pip install pandas==2.1.0
```

Минимальная версия (не ниже указанной):

```bash
pip install "pandas>=2.0"
```

**Обновление пакета** до последней совместимой версии:

```bash
pip install --upgrade pandas
```

**Просмотр установленных пакетов:**

```bash
pip list
```

Краткая информация о конкретном пакете (версия, расположение, зависимости):

```bash
pip show pandas
```

## 1.4.3. Установка пакетов для работы с данными

Для прохождения этой книги достаточно установить NumPy и Pandas; позже понадобятся Jupyter (если ещё не установлен), Scikit-learn и при необходимости библиотеки для визуализации. Ниже — минимальный набор для Части I и II.

**Базовый набор (NumPy и Pandas):**

```bash
pip install numpy pandas
```

pip автоматически подтянет зависимости (например, у Pandas есть зависимость от NumPy). После установки проверьте в REPL или в скрипте:

```python
import numpy as np
import pandas as pd
print(np.__version__, pd.__version__)
```

**Jupyter** (если планируете работать в ноутбуках):

```bash
pip install jupyter
```

или `pip install jupyterlab` для JupyterLab.

**Для глав по машинному обучению (Часть III):**

```bash
pip install scikit-learn
```

Остальные пакеты (SciPy, Matplotlib, Seaborn и т.д.) можно ставить по мере необходимости; в соответствующих разделах будет указано, что установить.

## 1.4.4. requirements.txt: фиксация зависимостей

Чтобы воспроизвести окружение на другой машине или через время, зависимости проекта записывают в текстовый файл. Стандартное имя — **requirements.txt**. В каждой строке — имя пакета и при необходимости ограничение версии.

**Пример содержимого:**

```text
numpy>=1.24
pandas>=2.0
jupyter
scikit-learn>=1.3
```

**Установка всех зависимостей из файла:**

```bash
pip install -r requirements.txt
```

pip прочитает файл и установит перечисленные пакеты с указанными ограничениями. Так новый разработчик или CI-сервер получает тот же набор версий (в пределах заданных диапазонов).

**Создание requirements.txt из текущего окружения:** если вы уже поставили пакеты и хотите зафиксировать их текущие версии:

```bash
pip freeze > requirements.txt
```

Команда `pip freeze` выводит список всех установленных пакетов в формате `пакет==версия`; перенаправление `>` записывает вывод в файл. Минус такого подхода — в файл попадают и все транзитивные зависимости с жёстко зафиксированными версиями, поэтому файл получается длинным. Для ручного ведения часто пишут только основные пакеты с мягкими ограничениями (как в примере выше); для строгой воспроизводимости (деплой, Docker) используют `pip freeze` или инструменты вроде `pip-tools`.

**Практика:** храните `requirements.txt` в корне проекта и добавьте его в репозиторий; каталог виртуального окружения (`.venv`) в Git не коммитят и перечисляют в `.gitignore`.

## 1.4.5. Типичные ошибки

- **Установка без активированного venv** — пакеты попадают в системный Python или в другое окружение; потом `import numpy` в проекте не находит модуль. Решение: активировать окружение перед `pip install`.
- **Команда pip не найдена** — на некоторых Linux-системах после установки Python через пакетный менеджер для пользовательской установки пакетов нужно вызывать `pip3` или `python3 -m pip`. В venv после активации обычно доступны и `pip`, и `python -m pip`.
- **Ошибки прав доступа** — при установке «в систему» (без venv) может потребоваться `sudo pip install`, что не рекомендуется: лучше использовать виртуальное окружение и не трогать системные пакеты.
- **Сетевые ошибки / таймауты** — PyPI может быть недоступен или медленным; можно указать альтернативный индекс (`pip install -i https://pypi.org/simple/ пакет`) или настроить зеркало.

## Ключевое

- **pip** — стандартный менеджер пакетов Python; пакеты загружаются с **PyPI**. Всегда устанавливайте пакеты в активированное виртуальное окружение.
- Установка: `pip install пакет` или `pip install пакет1 пакет2`; версия — `pip install пакет==1.0` или `пакет>=1.0`; обновление — `pip install --upgrade пакет`.
- Для книги: `pip install numpy pandas`; при необходимости `jupyter`, `scikit-learn`. Проверка: `import numpy`, `import pandas` в REPL или скрипте.
- **requirements.txt** — файл со списком зависимостей (по одной в строке); установка всего списка: `pip install -r requirements.txt`; экспорт текущих версий: `pip freeze > requirements.txt`. Файл хранят в репозитории; .venv — в .gitignore.
