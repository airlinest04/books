# §4.4 Управление сессиями и запросами

В [§4.3](chapter-04-03.md) мы разобрали метрики кластера, очистку и выгрузку данных, а также интеграцию с внешним мониторингом. В этом разделе — **управление сессиями и запросами**: завершение зависших запросов и сессий (Terminate, Cancel), **управление очередью** выполнения (ресурсные группы, статистика очереди в ADB Control), **ограничение ресурсов** (память, параллелизм в ресурсных группах ADB). Материал опирается на [документацию по сессиям](https://docs.arenadata.io/ru/ADB/current/tutorials/adbc/monitoring/sessions.html), [транзакциям](https://docs.arenadata.io/ru/ADB/current/tutorials/adbc/monitoring/transactions.html) и [авторизации](https://docs.arenadata.io/ru/ADB/current/tutorials/adbc/authorization.html). Ресурсные группы создаются и настраиваются в самой СУБД ADB (Greenplum/Greengage); ADB Control позволяет просматривать статистику по ним и в части версий — редактировать параметры. См. [Глоссарий](glossary.md).

## 4.4.1. Завершение зависших запросов и сессий

**Прерывание сессии (Terminate).** Вкладка **Monitoring → Sessions** выводит список клиентских сессий ADB с колонками: Session ID, Resource group, Username, Database, **State** (Active, Idle, Idle in transaction), Application name, Start time, Idle time, Command text, Tags. В верхней части — счётчики Active, Idle, Idle in transaction. По [документации по сессиям](https://docs.arenadata.io/ru/ADB/current/tutorials/adbc/monitoring/sessions.html) для прерывания сессии нужно нажать иконку в столбце **Actions** в строке сессии, в диалоге подтвердить кнопкой **Terminate**. Сессия завершается (вызов `pg_terminate_backend` на стороне ADB), соединение разрывается, сессия пропадает из списка. Это применяют для освобождения пула соединений при «зависших» или долго неактивных сессиях (например, Idle in transaction без завершения транзакции).

Доступ к странице Sessions и возможность прерывания сессий определяются правами пользователя ADB Control: **View sessions** и при необходимости **Kill some queries** / **Kill all queries** (см. п. 4.4.2 про права).

**Отмена транзакции (Cancel и Terminate).** Если нужно остановить выполняющуюся команду или транзакцию, но **не разрывать сессию**, используют отмену транзакции. На вкладке **Monitoring → Transactions → Online** выбирают активную транзакцию, по клику на Transaction ID открывают детали; в заголовке доступны кнопки **Cancel** и **Terminate**. По [документации по транзакциям](https://docs.arenadata.io/ru/ADB/current/tutorials/adbc/monitoring/transactions.html):

- **Cancel** — вызов `pg_cancel_backend`: отмена текущей команды/транзакции в процессе, сессия остаётся, клиент может выполнить следующий запрос.
- **Terminate** — вызов `pg_terminate_backend`: завершение процесса, сессия разрывается.

После успешной отмены транзакция переходит в статус Aborted, входящие в неё команды — в Cancelled. Кнопки доступны только для транзакций в статусе Active; для записей на вкладке History Cancel и Terminate недоступны.

**Права на завершение и отмену.** По [документации по авторизации](https://docs.arenadata.io/ru/ADB/current/tutorials/adbc/authorization.html):

- **Kill self queries** — завершение и отмена только своих транзакций и команд (запущенных в ADB под ролью, совпадающей с пользователем ADB Control или его LDAP-группой).
- **Kill some queries** — завершение и отмена транзакций, к которым у пользователя есть доступ (в рамках назначенных кластеров и БД для роли Advanced User).
- **Kill all queries** — завершение и отмена любых транзакций (роли Administrator, Owner).

Роли Regular User имеют только Kill self queries; для просмотра и завершения чужих сессий/транзакций нужны права Advanced User и выше с соответствующим доступом к кластерам и БД (Users → Access).

## 4.4.2. Управление очередью (ресурсные группы)

В ADB (как и в Greenplum) **ресурсные группы** (resource groups) ограничивают число одновременно выполняемых транзакций и распределяют ресурсы между группами. Запросы, принадлежащие группе с ограниченным параллелизмом (concurrency), при превышении лимита попадают в **очередь** и выполняются по мере освобождения слотов.

**Мониторинг очереди в ADB Control.** В интерфейсе ADB Control раздел **Monitoring → Resource groups** (при его наличии в используемой версии) отображает информацию о ресурсных группах кластеров ADB. На вкладке **Statistic** приводятся метрики по каждой группе: **Running** — число транзакций, выполняющихся в данный момент; **Queueing** — число транзакций в очереди; **Queued** — общее число транзакций, побывавших в очереди за период наблюдений; **Total queued duration** — суммарное время пребывания транзакций в очереди. По этим данным можно оценить загрузку групп и наличие очередей. В документации указано, что **управление ресурсными группами** (редактирование конфигурации) в ADB Control в некоторых версиях (например, 4.15) временно недоступно и планируется к возврату в будущих релизах; актуальность раздела Resource groups и вкладки Configuration следует уточнять по версии вашей установки.

**Очередь на уровне СУБД.** Назначение транзакции ресурсной группе и параметр **Concurrency** (максимальное число одновременно выполняемых транзакций в группе) задаются в самой ADB (SQL: `CREATE RESOURCE GROUP`, `ALTER RESOURCE GROUP`, назначение ролей группе). При исчерпании слотов новые транзакции этой группы ставятся в очередь; время ожидания в очереди может отображаться в ADB Control в колонках, связанных с ресурсной группой (например, в выгружаемых данных сессий — поле `rsgqueueduration`). Управление очередью по сути сводится к настройке ресурсных групп в ADB и при необходимости к завершению части запросов или сессий, чтобы освободить слоты.

## 4.4.3. Ограничение ресурсов (ресурсные группы ADB)

Ресурсные группы в ADB (наследуемые от Greenplum) реализованы на основе механизма **cgroups** в Linux и ограничивают потребление памяти и CPU, а также количество одновременно выполняемых транзакций. Параметры задаются в СУБД (через SQL или конфигурацию при развёртывании), а не только в ADB Control.

**Основные параметры ресурсной группы (в ADB/Greenplum):**

- **memory_limit** — доля памяти (в процентах), выделяемая группе относительно общего объёма, доступного для запросов.
- **memory_spill_ratio** — порог (в процентах), при превышении которого данные начинают выгружаться на диск (spill), чтобы не исчерпывать память.
- **concurrency** — максимальное число транзакций, выполняющихся одновременно в этой группе; остальные ставятся в очередь.

Роли и пользователи ADB привязываются к ресурсной группе (например, `ALTER ROLE ... SET resource_group TO 'group_name'`); все их транзакции учитываются в лимитах этой группы.

**Отображение в ADB Control.** В таблицах **Commands**, **Transactions**, **Sessions** выводится колонка **Resource group** — имя ресурсной группы, к которой отнесена команда/транзакция/сессия. Это позволяет фильтровать и анализировать нагрузку по группам. На странице **Monitoring → Resource groups** (если доступна) вкладка **Configuration** в части версий позволяла просматривать и редактировать параметры групп (в том числе Concurrency); при временном отсутствии этой функциональности изменение параметров выполняется напрямую в ADB (psql, скрипты администрирования). Документация по созданию и изменению ресурсных групп в Greenplum/ADB приведена в руководствах по администрированию СУБД.

## Ключевое

- **Завершение сессий:** Monitoring → Sessions → иконка Actions → Terminate; сессия разрывается, соединение освобождается. Подходит для «зависших» или долго неактивных сессий (Idle in transaction и т.п.).
- **Отмена транзакций:** Monitoring → Transactions → детали транзакции → Cancel (отмена команды/транзакции, сессия остаётся) или Terminate (завершение процесса). Права: Kill self queries (свои), Kill some queries (доступные по БД/кластерам), Kill all queries (все).
- **Очередь:** ресурсные группы ограничивают число одновременно выполняемых транзакций (Concurrency); при превышении запросы ждут в очереди. В ADB Control при наличии раздела Monitoring → Resource groups — вкладка Statistic (Running, Queueing, Queued, Total queued duration). Редактирование групп в UI в некоторых версиях временно недоступно.
- **Ограничение ресурсов:** в ADB задаются параметры ресурсных групп (memory_limit, memory_spill_ratio, concurrency) через SQL; в ADB Control отображаются имя группы в Commands/Transactions/Sessions и при наличии — статистика и конфигурация на странице Resource groups.
