# §4.1 Arenadata DB Control: обзор

В [§3.4](chapter-03-04.md) мы развернули кластер Arenadata DB и получили к нему доступ. В главе 4 рассматриваются **мониторинг и управление** кластером с помощью **Arenadata DB Control (ADB Control)**. В этом разделе — **обзор ADB Control**: назначение системы, доступ к веб-интерфейсу после развёртывания, **основные разделы** интерфейса (Monitoring, Configuration, Dashboard) и **ключевые метрики**, которые администратор видит «на первом экране». Архитектура и детали компонентов ADB Control описаны в [§2.2](chapter-02-02.md); углублённая работа с запросами, метриками, алертами и управлением сессиями — в [§4.2](chapter-04-02.md)–[§4.4](chapter-04-04.md). См. [Глоссарий](glossary.md).

## 4.1.1. Назначение и доступ к веб-интерфейсу

**Arenadata DB Control** — система **мониторинга запросов** Arenadata DB в режиме реального времени. По [обзору ADB Control](https://docs.arenadata.io/ru/ADB/current/tutorials/adbc/overview.html) она обеспечивает: мониторинг SQL-запросов и транзакций (включая планы выполнения и прогресс); мониторинг клиентских сессий с возможностью прерывания «зависших» сессий; сбор метрик потребления ресурсов (CPU, память, I/O, spill) по запросам и транзакциям; построение графиков метрик за выбранный период; отмену выполняющихся транзакций; выгрузку метрик во внешнюю аналитическую БД; аудит обращений к таблицам ADB и действий пользователей в ADB Control. Один экземпляр ADB Control может работать с **несколькими кластерами ADB** одновременно.

**Доступность:** ADB Control входит в состав **ADB Enterprise**; установка возможна только в режиме **offline** (при офлайн-установке кластера через ADCM). Если при развёртывании кластера был добавлен и установлен сервис ADB Control, веб-интерфейс становится доступен после запуска компонентов ADB Control на выделенных хостах. **URL и порт** веб-интерфейса задаются при конфигурировании сервиса ADB Control в ADCM (параметры развёртывания, адрес UI Backend); точное значение берут из конфигурации кластера или у администратора, выполнявшего установку. Обычно доступ выполняется по протоколу HTTP или HTTPS на порт, указанный в настройках (например, `http://<хост_ADB_Control>:<порт>/`). Для входа используются учётные данные пользователей ADB Control (создание и права пользователей настраиваются при установке и в администрировании ADB Control). Рекомендуется синхронизация времени на хостах кластера (Chrony) для корректной работы планировщика задач и метрик.

## 4.1.2. Основные разделы веб-интерфейса

Структура веб-интерфейса ADB Control организована по разделам меню. По [документации по мониторингу](https://docs.arenadata.io/ru/ADB/current/tutorials/adbc/monitoring/commands.html) и [Dashboard](https://docs.arenadata.io/ru/ADB/current/tutorials/adbc/monitoring/chart.html):

**Monitoring** — раздел мониторинга текущего состояния кластеров:

- **Commands** — список SQL-команд: вкладки **Queries** (Online — выполняющиеся и ожидающие; History — завершённые) и **Groups** (группы запросов по SQL ID). Для каждой команды отображаются идентификатор, текст, пользователь, статус, база данных, время выполнения; при переходе в детали — план выполнения (с прогрессом по узлам), метрики производительности (CPU, RAM, I/O, spill), текст запроса.
- **Sessions** — список клиентских сессий ADB: состояние (Active, Idle, Idle in transaction), пользователь, база, время простоя, последняя/текущая команда; возможность прервать сессию (Terminate).
- **Transactions** — мониторинг транзакций (активные, завершённые), отмена выполняющейся транзакции (Cancel).
- **Dashboard** — графики метрик за выбранный период (см. п. 4.1.3).

**Configuration** — настройки ADB Control:

- **Clusters** — список кластеров ADB, подключённых к ADB Control; назначение кластера по умолчанию для фильтров; добавление/редактирование/архивация кластеров; настройки мониторинга по кластеру (базы данных, GUC, выгрузка метрик).
- **Job policy** — политики планировщика: автоматическая очистка старых данных, расписание выгрузки метрик во внешнюю БД (Offload DB).

**Audit** — аудит обращений к таблицам в кластерах ADB и действий пользователей в ADB Control (при включённом аудите).

Навигация между разделами выполняется через боковое или верхнее меню; на страницах Monitoring доступны фильтры по кластеру (по умолчанию подставляется кластер, отмеченный как default в Configuration → Clusters) и по базе данных.

## 4.1.3. Основные метрики (Dashboard и сводки)

Страница **Dashboard** даёт сводное представление о загрузке кластеров за выбранный период. По [документации по Dashboard](https://docs.arenadata.io/ru/ADB/current/tutorials/adbc/monitoring/chart.html) на ней отображаются вкладки с графиками:

| Вкладка | Метрика | Описание |
|---------|---------|----------|
| **Commands** | Число SQL-команд в статусе Running | Количество выполняющихся в данный момент запросов. |
| **Transactions** | Число транзакций в статусе Active | Количество активных транзакций. |
| **CPU** | Общий объём потребляемого CPU (в %) | Загрузка процессора по кластеру. |
| **Memory** | Общий объём выделенной виртуальной памяти (байты) | Потребление памяти. |
| **Read** | Общий объём прочитанных данных (байты) | Дисковое чтение. |
| **Write** | Общий объём записанных данных (байты) | Дисковая запись. |

Для каждой вкладки задаются: **Cluster** (кластер для графиков), **Frequency** (частота обновления), **Time period** (временной диапазон). Режим **View** (Summary / Hosts) позволяет строить график по кластеру в целом или по каждому хосту отдельно. Под графиками выводятся сводные значения: **Current** (последнее значение), **Maximum**, **Minimum**, **Average** за выбранный период.

На странице **Monitoring → Commands** в таблице запросов отображаются столбцы с метриками (Run time, при настройке — CPU, RAM и др.); в деталях команды секция **Performance** показывает метрики по сегментам (CPU usage, RAM, Read/Write, Spill files, skew). На странице **Sessions** в верхней части выводятся счётчики: **Active**, **Idle**, **Idle in transaction** — быстрая оценка количества активных и «висящих» сессий. Эти метрики позволяют быстро оценить нагрузку на кластер и перейти к детальному разбору запросов или сессий в [§4.2](chapter-04-02.md) и [§4.4](chapter-04-04.md).

- **§4.2 Мониторинг запросов в реальном времени** — детальная работа с активными и завершёнными запросами: просмотр планов выполнения, время выполнения, блокировки, фильтры и детали команды.
- **§4.3 Метрики и алерты** — метрики кластера, настройка алертов при сбоях и превышении порогов, интеграция с внешним мониторингом.
- **§4.4 Управление сессиями и запросами** — завершение зависших запросов и сессий, управление очередью, ограничение ресурсов (ресурсные группы).

Если ADB Control не развёрнут (Community-редакция или кластер без сервиса ADB Control), мониторинг выполняется средствами ОС и СУБД (системные представления PostgreSQL/Greenplum, логи, утилиты на хостах); обзор возможностей ADB Control в этом разделе ориентирован на сценарий с установленным ADB Control (Enterprise, offline-установка).

## Ключевое

- **ADB Control** — система мониторинга запросов ADB в реальном времени; входит в ADB Enterprise; установка только offline; один экземпляр может мониторить несколько кластеров. Доступ к веб-интерфейсу — по URL и порту из конфигурации сервиса ADB Control в кластере.
- **Основные разделы:** Monitoring (Commands — запросы Online/History и группы; Sessions — сессии и Terminate; Transactions; Dashboard — графики); Configuration (Clusters, Job policy); Audit.
- **Основные метрики:** на Dashboard — Commands (Running), Transactions (Active), CPU, Memory, Read, Write за выбранный период; на Commands — время выполнения и метрики по запросам; на Sessions — счётчики Active, Idle, Idle in transaction.

В [§4.2](chapter-04-02.md) мы разберём мониторинг запросов в реальном времени: просмотр активных запросов, планы выполнения, время выполнения и блокировки.
