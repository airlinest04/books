# §2.4 Дополнительные инструменты

В [§2.3](chapter-02-03.md) мы разобрали Arenadata DB Backup Manager. В этом разделе рассматриваются **дополнительные инструменты** экосистемы Arenadata: коннекторы для интеграции ADB с внешними системами (Kafka, ClickHouse, другой ADB, Spark), Platform Extension Framework (PXF) для доступа к внешним данным через SQL, утилиты для загрузки данных и администрирования (gpfdist, gpssh и др.), логическое резервное копирование (gpbackup/gprestore), расширения для аналитики и геоданных (MADlib, PostGIS), а также **документация и поддержка**. Эти инструменты дополняют ADCM, ADB Control и ADBM и позволяют строить полный контур загрузки, хранения, интеграции и сопровождения хранилища данных на базе Arenadata DB. Развёртывание кластера с нуля с помощью ADCM начинается в [главе 3](chapter-03-01.md). См. [Глоссарий](glossary.md).

---

## 2.4.1. Коннекторы Arenadata DB

Помимо стандартного доступа по JDBC/ODBC (совместимость с PostgreSQL) Arenadata поставляет **специализированные коннекторы** для интеграции ADB с потоковыми платформами, другими хранилищами и вычислительными средами. По [материалам Arenadata](https://arenadata.tech/products/arenadata-db/):

| Коннектор | Назначение |
|-----------|------------|
| **ADB Kafka Connector** | Интеграция Apache Kafka с Arenadata DB: запись и чтение данных в формате AVRO из топиков Kafka; поддержка CSV и текстового формата; поддержка транзакций в ADB. Документация: [tutorials/connectors/kafka](https://docs.arenadata.io/ru/ADB/current/tutorials/connectors/kafka/overview.html). |
| **ADB ClickHouse Connector** | Передача данных между Arenadata DB и Arenadata QuickMarts/ClickHouse на базе foreign data wrapper и foreign-таблиц; управление учётными данными, настройки соединения, распределение нагрузки по хостам, управление кастомными настройками и освобождение ресурсов. |
| **ADB to ADB Connector** | Двусторонняя передача данных между двумя кластерами Arenadata DB на базе foreign data wrapper и parallel retrieve cursor; автоматическое определение числа обработчиков (QE); транзакционная вставка в режиме master—master; параллельное получение данных сегментами локального кластера напрямую с сегментов удалённого. |
| **ADB Spark Connector** | Распределённый двунаправленный перенос данных между Arenadata DB и Arenadata Hyperwave; оптимизация count, извлечение статистики и ключа распределения из ADB, push-down фильтры, автоматическое формирование схем; запись из Hyperwave в ADB в режимах Append, Overwrite, ErrorIfExists. |

Коннекторы Kafka и ClickHouse входят в **ADB Enterprise** (по сравнительной таблице редакций на сайте Arenadata); коннекторы к Hadoop и JDBC-источникам доступны и в Community. Использование коннекторов позволяет строить пайплайны загрузки из Kafka в DWH, репликации между кластерами ADB или обмена данными с ClickHouse и Spark без выгрузки в файлы и ручного COPY.

## 2.4.2. Platform Extension Framework (PXF)

**Platform Extension Framework (PXF)** — фреймворк для **параллельного обмена данными** со сторонними системами хранения и обработки. По [материалам Arenadata](https://arenadata.tech/products/arenadata-db/), PXF обеспечивает: кластеризацию, шардирование и учёт локальности данных в каждом компоненте хранения; **межкомпонентный массово-параллельный проброс предикатов запроса** (в том числе во внешние системы); специализированный движок виртуализации данных; **единую точку входа** для SQL-запросов к разнородным источникам. Поддерживаются интеграции с Hadoop, S3, объектными хранилищами и другими системами, для которых реализованы коннекторы PXF.

С точки зрения пользователя ADB: через PXF можно создавать **внешние таблицы** (foreign tables), обращение к которым выполняется параллельно сегментами кластера; данные при этом остаются во внешней системе (например, в HDFS или S3), а не копируются в ADB. Это удобно для «озёр данных», гибридных сценариев (часть данных в ADB, часть — во внешнем хранилище) и загрузки данных из внешних источников без промежуточных файлов на координаторе. Документация по PXF входит в раздел документации Arenadata DB на [docs.arenadata.io](https://docs.arenadata.io/ru/ADB/current/introduction/intro.html); в книге по Greenplum PXF разбирается отдельно (см. [§1.4](chapter-01-04.md) — связь с книгой по Greenplum).

## 2.4.3. Утилиты загрузки и администрирования

Arenadata DB наследует утилиты экосистемы Greenplum/Greengage для загрузки данных и управления кластером. Основные:

- **gpfdist** — демон для **параллельной загрузки** данных из файлов в ADB. Клиенты (сегменты) подключаются к gpfdist и читают части файла параллельно; это существенно быстрее загрузки через единственное соединение (например, COPY с локального файла на координаторе). Используется в ETL-сценариях при загрузке больших объёмов из CSV, текстовых и других форматов.
- **gpssh, gpscp** — утилиты для выполнения команд и копирования файлов на **нескольких хостах** кластера по списку из конфигурации (hostfile). Удобны для администрирования (установка пакетов, сбор логов, проверка дисков) без входа на каждый хост по отдельности.
- **gpbackup / gprestore** — инструменты **логического** резервного копирования и восстановления (схемы, метаданные, выборочные таблицы или базы). В отличие от ADBM (бинарные бэкапы на базе pgbackrest) gpbackup/gprestore создают логические дампы и подходят для переноса данных между кластерами, выборочного восстановления таблиц и миграции. ADBM и gpbackup дополняют друг друга: ADBM — для полного PITR и restore points; gpbackup — для переноса схем и выборочных данных. В документации ADBM упоминается CLI для работы с логическими бэкапами; детали — в руководствах по [gpbackup](https://docs.arenadata.io/ru/ADB/current/)/соответствующих разделах документации ADB.

Остальные утилиты (gpstart, gpstop, gpstate, gprecoverseg и т.д.) описаны в документации по эксплуатации ADB и Greenplum/Greengage; они входят в поставку ADB и доступны после установки кластера.

## 2.4.4. Расширения: MADlib и PostGIS

По [материалам Arenadata](https://arenadata.tech/products/arenadata-db/) о возможностях ADB, поддерживаются расширения для аналитики и работы с геоданными:

- **MADlib** — библиотека алгоритмов машинного обучения и статистики, выполняемых **внутри БД** (на данных в таблицах ADB). Линейная регрессия, нейронные сети, кластеризация и другие функции доступны через SQL-функции после установки и включения расширения. Удобно для предиктивной аналитики и экспериментов без выгрузки данных во внешние ML-платформы.
- **PostGIS** — расширение для работы с **геоданными** (геометрия, координаты, пространственные запросы). Подходит для сценариев с географической привязкой (логистика, ритейл, телеком).

Установка и настройка MADlib и PostGIS описываются в документации Arenadata DB и в книге по Greenplum (MADlib и геоданные). Совместимость с Greenplum/Greengage сохраняется: расширения, работающие в Greenplum, как правило применимы в ADB при той же версии ядра.

## 2.4.5. Документация и поддержка

**Документация** по продуктам Arenadata публикуется на портале [docs.arenadata.io](https://docs.arenadata.io/ru/ADB/current/introduction/intro.html). Доступны разделы:

- Arenadata DB (введение, архитектура, планирование, установка, концепции данных, SQL, туториалы по ADB Control, ADBM, коннекторам, эксплуатация).
- Arenadata Cluster Manager (ADCM): установка, требования, работа с кластерами и бандлами, API.
- Руководства по установке и управлению для каждого продукта (ADB, ADH, ADQM, ADS, ADPG и др.).

Документация поддерживается на **русском и английском** языках и обновляется в соответствии с релизами продуктов. Для быстрого старта полезны разделы «Начало работы» (Get started) и туториалы по установке ADB через ADCM, настройке ADB Control и ADBM.

**Техническая поддержка** предоставляется вендором Arenadata по тарифам (8/5 или 24/7, базовый и расширенный уровни); обращения принимаются через [службу поддержки](https://arenadata.tech/support/). **Обучение:** учебный центр Arenadata проводит курсы по Arenadata DB (для аналитиков, для разработчиков, полный курс по эксплуатации). **Сообщество:** для ADCM доступен открытый Telegram-канал [t.me/arenadata_cm](https://t.me/arenadata_cm); для Greengage — [t.me/greengagedb](https://t.me/greengagedb). При возникновении вопросов по конфигурации, миграции или интеграции имеет смысл обращаться к актуальной документации и при необходимости — в поддержку или на курсы.

## 2.4.6. Типичные ошибки при выборе инструментов

- **Подменять ADBM логическим бэкапом:** ADBM решает задачу бинарного PITR и restore points; для выборочного переноса схем/таблиц или миграции между кластерами нужны gpbackup/gprestore или ETL. Оба подхода можно использовать в одной инфраструктуре.
- **Ожидать коннекторы Kafka/ClickHouse в Community-редакции:** по сравнительной таблице Arenadata они входят в Enterprise; в Community доступны коннекторы к Hadoop и JDBC-источникам.
- **Игнорировать PXF при наличии внешних данных в HDFS/S3:** загрузка через единое соединение или выгрузка во временные файлы масштабируются хуже; PXF даёт параллельный доступ к внешним данным из SQL.
- **Искать документацию только на английском:** портал docs.arenadata.io поддерживает русскую и английскую версии; при установке и настройке удобно использовать раздел на русском.

## Ключевое

- **Коннекторы:** ADB Kafka Connector (Kafka ↔ ADB, AVRO и др.), ADB ClickHouse Connector (ADB ↔ ClickHouse, FDW), ADB to ADB Connector (два кластера ADB), ADB Spark Connector (ADB ↔ Arenadata Hyperwave); Kafka и ClickHouse — в Enterprise.
- **PXF** — фреймворк параллельного доступа к внешним данным (Hadoop, S3 и др.); единая точка входа для SQL к внешним источникам; внешние таблицы без копирования данных в ADB.
- **Утилиты:** gpfdist (параллельная загрузка из файлов), gpssh/gpscp (управление хостами), gpbackup/gprestore (логические бэкапы и перенос данных); остальные утилиты Greenplum/Greengage входят в поставку ADB.
- **Расширения:** MADlib (ML и статистика в БД), PostGIS (геоданные); установка и использование — по документации ADB и Greenplum.
- **Документация и поддержка:** [docs.arenadata.io](https://docs.arenadata.io/ru/ADB/current/introduction/intro.html) (русский и английский), техническая поддержка Arenadata, курсы, Telegram (arenadata_cm, greengagedb).

В [§3.1](chapter-03-01.md) мы начнём главу «Развёртывание с ADCM»: подготовка окружения для установки кластера Arenadata DB — требования к ОС, CPU, RAM, сети, пользователям и SSH.
