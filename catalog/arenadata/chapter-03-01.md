# §3.1 Подготовка окружения

В [§2.4](chapter-02-04.md) мы завершили обзор компонентов и дополнительных инструментов Arenadata. С этого раздела начинается **глава 3 «Развёртывание с ADCM»**: пошаговая подготовка и установка кластера Arenadata DB. **Подготовка окружения** — это проверка и выполнение требований к оборудованию (CPU, RAM, диски), операционной системе, сети, пользователям и SSH до того, как в ADCM будет создан кластер и запущена установка. В этом разделе вы узнаете минимальные требования к хостам координатора и сегментов ADB, к хостам ADB Control и ADBM (если они используются), программные требования (ОС, Docker, Java, локали, репозитории), предварительную настройку ОС (/etc/hosts, SELinux, sshd, лимиты, firewall, параметры ядра), а также типовые рекомендации по размещению узлов и доступу по SSH. Документация предупреждает: указанные значения **минимальны**; целевой сайзинг нужно рассчитывать под нагрузку организации. Детальные шаги установки ADCM и развёртывания кластера — в [§3.2](chapter-03-02.md)–[§3.4](chapter-03-04.md). См. [Глоссарий](glossary.md).

## 3.1.1. Требования к оборудованию (ADB)

По [документации по требованиям к оборудованию](https://docs.arenadata.io/ru/ADB/current/planning/requirements/hardware.html), минимальные требования к хостам **Arenadata DB** следующие. Указания даны для физических серверов; при использовании виртуальных машин ресурсы должны быть выделены соответствующим образом.

**Хост координатора (Master):**

- CPU: от **8 ядер**.
- RAM: от **16 ГБ**.
- Диск: отдельный физический неформатированный массив **RAID 10** (от **5 ГБ**).

**Сегмент-хосты (Segment hosts):**

- CPU: от **16 ядер**.
- RAM: от **32 ГБ**.
- Диск: один или несколько физических неформатированных массивов **RAID 10** (от **10 ГБ** каждый).

Число сегмент-хостов и объём дисков определяются объёмом данных и целевой производительностью; минимальная конфигурация кластера по документации ADB — несколько узлов (координатор + сегменты). Рекомендуемая файловая система для данных ADB — **XFS** (оптимальная производительность и стабильность; указывается в документации по программным требованиям).

## 3.1.2. Требования к оборудованию (ADB Control и ADBM)

При использовании **ADB Control** и **ADBM** (редакция ADB Enterprise) к расчёту ресурсов добавляются хосты или контейнеры этих сервисов.

**Хост с ADB Control** (минимальные требования по компонентам; по [документации](https://docs.arenadata.io/ru/ADB/current/planning/requirements/hardware.html)):

| Сервис | CPU (ядра) | RAM | Диск | Примечание |
|--------|------------|-----|------|------------|
| Backend Server | 6 | 16 ГБ | — | Возможен доп. мониторинг очередей метрик. |
| Scheduler | 2 | 4 ГБ | — | Зависит от настроек job (тайм-ауты, батчи). |
| Metrics DB (ClickHouse) | 4 | 16 ГБ | 100 ГБ | Рекомендуется RAM порядка сжатых данных в ClickHouse. |
| Query DB (PostgreSQL) | 4 | 8 ГБ | 200 ГБ | Контроль места между запусками cleanup. |
| Прочие (Web UI, UI Backend, Service Registry) | 4 | 20 ГБ | 10 ГБ | — |
| **Итого** | **20** | **64 ГБ** | **310 ГБ** | — |

На каждом **хосте ADB**, где установлен агент ADB Control: CPU от 4 ядер, RAM от 4 ГБ.

**Хост с ADBM:** ADBM может стоять на том же хосте, что и ADB Control, или на отдельном. Минимум для хоста с ADBM (Backup Manager, Service Registry, etcd): CPU от 4 ядер, RAM от 12 ГБ, диск от 10 ГБ. На каждом **сегмент-хосте ADB** агент ADBM и pgbackrest при бэкапе используют порядка **30% CPU** и **2 ГБ RAM** (при однопоточном процессе бэкапирования). Для работы агентов ADBM между сегмент-хостами рекомендуется сеть **не ниже 1 Гбит/с**; для интенсивных бэкапов — **10–25 Гбит/с**.

**Arenadata Enterprise Tools (ET):** при offline-установке используется хост с ET; рекомендации: виртуальный сервер, CPU от 4 ядер, RAM от 8 ГБ, диск от 50 ГБ.

## 3.1.3. Программные требования: ОС, Docker, Java, репозитории

По [документации по программным требованиям](https://docs.arenadata.io/ru/ADB/current/planning/requirements/software.html):

**Поддерживаемые операционные системы для ADB:**

- **Ubuntu 22.04** (с учётом требований для Astra/Ubuntu — см. ниже).
- **Alt Linux 10.2 SP** (для Enterprise-версии ADB).
- **РЕД ОС 7.3** Сертифицированная редакция (для Enterprise).
- **Astra Linux 1.7.6** «Орёл» SE и «Воронеж» (для Enterprise); для Astra и Ubuntu рекомендуется использовать **generic-ядра** (не lowlatency) для аналитической нагрузки.

**Docker:** ADB использует Docker для контейнеризации части сервисов (ADB Control, ADBM, Enterprise Tools). Поддерживаются версии Docker, поставляемые вендорами ОС; возможна опция «Use existing docker» при конфигурировании кластера. Начиная с ADB 6.27.1 сервис ADB Control перезаписывает настройки в `/etc/docker/daemon.json` в целях безопасности; при необходимости своих настроек используют «Use existing docker» (в том числе для rootless Docker).

**Java 17:** требуется для PXF, ADB Control, ADBM. В Ubuntu, РЕД ОС и Alt Linux Java обычно поставляется с ОС; в **Astra Linux** перед установкой ADB нужно установить Java 17 и указать `JAVA_HOME` при конфигурировании кластера. Пути по умолчанию: Ubuntu — `/usr/lib/jvm/java-17-openjdk-amd64`, РЕД ОС — `/usr/lib/jvm/jre-17-openjdk`, Alt Linux — `/usr/lib/jvm/jre-17`.

**Локаль:** на всех хостах кластера должна быть доступна локаль **en_US.UTF-8** (не обязательно по умолчанию). Во всех поддерживаемых ОС, кроме Astra Linux, она есть по умолчанию; в Astra Linux добавляется при установке ADB. Проверка: `localectl list-locales`.

**Репозитории:** для **online-установки** все хосты должны иметь доступ к репозиториям Arenadata (Arenadata repo url, Monitoring repo url — задаются в конфигурации кластера в ADCM). Для **offline-установки** нужен доступ к хосту с развёрнутым Enterprise Tools. Для обоих вариантов необходим доступ к официальным репозиториям ОС со всех хостов (или локальные зеркала): Alt Linux (ftp.altlinux.org), Astra Linux (download.astralinux.ru), РЕД ОС (repo.red-soft.ru, repo1.red-soft.ru), Ubuntu (archive.ubuntu.com/ubuntu).

**Прочее:** рекомендуется отключать антивирус на хостах ADB перед установкой и при эксплуатации (или согласовать исключения с поставщиком антивируса). Имена баз данных в ADB — только латинские буквы и цифры; не использовать зарезервированные символы (`"`, `&`, `'`, пробел, скобки, `;`, `<`, `>`, `\`, `` ` ``, `|`) — иначе ADBM не сможет выполнить бэкап/восстановление этих баз. Минимальная версия **ADCM** для установки ADB — 2.6.0; для ADB 7 при использовании ADBM — ADBM не ниже 2.8.0, ADB Control — не ниже 4.15.0.

## 3.1.4. Предварительная настройка ОС

Перед установкой ADB на хостах кластера необходимо выполнить ряд настроек ОС. Их можно применить **вручную** на всех хостах или выбрать соответствующие **конфигурационные параметры сервиса ADB** в ADCM — тогда настройки будут применены автоматически при установке. Перед установкой рекомендуется запустить действие **Precheck** в ADCM — оно в том числе проверяет параметры ОС. По [документации](https://docs.arenadata.io/ru/ADB/current/planning/requirements/software.html):

| Требование | Параметр в конфигурации ADB | Примечание |
|------------|-----------------------------|------------|
| **/etc/hosts** | Edit /etc/hosts | Должны быть прописаны имена всех хостов кластера (master, standby master, сегменты). Альтернатива — DNS. |
| **SELinux отключён** | Disable linux security module | Требует перезагрузки хостов. |
| **IPv6 отключён** | Disable IPv6 | — |
| **sshd: MaxStartups** | Set up MaxStartups for sshd | Значение `1000:30:1022`. |
| **Transparent Huge Pages отключены** | Set up GRUB for DBMS | Требует перезагрузки. |
| **Лимиты для пользователя БД** | Set up ulimits for DBMS user | В /etc/security/limits.conf: открытые файлы — 524288 (мягкий и жёсткий лимит), процессы — 150000. |
| **Firewall отключён** | Disable firewall | На хостах ADB. |
| **Параметры ядра (sysctl)** | Sysctl parameters | Набор параметров kernel.*, net.*, vm.* (core_pipe_limit, msgmax, sem, shmmni, rmem_max, wmem_max, tcp_max_syn_backlog, dirty_*, overcommit_memory, swappiness и др.). Полный список — в документации. |

Для применения настроек **Disable linux security module** и **Set up GRUB for DBMS** после установки нужна **перезагрузка** хостов. При выполнении действия Install (или Reinstall) в ADCM следует установить флаг **Reboot cluster servers after installation**; при добавлении новых хостов (Expand, Move Host Segment, Init Standby Master) — соответствующие флаги перезагрузки новых серверов. Без перезагрузки эти настройки не вступят в силу. В процессе установки ADB изменяются файлы `/etc/ssh/sshd_config`, `/etc/security/limits.conf`, при установке Chrony — `/etc/chrony.conf`; создаётся сервис cgroup для ADB и файлы в `/sys/fs/cgroup`. Не рекомендуется менять эти объекты вручную после установки; изменения расписания и аргументов скриптов обслуживания — через конфигурационные параметры ADB в ADCM.

## 3.1.5. Пользователи и SSH

Установка кластера ADB через ADCM выполняется с **хоста, где запущен ADCM** (или с выделенного сервера управления), путём запуска Ansible-сценариев на целевых хостах. Для этого необходимо:

- **SSH-доступ** с хоста ADCM (или с узла, с которого Ansible подключается к хостам) на **все хосты кластера ADB** под пользователем, имеющим права на установку пакетов и настройку системы (как правило, с правами sudo или root). Пароли или ключи задаются при настройке хостпровайдера в ADCM (SSH-хост или облачный провайдер).
- На хостах ADB при установке создаётся **системный пользователь БД** (по умолчанию **gpadmin**); для него настраиваются лимиты (ulimits) и cron для скриптов обслуживания. Доступ к `crontab -e -u gpadmin` должен быть у технических учётных записей, используемых для администрирования.
- Параметр **MaxStartups** в sshd должен быть установлен в `1000:30:1022`, чтобы при массовом параллельном подключении сегментов (например, при запуске кластера) не происходило отказов по SSH. Эта настройка входит в предварительную настройку ОС (см. выше) и может быть применена автоматически через конфигурацию ADB в ADCM.

Перед добавлением хостов в кластер в ADCM необходимо завести **хостпровайдера** (Hostprovider) — например, тип SSH с указанием списка хостов, учётных данных и путей к ключам. Детали добавления хостов и хостпровайдеров — в [§3.3](chapter-03-03.md).

## 3.1.6. Сеть и размещение узлов

**Сеть:** между всеми хостами кластера ADB (координатор и сегменты) должен быть стабильный сетевой доступ с низкой задержкой; межсегментный обмен данными (interconnect) чувствителен к задержкам и потерям. Для агентов ADBM между сегмент-хостами минимально — 1 Гбит/с, для интенсивных бэкапов рекомендуется 10–25 Гбит/с. Синхронизация времени (NTP/Chrony) на всех хостах обязательна для корректной работы ADB Control, ADBM и согласованности логов; при установке ADB можно включить установку Chrony через конфигурацию.

**Размещение узлов:** при планировании размещения учитывают:

- **Координатор (Master)** и **Standby Master** (если используется) — на отдельных хостах; standby обычно в другой стойке/ЦОД для отказоустойчивости.
- **Сегменты** — равномерное распределение по хостам; на одном хосте может быть несколько сегментов (и при необходимости зеркала). Диски для данных — отдельные массивы RAID 10, не занятые ОС и другими сервисами.
- **ADB Control** и **ADBM** — могут быть на одном хосте или на разных; при совмещении учитывают суммарные требования по CPU, RAM и диску. Хост(ы) ADB Control/ADBM могут быть вне набора сегмент-хостов (отдельные серверы управления).

Минимальная конфигурация кластера по документации — несколько машин (например, 1 координатор + 3 сегмент-хоста); точный состав задаётся при создании кластера в ADCM и распределении компонентов по хостам (Mapping). Подробнее добавление хостов и Mapping — в [§3.3](chapter-03-03.md).

## 3.1.7. Типичные ошибки при подготовке окружения

- **Использовать минимальные требования как целевые:** они рассчитаны на минимально рабочую конфигурацию; для продакшена нужен запас по CPU, RAM и дискам и учёт пиковой нагрузки и роста данных.
- **Пропустить Precheck:** действие Precheck в ADCM проверяет параметры ОС и окружения до установки; его запуск снижает риск неудачной установки из-за неподходящих лимитов, ядра или сети.
- **Не перезагрузить хосты после установки при включённых SELinux/GRUB-настройках:** если были выбраны параметры Disable linux security module или Set up GRUB for DBMS, без перезагрузки настройки не применятся; нужно установить флаг перезагрузки при Install или перезагрузить хосты вручную после установки.
- **Забыть про локаль en_US.UTF-8 в Astra Linux:** в этой ОС локаль может отсутствовать по умолчанию; при установке ADB она добавляется автоматически, но при ручной подготовке образов её нужно учесть.
- **Использовать lowlatency-ядро в Ubuntu/Astra:** для аналитической СУБД рекомендуется generic-ядро; lowlatency может не дать оптимальной производительности для типичной нагрузки ADB.

## Ключевое

- **Оборудование ADB:** координатор — от 8 CPU, 16 ГБ RAM, диск RAID 10 от 5 ГБ; сегмент-хосты — от 16 CPU, 32 ГБ RAM, диски RAID 10 от 10 ГБ каждый. Рекомендуемая ФС — XFS.
- **ADB Control/ADBM:** хост ADB Control — суммарно от 20 CPU, 64 ГБ RAM, 310 ГБ диска (Backend, Scheduler, Metrics DB, Query DB, UI и др.); хост ADBM — от 4 CPU, 12 ГБ RAM, 10 ГБ диска; на сегмент-хостах агенты ADBM — ~30% CPU и 2 ГБ RAM при бэкапе. Сеть для ADBM — не ниже 1 Гбит/с, рекомендуется 10–25 Гбит/с.
- **ПО:** ОС из списка (Ubuntu 22.04, Alt 10.2, РЕД ОС 7.3, Astra 1.7.6); Docker; Java 17; локаль en_US.UTF-8; доступ к репозиториям Arenadata (online) или к хосту ET (offline) и к репозиториям ОС. ADCM не ниже 2.6.0.
- **Преднастройка ОС:** /etc/hosts (или DNS), отключение SELinux и IPv6, sshd MaxStartups, отключение THP (GRUB), ulimits для пользователя БД (524288 файлов, 150000 процессов), отключение firewall, набор sysctl. Применяется вручную или через параметры сервиса ADB в ADCM; для части настроек нужна перезагрузка — использовать флаги при Install/Expand.
- **Пользователи и SSH:** SSH-доступ с узла управления на все хосты кластера под пользователем с правами sudo/root; настройка хостпровайдера в ADCM. Сеть: стабильный низколатентный доступ между всеми узлами, NTP/Chrony, при использовании ADBM — достаточная пропускная способность.

В [§3.2](chapter-03-02.md) мы разберём установку ADCM: получение дистрибутива, установка ADCM и первый запуск веб-интерфейса.
