## Подробное содержание

### Глава 1. Хранилище данных: цели и принципы

- **1.1 Определение хранилища данных (DWH)** — единый источник правды для аналитики и отчётности; отличия от операционных систем (OLTP).
- **1.2 Цели DWH** — поддержка решений на основе данных; историчность; согласованность; производительность аналитических запросов.
- **1.3 Принципы построения** — предметная ориентация, интеграция источников, неизменяемость истории (или версионирование), временная привязка; по Инмону и практике.
- **1.4 Жизненный цикл данных в DWH** — поступление из источников, слои хранения, потребление отчётами и аналитикой.
- *Ключевое:* определение DWH, цели, принципы. *Задания:* формулирование целей DWH для кейса, проверка соответствия принципам.

---

### Глава 2. Подход Инмона и подход Кимбалла

- **2.1 Подход Билла Инмона** — нормализованное хранилище предприятия (EDW) как ядро; данные хранятся в 3NF или близко; витрины как подмножества для доменов.
- **2.2 Подход Ральфа Кимбалла** — хранилище как совокупность витрин; схемы «звезда»/«снежинка»; с самого начала проектирование под запросы.
- **2.3 Сравнение подходов** — таблица: структура, источник проектирования, гибкость, сложность внедрения, типичные сценарии.
- **2.4 Гибридные и современные варианты** — данные озеро + витрины; Data Vault; когда что уместно.
- *Ключевое:* отличия Инмон vs Кимбалл, область применимости. *Задания:* выбор подхода для заданного контекста, аргументация.

---

### Глава 3. Слои данных (Data Layering)

- **3.1 Зачем делить на слои** — разделение сырых, очищенных и готовых к потреблению данных; переиспользование, аудит, перезапуск пайплайнов.
- **3.2 Классические слои** — Raw / Landing (сырые), Staging / ODS (очистка и согласование), Core / DWH (интегрированное хранилище), Mart / Presentation (витрины для отчётов и BI).
- **3.3 Наименования и варианты** — отличия в терминологии (Bronze/Silver/Gold и др.); соответствие целям слоя.
- **3.4 Правила перехода между слоями** — что можно и нельзя на каждом слое; идемпотентность и повторяемость загрузок.
- *Ключевое:* назначение каждого слоя, правила. *Задания:* разметка пайплайна по слоям, предложение слоёв для кейса.

---

### Глава 4. Схема «звезда» и схема «снежинка»

- **4.1 Измерения и факты** — фактовая таблица (меры, ключи измерений); таблицы измерений (атрибуты сущности); примеры (продажи, заказы).
- **4.2 Схема «звезда» (Star Schema)** — одна таблица фактов и несколько таблиц измерений без дальнейшей нормализации измерений; плюсы: простые запросы, производительность.
- **4.3 Схема «снежинка» (Snowflake)** — нормализованные измерения (иерархии вынесены в отдельные таблицы); плюсы и минусы по сравнению со «звездой»; роль измерений (role-playing dimensions) — одно измерение в нескольких ролях в факте.
- **4.4 Выбор схемы** — по типу запросов, по объёму и изменчивости измерений; комбинирование.
- **4.5 Типы фактов** — транзакционная таблица фактов; периодический снимок (periodic snapshot); накопительный снимок (accumulating snapshot); когда какой тип.
- **4.6 Агрегатные таблицы и мини-витрины** — предрасчёт для ускорения отчётов; обновление агрегатов.
- *Ключевое:* факт/измерение, звезда vs снежинка, типы фактов. *Задания:* построение звёздной схемы по описанию, обоснование выбора схемы.

---

### Глава 5. Обработка изменений (SCD — Slowly Changing Dimensions)

- **5.1 Зачем отслеживать историю измерений** — изменение атрибутов во времени (переименование, смена иерархии); корректность исторических отчётов.
- **5.2 Типы SCD** — Type 1 (перезапись), Type 2 (новая строка, флаги/даты), Type 3 (отдельные столбцы для старого значения); кратко о других.
- **5.3 Реализация Type 2** — суррогатный ключ, effective_from / effective_to, is_current; логика в ETL при обновлении измерения.
- **5.4 Срезы по дате и запросы к истории** — как писать запросы к измерению «на дату»; связь с фактами по периоду действия.
- *Ключевое:* типы SCD, реализация Type 2. *Задания:* выбор типа SCD для атрибутов, написание логики обновления (псевдокод/SQL).

---

### Глава 6. Витрины данных (Data Marts) и их место в архитектуре

- **6.1 Определение витрины данных (Data Mart)** — подмножество данных DWH, ориентированное на домен или группу пользователей; упрощённая модель для отчётов.
- **6.2 Роль в архитектуре** — между DWH и BI/отчётами; зависимые витрины (от DWH) vs независимые (риски).
- **6.3 Проектирование витрины** — от требований отчётов к структуре; денормализация, агрегаты, срезы.
- **6.4 Обновление витрин** — полная перезагрузка vs инкремент; расписание и зависимость от загрузки DWH.
- *Ключевое:* определение Data Mart, место в архитектуре, проектирование. *Задания:* описание витрины по списку отчётов, план обновления.
