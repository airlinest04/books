# §8.1 Микропакетная обработка

В [§7.4](chapter-07-04.md) мы завершили главу об агрегациях, окнах и соединениях. Глава 8 кратко знакомит с **Spark Streaming** — обработкой потоковых данных. В современном API Spark для потоков используется **Structured Streaming**: поток представляется как «бесконечная» таблица, а движок обрабатывает его **микропакетами** (небольшими порциями). В этом разделе рассмотрим идею Structured Streaming, **триггеры** (когда запускать очередной микропакет) и вывод результатов в консоль, файл или внешнюю систему. Подробности источников и приёмников — в [§8.2](chapter-08-02.md). См. [Глоссарий](glossary.md).

---

## 8.1.1. Structured Streaming: поток как бесконечная таблица

**Structured Streaming** — API потоковой обработки в Spark, построенный поверх того же движка, что и пакетные DataFrame и Spark SQL. Поток данных (сообщения из Kafka, новые файлы в каталоге и т.д.) рассматривается как **непрерывно растущая таблица**: к ней постоянно «добавляются» новые строки. Запрос (выборка, фильтр, агрегация, окна) применяется к этой таблице; Spark периодически выполняет **микропакет** — обрабатывает очередную порцию новых данных и обновляет результат. См. [Глоссарий](glossary.md).

С точки зрения кода поток чтения выглядит как **DataFrame**: **spark.readStream** вместо **spark.read**, далее те же трансформации (select, filter, groupBy, join с статическими таблицами). Выполнение запускается не действием вроде **count()** или **write**, а методом **writeStream**: задаётся приёмник (куда писать) и опции (триггер, режим вывода). См. [§5.3](chapter-05-03.md), [§6.1](chapter-06-01.md).

---

## 8.1.2. Триггеры: когда обрабатывать следующий микропакет

**Триггер** определяет, как часто запускается обработка новой порции данных. Задаётся в **.trigger()** у **writeStream**. См. [Глоссарий](glossary.md).

- **ProcessingTime(interval)** — по таймеру, например каждые 10 секунд: **.trigger(processingTime="10 seconds")**. Обрабатываются все данные, поступившие к моменту запуска. Простой и предсказуемый вариант для многих сценариев.
- **Once** — один микропакет (все доступные на момент запуска данные), затем поток останавливается; удобно для «обработать всё что есть и завершиться».
- **Continuous** (экспериментальный режим) — очень низкая задержка, поддерживается не для всех источников и приёмников.

Пример:

```python
df_stream = spark.readStream.schema(schema).parquet("/path/to/input")
df_stream.writeStream \
  .format("console") \
  .trigger(processingTime="5 seconds") \
  .start()
```

Без **trigger** по умолчанию используется режим, обрабатывающий данные по мере поступления (микропакет за микропакетом). См. [§8.2](chapter-08-02.md).

## 8.1.3. Режимы вывода: append, complete, update

При потоковой агрегации или окнах результат может обновляться. Режим вывода (**outputMode**) задаётся в **.outputMode(...)** у writeStream. См. [Глоссарий](glossary.md).

- **append** — в приёмник добавляются только **новые** строки результата (подходит для запросов без агрегации или с агрегацией по окну времени с watermark: каждая строка выводится один раз). Для глобальных агрегатов без watermark append не допускается.
- **update** — в приёмник выводятся только **изменившиеся** строки результата (обновлённые или новые); строки, не изменившиеся с прошлого микропакета, не дублируются. Подходит для агрегатов с обновлением по ключу.
- **complete** — каждый микропакет выводит **полный** результат (например, полная таблица агрегатов). Подходит для небольших итоговых наборов; при большом объёме результата нагрузка на приёмник высокая.

Выбор режима зависит от типа запроса и возможностей приёмника (консоль, файл, Kafka и т.д.). См. [§8.2](chapter-08-02.md), [§8.3](chapter-08-03.md).

## 8.1.4. Вывод в консоль, файл и внешнюю систему

**Приёмник (sink)** задаётся через **.format(...)** в writeStream. См. [Глоссарий](glossary.md).

- **console** — вывод каждой порции результата в консоль драйвера (для отладки и демонстрации). **.format("console")**.
- **parquet** (и другие файловые форматы) — запись в каталог; обычно с **checkpointLocation** для восстановления при перезапуске. Каждый микропакет может писать в отдельный подкаталог. **.format("parquet").option("path", "/path/to/output")**.
- **kafka** — запись в топики Kafka; настройки брокеров и топика через **.option()**. **.format("kafka")**.
- **foreach** / **foreachBatch** — произвольная логика записи: для каждой порции или для каждого микропакета вызывается пользовательский код (например, запись в внешнюю БД или API).

Обязательно указывается **checkpointLocation** (кроме консоли в учебных примерах): Spark сохраняет прогресс обработки потока, чтобы после перезапуска продолжить с нужного места. См. [§8.2](chapter-08-02.md).

---

## Ключевое

- **Structured Streaming** — поток как бесконечная таблица; те же трансформации DataFrame, чтение через **readStream**, запуск через **writeStream**.
- Обработка идёт **микропакетами**; **триггер** задаёт частоту: **processingTime("N seconds")**, **Once** или (в экспериментальном режиме) **Continuous**.
- **outputMode**: **append** — только новые строки результата; **update** — только изменившиеся; **complete** — полный результат каждый раз.
- Приёмник задаётся **.format()** (console, parquet, kafka и др.); для продакшена обычно нужна **checkpointLocation**.

В [§8.2](chapter-08-02.md) рассмотрим источники (Kafka, файловый каталог) и приёмники подробнее.
