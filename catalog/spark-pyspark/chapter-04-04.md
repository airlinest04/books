# §4.4 Интеграция с DWH и витринами

В [§4.3](chapter-04-03.md) мы разобрали партиционирование при записи в файловые хранилища. Помимо файлов (HDFS, S3, Parquet, ORC), данные часто хранятся в **реляционных хранилищах** — DWH и витринах. Spark может **читать** таблицы из таких БД и **записывать** в них результаты по **JDBC**. В этом разделе рассмотрим чтение и запись по JDBC и типичный сценарий: Spark как этап ETL между озером данных (или файлами) и загрузкой в DWH. Конкретный синтаксис в PySpark — в [§6.1](chapter-06-01.md) и [§6.4](chapter-06-04.md); здесь — общая модель и опции. С этим разделом заканчивается глава 4; в главе 5 начнём работу с PySpark: установка, SparkSession и основы DataFrame. См. [Глоссарий](glossary.md).

---

## 4.4.1. Чтение из БД по JDBC

**JDBC (Java Database Connectivity)** — стандартный API доступа к реляционным СУБД из Java. Spark использует JDBC-драйверы для подключения к PostgreSQL, MySQL, Oracle, SQL Server и другим БД. Чтение выполняется через **`spark.read.jdbc(url, table, properties)`** или перегрузки с указанием столбца партиционирования и границ для параллельного чтения. См. [§1.3](chapter-01-03.md), [Глоссарий](glossary.md).

Параметры:

- **url** — JDBC URL (например, `jdbc:postgresql://host:5432/dbname`);
- **table** — имя таблицы или подзапрос в скобках: `(SELECT * FROM t WHERE date >= '2024-01-01') AS sub`;
- **properties** — объект или словарь с минимум **user** и **password** (или способом их передачи), а также при необходимости настройками драйвера. Для передачи пароля безопаснее использовать конфигурацию или переменные окружения, а не жёстко задавать в коде.

Результат — DataFrame со схемой, соответствующей столбцам таблицы (или подзапроса). Чтение выполняется при первом действии над этим DataFrame; данные загружаются с сервера БД на исполнителей (каждый исполнитель может читать свой диапазон строк при настройке партиционирования по столбцу). См. [Глоссарий](glossary.md).

---

## 4.4.2. Параллельное чтение по JDBC (опционально)

При чтении большой таблицы по умолчанию один драйвер запрашивает данные и распределяет по исполнителям; это может быть узким местом. Для **параллельного** чтения можно указать столбец для разбиения (**partitionColumn**), нижнюю и верхнюю границы значений и число партиций. Spark сгенерирует подзапросы вида `SELECT ... WHERE partitionColumn >= ? AND partitionColumn < ?` для каждой партиции и выполнит их параллельно. Требования: столбец числовой или с упорядочиваемыми значениями; равномерное распределение значений улучшает баланс нагрузки. При неравномерном распределении часть партиций может читать много данных, часть — мало. См. [§2.2](chapter-02-02.md), [§6.1](chapter-06-01.md).

## 4.4.3. Запись в таблицу БД по JDBC

Запись в таблицу DWH или витрины выполняется через **`df.write.jdbc(url, table, mode, properties)`** (или эквивалент в вашем API). Параметры: **url** и **properties** — как при чтении; **table** — имя целевой таблицы; **mode** — режим записи: **overwrite** (обычно через DROP TABLE и создание заново или TRUNCATE, в зависимости от опций), **append** (INSERT), **error** (ошибка при существующей таблице). См. [Глоссарий](glossary.md).

Данные записываются с исполнителей: каждая партиция DataFrame пишется в БД (батчами INSERT). Число одновременных соединений и размер батча задаются опциями (numPartitions при записи, batchsize и т.д.). Таблица должна существовать и иметь совместимую схему при append; при overwrite с опцией создания таблицы Spark может создать таблицу по схеме DataFrame. Типы данных Spark приводятся к типам СУБД по правилам драйвера; при несовместимости возможны ошибки или потери точности — схему целевой таблицы стоит сверять. См. [§6.4](chapter-06-04.md).

## 4.4.4. Spark как этап ETL перед загрузкой в DWH

Типичный сценарий интеграции: **сырые данные** лежат в озере (файлы в S3/HDFS в формате Parquet, JSON и т.д.); их нужно очистить, агрегировать или объединить и загрузить в **витрину или DWH** для отчётности и аналитики. Spark удобен как единый движок для этого пайплайна:

1. **Чтение** из файлов: `spark.read.parquet("s3a://bucket/raw/")` или из нескольких источников (файлы + JDBC).
2. **Преобразования:** фильтрация, объединение с справочниками, агрегация, приведение типов — через DataFrame API или Spark SQL.
3. **Запись** в DWH: `df.write.jdbc(url, "schema.vitrina_table", "overwrite", properties)` или append для инкрементальной загрузки.

Таким образом, Spark выступает этапом **ETL** (Extract, Transform, Load): извлечение из озера или БД, преобразование в памяти кластера, загрузка в целевую таблицу. Тяжёлые соединения и агрегации выполняются в Spark; СУБД получает уже подготовленные данные. Альтернатива — читать из DWH в Spark для сложных расчётов (например, объединение с данными из озера) и записывать результат обратно или в другую таблицу. См. [§1.3](chapter-01-03.md), [§4.1](chapter-04-01.md), [Глоссарий](glossary.md).

## 4.4.5. Опции и ограничения JDBC

- **Драйвер:** на узлах кластера (или в classpath драйвера) должен быть установлен JDBC-драйвер целевой СУБД (JAR). Для PySpark драйвер загружается в JVM на драйвере и исполнителях; при spark-submit его можно указать через `--jars` или упаковать в образ.
- **Сеть:** исполнители должны иметь сетевой доступ к хосту БД (порты, фаервол, VPN). Учётные данные должны быть доступны на исполнителях (конфиг, переменные окружения или безопасный способ передачи).
- **Объём и производительность:** запись очень больших DataFrame в одну таблицу через JDBC может создавать нагрузку на БД (много одновременных INSERT). Настройка числа партиций при записи и размера батча помогает; для очень больших выгрузок иногда предпочитают запись в файлы (Parquet) в общем хранилище и загрузку в DWH через собственный механизм СУБД (COPY, внешние таблицы и т.д.). См. [§4.1](chapter-04-01.md).

---

## Ключевое

- **Чтение по JDBC:** `spark.read.jdbc(url, table, properties)` возвращает DataFrame; таблица или подзапрос, учётные данные в properties; при необходимости — параллельное чтение через partitionColumn и границы.
- **Запись по JDBC:** `df.write.jdbc(url, table, mode, properties)`; режимы overwrite, append, error; данные пишутся с исполнителей батчами; целевая таблица и схема должны быть совместимы.
- **Spark как ETL:** чтение из озера (Parquet и др.) или из БД, преобразования в Spark, запись в DWH/витрину по JDBC; единый движок для извлечения, преобразования и загрузки.
- Для JDBC нужен драйвер СУБД на узлах, сетевой доступ к БД и безопасная передача учётных данных; при очень больших объёмах выгрузки иногда комбинируют с записью в файлы и загрузкой средствами DWH.
