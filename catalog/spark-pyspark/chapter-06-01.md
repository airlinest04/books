# §6.1 Чтение

В [§5.4](chapter-05-04.md) мы завершили главу 5 — PySpark: установка, SparkSession и основы DataFrame. С этого раздела начинается глава о **работе с данными** в PySpark: чтение, преобразования и запись. Чтение выполняется через **spark.read**: указание формата, пути и опций даёт DataFrame, из которого дальше строят пайплайн. В этом разделе рассмотрим **общий вид** чтения (format + load), **короткие методы** для Parquet, CSV и JSON, основные **опции** (header, schema, sep, inferSchema) и типичные **пути** (локальный, HDFS, S3). Детали форматов и сжатия — в [§4.1](chapter-04-01.md); пути к хранилищам — в [§4.2](chapter-04-02.md). В [§6.2](chapter-06-02.md) перейдём к выборке столбцов и фильтрации. См. [Глоссарий](glossary.md).

---

## 6.1.1. Общий вид: format и load

Чтение данных в PySpark выполняется через **DataFrameReader**, доступный как **spark.read**. Общая форма вызова:

```python
df = spark.read.format("формат").option("ключ", "значение").load("путь")
```

- **format("parquet")**, **format("csv")**, **format("json")** и т.д. — задаёт формат данных; от него зависят допустимые опции и способ разбора.
- **option("key", "value")** — опции формата (например, для CSV: header, sep, encoding). Несколько опций задаются цепочкой вызовов **.option(...).option(...)**.
- **load("path")** — путь к файлу или каталогу. Для каталога Spark читает все файлы указанного формата внутри (по расширению или по содержимому в зависимости от формата). Путь может быть локальным, **hdfs://...** или **s3a://...** (см. [§4.2](chapter-04-02.md)).

Результат — DataFrame; чтение **ленивое**: данные не загружаются до вызова действия (show, count, write и т.д.). См. [§4.1](chapter-04-01.md), [Глоссарий](glossary.md).

---

## 6.1.2. Parquet и ORC

Для колоночных форматов **Parquet** и **ORC** схема хранится в самих файлах; обычно достаточно указать путь. Короткие методы:

```python
df = spark.read.parquet("/path/to/data")
df = spark.read.orc("/path/to/data")
```

Путь — к одному файлу или к каталогу; при чтении каталога обрабатываются все файлы формата. Партиционированные данные (подкаталоги вида `col=value`) автоматически дают столбцы из имён партиций (см. [§4.3](chapter-04-03.md)). Опции при необходимости: сжатие при записи задаётся в write; при чтении распаковка по умолчанию. Явная схема через **.schema(schema)** может понадобиться, если нужно ограничить или изменить типы столбцов. См. [Глоссарий](glossary.md).

---

## 6.1.3. CSV: опции header, sep, inferSchema

Для **CSV** формат не содержит типов и часто не содержит имён столбцов в явном виде. Основные опции:

- **header** — `True` или `"true"`: первая строка файла считается заголовком (имена столбцов). По умолчанию часто `False`.
- **sep** — разделитель полей (по умолчанию запятая `","`). Для табуляции: `sep="\t"`.
- **inferSchema** — `True`: Spark просматривает данные и выводит типы столбцов (целые, дробные, строки). Без inferSchema все столбцы будут строковыми. Вывод схемы требует прохода по данным и может замедлить первое действие.
- **encoding** — кодировка файла (например, `"utf-8"`, `"windows-1251"`).
- **nullValue** — строка, которую трактовать как NULL (например, пустая ячейка или `"NA"`).

Пример:

```python
df = spark.read.csv(
    "/path/to/file.csv",
    header=True,
    inferSchema=True,
    sep=",",
    encoding="utf-8"
)
```

Короткий метод: **spark.read.csv(path, header=True, inferSchema=True, sep=",")**. Для полного контроля над типами можно задать **.schema(schema)** и не использовать inferSchema. См. [§4.1](chapter-04-01.md), [§6.3](chapter-06-03.md).

## 6.1.4. JSON

При чтении **JSON** каждый файл может содержать один JSON-объект, массив объектов или **несколько объектов по одному на строку** (JSON Lines). Схема выводится из данных, если не задана явно. Короткий метод:

```python
df = spark.read.json("/path/to/data.json")
```

Опции: **primitivesAsString** (все примитивы как строки), **dateFormat**, **timestampFormat** и др. Для нестандартного формата (например, вложенные объекты) схема может быть сложной (вложенные struct, array); при необходимости её задают через **.schema(schema)**. См. [§4.1](chapter-04-01.md).

---

## 6.1.5. Явная схема: schema

Когда нужно зафиксировать типы столбцов (например, для CSV без вывода схемы или для единообразия), схему задают через **.schema(schema)**. В PySpark схема — объект **StructType** из **pyspark.sql.types**:

```python
from pyspark.sql.types import StructType, StructField, StringType, IntegerType, LongType

schema = StructType([
    StructField("user_id", LongType(), True),
    StructField("event", StringType(), True),
    StructField("count", IntegerType(), True),
])
df = spark.read.schema(schema).csv("/path/to/file.csv", header=True)
```

Тогда inferSchema не нужен; типы берутся из схемы. Это ускоряет чтение (нет прохода для вывода типов) и избегает неверного вывода при «грязных» данных. См. [§3.2](chapter-03-02.md), [§6.3](chapter-06-03.md).

---

## 6.1.6. Путь: файл и каталог

Параметр **path** в **load()** (или в parquet/csv/json) может быть:

- **Один файл** — читается этот файл.
- **Каталог** — Spark перечисляет файлы в каталоге (и при необходимости в подкаталогах) и читает подходящие по формату. Для партиционированных данных путь указывают на **корневой** каталог (см. [§4.3](chapter-04-03.md)); подкаталоги вида `col=value` интерпретируются как партиции.
- **Схема пути:** локальный `file:///path` или просто `"/path"`; **hdfs:///path** или **hdfs://host:port/path** для HDFS; **s3a://bucket/key** для S3. Настройка доступа к HDFS и S3 — в [§4.2](chapter-04-02.md). См. [Глоссарий](glossary.md).

---

## 6.1.7. Чтение по JDBC (напоминание)

Для чтения таблиц из реляционной БД используется **spark.read.jdbc(url, table, properties)**. Таблица задаётся именем или подзапросом; при необходимости указывают partitionColumn для параллельного чтения. Подробнее — в [§4.4](chapter-04-04.md). См. [Глоссарий](glossary.md).

---

## Ключевое

- **Чтение:** `spark.read.format("формат").option(...).load(path)` или короткие методы **parquet**, **csv**, **json**; путь — файл или каталог; чтение ленивое.
- **Parquet/ORC:** схема в файлах; обычно достаточно пути; партиционированные каталоги дают столбцы из имён партиций.
- **CSV:** важны опции **header**, **sep**, **inferSchema**; при необходимости **encoding**, **nullValue**; для фиксированных типов — **.schema(schema)**.
- **JSON:** схема выводится из данных; при сложной структуре можно задать schema явно.
- **Явная схема** — StructType + StructField из pyspark.sql.types; задаётся через **.schema(schema)** перед load/csv/json; ускоряет чтение и даёт контроль над типами.
- Путь может быть локальным, hdfs:// или s3a://; для кластера и S3 нужна соответствующая настройка (см. §4.2).

В [§6.2](chapter-06-02.md) мы разберём выборку столбцов и фильтрацию: select, filter/where, withColumn, withColumnRenamed, drop.
