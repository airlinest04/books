# §5.1 Установка и запуск

В [§4.4](chapter-04-04.md) мы завершили главу 4 — связь Spark с хранилищами данных и DWH. С этого раздела начинается **часть II: PySpark** — работа с Spark на языке Python. Чтобы писать и запускать код на PySpark, нужно настроить среду: установить PySpark, при необходимости указать путь к Java и к интерпретатору Python, и уметь запускать интерактивную оболочку или скрипты. В этом разделе рассмотрим **установку PySpark через pip**, **переменные окружения** (SPARK_HOME, PYSPARK_PYTHON) и **локальный запуск** оболочки pyspark и скриптов. В [§5.2](chapter-05-02.md) перейдём к созданию SparkSession и конфигурации. См. [Глоссарий](glossary.md).

---

## 5.1.1. Требования: Java и Python

PySpark — это Python-библиотека, которая при запуске поднимает **JVM** (Java Virtual Machine) и общается с движком Spark через Py4J. Поэтому на машине должны быть установлены:

- **Java** — обычно Java 8 или 11 (в зависимости от версии Spark; актуальные требования смотрите в документации выбранной версии PySpark). Переменная **JAVA_HOME** должна указывать на каталог установки JDK (или JRE), и команда `java` должна быть в PATH.
- **Python** — версия 3.8 и выше (для современных версий PySpark). Рекомендуется использовать виртуальное окружение (venv или conda), чтобы не смешивать зависимости с системным Python.

Проверка: в терминале выполнить `java -version` и `python3 --version` (или `python --version`). Без корректной Java PySpark не запустится. См. [§1.4](chapter-01-04.md), [Глоссарий](glossary.md).

---

## 5.1.2. Установка PySpark через pip

Самый простой способ установить PySpark для локальной разработки — через **pip**:

```bash
pip install pyspark
```

(или `pip3 install pyspark` в зависимости от того, какой Python используется.) Устанавливается пакет из PyPI; в него входят библиотеки Spark (в том числе встроенная JVM не входит — Java должна стоять отдельно). После установки можно импортировать PySpark в коде: `from pyspark.sql import SparkSession`. Версию пакета можно зафиксировать: `pip install pyspark==3.5.0` (подставьте нужную версию). См. [Глоссарий](glossary.md).

При установке через pip **отдельный дистрибутив Spark** (архив со spark-submit, скриптами sbin и т.д.) для локального режима не обязателен: PySpark из pip содержит необходимые JAR и при создании SparkSession по умолчанию использует встроенные артефакты. Для подключения к кластеру (YARN, Kubernetes, standalone) может понадобиться полный дистрибутив Spark и переменная **SPARK_HOME** (см. ниже). См. [§2.5](chapter-02-05.md).

---

## 5.1.3. Переменные окружения SPARK_HOME и PYSPARK_PYTHON

**SPARK_HOME** — путь к корневому каталогу дистрибутива Spark (где лежат подкаталоги `bin`, `jars`, `conf` и т.д.). Если вы установили Spark из архива (например, для spark-submit или для работы с кластером), задайте:

```bash
export SPARK_HOME=/path/to/spark
```

Многие скрипты (pyspark, spark-submit из дистрибутива) и конфигурации ищут Spark по этой переменной. При установке **только** через `pip install pyspark` SPARK_HOME может не требоваться для локального режима: PySpark сам находит свои JAR внутри пакета. Если при запуске возникает ошибка «SPARK_HOME not set», задайте SPARK_HOME вручную или установите полный дистрибутив Spark. См. [Глоссарий](glossary.md).

**PYSPARK_PYTHON** — путь к исполняемому файлу Python, который будут использовать **исполнители** (executors) при запуске на кластере. На узлах кластера может быть установлен другой Python или другая версия; если не задать PYSPARK_PYTHON (и при необходимости PYSPARK_DRIVER_PYTHON для драйвера), Spark может подхватить системный `python`, что приведёт к несовместимости версий или отсутствию зависимостей. В локальном режиме на одной машине часто достаточно не задавать PYSPARK_PYTHON — будет использован тот же интерпретатор, что и у драйвера. Пример:

```bash
export PYSPARK_PYTHON=/usr/bin/python3
```

(или путь к Python внутри venv: `./venv/bin/python`). См. [§2.1](chapter-02-01.md), [Глоссарий](glossary.md).

## 5.1.4. Запуск интерактивной оболочки pyspark

Интерактивная оболочка **pyspark** позволяет вводить команды по одной и сразу видеть результат — удобно для экспериментов и отладки. См. [Глоссарий](glossary.md).

**Если установлен дистрибутив Spark** (и задан SPARK_HOME):

```bash
$SPARK_HOME/bin/pyspark
```

Запустится Python-интерпретатор с предзагруженным модулем `pyspark` и переменной **`spark`** — объектом SparkSession (созданным по умолчанию). Можно сразу писать, например: `spark.range(10).show()`.

**Если установлен только pip-пакет:** команды `pyspark` в PATH может не быть. Запуск через модуль Python:

```bash
python -m pyspark
```

(или `python3 -m pyspark`). Аналогично создаётся сессия с переменной `spark`. По умолчанию используется **локальный** режим (local[*] или аналог). Выход из оболочки — `exit()` или Ctrl+D. См. [§2.5](chapter-02-05.md), [§5.2](chapter-05-02.md).

## 5.1.5. Запуск скрипта

Для выполнения готового скрипта (файл `.py`) возможны два подхода.

**1. Обычный запуск Python:** если в скрипте создаётся SparkSession (например, через `SparkSession.builder.getOrCreate()`), достаточно запустить:

```bash
python my_script.py
```

При этом используется Spark, встроенный в установленный пакет PySpark (локальный режим по умолчанию). Подходит для разработки и для джоб, которые работают в локальном режиме. См. [§5.2](chapter-05-02.md).

**2. spark-submit:** для отправки приложения в кластер (YARN, Kubernetes, standalone) используется **spark-submit**. Скрипт передаётся как аргумент:

```bash
spark-submit --master yarn --deploy-mode cluster my_script.py
```

Для spark-submit обычно нужен полный дистрибутив Spark (SPARK_HOME) и настройки кластера. В скрипте по-прежнему создаётся или получается SparkSession; мастер и ресурсы задаются через аргументы spark-submit или конфигурацию. См. [§2.5](chapter-02-05.md).

## 5.1.6. Виртуальное окружение и зависимости

Рекомендуется изолировать проект в **виртуальном окружении** (venv):

```bash
python3 -m venv venv
source venv/bin/activate   # Linux/macOS
# или: venv\Scripts\activate  на Windows
pip install pyspark
```

Так версия PySpark и других библиотек (pandas, jupyter при необходимости) не конфликтуют с другими проектами. Если используете **Jupyter** для интерактивной работы с PySpark, установите в то же окружение `jupyter` и при запуске ядра укажите Python из этого venv; в первой ячейке можно создать SparkSession и работать с DataFrame. См. [§5.2](chapter-05-02.md), [§5.3](chapter-05-03.md).

---

## Ключевое

- Для PySpark нужны **Java** (JAVA_HOME, версия по требованиям Spark) и **Python** 3.8+; рекомендуется venv.
- **Установка:** `pip install pyspark`; для локального режима отдельный дистрибутив Spark не обязателен; для кластера может понадобиться полный Spark и SPARK_HOME.
- **SPARK_HOME** — путь к дистрибутиву Spark при использовании spark-submit и скриптов из дистрибутива; **PYSPARK_PYTHON** — путь к Python на исполнителях (важно для кластера).
- **Интерактивная оболочка:** `$SPARK_HOME/bin/pyspark` или `python -m pyspark`; по умолчанию создаётся SparkSession в переменной `spark`, режим локальный.
- **Скрипт:** `python my_script.py` при локальном режиме; для кластера — `spark-submit` с указанием master и пути к скрипту.

В [§5.2](chapter-05-02.md) мы разберём SparkSession: создание объекта, конфигурацию (память, число ядер) и использование как точки входа к DataFrame и SQL.
