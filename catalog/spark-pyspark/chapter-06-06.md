# §6.6 Кэширование и партиции

В [§6.5](chapter-06-05.md) мы разобрали обработку пропусков (na.fill, na.drop). Два последних практических аспекта работы с DataFrame в PySpark — **кэширование** (сохранение результата в памяти или на диске для повторного использования) и **управление партициями** (coalesce, repartition, выбор числа партиций). В этом разделе рассмотрим **cache()** и **persist()**, когда их применять, а также **coalesce()** и **repartition()** и выбор числа партиций при чтении, после shuffle и при записи. С этим разделом заканчивается глава 6; в главе 7 перейдём к агрегациям, окнам и соединениям. См. [Глоссарий](glossary.md).

---

## 6.6.1. cache() и persist(): зачем кэшировать

По умолчанию DataFrame описывает только **граф вычислений** (lineage); данные не хранятся после выполнения действия. Если вызвать **два действия** над одним и тем же DataFrame (например, сначала count(), потом write), план выполнится **дважды**: данные снова прочитаются из источника и пройдут все трансформации. Чтобы избежать повторного вычисления, результат можно **закэшировать**: после первого действия партиции останутся в памяти (или на диске) исполнителей, и последующие действия будут читать из кэша. См. [§2.2](chapter-02-02.md), [§2.4](chapter-02-04.md), [Глоссарий](glossary.md).

**cache()** — краткая форма **persist()** с уровнем хранения **MEMORY_AND_DISK**: данные по возможности в памяти, при нехватке места — на локальный диск исполнителя. См. [§2.1](chapter-02-01.md).

```python
df = spark.read.parquet("/path/to/data").filter(col("date") >= "2024-01-01")
df.cache()   # или df.persist()
df.count()   # первое действие — вычисление и загрузка в кэш
df.write.parquet("/output/1")  # второе действие — чтение из кэша
```

Кэширование само по себе **не запускает** вычисление; вычисление запускает первое **действие** над этим DataFrame. После cache()/persist() при следующем действии данные берутся из кэша (если партиция ещё там). См. [Глоссарий](glossary.md).

---

## 6.6.2. Уровни хранения: persist(storageLevel)

Метод **persist(storageLevel)** позволяет задать **уровень хранения**. Основные варианты (из pyspark.StorageLevel):

- **MEMORY_ONLY** — только в памяти; при нехватке места партиция не кэшируется (при следующем обращении пересчитается).
- **MEMORY_AND_DISK** — сначала в памяти, при переполнении — на диск; то же поведение, что у cache().
- **MEMORY_ONLY_SER** / **MEMORY_AND_DISK_SER** — сериализованное хранение (меньше объём, больше CPU при чтении).
- **DISK_ONLY** — только на диск (при нехватке памяти).

Для большинства сценариев достаточно **cache()** (MEMORY_AND_DISK). Снятие с кэша — **df.unpersist()**; освобождает память и диск на исполнителях. См. [Глоссарий](glossary.md).

---

## 6.6.3. Когда кэшировать

Кэшировать имеет смысл, когда **один и тот же** DataFrame (или RDD) используется в **нескольких действиях** или в нескольких ветках графа, и пересчёт дорог. Типичные случаи:

- Один раз отфильтровали/объединили данные, затем делаете по ним несколько агрегатов или записей — закэшировать после тяжёлых трансформаций, перед первым действием.
- Интерактивная работа: несколько раз подряд вызываете show(), count(), разные запросы к одному набору данных — кэш избегает повторного чтения с диска.

**Не стоит** кэшировать, если DataFrame используется только один раз (лишняя память), или если данных очень много и кэш вытеснит другие нужные данные. После использования кэша в длинных скриптах лучше вызвать **unpersist()**, чтобы освободить ресурсы. См. [§2.4](chapter-02-04.md).

## 6.6.4. coalesce и repartition: изменение числа партиций

Число **партиций** определяет, сколько задач выполняется параллельно и как данные распределены по узлам. Иногда нужно **уменьшить** или **увеличить** число партиций без изменения логики данных. См. [§2.2](chapter-02-02.md), [Глоссарий](glossary.md).

**coalesce(n)** — уменьшить число партиций до **n**. Объединяет партиции **без полного shuffle**: данные перемещаются только между партициями на одних и тех же исполнителях, где это возможно. Быстрее, чем repartition(n), когда n меньше текущего числа партиций. Не гарантирует равномерное распределение по размеру (некоторые партиции могут остаться крупнее). См. [Глоссарий](glossary.md).

**repartition(n)** — установить число партиций равным **n**. Выполняется **shuffle**: данные перераспределяются по всем исполнителям. Используется, когда нужно увеличить число партиций или выровнять размер партиций после фильтра (после сильного фильтра партиций может остаться много, но они мелкие — имеет смысл coalesce; или наоборот, нужно больше партиций для параллелизма). repartition("col") с именем столбца перераспределяет по хэшу столбца — полезно перед операциями по ключу. См. [§2.3](chapter-02-03.md), [Глоссарий](glossary.md).

```python
df = df.coalesce(4)      # уменьшить до 4 партиций без полного shuffle
df = df.repartition(100) # 100 партиций, с shuffle
df = df.repartition(20, "date")  # 20 партиций по хэшу date
```

## 6.6.5. Выбор числа партиций

- **При чтении:** число партиций задаётся источником (по блокам файлов в HDFS/S3, по файлам в каталоге). Явно ограничить можно через опции формата (например, maxPartitionBytes) или через repartition/coalesce после чтения.
- **После shuffle:** число партиций после операций с shuffle (groupBy, join, distinct и т.д.) задаётся конфигурацией **spark.sql.shuffle.partitions** (по умолчанию часто 200). Для малых данных 200 партиций — избыточно (много мелких задач); можно уменьшить в SparkSession или в конфиге. Для очень больших данных иногда увеличивают. См. [§2.6](chapter-02-06.md).
- **Перед записью:** при записи в один каталог без partitionBy в каждом партиции DataFrame создаётся один файл (или несколько при определённых настройках). Чтобы получить, например, 10 файлов на выходе, перед write вызывают **df.coalesce(10)** или **df.repartition(10)**. При partitionBy число файлов = число партиций × число партиционных подкаталогов (по одной партиции на подкаталог). См. [§4.3](chapter-04-03.md), [§6.4](chapter-06-04.md).

Слишком мало партиций — недогрузка кластера; слишком много — накладные расходы на планирование и мелкие задачи. Ориентир: порядка числа ядер в кластере или в несколько раз больше, с учётом объёма данных. См. [§2.2](chapter-02-02.md).

## Ключевое

- **cache()** и **persist()** помечают DataFrame для сохранения в памяти (и при необходимости на диске) после первого действия; последующие действия читают из кэша и не пересчитывают граф. **unpersist()** снимает с кэша.
- **persist(storageLevel)** задаёт уровень (MEMORY_ONLY, MEMORY_AND_DISK, DISK_ONLY и др.); cache() = persist(MEMORY_AND_DISK).
- Кэшировать стоит при **повторном использовании** одного и того же DataFrame в нескольких действиях; не кэшировать одноразовые ветки и при нехватке памяти.
- **coalesce(n)** — уменьшить до n партиций без полного shuffle; **repartition(n)** — установить n партиций с shuffle; repartition(n, "col") — по хэшу столбца.
- Число партиций задаётся источником при чтении, конфигом spark.sql.shuffle.partitions после shuffle; перед записью coalesce/repartition задаёт число файлов на выходе. Баланс: не слишком мало (параллелизм), не слишком много (накладные расходы).
