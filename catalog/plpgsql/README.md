## Подробное содержание

### Глава 1. Введение в PL/pgSQL: зачем процедурное расширение

- **1.1 Ограничения чистого SQL** — нет ветвлений, циклов, локальных переменных; сложная логика в приложении или в БД.
- **1.2 Что даёт PL/pgSQL** — процедурная логика внутри PostgreSQL; меньше round-trip между приложением и БД; согласованность и безопасность.
- **1.3 Где выполняется PL/pgSQL** — функции и процедуры в базе; вызов из SQL, из приложения, из триггеров.
- **1.4 Первый блок** — анонимный блок DO $$ ... $$; выполнение в psql.
- *Ключевое:* зачем PL/pgSQL, где выполняется. *Задания:* выполнение простого блока DO.

---

### Глава 2. Синтаксис: блоки, переменные, типы данных

- **2.1 Структура блока** — DECLARE, BEGIN, EXCEPTION, END; метки блока.
- **2.2 Объявление переменных** — имя, тип, DEFAULT; типы из PostgreSQL (INTEGER, VARCHAR(n), DATE, и т.д.); %TYPE (тип по столбцу), %ROWTYPE (строка таблицы).
- **2.3 Присваивание** — := и =; SELECT ... INTO для одной строки.
- **2.4 Константы и параметры** — константы в DECLARE; параметры функций (см. гл. 5) — здесь только упоминание.
- *Ключевое:* блок, DECLARE, переменные, %TYPE, %ROWTYPE. *Задания:* блок с переменными и присваиванием.

---

### Глава 3. Управляющие конструкции: условия и циклы

- **3.1 Условие IF** — IF ... THEN ... ELSIF ... ELSE ... END IF; вложенность.
- **3.2 CASE** — CASE по значению и CASE по условию; в выражениях и в операторах.
- **3.3 Цикл LOOP** — простой LOOP с EXIT WHEN; бесконечный цикл и выход.
- **3.4 Циклы WHILE и FOR** — WHILE условие LOOP; FOR по диапазону целых (FOR i IN 1..10); FOR по результату запроса (FOR rec IN SELECT ...).
- **3.5 CONTINUE и вложенные циклы** — метки циклов; EXIT/CONTINUE с меткой.
- *Ключевое:* IF, CASE, LOOP, WHILE, FOR. *Задания:* процедурная логика с ветвлениями и циклами.

---

### Глава 4. Обработка исключений

- **4.1 Блок EXCEPTION** — когда произошла ошибка, управление переходит в EXCEPTION; после обработки блок завершается.
- **4.2 Обработка по типу ошибки** — WHEN SQLSTATE, WHEN OTHERS; типичные коды (unique_violation, not_null_violation и др.).
- **4.3 Получение информации об ошибке** — SQLSTATE, SQLERRM; сохранение в переменные для логирования.
- **4.4 RAISE** — вызов исключения явно; уровни (EXCEPTION, WARNING, NOTICE и др.); RAISE NOTICE для отладки.
- *Ключевое:* EXCEPTION, WHEN, RAISE. *Задания:* обработка конкретных ошибок, логирование и повторный RAISE.

---

### Глава 5. Функции: создание, параметры, возврат значений

- **5.1 CREATE FUNCTION** — имя, параметры (IN, OUT, INOUT), возвращаемый тип, язык LANGUAGE plpgsql, тело.
- **5.2 Параметры** — именованные и позиционные; значения по умолчанию; VARIADIC для списка аргументов.
- **5.3 RETURN** — RETURN выражение; RETURN NEXT для набора строк (RETURNS SETOF); RETURN QUERY.
- **5.4 VOLATILITY и параллелизм** — VOLATILE, STABLE, IMMUTABLE; влияние на оптимизатор и параллельные запросы.
- **5.5 Вызов функции** — из SELECT, в выражениях; передача параметров по имени.
- **5.6 SECURITY DEFINER и INVOKER** — от чьего имени выполняется функция; права доступа к объектам; когда использовать SECURITY DEFINER.
- *Ключевое:* CREATE FUNCTION, IN/OUT, RETURN, RETURNS SETOF, SECURITY. *Задания:* написание функций с разными сигнатурами и возвратами.

---

### Глава 6. Процедуры в PostgreSQL

- **6.1 CREATE PROCEDURE** — отличие от функции: не возвращает значение в выражении; вызов CALL.
- **6.2 OUT-параметры процедур** — возврат нескольких значений через OUT; вызов и получение результатов.
- **6.3 Транзакции внутри процедуры** — процедура может содержать COMMIT/ROLLBACK (в отличие от функции); когда это нужно.
- *Ключевое:* PROCEDURE, CALL, OUT. *Задания:* процедура с OUT и вызов из блока.

---

### Глава 7. Работа с SQL внутри PL/pgSQL: курсоры и динамический SQL

- **7.1 Выполнение одного запроса** — SELECT ... INTO; выполнение DML (INSERT/UPDATE/DELETE) и получение количества строк.
- **7.2 Курсор** — объявление курсора (CURSOR); OPEN, FETCH, CLOSE; цикл FOR по курсору.
- **7.3 Динамический SQL** — построение строки запроса в переменной; EXECUTE ... USING для подстановки параметров; защита от SQL-инъекций.
- **7.4 Возврат набора из функции** — RETURN QUERY; RETURNS TABLE(...); RETURNS SETOF type.
- *Ключевое:* INTO, курсоры, EXECUTE ... USING. *Задания:* функция с курсором, динамический запрос с параметрами.

---

### Глава 8. Триггеры: события, создание, применение

- **8.1 События триггера** — BEFORE/AFTER INSERT, UPDATE, DELETE; по строке (FOR EACH ROW) и по оператору (FOR EACH STATEMENT).
- **8.2 Создание триггерной функции** — функция без аргументов, возврат NEW/OLD или NULL; NEW и OLD в контексте строки.
- **8.3 CREATE TRIGGER** — привязка к таблице; условие WHEN для строковых триггеров.
- **8.4 Типичные применения** — аудит (логирование изменений), заполнение полей (например, updated_at), проверки и модификация NEW.
- **8.5 Ограничения и риски** — производительность, каскадные эффекты; когда лучше проверки в приложении или ограничения БД.
- *Ключевое:* события, NEW/OLD, триггерная функция. *Задания:* триггер аудита, триггер с проверкой.

---

### Глава 9. Правила (Rules) в PostgreSQL

- **9.1 Что такое правила** — переписывание запроса на уровне планирования; вместо одной операции выполняется другая (или дополнительные).
- **9.2 CREATE RULE** — ON INSERT/UPDATE/DELETE/SELECT; DO INSTEAD / DO ALSO; примеры (представления с обновлением, логирование).
- **9.3 Отличие от триггеров** — уровень (правило — переписывание запроса, триггер — выполнение кода при событии); когда что использовать.
- **9.4 Отладка и диагностика** — RAISE NOTICE / RAISE DEBUG для вывода переменных; проверка синтаксиса (DO-блок с компиляцией); типичные ошибки при написании функций.
- *Ключевое:* RULE, INSTEAD/ALSO, отличия от триггеров. *Задания:* правило для логирования удалений (при необходимости).
