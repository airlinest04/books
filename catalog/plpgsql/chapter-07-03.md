# §7.3 Динамический SQL

В [§7.2](chapter-07-02.md) мы разобрали курсоры; запрос при объявлении или в OPEN был статическим. Когда **текст запроса или имена объектов** (таблицы, столбцы) формируются в run time (в переменных), в PL/pgSQL используют **динамический SQL**: сбор строки команды и выполнение через **EXECUTE**. В этом разделе — синтаксис **EXECUTE ... USING**, подстановка параметров ($1, $2, ...) как защита от **SQL-инъекций**, и безопасное включение имён объектов (quote_ident, format с %I и %L). Возврат набора из функции (RETURN QUERY EXECUTE) — в [§7.4](chapter-07-04.md). См. [Глоссарий](glossary.md).

---

## 7.3.1. Когда нужен динамический SQL

Обычные SQL-команды в PL/pgSQL (SELECT, INSERT, UPDATE, DELETE) допускают **подстановку переменных** в запрос: имена переменных в тексте заменяются на параметры, значения передаются при выполнении. Так можно безопасно подставлять **значения** (числа, строки, даты). Но **имена таблиц, столбцов, схем** и сама **структура запроса** (разное количество условий, другой список полей) в статическом тексте задать нельзя — они должны быть известны на этапе разбора. См. [Глоссарий](glossary.md).

**Динамический SQL** — формирование строки команды в переменной (конкатенация, format и т.д.) и выполнение её через **EXECUTE**. Так можно, например, выбирать таблицу по имени параметра, строить ORDER BY по имени столбца или выполнять DDL с именами из переменных. Недостаток — риск **SQL-инъекции**, если в строку попадает непроверенный ввод; ниже — как подставлять значения и идентификаторы безопасно.

---

## 7.3.2. EXECUTE — выполнение строки команды

Синтаксис (по документации PostgreSQL, раздел 41.5.4):

```
EXECUTE строка_команды [ INTO [ STRICT ] цель ] [ USING выражение [, ...] ];
```

**строка_команды** — выражение типа text (часто переменная с собранным запросом). Команда выполняется каждый раз заново; план **не кэшируется** (в отличие от статического запроса). **INTO** — куда записать результат одной строки (как в SELECT INTO); при нескольких строках берётся первая или ошибка при STRICT. **USING** — список выражений, подставляемых в команду вместо **$1**, **$2**, ... в тексте строки. См. [Глоссарий](glossary.md).

Подстановка переменных PL/pgSQL в саму **строку_команды** не выполняется: всё, что должно меняться, нужно либо вшить в строку с экранированием (через функции цитирования), либо передать через **USING**. Параметры **$1**, **$2** в строке относятся только к USING; для данных (значения в WHERE, в INSERT) предпочтительно использовать именно USING — так значения передаются в нативном формате и не требуют ручного экранирования кавычками, что снижает риск инъекции.

Пример: запрос с параметром по значению (безопасно):

```sql
EXECUTE 'SELECT count(*) FROM orders WHERE user_id = $1 AND status = $2'
  INTO cnt
  USING p_user_id, p_status;
```

## 7.3.3. Защита от SQL-инъекций: USING и цитирование

**SQL-инъекция** — подстановка в текст запроса фрагментов, меняющих смысл команды (например, закрытие кавычки и добавление своего SQL). Чтобы её избежать: **значения данных** не вшивать в строку конкатенацией, а передавать через **USING** ($1, $2, ...). Тогда они обрабатываются как параметры запроса, а не как часть текста. См. [Глоссарий](glossary.md).

**Имена объектов** (таблицы, столбцы, схемы) через USING передать нельзя — в SQL параметры допустимы только для значений. Имена нужно вставлять в строку команды. Для безопасного включения используют:

- **quote_ident(text)** — заключает идентификатор в двойные кавычки и экранирует спецсимволы; подходит для имён таблиц и столбцов из переменных.
- **format(format_string, ...)** — аналог sprintf; спецификатор **%I** вставляет идентификатор (как quote_ident), **%L** — литерал значения (как quote_nullable). Для значений, которые могут быть NULL, предпочтителен **%L** или отдельно **quote_nullable**. См. документацию PostgreSQL, функции строк и format.

Пример: динамическое имя таблицы и параметр по значению:

```sql
EXECUTE format('SELECT count(*) FROM %I WHERE id = $1', p_table_name)
  INTO cnt
  USING p_id;
```

Имя таблицы вставлено через %I (безопасно); значение условия — через USING. Другой вариант без format: конкатенация с quote_ident(p_table_name) и USING для p_id.

**Опасный приём** — конкатенация непроверенной строки в команду:

```sql
-- опасно: если p_name содержит ', то возможна инъекция
EXECUTE 'SELECT * FROM users WHERE name = ''' || p_name || '''';
```

Правильно: использовать USING и $1:

```sql
EXECUTE 'SELECT * FROM users WHERE name = $1' INTO rec USING p_name;
```

## 7.3.4. quote_ident, quote_literal, quote_nullable

Функции **quote_ident**, **quote_literal**, **quote_nullable** (документация PostgreSQL, строковые функции) помогают безопасно вставлять фрагменты в динамическую команду. См. [Глоссарий](glossary.md).

- **quote_ident(text)** — возвращает идентификатор в двойных кавычках с экранированием; для имён таблиц и столбцов.
- **quote_literal(text)** — возвращает строковый литерал в одинарных кавычках с экранированием; при аргументе NULL возвращает NULL (строка команды может стать невалидной).
- **quote_nullable(text)** — как quote_literal, но для NULL возвращает слово NULL без кавычек; удобно для значений, которые могут быть NULL.

Пример вставки имени столбца и значения:

```sql
EXECUTE 'UPDATE tbl SET ' || quote_ident(p_col_name) || ' = ' || quote_nullable(p_value)
  || ' WHERE id = $1'
  USING p_id;
```

Значение p_id передаётся через USING; имя столбца и литерал значения вшиты через quote_ident и quote_nullable. То же можно записать через format: `format('UPDATE tbl SET %I = %L WHERE id = $1', p_col_name, p_value) USING p_id;` (если p_value не NULL; иначе %L даёт NULL в строке, что допустимо для SET col = NULL).

## 7.3.5. OPEN курсора FOR EXECUTE

Непривязанный курсор ([§7.2](chapter-07-02.md)) можно открыть с **динамическим запросом** (по документации PostgreSQL):

```
OPEN имя_курсора [ [ NO ] SCROLL ] FOR EXECUTE строка_запроса [ USING выражение [, ...] ];
```

Запрос задаётся строкой; параметры — через USING ($1, $2, ...). Имена объектов в строке собирают с quote_ident или format(%I). После OPEN курсор используется как обычно (FETCH, CLOSE или цикл). См. [Глоссарий](glossary.md).

Пример:

```sql
OPEN cur FOR EXECUTE format('SELECT * FROM %I WHERE status = $1', p_table_name)
  USING p_status;
```

---

## Ключевое

- **Динамический SQL** — сбор строки команды в переменной и выполнение через **EXECUTE**; нужен, когда меняются имена объектов или структура запроса.
- **EXECUTE** строка **[ INTO цель ] [ USING выражение, ... ]**; в строке параметры **$1**, **$2** получают значения из USING; план не кэшируется.
- **Защита от инъекций:** данные подставлять через **USING**, не конкатенацией; имена объектов — через **quote_ident** или **format(%I)**; значения-литералы при необходимости — **quote_nullable** или **format(%L)**.
- **OPEN** курсор **FOR EXECUTE** строка **[ USING ... ]** — открытие курсора с динамическим запросом.

В [§7.4](chapter-07-04.md) разберём **возврат набора из функции**: RETURN QUERY, RETURN QUERY EXECUTE, RETURNS TABLE и RETURNS SETOF.
