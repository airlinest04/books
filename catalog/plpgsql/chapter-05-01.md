# §5.1 CREATE FUNCTION

В [§4.4](chapter-04-04.md) мы завершили главу об обработке исключений. С этой главы — **функции** на PL/pgSQL: создание, параметры, возврат значений, вызов и безопасность. В этом разделе разберём **CREATE FUNCTION** — имя функции, список параметров (режимы IN, OUT, INOUT), возвращаемый тип, указание языка **LANGUAGE plpgsql** и тело функции (AS $$ ... $$). Детали параметров (имена, значения по умолчанию, VARIADIC) — в [§5.2](chapter-05-02.md), операторы RETURN — в [§5.3](chapter-05-03.md), атрибуты VOLATILITY и SECURITY — в [§5.4](chapter-05-04.md) и [§5.6](chapter-05-06.md). См. [Глоссарий](glossary.md).

---

## 5.1.1. Общий вид команды CREATE FUNCTION

Команда **CREATE FUNCTION** определяет новую функцию в текущей схеме (или в указанной, если задано schema_name.func_name). Синтаксис (сокращённо по документации PostgreSQL):

```
CREATE [ OR REPLACE ] FUNCTION имя
  ( [ [ argmode ] [ argname ] argtype [ { DEFAULT | = } выражение ] [, ...] ] )
  RETURNS тип_результата
  LANGUAGE lang_name
  AS 'определение'
```

**OR REPLACE** — если функция с таким именем и типами аргументов уже есть, её определение заменяется. Имя и типы входных аргументов менять при замене нельзя; возвращаемый тип тоже нельзя изменить (для смены типа функцию нужно удалить и создать заново). Владелец и права при OR REPLACE сохраняются. См. [Глоссарий](glossary.md).

Для PL/pgSQL **язык** указывают как **LANGUAGE plpgsql**. **Определение** — строка с телом функции (блок PL/pgSQL); обычно задают долларовыми кавычками: **AS $$ ... $$**. Создавать функцию может пользователь с привилегией USAGE на язык plpgsql и на типы аргументов и результата.

---

## 5.1.2. Имя и схема

**Имя** функции может быть простым или квалифицированным схемой: `имя` или `схема.имя`. Без схемы функция создаётся в текущей схеме поиска (как правило, `public`). В одной схеме не могут сосуществовать две функции с одинаковым именем и **одинаковыми типами входных аргументов** (игнорируя OUT); при разных наборах типов аргументов перегрузка разрешена. См. [Глоссарий](glossary.md).

Примеры: `my_func`, `app_schema.calc_total`.

---

## 5.1.3. Параметры: режим и тип

Каждый параметр задаётся режимом **(argmode)**, именем **(argname)** и типом **(argtype)**; для входных параметров можно указать значение по умолчанию. Режимы (по документации PostgreSQL):

- **IN** (по умолчанию) — аргумент только на вход; в теле доступен для чтения. Можно не писать IN.
- **OUT** — выходной параметр; функция не возвращает значение через RETURNS в обычном смысле, а через присваивание OUT-параметрам; имена OUT задают имена столбцов при возврате записи. OUT-параметры не передаются при вызове.
- **INOUT** — и вход, и выход; передаётся при вызове и может быть изменён в теле.

Тип задаётся любым SQL-типом (в том числе `таблица.столбец%TYPE`). Подробнее имена, порядок, DEFAULT и VARIADIC — в [§5.2](chapter-05-02.md). См. [Глоссарий](glossary.md).

Примеры объявления параметров:

```sql
CREATE FUNCTION add(a integer, b integer) RETURNS integer ...
CREATE FUNCTION lookup(key text, OUT value text) ...
CREATE FUNCTION swap(INOUT x int, INOUT y int) ...
```

---

## 5.1.4. RETURNS — возвращаемый тип

**RETURNS** задаёт тип возвращаемого значения. Должен соответствовать типу выражения в RETURN (или типу единственного OUT, если OUT один). Если выходных параметров несколько (несколько OUT или INOUT), возвращаемый тип неявно — запись с полями по OUT; в этом случае можно написать **RETURNS record** или опустить RETURNS. **RETURNS void** — функция ничего не возвращает (только побочные эффекты). **RETURNS SETOF тип** — функция возвращает набор строк (см. [§5.3](chapter-05-03.md), гл. 7). См. [Глоссарий](glossary.md).

Примеры:

```sql
RETURNS integer
RETURNS text
RETURNS void
RETURNS SETOF users
RETURNS TABLE(id int, name text)   -- эквивалент SETOF с именованными столбцами
```

---

## 5.1.5. LANGUAGE и тело функции (AS)

Для функций на PL/pgSQL указывают **LANGUAGE plpgsql**. Тело задаётся строкой; рекомендуется **долларовые кавычки** (см. [§1.4](chapter-01-04.md)): **AS $$ блок PL/pgSQL $$**. Внутри тела — один блок PL/pgSQL (DECLARE, BEGIN, EXCEPTION, END). См. [Глоссарий](glossary.md).

Полный минимальный пример (по документации PostgreSQL, адаптировано):

```sql
CREATE OR REPLACE FUNCTION increment(i integer) RETURNS integer
AS $$
BEGIN
  RETURN i + 1;
END;
$$ LANGUAGE plpgsql;
```

Порядок предложений (RETURNS, LANGUAGE, AS) может быть произвольным; часто пишут RETURNS сразу после списка параметров, затем AS $$ ... $$, затем LANGUAGE plpgsql.

---

## 5.1.6. Дополнительные атрибуты (кратко)

При создании функции можно задать и другие атрибуты (подробнее в следующих разделах):

- **IMMUTABLE | STABLE | VOLATILE** — поведение для оптимизатора и параллельных запросов ([§5.4](chapter-05-04.md)).
- **SECURITY INVOKER | SECURITY DEFINER** — от чьего имени выполняется функция и с какими правами ([§5.6](chapter-05-06.md)).
- **STRICT** (RETURNS NULL ON NULL INPUT) — при NULL в любом аргументе функция не вызывается, сразу возвращается NULL.
- **SET** — установка параметров конфигурации на время выполнения функции.

Для начала достаточно **CREATE FUNCTION ... RETURNS ... AS $$ ... $$ LANGUAGE plpgsql;** остальное добавляют по необходимости.

---

## Ключевое

- **CREATE FUNCTION имя (параметры) RETURNS тип AS $$ тело $$ LANGUAGE plpgsql** — базовая форма функции на PL/pgSQL.
- **CREATE OR REPLACE FUNCTION** заменяет существующую функцию с тем же именем и типами аргументов; имя, типы аргументов и возвращаемый тип при замене не меняют.
- Параметры: **IN** (по умолчанию), **OUT**, **INOUT**; тип и при необходимости имя и DEFAULT; детали в §5.2.
- **RETURNS** задаёт тип результата; при нескольких OUT можно опустить или указать RETURNS record; RETURNS SETOF — набор строк (§5.3, гл. 7).
- Тело — один блок PL/pgSQL в строке (рекомендуется $$ ... $$); язык — **LANGUAGE plpgsql**.

В [§5.2](chapter-05-02.md) мы разберём параметры подробнее: именованные и позиционные аргументы, значения по умолчанию и VARIADIC.
