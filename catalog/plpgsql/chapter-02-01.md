# §2.1 Структура блока

В [§1.4](chapter-01-04.md) мы выполнили первый анонимный блок с минимальной структурой BEGIN ... END. В этом разделе разберём **полную структуру блока** PL/pgSQL: необязательная метка, секция DECLARE для объявления переменных и курсоров, обязательные BEGIN и END, необязательная секция EXCEPTION для обработки ошибок и правила для меток и вложенных блоков. Объявление переменных (типы, DEFAULT, %TYPE, %ROWTYPE) подробно рассмотрено в [§2.2](chapter-02-02.md), присваивание — в [§2.3](chapter-02-03.md); обработка исключений по типам ошибок — в гл. 4. Здесь — общая схема блока и порядок секций. См. [Глоссарий](glossary.md).

---

## 2.1.1. Полный синтаксис блока

PL/pgSQL — язык с блочной структурой: тело функции, процедуры или анонимного блока DO должно быть **одним блоком**. Блок задаётся так (по документации PostgreSQL):

```
[ <<метка>> ]
[ DECLARE
    объявления ]
BEGIN
  операторы
[ EXCEPTION
    WHEN условие [ OR условие ... ] THEN
      операторы_обработчика
    [ WHEN условие [ OR условие ... ] THEN
      операторы_обработчика
      ... ]
]
END [ метка ];
```

Квадратные скобки обозначают необязательные части. **Порядок секций фиксирован:** сначала при необходимости метка и DECLARE, затем обязательно BEGIN и операторы, затем при необходимости EXCEPTION с обработчиками, затем END с опциональной меткой. Секция EXCEPTION не может стоять отдельно от BEGIN: это одна конструкция «блок с обработкой ошибок». См. [Глоссарий](glossary.md).

Каждое объявление в DECLARE и каждый оператор завершаются **точкой с запятой**. После `END` вложенного блока точка с запятой обязательна; после конечного `END` всего тела (например, функции) точка с запятой не обязательна. Типичная ошибка — ставить точку с запятую сразу после `BEGIN`; так делать нельзя, это приводит к синтаксической ошибке.

---

## 2.1.2. Секция DECLARE

Секция **DECLARE** идёт сразу после метки блока (если она есть) и перед **BEGIN**. В ней объявляются локальные переменные, константы, курсоры и другие объекты, видимые во всём блоке (до конца этого блока, включая обработчики EXCEPTION). См. [Глоссарий](glossary.md).

Формат объявлений: каждое объявление — на одной строке или нескольких, заканчивается точкой с запятой. Пример без деталей типов (они в [§2.2](chapter-02-02.md)):

```sql
DECLARE
  counter integer;
  user_name text := 'unknown';
  row_rec tablename%ROWTYPE;
BEGIN
  -- операторы, использующие counter, user_name, row_rec
END;
```

Если переменные не нужны, секцию DECLARE можно опустить — тогда блок начинается сразу с BEGIN. В одном блоке может быть только одна секция DECLARE, и она должна располагаться целиком перед первым оператором (перед BEGIN).

---

## 2.1.3. BEGIN и операторы

**BEGIN** открывает исполняемую часть блока. Между **BEGIN** и **END** (или перед **EXCEPTION**, если он есть) идут **операторы** PL/pgSQL: присваивания, вызовы SQL (SELECT, INSERT, UPDATE, DELETE и т.д.), управляющие конструкции (IF, LOOP, и т.д.), вложенные блоки, вызовы процедур (CALL) и т.п. Каждый оператор заканчивается точкой с запятой.

Важно не путать **BEGIN/END в PL/pgSQL** с одноимёнными командами SQL. В SQL команды `BEGIN` и `COMMIT`/`ROLLBACK` управляют транзакцией. В PL/pgSQL пара `BEGIN`/`END` только группирует операторы внутри блока; она **не начинает и не завершает транзакцию**. Транзакция определяется сессией и явными COMMIT/ROLLBACK (в процедурах они допустимы; в функциях и в DO внутри транзакции — с ограничениями). См. документацию PostgreSQL, раздел 41.8 (Transactions).

---

## 2.1.4. Секция EXCEPTION

Сразу перед закрывающим **END** блока можно указать секцию **EXCEPTION**. В ней перечисляются обработчики: при какой ошибке (условие) выполнять какие операторы. Если во время выполнения операторов между BEGIN и EXCEPTION возникает ошибка, дальнейшее выполнение операторов прерывается и управление переходит в список EXCEPTION; ищется первый подходящий обработчик (WHEN условие THEN ...), выполняются его операторы, после чего управление переходит к следующему оператору после всего блока. Если подходящего обработчика нет, ошибка распространяется наружу (к вызывающему или прерывает транзакцию). См. [Глоссарий](glossary.md).

Блок с EXCEPTION образует по сути подтранзакцию: при входе в такой блок создаётся точка сохранения, и при попадании в обработчик откатываются только изменения, сделанные внутри этого блока; изменения снаружи блока сохраняются. Подробнее обработка ошибок, коды условий (SQLSTATE, OTHERS) и получение информации об ошибке — гл. 4.

Пример минимальной структуры (обработчик просто завершает блок):

```sql
BEGIN
  -- операторы
EXCEPTION
  WHEN OTHERS THEN
    RAISE NOTICE 'Ошибка: %', SQLERRM;
END;
```

Если EXCEPTION не нужен, его не пишут — тогда блок заканчивается сразу на END.

## 2.1.5. Метки блока

Перед блоком можно указать **метку** в двойных угловых скобках: `<<имя_метки>>`. Та же метка может быть указана после закрывающего END: `END имя_метки;`. Метка после END должна совпадать с меткой в начале блока. См. [Глоссарий](glossary.md).

Метка нужна в двух случаях:

1. **EXIT с меткой:** чтобы выйти из вложенного блока или из внешнего цикла оператором EXIT 'метка' (подробнее гл. 3).
2. **Квалификация имён переменных:** во вложенном блоке переменная внутреннего блока перекрывает одноимённую переменную внешнего. Чтобы обратиться к переменной внешнего блока, используют квалифицированное имя: `метка.имя_переменной`. Например, во вложенном блоке с переменной `quantity` обращение `outerblock.quantity` даёт переменную внешнего блока с меткой `<<outerblock>>`.

Пример (по документации PostgreSQL, адаптировано):

```sql
<<outerblock>>
DECLARE
  quantity integer := 30;
BEGIN
  quantity := 50;
  DECLARE
    quantity integer := 80;
  BEGIN
    RAISE NOTICE 'Внутри: %', quantity;           -- 80
    RAISE NOTICE 'Снаружи: %', outerblock.quantity; -- 50
  END;
  RAISE NOTICE 'Снова снаружи: %', quantity;       -- 50
END;
```

Без метки во вложенном блоке нельзя было бы обратиться к внешней `quantity`.

## 2.1.6. Вложенные блоки и точка с запятой

Любой оператор в исполняемой части блока может быть **вложенным блоком**: у него свои DECLARE (если нужны), BEGIN, при необходимости EXCEPTION и END. Вложенный блок даёт локальную область видимости: переменные, объявленные в нём, видны только внутри него и перекрывают одноимённые переменные внешнего блока; снаружи к ним обратиться можно только через метку внешнего блока, если переменная там объявлена с тем же именем. См. [Глоссарий](glossary.md).

Правило для точки с запятой: **после END вложенного блока точка с запятой обязательна**, так как этот END завершает оператор. После конечного END всего тела (функции, DO) точка с запятой не обязательна — границу оператора задаёт конец строки или следующий символ (например, `$$` в DO).

Комментарии в PL/pgSQL работают как в SQL: `--` до конца строки, `/* ... */` для блочного комментария; блочные комментарии могут быть вложенными. Ключевые слова не чувствительны к регистру; идентификаторы без двойных кавычек приводятся к нижнему регистру.

---

## Ключевое

- Блок PL/pgSQL: необязательная **метка** `<<имя>>`, необязательная секция **DECLARE**, обязательные **BEGIN** и **END**, необязательная секция **EXCEPTION** (сразу перед END).
- **DECLARE** — объявления переменных, констант, курсоров; одна секция на блок, перед BEGIN. Подробнее [§2.2](chapter-02-02.md).
- **BEGIN/END** в PL/pgSQL только группируют операторы; они не управляют транзакцией (в отличие от SQL COMMIT/ROLLBACK).
- **EXCEPTION** — обработка ошибок; при ошибке управление переходит в список WHEN; блок с EXCEPTION образует подтранзакцию. Подробнее гл. 4.
- **Метка** нужна для EXIT с меткой и для квалификации имён переменных во вложенных блоках (`метка.переменная`).
- Каждый оператор и каждое объявление заканчиваются точкой с запятой; после END вложенного блока точка с запятой обязательна; не ставить точку с запятой сразу после BEGIN.

В [§2.2](chapter-02-02.md) мы разберём объявление переменных: типы, DEFAULT, %TYPE и %ROWTYPE.
