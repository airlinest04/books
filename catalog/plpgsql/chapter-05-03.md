# §5.3 RETURN

В [§5.2](chapter-05-02.md) мы разобрали параметры функций. В этом разделе рассмотрим **возврат значения** из функции: **RETURN выражение** для одного значения, **RETURN NEXT** и **RETURN QUERY** для функций, возвращающих **набор строк** (RETURNS SETOF или RETURNS TABLE). Кратко затронем RETURN в процедуре и при OUT-параметрах. Динамический RETURN QUERY EXECUTE и детали работы с наборами — в гл. 7. См. [Глоссарий](glossary.md).

---

## 5.3.1. RETURN выражение — возврат одного значения

Функция, объявленная с **RETURNS тип** (скаляр или одна строка/запись), завершает выполнение и возвращает значение оператором **RETURN выражение**. Выражение должно приводиться к возвращаемому типу. После выполнения RETURN управление выходит из функции; следующие операторы не выполняются. См. [Глоссарий](glossary.md).

Примеры (по документации PostgreSQL):

```sql
RETURN 1 + 2;
RETURN scalar_var;
RETURN composite_var;
RETURN (col1, col2, col3);   -- для составного типа может потребоваться явное приведение
```

Если функция объявлена как **RETURNS void**, допустим только **RETURN;** без выражения — досрочный выход. Если возвращаемый тип задан, функция обязана вернуть значение: достижение конца тела без RETURN (и без OUT-параметров, которые считаются возвратом) приведёт к ошибке времени выполнения. При объявлении с **OUT-**параметрами можно писать **RETURN;** без выражения — вернутся текущие значения OUT.

---

## 5.3.2. RETURN NEXT — добавление строки в набор результата

Функция может быть объявлена как возвращающая **набор** строк: **RETURNS SETOF тип** или **RETURNS TABLE(...)**. В таком случае строки формируются операторами **RETURN NEXT** и/или **RETURN QUERY**; завершает функцию **RETURN;** без аргумента (или достижение конца тела). См. [Глоссарий](glossary.md).

**RETURN NEXT выражение;** добавляет одну строку в результат функции и **не** выходит из функции — выполнение продолжается со следующего оператора. Выражение должно соответствовать типу элемента набора (скаляр или строка/запись). Несколько RETURN NEXT подряд формируют несколько строк; в конце нужен **RETURN;** (без выражения), чтобы выйти из функции.

Пример (по документации PostgreSQL, адаптировано):

```sql
CREATE FUNCTION get_all_foo() RETURNS SETOF foo AS $$
DECLARE
  r foo%ROWTYPE;
BEGIN
  FOR r IN SELECT * FROM foo WHERE fooid > 0 LOOP
    -- возможна обработка
    RETURN NEXT r;
  END LOOP;
  RETURN;
END;
$$ LANGUAGE plpgsql;

SELECT * FROM get_all_foo();
```

Если функция объявлена с **OUT-**параметрами и возвращает набор, пишут **RETURN NEXT** без выражения — в результат попадают текущие значения OUT-переменных. При нескольких OUT функция должна быть объявлена как RETURNS SETOF record (или эквивалент).

---

## 5.3.3. RETURN QUERY — добавление результата запроса

**RETURN QUERY запрос;** выполняет запрос (SELECT или команду с RETURNING) и **добавляет все его строки** к результату функции. Запрос пишется как обычный SQL; переменные PL/pgSQL в нём подставляются как параметры. RETURN QUERY можно комбинировать с RETURN NEXT в одной функции — строки объединяются в общий результат. См. [Глоссарий](glossary.md).

Пример (по документации PostgreSQL):

```sql
CREATE FUNCTION get_available_flightid(d date) RETURNS SETOF integer AS $$
BEGIN
  RETURN QUERY SELECT flightid
    FROM flight
    WHERE flightdate >= d AND flightdate < (d + 1);
  IF NOT FOUND THEN
    RAISE EXCEPTION 'No flight at %.', d;
  END IF;
  RETURN;
END;
$$ LANGUAGE plpgsql;
```

**RETURN QUERY EXECUTE строка_запроса [ USING выражение, ... ]** — вариант для динамического запроса (строка собирается в переменной); подробнее в гл. 7.

---

## 5.3.4. Порядок выполнения и накопление результата

RETURN NEXT и RETURN QUERY **не выходят** из функции — они только добавляют строки к внутреннему набору результата. Текущая реализация PL/pgSQL **сначала накапливает весь набор**, и только затем результат передаётся вызывающему. Поэтому функции, возвращающие очень большой набор, могут потреблять много памяти или сбрасывать данные на диск (зависит от work_mem); сама функция не завершится, пока не сформирует все строки. См. документацию PostgreSQL, раздел 41.6.1.2. См. [Глоссарий](glossary.md).

Финальный **RETURN;** (без выражения) завершает функцию; без него при достижении конца тела функция тоже завершится, но для ясности его рекомендуется писать явно.

---

## 5.3.5. RETURN в процедуре

**Процедура** (CREATE PROCEDURE) не возвращает значение в выражении. В теле процедуры **RETURN;** без выражения допустим для досрочного выхода. Если у процедуры есть OUT-параметры, их итоговые значения возвращаются вызывающему при выходе (но не через RETURN с выражением). Подробнее процедуры — гл. 6. См. [Глоссарий](glossary.md).

---

## Ключевое

- **RETURN выражение** — возврат одного значения и выход из функции; для RETURNS void допустим только **RETURN;**.
- Функция с возвращаемым типом должна выполнить RETURN (или вернуть через OUT); иначе — ошибка при достижении конца тела.
- **RETURN NEXT выражение** — добавить строку в набор результата (RETURNS SETOF / TABLE); выполнение продолжается; в конце — **RETURN;** без аргумента.
- **RETURN QUERY запрос** — добавить все строки результата запроса к набору; можно комбинировать с RETURN NEXT.
- Набор результата формируется целиком до выхода из функции; для больших объёмов это может влиять на память и производительность.

В [§5.4](chapter-05-04.md) мы разберём атрибуты VOLATILITY (VOLATILE, STABLE, IMMUTABLE) и их влияние на оптимизатор и параллельное выполнение.
