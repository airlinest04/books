# §4.4 RAISE

В [§4.3](chapter-04-03.md) мы разобрали получение информации об ошибке в обработчике. В этом разделе рассмотрим **RAISE** — оператор PL/pgSQL для явной отправки сообщений и вызова исключений: уровни серьёзности (EXCEPTION, WARNING, NOTICE и др.), формат сообщения с подстановкой, опции USING (DETAIL, HINT, ERRCODE) и **перевыброс** текущего исключения (RAISE без параметров). С этим завершается глава 4; далее — гл. 5 (функции). См. [Глоссарий](glossary.md).

---

## 4.4.1. Синтаксис RAISE и уровни серьёзности

**RAISE** позволяет отправить сообщение клиенту и/или в лог сервера либо возбудить исключение и прервать выполнение. Общий вид (по документации PostgreSQL):

```
RAISE [ уровень ] 'формат' [ , выражение [ , ... ] ] [ USING вариант = выражение [ , ... ] ];
```

**Уровень (level)** задаёт серьёзность. Допустимые значения (от менее к более «серьёзным»): **DEBUG**, **LOG**, **INFO**, **NOTICE**, **WARNING**, **EXCEPTION**. Если уровень не указан, по умолчанию принимается **EXCEPTION**. См. [Глоссарий](glossary.md).

- **EXCEPTION** — возбуждает ошибку: выполнение прерывается, транзакция откатывается (если не перехватить в EXCEPTION). Сообщение передаётся клиенту как текст ошибки.
- **DEBUG**, **LOG**, **INFO**, **NOTICE**, **WARNING** — только сообщения; выполнение продолжается. Попадают в лог сервера и/или клиент в зависимости от настроек `client_min_messages` и `log_min_messages`. NOTICE по умолчанию виден клиенту (например, в psql).

В формате символ **%** подставляет следующее выражение из списка (по порядку); **%%** выводит один символ %. Количество % должно соответствовать числу выражений после формата.

---

## 4.4.2. RAISE EXCEPTION — явный вызов ошибки

**RAISE EXCEPTION** прерывает выполнение и передаёт клиенту сообщение об ошибке. Используется для проверок (например, не найден объект, неверный аргумент) и для перевыброса с дополнением. См. [Глоссарий](glossary.md).

Примеры:

```sql
RAISE EXCEPTION 'Идентификатор не найден: %', user_id;

RAISE EXCEPTION 'Недопустимое значение % для поля %', v_value, field_name;
```

С опцией **USING** можно задать код ошибки, детали и подсказку (как у «настоящих» ошибок PostgreSQL):

```sql
RAISE EXCEPTION 'Дубликат ключа'
  USING ERRCODE = 'unique_violation',
        HINT = 'Проверьте уникальность поля code',
        DETAIL = 'Значение: ' || v_code;
```

**ERRCODE** — пятисимвольный SQLSTATE (например, '23505' для unique_violation). Без USING используется код 'P0001' (raise_exception). **DETAIL** и **HINT** — дополнительные строки, которые клиент и логи могут показать отдельно.

---

## 4.4.3. RAISE NOTICE, WARNING и другие уровни для отладки

**RAISE NOTICE** выводит сообщение клиенту (в psql — в консоль) и при необходимости в лог. Удобно для отладки: вывести значение переменной или метку «дошло сюда». См. [Глоссарий](glossary.md).

Примеры:

```sql
RAISE NOTICE 'Текущее значение counter: %', counter;
RAISE NOTICE 'Выполнен блок обновления для id = %', rec.id;
```

**RAISE WARNING** — предупреждение; выполнение не прерывается. **RAISE INFO** и **RAISE DEBUG** — информационные и отладочные сообщения; по умолчанию DEBUG не показывается клиенту (зависит от client_min_messages). **RAISE LOG** пишет в лог сервера. Для повседневной отладки в разработке чаще всего используют NOTICE.

## 4.4.4. Перевыброс исключения: RAISE без параметров

Внутри обработчика **EXCEPTION** оператор **RAISE;** (без уровня, без формата и без USING) **перевыбрасывает текущее перехваченное исключение**. Ошибка с тем же кодом и сообщением передаётся наверх (внешнему блоку или вызывающему). Используется, когда в обработчике нужно залогировать ошибку или выполнить действия, после чего пробросить её дальше. См. [Глоссарий](glossary.md).

Пример (уже встречался в §4.2, §4.3):

```sql
EXCEPTION
  WHEN OTHERS THEN
    INSERT INTO error_log (code, message) VALUES (SQLSTATE, SQLERRM);
    RAISE;   -- перевыброс без изменений
END;
```

После **RAISE;** выполнение обработчика прерывается; следующий оператор в том же обработчике не выполнится. Исключение распространяется так, как если бы блок EXCEPTION его не перехватывал (но изменения в обработчике до RAISE уже выполнены, например запись в error_log).

---

## 4.4.5. Формат сообщения и использование %

В строке формата **%** заменяется на следующее значение из списка выражений (в текстовом виде). Для вывода одного символа % используется **%%**. Количество плейсхолдеров % должно совпадать с количеством выражений. См. [Глоссарий](glossary.md).

Пример:

```sql
RAISE NOTICE 'Пользователь % (id=%) выполнил действие %', user_name, user_id, action;
```

Если выражений меньше, чем %, оставшиеся % дадут пустую подстановку или ошибку в зависимости от контекста; лишние выражения игнорируются. Формат не поддерживает спецификаторы ширины или типа, как в C (только % и %%).

---

## Ключевое

- **RAISE уровень 'формат' [, выражение, ...] [USING вариант = выражение, ...]** — отправка сообщения или вызов исключения; уровень: DEBUG, LOG, INFO, NOTICE, WARNING, EXCEPTION (по умолчанию EXCEPTION).
- **RAISE EXCEPTION** прерывает выполнение и откатывает транзакцию; через **USING** задают ERRCODE, HINT, DETAIL.
- **RAISE NOTICE** и **RAISE WARNING** не прерывают выполнение; NOTICE удобен для отладки (вывод в клиент).
- **RAISE;** без параметров в обработчике EXCEPTION перевыбрасывает текущее исключение.
- В формате **%** подставляет следующее выражение, **%%** — один символ %.
