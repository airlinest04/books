# §4.2 Обработка по типу ошибки

В [§4.1](chapter-04-01.md) мы разобрали, когда управление переходит в EXCEPTION и как завершается блок. В этом разделе рассмотрим **условия** в WHEN: по **имени условия** (condition name), по **коду SQLSTATE** и универсальное **OTHERS**; приведём таблицу типичных кодов и рекомендации по порядку обработчиков. Полный список кодов — в приложении A документации PostgreSQL (Error Codes). Получение текста и кода ошибки в обработчике (SQLSTATE, SQLERRM) — в [§4.3](chapter-04-03.md). См. [Глоссарий](glossary.md).

---

## 4.2.1. Имя условия (condition name)

В WHEN можно указать **имя условия** — символьное имя, соответствующее коду ошибки PostgreSQL. Имена приведены в приложении A документации (PostgreSQL Error Codes); в колонке «Condition Name» указано, как писать имя в PL/pgSQL. Регистр не важен: `unique_violation` и `UNIQUE_VIOLATION` допустимы. См. [Глоссарий](glossary.md).

Примеры:

```sql
EXCEPTION
  WHEN unique_violation THEN
    -- нарушение уникальности (дубликат ключа)
  WHEN not_null_violation THEN
    -- нарушение NOT NULL
  WHEN division_by_zero THEN
    -- деление на ноль
```

Имена условий стабильны между версиями и не зависят от локализации сообщений; их предпочтительно использовать вместо сравнения с текстом сообщения.

---

## 4.2.2. WHEN SQLSTATE 'код'

Ошибки в PostgreSQL имеют пятисимвольный код **SQLSTATE** (по стандарту SQL). В WHEN можно указать код напрямую: **WHEN SQLSTATE 'код'**. Например, `WHEN SQLSTATE '23505'` эквивалентно `WHEN unique_violation`, `WHEN SQLSTATE '22012'` — `WHEN division_by_zero`. См. [Глоссарий](glossary.md).

Пример:

```sql
WHEN division_by_zero THEN ...
WHEN SQLSTATE '22012' THEN ...   -- то же самое
```

Коды перечислены в приложении A документации PostgreSQL. Удобно, когда нужно обработать ошибку, для которой в PL/pgSQL нет отдельного имени условия, или когда код приходит из внешнего источника.

---

## 4.2.3. Категория ошибок (класс SQLSTATE)

Первые **два символа** SQLSTATE задают **класс** ошибок. В приложении A для класса указан «общий» код с последними тремя цифрами `000` и имя условия (например, класс 23 — Integrity Constraint Violation, условие `integrity_constraint_violation`, код `23000`). Условие по **имени класса** перехватывает **любую** ошибку этого класса. См. [Глоссарий](glossary.md).

Пример: класс 23 — нарушения ограничений целостности; сюда входят unique_violation, not_null_violation, foreign_key_violation, check_violation и др. Один обработчик на весь класс:

```sql
EXCEPTION
  WHEN integrity_constraint_violation THEN
    -- любая ошибка класса 23 (23502, 23503, 23505, 23514, ...)
```

Если нужна разная реакция на разные типы нарушений, перечисляют более частные условия **перед** общим (первый подходящий обработчик выполняется).

---

## 4.2.4. WHEN OTHERS

Условие **OTHERS** перехватывает **любую** ошибку (любой SQLSTATE), кроме двух: **QUERY_CANCELED** (отмена запроса, например пользователем) и **ASSERT_FAILURE**. Их по умолчанию не перехватывают, чтобы не скрывать отмену и сбой утверждений. При необходимости эти два типа можно обработать явно по имени. См. [Глоссарий](glossary.md).

Пример:

```sql
EXCEPTION
  WHEN unique_violation THEN
    -- своя обработка дубликата
  WHEN OTHERS THEN
    -- любая другая ошибка (кроме query_canceled и assert_failure)
    RAISE NOTICE 'Ошибка: %', SQLERRM;
    RAISE;   -- перевыбросить (см. §4.4)
```

OTHERS обычно ставят **последним** обработчиком: сначала перехватывают конкретные коды, затем OTHERS как «запасной вариант». В OTHERS часто логируют ошибку и вызывают RAISE для передачи её выше.

---

## 4.2.5. Типичные коды ошибок

Ниже — часто используемые имена условий и коды SQLSTATE (по документации PostgreSQL, приложение A). Полный список — в документации.

| Условие | SQLSTATE | Описание |
|---------|----------|----------|
| unique_violation | 23505 | Нарушение уникальности (дубликат ключа) |
| not_null_violation | 23502 | Нарушение NOT NULL |
| foreign_key_violation | 23503 | Нарушение внешнего ключа |
| check_violation | 23514 | Нарушение CHECK |
| exclusion_violation | 23P01 | Нарушение EXCLUDE |
| integrity_constraint_violation | 23000 | Любая ошибка класса 23 |
| division_by_zero | 22012 | Деление на ноль |
| no_data_found | P0002 | SELECT INTO не вернул строку (при STRICT) |
| too_many_rows | P0003 | SELECT INTO вернул более одной строки (при STRICT) |
| case_not_found | 20000 | CASE без подходящей ветки и без ELSE |
| syntax_error | 42601 | Синтаксическая ошибка SQL |
| undefined_table | 42P01 | Таблица не найдена |
| undefined_column | 42703 | Столбец не найден |

Класс 22 — data_exception (ошибки данных); класс 42 — syntax_error_or_access_rule_violation. Для предупреждений (классы 00, 01, 02) имена условий в PL/pgSQL не распознаются как перехватываемые исключения (документация PostgreSQL).

---

## 4.2.6. Несколько условий в одном WHEN и порядок обработчиков

В одном WHEN можно перечислить несколько условий через **OR**: `WHEN условие1 OR условие2 OR условие3 THEN ...`. Тогда выполняется один и тот же обработчик при любой из перечисленных ошибок. См. [Глоссарий](glossary.md).

Обработчики просматриваются **сверху вниз**; выполняется **первый** подходящий. Поэтому более **частные** условия (конкретный код или имя) обычно ставят **выше** общих (категория, OTHERS). Иначе общий обработчик перехватит всё и частные никогда не сработают.

Пример:

```sql
EXCEPTION
  WHEN unique_violation THEN
    -- только дубликат
  WHEN integrity_constraint_violation THEN
    -- остальные нарушения ограничений класса 23
  WHEN OTHERS THEN
    -- всё остальное
END;
```

---

## Ключевое

- В **WHEN** указывают **имя условия** (например, unique_violation) или **SQLSTATE 'код'**; регистр имён не важен.
- **Имя класса** (например, integrity_constraint_violation) перехватывает любую ошибку этого класса SQLSTATE.
- **OTHERS** перехватывает все ошибки, кроме QUERY_CANCELED и ASSERT_FAILURE.
- Частные условия ставят **выше** общих; в одном WHEN можно перечислить условия через OR.
- Полный список кодов — приложение A документации PostgreSQL (Error Codes).

В [§4.3](chapter-04-03.md) мы разберём получение информации об ошибке в обработчике: SQLSTATE, SQLERRM и GET STACKED DIAGNOSTICS.
