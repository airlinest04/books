# §9.4 Отладка и диагностика

В [§9.3](chapter-09-03.md) мы сравнили правила и триггеры. В этом разделе — **отладка и диагностика** кода на PL/pgSQL: вывод значений переменных через **RAISE NOTICE** и **RAISE DEBUG**, проверка **синтаксиса** без полного выполнения (DO-блок, компиляция функции) и **типичные ошибки** при написании функций и триггеров. Этим завершается глава 9 и основная часть книги; далее — [Глоссарий](glossary.md) и список литературы. См. [Глоссарий](glossary.md).

## 9.4.1. RAISE NOTICE и RAISE DEBUG для отладки

Оператор **RAISE** с уровнями **NOTICE**, **DEBUG**, **LOG**, **INFO**, **WARNING** не прерывает выполнение и выводит сообщение (подробнее — [§4.4](chapter-04-04.md)). Для отладки чаще всего используют **RAISE NOTICE**: сообщение по умолчанию попадает клиенту (в psql выводится в консоль). В формате строки символ **%** подставляет следующее выражение из списка. См. [Глоссарий](glossary.md).

Примеры вывода переменных:

```sql
RAISE NOTICE 'user_id = %, name = %', user_id, user_name;
RAISE NOTICE 'Строка: %', row_var;
```

**RAISE DEBUG** выводит сообщение только если уровень логирования клиента допускает DEBUG (в psql: `SET client_min_messages = DEBUG;`). Удобно для подробного трассирования без засорения вывода в обычном режиме. В продакшене можно оставить RAISE DEBUG в коде и управлять видимостью через `client_min_messages`.

После отладки лишние RAISE NOTICE/DEBUG лучше удалить или заменить на условное логирование (проверка переменной или уровня), чтобы не засорять логи.

## 9.4.2. Проверка синтаксиса: DO-блок и компиляция функции

Проверить, что блок PL/pgSQL **синтаксически корректен**, можно, выполнив **DO** с этим блоком. Если в блоке только объявления и пустое тело или минимальная логика, выполнение быстро завершится и ошибки компиляции (неверный синтаксис, несуществующие типы, опечатки в именах) будут видны сразу. См. [Глоссарий](glossary.md).

Пример: проверить, что фрагмент кода компилируется:

```sql
DO $$
DECLARE
  x int;
BEGIN
  SELECT 1 INTO x;
  RAISE NOTICE 'ok';
END;
$$;
```

При создании функции **CREATE FUNCTION** проверяется синтаксис тела; при ошибке функция не будет создана. Поэтому «сохранить» функцию с заведомо неверным телом нельзя — ошибка появится уже на этапе CREATE. Чтобы проверить только компиляцию без создания объекта, можно временно обернуть тело в DO и выполнить.

## 9.4.3. Типичные ошибки при написании функций

**Функция с RETURNS тип не вернула значение** — выполнение вышло из тела без выполнения RETURN (достигнут конец блока или выход по EXCEPTION без RETURN). Нужен хотя бы один исполняемый RETURN на каждой ветке выхода. Исключение: RETURNS void и функция с только OUT-параметрами. См. [Глоссарий](glossary.md).

**SELECT без INTO в теле функции** — в PL/pgSQL запрос, возвращающий строки, должен быть либо **SELECT ... INTO** (или RETURNING ... INTO), либо **PERFORM** (результат отбрасывается). Один только SELECT без INTO приводит к ошибке. См. [§7.1](chapter-07-01.md).

**Путаница SELECT INTO в PL/pgSQL и в SQL** — в SQL команда SELECT INTO создаёт таблицу; в PL/pgSQL SELECT ... INTO присваивает результат переменным. Внутри функции/процедуры всегда трактуется как присваивание. См. [§2.3](chapter-02-03.md).

**Триггерная функция: неверный возврат** — для BEFORE по строке нужно RETURN NEW или RETURN OLD (или NULL для отмены); для AFTER — возврат игнорируется, обычно RETURN NULL. Возврат выражения в AFTER или возврат не того типа в BEFORE приводит к ошибкам. См. [§8.2](chapter-08-02.md).

**Использование переменной до присваивания** — переменная RECORD или составного типа до первого присваивания не имеет полей; обращение к полю даёт ошибку. Проверять FOUND после SELECT INTO или инициализировать переменные в DECLARE. См. [§2.2](chapter-02-02.md).

**EXCEPTION и производительность** — блок с EXCEPTION дороже входа/выхода; не оборачивать в EXCEPTION большие куски кода «на всякий случай», только там, где реально обрабатываем ошибку. См. гл. 4.

## Ключевое

- **RAISE NOTICE** — вывод в клиент (psql) для отладки; **RAISE DEBUG** — при `client_min_messages = DEBUG`; в формате используется **%** для подстановки выражений.
- Проверка синтаксиса: выполнить **DO $$ ... $$** с фрагментом кода или создать функцию (CREATE FUNCTION проверяет тело при создании).
- Типичные ошибки: нет RETURN во всех ветках; SELECT без INTO (нужен INTO или PERFORM); триггер возвращает не то (NEW/OLD/NULL); использование переменной до присваивания; избыточное использование EXCEPTION.
