# §5.2 Параметры

В [§5.1](chapter-05-01.md) мы разобрали CREATE FUNCTION и общий вид параметров (IN, OUT, INOUT). В этом разделе рассмотрим **именованные и позиционные** параметры (обращение в теле и при вызове), **значения по умолчанию** (DEFAULT) и **VARIADIC** — параметр в виде массива для переменного числа аргументов. Вызов функции и передача аргументов по имени подробнее — в [§5.5](chapter-05-05.md). См. [Глоссарий](glossary.md).

---

## 5.2.1. Именованные и позиционные параметры в теле функции

В теле функции PL/pgSQL параметры доступны **по позиции** — как **$1**, **$2**, … (порядок следования в списке параметров CREATE FUNCTION), — и **по имени**, если имя указано в определении функции. Имя задаётся в CREATE FUNCTION: `имя_аргумента тип`. Тогда в теле можно писать как `$1`, так и `имя_аргумента`. Для выходных (OUT, INOUT) параметров имя важно ещё и тем, что задаёт имя столбца в возвращаемой записи при вызове `SELECT * FROM func(...)`. См. [Глоссарий](glossary.md).

Пример (по документации PostgreSQL):

```sql
CREATE FUNCTION sales_tax(subtotal real) RETURNS real AS $$
BEGIN
  RETURN subtotal * 0.06;
END;
$$ LANGUAGE plpgsql;
```

Здесь `subtotal` и `$1` — один и тот же параметр. Если имя не указано (например, `CREATE FUNCTION f(real)`), в теле доступны только `$1`, `$2`, … Для читаемости рекомендуется задавать имена входных параметров в CREATE FUNCTION. Для совместимости со старым кодом в DECLARE можно объявить алиас: **имя ALIAS FOR $n;** — тогда в теле используется это имя.

## 5.2.2. Значения по умолчанию (DEFAULT)

У **входных** параметров (IN и INOUT) можно задать значение по умолчанию: **argtype DEFAULT выражение** или **argtype = выражение**. При вызове функции соответствующий аргумент можно не передавать — подставится выражение по умолчанию. Выражение должно приводиться к типу параметра и вычисляется при каждом вызове (не при создании функции). См. [Глоссарий](glossary.md).

Важное правило (по документации PostgreSQL): **все параметры, следующие за параметром с DEFAULT, тоже должны иметь значение по умолчанию**. Иначе вызов с опущенным аргументом был бы неоднозначным (неясно, какой аргумент опущен). OUT-параметры не передаются при вызове, поэтому DEFAULT для них не задаётся.

Пример:

```sql
CREATE FUNCTION discount(amount numeric, rate numeric DEFAULT 0.1)
RETURNS numeric AS $$
BEGIN
  RETURN amount * (1 - rate);
END;
$$ LANGUAGE plpgsql;

-- вызовы:
SELECT discount(100);        -- rate = 0.1
SELECT discount(100, 0.2);   -- rate = 0.2
SELECT discount(amount => 100, rate => 0.15);  -- по имени (§5.5)
```

При перегрузке (несколько функций с одним именем и разными типами) вызов с опущенными аргументами может оказаться неоднозначным, если подходят несколько вариантов — тогда PostgreSQL выдаст ошибку.

## 5.2.3. VARIADIC — переменное число аргументов

Параметр можно объявить как **VARIADIC**: он принимает **массив** значений; при вызове можно передать несколько аргументов одного типа, и они будут собраны в массив. В объявлении указывают тип **массива** (например, **VARIADIC arr integer[]** или **VARIADIC arr text[]**). При вызове передают либо один массив: `func(ARRAY[1,2,3])`, либо список элементов: `func(1, 2, 3)` — в теле параметр будет массивом. См. [Глоссарий](glossary.md).

В списке параметров **VARIADIC** может быть только один и должен стоять **последним** среди входных; после него допускаются только OUT-параметры (по документации PostgreSQL). В теле функции переменная имеет тип массива; перебирать элементы можно через FOREACH или по индексу.

Пример:

```sql
CREATE FUNCTION sum_vals(VARIADIC vals integer[]) RETURNS integer AS $$
DECLARE
  s integer := 0;
  x integer;
BEGIN
  FOREACH x IN ARRAY vals LOOP
    s := s + x;
  END LOOP;
  RETURN s;
END;
$$ LANGUAGE plpgsql;

SELECT sum_vals(1, 2, 3, 4, 5);   -- 15
SELECT sum_vals(ARRAY[10, 20]);   -- 30
```

Функция с VARIADIC при перегрузке может конфликтовать с функцией, принимающей один аргумент — массив того же типа; вызов с одним массивом может быть неоднозначным.

## 5.2.4. Позиционная и именованная передача при вызове

При вызове функции аргументы можно передавать **позиционно** (в том же порядке, что и параметры) или **по имени**: `имя_параметра => значение`. Именованная передача удобна при большом числе параметров и при наличии DEFAULT — можно задать только нужные. Подробнее синтаксис вызова и смешение позиционных и именованных аргументов — в [§5.5](chapter-05-05.md). См. [Глоссарий](glossary.md).

Кратко: после первого именованного аргумента все следующие должны быть именованными; позиционные идут до любых именованных. Порядок именованных аргументов может не совпадать с порядком параметров в определении.

---

## Ключевое

- В теле функции параметры доступны по **позиции** ($1, $2, …) и по **имени**, если оно задано в CREATE FUNCTION; имена OUT задают имена столбцов результата.
- **DEFAULT** (или =) задаётся только для IN и INOUT; все параметры **после** параметра с DEFAULT тоже должны иметь DEFAULT.
- **VARIADIC** — один последний входной параметр типа массив; при вызове можно передать список значений или один массив; в теле — переменная-массив.
- При вызове аргументы можно передавать позиционно или по имени (имя => значение); детали в §5.5.

В [§5.3](chapter-05-03.md) мы разберём RETURN: возврат одного значения, RETURN NEXT и RETURN QUERY для набора строк.
