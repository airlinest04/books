# §7.4 Мониторинг и логи

В [§7.3](chapter-07-03.md) мы разобрали параметры и конфигурацию. В этом разделе рассматриваются **мониторинг и логи**: **Spark UI** (веб-интерфейс для наблюдения за выполнением заданий), **логи** приложения Datagram и оркестратора и **отладка сбоев** — как находить причину ошибки и что проверять. Раздел завершает главу 7; в [§8.1](chapter-08-01.md) мы перейдём к практике — постановке задачи пайплайна загрузки из HDFS в DWH. См. [Глоссарий](glossary.md).

## 7.4.1. Spark UI

**Spark UI** — веб-интерфейс приложения Spark, доступный во время и после выполнения задания. Драйвер поднимает HTTP-сервер на порту (по умолчанию 4040 для текущего приложения); адрес указывается в логах при запуске и может быть проброшен через прокси при работе за фаерволом. В кластерном режиме (YARN cluster, K8s) UI драйвера доступен по ссылке из интерфейса менеджера кластера (YARN Application Master, история приложений).

В Spark UI можно посмотреть:

- **Jobs** — задания (действия над данными: count, save, collect и т.д.); для каждого — стадии (stages), время выполнения, статус.
- **Stages** — стадии выполнения (например, стадия shuffle); внутри — задачи (tasks) по партициям; видны длительность, место выполнения (executor), объём данных (input/output), сбойные задачи.
- **Storage** — кэшированные RDD/DataFrame и использование памяти.
- **Environment** — конфигурация Spark (spark.*), системные свойства, переменные окружения.
- **Executors** — список исполнителей, использование памяти и CPU, логи исполнителей (stderr/stdout) по узлам; полезно при OOM или сбоях на конкретном узле.

По стадиям и задачам можно оценить узкие места: долгие стадии, skew (сильный перекос по партициям), спилл на диск. После завершения приложения UI текущего приложения может быть недоступен; для просмотра истории включите **Spark History Server**: он читает логи событий (event logs), записываемые Spark в указанный каталог (например, HDFS), и отдаёт тот же интерфейс для завершённых приложений. Настройка каталога логов и History Server уточняйте в документации Spark и у администратора кластера.

## 7.4.2. Логи Datagram и оркестратора

**Логи приложения** (сгенерированного кода Datagram) — вывод в stdout/stderr драйвера и при необходимости исполнителей. В них попадают сообщения фреймворка логирования (например, Logback, Log4j): уровень (INFO, WARN, ERROR), сообщения об ошибках и стек вызовов. Логи драйвера обычно сохраняются оркестратором (Airflow сохраняет логи задачи; в YARN логи контейнера драйвера доступны через YARN UI или History Server). По ним можно понять: на каком шаге упало приложение (чтение источника, трансформация, запись), какое исключение выброшено (FileNotFoundException, парсинг, таймаут подключения).

**Логи оркестратора** — логи задачи, которая выполняет `spark-submit`: вывод самой команды (подтверждение отправки задания, в YARN — ID приложения), а также логи Airflow/Oozie по выполнению DAG/workflow. Они показывают, была ли задача запущена, с какими параметрами, завершилась ли команда с кодом 0 или с ошибкой. Если сбой на стороне оркестратора (не найден JAR, нет прав, таймаут подключения к кластеру), это будет видно в логах задачи оркестратора, а не в Spark UI.

Рекомендация: настроить уровень логирования (INFO для продакшена, DEBUG для отладки), единый формат логов и при необходимости централизованный сбор (ELK, Splunk и т.д.) для поиска по run id и по имени приложения. Имя приложения Spark (`--name`) задаётся при запуске ([§7.2](chapter-07-02.md)) и помогает отфильтровать логи конкретного потока.

## 7.4.3. Отладка сбоев

**Отладка сбоев** — поиск причины ошибки по логам, Spark UI и воспроизведению сценария. Типичные ситуации:

- **Задание не запускается** — оркестратор не может выполнить команду: путь к JAR неверный, главный класс не найден, нет доступа к кластеру. Проверьте логи задачи оркестратора: полная команда, код возврата, stderr. Убедитесь, что JAR и конфиги доступны с узла, где выполняется задача, и что версия Spark совпадает с кластером.
- **Сбой во время выполнения (драйвер)** — исключение в коде драйвера (например, при инициализации источника или при сборе метаданных). Стек вызовов в логах драйвера укажет класс и строку; часто это конфигурация (неверный путь, недоступный хост), отсутствующая зависимость или ошибка в сгенерированном/доработанном коде.
- **Сбой на исполнителе (OOM, исключение в задаче)** — в Spark UI откройте провалившуюся стадию и задачу; посмотрите логи исполнителя (Executors → логи контейнера). OOM: увеличьте память исполнителя или уменьшите размер партиций; skew: перепартиционирование или изменение ключа. Исключение в задаче (например, парсинг, приведение типов) — смотреть стек в логах исполнителя; данные на проблемной партиции могут быть «грязными».
- **Таймауты и зависания** — задание долго выполняется или не завершается. В Spark UI проверьте, какие стадии выполняются, нет ли одной долгой задачи (skew) или ожидания ресурсов. Проверьте сеть и доступность внешних систем (HDFS, Hive, Kafka); при необходимости увеличьте таймауты в конфигурации Spark или коннектора.

Чек-лист при сбое: (1) логи задачи оркестратора — запустилась ли команда; (2) Spark UI (или event logs) — на какой стадии/задаче сбой; (3) логи драйвера и при необходимости исполнителя — текст исключения и стек; (4) конфигурация и параметры — пути, дата среза, окружение. После исправления перезапуск этапа (если оркестратор поддерживает повторный запуск задачи без полного перезапуска Workflow) позволяет проверить результат без повторного выполнения всех предыдущих этапов.

## Ключевое

- **Spark UI** — веб-интерфейс приложения Spark: задания, стадии, задачи, исполнители, логи; доступен во время выполнения и через History Server после завершения; помогает оценить производительность и локализовать сбой.
- **Логи** — приложения (драйвер, при необходимости исполнители) и оркестратора (вывод задачи с `spark-submit`); уровень логирования и единый формат облегчают поиск; имя приложения и run id помогают фильтровать.
- **Отладка сбоев:** не запускается — смотреть логи оркестратора; сбой в драйвере — стек в логах драйвера; сбой на исполнителе — Spark UI и логи исполнителя (OOM, skew, исключения в данных). Проверять конфигурацию и параметры.
