# §2.2 Транзакции: авторизация и клиринг

В [§2.1](chapter-02-01.md) мы ввели карточные продукты и сущности: карта, договор, счёт. Теперь разберём, что происходит при оплате картой: **авторизация** в момент операции, **клиринг** и расчёты между участниками, и какие **данные транзакции** (сумма, дата, мерчант, MCC) фиксируются для отчётности, аналитики и антифрода. Эти данные — основа для витрин оборотов по картам ([§2.3](chapter-02-03.md)) и для проводок в бухучёте ([§2.4](chapter-02-04.md)). См. [Глоссарий](glossary.md).

---

## 2.2.1. Авторизация в момент операции

**Авторизация** — запрос на разрешение операции по карте в момент её совершения: держатель предъявляет карту (или данные карты) в торговой точке, банкомате или при онлайн-оплате; банк-эмитент (или платёжная система от его имени) проверяет карту, лимиты и при положительном результате резервирует сумму и возвращает код одобрения. Операция в точке обслуживания завершается сразу; фактическое списание средств со счёта (или увеличение задолженности по кредитной карте) отражается в бухучёте позже — после клиринга. См. [Глоссарий](glossary.md).

В данных при авторизации фиксируются: идентификатор транзакции (уникальный в рамках системы или платёжной сети), дата и время операции, карта (номер/маска, токен, ссылка на карту/договор/счёт), сумма, валюта операции, тип операции (покупка, снятие наличных, отмена и т.д.), точка приёма — мерчант или банкомат (идентификатор, при необходимости название), код категории мерчанта (MCC), страна и при необходимости другие атрибуты. Эти данные формируют запись **транзакции** (authorization record); позже к ней может привязаться запись о клиринге и проводке. Для антифрода и расследований важны дата/время с точностью до секунды, геолокация (если есть), канал (POS, ATM, e-commerce). См. [§2.3](chapter-02-03.md), [§9.2](chapter-09-02.md).

---

## 2.2.2. Клиринг и расчёты

**Клиринг** — обмен и сверка данных об авторизованных операциях между банком-эмитентом (банк держателя карты), эквайером (банк мерчанта или банкоматной сети) и при необходимости платёжной системой (Visa, Mastercard, МИР и т.д.) с целью определить итоговые суммы к переводу между участниками. После клиринга выполняются **расчёты** (settlement): фактическое движение денег между счетами банков и зачисление/списание по счётам клиентов. См. [Глоссарий](glossary.md).

Последовательность упрощённо:

1. **Авторизация** — в момент операции; создаётся запись об авторизованной сумме.
2. **Клиринг** — передача данных о транзакциях (часто пакетами за день); сверка объёмов и сумм; формирование итогов для расчётов (сколько эквайер должен получить от эмитента за операции мерчантов, комиссии платёжной системы и т.д.).
3. **Расчёты (settlement)** — переводы между банками, зачёт по счетам; у эмитента — списание со счёта клиента (дебетовая карта) или увеличение ссудной задолженности (кредитная карта), проводки в бухучёте. Дата зачёта (валютирования) для клиента и для бухучёта обычно привязана к дате клиринга или к следующему рабочему дню.

Для инженера данных важно: **дата и время авторизации** — момент операции (для отчётности по дате операции, для антифрода); **дата клиринга/валютирования** — момент отражения в бухучёте и для отчётов «по дате зачёта». В данных транзакции должны храниться обе даты (и при необходимости время); витрины и отчёты должны явно указывать, по какой дате построен срез (операции или зачёта). См. [§1.1](chapter-01-01.md) (дата операции и дата зачёта), [§2.4](chapter-02-04.md).

## 2.2.3. Данные транзакции: сумма, дата, мерчант, MCC

**Транзакция** (карточная) в контексте данных — запись об одной авторизованной (и при необходимости проведённой после клиринга) операции по карте. Для отчётности, аналитики и антифрода в записи транзакции должны быть следующие поля (минимальный набор). См. [Глоссарий](glossary.md).

| Группа | Поля | Назначение |
|--------|------|------------|
| Идентификация | ID транзакции, ID авторизации (код из сети) | Уникальность, связь с клирингом и проводкой |
| Время | Дата и время авторизации, дата валютирования (зачёта) | Отчёты по дате операции и по дате зачёта; антифрод |
| Карта и счёт | Карта (ID или маска), договор, счёт | Привязка к продукту и бухучёту |
| Сумма и валюта | Сумма операции, валюта операции, сумма в валюте счёта (при конвертации) | Обороты, средний чек, проводки |
| Тип операции | Покупка, снятие наличных, отмена, возврат и т.д. | Фильтрация и агрегаты по типам |
| Точка приёма | Мерчант (ID, название), страна, MCC | Сегментация, отчёты по категориям, антифрод |
| Статус | Авторизована, проведена, отменена, оспорена | Фильтрация, сверка с проводками |

**Мерчант** (merchant) — торговая или сервисная точка (или интернет-продавец), принимающая оплату картой. В данных хранится идентификатор мерчанта (например, из платёжной системы), при необходимости — название, категория (MCC), страна. См. [Глоссарий](glossary.md).

**MCC** (Merchant Category Code) — код категории мерчанта (например, 5411 — супермаркеты, 5812 — рестораны). Используется платёжными системами и банками для сегментации операций, отчётов по категориям расходов и правил антифрода. В данных транзакции MCC хранится как атрибут операции; справочник MCC используется для расшифровки категорий в отчётах. См. [Глоссарий](glossary.md).

Дополнительно для антифрода и расследований могут храниться: канал (POS/ATM/e-commerce), код ответа авторизации, IP (для онлайн), идентификатор устройства. См. [§9.2](chapter-09-02.md).

## 2.2.4. Жизненный цикл записи транзакции в данных

В операционных системах банка жизненный цикл транзакции обычно выглядит так:

1. **Авторизация:** создаётся запись с датой/временем авторизации, суммой, картой, мерчантом, MCC, статусом «авторизована». Идентификатор транзакции и код авторизации позволяют связать запись с платёжной сетью.
2. **Клиринг:** при поступлении данных клиринга запись обновляется: дата валютирования, при необходимости уточнённая сумма (например, с конвертацией), статус «проведена» или «ожидает проведения».
3. **Проводка:** бухгалтерская система (или карточный модуль) формирует проводки по счёту клиента на дату валютирования; в данных транзакции может проставляться ссылка на проводку или признак «проведена».
4. **Отмена и возврат:** при отмене операции или возврате создаётся отдельная транзакция (тип «отмена» или «возврат») с привязкой к исходной транзакции; сумма отрицательная или нулевая; проводки — обратные или сторнирующие.

Для DWH и витрин загружаются уже проведённые транзакции (или все с признаком статуса); ключ — идентификатор транзакции, дата валютирования и дата авторизации позволяют строить отчёты «по дате операции» и «по дате зачёта». См. [§2.3](chapter-02-03.md), [§2.4](chapter-02-04.md).

## 2.2.5. Типичные ошибки при работе с данными транзакций

- **Смешивать дату авторизации и дату валютирования без различения:** отчёты «обороты за месяц» могут считаться по разным правилам; для сверки с бухучётом нужна дата валютирования; для анализа поведения клиента и антифрода — дата операции. В витринах и отчётах явно указывать базу даты.
- **Не хранить привязку транзакция — карта — договор — счёт:** без неё нельзя агрегировать обороты по договору/клиенту и сверять с проводками по счёту; связь должна быть в каждой записи транзакции или восстанавливаться по карте на дату операции.
- **Терять связь отмена/возврат с исходной транзакцией:** для корректных оборотов и отчётов по возвратам нужна явная связь; иначе возможен двойной учёт или пропуск сторнирующих операций.
- **Игнорировать MCC и мерчант:** сегментация расходов, отчёты по категориям и правила антифрода опираются на MCC и идентификатор мерчанта; их отсутствие ограничивает аналитику.
- **Дублировать транзакции при загрузке в DWH:** при повторной загрузке авторизаций и клиринга нужна идемпотентность по ID транзакции (или по паре ID + дата обновления), иначе обороты за период завышаются.

## Ключевое

- **Авторизация** — разрешение операции в момент её совершения; в данных фиксируются дата/время, сумма, карта, мерчант, MCC, тип операции; запись создаётся при авторизации.
- **Клиринг** — обмен и сверка данных об операциях между участниками; **расчёты** — фактическое движение денег и отражение в бухучёте. Дата валютирования (зачёта) обычно привязана к клирингу; для отчётов нужно различать дату операции и дату зачёта.
- **Данные транзакции:** ID, дата авторизации, дата валютирования, карта/договор/счёт, сумма, валюта, тип операции, мерчант, MCC, статус. Мерчант — точка приёма; MCC — код категории мерчанта для сегментации и антифрода.
- Жизненный цикл в данных: авторизация (запись, статус «авторизована») → клиринг (дата валютирования, статус «проведена») → проводка по счёту; отмена/возврат — отдельная транзакция с привязкой к исходной.

В [§2.3](chapter-02-03.md) мы разберём данные для отчётности и аналитики по картам: обороты, средний чек, сегментация и что нужно для отчётов и антифрода.
