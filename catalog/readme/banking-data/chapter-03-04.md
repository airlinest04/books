# §3.4 Данные для сверки и отчётности

В [§3.1](chapter-03-01.md)–[§3.3](chapter-03-03.md) мы разобрали внутренние и внешние платежи, форматы сообщений (SWIFT, ISO 20022), жизненный цикл и статусы. Завершающий раздел главы 3 — какие **данные** нужны для **сверки** с контрагентами и ЦБ и для **регуляторной отчётности** по платежам: объёмы, суммы, валюты, ключи сверки и связь с формами отчётности. Детали пайплайна подготовки отчётов и валидации — в главах 5 и 6. См. [Глоссарий](glossary.md).

***

## 3.4.1. Объёмы, суммы, валюты: агрегаты для отчётности

Для внутренних отчётов и регуляторных форм по платежам нужны агрегаты за период в разных разрезах. См. [§3.3](chapter-03-03.md), [§5.1](chapter-05-01.md).

**Объёмы** — количество платежей за период (день, месяц): всего, по типам (внутренние/внешние), по платёжной системе, по направлению (входящие/исходящие), по статусу (исполненные, отклонённые). Считаются по выбранной дате: дата валютирования (для оборотов и сверки с бухучётом) или дата создания (для анализа нагрузки). В данных должны быть: фильтр по статусу «исполнен» (или эквивалент), дата валютирования, признаки типа платежа и направления; агрегация — count по идентификатору платежа.

**Суммы** — сумма исполненных платежей за период в выбранной валюте (рубли, доллары, евро или по валюте операции с пересчётом). Разрезы: по валюте операции, по платёжной системе, по банку-контрагенту, по типу (внутренние/внешние). Для сверки с бухучётом суммы считаются по дате валютирования и должны совпадать с оборотами по корреспондентским и клиентским счетам. В данных: сумма платежа, валюта, дата валютирования, статус «исполнен»; при мультивалютности — курс пересчёта в отчётную валюту по правилам ЦБ или внутренним правилам.

**Валюты** — разбивка объёмов и сумм по валюте операции (RUB, USD, EUR и др.). Регуляторные формы часто требуют отдельные показатели по рублёвым и валютным платежам; в записи платежа должно быть поле валюта, при агрегации — группировка по нему. См. [§5.3](chapter-05-03.md), [§6.2](chapter-06-02.md).

## 3.4.2. Сверка с контрагентами

**Сверка** (reconciliation) — сопоставление данных банка о платежах с данными контрагента (другой банк, платёжная система, ЦБ) для выявления расхождений. См. [Глоссарий](glossary.md), [§6.2](chapter-06-02.md).

Ключи сверки по платежам:

* **Уникальный идентификатор в платёжной системе** (UETR в SWIFT, EndToEndId в ISO 20022) — основной ключ для сопоставления одной и той же операции у отправителя и получателя (или у банка и системы). Без UETR однозначная сверка невозможна.
* **Сумма и валюта** — должны совпадать у обеих сторон; при расхождении — ошибка передачи или учёта.
* **Дата валютирования** — обычно совпадает; при расхождениях в датах зачёта возможны разницы в отчётах по периодам.
* **Реквизиты плательщика и получателя** — счета, банки; при сверке с банком-контрагентом проверяется соответствие «наш исходящий — их входящий» по одному UETR.

Процесс сверки: банк формирует выгрузку исполненных платежей за период (UETR, сумма, валюта, дата валютирования, стороны); контрагент — свою выгрузку; сопоставление по UETR (или по связке реквизитов при отсутствии UETR). Несовпадения: платёж есть у одной стороны и отсутствует у другой; расхождение по сумме или дате. Результат — отчёт о расхождениях для разбора и исправления. В данных для сверки обязательны: UETR, сумма, валюта, дата валютирования, счета и банки плательщика и получателя, статус. См. [§3.2](chapter-03-02.md), [§6.2](chapter-06-02.md).

## 3.4.3. Сверка с ЦБ и платёжной системой

Банк России как оператор платёжной системы (и как регулятор) получает данные о прохождении платежей через систему Банка России. Банк обязан сверять свои данные с выписками и отчётами ЦБ: объёмы и суммы за период, остатки и обороты по корреспондентским счетам. См. [§5.1](chapter-05-01.md), [§6.1](chapter-06-01.md).

Данные для сверки с ЦБ:

* **По платежам:** список исполненных платежей за период с UETR (или идентификатором в системе ЦБ), суммой, валютой, датой валютирования; сопоставление с выпиской/отчётом из системы ЦБ по тем же ключам.
* **По счетам:** обороты и остатки по корреспондентскому счёту банка в ЦБ за период; они должны совпадать с оборотом по платежам (исходящим и входящим) и с данными бухучёта. См. [§1.4](chapter-01-04.md), [§6.2](chapter-06-02.md).

Расхождения выявляются и передаются в подразделение, ответственное за расчёты; причины — задержка учёта, ошибка в реквизитах, двойная проводка или пропуск. Регулярная автоматическая сверка по UETR и по оборотам снижает риск необнаруженных ошибок. См. [§6.3](chapter-06-03.md), [§6.4](chapter-06-04.md).

## 3.4.4. Регуляторные отчёты по платежам

Регуляторная отчётность в ЦБ включает формы, связанные с платёжной деятельностью: объёмы и суммы переводов, участие в платёжных системах, показатели по ликвидности и проведению платежей. Точный состав форм и сроки сдачи задаются указаниями и положениями Банка России. См. [Глоссарий](glossary.md), главы 5 и 6.

Данные для заполнения форм берутся из:

* **Операционных систем платежей:** платежи за период (объём, сумма, валюта, дата валютирования, платёжная система, направление); агрегаты по типам и валютам.
* **Бухучёта:** обороты и остатки по корреспондентским счетам, по счетам клиентов по проведённым платежам; сверка с данными из платёжной системы.
* **Справочников:** банки (БИК), валюты, коды платёжных систем.

Маппинг «поле отчёта — источник данных» и правила расчёта показателей задаются регламентом по каждой форме. Пайплайн подготовки: извлечение из DWH или из операционных систем → расчёт показателей → заполнение формы → валидация → сдача. См. [§5.3](chapter-05-03.md), [§6.1](chapter-06-01.md). Список актуальных форм и указаний ЦБ — в [Список литературы](../../banking-data/sources.md).

## 3.4.5. Витрины и данные для аналитики платежей

Для отчётности и аналитики в DWH строятся витрины по платежам. См. [§4.2](chapter-04-02.md).

**Витрина «Платежи» (факты):** одна запись на платёж с полным набором полей: ID, UETR, сумма, валюта, дата создания, дата валютирования, плательщик (счёт, банк), получатель (счёт, банк), назначение, платёжная система, статус, причина отказа (при наличии). Источник для агрегатов и сверки.

**Витрина «Обороты по платежам»:** агрегаты за период (день, месяц) в разрезе: направление (входящие/исходящие), тип (внутренние/внешние), валюта, платёжная система; количество платежей, сумма. Строится из витрины «Платежи» по дате валютирования и статусу «исполнен».

**Связь с проводками:** платёж связан со счётом плательщика и счётом получателя; обороты по витрине за период по счёту должны совпадать с оборотом по этому счёту в бухучёте. Ключи для джойнов: счёт, дата валютирования, внутренний ID платежа. См. [§4.3](chapter-04-03.md), [§6.2](chapter-06-02.md).

## 3.4.6. Типичные ошибки

* **Сверка без UETR (или аналога):** сопоставление только по сумме и дате даёт ложные совпадения и пропуски при нескольких одинаковых суммах в один день; ключ сверки — уникальный идентификатор в системе.
* **Разные базы дат в отчёте и в бухучёте:** обороты за месяц по платежам считаются по дате валютирования; в отчёте и в сверке должна использоваться та же база, что и в проводках.
* **Не учитывать валюту при агрегатах:** при отчёте в рублях нужны пересчёт по курсу на дату валютирования (или по правилам ЦБ); без явного правила курса агрегаты по разным валютам несопоставимы.
* **Игнорировать отклонённые платежи в анализе:** для отчётов по объёму отказов и причинам нужна выборка по статусу «отклонён» с причиной; иначе нельзя анализировать качество процесса.
* **Нет связи платёж — счёт в витрине:** без неё нельзя сверять обороты по витрине с оборотами по счетам в бухучёте; в записи платежа должны быть идентификаторы счетов плательщика и получателя.

***

## Ключевое

* **Объёмы, суммы, валюты:** агрегаты за период (количество платежей, сумма в разрезе валюты и типа); база даты — явно валютирование или создание; для сверки с бухучётом — по дате валютирования.
* **Сверка с контрагентами:** ключ — **UETR** (или аналог); сопоставление по UETR, сумме, валюте, дате валютирования, реквизитам сторон; выгрузки за период и отчёт о расхождениях.
* **Сверка с ЦБ:** данные по платежам (UETR, сумма, валюта, дата) и обороты по корреспондентским счетам; соответствие выпискам и отчётам системы ЦБ.
* **Регуляторные отчёты по платежам:** формы ЦБ заполняются из операционных данных и бухучёта; маппинг полей и пайплайн — в главах 5 и 6.
* **Витрины:** факты платежей (полные поля), агрегаты оборотов за период; связь платёж — счета для сверки с бухучётом.

В [§4.1](chapter-04-01.md) мы переходим к общим принципам моделей данных по продуктам: события и снимки на дату, выбор гранулярности для витрин кредитов, карт и платежей.
