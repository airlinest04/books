# §5.3 Источники данных для форм

В [§5.1](chapter-05-01.md) и [§5.2](chapter-05-02.md) мы рассмотрели типы форм отчётности в ЦБ, их связь с бухучётом и витринами, сроки и периодичность. Теперь — **какие таблицы и витрины** используются для заполнения форм и как строится **маппинг «поле отчёта — источник»**. Это основа для пайплайна подготовки отчёта ([§6.1](chapter-06-01.md)) и для поддержки при изменении форм ([§5.4](chapter-05-04.md)). См. [Глоссарий](glossary.md).

---

## 5.3.1. Таблицы и витрины как источники для форм

Данные для форм ЦБ берутся из бухгалтерской системы, из DWH (Core и витрины) и при необходимости из операционных систем напрямую. См. [§4.2](chapter-04-02.md), [§4.4](chapter-04-04.md).

**Бухгалтерия:** таблицы проводок (дата валютирования, дебет-счёт, кредит-счёт, сумма), остатки по счетам на дату, план счетов (код, наименование, тип счёта). Используются для форм, дублирующих или детализирующих баланс, для оборотов за период и для сверки с витринами. См. [§1.4](chapter-01-04.md), [§4.3](chapter-04-03.md).

**Витрины по продуктам:** витрина «портфель кредитов» (остаток, DPD, категория качества, резерв на дату), витрина «движения по кредитам», витрина «просрочка»; витрина «портфель карт», витрина «транзакции», витрина «обороты по картам»; витрина «платежи», витрина «обороты по платежам». Используются для расшифровок, для показателей по рискам и резервам, для данных по платёжной системе. См. [§4.2](chapter-04-02.md), [§5.1](chapter-05-01.md).

**Core DWH:** нормализованные сущности (договоры, карты, счета, клиенты) и факты (выдачи, платежи, транзакции) — если форма требует детализации, которой нет в готовой витрине, или если витрина строится на лету из Core при заполнении формы. См. [§4.4](chapter-04-04.md).

**Справочники:** план счетов, клиенты (сегмент, тип), продукты, филиалы, валюты — для кодирования и расшифровки статей отчёта. См. [§4.2](chapter-04-02.md), [§4.4](chapter-04-04.md).

Сводка по направлениям форм (повторение и уточнение из §5.1):

| Направление формы | Типичные источники (таблицы / витрины) |
|-------------------|----------------------------------------|
| Баланс, учёт | Остатки по счетам (бухучёт), план счетов |
| Риски, резервы | Витрина «портфель кредитов», «просрочка»; остатки по счетам ссуд и резервов (бухучёт) |
| Ликвидность | Остатки и обороты по счетам (бухучёт), расчётные модули нормативов |
| Платёжная система | Витрина «платежи», «обороты по платежам»; остатки по корсчетам (бухучёт) |

См. [§5.1](chapter-05-01.md), [§6.2](chapter-06-02.md).

## 5.3.2. Маппинг «поле отчёта — источник»

**Маппинг** — соответствие между полем (показателем, строкой) формы отчётности и источником данных: таблица (или витрина), поле или выражение (агрегат, расчёт). См. [Глоссарий](glossary.md).

Структура маппинга для одной формы:

- **Код/наименование поля в форме** — как поле названо в указании ЦБ или во внутреннем описании формы.
- **Источник:** система (бухучёт, DWH), таблица/витрина, поле (или формула: сумма полей, остаток на дату, группировка по коду счёта и т.д.).
- **Правило расчёта** (если не прямое копирование): например, «остаток по счёту 45201 на дату», «сумма оборотов по дебету счёта 40702 за период», «агрегат по витрине портфель: сумма остатка по договорам с категорией качества III».
- **Зависимости:** от других полей формы или от других форм (перекрёстные проверки). См. [§6.2](chapter-06-02.md).

Маппинг хранится в виде реестра (таблица или конфигурация в системе отчётности): форма, поле, источник, правило. Это позволяет при изменении формы или источника быстро обновить только затронутые поля и воспроизвести заполнение формы. См. [§5.4](chapter-05-04.md), [§6.1](chapter-06-01.md).

## 5.3.3. Примеры маппинга (схематично)

Ниже — условные примеры без привязки к конкретным номерам форм ЦБ. Реальный маппинг задаётся указаниями ЦБ и регламентом банка.

**Баланс (остатки на дату):** поле формы «Остаток по счёту X» → источник: бухучёт, таблица остатков, поле «остаток» по счёту X на отчётную дату. При детализации по валютам или по аналитике — таблица остатков с группировкой по коду счёта и аналитике.

**Риски (ссудная задолженность по категориям качества):** поле формы «Сумма ссуд категории N» → источник: витрина «портфель кредитов» или «просрочка», фильтр по категории качества = N, сумма поля «остаток долга» (или «сумма резерва» — по назначению поля). Сверка: итог по витрине по всем категориям должен совпадать с остатком по счёту ссудной задолженности из бухучёта. См. [§1.3](chapter-01-03.md), [§4.3](chapter-04-03.md), [§6.2](chapter-06-02.md).

**Платёжная система (объём переводов за период):** поле формы «Количество платежей за период» → источник: витрина «платежи» (или «обороты по платежам»), фильтр по дате валютирования в периоде, статус «исполнен», агрегат count. Поле «Сумма» → сумма поля «сумма» по тем же фильтрам. См. [§3.4](chapter-03-04.md), [§4.2](chapter-04-02.md).

При появлении новой формы или изменении состава полей маппинг дополняется или корректируется; версия маппинга привязывается к версии формы. См. [§5.4](chapter-05-04.md).

## 5.3.4. Реестр форм и источников

**Реестр** «форма — источник — ответственный» (или «форма — поле — источник — правило») обеспечивает управляемость отчётностью: по каждой форме зафиксировано, откуда берутся данные, кто отвечает за подготовку и сдачу, при необходимости — ссылка на пайплайн и на документацию маппинга. См. [§5.1](chapter-05-01.md), [§6.1](chapter-06-01.md).

Содержимое реестра (минимальный набор):

- Идентификатор формы (код ЦБ, внутренний код).
- Наименование формы, периодичность, срок сдачи (или ссылка на календарь).
- Источники данных: перечень таблиц/витрин и систем.
- Маппинг: таблица или ссылка на документ/конфиг «поле формы — источник — правило».
- Ответственное подразделение (или роль).
- Ссылка на пайплайн подготовки (скрипт, джоб, задача в оркестраторе).

Реестр ведётся в виде таблицы, wiki, системы управления отчётностью; при изменении форм и источников реестр актуализируется. Это снижает риск «знаний в головах» и упрощает онбординг и аудит. См. [§5.4](chapter-05-04.md).

## 5.3.5. Типичные ошибки

- **Маппинг только в коде без документации:** при смене разработчика или системы логика заполнения поля теряется; маппинг должен быть описан в реестре или в конфиге с комментариями.
- **Один источник для поля без альтернативы при сбое:** если единственный источник — одна таблица и она недоступна, форма не заполняется; где возможно, иметь правило сверки с другим источником (бухучёт vs витрина) и алерт при расхождении.
- **Не проверять актуальность маппинга при изменении формы ЦБ:** при выходе нового указания ЦБ поля формы могли измениться; маппинг нужно сверять с новой версией формы и обновлять. См. [§5.4](chapter-05-04.md).
- **Подставлять в форму поле из витрины без проверки сверки с бухучётом:** для показателей, дублирующих баланс или обороты, перед сдачей должна выполняться сверка с бухучётом; иначе ошибка в витрине попадёт в отчёт. См. [§6.2](chapter-06-02.md), [§6.3](chapter-06-03.md).

## Ключевое

- **Источники для форм:** бухучёт (проводки, остатки, план счетов), витрины по продуктам (портфель кредитов, просрочка, транзакции, платежи, обороты), Core DWH, справочники. Выбор зависит от направления формы (баланс, риски, ликвидность, платёжная система). См. §5.1, §4.2.
- **Маппинг «поле отчёта — источник»:** для каждого поля формы — источник (таблица/витрина, поле или выражение), правило расчёта при необходимости; хранится в реестре или конфиге; при изменении формы маппинг обновляется.
- **Реестр форм и источников:** форма, источники, маппинг полей, ответственный, ссылка на пайплайн; ведение реестра и актуализация при изменении форм и указаний ЦБ снижают риски ошибок и потери знаний.
- Примеры маппинга: остатки из бухучёта по счёту на дату; риски и резервы из витрин портфеля/просрочки с сверкой с бухучётом; объёмы платежей из витрины платежей за период.

В [§5.4](chapter-05-04.md) мы разберём изменения форм и версионность: как ЦБ меняет формы, как хранить версионность отчётов и данных и как обеспечивать ретроспективу.
