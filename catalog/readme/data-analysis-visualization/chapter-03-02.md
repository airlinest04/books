# §3.2 Метрики по столбцам

В [§3.1](chapter-03-01.md) мы сформулировали цели профилирования: понимание структуры и содержания данных и выявление проблем качества. Конкретно эти цели достигаются за счёт **метрик** — числовых и сводных показателей по каждому столбцу (и при необходимости по таблице в целом). В этом разделе разбираются **метрики по столбцам**: количество значений, пропуски (null), уникальность, минимум и максимум, распределение, а также типы данных и форматы. Метрики по таблице и связям между таблицами — в [§3.3](chapter-03-03.md).

---

## 3.2.1. Количество значений и число строк

Базовая метрика для любого столбца — **сколько в нём значений**. Обычно считают:

- **Число непустых значений (count):** количество записей, в которых в данном столбце есть непустое значение. В SQL это `COUNT(column)` (значения NULL не учитываются).
- **Число строк в таблице:** общее количество записей. Должно совпадать с ожиданием по источнику и периоду; расхождение — повод проверить полноту данных ([§2.1](chapter-02-01.md)).

Сравнение числа непустых значений с числом строк даёт **количество пропусков** в столбце: разница между общим числом строк и count по столбцу. Эту метрику удобно дополнять долей пропусков (см. ниже).

---

## 3.2.2. Пропуски (NULL и пустые значения)

**Пропуски** — отсутствие значения в ячейке. Они влияют на полноту ([§2.1](chapter-02-01.md)) и на корректность агрегатов и джойнов.

**Метрики по пропускам:**

- **Количество пропусков:** число строк, где значение NULL или признаётся пустым (пустая строка, пробелы в зависимости от правил). В SQL: `COUNT(*) - COUNT(column)` для NULL; пустые строки считают отдельно, например `SUM(CASE WHEN TRIM(column) = '' THEN 1 ELSE 0 END)`.
- **Доля пропусков (в %):** (количество пропусков / число строк) × 100. Позволяет сравнивать столбцы между собой и с порогами качества (например, «критичный столбец — не более 5% пропусков»).
- **Различие типов пустоты:** в одних системах отсутствие значения — это NULL, в других — пустая строка, «N/A», «-» или специальный код. При профилировании полезно разделять их и считать отдельно, чтобы не смешивать «реальные» пропуски с закодированными значениями.

Высокая доля пропусков в ключевом столбце (идентификатор, дата, размерность для среза) ставит под вопрос использование этого поля без очистки или явного ограничения анализа («рассматриваем только записи с заполненным полем X»).

---

## 3.2.3. Уникальность

**Уникальность** характеризует, насколько значения в столбце различаются.

**Метрики:**

- **Число уникальных значений (count distinct):** сколько различных значений принимает столбец. В SQL: `COUNT(DISTINCT column)`. Для столбца-кандидата в первичный ключ ожидается равенство числу строк; меньше — есть дубликаты.
- **Доля уникальных значений (uniqueness ratio):** (число уникальных / число непустых значений) × 100. Близко к 100% — почти все значения разные; низкая доля — много повторений (категориальный или малоразрядный признак).
- **Частота максимально повторяющегося значения:** сколько раз встречается самое частое значение. Помогает выявить доминирующую категорию или подозрительное «заполнение по умолчанию» (например, одна и та же дата в большинстве строк).

Интерпретация зависит от роли столбца: для идентификатора важна уникальность по строкам; для категории — скорее число категорий и их сбалансированность. Уникальность по таблице в целом (дубликаты строк) разбирается в [§3.3](chapter-03-03.md).

---

## 3.2.4. Минимум, максимум и диапазон

Для **числовых** и **временных** столбцов базовые метрики — **минимум** и **максимум**. По ним судят о диапазоне данных и о возможных ошибках (отрицательные значения там, где они недопустимы; даты из будущего; нереалистичные величины).

**Метрики:**

- **Min, max:** минимальное и максимальное значение в столбце. В SQL для чисел: `MIN(column)`, `MAX(column)`; для дат — то же, интерпретация в календарных единицах.
- **Диапазон (range):** разность max − min для числовых данных. Полезен для понимания масштаба и для проверки выбросов ([§3.4](chapter-03-04.md)).
- **Контекстная проверка:** сравнение min/max с бизнес-правилами (возраст от 0 до 120, сумма заказа положительная, дата не позже текущей и т.д.). Выход за ожидаемые границы — сигнал для валидации и очистки.

Для **строковых** столбцов иногда считают минимальную и максимальную длину (LENGTH) и при необходимости распределение по длинам — чтобы выявить обрезанные значения или нестандартные форматы.

---

## 3.2.5. Распределение и частоты

**Распределение** показывает, как часто встречаются те или иные значения (или интервалы значений).

**Метрики и приёмы:**

- **Частота (count) по категориям:** для категориального столбца — сколько записей в каждой категории. В SQL: `GROUP BY column` с `COUNT(*)`. Выявляет доминирующие категории, редкие и потенциально ошибочные (опечатки, варианты написания).
- **Топ-N значений:** список наиболее частых значений и их доли. Помогает быстро увидеть «голову» распределения и типичные заполнения.
- **Описательная статистика для числовых столбцов:** среднее, медиана, стандартное отклонение, квантили ([§2.4](chapter-02-04.md)). По ним судят о центре и разбросе и о симметрии; медиана и квантили устойчивы к выбросам.
- **Гистограмма (интервалы):** разбиение числового столбца на интервалы (бины) и подсчёт числа значений в каждом. Даёт форму распределения и подозрительные «всплески» или пустые участки.

Распределение дополняет min/max и уникальность: по нему видно, не сосредоточены ли данные в одной точке (например, ноль или одна дата), нет ли мультимодальности (несколько «горбов») и насколько разумно применять среднее или регрессию.

---

## 3.2.6. Типы данных и форматы

Профилирование включает проверку **типов и форматов** данных.

**Заявленный vs фактический тип:**

- В схеме столбец может быть объявлен как integer, date, varchar и т.д. Фактическое содержимое может не соответствовать: в числовом поле — строки «N/A», в дате — смешение форматов (DD.MM.YYYY и YYYY-MM-DD), в строке — числа с разделителями. При профилировании полезно проверять: доля значений, успешно приводящихся к заявленному типу; примеры значений, не проходящих приведение.
- **Вывод типа по данным (type inference):** при отсутствии схемы или при приёмке файлов (CSV, Excel) инструменты профилирования часто пытаются вывести тип по выборке значений (все ли числа, все ли даты в одном формате). Результат вывода нужно проверять по образцам и по граничным случаям.

**Форматы:**

- **Даты:** единообразие формата (ISO 8601, локальный формат и т.д.); наличие невалидных дат или вне допустимого диапазона.
- **Числа:** десятичный разделитель (запятая vs точка); разделители разрядов; наличие пробелов или символов валюты в одном столбце.
- **Строки:** кодировка (UTF-8, иное); ведущие/концевые пробелы; смешение регистра в категориях, которые по смыслу должны быть нормализованы.

Несоответствие типа или формата — основание для правил преобразования и очистки в ETL или для явного указания ограничений в документации и в отчёте анализа.

---

## 3.2.7. Сводка метрик по столбцу

Для отчёта профилирования по каждому столбцу обычно сводят в таблицу:

| Метрика | Назначение |
|---------|------------|
| Число строк / число непустых | Объём и полнота по столбцу |
| Доля пропусков (%) | Оценка полноты, пороги качества |
| Число уникальных / доля уникальных | Уникальность, кандидат в ключ, категориальность |
| Min, max (для чисел/дат) | Диапазон, проверка на недопустимые значения |
| Среднее, медиана, std (для чисел) | Центр и разброс, подготовка к выбросам |
| Топ значений и частоты | Распределение категорий, доминирующие и редкие значения |
| Тип/формат (заявленный и выведенный) | Согласованность схемы и данных |

Набор можно расширять в зависимости от цели (например, добавление квантилей или проверки по справочнику). В [§3.3](chapter-03-03.md) переходим к метрикам на уровне таблицы и связей между таблицами.

---

## Ключевое

- **Метрики по столбцам** профилирования: количество значений и пропусков, уникальность, min/max, распределение (частоты, описательная статистика, гистограмма), типы и форматы.
- **Пропуски:** число и доля NULL (и иных пустых); различие типов пустоты; высокий % пропусков в ключевых полях — риск для анализа без оговорок или очистки.
- **Уникальность:** count distinct и доля уникальных; для кандидата в первичный ключ ожидается уникальность по строкам.
- **Min/max и диапазон** — для чисел и дат; проверка на допустимые границы; для строк — при необходимости длина.
- **Распределение:** частоты по категориям, топ значений, среднее/медиана/std и квантили, гистограмма — для оценки формы и выбросов.
- **Типы и форматы:** соответствие заявленному типу, вывод типа по данным, единообразие форматов дат и чисел; несоответствия задают правила ETL и ограничения в отчёте.

В [§3.3](chapter-03-03.md) мы разберём метрики по таблице и связям: число строк, ключи, дубликаты и целостность связей между таблицами.
