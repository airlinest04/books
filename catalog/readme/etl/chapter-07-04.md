## 7.4.1. SSIS и экосистема Microsoft

**SQL Server Integration Services (SSIS)** — компонент платформы Microsoft для построения решений интеграции и преобразования данных. Входит в состав **SQL Server** (лицензия на сервер или под соответствующими облачными предложениями) и тесно интегрирован с экосистемой Microsoft: SQL Server (как источник и как целевое хранилище), Azure SQL, файловые хранилища и облачные сервисы Azure, Active Directory и средствами управления и мониторинга Windows Server.

Разработка пакетов ведётся в **SSIS Designer**, который доступен в среде **SQL Server Data Tools (SSDT)** или в **Visual Studio** при установке рабочей нагрузки «Разработка служб интеграции». Дизайнер визуальный: пользователь собирает пакет из задач и компонентов потока данных, настраивает соединения и параметры. Для организаций, уже использующих SQL Server, Windows Server и Azure, SSIS даёт единую среду: те же учётные записи, те же механизмы развёртывания и планирования (SQL Server Agent, планировщик заданий Windows), при необходимости — интеграция с Azure Data Factory через SSIS Integration Runtime для выполнения пакетов в облаке.

Коннекторы и компоненты охватывают реляционные БД (в т.ч. через OLE DB, ODBC, ADO.NET), плоские файлы и Excel, XML, а также источники и назначения для облака Azure (Blob Storage, Data Lake и др.). Список встроенных источников, преобразований и назначений приведён в документации Microsoft.

## 7.4.2. Пакеты: поток управления и поток данных

Единица разработки и выполнения в SSIS — **пакет** (package). Пакет хранится в файле с расширением **.dtsx** (XML-описание) или входит в состав проекта развёртывания.

**Поток управления (Control Flow):** определяет порядок выполнения шагов пакета. В него входят **задачи** (tasks) — действия вроде «выполнить SQL», «скопировать файл», «выполнить другой пакет», «скрипт» (Script Task), а также **контейнеры** (например, цикл по файлам или по наборам данных). Задачи и контейнеры связываются **ограничениями предшествования** (precedence constraints): условные переходы по успеху/ошибке/завершению. Таким образом задаётся сценарий: что выполнять, в каком порядке и при каких условиях.

**Поток данных (Data Flow):** подзадача внутри пакета, отвечающая за перенос и преобразование данных. В поток данных входят **источники** (источники данных), **преобразования** (трансформации: фильтрация, сортировка, объединение, вычисляемые столбцы, агрегация и т.д.) и **назначения** (приёмники данных). Компоненты соединяются путями (paths), по которым передаются строки данных. Один пакет может содержать несколько потоков данных, вызываемых из потока управления. Поток данных — ядро ETL в SSIS: здесь реализуется извлечение, преобразование и загрузка на уровне записей.

Параметры и переменные пакета позволяют задавать значения при выполнении (например, путь к файлу, строка соединения) без изменения самого пакета; при развёртывании в проектной модели используются параметры проекта и окружения.

## 7.4.3. Развёртывание

Развёртывание пакетов SSIS поддерживает две основные модели (по документации Microsoft).

**Модель развёртывания проекта (Project Deployment Model)** — рекомендуемый вариант. Проект (набор пакетов) собирается в один артефакт развёртывания — файл **.ispac**. Он разворачивается в **каталог SSIS (SSISDB)** на экземпляре SQL Server. В каталоге хранятся проекты и пакеты, параметры, переменные окружения и журнал выполнения. Запуск и планирование выполняются на сервере (в т.ч. через SQL Server Agent); доступна проверка пакетов перед выполнением. Для окружений (dev, test, prod) используются параметры и конфигурации окружений в каталоге. Развёртывание возможно через мастер в SQL Server Management Studio (SSMS), из командной строки (ISDeploymentWizard.exe) или через скрипты PowerShell для автоматизации CI/CD.

**Модель развёртывания пакетов (Package Deployment Model)** — устаревший вариант: отдельные файлы пакетов (.dtsx) и конфигураций (.dtsConfig) разворачиваются в файловую систему или в базу данных msdb на SQL Server. Управление параметрами и окружениями менее централизовано; модель сохраняется для совместимости с существующими проектами.

Пакеты SSIS могут выполняться на SQL Server под Windows, в Azure (например, на виртуальной машине с SQL Server или через **Azure Data Factory** с SSIS Integration Runtime), что позволяет переносить ETL-нагрузку в облако и интегрировать пакеты в облачные пайплайны.

## Ключевое

- **SSIS** — компонент Microsoft для интеграции и ETL; разработка в SSIS Designer (Visual Studio / SSDT), тесная интеграция с SQL Server, Windows Server и Azure.
- **Пакет:** поток управления (задачи, контейнеры, ограничения предшествования) и поток данных (источники, преобразования, назначения); параметры и переменные для настройки без изменения пакета.
- **Развёртывание:** рекомендуемая модель — развёртывание проекта (.ispac) в каталог SSISDB на SQL Server с параметрами и окружениями; устаревшая — развёртывание отдельных .dtsx в файловую систему или msdb. Выполнение — на SQL Server (в т.ч. по расписанию через SQL Server Agent) или в Azure (Azure Data Factory, SSIS IR).
