## Подробное содержание

### Глава 1. Neoflex Datagram и Big Data ETL

* **1.1 Что такое Neoflex Datagram** — российская ETL-платформа для Big Data; преобразование данных и разработка аналитических приложений; высоконагруженная обработка больших объёмов.
* **1.2 Model Driven Architecture** — визуальное проектирование процессов; автоматическая генерация исполняемого кода (Scala); снижение порога входа; не требует глубоких знаний Big Data.
* **1.3 Место в экосистеме и рынке** — замена IBM Infosphere, Oracle Data Integrator; реестр российского ПО; импортозамещение; целевая аудитория.
* **1.4 Связь с теорией ETL и Spark** — ETL в контексте Big Data; исполнение на Apache Spark; связь с книгами по ETL, DWH, Spark.
* _Ключевое:_ Datagram, Model Driven, Big Data, Spark. _Задания:_ определить, когда Datagram предпочтительнее классического ETL.

***

### Глава 2. Архитектура и компоненты

* **2.1 Дизайнер трансформаций** — визуальная разработка потоков преобразования и маппинга; просмотр источников/приёмников; отслеживание полей; проверка результатов; сгенерированный Scala.
* **2.2 Дизайнер Workflow** — визуальная разработка последовательностей; параллельное, последовательное, условное исполнение; связь этапов.
* **2.3 Генерация Scala и исполнение на Spark** — как визуальная модель превращается в код; роль Spark; кластер.
* **2.4 Режимы batch и streaming** — пакетная обработка; потоковая обработка; Kafka; выбор режима.
* _Ключевое:_ Transformation Designer, Workflow Designer, Scala, Spark. _Задания:_ описать роли дизайнеров и связь со Spark.

***

### Глава 3. Источники и приёмники

* **3.1 Поддерживаемые источники** — обзор: файлы, БД, Kafka, Hive; форматы; ограничения.
* **3.2 Файловые источники: CSV, HDFS, Parquet, ORC** — настройка; схема; чтение из HDFS; колоночные форматы.
* **3.3 Apache Kafka и потоковые источники** — подключение к Kafka; топики; потоковый режим.
* **3.4 Apache Hive и RDBMS (JDBC)** — Hive-таблицы; JDBC для Oracle, PostgreSQL и др.; подключение.
* **3.5 Сложноструктурированные: XML, JSON, Avro** — парсинг; маппинг полей; schema.
* _Ключевое:_ CSV, HDFS, Parquet, ORC, Kafka, Hive, JDBC, JSON, Avro. _Задания:_ настроить источник из Parquet и из Kafka.

***

### Глава 4. Трансформации данных

* **4.1 Spark SQL в Datagram** — использование Spark SQL в потоке; запросы; вложенные структуры.
* **4.2 Реляционная алгебра: Join, Sort, Aggregation** — операции соединения, сортировки, группировки; визуальное представление.
* **4.3 Маппинг и преобразование полей** — переименование; вычисления; фильтрация.
* **4.4 Правила Drools** — бизнес-правила; Drools-движок; применение в потоке.
* **4.5 Spark MLLib и машинное обучение** — встроенные модели; предиктивная аналитика; интеграция с потоком.
* _Ключевое:_ Spark SQL, Join, Sort, Aggregation, Drools, MLLib. _Задания:_ построить поток с join и агрегацией.

***

### Глава 5. Создание потока трансформаций

* **5.1 Визуальное построение потока** — добавление источников, трансформаций, целей; связи; иерархия.
* **5.2 Отслеживание происхождения полей** — lineage; откуда пришло поле; какие преобразования применены.
* **5.3 Проверка промежуточных результатов** — отладка; просмотр данных на этапах; валидация.
* **5.4 Просмотр сгенерированного Scala-кода** — что генерируется; когда править вручную (если применимо); понимание кода.
* _Ключевое:_ поток, lineage, отладка, Scala. _Задания:_ создать поток и проверить lineage; просмотреть сгенерированный код.

***

### Глава 6. Workflow и управление потоком

* **6.1 Последовательное выполнение** — этап A → этап B → этап C; порядок; зависимости.
* **6.2 Параллельное выполнение** — этапы A и B одновременно; сведение; когда применимо.
* **6.3 Условное выполнение** — ветвление по условию; if-then-else; выбор пути.
* **6.4 Связывание этапов** — Link; передача контекста; параметры между этапами.
* _Ключевое:_ последовательное, параллельное, условное выполнение. _Задания:_ создать Workflow с параллельными и условными ветками.
