# §3.2 Файловые источники: CSV, HDFS, Parquet, ORC

В [§3.1](chapter-03-01.md) мы дали обзор поддерживаемых источников. В этом разделе рассматриваются **файловые источники** в Neoflex Datagram: настройка чтения из файлов в форматах **CSV**, **Parquet** и **ORC**, в том числе из **HDFS**; задание схемы и параметров. Эти форматы наиболее распространены для batch-загрузок и слоёв Raw/Staging в озере данных. Сложноструктурированные форматы (XML, JSON, Avro) — в [§3.5](chapter-03-05.md). В [§3.3](chapter-03-03.md) мы перейдём к Apache Kafka и потоковым источникам. См. [Глоссарий](glossary.md).

## 3.2.1. Общий принцип настройки файлового источника

Файловый источник в дизайнере трансформаций задаёт **откуда** и **в каком формате** читать данные. Минимально необходимо указать:

- **Путь к данным** — путь к файлу или к каталогу. Для HDFS путь имеет вид `hdfs://<namenode>:<port>/path/to/dir` или `/path/to/dir` при настроенном по умолчанию URI HDFS. Для локальной файловой системы — обычный путь ОС. При указании каталога Spark читает все файлы выбранного формата в этом каталоге (и при необходимости в подкаталогах); это удобно для партиционированных данных (например, `.../date=2025-02-16/`).
- **Формат** — CSV, Parquet, ORC или другой поддерживаемый. От формата зависят способ парсинга и возможность вывода схемы из самих данных (колоночные форматы хранят схему в файле; CSV чаще задаётся вручную или по заголовку).
- **Схема** — список полей (имя, тип данных). Для Parquet и ORC схема может быть прочитана из метаданных файла (импорт схемы в дизайнере); для CSV задаётся вручную или выводится из первой строки (header). Схема определяет структуру DataFrame на выходе источника и должна соответствовать последующим трансформациям.

Дополнительные параметры зависят от формата: разделитель и наличие заголовка для CSV; опции сжатия и партиционирования для Parquet/ORC. В сгенерированном коде эти настройки отображаются в вызовах `spark.read.format(...).option(...).load(path)` (или эквиваленте). Актуальный набор опций в дизайнере уточняйте в документации Neoflex.

## 3.2.2. Чтение из HDFS

**HDFS** (Hadoop Distributed File System) — распределённая файловая система; данные хранятся блоками на узлах кластера. Для чтения из HDFS кластер Spark должен иметь доступ к той же HDFS: корректно настроены `HADOOP_CONF_DIR` или параметры подключения к NameNode (URI, при необходимости Kerberos). Путь в настройках источника указывается в формате HDFS (например, `hdfs://nn.example.com:8020/data/raw/sales` или `/data/raw/sales` при default FS).

При чтении каталога Spark распределённо читает файлы из каталога (каждый executor может читать свои файлы), что обеспечивает параллелизм. Партиционированные данные (каталоги вида `key=value`) при чтении могут быть распознаны как партиции, и соответствующие столбцы добавлены в DataFrame (поведение задаётся опциями Spark и настройками в дизайнере). Для инкрементальной загрузки за период часто указывают путь к подкаталогу за дату (например, `.../year=2025/month=02/day=16/`); путь может задаваться параметром из Workflow (переменная даты). Подробнее параметры и конфигурация окружения — в [§7.3](chapter-07-03.md).

## 3.2.3. Источник CSV

**CSV** (Comma-Separated Values) — текстовый формат: строки — записи, столбцы разделены символом-разделителем (запятая, точка с запятой, табуляция). В дизайнере источника CSV обычно настраиваются:

- **Разделитель (delimiter)** — символ между полями (`,`; `;`; `\t`). Должен соответствовать реальному формату файла.
- **Заголовок (header)** — первая строка содержит имена столбцов. Если заголовок есть, схему можно вывести из него (и при необходимости скорректировать типы); если нет — схему задают вручную.
- **Кодировка** — например, UTF-8, Windows-1251; при несовпадении кодировки символы отображаются некорректно.
- **Схема** — при отсутствии заголовка или при необходимости явно задать типы: список полей и типов (string, integer, double, date и т.д.).

Ограничения CSV: один разделитель на файл; вложенные структуры и переносы строк внутри полей требуют экранирования (кавычки). Для больших объёмов и аналитических запросов колоночные форматы (Parquet, ORC) эффективнее. CSV удобен для обмена с внешними системами и для простых выгрузок. В сгенерированном коде чтение CSV соответствует `spark.read.format("csv").option("header", "true").option("delimiter", ";").schema(...).load(path)` (опции по настройкам дизайнера).

## 3.2.4. Колоночные форматы: Parquet и ORC

**Parquet** и **ORC** — колоночные (columnar) форматы: данные хранятся по столбцам, а не по строкам. Это даёт лучшее сжатие и эффективное чтение только нужных столбцов (projection pushdown). Оба формата хранят **схему в метаданных файла**, поэтому при добавлении источника Parquet или ORC платформа может **импортировать схему** из файла или из указанного каталога (по образцу файла). Это снижает ручную настройку и уменьшает ошибки несовпадения типов.

**Parquet** — формат из экосистемы Apache; нативно поддерживается Spark. Широко используется в озёрах данных и в Hive-таблицах. Опции чтения: сжатие (snappy, gzip и др.), чтение партиций из структуры каталогов. В дизайнере задаётся путь (файл или каталог в HDFS/локально); схема подтягивается из файла или задаётся вручную при необходимости переопределения.

**ORC** (Optimized Row Columnar) — колоночный формат, изначально связанный с Hive; хорошо сжимает и поддерживает типы Hive. Spark читает ORC через `spark.read.format("orc").load(path)`. Как и для Parquet, схема обычно берётся из файла; при записи в ORC можно задать сжатие и параметры Stripe.

При чтении из каталога с множеством файлов Parquet/ORC Spark параллельно читает файлы; объём данных может быть большим без необходимости загружать всё в память одного узла. Использование Parquet/ORC в качестве приёмника (запись результата потока в файлы в HDFS) настраивается через элемент «приёмник» с выбором формата и путём; поддерживается партиционирование по полям (например, по дате). Детали записи и партиционирования уточняйте в документации платформы.

## 3.2.5. Запись в файловые приёмники (кратко)

Файловый **приёмник** в дизайнере задаёт путь и формат записи (CSV, Parquet, ORC). Режим записи: **перезапись** (overwrite) — целевой путь/партиция перезаписываются; **добавление** (append) — данные дописываются (для партиционированных таблиц обычно запись в новую партицию). Партиционирование по столбцам при записи в каталог создаёт структуру подкаталогов (`col=value`), что удобно для последующего чтения по партициям. Сгенерированный код использует `df.write.format(...).mode("overwrite"|"append").partitionBy(...).save(path)`. Настройки сжатия и опции формата задаются в свойствах приёмника. Подробнее использование файловых приёмников в полном пайплайне — в главе 8.

## Ключевое

- **Файловый источник** задаётся путём, форматом и схемой. Путь — к файлу или каталогу (HDFS или локально); при каталоге читаются все файлы выбранного формата.
- **HDFS:** путь в формате HDFS; для доступа нужна настройка кластера Spark (Hadoop config, Kerberos при необходимости). Партиционированные каталоги поддерживаются; путь может быть параметризован (например, по дате).
- **CSV:** настройка разделителя, заголовка, кодировки и схемы; схема из заголовка или вручную. Удобен для обмена; для больших объёмов предпочтительны колоночные форматы.
- **Parquet и ORC:** колоночные форматы; схема обычно импортируется из файла. Эффективное сжатие и выборочное чтение столбцов; типичны для HDFS и слоёв Raw/Staging.
- **Приёмник:** путь, формат, режим записи (overwrite/append) и при необходимости партиционирование; код использует `DataFrame.write.format(...).save(path)`.
