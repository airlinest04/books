# §8.1 События триггера

В [§7.4](chapter-07-04.md) мы завершили главу о работе с SQL и возврате наборов. Глава 8 посвящена **триггерам** в PostgreSQL: автоматический вызов функции при определённых операциях над таблицей (или представлением). В этом разделе — **события** триггера: типы операций (INSERT, UPDATE, DELETE), момент срабатывания (**BEFORE** / **AFTER**) и уровень (**FOR EACH ROW** — по строке, **FOR EACH STATEMENT** — по оператору). Создание триггерной функции (NEW, OLD) — в [§8.2](chapter-08-02.md), привязка к таблице (CREATE TRIGGER) — в [§8.3](chapter-08-03.md). См. [Глоссарий](glossary.md).

---

## 8.1.1. Что такое триггер и когда он срабатывает

**Триггер** — объект БД, привязанный к таблице (или представлению, внешней таблице), который задаёт: при наступлении **события** (например, INSERT или UPDATE) вызывать указанную **функцию**. Функция объявляется без аргументов и с возвращаемым типом **trigger**; данные о событии и строке передаются через специальные переменные (NEW, OLD — в [§8.2](chapter-08-02.md)). Триггер выполняется в **той же транзакции**, что и вызвавшая его команда; ошибка в триггере откатывает и команду. См. [Глоссарий](glossary.md).

По документации PostgreSQL (раздел 37.1) триггеры можно вешать на обычные и партиционированные таблицы, представления и внешние таблицы. События — **INSERT**, **UPDATE**, **DELETE**; для таблиц также **TRUNCATE** (только на уровне оператора). UPDATE-триггер можно ограничить по столбцам (срабатывает только если в SET указаны заданные столбцы). Ниже — момент (BEFORE/AFTER) и уровень (по строке / по оператору).

---

## 8.1.2. BEFORE и AFTER

Момент срабатывания относительно операции (по документации PostgreSQL):

- **BEFORE** — функция вызывается **до** применения операции к строке (для построчного триггера) или до начала оператора (для триггера по оператору). Позволяет проверить или **изменить** данные до записи; для INSERT/UPDATE возвращаемая строка подставляется вместо исходной.
- **AFTER** — функция вызывается **после** того, как операция уже выполнена. Для построчного триггера — после обработки строки, но вызов откладывается до конца оператора; для триггера по оператору — в конце оператора. Удобно для распространения изменений в другие таблицы или проверок по уже зафиксированным в таблице данным.
- **INSTEAD OF** — только для **представлений**; срабатывает вместо стандартной обработки INSERT/UPDATE/DELETE по представлению; логика подставленных операций реализуется в теле триггера. На таблицах не используется.

Для таблиц и внешних таблиц обычно используют **BEFORE** или **AFTER**; выбор зависит от того, нужно ли менять строку до записи (BEFORE) или реагировать на уже записанное (AFTER). См. [Глоссарий](glossary.md).

## 8.1.3. FOR EACH ROW и FOR EACH STATEMENT

Уровень триггера (по документации PostgreSQL):

- **FOR EACH ROW** (построчный, row-level) — функция вызывается **один раз для каждой затронутой строки**. При `UPDATE t SET x = 1 WHERE id IN (1,2,3)` триггер вызовется три раза (если затронуты три строки). В функции доступны **NEW** (новая версия строки при INSERT/UPDATE) и **OLD** (старая при UPDATE/DELETE) — см. [§8.2](chapter-08-02.md).
- **FOR EACH STATEMENT** (по оператору, statement-level) — функция вызывается **один раз на оператор**, независимо от числа затронутых строк. Оператор, изменивший ноль строк, всё равно вызовет соответствующий триггер по оператору. В простом варианте в функции нет построчных данных NEW/OLD (доступ к наборам изменённых строк — через transition tables, отдельная тема).

**TRUNCATE** допускает только триггеры по оператору (FOR EACH STATEMENT). На представлениях **INSTEAD OF** триггеры всегда по строке. См. [Глоссарий](glossary.md).

Типичное использование: проверка или подстановка полей (например, updated_at) — **BEFORE FOR EACH ROW**; логирование в таблицу аудита после изменений — **AFTER FOR EACH ROW** или **AFTER FOR EACH STATEMENT** в зависимости от того, нужно ли реагировать на каждую строку или один раз на оператор.

## 8.1.4. Порядок срабатывания и несколько триггеров

Для одного оператора порядок такой (упрощённо): сначала все **BEFORE** по строкам (если есть FOR EACH ROW), затем выполняется изменение строки, затем в конце оператора — все **AFTER** по строкам, затем **AFTER** по оператору. **BEFORE** по оператору срабатывают в начале, до обработки строк. См. [Глоссарий](glossary.md).

Если на одно и то же событие (например, BEFORE INSERT) повешено несколько триггеров, они выполняются **в алфавитном порядке по имени триггера**. Для BEFORE и INSTEAD OF возвращаемая триггером строка передаётся следующему триггеру; если какой-то триггер вернёт NULL, операция для этой строки отменяется и последующие триггеры для неё не вызываются. Подробности создания триггерной функции и возврата NEW/NULL — в [§8.2](chapter-08-02.md) и [§8.3](chapter-08-03.md).

---

## Ключевое

- **Триггер** привязан к таблице (или представлению) и вызывает функцию при наступлении события (INSERT, UPDATE, DELETE; на таблицах также TRUNCATE).
- **BEFORE** — до операции (можно изменить или отменить строку); **AFTER** — после; **INSTEAD OF** — только на представлениях, вместо стандартной обработки.
- **FOR EACH ROW** — вызов для каждой затронутой строки (доступны NEW, OLD); **FOR EACH STATEMENT** — один вызов на оператор, даже если затронуто ноль строк.
- Несколько триггеров на одно событие выполняются по алфавиту имени; BEFORE может вернуть изменённую строку или NULL (отмена операции для строки).

В [§8.2](chapter-08-02.md) разберём **создание триггерной функции** на PL/pgSQL: сигнатура (RETURNS trigger), переменные **NEW** и **OLD** и что возвращать (NEW, OLD или NULL).
