# §8.3 CREATE TRIGGER

В [§8.2](chapter-08-02.md) мы разобрали создание триггерной функции (RETURNS trigger, NEW, OLD). Триггер привязывается к таблице (или представлению) командой **CREATE TRIGGER**. В этом разделе — синтаксис CREATE TRIGGER: имя, момент (BEFORE/AFTER/INSTEAD OF), события (INSERT, UPDATE, DELETE, TRUNCATE), уровень (FOR EACH ROW/STATEMENT), **условие WHEN** для построчных триггеров и вызов функции. Типичные применения (аудит, updated_at) и ограничения — в [§8.4](chapter-08-04.md) и [§8.5](chapter-08-05.md). См. [Глоссарий](glossary.md).

---

## 8.3.1. Синтаксис CREATE TRIGGER

Команда **CREATE TRIGGER** создаёт триггер, связанный с указанной таблицей (или представлением, внешней таблицей), и задаёт функцию, вызываемую при наступлении события (по документации PostgreSQL):

```
CREATE [ OR REPLACE ] TRIGGER имя
  { BEFORE | AFTER | INSTEAD OF } { событие [ OR ... ] }
  ON имя_таблицы
  [ FOR [ EACH ] { ROW | STATEMENT } ]
  [ WHEN ( условие ) ]
  EXECUTE { FUNCTION | PROCEDURE } имя_функции ( [ аргументы ] )
```

**имя** — уникальное имя триггера для данной таблицы; схема не указывается (триггер наследует схему таблицы). **BEFORE | AFTER | INSTEAD OF** — момент срабатывания ([§8.1](chapter-08-01.md)). **событие** — INSERT, UPDATE, DELETE или TRUNCATE; несколько событий через OR (например, `INSERT OR UPDATE`). Для **UPDATE** можно ограничить по столбцам: `UPDATE OF столбец1, столбец2` — триггер срабатывает только если в SET указан хотя бы один из этих столбцов. См. [Глоссарий](glossary.md).

**FOR EACH ROW** — построчный триггер; **FOR EACH STATEMENT** — по оператору; если не указано, по умолчанию FOR EACH STATEMENT. **EXECUTE FUNCTION** (или EXECUTE PROCEDURE, исторически) задаёт вызываемую функцию; это должна быть функция с RETURNS trigger, а не процедура. **аргументы** — необязательный список строковых констант, доступных в функции через **TG_ARGV** ([§8.2](chapter-08-02.md)).

Для создания триггера нужны привилегия **TRIGGER** на таблицу и **EXECUTE** на функцию.

---

## 8.3.2. Привязка функции к таблице: пример

Функция создаётся до триггера. Пример привязки триггера из [§8.2](chapter-08-02.md) (emp_stamp) к таблице emp (по документации PostgreSQL):

```sql
CREATE TRIGGER emp_stamp
  BEFORE INSERT OR UPDATE ON emp
  FOR EACH ROW
  EXECUTE FUNCTION emp_stamp();
```

Триггер срабатывает перед каждой вставкой и каждым обновлением строки в emp; функция emp_stamp() проверяет и заполняет поля и возвращает NEW. Удаление триггера — **DROP TRIGGER имя ON таблица;** (или DROP TRIGGER имя; с указанием таблицы в некоторых версиях). См. [Глоссарий](glossary.md).

## 8.3.3. Условие WHEN для построчных триггеров

В построчном триггере можно задать **WHEN ( условие )** — булево выражение; функция вызывается **только если условие истинно** (по документации PostgreSQL). В условии можно ссылаться на **OLD** и **NEW**: для INSERT доступен только NEW, для DELETE — только OLD, для UPDATE — оба. Ссылки записывают как имена столбцов: **OLD.столбец**, **NEW.столбец**. См. [Глоссарий](glossary.md).

Пример: вызывать триггер только при реальном изменении баланса:

```sql
CREATE TRIGGER check_update
  BEFORE UPDATE ON accounts
  FOR EACH ROW
  WHEN (OLD.balance IS DISTINCT FROM NEW.balance)
  EXECUTE FUNCTION check_account_update();
```

Для **AFTER** триггера условие WHEN вычисляется сразу после изменения строки; если оно ложно, вызов функции для этой строки не ставится в очередь. Это может заметно ускорить операторы, затрагивающие много строк, когда триггер нужен только для части из них. **INSTEAD OF** триггеры условия WHEN не поддерживают. В WHEN нельзя использовать подзапросы (на момент документации PostgreSQL).

## 8.3.4. UPDATE OF столбцы и аргументы триггера

**UPDATE OF столбец1 [, столбец2 ...]** — триггер срабатывает только если в команде UPDATE в предложении SET указан хотя бы один из перечисленных столбцов (или целевой столбец сгенерированной колонки). Полезно, когда реакция нужна только на изменение конкретных полей. См. [Глоссарий](glossary.md).

**Аргументы** в CREATE TRIGGER — список констант (строки, числа), передаваемых в функцию при каждом срабатывании. В PL/pgSQL они доступны как **TG_ARGV[0]**, **TG_ARGV[1]**, ... (тип text); **TG_NARGS** — их количество. Так одна и та же функция может использоваться в разных триггерах с разными параметрами (например, имена столбцов для проставления даты и пользователя).

Пример с аргументами (обобщённая функция «заполнить два столбца»):

```sql
CREATE TRIGGER set_audit
  BEFORE INSERT OR UPDATE ON orders
  FOR EACH ROW
  EXECUTE FUNCTION set_audit_columns('updated_at', 'updated_by');
```

В функции имена столбцов берут из TG_ARGV[0] и TG_ARGV[1] и формируют динамический UPDATE или присваивание NEW (через EXECUTE или ветвление по имени столбца).

---

## Ключевое

- **CREATE TRIGGER** имя **BEFORE|AFTER|INSTEAD OF** событие **[ OR событие ... ] ON** таблица **FOR EACH ROW|STATEMENT [ WHEN ( условие ) ] EXECUTE FUNCTION** функция **( аргументы )**.
- События: INSERT, UPDATE, DELETE, TRUNCATE; для UPDATE — опционально **UPDATE OF** список столбцов.
- **WHEN ( условие )** — только для строк, по которым вызывать функцию; в условии допустимы OLD и NEW; для AFTER даёт выигрыш по производительности; INSTEAD OF не поддерживает WHEN.
- Нужны привилегии TRIGGER на таблицу и EXECUTE на функцию; удаление — DROP TRIGGER.

В [§8.4](chapter-08-04.md) разберём **типичные применения** триггеров: аудит (логирование изменений), заполнение полей (updated_at, updated_by), проверки и модификация NEW.
