# §9.2 CREATE RULE

В [§9.1](chapter-09-01.md) мы ввели понятие правила как переписывания запроса. В этом разделе — **синтаксис CREATE RULE**: событие (ON SELECT/INSERT/UPDATE/DELETE), таблица или представление, **DO INSTEAD** и **DO ALSO**, необязательное условие WHERE и примеры — логирование удалений (DO ALSO) и обновляемое представление (DO INSTEAD). Отличие правил от триггеров и выбор между ними — в [§9.3](chapter-09-03.md). См. [Глоссарий](glossary.md).

---

## 9.2.1. Синтаксис CREATE RULE

Команда **CREATE RULE** определяет правило переписывания для указанной таблицы или представления (по документации PostgreSQL):

```
CREATE [ OR REPLACE ] RULE имя AS
  ON событие TO имя_таблицы [ WHERE условие ]
  DO [ ALSO | INSTEAD ] { NOTHING | команда | ( команда ; ... ) }
```

**имя** — уникальное имя правила для данной таблицы. **событие** — **SELECT**, **INSERT**, **UPDATE** или **DELETE**. **DO INSTEAD** — выполнить **вместо** исходной команды указанную команду (или несколько в скобках через точку с запятой). **DO ALSO** — выполнить указанную команду **дополнительно** к исходной; по умолчанию подразумевается ALSO. **DO INSTEAD NOTHING** — отменить выполнение исходной команды (используется для представлений, чтобы явно запретить обновление в необрабатываемых случаях). См. [Глоссарий](glossary.md).

В **условии** WHERE и в **командах** действия можно использовать псевдотаблицы **NEW** и **OLD**: NEW — строка при INSERT/UPDATE, OLD — при UPDATE/DELETE. Условие не может ссылаться на другие таблицы и не может содержать агрегатные функции. Несколько правил на одну таблицу и одно событие применяются в алфавитном порядке по имени правила.

Создавать и менять правила может только владелец таблицы.

---

## 9.2.2. DO INSTEAD и DO ALSO

**DO INSTEAD** — исходная команда **не выполняется**; вместо неё выполняется команда (или список команд) из правила. Типично для представлений: INSERT/UPDATE/DELETE по представлению переписываются в команды по базовым таблицам. См. [Глоссарий](glossary.md).

**DO ALSO** — исходная команда выполняется **и** дополнительно выполняется команда из правила. Используется, например, для логирования: при каждом DELETE по таблице дополнительно выполнить INSERT в таблицу архива или логов. Важно: по документации PostgreSQL команда NOTIFY в правиле выполняется безусловно (один раз на оператор), даже если условие правила не сработало ни для одной строки — это ограничение реализации.

---

## 9.2.3. Пример: логирование удалений (DO ALSO)

Требование: при удалении строк из таблицы `orders` записывать удалённые строки в таблицу `orders_deleted` (архив). Правило **DO ALSO** добавляет к каждому DELETE вставку в архив; в действии правила ссылаются на **OLD** (по документации PostgreSQL).

Таблица архива должна иметь структуру, совместимую с вставляемыми данными. Пример:

```sql
CREATE TABLE orders_deleted (LIKE orders INCLUDING ALL);

CREATE RULE log_orders_delete AS
  ON DELETE TO orders
  DO ALSO
  INSERT INTO orders_deleted SELECT OLD.*;
```

При выполнении `DELETE FROM orders WHERE ...` будет выполнен исходный DELETE и дополнительно INSERT в orders_deleted для каждой удалённой строки (переписанная команда содержит оба действия). Для сложной логики (проверки, преобразования) удобнее триггер AFTER DELETE. См. [Глоссарий](glossary.md).

## 9.2.4. Правила ON SELECT и представления

Правила **ON SELECT** допускаются **только на представлениях** (по документации PostgreSQL). Такое правило должно быть безусловным **INSTEAD**, с одним действием — одной командой SELECT, и обычно имеет имя **"_RETURN"**. Оно задаёт, какой запрос подставляется при обращении к представлению. Команда **CREATE VIEW** по сути создаёт «пустую» таблицу и такое правило. Вручную создавать ON SELECT для представлений редко нужно; для изменения определения представления предпочтительнее **CREATE OR REPLACE VIEW**. См. [Глоссарий](glossary.md).

---

## 9.2.5. Обновляемое представление через DO INSTEAD

Чтобы представление можно было обновлять (INSERT/UPDATE/DELETE по нему), для нужных операций создают правила **ON INSERT**, **ON UPDATE**, **ON DELETE** с **DO INSTEAD**: действие — команды по **базовым таблицам**, с подстановкой NEW/OLD. Для сложных представлений (несколько таблиц, соединения) логику проще реализовать **INSTEAD OF** триггерами (гл. 8). Простые представления часто делаются автоматически обновляемыми без явных правил (см. CREATE VIEW). См. [Глоссарий](glossary.md).

Ограничение: таблица с правилами INSERT или UPDATE **не может** быть целевой для **INSERT ... ON CONFLICT**; в таких сценариях рассматривают обновляемое представление или триггеры. MERGE по представлению с правилами на INSERT/UPDATE/DELETE не поддерживается (только правила ON SELECT).

---

## Ключевое

- **CREATE RULE** имя **ON** событие **TO** таблица **[ WHERE условие ] DO [ ALSO | INSTEAD ]** команда **(или NOTHING)**; события — SELECT, INSERT, UPDATE, DELETE.
- **DO INSTEAD** — подмена команды; **DO ALSO** — дополнительная команда к исходной; в условии и в командах доступны **NEW** и **OLD**.
- Пример DO ALSO — логирование удалений (INSERT INTO архив SELECT OLD.*).
- ON SELECT только на представлениях (правило _RETURN); обновляемые представления — правила ON INSERT/UPDATE/DELETE DO INSTEAD; для сложной логики чаще используют INSTEAD OF триггеры.

В [§9.3](chapter-09-03.md) разберём **отличие правил от триггеров** и когда что использовать.
