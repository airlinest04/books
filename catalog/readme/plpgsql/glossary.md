# Глоссарий

Термины PL/pgSQL (PostgreSQL), используемые в книге.

---

## %

**%ROWTYPE** — конструкция в объявлении переменной: тип «строка таблицы»; переменная хранит всю строку, поля доступны как `переменная.поле`. См. [§2.2](chapter-02-02.md).

**%TYPE** — конструкция в объявлении переменной: тип берётся от столбца таблицы (`таблица.столбец%TYPE`) или от другой переменной (`переменная%TYPE`). Сохраняет
совместимость при изменении типа в схеме. См. [§2.2](chapter-02-02.md).

---

## B

**BEFORE/AFTER триггер** — момент срабатывания: BEFORE — до операции (можно изменить или отменить строку); AFTER — после операции. INSTEAD OF — только на представлениях.
См. [§8.1](chapter-08-01.md).

---

## C

**CALL** — оператор SQL для вызова процедуры: CALL имя_процедуры(аргументы); при наличии OUT-параметров возвращается строка с их значениями. Функции вызывают через
SELECT, не через CALL. См. [§6.1](chapter-06-01.md), [§6.2](chapter-06-02.md).

**CASE_NOT_FOUND** — исключение в PL/pgSQL, возникающее при выполнении оператора CASE, если ни одна ветка WHEN не выбрана и ветка ELSE отсутствует. См. [§3.2]
(chapter-03-02.md).

**COMMIT** — команда завершения текущей транзакции с фиксацией изменений; в процедуре и блоке DO допустима только при вызове не внутри транзакционного блока; после COMMIT
автоматически начинается новая транзакция. COMMIT AND CHAIN открывает новую транзакцию с теми же параметрами. См. [§6.3](chapter-06-03.md).

**CONTINUE** — оператор перехода к следующей итерации цикла: CONTINUE — следующая итерация текущего цикла; CONTINUE WHEN условие — при истинном условии; CONTINUE метка —
следующая итерация цикла с указанной меткой. См. [§3.5](chapter-03-05.md).

**CREATE FUNCTION** — команда SQL для создания функции: имя, параметры (IN/OUT/INOUT), RETURNS тип, AS $$ тело $$, LANGUAGE plpgsql. CREATE OR REPLACE FUNCTION заменяет
существующую функцию с тем же именем и типами аргументов. См. [§5.1](chapter-05-01.md).

**CREATE PROCEDURE** — команда SQL для создания процедуры: имя, параметры (IN/OUT/INOUT), LANGUAGE plpgsql, AS $$ тело $$; предложения RETURNS нет; вызов — оператором
CALL. См. [§6.1](chapter-06-01.md).

**CREATE RULE** — команда SQL для создания правила: ON SELECT/INSERT/UPDATE/DELETE TO таблица [ WHERE условие ] DO INSTEAD|ALSO команда; в условии и командах доступны NEW
и OLD. См. [§9.2](chapter-09-02.md).

**CREATE TRIGGER** — команда SQL для создания триггера: имя, BEFORE/AFTER/INSTEAD OF, события (INSERT, UPDATE, DELETE, TRUNCATE), ON таблица, FOR EACH ROW/STATEMENT, WHEN
(условие), EXECUTE FUNCTION функция. См. [§8.3](chapter-08-03.md).

---

## E

**EXCEPTION (секция блока)** — необязательная часть блока перед END; при ошибке в BEGIN управление переходит в список WHEN ... THEN; блок с EXCEPTION образует
подтранзакцию. См. [§2.1](chapter-02-01.md), гл. 4.

**EXECUTE (динамический SQL)** — оператор PL/pgSQL: EXECUTE строка_команды [ INTO цель ] [ USING выражение, ... ]; выполняет команду, заданную строкой; параметры $1, $2 в
строке получают значения из USING. Используется для динамического SQL. См. [§7.3](chapter-07-03.md).

**EXIT** — оператор выхода из цикла: EXIT — выход из текущего цикла; EXIT WHEN условие — выход при истинном условии; EXIT метка — выход из цикла с указанной меткой. См.
[§3.3](chapter-03-03.md), [§3.5](chapter-03-05.md).

---

## F

**FOR (цикл)** — в PL/pgSQL: FOR по диапазону целых (IN низ..верх, REVERSE, BY шаг) или FOR по результату запроса (IN запрос / IN EXECUTE строка); переменная цикла
объявляется автоматически. См. [§3.4](chapter-03-04.md).

**FOR EACH ROW / FOR EACH STATEMENT** — уровень триггера: по строке (вызов для каждой затронутой строки, доступны NEW/OLD) или по оператору (один вызов на команду). См.
[§8.1](chapter-08-01.md).

**FOUND** — встроенная переменная типа boolean в PL/pgSQL; после SELECT ... INTO истина, если была присвоена строка, иначе ложь. Устанавливается и другими операторами
(PERFORM, DML, FETCH, FOR). См. [§2.3](chapter-02-03.md).

---

## G

**GET DIAGNOSTICS** — команда PL/pgSQL для получения текущего статуса выполнения: GET DIAGNOSTICS переменная = ROW_COUNT (и др.); ROW_COUNT — число строк, обработанных
последней SQL-командой. Не путать с GET STACKED DIAGNOSTICS (данные об исключении в обработчике). См. [§7.1](chapter-07-01.md), [§4.3](chapter-04-03.md).

**GET STACKED DIAGNOSTICS** — команда PL/pgSQL в обработчике EXCEPTION; присваивает переменным детали перехваченного исключения (RETURNED_SQLSTATE, MESSAGE_TEXT,
PG_EXCEPTION_DETAIL, PG_EXCEPTION_CONTEXT и др.). См. [§4.3](chapter-04-03.md).

---

## L

**LOOP** — безусловный цикл в PL/pgSQL: операторы между LOOP и END LOOP повторяются до EXIT или RETURN. См. [§3.3](chapter-03-03.md).

---

## N

**NEW (триггер)** — в построчном триггере переменная типа record: новая версия строки при INSERT и UPDATE; в BEFORE можно изменять и вернуть; при DELETE не определена.
См. [§8.2](chapter-08-02.md).

---

## O

**OLD (триггер)** — в построчном триггере переменная типа record: старая версия строки при UPDATE и DELETE; только для чтения; при INSERT не определена. См. [§8.2]
(chapter-08-02.md).

**OTHERS (WHEN OTHERS)** — условие в EXCEPTION, перехватывающее любую ошибку, кроме QUERY_CANCELED и ASSERT_FAILURE; обычно ставят последним обработчиком. См. [§4.2]
(chapter-04-02.md).

---

## P

**PARALLEL (UNSAFE, RESTRICTED, SAFE)** — атрибут функции в CREATE FUNCTION: допустимость выполнения в параллельных воркерах запроса; по умолчанию для пользовательских
функций — UNSAFE. См. [§5.4](chapter-05-04.md).

**PERFORM** — оператор PL/pgSQL: выполнить запрос (как SELECT, но с ключевым словом PERFORM вместо SELECT) и отбросить результат; FOUND устанавливается в true, если
получена хотя бы одна строка. См. [§7.1](chapter-07-01.md).

**PL/pgSQL** — процедурное расширение (загружаемый язык) PostgreSQL; добавляет к SQL управляющие конструкции (IF, циклы), переменные, обработку исключений; используется
для написания функций, процедур и триггеров. См. [§1.2](chapter-01-02.md).

---

## Q

**quote_ident**, **quote_literal**, **quote_nullable** — функции PostgreSQL для безопасной вставки в динамический SQL: quote_ident — идентификатор (таблица, столбец),
quote_literal — строковый литерал (при NULL возвращает NULL), quote_nullable — значение-литерал (при NULL возвращает слово NULL). См. [§7.3](chapter-07-03.md).

---

## R

**RAISE** — оператор PL/pgSQL для отправки сообщений и вызова исключений: RAISE [уровень] 'формат' [, выражения] [USING ...]; уровни — DEBUG, LOG, INFO, NOTICE, WARNING,
EXCEPTION. RAISE EXCEPTION прерывает выполнение; RAISE; без параметров в обработчике перевыбрасывает текущее исключение. См. [§4.4](chapter-04-04.md).

**RECORD** — тип переменной без фиксированной структуры; структура определяется при присваивании (SELECT INTO, FETCH, FOR). До присваивания обращение к полям вызывает
ошибку. См. [§2.2](chapter-02-02.md).

**RETURN NEXT** — оператор PL/pgSQL в функции с RETURNS SETOF/TABLE: добавляет одну строку (выражение или текущие OUT) в набор результата; не завершает функцию; в конце
нужен RETURN; без аргумента. См. [§5.3](chapter-05-03.md).

**RETURN QUERY** — оператор PL/pgSQL в функции с RETURNS SETOF/TABLE: выполняет запрос и добавляет все его строки к набору результата; RETURN QUERY EXECUTE — для
динамического запроса. См. [§5.3](chapter-05-03.md), гл. 7.

**RETURNS SETOF** — объявление возвращаемого набора строк: RETURNS SETOF тип (скаляр, составной тип, record); вызов функции в FROM. См. [§5.3](chapter-05-03.md), [§7.4]
(chapter-07-04.md).

**RETURNS TABLE** — объявление возвращаемого набора с явными именами и типами столбцов: RETURNS TABLE (столбец тип, ...); вызов функции в FROM. См. [§7.4](chapter-07-04.
md).

**ROLLBACK** — команда отмены текущей транзакции; в процедуре и блоке DO допустима только при вызове не внутри транзакционного блока; после ROLLBACK автоматически
начинается новая транзакция. ROLLBACK AND CHAIN открывает новую транзакцию с теми же параметрами. См. [§6.3](chapter-06-03.md).

**Round-trip** — один цикл «клиент отправил запрос — сервер выполнил — клиент получил ответ». Уменьшение числа round-trip за счёт переноса логики в БД (PL/pgSQL) снижает
сетевые задержки и нагрузку на парсинг. См. [§1.1](chapter-01-01.md), [§1.2](chapter-01-02.md).

---

## S

**search_path** — список схем PostgreSQL, по которому ищутся объекты при использовании неквалифицированных имён; для SECURITY DEFINER рекомендуется задавать в CREATE
FUNCTION (SET search_path), чтобы исключить подмену объектов. См. [§5.6](chapter-05-06.md).

**SECURITY DEFINER** — режим выполнения функции: функция выполняется с правами владельца функции; используется для контролируемого доступа к объектам, на которые у
вызывающего нет прав; требует мер безопасности (search_path, ограничение EXECUTE). См. [§5.6](chapter-05-06.md).

**SECURITY INVOKER** — режим выполнения функции (по умолчанию): функция выполняется с правами вызывающего; доступ к объектам БД проверяется для его роли. См. [§5.6]
(chapter-05-06.md).

**SELECT ... INTO** — в PL/pgSQL форма SELECT с предложением INTO: результат одной строки запроса записывается в переменную записи, переменную строки или список
переменных. Не путать с SQL-командой SELECT INTO, создающей таблицу. См. [§2.3](chapter-02-03.md).

**SQL-инъекция** — подстановка в текст запроса фрагментов, меняющих смысл команды. Защита: данные передавать через USING, не конкатенацией; идентификаторы вставлять через
quote_ident или format(%I). См. [§7.3](chapter-07-03.md).

**SQLERRM** — встроенная переменная в обработчике EXCEPTION; содержит текст сообщения об ошибке перехваченного исключения; вне обработчика не определена. См. [§4.3]
(chapter-04-03.md).

**SQLSTATE** — пятисимвольный код ошибки по стандарту SQL; в PL/pgSQL доступен в обработчике как встроенная переменная; в WHEN можно писать WHEN SQLSTATE 'код'. См. [§4.2]
(chapter-04-02.md), [§4.3](chapter-04-03.md).

**STRICT (INTO)** — опция в SELECT/INSERT/UPDATE/DELETE/MERGE ... INTO: требуется ровно одна строка результата; при нуле строк — NO_DATA_FOUND, при нескольких —
TOO_MANY_ROWS. См. [§2.3](chapter-02-03.md).

---

## T

**TG_OP** — в триггерной функции переменная типа text: операция, вызвавшая триггер — 'INSERT', 'UPDATE', 'DELETE' или 'TRUNCATE'. См. [§8.2](chapter-08-02.md).

---

## V

**VARIADIC** — объявление параметра функции как массива переменной длины: при вызове можно передать несколько значений одного типа (они собираются в массив) или один
массив; в теле параметр имеет тип массива. См. [§5.2](chapter-05-02.md).

**VOLATILE (STABLE, IMMUTABLE)** — категории изменчивости функции для оптимизатора: IMMUTABLE — тот же результат при тех же аргументах всегда; STABLE — тот же результат в
пределах одной команды; VOLATILE (по умолчанию) — результат может меняться или есть побочные эффекты. См. [§5.4](chapter-05-04.md).

---

## W

**WHILE** — цикл с проверкой условия в начале каждой итерации: WHILE условие LOOP ... END LOOP; при ложном условии при входе тело не выполняется. См. [§3.4](chapter-03-04.
md).

---

## А

**Анонимный блок (DO)** — блок кода на PL/pgSQL, выполняемый оператором DO $$ ... $$; не сохраняется в каталоге БД, выполняется один раз при отправке оператора. См. [§1.3]
(chapter-01-03.md), [§1.4](chapter-01-04.md).

---

## Б

**Блок (PL/pgSQL)** — структура из необязательных метки и DECLARE, обязательных BEGIN/END и необязательной секции EXCEPTION; тело функции, процедуры или DO должно быть
одним блоком. См. [§2.1](chapter-02-01.md).

---

## Д

**Декларативность (SQL)** — описание *что* нужно получить или изменить, а не *как* пошагово выполнять; порядок и способ выполнения определяет движок БД.
Противопоставляется императивному (процедурному) стилю с явными ветвлениями и циклами.

**Долларовые кавычки (dollar quoting)** — способ задания строкового литерала в PostgreSQL: `$$текст$$` или `$метка$текст$метка$`; внутри не нужно экранировать одинарные
кавычки. Используется для тела функций и блоков DO. См. [§1.4](chapter-01-04.md).

---

## К

**Константа (CONSTANT)** — переменная, объявленная с CONSTANT в DECLARE; обязательно имеет начальное значение; присваивание в теле блока запрещено. См. [§2.4]
(chapter-02-04.md).

**Курсор (cursor)** — в PL/pgSQL переменная типа refcursor, инкапсулирующая запрос и позицию в результате; OPEN открывает, FETCH читает строку в переменные, CLOSE
закрывает; цикл FOR по привязанному курсору сам открывает и закрывает. См. [§7.2](chapter-07-02.md).

---

## Л

**Локальные переменные** — именованные ячейки для хранения значений внутри процедурного блока (функции, процедуры, анонимного блока); объявляются в DECLARE, им
присваиваются результаты запросов или выражений и используются в последующих операторах. В чистом SQL между отдельными запросами нет. См. [§1.1](chapter-01-01.md), [§2.2]
(chapter-02-02.md).

---

## М

**Метка блока** — имя в двойных угловых скобках `<<имя>>` перед блоком и опционально после END; используется для EXIT с меткой и для квалификации переменных во вложенных
блоках (`метка.переменная`). См. [§2.1](chapter-02-01.md).

---

## П

**Правило (rule)** — механизм переписывания запроса в PostgreSQL: до планирования команда заменяется (DO INSTEAD) или дополняется (DO ALSO) другими командами;
привязывается к таблице/представлению по событию (SELECT, INSERT, UPDATE, DELETE). Отличается от триггера уровнем (переписывание, а не выполнение кода при событии). См.
[§9.1](chapter-09-01.md), гл. 9.

---

## Т

**Транзакция** — группа операторов, выполняемых как единое целое: либо все изменения фиксируются (COMMIT), либо при ошибке откатываются (ROLLBACK). Логика в одной функции/
процедуре PL/pgSQL выполняется в рамках транзакции вызова. См. [§1.2](chapter-01-02.md).

**Триггер** — объект БД, привязанный к таблице (или представлению), задающий вызов функции при наступлении события (INSERT, UPDATE, DELETE и т.д.). См. [§1.3]
(chapter-01-03.md), гл. 8.

**Триггерная функция** — функция (часто на PL/pgSQL), привязанная к триггеру; вызывается движком PostgreSQL автоматически при срабатывании триггера, а не по явному вызову
из запроса. См. [§1.3](chapter-01-03.md), гл. 8.

---

## У

**Управляющие конструкции** — операторы, задающие поток выполнения: ветвления (IF, CASE по условию) и циклы (LOOP, WHILE, FOR). В чистом SQL отсутствуют; в PL/pgSQL
доступны. См. [§1.1](chapter-01-01.md), гл. 3.

---

## Х

**Хранимая процедура** — процедура, определённая в БД (CREATE PROCEDURE); выполняется на сервере, вызывается оператором CALL; в отличие от функции не возвращает значение
в выражении. См. [§1.2](chapter-01-02.md), гл. 6.

**Хранимая функция** — функция, определённая в БД (например, на PL/pgSQL); выполняется на сервере, вызывается из SQL, из приложения или из других функций/триггеров. См.
[§1.2](chapter-01-02.md), гл. 5.

---

## Ч

**Чистый SQL** — язык запросов и DDL PostgreSQL без процедурных расширений: отдельные операторы SELECT, INSERT, UPDATE, DELETE, WITH, DDL; один запрос выполняется как единое целое, без ветвлений, циклов и локальных переменных между запросами. См. [§1.1](chapter-01-01.md).
