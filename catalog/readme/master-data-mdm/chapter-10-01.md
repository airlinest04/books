# §10.1 Слой эталонных данных в DWH

Часть III завершила тему моделей MDM (реестр, консолидация, сосуществование). Часть IV посвящена **эталонным данным в DWH** — как они проходят через слои хранилища и становятся измерениями витрин. В этом разделе рассмотрим **слой эталонных данных** в DWH: Raw/Staging эталонов, Core (золотая запись) и Mart (измерения для витрин). В [§10.2](chapter-10-02.md) разберём загрузку эталонов; в [§10.3](chapter-10-03.md) — витрины и измерения; в [§10.4](chapter-10-04.md) — SCD и историю изменений.

---

## 10.1.1. Отдельный поток эталонных данных

В многослойной архитектуре DWH эталонные данные образуют **отдельный поток**, параллельный потоку транзакций. См. [§1.4](chapter-01-04.md), [§8.4](chapter-08-04.md).

- **Транзакции:** продажи, платежи, движения — загружаются из операционных систем; образуют фактовые таблицы.
- **Эталоны:** клиенты, контрагенты, продукты, справочники — загружаются из тех же или иных источников; образуют измерения и справочные таблицы.

Частота загрузки может различаться: эталоны — раз в сутки или при изменении; факты — ежедневно, ежечасно, потоково. Эталоны загружаются, как правило, **до** фактов: при загрузке факта требуется маппинг source_id на golden_id (или surrogate key измерения); измерение должно содержать соответствующую запись. См. [§10.2](chapter-10-02.md).

---

## 10.1.2. Raw / Staging эталонов

**Raw** (сырой) слой эталонов — первые «приземлённые» выгрузки из источников (CRM, ERP, справочники) без бизнес-преобразований. Структура близка к источнику. См. книга по DWH, [§3.2](../dwh/chapter-03-02.md).

**Staging эталонов** — слой, в котором данные **очищаются и приводятся к единой структуре**:

- **Нормализация форматов:** телефоны, даты, пробелы — единый вид.
- **Структура:** единая модель для всех источников (name, inn, address, phone, ...); добавление метаданных source_system, source_id, loaded_at.
- **Подготовка к дедупликации:** данные готовы для сопоставления и слияния.

Выход Staging — таблицы (staging.counterparty, staging.customer) с записями из всех источников в единой схеме. Дубликаты ещё не слиты; одна сущность может быть представлена несколькими строками (из CRM, ERP и т.д.). См. [§8.2](chapter-08-02.md), [§3.2](chapter-03-02.md).

---

## 10.1.3. Core эталонов: золотая запись

**Core эталонов** — слой согласованных эталонных данных. Здесь формируется **золотая запись** по каждой сущности: дедупликация, слияние по правилам, единый ключ (golden_id). См. [§4.1](chapter-04-01.md), [§8.2](chapter-08-02.md).

Содержимое:

- **Таблицы золотых записей:** core.customer, core.counterparty, core.product — по одной строке на сущность с полным набором атрибутов.
- **Таблица маппинга:** (source_system, source_id) → golden_id для связи с источниками и транзакциями. См. [§7.2](chapter-07-02.md).
- **Метаданные:** источник значений, даты обновления; при SCD — effective_from, effective_to. См. [§10.4](chapter-10-04.md).

Core эталонов — **источник правды** для эталонных сущностей в границах DWH. Витрины и измерения строятся из Core. См. [§1.4](chapter-01-04.md).

---

## 10.1.4. Mart: измерения для витрин

**Mart** (витрина) — слой готовых к потреблению данных: факты + измерения в форме звёздной схемы (или снежинки). См. книга по DWH, [§3.2](../dwh/chapter-03-02.md).

**Измерения** (dim_customer, dim_product, dim_counterparty) — эталонные сущности в размерной модели. Строятся из Core эталонов с преобразованиями:

- **Денормализация:** иерархии (категория, регион) могут быть «развёрнуты» в столбцы измерения. См. [§6.4](chapter-06-04.md).
- **SCD:** при версионировании истории — effective_from, effective_to; surrogate key на версию. См. [§10.4](chapter-10-04.md).
- **Обрезка атрибутов:** только те поля, что нужны для витрины.

Суррогатный ключ измерения (customer_sk, product_sk) — golden_id или его производная. Факты ссылаются на этот ключ. См. [§10.3](chapter-10-03.md).

---

## 10.1.5. Схема потока

```
Источники (CRM, ERP, ...)
        │
        ▼
   Raw эталонов (сырые выгрузки)
        │
        ▼
   Staging эталонов (очистка, единая структура, source_system, source_id)
        │
        ▼
   Дедупликация + слияние
        │
        ▼
   Core эталонов (золотая запись, маппинг)
        │
        ▼
   Mart / измерения (dim_customer, dim_product, ...)
        │
        ▼
   Витрины (fact + dimensions)
```

---

## 10.1.6. Центр MDM вне DWH

Когда **центр MDM** реализован вне DWH (отдельная MDM-система), поток упрощается:

```
Источники → MDM (дедупликация, слияние, золотая запись)
                    │
                    ▼
            DWH: загрузка из MDM → Core (или сразу Mart)
```

DWH получает готовые золотые записи из MDM; Raw и Staging эталонов в DWH могут отсутствовать или использоваться только для аудита/отладки. Core в DWH — копия или представление данных из MDM. См. [§8.1](chapter-08-01.md), [§8.4](chapter-08-04.md).

---

## 10.1.7. Варианты наименований слоёв

Названия слоёв могут отличаться в зависимости от принятой в организации архитектуры:

| Наш термин | Альтернативы |
|------------|--------------|
| Raw эталонов | Landing, Bronze (для эталонов) |
| Staging эталонов | ODS эталонов, Silver (для эталонов) |
| Core эталонов | Integration Layer, Gold эталонов, MDM-слой |
| Mart / измерения | Presentation, витрина, Data Mart |

Суть: сырые данные → очищенные и приведённые к единой структуре → золотая запись (дедупликация, слияние) → измерения для витрин. См. книга по DWH, [§3.3](../dwh/chapter-03-03.md).

---

## 10.1.8. Типичные ошибки

- **Смешивать Raw и Staging:** Raw — «как пришло»; Staging — очищено и приведено к единой модели; не пропускать очистку.
- **Загружать факты до эталонов:** при загрузке факта нужен маппинг source_id → golden_id; измерение должно существовать.
- **Пропускать Core:** если измерения строятся напрямую из Staging без дедупликации — дубликаты попадут в витрины.
- **Игнорировать маппинг:** без маппинга невозможно корректно загружать транзакции и связывать source_id с golden_id.

---

## Ключевое

- **Эталонные данные** — отдельный поток в DWH: Raw → Staging → Core → Mart (измерения).
- **Raw/Staging эталонов:** сырые выгрузки, очистка, единая структура, source_system, source_id.
- **Core эталонов:** золотая запись, маппинг; результат дедупликации и слияния.
- **Mart / измерения:** dim_customer, dim_product — из Core; денормализация, SCD; для витрин.
- **Центр вне DWH:** DWH загружает из MDM; Raw/Staging могут быть минимальны.

В [§10.2](chapter-10-02.md) разберём загрузку эталонных данных: полная и инкрементальная, CDC, частота обновления.
