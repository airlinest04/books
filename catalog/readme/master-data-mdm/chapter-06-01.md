# §6.1 Иерархии: родитель — потомок

В главе 5 мы завершили тему дедупликации. Глава 6 посвящена **иерархиям и связям** между эталонными сущностями. В этом разделе рассмотрим **иерархию «родитель — потомок»**: дерево, самоссылка (parent_id), обход вверх и вниз по иерархии. Эта модель применима к категориям продуктов, организационной структуре, клиентам и филиалам. В [§6.2](chapter-06-02.md) разберём множественные иерархии; в [§6.3](chapter-06-03.md) — разрешение иерархий в запросах; в [§6.4](chapter-06-04.md) — связь с DWH и схемой «снежинка».

---

## 6.1.1. Иерархия как дерево

**Иерархия** — структура «родитель — потомок», образующая **дерево**: у каждого узла (кроме корня) есть один родитель; у узла может быть несколько потомков (детей). Корень — узел без родителя. См. [Глоссарий](glossary.md).

Примеры:

- **Категории продуктов:** Молочные (корень) → Сыры → Твёрдые → [продукт]
- **Организационная структура:** Компания (корень) → Дивизион → Управление → Отдел
- **Клиент — филиалы:** Головная организация (корень) → Филиал 1, Филиал 2, ...

Дерево не содержит циклов: от узла нельзя пройти по связям «родитель» и вернуться к нему же. При загрузке из источников нужно проверять отсутствие циклов. См. [§3.4](chapter-03-04.md).

---

## 6.1.2. Самоссылка (parent_id)

**Самоссылка** — ссылка записи на другую запись той же таблицы. Для иерархии каждая строка хранит `parent_id` — идентификатор родительской записи. Корень имеет `parent_id = NULL`. См. [Глоссарий](glossary.md).

Пример структуры:

```sql
CREATE TABLE dim_category (
    category_id   BIGINT PRIMARY KEY,
    parent_id     BIGINT REFERENCES dim_category(category_id),
    name          VARCHAR(200),
    level_num     INT  -- опционально: уровень в иерархии
);

-- Пример данных
-- id | parent_id | name
-- 1  | NULL      | Молочные продукты
-- 2  | 1         | Сыры
-- 3  | 1         | Молоко
-- 4  | 2         | Твёрдые
-- 5  | 2         | Мягкие
```

Дерево:

```
1 (Молочные)
├── 2 (Сыры)
│   ├── 4 (Твёрдые)
│   └── 5 (Мягкие)
└── 3 (Молоко)
```

Модель с parent_id проста и гибка: добавление узла, перемещение ветки (смена parent_id), изменение глубины — без перестройки всей структуры. См. [§2.2](chapter-02-02.md), [§2.4](chapter-02-04.md).

---

## 6.1.3. Обход вниз (от корня к листьям)

**Обход вниз** — от заданного узла ко всем его потомкам (детям, внукам и т.д.). Нужен для: «все продукты в категории и подкатегориях», «все подразделения в дивизионе», «все филиалы клиента».

В SQL — рекурсивный CTE (Common Table Expression):

```sql
-- Все потомки категории 1 (Молочные)
WITH RECURSIVE tree AS (
    -- Якорь: начальный узел
    SELECT category_id, parent_id, name, 1 AS level
    FROM dim_category
    WHERE category_id = 1
    
    UNION ALL
    
    -- Рекурсия: дети узлов из tree
    SELECT c.category_id, c.parent_id, c.name, t.level + 1
    FROM dim_category c
    JOIN tree t ON c.parent_id = t.category_id
)
SELECT * FROM tree;
```

Результат: категории 1, 2, 3, 4, 5 — вся ветка от корня вниз.

---

## 6.1.4. Обход вверх (от листа к корню)

**Обход вверх** — от заданного узла ко всем предкам (родитель, прародитель, … до корня). Нужен для: «путь от продукта до корневой категории», «путь от отдела до компании», «все родительские подразделения».

Рекурсивный CTE:

```sql
-- Все предки категории 4 (Твёрдые)
WITH RECURSIVE path AS (
    -- Якорь: начальный узел
    SELECT category_id, parent_id, name, 1 AS level
    FROM dim_category
    WHERE category_id = 4
    
    UNION ALL
    
    -- Рекурсия: родитель узлов из path
    SELECT c.category_id, c.parent_id, c.name, p.level + 1
    FROM dim_category c
    JOIN path p ON c.category_id = p.parent_id
)
SELECT * FROM path ORDER BY level;
```

Результат: 4 (Твёрдые) → 2 (Сыры) → 1 (Молочные).

---

## 6.1.5. Получение уровня (depth) и пути

**Уровень** (depth) — расстояние от корня. Корень — уровень 0 или 1 (по соглашению). В рекурсивном CTE уровень накапливается в столбце `level`.

**Путь** (path) — цепочка от корня к узлу или обратно. Можно собирать в рекурсии:

```sql
-- Путь от корня до каждого узла (например, "Молочные/Сыры/Твёрдые")
WITH RECURSIVE tree AS (
    SELECT category_id, parent_id, name, 
           1 AS level,
           name::TEXT AS path
    FROM dim_category
    WHERE parent_id IS NULL
    
    UNION ALL
    
    SELECT c.category_id, c.parent_id, c.name, 
           t.level + 1,
           t.path || '/' || c.name
    FROM dim_category c
    JOIN tree t ON c.parent_id = t.category_id
)
SELECT * FROM tree;
```

В PostgreSQL для конкатенации путей удобна функция `string_agg` в обратном направлении или накопление в рекурсии, как выше. См. [§6.3](chapter-06-03.md).

## 6.1.6. Oracle: CONNECT BY

В Oracle иерархии традиционно задают через `CONNECT BY`:

```sql
-- Обход вниз от узла 1
SELECT category_id, parent_id, name, LEVEL
FROM dim_category
START WITH category_id = 1
CONNECT BY parent_id = PRIOR category_id;

-- Обход вверх от узла 4
SELECT category_id, parent_id, name, LEVEL
FROM dim_category
START WITH category_id = 4
CONNECT BY category_id = PRIOR parent_id;
```

`LEVEL` — встроенный псевдоним для уровня. `CONNECT BY` и `PRIOR` определяют направление обхода. В PostgreSQL и других СУБД используют рекурсивные CTE. См. [§6.3](chapter-06-03.md).

## 6.1.7. Closure table (таблица путей)

**Closure table** — отдельная таблица пар «потомок — предок» для быстрого обхода без рекурсии. Каждая пара (descendant_id, ancestor_id) с distance (расстояние). См. [Глоссарий](glossary.md).

Пример:

```sql
CREATE TABLE category_closure (
    ancestor_id   BIGINT,
    descendant_id BIGINT,
    distance      INT,  -- 0 = сам узел, 1 = ребенок, 2 = внук ...
    PRIMARY KEY (ancestor_id, descendant_id)
);

-- Для категории 1 (Молочные) и её потомков:
-- ancestor | descendant | distance
-- 1        | 1          | 0
-- 1        | 2          | 1
-- 1        | 3          | 1
-- 1        | 4          | 2
-- 1        | 5          | 2
```

Запрос «все потомки узла 1»: `SELECT descendant_id FROM category_closure WHERE ancestor_id = 1 AND distance > 0`.

Плюсы: быстрые запросы без рекурсии. Минусы: при изменении структуры нужно обновлять closure table; хранение избыточно. Подходит для часто читаемых, редко меняющихся иерархий. См. [§3.4](chapter-03-04.md).

## 6.1.8. Проверка на циклы

При загрузке или обновлении иерархии возможны **циклы** (A → B → C → A). В дереве их быть не должно. Проверка в рекурсивном CTE — через сбор пройденных id:

```sql
-- Проверка: есть ли циклы
WITH RECURSIVE tree AS (
    SELECT category_id, parent_id, 
           ARRAY[category_id] AS path
    FROM dim_category
    WHERE parent_id IS NULL
    
    UNION ALL
    
    SELECT c.category_id, c.parent_id, 
           t.path || c.category_id
    FROM dim_category c
    JOIN tree t ON c.parent_id = t.category_id
    WHERE NOT (c.category_id = ANY(t.path))  -- предотвратить цикл
)
SELECT * FROM tree;
```

Если запрос обрывается из‑за цикла (без `WHERE NOT ...`), добавление условия исключает бесконечную рекурсию и пропуск «зацикленных» веток. Для валидации: при отсутствии условия запрос с циклическими данными приведёт к ошибке или зависанию. См. [§11.4](chapter-11-04.md).

---

## 6.1.9. Типичные ошибки

- **Забыть про NULL для корня:** parent_id корня должен быть NULL; иначе «сирота» или цикл.
- **Бесконечная рекурсия:** при циклах рекурсивный CTE зациклится; нужна защита (проверка на повторное посещение узла).
- **Путать направление в CONNECT BY:** `PRIOR category_id = parent_id` — вниз; `PRIOR parent_id = category_id` — вверх.
- **Смешивать уровни:** в одной иерархии уровень считается от корня; при объединении разных деревьев уровни могут несогласованно пересекаться.

---

## Ключевое

- **Иерархия** — дерево «родитель — потомок»; каждый узел (кроме корня) имеет одного родителя.
- **Самоссылка (parent_id):** в каждой строке — ссылка на родителя; корень: parent_id = NULL.
- **Обход вниз** — рекурсивный CTE: от узла к детям; `JOIN ... ON c.parent_id = t.id`.
- **Обход вверх** — рекурсивный CTE: от узла к родителям; `JOIN ... ON c.id = p.parent_id`.
- **Уровень и путь** — накапливаются в рекурсии.
- **Oracle CONNECT BY** — альтернатива рекурсивному CTE.
- **Closure table** — таблица пар потомок–предок для быстрого обхода без рекурсии.
- **Циклы** — недопустимы; при обходе нужна проверка на повторное посещение.

В [§6.2](chapter-06-02.md) мы рассмотрим множественные иерархии: один продукт — несколько «разрезов» (по категории, по бренду).
