# §6.2 Множественные иерархии

В [§6.1](chapter-06-01.md) мы разобрали иерархию «родитель — потомок». В этом разделе рассмотрим **множественные иерархии**: одна сущность (продукт, клиент) может участвовать в нескольких «деревьях» — по категории, по бренду, по региону и т.д. Каждая иерархия даёт свой «разрез» для аналитики. В [§6.3](chapter-06-03.md) разберём разрешение иерархий в запросах; в [§6.4](chapter-06-04.md) — связь со схемой «снежинка» в DWH.

---

## 6.2.1. Понятие множественных иерархий

**Множественная иерархия** — ситуация, когда одна сущность входит в несколько иерархических структур по разным признакам. Один продукт: по категории товара, по бренду, по типу упаковки, по поставщику. Один клиент: по региону, по сегменту, по каналу привлечения. Каждая иерархия — отдельное «дерево» со своей структурой; сущность — узел в нескольких деревьях одновременно. См. [§2.2](chapter-02-02.md), [§3.4](chapter-03-04.md).

---

## 6.2.2. Продукт: иерархия по категории и по бренду

Типичный пример — продукт:

**Иерархия по категории (товарная):**
```
Молочные → Сыры → Твёрдые → [Продукт: Сыр Пармезан]
```

**Иерархия по бренду:**
```
Бренды → [Производитель X] → [Продукт: Сыр Пармезан]
```

Один и тот же продукт (Сыр Пармезан) — в категории «Сыры / Твёрдые» и в бренде «Производитель X». Для отчёта «продажи по категориям» используют первую иерархию; для «продажи по брендам» — вторую. См. [§2.2](chapter-02-02.md).

---

## 6.2.3. Несколько «разрезов»

Каждая иерархия задаёт **разрез** (dimension slice) для аналитики:

| Разрез | Иерархия | Пример отчёта |
|--------|----------|---------------|
| По категории товара | Товарная категория | Продажи по категориям, подкатегориям |
| По бренду | Бренд → производитель | Продажи по брендам |
| По региону | Регион → страна | Продажи по регионам |
| По каналу | Канал сбыта | Продажи по каналам |
| По организационной единице | Оргструктура | Бюджет по подразделениям |

Одна и та же сущность (продажа, продукт, клиент) может быть «разрезана» по разным иерархиям. В DWH для каждого разреза — отдельное измерение или отдельная ветка в измерении. См. [§6.4](chapter-06-04.md), [§10.3](chapter-10-03.md).

---

## 6.2.4. Моделирование множественных иерархий

**Вариант 1: несколько ссылок в сущности**

Продукт хранит `category_id`, `brand_id`, `region_id` и т.д. Каждое поле — ссылка на узел в своей иерархии. Таблицы `dim_category`, `dim_brand`, `dim_region` — каждая со своей структурой parent_id.

```sql
-- Продукт с несколькими иерархиями
CREATE TABLE dim_product (
    product_id   BIGINT PRIMARY KEY,
    category_id  BIGINT,   -- иерархия категорий
    brand_id     BIGINT,   -- иерархия брендов
    name         VARCHAR(500),
    ...
);
```

**Вариант 2: связь многие-ко-многим**

Если продукт может входить в несколько категорий (редко) или в несколько брендов — промежуточная таблица `product_category`, `product_brand`. Для типичного случая «один продукт — одна категория, один бренд» достаточно ссылок в самой таблице продукта. См. [§6.1](chapter-06-01.md).

---

## 6.2.5. Консолидация иерархий из источников

В источниках иерархии могут быть разными:

- ERP: категория «Сыры твёрдые» (плоский справочник)
- PIM: «Молочные / Сыры / Твёрдые» (многоуровневая)
- Склад: код 1234 без текста

При загрузке в MDM/DWH нужно привести к единой модели: сопоставить узлы разных источников, построить общую иерархию, маппить продукты на узлы. Это отдельная задача консолидации; при множественности источников возможны расхождения (разная глубина, разные названия уровней). См. [§3.4](chapter-03-04.md), [§4.3](chapter-04-03.md).

---

## 6.2.6. Выбор иерархии для отчёта

При множественных иерархиях важно явно задавать, какую использовать:

- Отчёт «продажи по категориям» — джойн с dim_category.
- Отчёт «продажи по брендам» — джойн с dim_brand.
- Отчёт «продажи по категориям и брендам» — оба джойна; кросс-таблица или срез по двум измерениям.

В витринах и BI-инструментах каждое измерение (категория, бренд) — отдельное поле или таблица; пользователь выбирает разрез при построении отчёта. См. [§10.3](chapter-10-03.md).

---

## 6.2.7. Ролевые измерения (role-playing)

Одна и та же таблица иерархии может использоваться в факте в **нескольких ролях**. Классический пример — дата: дата заказа, дата отгрузки, дата оплаты — одна dim_date, три внешних ключа в факте. Для иерархий: одна таблица регионов — «регион клиента» и «регион магазина» в факте продаж. См. книга по DWH, [§4.3](chapter-04-03.md).

Это не множественная иерархия сущности, а использование одного измерения в нескольких контекстах. Различие: множественная иерархия — одна сущность (продукт) в разных деревьях; ролевое измерение — одно дерево в разных ролях в факте.

---

## 6.2.8. Типичные ошибки

- **Смешивать разрезы:** отчёт «по категориям» не должен использовать иерархию брендов; явно указывать измерение.
- **Предполагать одну иерархию:** продукт может быть в категории и в бренде; модель должна поддерживать обе ссылки.
- **Не согласовать иерархии между источниками:** при консолидации нужны правила маппинга узлов; иначе «одна категория» в разных источниках окажется разными узлами.
- **Путать множество категорий и множество иерархий:** один продукт — одна категория в товарной иерархии, один бренд в иерархии брендов; это два разных «разреза», а не «много категорий у продукта».

---

## Ключевое

- **Множественные иерархии** — одна сущность входит в несколько деревьев (по категории, по бренду, по региону и т.д.).
- **Продукт** — по категории товара, по бренду; разные разрезы для разных отчётов.
- **Разрез** — иерархия как ось аналитики; отчёт «по категориям» vs «по брендам».
- **Моделирование** — несколько ссылок в сущности (category_id, brand_id) или связь многие-ко-многим при необходимости.
- **Консолидация** — приведение иерархий из источников к единой модели; маппинг узлов.
- **Выбор иерархии** — при построении отчёта явно указывать, какой разрез использовать.
- **Ролевое измерение** — одно дерево в нескольких ролях в факте; отличается от множественных иерархий сущности.

В [§6.3](chapter-06-03.md) мы разберём разрешение иерархий в запросах: рекурсивные CTE, CONNECT BY, агрегация по иерархии.
