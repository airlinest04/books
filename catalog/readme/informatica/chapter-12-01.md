# §12.1 Постановка задачи

В [§11.4](chapter-11-04.md) мы рассмотрели профилирование и узкие места. **Глава 12** — практика: полный цикл загрузки из источника в слой Staging или DWH. В этом разделе — постановка задачи пайплайна: типовой сценарий, полная и инкрементальная загрузка, идемпотентность и SCD при необходимости. Подробнее маппинг извлечения и преобразования — в [§12.2](chapter-12-02.md). См. [Глоссарий](glossary.md).

---

## 12.1.1. Типовой сценарий

**Типовой пайплайн загрузки в DWH:** извлечение из операционной системы (ERP, CRM, транзакционная БД), преобразование (очистка, маппинг полей, обогащение справочниками), загрузка в Staging или в финальные таблицы хранилища. См. [§1.1](chapter-01-01.md), [§1.4](chapter-01-04.md).

**Слои данных (по книге по DWH):**

| Слой | Назначение | Реализация в Informatica |
|------|------------|--------------------------|
| **Staging** | Промежуточное хранение; минимальная трансформация; «сырые» данные для последующей обработки | Target — таблицы стейджинга; маппинг с фильтрацией, приведением типов |
| **Core / витрины** | Финальные таблицы фактов и измерений; бизнес-логика | Target — таблицы фактов и измерений; Lookup, Aggregator, SCD при необходимости |

Пайплайн может быть одношаговым (источник → DWH) или двухшаговым (источник → Staging → DWH). Двухшаговый упрощает отладку и позволяет перезапускать загрузку из Staging без повторного чтения источника. См. [§1.4.6](chapter-01-04.md).

## 12.1.2. Полная и инкрементальная загрузка

**Полная загрузка (full load):** каждый запуск читает все данные из источника и перезаписывает target. Простая реализация; при больших объёмах — долгое выполнение и нагрузка на источник. Источник: [§1.4.3](chapter-01-04.md).

**Инкрементальная загрузка (incremental load):** только изменённые или новые данные. Требует механизм выявления изменений: watermark (колонка даты/времени последнего обновления), CDC (Change Data Capture), сравнение снимков. Source Filter или SQL-override в Source Qualifier ограничивают выборку по дате или ключу. Источник: [§6.1](chapter-06-01.md).

**Mapping Template:** Informatica предоставляет шаблон Incremental Load; Mapping → Mapping Template Wizards. См. [§4.4](chapter-04-04.md).

---

## 12.1.3. Идемпотентность

**Идемпотентность** — повторный запуск пайплайна с теми же входными данными даёт тот же результат; дубликаты не появляются. Важно при retry, recovery (Restart) и ручном перезапуске. Источник: [§10.4](chapter-10-04.md).

**Способы достижения:**

| Подход | Описание |
|-------|----------|
| **Полная перезапись партиции** | TRUNCATE + INSERT по партиции (например, по дате); target очищается перед загрузкой. |
| **Upsert по ключу** | INSERT новых строк; UPDATE существующих по первичному ключу; Session в режиме Update или Update Strategy в маппинге. |
| **MERGE в SQL-override** | При pushdown или в pre-load SQL — MERGE/UPSERT на стороне БД. |
| **Уникальный ключ + проверка** | Lookup по target; вставка только при отсутствии; для инкрементальной загрузки. |

При стратегии Recovery = Restart маппинг должен обрабатывать повторную загрузку (идемпотентность); иначе возможны дубликаты. Источник: [§10.4.2](chapter-10-04.md).

## 12.1.4. SCD при необходимости

**SCD** (Slowly Changing Dimension) — измерение, атрибуты которого меняются со временем; требуется хранение истории. См. [§4.4](chapter-04-04.md), книгу по DWH.

| Тип | Описание |
|-----|----------|
| **Type 1** | Перезапись; история не сохраняется. |
| **Type 2** | Новая строка при изменении; версионность, даты начала/окончания. |
| **Type 3** | Предыдущее значение в отдельной колонке; ограниченная история. |

**Slowly Changing Dimensions Wizard** создаёт маппинг с Lookup, Expression, Router, Update Strategy. **Mapping Template** — шаблон SCD Type 2. Lookup с dynamic cache по target table — для определения insert/update. См. [§4.4](chapter-04-04.md), [§7.2](chapter-07-02.md), [§12.3](chapter-12-03.md).

SCD применяется к таблицам измерений (клиенты, продукты, контракты); для фактов и staging обычно не требуется.

## 12.1.5. Чек-лист постановки

Перед реализацией маппинга и workflow:

- [ ] **Источник:** тип (реляционная БД, flat file); структура; объём; частота обновления.
- [ ] **Целевой слой:** Staging или Core; структура target (совпадает с источником или трансформирована).
- [ ] **Режим загрузки:** полная или инкрементальная; при инкрементальной — механизм выявления изменений.
- [ ] **Идемпотентность:** способ (перезапись партиции, upsert, MERGE); учёт при Recovery = Restart.
- [ ] **SCD:** нужна ли история измерений; тип SCD; использование визарда или шаблона.
- [ ] **Расписание:** частота запуска; зависимость от других пайплайнов.

---

## Ключевое

- **Типовой пайплайн:** источник → Staging или DWH; одно- или двухшаговый.
- **Полная загрузка** — все данные; **инкрементальная** — только изменения; Source Filter, watermark, CDC.
- **Идемпотентность** — перезапись партиции, upsert по ключу, MERGE; важно при retry и Restart.
- **SCD** — при необходимости истории измерений; Type 1, 2, 3; Slowly Changing Dimensions Wizard.
- **Чек-лист** — источник, целевой слой, режим, идемпотентность, SCD, расписание.

В [§12.2](chapter-12-02.md) мы разберём маппинг извлечения и преобразования: Source Qualifier, Expression, Lookup, Filter.
