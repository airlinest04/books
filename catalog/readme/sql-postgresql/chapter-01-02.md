# §1.2 Установка и запуск PostgreSQL

В [§1.1](../../sql-postgresql/chapter-01-01.md) мы рассмотрели, что такое SQL и какие роли он играет в работе с реляционными базами данных. Чтобы начать писать и выполнять запросы, нужна работающая СУБД. В этом разделе мы разберём, **откуда взять PostgreSQL**, как установить его на Linux, Windows и macOS, как запустить сервер и какие клиентские средства (консольный `psql` и графические утилиты) использовать для подключения. После установки вы сможете перейти к [§1.3](chapter-01-03.md), где мы создадим базу и схему и выполним первый запрос.

***

## 1.2.1. Где взять PostgreSQL

**PostgreSQL** — свободная объектно-реляционная СУБД с открытым исходным кодом. Официальный сайт проекта — [postgresql.org](https://www.postgresql.org/). Оттуда можно скачать:

* **Готовые пакеты и установщики** для Linux, Windows, macOS, BSD и Solaris.
* **Исходный код** для сборки из архива или из репозитория Git (инструкции — в [документации по установке](https://www.postgresql.org/docs/current/installation.html)).

Для обучения и разработки достаточно использовать готовые пакеты или установщики; сборка из исходников обычно нужна для нестандартных конфигураций или включения экспериментальных возможностей. См. [Глоссарий](glossary.md).

Рекомендуется выбирать одну из **поддерживаемых мажорных версий** (например, 16, 17, 18). Актуальный список поддерживаемых версий и сроков поддержки приведён на странице [Versioning Policy](https://www.postgresql.org/support/versioning/). Старые мажорные версии со временем перестают получать обновления безопасности; для новых проектов разумно брать свежую стабильную версию.

***

## 1.2.2. Установка на Linux (Ubuntu и Debian)

На дистрибутивах семейства Debian/Ubuntu PostgreSQL чаще всего ставят через пакетный менеджер `apt`. Есть два основных варианта.

### Вариант 1: версия из репозитория дистрибутива

Ubuntu и Debian включают PostgreSQL в свои репозитории. Чтобы установить ту версию, которая есть в дистрибутиве:

```bash
sudo apt update
sudo apt install postgresql
```

(Среда: Ubuntu 22.04 / Debian 12, Bash)

После установки сервер обычно запускается автоматически и при старте системы. Версия PostgreSQL при этом совпадает с той, что упакована для вашей версии ОС, и может быть старше последней стабильной.

### Вариант 2: официальный репозиторий PostgreSQL (PostgreSQL Apt Repository)

Если нужна более новая или конкретная мажорная версия, используют [официальный Apt-репозиторий PostgreSQL](https://www.postgresql.org/download/linux/debian/). Он поддерживает Ubuntu (в том числе jammy 22.04, noble 24.04) и Debian.

**Автоматическая настройка репозитория:**

```bash
sudo apt install -y postgresql-common
sudo /usr/share/postgresql-common/pgdg/apt.postgresql.org.sh
```

**Ручная настройка (если автоматический скрипт недоступен):**

```bash
# Импорт ключа репозитория
sudo apt install curl ca-certificates
sudo install -d /usr/share/postgresql-common/pgdg
sudo curl -o /usr/share/postgresql-common/pgdg/apt.postgresql.org.asc \
  --fail https://www.postgresql.org/media/keys/ACCC4CF8.asc

# Добавление репозитория
. /etc/os-release
sudo sh -c "echo 'deb [signed-by=/usr/share/postgresql-common/pgdg/apt.postgresql.org.asc] \
  https://apt.postgresql.org/pub/repos/apt $VERSION_CODENAME-pgdg main' \
  > /etc/apt/sources.list.d/pgdg.list"

# Обновление списка пакетов
sudo apt update
```

**Установка конкретной версии (например, PostgreSQL 17):**

```bash
sudo apt install postgresql-17
```

Подставьте нужный номер версии вместо `17`. Дополнительно можно установить документацию: `postgresql-doc-17`, клиентские библиотеки для разработки: `libpq-dev`.

### Red Hat, Rocky, AlmaLinux, Fedora

На дистрибутивах семейства Red Hat используют [репозиторий PostgreSQL для Red Hat](https://www.postgresql.org/download/linux/redhat/). Типичная последовательность:

```bash
sudo dnf install -y https://download.postgresql.org/pub/repos/yum/reporpms/EL-9-x86_64/pgdg-redhat-repo-latest.noarch.rpm
sudo dnf -qy module disable postgresql
sudo dnf install -y postgresql17-server postgresql17
sudo /usr/pgsql-17/bin/postgresql-17-setup initdb
sudo systemctl enable postgresql-17
sudo systemctl start postgresql-17
```

(Адаптировано по [официальной инструкции](https://www.postgresql.org/download/linux/redhat/); для EL-8 или других веток пути и пакеты могут отличаться.)

## 1.2.3. Установка на Windows

На Windows используют **графический установщик от EDB** (EnterpriseDB), доступный по адресу [EnterpriseDB Downloads](https://www.enterprisedb.com/downloads/postgres-postgresql-downloads). Установщик сертифицирован для PostgreSQL и распространяется бесплатно.

В состав установщика входят:

* **Сервер PostgreSQL** — ядро СУБД.
* **pgAdmin** — графический инструмент администрирования и разработки.
* **Stack Builder** — утилита для установки дополнительных инструментов, драйверов и расширений.

Во время установки мастер предлагает:

1. Выбрать каталог установки.
2. Выбрать компоненты (сервер, клиентские инструменты, pgAdmin и др.).
3. Указать каталог для данных (data directory).
4. Задать пароль суперпользователя `postgres`.
5. Настроить порт (по умолчанию — 5432).

После установки сервер PostgreSQL обычно запускается как служба Windows и стартует вместе с системой. Статус службы можно проверить в «Службы» (services.msc) или через PowerShell:

```powershell
Get-Service postgresql*
```

(Среда: Windows 10/11, PowerShell)

## 1.2.4. Установка на macOS

На macOS доступны несколько способов установки.

### Установщик EDB

Тот же [установщик от EDB](https://www.enterprisedb.com/downloads/postgres-postgresql-downloads) поддерживает macOS. Процесс аналогичен Windows: выбор версии, компонентов, пароля суперпользователя; после установки PostgreSQL работает как фоновая служба.

### Postgres.app

[Postgres.app](https://postgresapp.com/) — простой нативный клиент для macOS. Приложение живёт в меню; при запуске поднимается сервер PostgreSQL, при закрытии — останавливается. Удобно для локальной разработки без настройки служб. Не требует прав администратора.

### Homebrew

При установке через [Homebrew](https://brew.sh/):

```bash
brew install postgresql@17
```

(Среда: macOS, Bash)

Для привязки к PATH может потребоваться добавить в `~/.zshrc` или `~/.bash_profile`:

```bash
export PATH="/opt/homebrew/opt/postgresql@17/bin:$PATH"
```

После установки сервер нужно запустить вручную (например, `brew services start postgresql@17`) или настроить автозапуск.

## 1.2.5. Сервер и клиенты: общая схема

PostgreSQL работает по **клиент-серверной архитектуре**:

* **Сервер (postgres)** — процесс, который принимает подключения, выполняет запросы, управляет данными. Может работать на том же компьютере, что и клиент, или на удалённой машине.
* **Клиент** — программа, которая подключается к серверу, отправляет SQL-запросы и получает результаты.

| Компонент                              | Назначение                                                                            |
| -------------------------------------- | ------------------------------------------------------------------------------------- |
| `postgres` (или `postgresql`)          | Основной процесс сервера.                                                             |
| `psql`                                 | Консольный интерактивный клиент; входит в пакет `postgresql-client` или `postgresql`. |
| pgAdmin                                | Графический клиент с веб-интерфейсом; часто поставляется вместе с установщиком.       |
| Драйверы (JDBC, libpq, psycopg2 и др.) | Позволяют приложениям на различных языках подключаться к PostgreSQL.                  |

Для работы с этой книгой достаточно **сервера** и **psql**; pgAdmin и другие GUI можно использовать по желанию. В [§1.3](chapter-01-03.md) мы подробно рассмотрим подключение через `psql`.

## 1.2.6. Проверка запуска сервера

После установки нужно убедиться, что сервер запущен.

**Linux (systemd):**

```bash
sudo systemctl status postgresql
# или для конкретной версии:
sudo systemctl status postgresql-17
```

При необходимости запустить или перезапустить:

```bash
sudo systemctl start postgresql
sudo systemctl restart postgresql
```

**macOS (Homebrew):**

```bash
brew services list
brew services start postgresql@17
```

**Windows:** через оснастку «Службы» или PowerShell (см. выше).

**Проверка через подключение:** если сервер слушает порт 5432 (по умолчанию), можно попробовать подключиться. На Linux после установки из пакета обычно создаётся системный пользователь `postgres`; подключение от его имени к локальной базе `postgres` часто разрешено без пароля (peer-аутентификация):

```bash
sudo -u postgres psql -c "SELECT version();"
```

(Среда: Linux, Bash)

Команда должна вернуть строку с версией PostgreSQL. Если подключение не удаётся, проверьте: запущен ли сервер, правильный ли порт, разрешена ли аутентификация в `pg_hba.conf` (см. [документацию по аутентификации](https://www.postgresql.org/docs/current/client-authentication.html)).

## 1.2.7. Консольный клиент psql

**psql** — интерактивный терминальный клиент PostgreSQL. Он входит в пакет сервера или в отдельный пакет `postgresql-client`. Запуск:

```bash
psql -h <хост> -p <порт> -U <пользователь> -d <база>
```

Если не указывать параметры, используются значения по умолчанию: хост — localhost (через Unix-сокет на Linux/macOS), порт — 5432, пользователь — текущий пользователь ОС, база — совпадает с именем пользователя.

Пример: подключение к базе `postgres` от пользователя `postgres` на локальном сервере:

```bash
psql -U postgres -d postgres
```

Подробнее о командах `psql` и работе с базой — в [§1.3](chapter-01-03.md).

## 1.2.8. Графические клиенты (GUI)

Для тех, кто предпочитает графический интерфейс:

* **pgAdmin** — стандартный инструмент, часто поставляется с установщиком. Позволяет подключаться к серверам, просматривать объекты, выполнять запросы, управлять пользователями.
* **DBeaver** — универсальный клиент для многих СУБД, в том числе PostgreSQL; бесплатен для большинства сценариев.
* **DataGrip** (JetBrains) — платный IDE-подобный клиент с поддержкой SQL и множества баз данных.
* **Azure Data Studio** — бесплатный клиент от Microsoft с расширением для PostgreSQL.

Выбор GUI не влияет на изучение SQL: синтаксис запросов одинаков. Консольный `psql` удобен для быстрых проверок и скриптов; GUI — для навигации по схемам и визуального просмотра данных.

## 1.2.9. Типичные ошибки при установке

* **Порты:** PostgreSQL по умолчанию использует порт 5432. Если он занят другой программой или экземпляром PostgreSQL, сервер не запустится. Проверьте `netstat -tlnp | grep 5432` (Linux) или аналог на вашей ОС.
* **Права доступа к данным:** каталог данных должен принадлежать пользователю, под которым запускается сервер. При ручной установке или миграции проверьте владельца и права (`chown`, `chmod`).
* **Аутентификация:** после установки на Linux подключение без пароля часто разрешено только для локального пользователя `postgres` через peer. Для подключения с паролем или удалённо нужно настроить `pg_hba.conf` и задать пароль пользователю.
* **Версия клиента и сервера:** обычно клиент и сервер разных мажорных версий совместимы, но при сбоях подключения стоит проверить совпадение версий и протокола.

## Ключевое

* PostgreSQL доступен на [postgresql.org](https://www.postgresql.org/) в виде пакетов и установщиков для Linux, Windows, macOS, BSD, Solaris; исходный код — для сборки самостоятельно.
* **Linux (Ubuntu/Debian):** установка из репозитория дистрибутива (`apt install postgresql`) или из официального Apt-репозитория PostgreSQL для выбора версии.
* **Windows:** установщик EDB с сервером, pgAdmin и Stack Builder; сервер регистрируется как служба.
* **macOS:** установщик EDB, Postgres.app или Homebrew (`brew install postgresql@17`).
* PostgreSQL — клиент-серверная СУБД; для работы нужны запущенный сервер и клиент (psql или GUI).
* **psql** — консольный интерактивный клиент; подключается к серверу по хосту, порту, имени пользователя и базе данных.
* Графические клиенты (pgAdmin, DBeaver и др.) удобны для навигации и визуальной работы; синтаксис SQL при этом не меняется.

В [§1.3](chapter-01-03.md) мы подключимся к PostgreSQL через psql, создадим базу данных и схему, познакомимся с основными командами клиента и подготовимся к первому запросу.
