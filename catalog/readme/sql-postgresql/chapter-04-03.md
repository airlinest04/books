# §4.3 LEFT (OUTER) JOIN, RIGHT JOIN, FULL JOIN

В [§4.2](chapter-04-02.md) мы рассмотрели INNER JOIN — только строки с совпадением. **Внешние соединения** (OUTER JOIN) позволяют включать в результат строки без соответствия: все клиенты (включая без заказов), все заказы (включая с удалённым клиентом) и т.п. В этом разделе разберём LEFT JOIN, RIGHT JOIN и FULL JOIN, а также важное различие между условиями в ON и в WHERE. Сравнение JOIN и подзапросов — в [§4.4](chapter-04-04.md). См. [документацию SELECT — FROM](https://www.postgresql.org/docs/current/sql-select.html#SQL-FROM).

---

## 4.3.1. Ограничение INNER JOIN

INNER JOIN отбрасывает строки без пары. Заказ с несуществующим `customer_id` не попадёт в результат. Клиент без заказов тоже не попадёт. Часто нужен другой вариант: «все заказы» или «все клиенты» — даже если в другой таблице нет совпадения.

---

## 4.3.2. LEFT OUTER JOIN

**LEFT [OUTER] JOIN** возвращает:

1. Все строки, где условие соединения выполняется (как в INNER JOIN).
2. Плюс по одной строке для каждой строки левой таблицы, для которой не найдено совпадения в правой. Столбцы правой таблицы в таких строках заполняются `NULL`.

По [документации](https://www.postgresql.org/docs/current/sql-select.html#SQL-FROM):

```sql
FROM таблица_левая
LEFT [OUTER] JOIN таблица_правая ON условие
```

Ключевое слово **OUTER** можно опустить. Левая таблица — та, что перед `LEFT JOIN`; правая — после.

Пример — все клиенты и их заказы (включая клиентов без заказов):

```sql
SELECT c.id, c.name, o.id AS order_id, o.total
FROM customers c
LEFT JOIN orders o ON o.customer_id = c.id;
```

Клиенты с заказами дадут строки с заполненными `order_id` и `total`. Клиенты без заказов — по одной строке с `order_id = NULL` и `total = NULL`.

---

## 4.3.3. Поиск строк без соответствия

LEFT JOIN удобен для поиска строк левой таблицы, у которых **нет** пары в правой. Добавляем условие `правая.ключ IS NULL`:

```sql
SELECT c.id, c.name
FROM customers c
LEFT JOIN orders o ON o.customer_id = c.id
WHERE o.id IS NULL;
```

Клиенты, для которых не нашлось ни одного заказа, в LEFT JOIN дают строку с `o.id = NULL`. Фильтр `WHERE o.id IS NULL` оставляет только таких клиентов.

Аналогично — заказы с «битой» ссылкой на клиента (клиент удалён):

```sql
SELECT o.id, o.total
FROM orders o
LEFT JOIN customers c ON o.customer_id = c.id
WHERE c.id IS NULL;
```

---

## 4.3.4. ON и WHERE при внешних соединениях

При внешних соединениях различие между **ON** и **WHERE** критично.

- **ON** — часть соединения. Определяет, какие строки считаются парой. Условия в ON не отсекают строки левой таблицы: при отсутствии совпадения строка всё равно остаётся, столбцы правой — NULL.
- **WHERE** — фильтр результата. Применяется **после** соединения. Строка с `NULL` в столбцах правой таблицы будет отброшена, если в WHERE есть условие типа `правая.столбец = значение` (равенство с не-NULL никогда не выполняется для NULL).

Пример: «все клиенты и их заказы за 2024 год». Неверно:

```sql
SELECT c.name, o.total
FROM customers c
LEFT JOIN orders o ON o.customer_id = c.id
WHERE o.created_at >= '2024-01-01';  -- отсечёт клиентов без заказов!
```

Клиенты без заказов получат `o.created_at = NULL`; условие `NULL >= '2024-01-01'` даёт NULL, строка отфильтровывается. Правильно — перенести условие по дате в ON:

```sql
SELECT c.name, o.total
FROM customers c
LEFT JOIN orders o ON o.customer_id = c.id AND o.created_at >= '2024-01-01';
```

Теперь клиенты без заказов за 2024 год сохраняются; для них `o.total` и другие столбцы заказа — NULL.

Правило: условия, ограничивающие строки **правой** таблицы (какие строки правой подключать), — в **ON**; условия, отсекающие строки **результата** в целом, — в **WHERE**.

---

## 4.3.5. RIGHT OUTER JOIN

**RIGHT [OUTER] JOIN** — зеркало LEFT: «опорная» таблица справа. Возвращаются все строки правой таблицы плюс совпадения из левой; при отсутствии совпадения столбцы левой таблицы — NULL.

```sql
FROM таблица_левая
RIGHT JOIN таблица_правая ON условие
```

Любой RIGHT JOIN можно переписать как LEFT JOIN, поменяв таблицы местами:

```sql
FROM a RIGHT JOIN b ON a.x = b.y
-- то же, что
FROM b LEFT JOIN a ON a.x = b.y
```

RIGHT JOIN используют редко; обычно пишут LEFT JOIN с нужным порядком таблиц — так запросы проще читать.

---

## 4.3.6. FULL OUTER JOIN

**FULL [OUTER] JOIN** возвращает:

1. Все строки с совпадением (как INNER JOIN).
2. Плюс строки левой таблицы без совпадения (столбцы правой — NULL).
3. Плюс строки правой таблицы без совпадения (столбцы левой — NULL).

```sql
FROM таблица1
FULL JOIN таблица2 ON условие
```

Пример — полное внешнее соединение для сравнения двух наборов:

```sql
SELECT COALESCE(a.id, b.id) AS id, a.value AS value_a, b.value AS value_b
FROM table_a a
FULL JOIN table_b b ON a.id = b.id;
```

В результате будут строки только из `a`, только из `b` и общие. FULL JOIN встречается реже LEFT; полезен при слиянии или сравнении двух источников.

---

## 4.3.7. COALESCE при отображении NULL

При внешнем соединении столбцы правой (или левой) таблицы могут быть NULL. Для удобного отображения используют **COALESCE** (см. [§3.2](chapter-03-02.md)):

```sql
SELECT c.name, COALESCE(o.total::text, 'нет заказов') AS order_info
FROM customers c
LEFT JOIN orders o ON o.customer_id = c.id;
```

Или для числовых столбцов:

```sql
SELECT c.name, COALESCE(SUM(o.total), 0) AS total_orders
FROM customers c
LEFT JOIN orders o ON o.customer_id = c.id
GROUP BY c.id, c.name;
```

---

## 4.3.8. Цепочка внешних соединений

При нескольких JOIN порядок важен. Строка сохраняется, только если она исходит из «опорной» стороны внешнего соединения.

Пример: клиенты, их заказы и позиции заказов. Нужны все клиенты и все их заказы (включая заказы без позиций):

```sql
SELECT c.name, o.id AS order_id, oi.product_id, oi.quantity
FROM customers c
LEFT JOIN orders o ON o.customer_id = c.id
LEFT JOIN order_items oi ON oi.order_id = o.id;
```

Первый LEFT JOIN сохраняет всех клиентов. Второй — все пары клиент–заказ (заказы без позиций дадут NULL в `oi.*`). Если второй JOIN сделать INNER, заказы без позиций исчезнут.

---

## 4.3.9. Типичные ошибки

- **Условие по правой таблице в WHERE** — отсекает строки без совпадения; переносить в ON.
- **Проверка на NULL не там** — `WHERE o.id IS NULL` ищет «нет заказов»; `WHERE o.id IS NOT NULL` при LEFT JOIN эквивалентно INNER JOIN по смыслу (но не по плану).
- **Путаница LEFT и RIGHT** — легче всегда использовать LEFT и менять порядок таблиц.
- **Несколько LEFT JOIN подряд** — следить, какая таблица опорная на каждом шаге; при необходимости менять порядок.

---

## Ключевое

- **LEFT JOIN** — все строки левой таблицы + совпадения из правой; при отсутствии совпадения столбцы правой — NULL.
- **RIGHT JOIN** — то же для правой таблицы; обычно переписывается как LEFT JOIN.
- **FULL JOIN** — все строки обеих таблиц; при отсутствии пары соответствующие столбцы — NULL.
- **ON и WHERE** — условия, ограничивающие строки правой таблицы, задавать в ON; иначе строки «без пары» будут отфильтрованы в WHERE.
- Для поиска строк без соответствия: LEFT JOIN + `WHERE правая.ключ IS NULL`.

В [§4.4](chapter-04-04.md) сравним JOIN и подзапросы — когда что использовать.
