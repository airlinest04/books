# §3.4 Уникальные значения

В [§3.3](chapter-03-03.md) мы рассмотрели фильтрацию через WHERE. При выборке из нескольких таблиц или при дублировании данных в источнике в результате могут появляться одинаковые строки. Чтобы оставить только уникальные, используют **DISTINCT**. В этом разделе разберём `SELECT DISTINCT`, расширение PostgreSQL `DISTINCT ON`, связь с ORDER BY и влияние на производительность. Соединения таблиц (JOIN) рассматриваются в [§4.1](chapter-04-01.md). См. [документацию SELECT](https://www.postgresql.org/docs/current/sql-select.html).

---

## 3.4.1. Зачем нужны уникальные значения

Повторяющиеся строки в результате могут возникать, когда:

- В источнике есть дубликаты (логические или физические);
- Используется соединение нескольких таблиц (JOIN) — одна строка левой таблицы может соответствовать нескольким правой;
- Подзапрос или UNION возвращает пересекающиеся наборы.

Иногда дубликаты допустимы; иногда нужен список без повторов. Для этого используется `SELECT DISTINCT`.

---

## 3.4.2. SELECT DISTINCT

По умолчанию `SELECT` возвращает все строки, включая дубликаты. Ключевое слово **ALL** (по умолчанию) явно это подчёркивает. Ключевое слово **DISTINCT** устраняет повторяющиеся строки. По [документации](https://www.postgresql.org/docs/current/sql-select.html#SQL-DISTINCT):

```sql
SELECT [ ALL | DISTINCT ] столбцы FROM таблица [WHERE ...];
```

Две строки считаются одинаковыми, если значения **всех** столбцов в списке SELECT совпадают. NULL при сравнении считается равным NULL.

Примеры:

```sql
SELECT DISTINCT status FROM orders;
SELECT DISTINCT category_id, status FROM products;
SELECT ALL * FROM users;  -- то же, что SELECT * FROM users
```

Если выбрать один столбец — получится список уникальных значений этого столбца. Если несколько — уникальные комбинации.

---

## 3.4.3. DISTINCT и порядок строк

Порядок строк при использовании DISTINCT не гарантирован, если не указан ORDER BY. Одинаковые строки удаляются, но оставшиеся могут идти в любом порядке. Для стабильного результата добавляйте ORDER BY (см. [§5.1](chapter-05-01.md)).

---

## 3.4.4. DISTINCT ON: одна строка на группу

Расширение PostgreSQL **DISTINCT ON** оставляет для каждой уникальной комбинации выражений в скобках только **одну** строку. Остальные отбрасываются. Первой оставляется строка, определяемая ORDER BY.

Синтаксис:

```sql
SELECT DISTINCT ON (выражение1 [, выражение2, ...]) столбцы
FROM таблица
[WHERE ...]
ORDER BY выражение1 [ASC|DESC] [, выражение2, ...] [дополнительные столбцы];
```

Важно: выражения в `DISTINCT ON` должны совпадать с **началом** списка ORDER BY (слева направо). Дополнительные столбцы в ORDER BY задают порядок внутри группы и определяют, какая строка останется первой.

Пример — последний заказ по каждому клиенту:

```sql
SELECT DISTINCT ON (customer_id) id, customer_id, total, created_at
FROM orders
ORDER BY customer_id, created_at DESC;
```

Для каждого `customer_id` остаётся одна строка — с максимальной датой `created_at` в рамках группы.

---

## 3.4.5. DISTINCT ON и подзапрос

Если нужен ORDER BY, не совпадающий с DISTINCT ON (например, сортировка итога по другой колонке), используется подзапрос:

```sql
SELECT * FROM (
  SELECT DISTINCT ON (customer_id) id, customer_id, total, created_at
  FROM orders
  ORDER BY customer_id, created_at DESC
) AS last_orders
ORDER BY total DESC;
```

Внутренний запрос выбирает последний заказ по клиенту; внешний сортирует результат по сумме.

---

## 3.4.6. NULL в DISTINCT

При сравнении для уникальности два NULL считаются равными. Поэтому `SELECT DISTINCT col FROM t` при нескольких NULL в `col` вернёт одну строку с NULL. Это соответствует стандарту SQL.

---

## 3.4.7. DISTINCT с выражениями

В списке SELECT после DISTINCT могут быть не только столбцы, но и выражения. Уникальность определяется по значениям этих выражений:

```sql
SELECT DISTINCT upper(status) AS status_upper FROM orders;
SELECT DISTINCT date_trunc('day', created_at) AS day FROM events;
```

---

## 3.4.8. Влияние на производительность

Устранение дубликатов требует сравнения строк и дополнительной памяти. PostgreSQL обычно использует сортировку или хеширование; при большом числе строк это может быть заметно.

Рекомендации:

- Не использовать DISTINCT «на всякий случай», если дубликатов нет. Например, при выборке по PRIMARY KEY дубликатов быть не может.
- При соединениях оценивать, нужны ли уникальные строки; иногда лучше уточнить условие JOIN или WHERE, чем полагаться на DISTINCT.
- Для DISTINCT ON ORDER BY должен начинаться с выражений из DISTINCT ON — планировщик может использовать индекс и избежать полной сортировки.

---

## 3.4.9. Сравнение DISTINCT и GROUP BY

Для простого «уникального списка значений» `SELECT DISTINCT col FROM t` семантически эквивалентен `SELECT col FROM t GROUP BY col`. Разница в intent и в том, что GROUP BY позволяет добавлять агрегатные функции (см. гл. 7). Для одной колонки без агрегатов DISTINCT чаще проще и читаемее.

DISTINCT ON нельзя заменить одним GROUP BY без подзапроса или оконных функций: GROUP BY не позволяет выбрать произвольную строку из группы.

---

## 3.4.10. Типичные ошибки

- **DISTINCT ON без соответствующего ORDER BY** — ORDER BY обязателен, и его начало должно совпадать с выражениями в DISTINCT ON.
- **ORDER BY не совпадает с DISTINCT ON** — приведёт к ошибке; при необходимости разной сортировки используйте подзапрос.
- **Лишний DISTINCT** — если дубликатов нет (например, выборка по уникальному ключу), DISTINCT только добавляет накладные расходы.
- **Непонимание NULL** — несколько NULL считаются одним значением; при необходимости различать «неизвестные» значения это нужно учитывать.

---

## Ключевое

- **SELECT DISTINCT** удаляет дубликаты по всем столбцам в списке SELECT; порядок строк не гарантирован без ORDER BY.
- **SELECT ALL** — поведение по умолчанию, с дубликатами.
- **DISTINCT ON (выражения)** — расширение PostgreSQL: одна строка на каждую уникальную комбинацию выражений; какая именно — задаётся ORDER BY.
- ORDER BY при DISTINCT ON должен начинаться с тех же выражений, что и DISTINCT ON.
- Устранение дубликатов может влиять на производительность; не использовать DISTINCT без необходимости.

В [§4.1](chapter-04-01.md) рассмотрим соединение таблиц (JOIN) — зачем оно нужно и как получать данные из нескольких таблиц в одном запросе.
