# §5.2 LIMIT и OFFSET

В [§5.1](chapter-05-01.md) мы рассмотрели ORDER BY. Чтобы вернуть только часть строк результата — например, «первые 10» или «страница 3» — используют **LIMIT** и **OFFSET**. В этом разделе разберём синтаксис, постраничную выборку и типичные ошибки. Стандартная форма FETCH FIRST рассматривается в [§5.3](chapter-05-03.md). См. [документацию SELECT](https://www.postgresql.org/docs/current/sql-select.html).

---

## 5.2.1. Синтаксис LIMIT

**LIMIT** ограничивает число возвращаемых строк. По [документации](https://www.postgresql.org/docs/current/sql-select.html#SQL-LIMIT):

```sql
SELECT столбцы FROM таблица [WHERE ...] [ORDER BY ...] LIMIT n;
```

Параметр `n` — целое число; возвращается не более `n` строк. При `LIMIT 0` результат пуст. `LIMIT ALL` эквивалентно отсутствию ограничения.

Примеры:

```sql
SELECT id, name, price FROM products ORDER BY price DESC LIMIT 5;
SELECT * FROM orders WHERE status = 'pending' ORDER BY created_at LIMIT 10;
```

---

## 5.2.2. Синтаксис OFFSET

**OFFSET** пропускает заданное число строк в начале результата. Идёт после ORDER BY и может использоваться вместе с LIMIT:

```sql
SELECT столбцы FROM таблица [WHERE ...] [ORDER BY ...] LIMIT n OFFSET m;
```

Сначала результат формируется и сортируется (если есть ORDER BY), затем пропускаются первые `m` строк, после чего возвращаются следующие `n` строк (или все оставшиеся, если LIMIT не указан).

Пример — пропустить 20 строк, вернуть следующие 10:

```sql
SELECT id, name FROM users ORDER BY name LIMIT 10 OFFSET 20;
```

---

## 5.2.3. Порядок LIMIT и OFFSET

В запросе LIMIT и OFFSET указываются после ORDER BY. Порядок записи: сначала LIMIT, затем OFFSET, или сначала OFFSET, затем LIMIT — оба варианта допустимы:

```sql
LIMIT 10 OFFSET 20
OFFSET 20 LIMIT 10
```

PostgreSQL принимает оба; привычный порядок — LIMIT перед OFFSET.

---

## 5.2.4. Постраничная выборка (пейджинг)

Для постраничного вывода используют формулу:

- **Размер страницы** — значение LIMIT.
- **Страница N** — `OFFSET = (N - 1) * размер_страницы`.

Пример — страница 3 при 10 записях на странице:

```sql
SELECT id, name, created_at
FROM orders
ORDER BY created_at DESC
LIMIT 10 OFFSET 20;
```

(Страница 1: OFFSET 0, страница 2: OFFSET 10, страница 3: OFFSET 20.)

---

## 5.2.5. ORDER BY обязателен для пейджинга

Без ORDER BY порядок строк не определён. При LIMIT и OFFSET без сортировки «страницы» будут несогласованными: при повторном запросе те же OFFSET и LIMIT могут дать другой набор строк. Для стабильного пейджинга всегда указывайте ORDER BY по столбцам с однозначным порядком (например, `id` или `created_at`).

---

## 5.2.6. Производительность OFFSET

OFFSET заставляет СУБД пройти и отбросить первые `m` строк. При больших значениях OFFSET (например, 100 000) это может быть медленно: сортировка и сканирование выполняются, но большую часть результата мы отбрасываем.

Альтернатива для глубокого пейджинга — курсоры или «ключ-based pagination»: вместо OFFSET 10000 использовать условие `WHERE id > last_seen_id ORDER BY id LIMIT 10`. Так обрабатываются только нужные строки. Подробнее — в документации и статьях по оптимизации.

---

## 5.2.7. Параметры и подготовленные выражения

LIMIT и OFFSET могут задаваться параметрами подготовленного запроса:

```sql
PREPARE paging (int, int) AS
  SELECT * FROM orders ORDER BY id LIMIT $1 OFFSET $2;
EXECUTE paging(10, 20);
```

В приложениях значения обычно подставляются через параметры API (?, $1 и т.п.).

---

## 5.2.8. OFFSET без LIMIT

Можно указать только OFFSET без LIMIT — тогда возвращаются все строки, кроме первых `m`:

```sql
SELECT * FROM logs ORDER BY id OFFSET 1000;
```

Для больших таблиц такая выборка может быть тяжёлой.

---

## 5.2.9. Типичные ошибки

- **Пейджинг без ORDER BY** — страницы непредсказуемы; всегда добавляйте ORDER BY.
- **Страница с 1, а OFFSET с 0** — для страницы 1 OFFSET должен быть 0; формула `(page - 1) * page_size`.
- **Отрицательные значения** — LIMIT и OFFSET не должны быть отрицательными; возможна ошибка или неожиданное поведение.
- **Огромный OFFSET** — при очень большом OFFSET запрос может выполняться долго; рассмотрите key-based pagination.

---

## Ключевое

- **LIMIT n** — не более `n` строк; **LIMIT ALL** — без ограничения.
- **OFFSET m** — пропустить первые `m` строк.
- Для пейджинга: `LIMIT page_size OFFSET (page - 1) * page_size`.
- ORDER BY обязателен для воспроизводимого постраничного вывода.
- Большой OFFSET может быть медленным; для глубоких страниц предпочтительна pagination по ключу.

В [§5.3](chapter-05-03.md) рассмотрим FETCH FIRST ... ROWS ONLY — стандартный SQL-синтаксис ограничения числа строк.
