# §1.4 Первый запрос

В [§1.3](chapter-01-03.md) мы подключились к PostgreSQL, создали базу и схему и освоили основные метакоманды psql. Теперь выполним **первый SQL-запрос** — самую простую форму выборки данных: `SELECT * FROM имя_таблицы`. В этом разделе мы разберём, что означают части запроса, зачем нужна точка с запятой и как PostgreSQL обрабатывает регистр ключевых слов и идентификаторов. Эти основы понадобятся во всей последующей работе с SQL. В [§2.1](chapter-02-01.md) мы научимся создавать таблицы и наполнять их данными, а в [§3.1](chapter-03-01.md) — выбирать конкретные столбцы вместо всех сразу.

---

## 1.4.1. Минимальная форма SELECT

Запрос `SELECT` извлекает строки из таблицы (или представления). Самая простая форма:

```sql
SELECT * FROM имя_таблицы;
```

- **SELECT** — ключевое слово, указывающее, что это запрос на выборку.
- **\*** (звёздочка) — «все столбцы»: в результат попадут все столбцы таблицы.
- **FROM имя_таблицы** — источник данных: таблица или представление.
- **;** (точка с запятой) — признак конца команды.

Результат — набор строк (возможно, пустой), каждая строка содержит значения всех столбцов таблицы.

---

## 1.4.2. Выполнение первого запроса

Для проверки нужна таблица, которая уже есть в базе. В любой установленной базе PostgreSQL есть системные представления. Одно из них — **pg_tables** — содержит информацию о таблицах. Его можно использовать как пример:

```sql
SELECT * FROM pg_tables LIMIT 5;
```

(Среда: PostgreSQL 14+, psql)

Команда вернёт не более 5 строк. Пример вывода:

```
 schemaname | tablename  | tableowner | tablespace | hasindexes | hasrules | hastriggers
------------+------------+------------+------------+------------+----------+-------------
 pg_catalog | pg_type    | postgres   |            | t          | f        | f
 pg_catalog | pg_user    | postgres   |            | t          | f        | f
 ...
(5 rows)
```

`LIMIT 5` ограничивает число строк в результате; без него вернулись бы все строки из `pg_tables`. Подробнее об ограничении результатов — в [§5.2](chapter-05-02.md).

Если у вас уже есть своя таблица (созданная вручную или из примеров), можно выполнить:

```sql
SELECT * FROM имя_вашей_таблицы;
```

---

## 1.4.3. Точка с запятой: конец команды

В SQL **точка с запятой (`;`)** завершает команду. Сервер выполняет только полностью введённую команду — до точки с запятой или до конца потока ввода.

В psql это проявляется так:

- Без точки с запятой приглашение меняется с `=>` на `->`, показывая, что ввод команды продолжается:

```
postgres=> SELECT * FROM pg_tables
postgres->
```

- После точки с запятой команда выполняется:

```
postgres=> SELECT * FROM pg_tables LIMIT 1;
 schemaname | tablename | ...
------------+-----------+----
 pg_catalog | pg_type   | ...
(1 row)
```

- Одна строка может содержать несколько команд, разделённых `;`:

```sql
SELECT 1; SELECT 2;
```

Каждая команда выполняется отдельно. Подробнее о лексической структуре SQL — в [документации PostgreSQL](https://www.postgresql.org/docs/current/sql-syntax-lexical.html).

---

## 1.4.4. Регистр ключевых слов

В PostgreSQL **ключевые слова** (`SELECT`, `FROM`, `WHERE` и т.д.) **не чувствительны к регистру**. Следующие варианты эквивалентны:

```sql
SELECT * FROM pg_tables LIMIT 5;
select * from pg_tables limit 5;
Select * From pg_tables Limit 5;
SeLeCt * FrOm pg_tables LiMiT 5;
```

Сервер интерпретирует их одинаково. Часто используют такой стиль: ключевые слова — заглавными, имена таблиц и столбцов — строчными. Это вопрос соглашений, а не синтаксиса.

---

## 1.4.5. Регистр идентификаторов (имён таблиц и столбцов)

**Идентификаторы** — имена таблиц, столбцов, схем и других объектов. Правила PostgreSQL (по [документации](https://www.postgresql.org/docs/current/sql-syntax-lexical.html#SQL-SYNTAX-IDENTIFIERS)):

| Форма записи | Обработка |
|--------------|-----------|
| Без кавычек (`mytable`, `MyTable`, `MYTABLE`) | Приводятся к **нижнему регистру**. Все три варианта обозначают один и тот же объект. |
| В двойных кавычках (`"MyTable"`) | **Сохраняется регистр**. `"MyTable"` и `"mytable"` — разные имена. |

Пример: если таблица создана как `CREATE TABLE "MyTable" (...)`, то к ней можно обратиться только так:

```sql
SELECT * FROM "MyTable";
```

Обращение `SELECT * FROM MyTable` будет трактоваться как `mytable` (нижний регистр) и, если такой таблицы нет, приведёт к ошибке.

**Рекомендация:** по возможности не использовать кавычки и писать имена в нижнем регистре (`users`, `order_date`). Тогда не придётся каждый раз помнить о кавычках и различиях регистра.

---

## 1.4.6. Имя таблицы со схемой

Если таблица находится не в текущей схеме (первой в `search_path`), нужно указать **полное имя**: схема и таблица через точку:

```sql
SELECT * FROM схема.таблица;
```

Пример:

```sql
SELECT * FROM pg_catalog.pg_tables LIMIT 3;
```

`pg_catalog` — системная схема, в которой хранятся служебные объекты. `pg_tables` — представление в этой схеме; при обращении `pg_tables` без указания схемы PostgreSQL находит его через `search_path`, где `pg_catalog` участвует неявно.

---

## 1.4.7. Комментарии в SQL

В запросах можно оставлять пояснения — **комментарии**. Они игнорируются сервером.

**Однострочный комментарий** (до конца строки):

```sql
-- Выборка всех таблиц
SELECT * FROM pg_tables LIMIT 5;
```

**Блочный комментарий** (между `/*` и `*/`):

```sql
/*
 Первый запрос: системные таблицы.
 Ограничим вывод пятью строками.
*/
SELECT * FROM pg_tables LIMIT 5;
```

Блочные комментарии можно вкладывать друг в друга; это расширение стандарта SQL.

---

## 1.4.8. Пустой результат

Если таблица пуста или условие (например, в `WHERE`) ничему не соответствует, запрос возвращает **пустой набор строк**:

```
postgres=> SELECT * FROM pg_tables WHERE tablename = 'nonexistent';
 schemaname | tablename | tableowner | tablespace | hasindexes | hasrules | hastriggers
------------+-----------+------------+------------+------------+----------+-------------
(0 rows)
```

Сообщение `(0 rows)` означает, что строк не найдено. Это нормальный результат, а не ошибка.

---

## 1.4.9. Ошибка «relation does not exist»

Если таблица или представление с указанным именем не существует, PostgreSQL выдаёт:

```
ERROR:  relation "имя" does not exist
```

Возможные причины:

1. Опечатка в имени таблицы.
2. Таблица в другой схеме — используйте полное имя `схема.таблица` или проверьте `search_path`.
3. Объект ещё не создан — напоминание, что `CREATE TABLE` рассматривается в [§2.1](chapter-02-01.md).

---

## 1.4.10. Кратко о TABLE

Вместо `SELECT * FROM таблица` можно использовать укороченную форму:

```sql
TABLE таблица;
```

Она эквивалентна `SELECT * FROM таблица` (по [документации SELECT](https://www.postgresql.org/docs/current/sql-select.html)). Удобна для быстрого просмотра содержимого, но не поддерживает фильтрацию, выбор столбцов и другие конструкции, поэтому в книге далее используется только `SELECT`.

---

## 1.4.11. Типичные ошибки

- **Забыть точку с запятую в скрипте:** в psql без `;` команда не выполнится; в некоторых клиентах и драйверах поведение может отличаться. Всегда завершайте команды точкой с запятой.
- **Путать кавычки:** для строковых литералов используются **одинарные** кавычки (`'строка'`), для идентификаторов — **двойные** (`"MyTable"`). `'mytable'` — строка, а не имя таблицы.
- **Использовать `*` в продакшене без необходимости:** `SELECT *` возвращает все столбцы. Для приложений лучше перечислять нужные столбцы — это понятнее и может быть эффективнее.

---

## Ключевое

- **SELECT \* FROM таблица;** — простейшая форма выборки: все столбцы из указанной таблицы.
- **Точка с запятой** завершает SQL-команду; без неё psql ждёт продолжения ввода.
- **Ключевые слова** (SELECT, FROM, WHERE и т.д.) не чувствительны к регистру.
- **Идентификаторы без кавычек** приводятся к нижнему регистру; **в двойных кавычках** сохраняют регистр.
- Для таблиц в другой схеме используйте полное имя: `схема.таблица`.
- Для первого запуска можно использовать системное представление `pg_tables` или `TABLE pg_tables LIMIT 5`.

В [§2.1](chapter-02-01.md) мы создадим свои таблицы с помощью `CREATE TABLE`, зададим столбцы и типы данных, чтобы затем выполнять запросы к собственным данным.
