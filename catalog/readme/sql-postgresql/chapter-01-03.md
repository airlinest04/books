# §1.3 Подключение к базе, создание базы и схемы

В [§1.2](chapter-01-02.md) мы установили PostgreSQL и убедились, что сервер запущен. Теперь нужно **подключиться** к нему и подготовить среду для работы: создать свою базу данных, при необходимости — схему, познакомиться с основными командами `psql`. В этом разделе мы разберём подключение через `psql`, метакоманды `\l`, `\c`, `\dt` и другие, а также операторы SQL `CREATE DATABASE` и `CREATE SCHEMA`. После этого в [§1.4](chapter-01-04.md) мы выполним первый запрос к таблице.

---

## 1.3.1. Подключение через psql

**psql** принимает параметры подключения в командной строке или использует значения по умолчанию. Синтаксис:

```bash
psql -h <хост> -p <порт> -U <пользователь> -d <база>
```

| Параметр | Значение по умолчанию | Описание |
|----------|------------------------|----------|
| `-h` (host) | localhost / Unix-сокет | Адрес сервера |
| `-p` (port) | 5432 | Порт |
| `-U` (user) | Имя текущего пользователя ОС | Имя пользователя PostgreSQL |
| `-d` (database) | То же, что и user | Имя базы данных |

На Linux после установки из пакета часто создаётся системный пользователь `postgres`; подключение от его имени к локальной базе `postgres` обычно разрешено без пароля (метод peer):

```bash
sudo -u postgres psql -d postgres
```

Либо переключение на пользователя `postgres` и запуск psql:

```bash
sudo -i -u postgres
psql -d postgres
```

(Среда: Linux, Bash)

На Windows и macOS при установке через EDB вы задавали пароль суперпользователя `postgres`. Подключение:

```bash
psql -U postgres -d postgres
```

При запросе пароля введите его. Чтобы не вводить пароль каждый раз, можно настроить файл `~/.pgpass` (Linux/macOS) или `%APPDATA%\postgresql\pgpass.conf` (Windows) — см. [документацию libpq](https://www.postgresql.org/docs/current/libpq-pgpass.html).

**Успешное подключение** выглядит так:

```
psql (17.x)
Type "help" for help.

postgres=>
```

Строка приглашения `postgres=>` показывает текущую базу (`postgres`) и режим (однострочный). В этом режиме можно вводить SQL и метакоманды psql.

## 1.3.2. Мета-команды psql: общие принципы

Всё, что начинается с **неэкранированного обратного слэша** `\`, psql трактует как **метакоманду** (meta-command) — управляющую команду самого клиента, а не SQL. Метакоманды выполняются psql локально или вызывают служебные запросы к серверу. См. [документацию psql](https://www.postgresql.org/docs/current/app-psql.html).

Формат: `\команда [аргументы]`

Аргументы разделяются пробелами. Пробелы внутри аргумента можно заключить в одинарные кавычки. Внутри кавычек две одинарные кавычки `''` дают одну кавычку.

Для справки по всем метакомандам введите `\?`; для справки по SQL — `\h`.

## 1.3.3. Список баз данных: \l

Команда `\l` (или `\list`) выводит список баз данных в кластере:

```
postgres=> \l
                                    List of databases
   Name    |  Owner   | Encoding | Locale provider | Collate | Ctype | Access privileges
-----------+----------+----------+-----------------+---------+-------+-------------------
 postgres  | postgres | UTF8     | libc            | C       | C     |
 template0 | postgres | UTF8     | libc            | C       | C     | =c/postgres ...
 template1 | postgres | UTF8     | libc            | C       | C     | =c/postgres ...
(3 rows)
```

При установке PostgreSQL создаёт служебные базы:

- **postgres** — база по умолчанию для подключений.
- **template0** — «чистый» шаблон, нельзя изменять; используется для создания баз с нестандартной локалью или кодировкой.
- **template1** — шаблон по умолчанию; при `CREATE DATABASE` без указания шаблона новая база создаётся копированием `template1`.

Вариант `\l+` выводит дополнительную информацию (размер, описание).

## 1.3.4. Переключение подключения: \c

Команда `\c` (или `\connect`) устанавливает новое подключение к серверу:

```sql
\c [база] [пользователь] [хост] [порт]
```

Если аргумент не указан, используется прежнее значение. Дефис `-` означает «оставить как было».

Примеры:

```sql
\c mydb
```
Подключение к базе `mydb` (пользователь, хост, порт — без изменений).

```sql
\c mydb myuser
```
Подключение к базе `mydb` от пользователя `myuser`.

```sql
\c "host=localhost port=5432 dbname=mydb"
```
Подключение по строке подключения (conninfo).

После успешного подключения приглашение меняется, например: `mydb=>`. Текущее подключение можно посмотреть командой `\conninfo`.

## 1.3.5. CREATE DATABASE: создание новой базы

Создавать базы данных можно только будучи суперпользователем или имея привилегию `CREATEDB`. Оператор `CREATE DATABASE` не может выполняться внутри транзакции.

Минимальный синтаксис:

```sql
CREATE DATABASE имя_базы;
```

Пример:

```sql
CREATE DATABASE mydb;
```

Новая база создаётся копированием шаблона `template1`. Полный синтаксис (по [документации](https://www.postgresql.org/docs/current/sql-createdatabase.html)):

```sql
CREATE DATABASE name
  [ WITH ] [ OWNER [=] user_name ]
  [ TEMPLATE [=] template ]
  [ ENCODING [=] encoding ]
  [ LOCALE [=] locale ]
  [ TABLESPACE [=] tablespace_name ]
  [ CONNECTION LIMIT [=] connlimit ]
  ... ;
```

Полезные варианты:

- **OWNER** — владелец базы (по умолчанию — текущий пользователь).
- **TEMPLATE template0** — создание «чистой» базы без объектов из `template1`; требуется при смене локали или кодировки.
- **ENCODING** — кодировка символов (например, `UTF8`).
- **CONNECTION LIMIT** — предельное число одновременных подключений (-1 — без ограничений).

Пример с владельцем и шаблоном:

```sql
CREATE DATABASE sales OWNER salesapp TEMPLATE template0;
```

Эквивалент из командной строки — утилита `createdb`:

```bash
createdb -U postgres mydb
```

## 1.3.6. Схемы: зачем они нужны

В PostgreSQL **схема (schema)** — это пространство имён внутри базы данных. Схема содержит объекты: таблицы, представления, функции, типы и т.д. В одной схеме не может быть двух объектов одного типа с одинаковым именем; в разных схемах — может. См. [документацию по схемам](https://www.postgresql.org/docs/current/ddl-schemas.html).

Иерархия: **кластер → база данных → схема → объекты (таблицы и др.)**

Схемы используют, чтобы:

- Разделять объекты между пользователями или приложениями.
- Группировать связанные таблицы и объекты.
- Изолировать сторонние приложения в отдельных схемах.

Каждая база по умолчанию содержит схему **public**. Объекты, созданные без указания схемы, попадают в схему, стоящую первой в `search_path` (обычно это `public`). См. [Глоссарий](glossary.md).

## 1.3.7. CREATE SCHEMA: создание схемы

Для создания схемы нужна привилегия `CREATE` в текущей базе. Суперпользователи ограничения обходят.

Базовый синтаксис:

```sql
CREATE SCHEMA имя_схемы;
```

Пример:

```sql
CREATE SCHEMA myschema;
```

Создание схемы с владельцем:

```sql
CREATE SCHEMA myschema AUTHORIZATION myuser;
```

Схема с именем пользователя (имя схемы совпадает с владельцем):

```sql
CREATE SCHEMA AUTHORIZATION joe;
```

Создание, если схема ещё не существует (PostgreSQL-расширение):

```sql
CREATE SCHEMA IF NOT EXISTS myschema;
```

В одном операторе можно создать схему и объекты в ней:

```sql
CREATE SCHEMA hollywood
  CREATE TABLE films (title text, release date, awards text[])
  CREATE VIEW winners AS
    SELECT title, release FROM hollywood.films WHERE awards IS NOT NULL;
```

Обратите внимание: подкоманды внутри `CREATE SCHEMA` не завершаются точкой с запятой. Подробнее — в [документации CREATE SCHEMA](https://www.postgresql.org/docs/current/sql-createschema.html).

## 1.3.8. Текущая схема и search_path

Текущая схема — первая в **search_path**. В неё создаются объекты при отсутствии явного указания схемы. Текущий путь поиска:

```sql
SHOW search_path;
```

По умолчанию обычно:

```
"$user", public
```

`"$user"` подставляется именем текущего пользователя; если такой схемы нет, элемент игнорируется. В результате новые объекты чаще всего создаются в `public`.

Сменить путь поиска:

```sql
SET search_path TO myschema, public;
```

Теперь неполные имена будут искаться сначала в `myschema`, затем в `public`, а новые объекты без указания схемы — создаваться в `myschema`.

## 1.3.9. Список таблиц: \dt и \d

Команда `\dt` (tables) выводит список таблиц текущей схемы:

```
mydb=> \dt
        List of relations
 Schema |  Name  | Type  |  Owner
--------+--------+-------+----------
 public | users  | table | postgres
 public | orders | table | postgres
(2 rows)
```

`\dt` с шаблоном — только совпадающие таблицы:

```sql
\dt user*
```

`\dt *.*` — таблицы во всех схемах.

`\dt+` — с дополнительной информацией (размер и т.д.).

Список таблиц **в указанной схеме**:

```sql
\dt myschema.*
```

Команда `\d` с именем таблицы показывает её структуру (столбцы, типы, ограничения):

```
mydb=> \d users
                        Table "public.users"
 Column |  Type   | Collation | Nullable | Default
--------+---------+-----------+----------+---------
 id     | integer |           | not null |
 name   | text    |           |          |
```

`\d+` — расширенный вывод (описание, размер, индексы и др.).

## 1.3.10. Другие полезные метакоманды

| Команда | Назначение |
|---------|------------|
| `\dn` | Список схем |
| `\du` | Список ролей (пользователей) |
| `\df` | Список функций |
| `\dv` | Список представлений (views) |
| `\ds` | Список последовательностей (sequences) |
| `\di` | Список индексов |
| `\df+ имя` | Определение функции |
| `\q` | Выход из psql |
| `\! команда` | Выполнение shell-команды |
| `\timing` | Вкл/выкл вывод времени выполнения запросов |
| `\x` | Переключение расширенного формата вывода (вертикальные строки) |

## 1.3.11. Пошаговый сценарий: от подключения до первой схемы

Типичная последовательность для начала работы:

1. Подключиться к PostgreSQL:

   ```bash
   psql -U postgres -d postgres
   ```

2. Создать базу для обучения:

   ```sql
   CREATE DATABASE sqlbook;
   ```

3. Подключиться к новой базе:

   ```sql
   \c sqlbook
   ```

4. Проверить список схем:

   ```sql
   \dn
   ```

   Должна быть хотя бы `public`.

5. При необходимости создать свою схему:

   ```sql
   CREATE SCHEMA examples;
   ```

6. Переключить search_path для работы в этой схеме:

   ```sql
   SET search_path TO examples, public;
   ```

В [§2.1](chapter-02-01.md) мы создадим первые таблицы в этой среде; в [§1.4](chapter-01-04.md) разберём простой `SELECT` к уже существующей таблице.

## 1.3.12. Типичные ошибки

- **Забыть указать базу при `\c`:** `\c` без аргументов переподключается с теми же параметрами; для смены базы нужно явно указать имя.
- **Создавать объекты в «чужой» схеме:** без указания схемы объекты создаются в первой схеме из `search_path`. Проверяйте `SHOW search_path` и при необходимости явно задавайте схему: `CREATE TABLE myschema.mytable (...)`.
- **Путать базу и схему:** база — отдельное хранилище, переключение — через `\c` или новый запуск psql; схема — пространство имён внутри базы, переключение — через `SET search_path`.

---

## Ключевое

- **Подключение:** `psql -h хост -p порт -U пользователь -d база`; на Linux часто `sudo -u postgres psql -d postgres`.
- **Мета-команды psql:** начинаются с `\`; `\l` — список баз, `\c` — переподключение, `\dt` — список таблиц, `\d имя` — структура таблицы, `\q` — выход.
- **CREATE DATABASE** создаёт новую базу (нужны права суперпользователя или CREATEDB); по умолчанию используется шаблон `template1`.
- **Схема** — пространство имён внутри базы; по умолчанию используется `public`.
- **CREATE SCHEMA** создаёт схему; `SET search_path TO schema1, public` задаёт порядок поиска и схему по умолчанию для новых объектов.
- Для работы с книгой достаточно создать базу (например, `sqlbook`), при необходимости — схему и переключиться в неё через `search_path`.

В [§1.4](chapter-01-04.md) мы выполним первый SQL-запрос: `SELECT * FROM table`, разберём точку с запятой и регистр ключевых слов.
