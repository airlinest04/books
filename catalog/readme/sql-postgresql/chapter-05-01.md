# §5.1 ORDER BY

В [§4.5](chapter-04-05.md) мы рассмотрели self-join. Без указания сортировки порядок строк в результате не гарантирован — СУБД может вернуть их в любом порядке. Предложение **ORDER BY** задаёт порядок вывода. В этом разделе разберём синтаксис ORDER BY, направление сортировки (ASC, DESC), обработку NULL и сортировку по нескольким столбцам. Ограничение числа строк (LIMIT, OFFSET) — в [§5.2](chapter-05-02.md). См. [документацию SELECT](https://www.postgresql.org/docs/current/sql-select.html) и [сортировку строк](https://www.postgresql.org/docs/current/queries-order.html).

---

## 5.1.1. Зачем нужна сортировка

Реляционная модель не задаёт порядок строк — таблица это множество. При выполнении запроса PostgreSQL возвращает строки в порядке, удобном для выполнения (например, по физическому расположению или по индексу). Для предсказуемого отображения — «сначала новые заказы», «по алфавиту», «по убыванию цены» — нужно явно указать ORDER BY.

---

## 5.1.2. Базовый синтаксис

По [документации](https://www.postgresql.org/docs/current/sql-select.html#SQL-ORDERBY):

```sql
SELECT столбцы
FROM таблица
[WHERE ...]
ORDER BY выражение1 [ASC | DESC] [NULLS { FIRST | LAST }]
         [, выражение2 [ASC | DESC] [NULLS { FIRST | LAST }], ...];
```

Выражение может быть именем столбца, выражением (в том числе с функциями) или порядковым номером столбца в списке SELECT (1, 2, 3, ...).

Примеры:

```sql
SELECT id, name, price FROM products ORDER BY price;
SELECT id, name, created_at FROM orders ORDER BY created_at DESC;
SELECT id, name FROM users ORDER BY upper(name);
```

---

## 5.1.3. ASC и DESC

- **ASC** (ascending) — по возрастанию; меньшее раньше. Значение по умолчанию.
- **DESC** (descending) — по убыванию; большее раньше.

```sql
ORDER BY price ASC;    -- от дешёвых к дорогим
ORDER BY price DESC;   -- от дорогих к дешёвым
ORDER BY name ASC;     -- по алфавиту (A–Z)
ORDER BY name DESC;   -- обратный алфавит (Z–A)
```

---

## 5.1.4. Несколько столбцов

В ORDER BY можно указать несколько выражений через запятую. Сначала сортировка по первому; при равенстве — по второму и т.д.

```sql
SELECT id, category_id, name, price
FROM products
ORDER BY category_id, price DESC;
```

Сначала по `category_id`, затем внутри каждой категории — по убыванию цены.

Разные столбцы могут иметь разное направление:

```sql
ORDER BY status ASC, created_at DESC;
```

---

## 5.1.5. Порядковый номер столбца

Вместо имени столбца можно использовать его номер в списке SELECT (начиная с 1):

```sql
SELECT id, name, price FROM products ORDER BY 3 DESC;
```

Сортировка по третьему столбцу (`price`). Этот приём сокращает запрос, но при изменении списка SELECT может сломать логику. Имя столбца обычно надёжнее.

---

## 5.1.6. Выражения в ORDER BY

В ORDER BY допустимы не только столбцы, но и выражения:

```sql
SELECT id, name, price FROM products ORDER BY price * 1.2;
SELECT id, name FROM users ORDER BY length(name);
SELECT id, extract(month FROM created_at) AS month FROM orders ORDER BY month;
```

Можно ссылаться на псевдонимы из SELECT (как в последнем примере), если они вычисляются на этапе выборки.

---

## 5.1.7. NULL в сортировке

По умолчанию в PostgreSQL:

- При **ASC** — NULL считаются большими всех остальных значений и идут в конце (**NULLS LAST**).
- При **DESC** — NULL считаются меньшими всех и идут в начале (**NULLS FIRST**).

Чтобы изменить это поведение, укажите явно:

```sql
ORDER BY phone ASC NULLS FIRST;   -- NULL в начале при возрастании
ORDER BY phone DESC NULLS LAST;   -- NULL в конце при убывании
```

Пример — заказы по дате, неотправленные (shipped_at = NULL) в конце:

```sql
SELECT id, total, shipped_at
FROM orders
ORDER BY shipped_at ASC NULLS LAST;
```

---

## 5.1.8. Место ORDER BY в запросе

ORDER BY идёт после SELECT, FROM, WHERE, JOIN, GROUP BY, HAVING и до LIMIT/OFFSET. Оно применяется к **итоговому** набору строк (после фильтрации и группировки).

При использовании агрегатных функций и GROUP BY сортировать можно по столбцам из GROUP BY, по агрегатам или по выражениям на их основе (подробнее в гл. 7).

---

## 5.1.9. Порядок строк без ORDER BY

Без ORDER BY порядок не определён. Одинаковые запросы могут возвращать строки в разном порядке при изменении данных, индексов или плана. Для воспроизводимого результата всегда указывайте ORDER BY, когда важен порядок.

---

## 5.1.10. ORDER BY и производительность

Сортировка может быть дорогой при большом числе строк. Индекс по тем же столбцам в том же порядке (например, `CREATE INDEX ON t (a, b DESC)`) иногда позволяет избежать явной сортировки. Подробнее — в документации по индексам.

---

## 5.1.11. Типичные ошибки

- **Полагаться на порядок без ORDER BY** — для стабильного отображения ORDER BY обязателен.
- **Сортировка по невыбранному столбцу** — допустимо, но при использовании номера столбца легко ошибиться.
- **NULL в неожиданном месте** — при необходимости явно задавать NULLS FIRST или NULLS LAST.
- **Несколько столбцов без учёта приоритета** — первый столбец задаёт основной порядок, остальные — для равных значений.

---

## Ключевое

- **ORDER BY** задаёт порядок вывода строк; без него порядок не гарантирован.
- **ASC** — по возрастанию (по умолчанию), **DESC** — по убыванию.
- Несколько выражений через запятую: первое — основной критерий, следующие — для равных значений.
- Выражение может быть столбцом, номером столбца (1, 2, …) или выражением.
- **NULLS FIRST** / **NULLS LAST** — явное размещение NULL; по умолчанию при ASC — NULLS LAST, при DESC — NULLS FIRST.

В [§5.2](chapter-05-02.md) рассмотрим LIMIT и OFFSET — как ограничивать число строк и делать постраничную выборку.
