# §5.4 Catchup и backfill

В [§5.3](chapter-05-03.md) мы разобрали start_date и логическую дату run. Если DAG включают с задержкой или нужно «догнать» данные за прошлые периоды, используются **catchup** (автоматический догон при включении DAG) и **backfill** (ручной запуск за выбранные даты). В этом разделе — что такое catchup, зачем его отключать, и как выполнить backfill из UI или CLI. В конце главы 5 — выводы и задание. Практика создания дага загрузки — в [главе 6](chapter-06-01.md).

---

## 5.4.1. Catchup: автоматический запуск за пропущенные периоды

**Catchup** — булев параметр DAG (`catchup=True` или `catchup=False` в конструкторе `DAG()`). Он определяет, будет ли планировщик при включении DAG создавать run **за все пропущенные периоды** между **start_date** и текущим моментом.

- **catchup=True** (в части версий — значение по умолчанию): после включения DAG планировщик создаёт run за каждый период от start_date до «сейчас» по правилам schedule_interval. Например, при ежедневном расписании и start_date полгода назад может создаться десятки или сотни run подряд. Это удобно, когда нужно один раз заполнить историю данных; но при большом start_date и частом расписании нагрузка и очередь могут стать большими.
- **catchup=False**: планировщик создаёт run только **вперёд** — начиная со следующего момента по расписанию после включения DAG. За прошлые даты run не создаются автоматически.

Рекомендация для многих пайплайнов данных: задавать **catchup=False**, чтобы при первом включении или после долгой паузы не порождать массу старых run. Запуск за прошлое при необходимости делают вручную через backfill.

---

## 5.4.2. Как отключить catchup

В определении DAG укажите:

```python
with DAG(
    dag_id="daily_load",
    schedule_interval="0 2 * * *",
    start_date=datetime(2025, 1, 1),
    catchup=False,
) as dag:
    ...
```

Глобально по умолчанию можно задать в `airflow.cfg`: параметр `catchup_by_default` (если есть в вашей версии). Для отдельного DAG приоритет у параметра в коде.

## 5.4.3. Backfill: ручной запуск за прошлые даты

**Backfill** — ручной запуск DAG за выбранный диапазон логических дат (периодов). Используется, когда нужно «догнать» данные за период, когда DAG не работал, был отключён или после исправления кода перезапустить старые run. См. [Глоссарий](glossary.md).

**Из веб-интерфейса:**

1. Откройте DAG.
2. Запустите Trigger DAG (или аналог «Backfill» / «Run», если в UI есть выбор дат).
3. В диалоге запуска укажите **Logical date** или диапазон дат (start / end) для backfill. Конкретные поля зависят от версии Airflow (в 2.x может быть «Logical date» для одного run или параметры backfill в конфигурации).
4. Подтвердите. Планировщик создаст run за указанные даты (или один run с выбранной логической датой) и поставит задачи в очередь.

**Из CLI:**

```bash
# Запуск за период с start_date по end_date
airflow dags backfill -s 2025-02-01 -e 2025-02-14 dag_id

# Один run за конкретную логическую дату (в зависимости от версии)
airflow dags backfill -s 2025-02-14 dag_id
```

Флаги `-s` (start) и `-e` (end) задают диапазон; даты интерпретируются как логические даты run. Дополнительные опции: `--reset-dagruns` (сбросить состояние run перед повторным запуском), `--ignore-first-depends-on-past` и др. — см. справку `airflow dags backfill --help`.

---

## 5.4.4. Когда использовать backfill

- После длительного простоя DAG — «догнать» данные за пропущенные дни.
- После исправления логики — перезапустить run за затронутые даты (при идемпотентных задачах результат будет корректным).
- Для разовой загрузки исторических данных за период до start_date или за период, когда DAG ещё не существовал.

При backfill убедитесь, что задачи **идемпотентны** ([§2.3](chapter-02-03.md)): повторный запуск за ту же дату не должен портить данные (перезапись среза, upsert по ключу).

---

## 5.4.5. Типичные ошибки

- **Включить DAG с большим start_date и catchup=True** — планировщик создаст очень много run; при необходимости ограничьте период или используйте catchup=False и выборочный backfill.
- **Backfill без идемпотентности** — повторный backfill за те же даты может создать дубликаты; проектируйте задачи на перезапись среза или upsert.
- **Путать даты в backfill** — `-s` и `-e` задают логические даты (периоды), а не время суток; убедитесь, что диапазон соответствует нужным дням.

## Ключевое по главе 5 и задание

**Выводы главы 5:**

1. **Паттерны графа:** линейная цепочка (A >> B >> C), параллельные ветки (A >> [B, C]) и сведение ([B, C] >> D).
2. **schedule_interval:** cron (строка), timedelta или None; задаёт, как часто создаются DAG Run.
3. **start_date** и **логическая дата:** start_date — начало ряда периодов; логическая дата run — идентификатор периода данных; в задачах использовать контекст (`ds` и др.), не текущее время.
4. **Catchup** — при True планировщик создаёт run за пропущенные периоды; при False — только вперёд. **Backfill** — ручной запуск за выбранный диапазон дат (UI или CLI).

**Задание:**

- **DAG с расписанием и ветвлением.** Создайте DAG с schedule_interval (например, ежедневно) и start_date, с ветвлением (одна задача → две параллельные → сведение в одну). Установите catchup=False. Выполните Trigger DAG или backfill за одну дату и проверьте в Tree View, что задачи выполнились в ожидаемом порядке.
