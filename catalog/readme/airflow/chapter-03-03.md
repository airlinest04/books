# §3.3 Установка и первый запуск

В [§3.2](chapter-03-02.md) мы разобрали компоненты Airflow: Scheduler, Executor, метаданные в БД и веб-интерфейс. Чтобы увидеть систему в действии, нужно установить Airflow, инициализировать базу метаданных и запустить Web server и Scheduler. В этом разделе даны пошаговые команды для установки через pip, инициализации БД и первого запуска; указаны требования к среде (Python, ОС) и версиям. Каталог, откуда Airflow подхватывает DAG, разбирается в [§3.4](chapter-03-04.md).

---

## 3.3.1. Требования к среде

- **Python:** Airflow 2.x требует Python 3.8, 3.9, 3.10 или 3.11 (актуальный список совместимости см. в официальной документации Apache Airflow; для новых версий Airflow могут добавляться или исключаться версии Python).
- **ОС:** Linux и macOS типичны для разработки и продакшена; на Windows установка возможна, но официально не поддерживается (рекомендуется WSL2 или виртуальная машина).
- **Память и диск:** для локальной разработки достаточно 2–4 ГБ RAM и нескольких гигабайт свободного места; для продакшена требования зависят от числа DAG и задач.

Ниже команды приведены для **Linux/macOS** и **Python 3.10** (при другой версии Python замените на свою). Рекомендуется использовать виртуальное окружение (venv), чтобы не смешивать зависимости Airflow с системным Python.

---

## 3.3.2. Виртуальное окружение и установка пакета

Создайте каталог для проекта и виртуальное окружение:

```bash
# Среда: Linux/macOS, Python 3.10
python3.10 -m venv ~/airflow-env
source ~/airflow-env/bin/activate   # Linux/macOS
```

Установите Apache Airflow. Ограничение версии Python задаётся через переменную окружения (для Airflow 2.x и Python 3.10):

```bash
# Установка последней версии Airflow 2.x для текущей версии Python
pip install "apache-airflow>=2.0,<3"
```

Для фиксированной мажорной версии (например, 2.7):

```bash
pip install "apache-airflow==2.7.*"
```

Установка может занять несколько минут из‑за количества зависимостей. При конфликтах версий или ошибках сборки сверьтесь с документацией Airflow (Constraints и версии Python). После установки проверьте:

```bash
airflow version
```

Должны отобразиться версия Airflow и путь к конфигурации.

---

## 3.3.3. Переменные окружения перед первым запуском

Перед инициализацией БД задайте домашний каталог Airflow (где будут конфиг, логи и каталог DAG). По умолчанию Airflow использует `~/airflow`; можно оставить или задать свой:

```bash
# Опционально: свой каталог (иначе будет ~/airflow)
export AIRFLOW_HOME=~/airflow
mkdir -p "$AIRFLOW_HOME"
```

Для первой установки без внешней БД Airflow использует **SQLite** и **SequentialExecutor**: одна БД в файле, задачи выполняются по одной. Это подходит только для знакомства и отладки; для нормальной работы с параллельными задачами позже настраивают PostgreSQL/MySQL и LocalExecutor или CeleryExecutor (см. документацию).

---

## 3.3.4. Инициализация базы метаданных

Команда инициализации создаёт таблицы в БД метаданных (при SQLite — файл `airflow.db` в `AIRFLOW_HOME`):

```bash
airflow db init
```

После выполнения в `$AIRFLOW_HOME` появятся файл БД (если используется SQLite), конфигурационный файл `airflow.cfg` и каталог для DAG (по умолчанию `dags`). При необходимости создать учётную запись администратора для веб-интерфейса (Airflow 2.x):

```bash
airflow users create \
  --role Admin \
  --username admin \
  --email admin@example.com \
  --firstname Admin \
  --lastname User \
  --password admin
```

Пароль при вводе можно заменить на свой; в продакшене обязательно смените учётные данные и используйте надёжное хранение паролей.

---

## 3.3.5. Запуск Web server

В одном терминале запустите веб-сервер:

```bash
airflow webserver --port 8080
```

По умолчанию интерфейс будет доступен по адресу `http://localhost:8080`. Откройте его в браузере; при запросе логина введите созданного пользователя (например, `admin`) и пароль. Сначала список DAG может быть пустым или содержать только примеры — свои DAG вы добавите в каталог DAG (см. [§3.4](chapter-03-04.md)). Web server лишь отдаёт UI и читает данные из БД; сам он не планирует и не выполняет задачи.

---

## 3.3.6. Запуск Scheduler

В **втором** терминале активируйте то же виртуальное окружение и задайте `AIRFLOW_HOME` (если задавали ранее), затем запустите планировщик:

```bash
source ~/airflow-env/bin/activate
export AIRFLOW_HOME=~/airflow   # если задавали свой каталог
airflow scheduler
```

Scheduler начнёт сканировать каталог DAG, создавать DAG Run по расписанию и ставить готовые задачи в очередь. При SequentialExecutor задачи выполняются в процессе Scheduler по одной. Оставьте оба процесса (webserver и scheduler) запущенными; остановка — по Ctrl+C в соответствующих терминалах.

---

## 3.3.7. Проверка: первый DAG в интерфейсе

После запуска Scheduler подхватит DAG из каталога `$AIRFLOW_HOME/dags`. Если в каталоге есть примеры (например, `example_dag.py` в некоторых поставках), они появятся в списке DAG в UI. Можно включить один из примеров и нажать «Trigger DAG» для ручного запуска, затем открыть граф или логи задачи и убедиться, что задача выполнилась.

Создание своего первого DAG и размещение файлов в каталоге DAG — тема [§3.4](chapter-03-04.md) и [главы 4](chapter-04-01.md).

## 3.3.8. Типичные проблемы

- **`airflow: command not found`** — активируйте venv (`source ~/airflow-env/bin/activate`) или убедитесь, что `pip install` выполнен в том же окружении.
- **Ошибки при `db init`** — проверьте права на запись в `AIRFLOW_HOME` и наличие места на диске; при использовании внешней БД — корректность строки подключения в `airflow.cfg`.
- **DAG не появляются в UI** — убедитесь, что Scheduler запущен и каталог DAG указан верно (по умолчанию `$AIRFLOW_HOME/dags`); проверьте, что в файлах нет синтаксических ошибок (в UI отображаются ошибки парсинга).
- **Порт 8080 занят** — укажите другой: `airflow webserver --port 8081`.

---

## Ключевое

- **Установка:** виртуальное окружение (Python 3.8+), `pip install apache-airflow`; при необходимости фиксировать версию (например, `2.7.*`).
- **Первый запуск:** задать `AIRFLOW_HOME` (опционально), выполнить `airflow db init`, при необходимости создать пользователя `airflow users create`, затем в двух терминалах запустить `airflow webserver --port 8080` и `airflow scheduler`.
- По умолчанию используются SQLite и SequentialExecutor (только для знакомства); для параллельного выполнения задач настраивают внешнюю БД и LocalExecutor или CeleryExecutor.
- Каталог с DAG и то, как Airflow его подхватывает, — в [§3.4](chapter-03-04.md).

В [§3.4](chapter-03-04.md) разберём каталог DAG (DAGs folder): где Airflow ищет файлы с DAG и как обновляются определения пайплайнов.
