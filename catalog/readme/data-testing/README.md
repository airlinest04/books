# Тестирование данных и пайплайнов

Типы тестов для данных; тестирование SQL (unit-тесты, assertions); тестирование ETL (маппинг, полнота, идемпотентность); тестирование отчётов (регрессия, контрольные суммы); тестовые данные и фикстуры; интеграция с Airflow и ETL. Без облачных сервисов: фокус на SQL, ETL-инструментах серии и Airflow.

## Подробное содержание

### Глава 1. Риски без тестирования

* **1.1 Что ломается в пайплайнах данных** — изменение схемы источника; ошибки в маппинге; сбои при загрузке; регрессии после изменений.
* **1.2 Последствия ошибок в данных** — неверные отчёты; регуляторные риски; потери для бизнеса; доверие к данным.
* **1.3 Тестирование vs мониторинг качества** — тестирование: проверка корректности пайплайна, до релиза; качество: непрерывный мониторинг; связь с книгой по качеству данных.
* **1.4 Роль тестирования в CI/CD для данных** — тесты до деплоя; smoke-тесты после деплоя; связь с Airflow, ETL-инструментами.
* _Ключевое:_ риски, последствия, отличие от мониторинга качества. _Задания:_ перечислить риски для заданного пайплайна.

### Глава 2. Типы тестов для данных

* **2.1 Unit-тесты для SQL** — изолированная проверка запроса или преобразования; фиксированный вход, ожидаемый выход.
* **2.2 Интеграционные тесты для ETL** — проверка полного пайплайна; источник — ETL — приёмник; полнота, целостность.
* **2.3 Регрессионные тесты для отчётов** — контрольные суммы; эталонные значения; обнаружение изменений после модификаций.
* **2.4 Smoke-тесты и санитарные проверки** — быстрые проверки «пайплайн работает»; row count, ключевые агрегаты; после деплоя.
* _Ключевое:_ unit, интеграция, регрессия, smoke. _Задания:_ выбрать типы тестов для сценария.

### Глава 3. Тестовые данные

* **3.1 Фикстуры и эталонные наборы** — предопределённые данные; воспроизводимость; управление фикстурами.
* **3.2 Синтетические данные** — генерация данных; Faker и аналоги; покрытие граничных случаев.
* **3.3 Маскирование и анонимизация** — персональные данные в тестах; маскирование; связь с безопасностью.
* **3.4 Управление тестовыми средами** — отдельная БД для тестов; изоляция; сброс состояния.
* _Ключевое:_ фикстуры, синтетика, маскирование, среды. _Задания:_ подготовить фикстуры для теста.

### Глава 4. Unit-тесты для запросов

* **4.2 Структура теста: вход — ожидание — результат** — Arrange (подготовка данных); Act (выполнение); Assert (проверка); пример на SQL.

### Глава 5. Assertions и проверка результатов

* **5.1 Assertions: что проверять** — количество строк; значения полей; агрегаты; отсутствие дубликатов.

* **5.3 Референциальная целостность** — нет сирот (orphans); FK выполняются; проверки в SQL.
* **5.4 Бизнес-правила в SQL** — проверка правил; дебет = кредит; баланс; примеры.
* _Ключевое:_ assertions, row count, контрольные суммы, целостность. _Задания:_ сформулировать assertions для сценария.

* **8.2 Регрессионное тестирование отчётов** — эталонные значения; контрольные суммы; обнаружение изменений.
* **8.3 Контрольные эталоны и сверка** — где хранить эталоны; как обновлять; версионность.
* **8.4 Обнаружение регрессий** — сравнение с эталоном; алерты при расхождении; разбор причин.
