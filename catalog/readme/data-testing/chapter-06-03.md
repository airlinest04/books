# §6.3 Фильтрация и джойны

В [§6.2](chapter-06-02.md) мы разобрали тестирование агрегаций и расчётов. Два следующих элемента преобразований — **фильтрация** (WHERE, HAVING) и **джойны** (JOIN). Ошибка в условии отбора или в типе/ключе соединения меняет состав строк: лишние попадают в результат или нужные теряются. В этом разделе мы разберём, как тестировать фильтры и джойны: что проверять, как строить фикстуры для сохранения и исключения строк и как формулировать assertions.

---

## 6.3.1. Тест фильтра

**Фильтр** отбирает строки по условию (WHERE или HAVING). Тест фильтра проверяет: при заданном наборе строк в результате остаются только те, что удовлетворяют условию, и ни одна «правильная» строка не теряется, ни одна «неправильная» не попадает.

Что покрывать:

- **Строки, которые должны пройти:** фикстура содержит строки с значениями, удовлетворяющими условию (например, status = 'completed', amount > 0). Assertion: все они присутствуют в результате, количество строк в результате равно ожидаемому.
- **Строки, которые не должны пройти:** фикстура содержит строки с status = 'pending', amount = 0, status = NULL. Assertion: этих строк нет в результате.
- **Граница условия:** значения ровно на границе (amount = 0 при условии amount > 0; дата ровно на границе при date >= '2025-01-01'). Тест фиксирует, включена граница в выборку или нет, и проверяет соответствие ожиданию.

В §4.1 и §4.3 уже был пример теста фильтра (status = 'completed' AND amount > 0): фикстура с пятью строками, в результате две (order_id 1 и 4). Общая схема та же: Arrange — таблица с «проходящими» и «не проходящими» строками; Act — запрос с WHERE; Assert — состав результата (набор ключей или количество строк) совпадает с эталоном. При изменении условия (например, с `>` на `>=`) тест с граничным значением должен отреагировать: раньше amount=0 не проходил, после изменения — проходит, тест обновляют осознанно или фиксируют регрессию.

---

## 6.3.2. Тест джойна

**Джойн** связывает две (или более) таблицы по ключу. Тест джойна проверяет: тип соединения (INNER, LEFT, RIGHT, FULL), ключ соединения и дополнительные условия — в результате ожидаемый набор строк, без лишних дубликатов и без потери строк там, где они не должны теряться.

Что проверять:

- **Тип джойна:** при LEFT JOIN все строки левой таблицы должны остаться; для строк без пары в правой таблице поля правой заполняются NULL. Фикстура: в левой таблице строка с ключом, которого нет в правой. Assertion: в результате эта строка есть, поля из правой таблицы — NULL. Для INNER такой строки в результате быть не должно.
- **Ключ соединения:** соединение идёт по правильным полям; нет случайного совпадения по другому полю. Фикстура с известными парами ключей (левая и правая таблицы); assertion — состав пар и количество строк совпадают с эталоном.
- **Количество строк:** при связи «один к одному» число строк не меняется; при «один ко многим» — равно числу строк в «многих» для выбранной части левой таблицы. Тест с фикстурой 3 заказа и 5 позиций (у одного заказа две позиции) даёт ожидаемое число строк в результате и проверяет отсутствие дубликатов по ключу, если ожидается уникальность.

В §4.3 был пример теста LEFT JOIN (заказы и клиенты, заказ с customer_id без пары в customers). Идея: фикстура с «сиротой»; assertion — в результате 3 строки, у заказа 103 поле customer_name IS NULL. Для теста INNER JOIN та же фикстура дала бы 2 строки (заказ 103 выпал бы).

## 6.3.3. Сохранение и исключение строк

При тестировании фильтрации и джойнов явно фиксируют, **какие строки должны сохраниться** и **какие исключиться**.

**Фильтр (WHERE):**

- Сохраняются: строки, удовлетворяющие условию.
- Исключаются: строки, не удовлетворяющие условию (в т.ч. с NULL в проверяемой колонке, если условие не учитывает IS NULL явно).

Фикстура должна содержать и те и другие; тест проверяет состав результата (набор id или ключей) и при необходимости количество. Для составного условия (AND, OR) добавляют строки, покрывающие ветки: обе части AND истинны, одна ложна; для OR — обе ложны, одна истинна.

**LEFT JOIN:**

- Сохраняются: все строки левой таблицы; при отсутствии пары в правой — NULL в полях правой.
- Исключаются: ничего из левой не исключается (в отличие от INNER).

Тест с строкой левой таблицы без пары проверяет именно сохранение с NULL.

**INNER JOIN:**

- Сохраняются: только строки, для которых есть совпадение в обеих таблицах.
- Исключаются: строки левой без пары в правой (и правой без пары в левой).

Тест с «сиротой» в левой таблице проверяет, что эта строка в результате отсутствует.

**Цепочка джойнов и фильтров:** порядок (сначала джойн, потом фильтр по полю правой таблицы vs сначала фильтр по левой) может влиять на результат при LEFT JOIN: фильтр по полю правой таблицы (WHERE right.col = ...) превращает LEFT по сути в INNER для отфильтрованной части. Тест должен быть с фикстурой, где видно различие: например, строка левой без пары в правой; при фильтре «right.col = 'X'» она должна исчезнуть из результата (потому что right.col для неё NULL). Явная фикстура и ожидание «эта строка в результате есть/нет» предотвращают регрессию при изменении порядка условий.

В [§6.4](chapter-06-04.md) мы разберём граничные случаи и null: пустой вход, null в полях, граничные значения и деление на ноль в тестах преобразований.

---

## Ключевое

- **Тест фильтра:** фикстура с «проходящими» и «не проходящими» строками и при необходимости с граничными значениями; assertion — состав результата (набор ключей, количество строк) совпадает с эталоном. Изменение условия (>, >=, учёт NULL) должно отражаться в тесте.
- **Тест джойна:** проверка типа (LEFT сохраняет все слева, INNER — только совпадения), ключа соединения и количества строк; фикстура с «сиротой» для LEFT проверяет наличие строки с NULL в полях правой таблицы.
- **Сохранение/исключение:** явно фиксировать, какие строки должны остаться и какие исчезнуть; для составных условий и цепочек джойн+фильтр — фикстура, показывающая ожидаемое поведение на граничных случаях.

В [§6.4](chapter-06-04.md) мы разберём граничные случаи и null: пустой вход, null в полях, граничные значения и деление на ноль.
