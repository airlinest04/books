# §3.2 Синтетические данные

В [§3.1](chapter-03-01.md) мы разобрали фикстуры и эталонные наборы — предопределённые данные, хранящиеся в репозитории. Альтернатива и дополнение — **синтетические данные**: данные, сгенерированные программно для тестов, а не взятые из продовой среды и не набранные вручную в CSV. Вы узнаете, зачем генерировать данные, какие инструменты использовать (Faker и аналоги), как обеспечивать воспроизводимость при генерации и как покрывать граничные случаи.

---

## 3.2.1. Зачем генерировать синтетические данные

Синтетическая генерация полезна, когда:

**Нужен объём.** Для нагрузочного тестирования пайплайна или проверки запросов на больших таблицах фикстуры в виде готовых файлов становятся тяжёлыми (мегабайты, гигабайты). Генерация по правилам позволяет создать нужное количество строк «на лету» в тесте или один раз сгенерировать дамп с фиксированным seed и хранить его как артефакт.

**Нужны разнообразные сценарии.** Генератор может выдавать данные с заданным распределением: определённая доля null, дубликаты по ключу, даты в заданном диапазоне, комбинации полей под тест джойна или агрегации. Меняя параметры (seed, диапазоны), получаем разные наборы без ручного набора сотен строк.

**Нельзя использовать продовые данные.** Из соображений безопасности или из-за отсутствия доступа к проду тестовые данные создаём сами. Синтетика не содержит персональных и коммерческих данных и не требует маскирования (о маскировании продовых данных — в [§3.3](chapter-03-03.md)).

**Граничные случаи.** Генератор можно настроить на создание именно «сложных» комбинаций: пустой набор, одна строка, все значения null в колонке, максимальные/минимальные числа, невалидные коды для проверки обработки ошибок. Это дополняет ручные фикстуры, где такие случаи тоже можно описать, но генерация упрощает масштабирование (например, 1000 строк с 10% null в заданном поле).

Ограничение: синтетические данные не отражают реальные корреляции и аномалии продовой среды. Для проверки «как ведёт себя пайплайн на реальных распределениях» по-прежнему используют снимки продовых данных (с маскированием при необходимости) или эталонные выгрузки; синтетика — инструмент для воспроизводимых тестов с контролируемым входом.

## 3.2.2. Генерация данных: Faker и аналоги

**Faker** — популярная библиотека для генерации правдоподобных «фейковых» данных: имена, адреса, даты, телефоны, email, числа, строки. Доступна для Python (`Faker`), PHP, Java, Ruby и других языков. В тестах данных её используют, чтобы быстро заполнить таблицы или файлы значениями нужного типа без ручного придумывания.

Пример (Python 3.x, библиотека `Faker`):

```python
from faker import Faker
fake = Faker('ru_RU')  # локаль для русских имён, адресов

# Воспроизводимость: фиксированный seed
Faker.seed(42)

row = {
    'name': fake.name(),
    'email': fake.email(),
    'birth_date': fake.date_of_birth(minimum_age=18, maximum_age=80),
    'amount': fake.random_int(min=100, max=10000),
}
```

Для тестов важно задавать **seed** (зерно генератора случайных чисел), чтобы при одном и том же seed последовательность значений повторялась от прогона к прогону. Иначе тест перестаёт быть воспроизводимым.

**Аналоги и расширения:**

- **Python:** `mimesis` — альтернатива Faker с поддержкой локалей; `factory_boy` — фабрики моделей с Faker-провайдерами для ORM и тестовых объектов.
- **SQL:** в некоторых СУБД есть функции генерации (например, `generate_series` в PostgreSQL, `DBMS_RANDOM` в Oracle); для простых целей можно генерировать строки прямо в SQL-скрипте теста.
- **Специализированные генераторы:** для доменных сущностей (заказы, транзакции, события) пишут свой скрипт или используют шаблон: N записей с полями, заполненными по правилам (дата из диапазона, сумма с распределением, ссылки на сгенерированные справочники).

Выбор инструмента зависит от стека: если тесты на Python — Faker/mimesis удобны; если тесты в основном SQL — генерация в SQL или вызов скрипта генерации перед тестом. См. [Глоссарий](glossary.md).

## 3.2.3. Воспроизводимость при генерации

Чтобы тесты с синтетическими данными оставались воспроизводимыми:

1. **Фиксированный seed.** Перед генерацией устанавливать зерно генератора случайных чисел (в Faker — `Faker.seed(123)` или `fake = Faker(); fake.seed_instance(123)`). Один и тот же seed даёт одну и ту же последовательность.
2. **Версионирование кода генерации.** Скрипт или функция, которая генерирует данные, хранится в репозитории; изменение логики генерации (добавление полей, смена распределения) осознанно и видно в истории.
3. **Фиксация параметров.** Количество строк, диапазоны дат, доли null и т.д. задаются в конфиге теста или константами, а не «случайным числом от 1 до 1000» без seed.
4. **Опционально: сохранять сгенерированный дамп.** Для тяжёлых интеграционных тестов можно один раз сгенерировать данные с фиксированным seed, сохранить в CSV/SQL и использовать как фикстуру; тогда прогон теста не тратит время на генерацию и не зависит от версии библиотеки генератора (но дамп нужно пересоздавать при изменении схемы или правил).

Типичная ошибка — генерировать данные без seed: «каждый раз новые данные, тест проверяет общую логику». Такой тест нестабилен (при неудачной комбинации может упасть) и не ловит регрессии по конкретным значениям; для стабильных тестов генерация должна быть детерминированной.

## 3.2.4. Покрытие граничных случаев

Синтетическая генерация удобна для **граничных случаев** — сценариев, где логика может вести себя иначе: пустой вход, одно значение, предельные числа, null, дубликаты.

Примеры:

| Граничный случай | Как сгенерировать | Что проверяем |
|------------------|-------------------|---------------|
| Пустой набор | 0 строк в таблице или пустой файл. | Запрос не падает, возвращает 0 строк или пустой результат; агрегаты дают 0 или null по правилам СУБД. |
| Одна строка | Генерация 1 строки. | Корректность агрегации и формул при одной записи. |
| Все null в колонке | Генератор заполняет только ключевые поля, остальные null. | Обработка null в запросе (COALESCE, фильтр, джойн). |
| Минимум/максимум | Задать min/max для числовых полей, крайние даты. | Обработка границ (сравнения, партиционирование по дате). |
| Дубликаты по ключу | Сгенерировать несколько строк с одинаковым ключом. | Дедупликация, GROUP BY, выбор одной записи по правилу. |
| Длинные строки, спецсимволы | Генератор строк с заданной длиной или набором символов. | Ограничения длины, экранирование, кодировки. |

Генератор можно параметризовать: «создать N заказов, в M из них customer_id отсутствует в справочнике клиентов» — для теста обработки сирот; «создать заказы только за одну дату» — для теста партиционирования. Так синтетика дополняет ручные фикстуры: фикстуры задают точечные сценарии вручную, генерация — массовые и вариативные при сохранении воспроизводимости через seed. В [§3.3](chapter-03-03.md) мы разберём маскирование и анонимизацию персональных данных в тестах и связь с безопасностью.

---

## Ключевое

- **Синтетические данные** — данные, сгенерированные программно для тестов (объём, разнообразие, граничные случаи) без использования продовых данных; обеспечивают контроль над сценарием и независимость от продовой среды.
- **Faker** и аналоги (mimesis, factory_boy, SQL-генерация) позволяют генерировать правдоподобные значения по типам полей; для воспроизводимости обязателен **фиксированный seed** и версионирование кода генерации.
- Воспроизводимость: один и тот же seed и параметры дают один и тот же набор данных; при необходимости сгенерированный дамп сохраняют как фикстуру.
- **Граничные случаи** (пустой набор, одна строка, null, дубликаты, минимум/максимум, длинные строки) удобно покрывать параметризованной генерацией; синтетика дополняет ручные фикстуры и не заменяет проверки на реальных снимках продовых данных при необходимости.

В [§3.3](chapter-03-03.md) мы разберём маскирование и анонимизацию персональных данных в тестах и связь с безопасностью.
