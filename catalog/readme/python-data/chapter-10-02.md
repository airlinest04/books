# §10.2 Запросы и результат в DataFrame

В [§10.1](chapter-10-01.md) мы разобрали создание движка и вызов **pd.read_sql()**. В этом разделе — как формировать **SELECT**-запросы для read_sql, использовать **параметризованные запросы** (подстановка значений без риска SQL-инъекций) и кратко **записывать** DataFrame в таблицу БД с помощью **df.to_sql()**. В [§10.3](chapter-10-03.md) перейдём к HTTP-запросам (requests) и загрузке JSON в DataFrame.

---

## 10.2.1. SELECT в read_sql()

В **pd.read_sql(sql, con, ...)** аргумент **sql** — строка с любым допустимым в СУБД **SELECT**: выбор столбцов, WHERE, JOIN, GROUP BY, ORDER BY, LIMIT и т.д. Результат запроса целиком превращается в DataFrame: имена столбцов берутся из алиасов или имён колонок в результате, строки — строки выборки.

Для больших таблиц разумно ограничивать объём: **LIMIT n** (в PostgreSQL, SQLite, MySQL) или эквивалент в другой СУБД. Имена столбцов с пробелами или спецсимволами в DataFrame будут доступны через **df['имя столбца']**.

Первый аргумент может быть не только строкой, но и объектом **sqlalchemy.text()** — для корректной передачи параметров и переноса строк в запросе (см. ниже). Для простых запросов достаточно строки.

```python
import pandas as pd
from sqlalchemy import create_engine

engine = create_engine("sqlite:///example.db")
df = pd.read_sql("SELECT id, name, amount FROM orders WHERE amount > 0 ORDER BY id LIMIT 100", engine)
# df — столбцы id, name, amount
```

## 10.2.2. Параметризованные запросы

Подставлять значения в SQL через конкатенацию строк (**f"SELECT * FROM t WHERE id = {x}"**) **нельзя**: это уязвимо к **SQL-инъекциям**. Нужны **параметризованные запросы**: плейсхолдеры в тексте запроса и передача значений отдельно через **params**.

**pd.read_sql(sql, con, params=...)** принимает **params** — словарь или последовательность (кортеж, список). В **sql** вставляются плейсхолдеры; их вид зависит от драйвера. В **SQLAlchemy** с именованными параметрами используют имена вида **:name** в запросе и словарь **params={'name': value}**. Для **psycopg2** допустимы также **%(name)s** и передача словаря. Для позиционных параметров — **%s** в запросе и **params** как кортеж или список.

Рекомендуется оборачивать запрос в **sqlalchemy.text()**: **text("SELECT * FROM t WHERE id = :id")** — тогда параметры :id подставляются безопасно. Без text() поведение может отличаться в разных версиях SQLAlchemy и Pandas.

```python
from sqlalchemy import create_engine, text
import pandas as pd

engine = create_engine("sqlite:///example.db")
query = text("SELECT * FROM orders WHERE user_id = :uid AND status = :status")
df = pd.read_sql(query, engine, params={"uid": 42, "status": "active"})
```

Для дат и строк передают обычные объекты Python (datetime, str); драйвер преобразует их в тип БД.

## 10.2.3. Запись в таблицу: to_sql()

**df.to_sql(name, con, schema=None, if_exists='fail', index=True, method=None, ...)** записывает DataFrame в таблицу БД. **name** — имя таблицы (строка), **con** — движок или соединение SQLAlchemy.

- **if_exists** — поведение, если таблица уже есть: **'fail'** (по умолчанию) — ошибка, **'replace'** — удалить таблицу и создать заново, **'append'** — дописать строки в существующую таблицу. При append структура таблицы должна совпадать с столбцами DataFrame (типы и порядок).
- **index** — записывать ли индекс DataFrame как отдельный столбец; **index=False** — не записывать (часто так и делают).
- **method** — при необходимости задаёт способ вставки (например, по батчам); по умолчанию вставка по строкам или батчами в зависимости от драйвера.

Типы столбцов DataFrame маппятся на типы СУБД (INTEGER, REAL, TEXT, TIMESTAMP и т.д.); при несовпадении может потребоваться предварительное преобразование столбцов (.astype(), pd.to_datetime()). Для создания таблицы «с нуля» to_sql создаёт её по структуре DataFrame; для сложных схем (индексы, ограничения) таблицу лучше создавать отдельно (миграциями или DDL), а to_sql использовать с if_exists='append'.

```python
df.to_sql("results", engine, if_exists="replace", index=False)
# таблица results создана или перезаписана; строки df записаны
```

---

## Ключевое

- В **read_sql(sql, con)** передаётся любой SELECT; результат — DataFrame с столбцами и строками выборки. Ограничивайте объём (LIMIT) при больших таблицах.
- **Параметризованные запросы**: плейсхолдеры в SQL (например, **:name** в text()) и **params** — словарь значений. Не подставляйте значения через f-строки — это риск SQL-инъекций.
- **df.to_sql(name, con, if_exists=..., index=...)** — запись DataFrame в таблицу БД; **if_exists** — 'fail', 'replace', 'append'; **index=False** — не записывать индекс как столбец.
