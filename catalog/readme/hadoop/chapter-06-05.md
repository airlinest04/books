# §6.5 Партиционирование и bucketing в Hive

В [§6.4](chapter-06-04.md) мы разобрали DML: запросы и загрузку данных. Чтобы ускорить запросы с фильтром по одному или нескольким полям и упростить управление данными по времени или категориям, в Hive используют **партиционирование** — разбиение данных по значениям столбцов (например, по дате) в отдельные подкаталоги. **Bucketing** (бакетирование) — дополнительное разбиение данных внутри партиции (или в таблице без партиций) на фиксированное число файлов по хешу столбца; это выравнивает размер файлов и может ускорять JOIN и выборки. В этом разделе — как устроены партиции и бакеты, как в них загружать данные и как они ускоряют запросы. Следующая глава — [Pig](chapter-07-01.md): язык и среда для ETL. См. [Глоссарий](glossary.md).

---

## 6.5.1. Партиционирование по столбцу

**Партиционирование** в Hive — организация данных таблицы по **значениям одного или нескольких столбцов** (столбцов партиции). Физически каждому значению (или комбинации значений) соответствует **отдельный подкаталог** в каталоге таблицы; в метаданных (Metastore) хранится соответствие «партиция → путь». Столбцы партиции задаются в CREATE TABLE через **PARTITIONED BY** и не хранятся в теле файлов — они выводятся из пути (например, `dt=2024-01-15`). См. [Глоссарий](glossary.md).

Типичный случай — партиция по **дате** (день или месяц): данные за каждый день лежат в своём подкаталоге; запросы с условием `WHERE dt = '...'` читают только нужный подкаталог, не сканируя остальные данные (**partition pruning**). Это сокращает I/O и время выполнения.

Ограничения: не стоит делать партиций слишком много при малом объёме данных (например, партиция на каждую уникальную строку) — растёт число каталогов в Metastore и в HDFS, накладные расходы на планирование. Обычно партиционируют по полям с ограниченным числом значений и по которым часто фильтруют (дата, регион, тип).

## 6.5.2. Структура каталогов и partition pruning

Каталог таблицы в HDFS имеет вид:

```
/path/to/table/
  partition_col=value1/
    file1, file2, ...
  partition_col=value2/
    ...
```

При нескольких столбцах партиции вложенность: например, `dt=2024-01-15/region=eu/`. При выполнении запроса с **WHERE** по столбцу партиции Hive по метаданным определяет, какие подкаталоги соответствуют условию, и передаёт в план только их пути; неподходящие партиции не читаются. Это и есть **partition pruning** (отсечение партиций). См. [Глоссарий](glossary.md).

Чтобы pruning сработал, условие должно быть на столбце партиции и желательно допускать статическое определение партиций (например, `dt = '2024-01-15'` или `dt IN ('2024-01-15', '2024-01-16')`). Условия вида `dt > '2024-01-01'` также позволяют отсечь часть партиций, если движок и метаданные это поддерживают.

## 6.5.3. Загрузка данных в партиции

**Статическая партиция:** при INSERT или LOAD явно указывается значение партиции:

```sql
INSERT OVERWRITE TABLE events_part PARTITION (dt='2024-01-15')
SELECT id, user_id, event_type FROM events_staging WHERE dt = '2024-01-15';
```

```sql
LOAD DATA INPATH '/data/events/2024-01-15/' INTO TABLE events_part PARTITION (dt='2024-01-15');
```

**Динамическое партиционирование:** значение партиции берётся из столбца в SELECT. Включается настройкой `hive.exec.dynamic.partition = true`; при необходимости `hive.exec.dynamic.partition.mode = nonstrict` (если партиций много). В INSERT столбец партиции включается в SELECT, в PARTITION указывается только имя столбца без значения:

```sql
INSERT OVERWRITE TABLE events_part PARTITION (dt)
SELECT id, user_id, event_type, dt FROM events_staging;
```

Последний столбец в SELECT (здесь `dt`) сопоставляется со столбцом партиции. Hive создаёт подкаталоги по получающимся значениям и записывает туда данные.

**Внешние данные в каталогах:** если файлы уже положены в каталоги вида `dt=2024-01-15/` вручную или другим процессом, нужно зарегистрировать партиции в Metastore: `MSCK REPAIR TABLE events_part;` или `ALTER TABLE events_part ADD PARTITION (dt='2024-01-15') LOCATION '/path/to/events_part/dt=2024-01-15';`.

## 6.5.4. Bucketing (бакетирование)

**Bucketing** (бакетирование) — разбиение строк таблицы (или одной партиции) на **фиксированное число групп (бакетов)** по хешу от значения указанного столбца (или набора столбцов). Каждый бакет записывается в один или несколько файлов; при чтении с фильтром или JOIN по тому же столбцу Hive может обращаться только к нужным бакетам, что уменьшает объём сканируемых данных и может выравнивать нагрузку при JOIN. См. [Глоссарий](glossary.md).

В DDL задаётся так:

```sql
CREATE TABLE events_bucketed (
  id BIGINT,
  user_id INT,
  event_type STRING
)
PARTITIONED BY (dt STRING)
CLUSTERED BY (user_id) INTO 32 BUCKETS
STORED AS ORC;
```

- **CLUSTERED BY (столбец)** — столбец, по которому считается хеш; строки с одинаковым хешем попадают в один бакет.
- **INTO N BUCKETS** — число бакетов (обычно степень двойки). Данные при записи должны попадать в бакеты согласованно (запись через INSERT из другой таблицы с тем же CLUSTERED BY и числом бакетов, либо через задание `set hive.enforce.bucketing = true` при вставке из запроса).

Плюсы: выравнивание размера файлов при неравномерном распределении по партициям; ускорение JOIN по ключу бакетирования (одинаковые ключи в одном бакете — map-side join или меньше shuffle); удобная выборка по подмножеству бакетов (TABLESAMPLE). Минусы: нужно планировать число бакетов и писать данные через Hive, чтобы бакеты заполнялись корректно.

---

## 6.5.5. Когда использовать партиции и бакеты

**Партиционирование** — когда:
- часто фильтруют по одному полю (дата, регион);
- данные логически разделяются по времени или категории и загрузка идёт по частям (например, по дням);
- нужно ограничивать объём сканируемых данных (partition pruning).

**Бакетирование** — когда:
- важны равномерный размер файлов и предсказуемое число файлов в партиции;
- часты JOIN по одному и тому же столбцу (одинаковые ключи в одном бакете);
- нужна выборка по подмножеству данных (TABLESAMPLE BY bucket).

Часто комбинируют: партиция по дате + бакеты по ключу (user_id, id) внутри каждой партиции.

---

## Ключевое

- **Партиционирование** — разбиение по значениям столбца (столбцов) в подкаталоги; PARTITIONED BY в CREATE TABLE; **partition pruning** при WHERE по партиции сокращает I/O.
- Загрузка в партиции: **статическая** (PARTITION (col=value)), **динамическая** (PARTITION (col) и столбец в SELECT), **MSCK REPAIR** / ADD PARTITION для уже созданных каталогов.
- **Bucketing** — CLUSTERED BY (col) INTO N BUCKETS; разбиение по хешу; выравнивание файлов, ускорение JOIN по ключу бакетирования, TABLESAMPLE.
- Партиции по полям фильтрации (дата), при необходимости бакеты по ключу джойна.
