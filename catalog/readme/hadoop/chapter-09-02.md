# §9.2 Импорт из БД в HDFS

В [§9.1](chapter-09-01.md) мы разобрали назначение Sqoop и понятия импорта и экспорта. **Импорт** — выгрузка данных из реляционной БД в файлы в HDFS. В этом разделе — команда **sqoop import**, указание таблицы и условий (WHERE, запрос), **форматы вывода** (текст, Parquet) и **инкрементальный импорт** для регулярной подгрузки только новых или изменённых строк. Экспорт — в [§9.3](chapter-09-03.md); связь с Hive и Oozie — в [§9.4](chapter-09-04.md). См. [Глоссарий](glossary.md).

---

## 9.2.1. Базовая команда sqoop import

Импорт выполняется командой **sqoop import**. Обязательные параметры: **подключение к БД** и **источник данных** (таблица или запрос), а также **каталог вывода** в HDFS. См. [Глоссарий](glossary.md).

Пример:

```bash
sqoop import \
  --connect jdbc:mysql://dbhost:3306/mydb \
  --username user \
  --password pass \
  --table orders \
  --target-dir /data/import/orders \
  -m 4
```

- **--connect** — JDBC URL (хост, порт, имя базы; для MySQL, PostgreSQL, Oracle синтаксис различается).
- **--username**, **--password** — учётные данные (пароль можно передать через --password-file с путём к файлу в HDFS для безопасности).
- **--table** — имя таблицы для выгрузки целиком.
- **--target-dir** — каталог в HDFS, куда записываются файлы; каталог не должен существовать (Sqoop создаёт его), иначе ошибка.
- **-m** (или --num-mappers) — число мапперов (по умолчанию 4); каждый маппер выгружает свой срез и пишет свой файл (part-m-00000, part-m-00001 и т.д.).

Sqoop по метаданным БД определяет столбцы и типы; при импорте создаётся Java-класс (по умолчанию с именем таблицы), но для простого получения файлов в HDFS он не обязателен. Результат по умолчанию — текстовые файлы с запятыми в качестве разделителя полей.

## 9.2.2. Условия и произвольный запрос

Чтобы выгрузить не всю таблицу, а выборку по условию, используют **--where** или **--query**. См. [Глоссарий](glossary.md).

**--where** — условие SQL, подставляемое в запрос вида `SELECT * FROM table WHERE ...`. Пример:

```bash
sqoop import --connect ... --table orders --where "dt >= '2024-01-01'" --target-dir /data/orders_2024
```

**--query** — полный SQL-запрос. Обязательно указать **--split-by** (столбец, по которому разбивать выборку между мапперами) и условие **\$CONDITIONS** в WHERE: Sqoop подставит в него диапазоны для каждого маппера. Пример:

```bash
sqoop import --connect ... \
  --query "SELECT id, user_id, amount FROM orders WHERE dt >= '2024-01-01' AND \$CONDITIONS" \
  --split-by id \
  --target-dir /data/orders_2024 \
  -m 4
```

Без \$CONDITIONS Sqoop не сможет распараллелить запрос. **--split-by** задаёт столбец для разбиения (обычно числовой или дата); Sqoop вычисляет min/max и раздаёт мапперам диапазоны.

## 9.2.3. Форматы вывода: текст и Parquet

По умолчанию Sqoop пишет **текстовые файлы**: поля в одной строке, разделитель — запятая (можно задать **--fields-terminated-by**, **--lines-terminated-by**). Формат удобен для просмотра и совместим с Hive (CREATE TABLE с ROW FORMAT DELIMITED). См. [Глоссарий](glossary.md).

Для аналитических сценариев часто используют **Parquet** ([§5.3](chapter-05-03.md)): колоночное хранение, сжатие, предикат pushdown в Hive/Spark. Импорт в Parquet задаётся опцией **--as-parquetfile** (в Sqoop 1.x может потребоваться отдельный паркет-коннектор):

```bash
sqoop import --connect ... --table orders --target-dir /data/orders_parquet --as-parquetfile
```

В зависимости от версии Sqoop доступны и другие форматы (например, SequenceFile). Выбор формата влияет на дальнейшее использование в Hive (STORED AS PARQUET и т.д.) и на объём места в HDFS.

## 9.2.4. Инкрементальный импорт

При регулярной выгрузке одной и той же таблицы полный импорт каждый раз неэффективен. **Инкрементальный импорт** выгружает только **новые** или **изменённые** строки, опираясь на значение столбца (например, первичный ключ или дата изменения). См. [Глоссарий](glossary.md).

Два режима:

**append** — добавление строк с значением столбца **больше** сохранённого ранее. Подходит для монотонно растущего ключа (id, дата добавления). Параметры:

- **--incremental append**
- **--check-column** — столбец, по которому определять «новизну» (например, id).
- **--last-value** — последнее обработанное значение; при следующем запуске Sqoop выгрузит только строки где check-column > last-value и обновит сохранённое значение (в каталоге на кластере или в metastore).

Пример (ежедневный импорт по id):

```bash
sqoop import --connect ... --table orders --target-dir /data/orders_incr \
  --incremental append --check-column id --last-value 100000
```

При следующем запуске в --last-value подставляют максимальный id из предыдущей выгрузки (вручную или из скрипта/Oozie).

**lastmodified** — выгрузка строк, у которых столбец **даты изменения** (timestamp) больше сохранённого. Подходит для таблиц с updated_at. Параметры: **--incremental lastmodified**, **--check-column** (столбец даты), **--last-value** (последняя дата). Sqoop может объединять результаты в один каталог (merge) или писать в новый подкаталог при каждом запуске.

Инкрементальный импорт часто комбинируют с Oozie: coordinator по расписанию запускает Sqoop с обновлённым --last-value (значение берётся из предыдущего run или из файла в HDFS).

## 9.2.5. Разделение по мапперам (split-by)

Параллелизм импорта возможен, только если Sqoop может разбить выборку на части. По умолчанию Sqoop использует **первичный ключ** таблицы для разбиения: вычисляет min и max, делит диапазон между мапперами. Если первичного ключа нет или нужен другой столбец, задаётся **--split-by** (например, --split-by id). Для запроса с --query --split-by обязателен. См. [Глоссарий](glossary.md).

Не все типы столбцов подходят для split: предпочтительны числовые и даты. При --query с JOIN разбиение возможно по столбцу одной из таблиц; нужно следить, чтобы условие \$CONDITIONS корректно ограничивало выборку по этому столбцу.

---

## Ключевое

- **sqoop import** — импорт из БД в HDFS: --connect, --table (или --query), --target-dir, -m (число мапперов).
- **Условия:** --where для простого фильтра; --query с \$CONDITIONS и --split-by для произвольного запроса и параллелизма.
- **Форматы:** по умолчанию текст (разделители полей/строк); --as-parquetfile для Parquet.
- **Инкрементальный импорт:** --incremental append (по растущему столбцу) или lastmodified (по дате изменения); --check-column, --last-value; при регулярных запусках last-value обновляется.
