# §3.1 Идея MapReduce

В [главе 2](chapter-02-01.md) мы разобрали HDFS — распределённое хранилище данных в Hadoop. Данные лежат в HDFS блоками на многих узлах; чтобы их обрабатывать параллельно на кластере, нужна **модель вычислений**, которая определяет, как разбить работу по узлам и как объединить результаты. **MapReduce** — именно такая модель: задача формулируется в виде двух этапов — **Map** (обработка частей данных с выдачей пар ключ–значение) и **Reduce** (агрегация по ключу). В этом разделе мы вводим **идею MapReduce** без привязки к коду: что делают этапы Map и Reduce, зачем нужны пары ключ–значение и как за счёт параллельного выполнения многих Map- и Reduce-задач достигается масштабирование. Детали выполнения (сплиты, shuffle, sort) — в [§3.2](chapter-03-02.md); написание программы и пример WordCount — в [§3.3](chapter-03-03.md) и [§3.4](chapter-03-04.md). См. [Глоссарий](glossary.md).

---

## 3.1.1. Модель: два этапа — Map и Reduce

**MapReduce** — модель программирования (и одновременно реализация в Hadoop) для **массово параллельной обработки** больших объёмов данных. Вычисление разбивается на два последовательных этапа. См. [Глоссарий](glossary.md).

- **Этап Map (маппинг):** каждая **Map-задача** получает свою **порцию входных данных** (например, один блок файла в HDFS или один файл). Она обрабатывает эту порцию и выдаёт набор **пар (ключ, значение)**. Разные Map-задачи работают **независимо** и **параллельно** над разными порциями; между ними нет обмена данными.
- **Этап Reduce (редукция):** все пары с **одинаковым ключом** собираются вместе (это делает фреймворк) и передаются одной **Reduce-задаче**. Reduce-задача получает ключ и список всех значений по этому ключу и выдаёт результат агрегации (например, сумму, список, одну запись). Разные Reduce-задачи обрабатывают разные ключи и выполняются **параллельно**.

Между Map и Reduce фреймворк выполняет **shuffle and sort**: передаёт пары с Map-узлов на Reduce-узлы и группирует по ключу (часто с сортировкой по ключу). Пользователь программирует только логику Map и Reduce; разбиение данных, планирование задач, передачу и группировку обеспечивает система. Таким образом, модель MapReduce даёт **простую абстракцию** (два этапа, ключ–значение) и **автоматическое масштабирование**: при росте объёма данных добавляются Map- и Reduce-задачи на узлах кластера.

---

## 3.1.2. Этап Map: порция на входе, пары (ключ, значение) на выходе

**Map** — первый этап. Вход Map-задачи — **одна порция** входных данных (сплит): например, содержимое одного блока файла в HDFS или один файл. Задача читает эту порцию (строки, записи, байты) и для каждой логической единицы (строка, запись) применяет пользовательскую функцию **map**: она выдаёт ноль, одну или несколько пар **(ключ, значение)**. См. [Глоссарий](glossary.md).

Примеры (схематично):

- **Подсчёт слов (WordCount):** вход — текст; для каждого слова в строке Map выдаёт пару (слово, 1). Ключ — слово, значение — единица (счётчик).
- **Обработка логов:** вход — строки лога; Map выделяет поле (например, id пользователя) и выдаёт (id, строка_лога). Дальше Reduce может группировать все строки по id.
- **Фильтрация:** Map читает записи и выдаёт пару только для тех, что прошли условие (остальные отбрасываются). Ключ может быть сам объект или его часть.

Важно: **одна Map-задача не знает о других**. Она обрабатывает только свою порцию и пишет свои пары (ключ, значение). Масштабирование по данным достигается тем, что порций много — по одной на блок или файл — и каждая обрабатывается отдельной Map-задачей на узле кластера (желательно на том, где лежат данные). Подробнее разбиение на сплиты и размещение Map-задач — в [§3.2](chapter-03-02.md).

---

## 3.1.3. Этап Reduce: агрегация по ключу

**Reduce** — второй этап. На вход Reduce-задачи приходят **все пары с одним и тем же ключом**: фреймворк собрал вывод всех Map-задач, сгруппировал по ключу и передал каждый ключ (и список его значений) одной Reduce-задаче. Reduce-задача применяет пользовательскую функцию **reduce**: она получает ключ и итератор по значениям и выдаёт результат — обычно одну или несколько пар (ключ, результат_агрегации), которые записываются в выход HDFS. См. [Глоссарий](glossary.md).

Примеры:

- **WordCount:** для ключа «слово» приходят значения [1, 1, 1, …]. Reduce суммирует их и выдаёт (слово, сумма). Итог — количество вхождений слова.
- **Группировка по id:** ключ — id пользователя, значения — строки логов. Reduce может выдать (id, объединённый_лог) или (id, количество_событий).
- **Максимум/минимум по ключу:** значения — числа; Reduce находит максимум и выдаёт (ключ, max).

Количество Reduce-задач задаётся отдельно (например, по числу ключей или фиксированно). Все пары с ключом K попадают в **одну** Reduce-задачу — так гарантируется, что агрегация по ключу корректна. Разные ключи обрабатываются разными Reduce-задачами **параллельно**. Выход MapReduce job — набор файлов в HDFS (по одному на Reduce-задачу или по партиции), содержащих пары (ключ, результат).

---

## 3.1.4. Роль пар ключ–значение

Вся передача данных между этапами и внутри этапа идёт в виде **пар (ключ, значение)**. Ключ определяет:

- **Куда попадёт запись на этапе Reduce:** все записи с одним ключом обрабатываются одной Reduce-задачей. Выбор ключа — это выбор «по какому полю группировать и агрегировать».
- **Порядок и локальность:** фреймворк часто сортирует пары по ключу перед передачей в Reduce; это позволяет эффективно группировать и поддерживать порядок по ключу при обходе значений.

Ключи и значения могут быть простыми типами (строка, число) или составными (объекты, кортежи); в Hadoop они сериализуются (например, через Writable). От выбора ключа зависит и распределение нагрузки: если один ключ имеет очень много значений, одна Reduce-задача будет перегружена («скудный» ключ); при равномерном распределении ключей нагрузка между Reduce-задачами балансируется. См. [Глоссарий](glossary.md).

---

## 3.1.5. Масштабирование за счёт параллельных Map и Reduce

Сила модели MapReduce — **масштабирование по данным и по кластеру** без явного программирования параллелизма. См. [Глоссарий](glossary.md).

- **Параллелизм Map:** входные данные (файлы в HDFS) разбиваются на **сплиты** (часто сплит = один блок). Для каждого сплита запускается одна Map-задача. Чем больше данных и блоков, тем больше Map-задач; они могут выполняться на разных узлах одновременно. Ограничение — число блоков и ресурсы кластера (YARN выделяет контейнеры под задачи).
- **Параллелизм Reduce:** количество Reduce-задач задаётся при запуске job (например, 10, 100). Ключи распределяются по этим задачам (обычно по хешу ключа). Чем больше Reduce-задач, тем мельче гранулярность и тем больше параллелизма; но слишком много Reduce ведёт к большому числу выходных файлов и накладным расходам на shuffle.

Итого: при росте объёма данных можно добавлять узлы в кластер — появятся новые блоки в HDFS, появятся новые Map-задачи; время выполнения растёт не линейно с данными, а сглаживается за счёт параллелизма. Модель «Map + группировка по ключу + Reduce» естественно ложится на распределённое выполнение: Map читает локальные данные, shuffle доставляет пары по ключам, Reduce пишет результат в HDFS.

## 3.1.6. Типичные сценарии, подходящие под MapReduce

Модель MapReduce хорошо подходит для задач, которые можно выразить как:

- **Агрегация по ключу:** подсчёт, сумма, максимум, минимум, группировка (например, количество кликов по пользователю, сумма продаж по региону). Map выдаёт (ключ, частичное_значение), Reduce объединяет по ключу.
- **Фильтрация и преобразование с группировкой:** отбор записей по условию, извлечение полей; затем группировка или агрегация по ключу на этапе Reduce.
- **Join-подобные операции:** при правильном выборе ключа (например, id) Map подготавливает пары (id, запись), Reduce получает все записи с одним id и может «склеить» данные из разных источников (при предварительной маркировке источника).

Задачи, плохо укладывающиеся в один проход Map–Reduce: многошаговые итеративные алгоритмы (каждая итерация — отдельный job с записью в HDFS и чтением заново), интерактивные запросы с низкой латентностью. Ограничения модели разобраны в [§3.5](chapter-03-05.md).

## 3.1.7. Сводка: от данных к результату через Map и Reduce

| Этап | Вход | Действие | Выход |
|------|------|----------|--------|
| **Map** | Одна порция (сплит) входных данных | Пользовательская функция map: для каждой единицы данных выдаёт пары (ключ, значение) | Множество пар (ключ, значение) |
| **Shuffle/Sort** | Вывод всех Map-задач | Передача пар на узлы Reduce, группировка по ключу (и сортировка) | Для каждого ключа — один поток (ключ, список значений) |
| **Reduce** | Ключ + итератор по значениям | Пользовательская функция reduce: агрегирует значения по ключу | Одна или несколько пар (ключ, результат), запись в HDFS |

Пользователь задаёт только функции map и reduce; разбиение на сплиты, планирование задач, shuffle, sort и запись результата обеспечивает фреймворк MapReduce в Hadoop.

## 3.1.8. Типичные ошибки при понимании идеи MapReduce

- **Путать Map и Reduce по смыслу:** Map обрабатывает **каждую порцию данных** и выдаёт пары; Reduce получает **все значения по одному ключу** и агрегирует. Map не «знает» о других ключах; Reduce не читает сырые входные данные, только сгруппированный вывод Map.
- **Считать, что ключ не важен:** ключ определяет, какая Reduce-задача обработает запись и как данные сгруппируются. Неверный выбор ключа (например, константа для всех) приводит к тому, что вся нагрузка падает на одну Reduce-задачу.
- **Ожидать произвольного порядка значений в Reduce:** порядок значений по одному ключу может быть определён сортировкой по ключу (и по вспомогательному полю, если задано); не стоит полагаться на «случайный» порядок без явной настройки.
- **Думать, что MapReduce — единственный способ обработки в Hadoop:** поверх HDFS и YARN работают и Hive, и Pig, и Spark; MapReduce — одна из моделей, подходящая для пакетной агрегации по ключу.

---

## Ключевое

- **MapReduce** — модель из двух этапов: **Map** (обработка порции данных, вывод пар ключ–значение) и **Reduce** (агрегация по ключу; все значения с одним ключом обрабатываются одной Reduce-задачей).
- **Map** обрабатывает сплиты независимо и параллельно; **Reduce** получает сгруппированные по ключу данные и пишет результат в HDFS.
- **Пара (ключ, значение)** — единица обмена между этапами; ключ определяет группировку и распределение по Reduce-задачам.
- **Масштабирование:** много Map-задач по числу сплитов/блоков, много Reduce-задач по выбору пользователя; параллельное выполнение на кластере сокращает время при росте данных.

В [§3.2](chapter-03-02.md) мы разберём этапы выполнения job в Hadoop: как вход разбивается на сплиты, как работает shuffle and sort и как результат записывается в HDFS.
