## Подробное содержание

### Глава 1. Введение в большие данные и экосистему Hadoop

* **1.1 Большие данные: объём, скорость, разнообразие** — характеристики; почему одной машины недостаточно; масштабирование «по горизонтали».
* **1.2 Apache Hadoop** — открытый фреймворк для распределённого хранения и обработки; основные компоненты: HDFS, MapReduce, YARN; краткая история.
* **1.3 Экосистема Hadoop** — Hive, Pig, HBase, Oozie, Sqoop и др.; как они опираются на HDFS и YARN; роль ZooKeeper (координация сервисов) — кратко.
* **1.4 Когда уместен Hadoop** — пакетная обработка больших объёмов; альтернативы (Spark, облачные сервисы) — кратко.
* _Ключевое:_ что такое Hadoop, компоненты, экосистема. _Задания:_ сопоставить задачу и компонент экосистемы.

***

### Глава 2. HDFS: распределённая файловая система

* **2.1 Назначение HDFS** — хранение очень больших файлов; потоковое чтение; «write once, read many»; отказоустойчивость через репликацию.
* **2.2 Архитектура** — NameNode (метаданные, структура каталогов) и DataNode (блоки данных); один активный NameNode; блоки (типичный размер 128–256 MB).
* **2.3 Репликация** — фактор репликации; размещение реплик (разные стойки/узлы); чтение от ближайшей копии.
* **2.4 Команды и API** — hdfs dfs (или hadoop fs): ls, put, get, mkdir, rm; создание директорий и загрузка файлов; просмотр содержимого.
* **2.5 Ограничения HDFS** — не подходит для малых файлов, случайного доступа, множественных записей в один файл; латентность.
* _Ключевое:_ NameNode, DataNode, блоки, репликация, основные команды. _Задания:_ загрузить файлы в HDFS, проверить репликацию.

***

### Глава 3. MapReduce: модель и реализация

* **3.1 Идея MapReduce** — разделение работы на этапы Map (обработка пар ключ–значение) и Reduce (агрегация по ключу); масштабирование за счёт параллельных Map и Reduce.
* **3.2 Этапы выполнения** — входные данные разбиваются на сплиты; Map-задачи обрабатывают сплиты; shuffle and sort по ключу; Reduce-задачи агрегируют; вывод в HDFS.
* **3.3 Программа MapReduce** — класс Mapper (map), класс Reducer (reduce); конфигурация Job; запуск через hadoop jar.
* **3.4 Пример: подсчёт слов (WordCount)** — Map выдаёт (слово, 1); Reduce суммирует по слову; разбор кода и запуска.
* **3.5 Ограничения модели** — итеративные алгоритмы, интерактивные запросы; латентность и накладные расходы; связь с появлением Spark.
* _Ключевое:_ Map, Reduce, shuffle, пример WordCount. _Задания:_ написать простой MapReduce (например, подсчёт по полю).

***

### Глава 4. YARN: управление ресурсами и приложениями

* **4.1 Зачем YARN** — отделение управления ресурсами кластера от модели вычислений (MapReduce); один кластер для MapReduce, Spark и других фреймворков.
* **4.2 Компоненты** — ResourceManager (глобальный планировщик); NodeManager на каждом узле (контейнеры, ресурсы); ApplicationMaster для каждого приложения (например, для MapReduce job).
* **4.3 Контейнеры и ресурсы** — контейнер как единица ресурсов (память, CPU); запрос контейнеров приложением; планирование (FIFO, Capacity, Fair — кратко).
* **4.4 Запуск приложения** — как MapReduce или Spark запрашивают контейнеры через YARN; просмотр приложений в UI ResourceManager.
* _Ключевое:_ ResourceManager, NodeManager, контейнер, роль YARN. _Задания:_ запустить MapReduce job и посмотреть в YARN UI.

***

### Глава 5. Форматы хранения данных в экосистеме Hadoop

* **5.1 Текстовые форматы** — CSV, JSON; плюсы (читаемость) и минусы (нет схемы, неэффективное сжатие и разбиение).
* **5.2 SequenceFile** — бинарный формат для пар ключ–значение; поддержка сжатия; использование в MapReduce.
* **5.3 Columnar и сжатие** — Parquet, ORC: колоночное хранение, сжатие, предикат pushdown; когда использовать для аналитики.
* **5.4 Выбор формата** — по типу доступа (полный скан vs выборка столбцов), по инструментам (Hive, Spark).
* _Ключевое:_ текстовые форматы, Parquet/ORC, критерии выбора. _Задания:_ записать и прочитать данные в Parquet (через Hive или Spark).

***

### Глава 6. Hive: SQL поверх Hadoop

* **6.1 Назначение Hive** — SQL-подобный интерфейс к данным в HDFS; преобразование запросов в MapReduce/Tez/Spark jobs.
* **6.2 Метаданные** — Hive Metastore (таблицы, схемы, расположение данных); внутренние и внешние таблицы.
* **6.3 DDL** — CREATE TABLE; указание формата (TEXTFILE, PARQUET, ORC), разделов (PARTITIONED BY), расположения (LOCATION).
* **6.4 DML** — SELECT, JOIN, агрегация; загрузка данных LOAD и INSERT OVERWRITE; запросы и их выполнение (просмотр плана, логи).
* **6.5 Партиционирование и bucketing** — партиции по столбцу (например, по дате); бакеты для равномерного распределения; ускорение запросов.
* _Ключевое:_ Hive как SQL-слой, метаданные, форматы, партиции. _Задания:_ создать таблицу, загрузить данные, выполнить запросы.

***

### Глава 7. Pig: язык и среда для ETL

* **7.1 Зачем Pig** — процедурный язык поверх Hadoop (Pig Latin); цепочка преобразований для ETL; меньше кода, чем MapReduce.
* **7.2 Основные конструкции** — LOAD, FILTER, FOREACH, GROUP, JOIN, ORDER BY, STORE; типы данных (скаляры, кортежи, баги).
* **7.3 Выполнение** — локальный и распределённый режим; преобразование в MapReduce под капотом.
* **7.4 Пример пайплайна** — загрузка логов, фильтрация, группировка, сохранение; сравнение с эквивалентным Hive или MapReduce.
* _Ключевое:_ Pig Latin, LOAD/FILTER/GROUP/JOIN/STORE. _Задания:_ написать скрипт Pig для простого ETL.

***

### Глава 8. Oozie: оркестрация рабочих процессов

* **8.1 Назначение Oozie** — планировщик и оркестратор jobs в экосистеме Hadoop; workflow (последовательность и ветвления), coordinator (расписание), bundle (набор координаторов).
* **8.2 Workflow** — XML-описание; действия (actions): MapReduce, Hive, Pig, Shell, Java и др.; переходы по условиям (decision).
* **8.3 Coordinator** — запуск workflow по расписанию (cron) или по появлению данных; параметризация по дате.
* **8.4 Запуск и мониторинг** — отправка workflow/coordinator; веб-интерфейс Oozie; сравнение с Airflow (кратко).
* _Ключевое:_ workflow, coordinator, действия. _Задания:_ описать и запустить простой workflow (MapReduce или Hive action).

#### Глава 9. Sqoop: перенос данных между БД и HDFS

* **9.1 Назначение Sqoop** — перенос данных между реляционными СУБД и HDFS; импорт и экспорт; место в ETL-пайплайнах.
* **9.2 Импорт из БД в HDFS** — sqoop import; указание таблицы и условий; форматы (текст, Parquet); инкрементальный импорт.
* **9.3 Экспорт из HDFS в БД** — sqoop export; загрузка результатов обработки в таблицу целевой БД.
* **9.4 Связь с Hive и Oozie** — импорт в таблицу Hive; использование Sqoop в Oozie workflow.
* _Ключевое:_ import, export, инкремент. _Задания:_ выполнить импорт таблицы из БД в HDFS и при необходимости в Hive.
