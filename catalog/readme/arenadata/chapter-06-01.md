# §6.1 Arenadata DB Backup Manager

В [§5.4](chapter-05-04.md) мы завершили главу о миграции: верификацию, сравнение запросов и план отката. Глава 6 посвящена **резервному копированию и восстановлению** кластера Arenadata DB в эксплуатации. В этом разделе — **Arenadata DB Backup Manager (ADBM)**: назначение системы (бинарные бэкапы, PITR, restore points), **соотношение с gpbackup** (логические бэкапы) и **интерфейс управления** (вход, основные разделы, типовой цикл работы). Детальная архитектура ADBM и типы бэкапов разобраны в [§2.3](chapter-02-03.md); настройка расписаний, полный и инкрементальный бэкап и восстановление — в [§6.2](chapter-06-02.md)–[§6.4](chapter-06-04.md). См. [Глоссарий](glossary.md).

## 6.1.1. Назначение ADBM

**Arenadata DB Backup Manager (ADBM)** — система управления **бинарными** резервными копиями кластера Arenadata DB. По [документации ADBM](https://docs.arenadata.io/ru/ADB/current/tutorials/adbm/overview.html) она построена на **pgbackrest** и обеспечивает:

- формирование полных, дифференциальных и инкрементных бэкапов по расписанию и вручную;
- архивирование WAL и восстановление на произвольный момент времени (**PITR** — point-in-time recovery);
- создание **именованных точек восстановления (restore point)** и восстановление кластера или выбранных таблиц на выбранную точку;
- хранение бэкапов и архива WAL в Posix- и S3-совместимых хранилищах;
- поддержку нескольких кластеров ADB (в том числе с standby и зеркалированием), ведение истории бэкапов и действий, верификацию и очистку по политикам.

ADBM решает задачу **операционного** резервного копирования: быстрый откат при сбоях, восстановление на заданный момент (restore point или произвольный момент в пределах WAL), выборочное восстановление таблиц (Partial restore). Она входит в состав **ADB Enterprise** и устанавливается только в режиме **offline** (при офлайн-установке кластера через ADCM). Подробнее архитектура (Backup Manager, агенты, Service Registry, PostgreSQL) и типы бэкапов описаны в [§2.3](chapter-02-03.md).

## 6.1.2. Интеграция с gpbackup

**ADBM** и **gpbackup/gprestore** — разные инструменты, которые **дополняют** друг друга в одной инфраструктуре ADB.

| Аспект | ADBM | gpbackup / gprestore |
|--------|------|----------------------|
| Тип копии | Бинарный (на базе pgbackrest) | Логический (метаданные + данные в формате дампа) |
| Назначение | PITR, восстановление на restore point, операционная страховка | Выборочный бэкап схем/таблиц, перенос между кластерами, миграция |
| Гранулярность восстановления | Кластер или выборочные таблицы на момент restore point | База, схема, таблица по выбору |
| Расписание и UI | Управление через ADBM (расписания, хранилища, действия в веб-интерфейсе) | Запуск вручную или через свои скрипты/cron |

**Интеграция** в смысле «одна система» между ADBM и gpbackup нет: ADBM не запускает gpbackup и не подменяет его. Оба подхода используются параллельно: ADBM — для регулярных бинарных бэкапов и восстановления на точку во времени; gpbackup/gprestore — когда нужен выборочный логический бэкап или перенос данных в другой кластер (см. [§5.3](chapter-05-03.md), [§2.4](chapter-02-04.md)). В документации ADBM может упоминаться CLI или сценарии для логических бэкапов; фактическое выполнение логических бэкапов остаётся за утилитами gpbackup/gprestore и скриптами заказчика.

## 6.1.3. Интерфейс управления

**Доступ к ADBM:** пользовательский интерфейс ADBM **встроен в веб-интерфейс ADB Control**. После входа в ADB Control в левом меню выбирают пункт **Backup manager**. Подключение к сервису ADBM выполняется через хост и порт ADB Control (порт по умолчанию для ADBM — 81; задаётся при конфигурировании сервиса ADB Control). Доступ к странице Backup manager имеют пользователи с ролями **Administrator**, **ADBM Administrator** или **Owner**. Подробнее — в [документации по подключению к ADBM](https://docs.arenadata.io/ru/ADB/current/tutorials/adbm/connect.html).

**Основные разделы интерфейса:**

- **Clusters** — список кластеров ADB, подключённых к ADBM; для каждого кластера отображаются статус, конфигурация бэкапа, список бэкапов и restore points; отсюда запускаются действия (Backup, Create restore point, Restore, Cleanup, Verify, Terminate, Resume). По клику на кластер открывается страница кластера с вкладками.
- **Configuration** — настройки выбранного кластера: **Backup configuration** (общие параметры, таймауты, хранилище, workspace, сжатие); **Schedule** (cron для full/differential/incremental backup, restore point, cleanup); **Storages** (определение хранилищ Posix, S3, CIFS и мониторинг заполненности). В каждый момент активна одна версия конфигурации (current); редактирование — через создание новой версии (Create new).
- **Backups** — список бэкапов кластера: тип (Full, Diff, Incr), время, статус (Done, Failed, Stopped и др.), связь с restore points. Детали бэкапа и топология отображаются при выборе записи.
- **Actions** — история запущенных действий (Backup, Restore, Cleanup и т.д.), статусы, логи и причины сбоев. Запуск действий эксклюзивен (одновременно только одно действие, кроме Terminate).

**Типовой цикл:** создать и применить конфигурацию бэкапа (Backup configuration, Storages, Schedule) → дождаться или вручную запустить первый полный бэкап → создавать restore points по расписанию или вручную → при необходимости выполнять Common restore или Partial restore, Cleanup, Verify; при сбое бэкапа — Terminate при необходимости, разбор логов в Actions, исправление конфигурации или хранилища. Детали действий и параметров — в [§2.3](chapter-02-03.md) и в [§6.2](chapter-06-02.md)–[§6.3](chapter-06-03.md).

---

## Ключевое

- **Назначение ADBM:** управление бинарными бэкапами ADB на базе pgbackrest; полный/diff/incr, WAL и PITR, restore points; поддержка нескольких кластеров, Posix и S3; входит в ADB Enterprise, установка только offline.
- **Интеграция с gpbackup:** ADBM и gpbackup — разные инструменты (бинарный vs логический бэкап); дополняют друг друга: ADBM для PITR и операционного восстановления, gpbackup/gprestore для выборочного бэкапа и миграции между кластерами.
- **Интерфейс:** Backup manager в ADB Control (пункт меню); разделы Clusters, Configuration (Backup configuration, Schedule, Storages), Backups, Actions; доступ — роли Administrator, ADBM Administrator, Owner; типовой цикл — конфигурация → бэкапы по расписанию → restore points → при необходимости restore, cleanup, verify.

В [§6.2](chapter-06-02.md) мы разберём полный и инкрементальный бэкап, настройку расписаний и хранение.
