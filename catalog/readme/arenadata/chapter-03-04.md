# §3.4 Развёртывание кластера

В [§3.3](chapter-03-03.md) мы настроили кластер в ADCM: создали кластер, добавили сервисы и хосты, распределили компоненты (Master, Segments) и при необходимости задали параметры конфигурации. В этом разделе описывается **процесс развёртывания**: предварительная проверка (Precheck), запуск установки (действие Install), проверка статуса после установки, создание и проверка базы данных по умолчанию, а также **доступ к кластеру** (подключение к координатору под пользователем `gpadmin`, использование `psql`). После успешного развёртывания кластер переходит в состояние `installed` и готов к работе; мониторинг и эксплуатация рассматриваются в [главе 4](chapter-04-01.md). См. [Глоссарий](glossary.md).

---

## 3.4.1. Предварительная проверка (Precheck)

Перед установкой кластера рекомендуется выполнить **предварительную проверку** — действие **Precheck**. Оно проверяет доступность репозиториев, отсутствие дублирования IP-адресов у хостов и соблюдение прочих требований. По [документации по установке кластера ADB](https://docs.arenadata.io/ru/ADB/current/get-started/online-install/adb-install/install-services.html):

1. На странице **Clusters** выбрать кластер (клик по имени).
2. В столбце **Actions** нажать на иконку меню действий и выбрать **Precheck**.
3. В открывшемся диалоге подтвердить запуск (Run).
4. Открыть вкладку **Jobs** в ADCM и дождаться завершения задачи; при необходимости кликнуть по задаче и просмотреть логи (вкладки Ansible stdout/stderr, кнопка Download для архива логов).

Если в логах есть ошибки, связанные с конфигурацией хостов (IPv6, параметры sysctl и т.п.), следует убедиться, что выполнена [предварительная настройка ОС](https://docs.arenadata.io/ru/ADB/current/planning/requirements/software.html#os_prerequisites) по §3.1. Precheck не устанавливает кластер; после успешной проверки переходят к действию Install.

---

## 3.4.2. Запуск установки (Install)

Установка кластера выполняется действием **Install**. Доступно два способа: установка **всего кластера** одной операцией или установка **отдельных сервисов** по очереди. По [документации по установке](https://docs.arenadata.io/ru/ADB/current/get-started/online-install/adb-install/install-services.html) и [кластерным действиям ADB](https://docs.arenadata.io/ru/ADB/current/how-to/manage-cluster/cluster-actions.html):

**Установка всего кластера (рекомендуется для первого развёртывания):**

1. На странице **Clusters** выбрать кластер → в столбце **Actions** нажать иконку меню → выбрать **Install**.
2. В диалоге обратить внимание на параметры. Флаг **Reboot cluster servers after installation** при необходимости включает автоматическую перезагрузку хостов после установки (нужна для применения настроек ОС из §3.1, например Disable linux security module, Set up GRUB for DBMS). Если флаг сброшен, перезагрузку выполняют вручную. При необходимости задать комментарий и флаг **Verbose** для детальных логов на вкладке Jobs.
3. Подтвердить действие (**Run**). ADCM последовательно установит все добавленные сервисы (ADB, Chrony, PXF и др.) на соответствующие хосты по Mapping; каждый сервис после установки запускается автоматически.
4. Дождаться завершения установки. Ход выполнения отображается на вкладке **Jobs**; при ошибках логи просматривают на странице задачи (подзадачи Install ADB и др., вкладки Ansible stdout/stderr).

**Установка отдельных сервисов:** если требуется установить сервисы вручную (например, после добавления нового сервиса в уже развёрнутый кластер), на вкладке **Services** страницы кластера для каждого сервиса нажимают иконку Actions и выбирают **Install** (для сервиса ADB — **Install ADB**). Сервисы устанавливают **по очереди**: не запускают установку следующего до завершения предыдущего. Рекомендуемый порядок: ADB → Chrony → ADB to ADB → PXF → ADB ClickHouse Connector → ADB to Kafka → Kafka to ADB.

**При сбоях:** если один или несколько сервисов не удалось установить, причину определяют по логам на странице Jobs; после исправления конфигурации или окружения можно запустить действие **Reinstall** (Actions кластера) и повторить установку. В диалоге Reinstall также доступен флаг перезагрузки хостов после переустановки.

## 3.4.3. Проверка статуса после установки

После успешного завершения Install статус кластера и сервисов обновляется. По [документации](https://docs.arenadata.io/ru/ADB/current/get-started/online-install/adb-install/install-services.html):

- **Кластер:** в столбце **State** на странице Clusters значение меняется с `created` на **`installed`**. Рядом с именем кластера зелёная точка указывает, что компоненты и хосты в рабочем состоянии; жёлтая — какой-то компонент или хост остановлен или недоступен.
- **Сервисы:** на вкладке **Services** страницы кластера статус каждого установленного сервиса меняется с `created` на **`installed`** (ADB, Chrony, PXF и добавленные коннекторы).

На вкладке **Overview** кластера отображаются секции Services и Hosts с круговыми диаграммами (Up/Down). При необходимости состояние компонентов и хостов уточняют на вкладках **Hosts** и **Services** → Components. Детали выполнения последней задачи установки и подзадач (включая логи Ansible) доступны на вкладке **Jobs** по ссылке на соответствующую задачу.

## 3.4.4. База данных по умолчанию и её проверка

При установке сервиса ADB автоматически создаётся **база данных по умолчанию**. Её имя задаётся конфигурационным параметром **Name of default database** сервиса ADB (до установки); по умолчанию — **`adb`**. Эта база используется по умолчанию для клиентских подключений и при выполнении сервисных действий ADB (например, установка расширений).

**Проверка создания базы данных** (по [документации](https://docs.arenadata.io/ru/ADB/current/get-started/online-install/adb-install/install-services.html)):

1. Подключиться к **хосту координатора** ADB (например, по SSH).
2. Переключиться на пользователя **`gpadmin`** (создаётся при установке ADB по умолчанию):

```bash
$ sudo su - gpadmin
```

3. Получить список баз данных:

```bash
psql -l
```

В выводе должна присутствовать база **`adb`** (или другое имя, заданное в Name of default database), а также системные базы `postgres`, `template0`, `template1`. Пример вывода:

```
 List of databases
 Name    | Owner  | Encoding  | Collate        | Ctype         | Access privileges
---------+--------+-----------+----------------+----------------+---------------------
 adb     | gpadmin| UTF8      | en_US.UTF-8    | en_US.UTF-8   | ...
 postgres| gpadmin| UTF8      | en_US.UTF-8    | en_US.UTF-8   |
 template0 | gpadmin | UTF8   | en_US.UTF-8    | en_US.UTF-8   | ...
 template1 | gpadmin | UTF8   | en_US.UTF-8    | en_US.UTF-8   | ...
(4 rows)
```

Подключение к базе `adb` по умолчанию: `psql adb` или `psql -d adb`. Дальнейшая работа с SQL и объектами БД выполняется так же, как в PostgreSQL/Greenplum (команды `\dt`, `\dn`, выполнение запросов и т.д.).

## 3.4.5. Доступ к кластеру извне

**С хоста координатора:** пользователь `gpadmin` подключается к координатору локально: `psql -d adb` (порт координатора по умолчанию — **5432**, если не изменён в конфигурации ADB). Координатор принимает клиентские соединения только на этом хосте; для доступа с других машин необходимо настроить подключение к IP или имени хоста координатора и убедиться, что firewall и конфигурация ADB (например, `listen_addresses`, `pg_hba.conf`) разрешают удалённые подключения.

**С удалённой машины:** при разрешённом сетевом доступе клиент (psql, приложение) подключается к хосту, на котором размещён компонент **ADB Master** (координатор), по порту **5432** (или заданному в конфигурации). Пример:

```bash
psql -h <IP_или_имя_хоста_координатора> -p 5432 -U gpadmin -d adb
```

Параметры аутентификации (пароль, pg_hba.conf) задаются при настройке кластера ADB; при первом подключении может потребоваться ввод пароля пользователя `gpadmin` (если настроена парольная аутентификация). Документация по настройке подключений и безопасности — в руководствах по конфигурации ADB и Greenplum/Greengage.

**ADB Control и ADBM:** если в кластер добавлены сервисы ADB Control и ADBM, их веб-интерфейсы и API доступны по адресам и портам, заданным при развёртывании (см. главу 4 и документацию по ADB Control и ADBM).

## 3.4.6. Типичные проблемы при развёртывании

- **Install зависает или падает с ошибкой:** просмотреть логи на вкладке **Jobs** → выбрать задачу Install → открыть подзадачи (например, Install ADB) и вкладки Ansible stdout/stderr. Частые причины: недоступность репозиториев с хостов, ошибки предварительной настройки ОС (limits, sysctl, SSH), неверный Mapping (например, не размещён обязательный компонент), недостаточно прав или места на дисках.
- **Precheck не пройден:** исправить указанные в логах Precheck проблемы (репозитории, уникальность IP, предварительная настройка ОС), затем снова запустить Precheck и только после успешного прохождения — Install.
- **После Install сервисы в состоянии Down:** проверить вкладки Hosts и Services (какие компоненты/хосты Down), логи на Jobs; при необходимости перезапустить сервисы действием **Start** (Actions кластера) или проверить состояние процессов и логов на самих хостах (под пользователем gpadmin или root).
- **Нет базы adb в выводе psql -l:** убедиться, что установка сервиса ADB завершилась успешно (статус `installed`); при необходимости проверить логи установки ADB и при создании БД по умолчанию. Имя БД может отличаться от `adb`, если был изменён параметр Name of default database.
- **Не удаётся подключиться с удалённого хоста:** проверить сеть, firewall (порт 5432), настройки `listen_addresses` и `pg_hba.conf` на координаторе; при необходимости настроить доверенные подсети и метод аутентификации в конфигурации ADB в ADCM и применить реконфигурацию.

## Ключевое

- **Precheck:** перед Install рекомендуется запустить действие Precheck для кластера (Clusters → Actions → Precheck); просмотр результата и логов — на вкладке Jobs. При ошибках — исправить конфигурацию или ОС и повторить проверку.
- **Install:** Clusters → выбрать кластер → Actions → Install. Установка всего кластера — одна операция; при необходимости включить флаг Reboot cluster servers after installation. Альтернатива — установка сервисов по одному (Services → Actions → Install / Install ADB) в указанном порядке. Логи и ошибки — на вкладке Jobs; при сбоях — Reinstall после исправлений.
- **Проверка:** после успешной установки State кластера — `installed`, статусы сервисов — `installed`; на Overview — состояние Services и Hosts (Up/Down).
- **База по умолчанию:** создаётся автоматически (имя — параметр Name of default database, по умолчанию `adb`). Проверка: SSH на координатор → `sudo su - gpadmin` → `psql -l`; в списке должна быть база `adb`.
- **Доступ:** подключение к координатору под `gpadmin` локально — `psql -d adb`; с удалённой машины — к IP/имени хоста координатора, порт 5432 (при разрешённом доступе и настройках pg_hba.conf).
