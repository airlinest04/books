# §6.4 Запись

В [§6.3](chapter-06-03.md) мы разобрали типы данных и приведение (cast). Преобразованный DataFrame часто нужно **записать** во внешнее хранилище: файлы в локальной файловой системе, HDFS или S3. Запись в PySpark выполняется через **df.write**: указываются формат, путь, режим (перезапись или добавление) и при необходимости партиционирование. В этом разделе рассмотрим **общий вид** записи (format, mode, save), **режимы** overwrite и append, **partitionBy()** и короткие методы для Parquet, CSV и JSON. Детали форматов и путей — в [§4.1](chapter-04-01.md) и [§4.3](chapter-04-03.md); число партиций при записи — в [§6.6](chapter-06-06.md). В [§6.5](chapter-06-05.md) перейдём к обработке пропусков. См. [Глоссарий](glossary.md).

---

## 6.4.1. Общий вид: write.format, mode, save

Запись выполняется через **DataFrameWriter**, доступный как **df.write**. Общая форма:

```python
df.write.format("формат").mode("режим").option("ключ", "значение").save("путь")
```

- **format("parquet")**, **format("csv")**, **format("json")** и т.д. — формат выходных данных.
- **mode("overwrite")**, **mode("append")** и др. — поведение при существующем пути (см. ниже).
- **option("key", "value")** — опции формата (сжатие, header для CSV и т.д.).
- **save("path")** — путь к каталогу (реже к одному файлу в зависимости от формата). Запись — **действие**: при вызове save выполняется весь план от корня до этого DataFrame; данные пишутся с исполнителей. См. [§2.4](chapter-02-04.md), [§4.1](chapter-04-01.md).

---

## 6.4.2. Режимы записи: overwrite и append

Параметр **mode()** задаёт, что делать, если путь (каталог) уже существует:

- **overwrite** — удалить существующий каталог (или его содержимое) и записать данные заново. Все предыдущие данные по этому пути теряются.
- **append** — добавить данные: новые файлы создаются в том же каталоге (и в соответствующих подкаталогах при партиционировании). Существующие файлы не удаляются. Удобно для инкрементальной загрузки (например, ежедневные срезы).
- **error** или **errorifexists** — выдать ошибку, если путь уже существует; запись не выполняется. Защита от случайной перезаписи.
- **ignore** — если путь существует, не писать и не выдавать ошибку; если не существует — записать.

По умолчанию в многих версиях используется **errorifexists**. Для перезаписи витрины явно указывают **mode("overwrite")**; для дополнения — **mode("append")**. См. [§4.1](chapter-04-01.md), [§4.3](chapter-04-03.md).

---

## 6.4.3. Партиционирование при записи: partitionBy()

Метод **partitionBy(*cols)** разбивает вывод по значениям указанных столбцов: под каталогом пути создаются подкаталоги вида **col=value**, внутри — файлы формата. Партиционные столбцы в записанных файлах по умолчанию не дублируются как отдельные колонки; при чтении они восстанавливаются из структуры каталогов. См. [§4.3](chapter-04-03.md), [Глоссарий](glossary.md).

```python
df.write.mode("overwrite").partitionBy("date", "region").parquet("/path/to/output")
```

Выбор столбцов для partitionBy — по частоте фильтрации при последующем чтении (partition pruning) и по кардинальности (см. [§4.3](chapter-04-03.md)). При append с partitionBy новые данные попадают в соответствующие подкаталоги; число файлов в партиции может расти — при необходимости его контролируют через repartition/coalesce перед записью (см. [§6.6](chapter-06-06.md)). См. [Глоссарий](glossary.md).

---

## 6.4.4. Короткие методы: parquet, csv, json

Вместо **format(...).save(path)** можно использовать короткие методы:

```python
df.write.parquet("/path/to/output")
df.write.mode("overwrite").csv("/path/to/csv", header=True, sep=",")
df.write.mode("append").json("/path/to/json")
```

Опции передаются как именованные аргументы (header, sep для CSV; compression и др.). Режим и партиционирование задаются до вызова метода:

```python
df.write.mode("overwrite").partitionBy("date").option("compression", "snappy").parquet("/path")
```

См. [§4.1](chapter-04-01.md).

---

## 6.4.5. Опции при записи

Типичные опции:

- **compression** — алгоритм сжатия при записи (для Parquet/ORC: "snappy", "gzip", "none" и т.д.).
- **header** — для CSV: записать первую строку с именами столбцов (True/False).
- **sep** — для CSV: разделитель полей.
- **nullValue** — для CSV: строка для записи значений null (по умолчанию пустая строка).

Полный список опций зависит от формата; см. документацию Spark по DataFrameWriter. См. [§4.1](chapter-04-01.md).

---

## 6.4.6. Запись в таблицу каталога: saveAsTable

Кроме записи в путь, можно записать DataFrame в **таблицу** каталога Spark (управляемую или внешнюю): **df.write.saveAsTable("db_name.table_name")**. Режим (overwrite/append) задаётся через **mode()**; при необходимости указывают format и опции. Таблица будет видна в spark.catalog и в Spark SQL. Управляемые таблицы хранят данные в каталоге каталога; при DROP TABLE данные удаляются. Подробнее каталог и таблицы — в [§3.4](chapter-03-04.md). Запись по JDBC в внешнюю БД — через **df.write.jdbc(...)** (см. [§4.4](chapter-04-04.md)). См. [Глоссарий](glossary.md).

---

## Ключевое

- **Запись:** df.write.format(...).mode(...).option(...).save(path) или короткие методы parquet/csv/json; save — **действие**, выполняется весь план.
- **Режимы:** overwrite (перезаписать), append (добавить), error/errorifexists (ошибка при существующем пути), ignore (не писать, если путь есть).
- **partitionBy("col1", "col2")** создаёт подкаталоги col1=value1/col2=value2/; удобно для последующего чтения с фильтром по этим столбцам (partition pruning).
- Опции формата: compression, header и sep для CSV, nullValue и др.; задаются через .option() или именованные аргументы коротких методов.
- Запись в таблицу каталога — saveAsTable(); в БД — write.jdbc() (см. §4.4).

В [§6.5](chapter-06-05.md) мы разберём обработку пропусков: na.fill(), na.drop() и стратегии работы с null.
