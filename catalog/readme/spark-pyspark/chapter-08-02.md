# §8.2 Источники и приёмники

В [§8.1](chapter-08-01.md) мы разобрали микропакетную обработку, триггеры и режимы вывода. Чтобы поток заработал, нужно указать **источник** (откуда читать) и **приёмник** (куда писать). В этом разделе рассмотрим чтение из **файлового каталога** (новые файлы) и из **Kafka**, а также запись в консоль, в **parquet** и в Kafka. В [§8.3](chapter-08-03.md) перейдём к агрегациям в потоке (окна времени, watermark). См. [Глоссарий](glossary.md).

---

## 8.2.1. Источник: файловый каталог (новые файлы)

Один из самых простых источников — **каталог в файловой системе** (локальной, HDFS или объектном хранилище). Spark читает **только новые файлы**, появившиеся в каталоге после начала потока или после последнего микропакета (в зависимости от формата и опций). Подходят форматы с поддержкой потокового чтения: **parquet**, **json**, **csv**, **orc**. См. [§4.1](chapter-04-01.md), [§4.2](chapter-04-02.md).

```python
schema = "id LONG, value DOUBLE, ts TIMESTAMP"
df = spark.readStream.schema(schema).format("parquet").load("/path/to/input/dir")
```

Для форматов без встроенной схемы (csv, json) схему задают **.schema(schema)** — строкой DDL или **StructType**. Опции чтения передаются через **.option("key", "value")** (например, разделитель для csv). Важно: файлы считаются «новыми», когда они **появились** в каталоге; переименование или изменение существующих файлов может привести к повторному чтению или пропуску в зависимости от формата. Для parquet обычно обрабатываются только полностью записанные файлы. См. [§6.1](chapter-06-01.md).

---

## 8.2.2. Источник: Kafka

Чтение из **Kafka** позволяет подписаться на один или несколько топиков и обрабатывать сообщения как поток. Источник задаётся **.format("kafka")**; обязательные опции — адреса брокеров (**kafka.bootstrap.servers**) и подписка на топики (**subscribe** или **assign**). См. [Глоссарий](glossary.md).

```python
df = spark.readStream.format("kafka") \
  .option("kafka.bootstrap.servers", "host1:9092,host2:9092") \
  .option("subscribe", "topic1") \
  .load()
```

Столбцы Kafka-источника включают **key**, **value** (оба binary), **topic**, **partition**, **offset**, **timestamp** и др. Обычно **value** парсят в нужную структуру (например, JSON) и дальше работают с полями. Опции **startingOffsets** (earliest / latest или JSON с offset по партициям) задают, с какого места начинать чтение при первом запуске. Для восстановления после сбоя используется **checkpointLocation**: Spark запоминает обработанные offset. См. [§8.1](chapter-08-01.md).

---

## 8.2.3. Приёмник: консоль

Приёмник **console** выводит каждую порцию результата в stdout драйвера. Задаётся **.format("console")**. Подходит для отладки и обучения; в продакшене не используется. Дополнительные опции (например, **numRows**) ограничивают число выводимых строк. **checkpointLocation** для консоли обычно не указывают. См. [§8.1](chapter-08-01.md).

```python
df.writeStream.format("console").trigger(processingTime="5 seconds").start()
```

---

## 8.2.4. Приёмник: Parquet (и другие файловые форматы)

Запись в файловую систему (HDFS, S3, локальный диск) выполняется с **.format("parquet")** (или **json**, **csv** и т.д.) и **.option("path", "/path/to/output")**. Обязательно указывают **checkpointLocation** — каталог, где Spark хранит метаданные потока и прогресс; без него при перезапуске запись начнётся заново или возникнут конфликты. См. [§4.1](chapter-04-01.md), [Глоссарий](glossary.md).

```python
df.writeStream.format("parquet") \
  .option("path", "/path/to/output") \
  .option("checkpointLocation", "/path/to/checkpoint") \
  .trigger(processingTime="10 seconds") \
  .start()
```

Режим вывода для файловых приёмников обычно **append**: каждый микропакет добавляет новые файлы (или данные в партиционированный каталог). Имена и структура каталогов зависят от формата и партиционирования. См. [§4.3](chapter-04-03.md).

---

## 8.2.5. Приёмник: Kafka

Запись в Kafka задаётся **.format("kafka")** с опциями **kafka.bootstrap.servers** и **topic** (или **topic** в данных). Каждая порция результата отправляется в указанный топик. Нужны сериализация ключа и значения (например, **kafka.key.serializer**, **kafka.value.serializer** или эквиваленты в option). Как и для файлового приёмника, для надёжности указывают **checkpointLocation**. См. [§8.2](chapter-08-02.md).

---

## Ключевое

- **Источник** задаётся в **readStream.format(...)** с опциями: **file** (parquet/json/csv/orc) — каталог, обрабатываются новые файлы; **kafka** — bootstrap.servers, subscribe (или assign), при необходимости startingOffsets.
- Для файлового источника при отсутствии схемы в данных указывают **.schema()**; для Kafka результат содержит key, value, topic, partition, offset — value обычно парсят отдельно.
- **Приёмник console** — вывод в stdout; **parquet** (и др.) — запись в каталог с обязательной **checkpointLocation**; **kafka** — запись в топик с настройками сериализации.
- **checkpointLocation** обязателен для восстановления прогресса и корректной работы при перезапуске (кроме консоли в учебных целях).

В [§8.3](chapter-08-03.md) рассмотрим агрегации в потоке: группировка по окну времени и watermark.
