# §8.3 Агрегации в потоке

В [§8.2](chapter-08-02.md) мы разобрали источники и приёмники потокового запроса. В потоке часто нужны **агрегаты по времени**: например, число событий за последний час или сумма за скользящее окно. В Structured Streaming для этого используется **группировка по окну времени** и **watermark** для отложенных данных. В этом разделе рассмотрим функцию **window()** по столбцу времени, настройку **withWatermark** и режимы вывода для потоковых агрегатов. В [§8.4](chapter-08-04.md) подведём итоги главы. См. [Глоссарий](glossary.md).

---

## 8.3.1. Окно по времени: window()

В потоке строки приходят с меткой времени (**event time** — время события или **processing time** — время обработки). **Окно времени** группирует строки по интервалам: например, все события с 10:00 до 11:00 попадают в одно окно. В PySpark для этого используется функция **window()** из **pyspark.sql.functions**: первый аргумент — столбец с временем (timestamp), второй — длительность окна (например, **"1 hour"**), опционально — размер шага (slide) и начало окна. Результат — структура с полями **start** и **end** (границы окна), её можно использовать в **groupBy**. См. [Глоссарий](glossary.md).

```python
from pyspark.sql.functions import window, col, count

df.withColumn("w", window(col("event_time"), "1 hour")) \
  .groupBy("w").agg(count("*").alias("cnt"))
```

Или короче: **groupBy(window(col("event_time"), "10 minutes"))** и далее **agg(...)**. Окна задаются по **event time**, если в данных есть столбец с временем события; иначе можно использовать **current_timestamp()** (processing time). Для потоковых агрегатов по окну времени обычно требуется **watermark**. См. [§7.1](chapter-07-01.md), [§7.2](chapter-07-02.md).

---

## 8.3.2. Watermark: зачем нужен и как задать

Данные в потоке могут приходить **с задержкой**: событие произошло в 10:05, а обработано в 10:30. Без ограничения движок должен хранить состояние всех окон бесконечно долго, ожидая возможных опоздавших записей. **Watermark** задаёт порог задержки: события с меткой времени **старше** (текущее время минус watermark) считаются «опоздавшими» и могут быть отброшены (или обработаны по политике движка). Состояние для окон старше watermark можно удалять, ограничивая объём хранимого состояния. См. [Глоссарий](glossary.md).

Задаётся методом **withWatermark(eventTimeColumn, delayThreshold)** у потокового DataFrame. Например: **delayThreshold = "10 minutes"** означает, что события с event time более чем на 10 минут раньше текущего времени обработки не гарантируют попадание в результат (движок может их не учитывать). Порог выбирают по допустимой задержке доставки данных. См. [§8.1](chapter-08-01.md).

```python
df.withWatermark("event_time", "10 minutes") \
  .groupBy(window(col("event_time"), "5 minutes")).agg(count("*").alias("cnt")) \
  .writeStream.format("console").outputMode("append").start()
```

## 8.3.3. Режим вывода при агрегации по окну с watermark

При группировке по окну времени с **watermark** результат окна считается **окончательным**, когда время обработки прошло порог watermark после конца окна: все «своевременные» данные для этого окна уже учтены. В режиме **append** в приёмник выводятся только такие окончательные строки (по одному разу на окно). Режимы **update** и **complete** при потоковых агрегатах также зависят от watermark и типа запроса; для окон с watermark **append** — типичный выбор при записи в файл или Kafka. См. [§8.1](chapter-08-01.md), [§8.2](chapter-08-02.md).

Без watermark потоковая агрегация по окну времени не поддерживается в режиме append (движок не знает, когда закрыть окно). Глобальная агрегация без окна (например, одна накапливаемая сумма) обычно использует **update** или **complete**. См. [§7.1](chapter-07-01.md).

---

## Ключевое

- **Окно по времени** задаётся функцией **window(timestamp_column, windowDuration)** (и при необходимости slide, startTime); используется в **groupBy** для агрегации по интервалам (например, по часу или 10 минутам).
- **Watermark** — **withWatermark(eventTimeColumn, delayThreshold)**; задаёт порог задержки (например, "10 minutes"), после которого опоздавшие события могут не учитываться; ограничивает объём хранимого состояния.
- При агрегации по окну с watermark в режиме **append** в приёмник выводятся строки по окнам, когда окно считается закрытым (все своевременные данные учтены).
- Без watermark потоковая группировка по окну времени в append не поддерживается; для глобальных агрегатов используют update или complete.
