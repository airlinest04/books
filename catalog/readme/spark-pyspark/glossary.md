# Глоссарий

Термины Spark, PySpark и смежных технологий, используемые в книге.

---

## B

**Broadcast join** — стратегия соединения, при которой малая таблица рассылается на все узлы и соединяется с большой без shuffle большой таблицы по ключу; в PySpark задаётся через broadcast(df) в join. См. [§7.3](chapter-07-03.md).

---

## C

**Catalyst** — модуль оптимизации запросов Spark SQL: анализ логического плана, логическая оптимизация (проталкивание предикатов, упрощение), выбор физического плана и генерация кода. См. [§3.1](chapter-03-01.md).

---

## D

**DAG** (Directed Acyclic Graph, направленный ациклический граф) — граф операций без циклов; в Spark используется для представления цепочки преобразований (трансформаций) над данными до момента выполнения. См. [§1.1](chapter-01-01.md), [§2.3](chapter-02-03.md).

**DataFrame** — табличная абстракция в Spark со схемой (имена и типы столбцов); API для выборки, фильтрации, группировки и соединений; план выполнения оптимизируется движком (Catalyst). См. [§1.2](chapter-01-02.md), [§3.1](chapter-03-01.md).

**DWH** (Data Warehouse, хранилище данных) — предметно-ориентированное хранилище данных для аналитики и отчётности; Spark может читать из DWH и записывать в него по JDBC. См. [§1.3](chapter-01-03.md), [§4.4](chapter-04-04.md).

---

## E

**ETL** (Extract, Transform, Load) — извлечение данных из источников, преобразование (очистка, агрегация, объединение) и загрузка в целевое хранилище (DWH, витрина); Spark часто используют как этап ETL между озером данных и DWH. См. [§4.4](chapter-04-04.md).

---

## G

**GroupedData** — объект, возвращаемый методом groupBy() у DataFrame; описывает группировку по ключу; сам по себе не даёт DataFrame, используется для вызова agg() или коротких методов (count, sum, avg и т.д.). См. [§7.1](chapter-07-01.md).

---

## H

**Hadoop** — экосистема с открытым исходным кодом для распределённого хранения и обработки данных: HDFS, MapReduce (и позднее YARN как менеджер ресурсов). Spark часто работает поверх HDFS и YARN. См. [§1.1](chapter-01-01.md).

**HDFS** (Hadoop Distributed File System) — распределённая файловая система, рассчитанная на хранение больших объёмов данных на кластере; данные реплицируются между узлами. Часто используется как хранилище для MapReduce и Spark. См. [§1.1](chapter-01-01.md), [§4.2](chapter-04-02.md).

**HAVING** — в SQL условие на результат агрегации (после GROUP BY); в PySpark эквивалент — вызов filter() по DataFrame, полученному после groupBy().agg(), по столбцам агрегатов. См. [§7.1](chapter-07-01.md).

**Hive Metastore** — сервис хранения метаданных таблиц и баз данных (схема, путь к данным, формат); Spark может подключаться к Metastore и использовать те же таблицы, что и Hive. См. [§3.4](chapter-03-04.md).

---

## I

**In-memory** (в памяти) — стратегия вычислений, при которой промежуточные результаты хранятся в оперативной памяти узлов кластера, а не записываются на диск между этапами; в Spark используется для ускорения итеративных и интерактивных сценариев. См. [§1.2](chapter-01-02.md).

---

## J

**JDBC** (Java Database Connectivity) — стандартный API доступа к реляционным БД из Java; Spark использует JDBC для чтения таблиц из СУБД и записи результатов в DWH и витрины. См. [§1.3](chapter-01-03.md), [§4.4](chapter-04-04.md).

---

## K

**Kubernetes** — платформа оркестрации контейнеров; Spark может запускать драйвер и исполнители как поды в кластере (master: k8s://...). См. [§2.5](chapter-02-05.md).

---

## L

**Lineage** (линия происхождения) — запись о том, как получены данные RDD (из какого источника или из каких трансформаций); используется для пересчёта при сбоях без хранения всех промежуточных результатов на диске. См. [§1.2](chapter-01-02.md), [§2.2](chapter-02-02.md).

---

## M

**MapReduce** — модель распределённых вычислений из двух фаз (Map и Reduce); промежуточные результаты между фазами записываются на диск (например, в HDFS). Реализация — Apache Hadoop MapReduce. См. [§1.1](chapter-01-01.md).

---

## O

**ORC** (Optimized Row Columnar) — колоночный бинарный формат хранения данных со схемой и сжатием; часто используется с Hive; Spark поддерживает чтение и запись. См. [§4.1](chapter-04-01.md).

---

## P

**Parquet** — колоночный бинарный формат хранения данных со схемой в метаданных и сжатием; широко используется в Spark и экосистеме больших данных. См. [§4.1](chapter-04-01.md).

**Partition pruning** (отсечение партиций) — при чтении партиционированных данных (например, по каталогам col=value) оптимизатор читает только подкаталоги, удовлетворяющие фильтру по партиционным столбцам, уменьшая объём I/O. См. [§4.3](chapter-04-03.md).

**PYSPARK_PYTHON** — переменная окружения: путь к интерпретатору Python, используемому на исполнителях (и при необходимости на драйвере); важна при запуске на кластере. См. [§5.1](chapter-05-01.md).

**PySpark** — API Apache Spark для языка Python; позволяет писать Spark-приложения (RDD, DataFrame, Spark SQL, Structured Streaming) на Python; взаимодействие с JVM через Py4J. В этой книге — основной используемый API. См. [§1.4](chapter-01-04.md), [§5.1](chapter-05-01.md).

---

## R

**RDD** (Resilient Distributed Dataset) — неизменяемая распределённая коллекция объектов в Spark, разбитая на партиции; описывает происхождение данных и цепочку трансформаций; вычисление выполняется лениво при вызове действия. См. [§1.2](chapter-01-02.md), [§2.2](chapter-02-02.md).

---

## S

**S3** (Amazon Simple Storage Service) — объектное хранилище Amazon; в Spark доступ через схему **s3a://** (драйвер Hadoop S3A): путь s3a://bucket/key; настройка доступа — ключи или IAM. См. [§4.2](chapter-04-02.md).

**Shuffle** (перемешивание) — этап в распределённой обработке, при котором данные перераспределяются между узлами по ключу (например, для группировки или соединения); в MapReduce и в Spark сопровождается передачей данных по сети и часто записью на диск. См. [§1.1](chapter-01-01.md), [§2.3](chapter-02-03.md).

**Skew** (перекос данных) — неравномерное распределение данных по партициям при группировке или соединении; часть задач обрабатывает непропорционально много данных, стадия замедляется. См. [§2.6](chapter-02-06.md).

**SPARK_HOME** — переменная окружения: путь к корневому каталогу дистрибутива Spark; используется spark-submit и скриптами из дистрибутива. См. [§5.1](chapter-05-01.md).

**Spark SQL** — модуль Spark для выполнения SQL-запросов над DataFrame и таблицами каталога; регистрация DataFrame как представления (createOrReplaceTempView), запросы через spark.sql(); тот же движок и Catalyst, что и для DataFrame API. См. [§3.3](chapter-03-03.md).

**SparkSession** — единая точка входа в Spark в приложении: создаётся через SparkSession.builder.getOrCreate(); даёт доступ к spark.read, spark.sql, spark.catalog; в PySpark обычно хранится в переменной spark. См. [§5.2](chapter-05-02.md).

**Spark UI** — веб-интерфейс мониторинга Spark (по умолчанию http://localhost:4040): джобы, стадии, задачи, shuffle read/write, кэш, исполнители. См. [§2.6](chapter-02-06.md).

**Standalone (Spark)** — встроенный менеджер кластера Spark (master + workers), мастер spark://host:7077; не требует YARN или Kubernetes. См. [§2.5](chapter-02-05.md).

**Structured Streaming** — API потоковой обработки в Spark; поток представляется как бесконечная таблица, обработка выполняется микропакетами; чтение через readStream, запуск через writeStream (триггер, приёмник, outputMode). См. [§8.1](chapter-08-01.md).

---

## W

**Watermark** (водяной знак) — в Structured Streaming порог задержки по времени события (withWatermark(eventTimeColumn, delayThreshold)); события с event time старше этого порога считаются опоздавшими и могут не учитываться; позволяет ограничить объём хранимого состояния при агрегации по окну времени. См. [§8.3](chapter-08-03.md).

---

## Y

**YARN** (Yet Another Resource Negotiator) — менеджер ресурсов в экосистеме Hadoop; Spark может запускаться в режиме YARN (master: yarn), запрашивая контейнеры для драйвера и исполнителей. См. [§2.5](chapter-02-05.md).

---

## Д

**Действие (action)** — операция в Spark, которая запускает выполнение DAG и возвращает результат на драйвер или записывает данные вовне (count, collect, take, show, write и т.д.). См. [§2.4](chapter-02-04.md).

**Драйвер (Driver)** — процесс Spark-приложения, в котором выполняется пользовательский код; строит DAG, планирует стадии и задачи, рассылает задачи исполнителям и собирает результаты. Один на приложение. См. [§2.1](chapter-02-01.md).

---

## З

**Задача (task)** — единица работы в Spark: выполнение операций одной стадии над одной партицией; планировщик рассылает задачи исполнителям. См. [§2.3](chapter-02-03.md), [§2.6](chapter-02-06.md).

---

## И

**Исполнитель (Executor)** — процесс на узле кластера (или в локальном режиме), выполняющий задачи Spark и хранящий кэш RDD/DataFrame и результаты shuffle в памяти или на диске. См. [§2.1](chapter-02-01.md).

**Источник (streaming source)** — в Structured Streaming место, откуда читается поток данных; задаётся в readStream.format(...) (файловый каталог, Kafka и др.). См. [§8.2](chapter-08-02.md).

---

## К

**Кадр (frame)** — подмножество строк внутри партиции окна, по которому вычисляется агрегатная или иная оконная функция; задаётся rowsBetween или rangeBetween в спецификации Window. См. [§7.2](chapter-07-02.md).

---

## Л

**Ленивое выполнение (lazy evaluation)** — в Spark трансформации не выполняются сразу, а лишь добавляют узлы в DAG; вычисление запускается только при вызове действия (count, collect, write и т.д.). См. [§2.2](chapter-02-02.md), [§2.4](chapter-02-04.md).

**Локальный режим (local)** — выполнение Spark на одной машине (master: local, local[N], local[*]); для разработки и отладки. См. [§2.5](chapter-02-05.md), [§5.1](chapter-05-01.md).

---

## М

**Микропакет (micro-batch)** — в Structured Streaming порция потоковых данных, обрабатываемая за один запуск задания; триггер задаёт, как часто запускается обработка очередного микропакета. См. [§8.1](chapter-08-01.md).

---

## О

**Оконная функция (window function)** — функция, вычисляющая для каждой строки значение по окну (партиция + порядок + опционально кадр); в PySpark задаётся через Window.partitionBy().orderBy() и .over(spec); примеры: row_number, rank, lag, lead, sum/avg over окно. См. [§7.2](chapter-07-02.md).

---

## П

**Партиция (partition)** — часть RDD или DataFrame, обрабатываемая одной задачей на одном исполнителе; число партиций задаёт степень параллелизма. См. [§2.2](chapter-02-02.md), [§6.6](chapter-06-06.md).

**Приёмник (sink)** — в Structured Streaming место назначения результата потокового запроса: консоль, файл (parquet и др.), Kafka, или пользовательский код (foreach/foreachBatch). Задаётся в writeStream.format(...). См. [§8.1](chapter-08-01.md), [§8.2](chapter-08-02.md).

---

## С

**Соединение (join)** — объединение двух DataFrame (или таблиц) по ключу; в PySpark — метод .join(other, on, how); типы: inner, left, right, full; при соединении выполняется shuffle по ключу (если не используется broadcast). См. [§7.3](chapter-07-03.md).

**Стадия (stage)** — блок операций в DAG с только узкими зависимостями; граница между стадиями — широкая зависимость (shuffle); стадии выполняются по порядку. См. [§2.3](chapter-02-03.md), [§2.6](chapter-02-06.md).

---

## Т

**Трансформация (transformation)** — операция над RDD или DataFrame, возвращающая новый RDD/DataFrame и не выполняющая вычисление сразу (map, filter, groupBy, join и т.д.); расширяет DAG. См. [§2.4](chapter-02-04.md).

**Триггер (trigger)** — в Structured Streaming настройка, определяющая, когда запускается обработка следующего микропакета: по времени (processingTime), один раз (Once) или в режиме Continuous. Задаётся в writeStream.trigger(). См. [§8.1](chapter-08-01.md).
