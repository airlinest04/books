# §7.4 Уникальные значения и дубликаты

В [§7.3](chapter-07-03.md) мы разобрали соединения (join). Часто после слияния таблиц или из-за особенностей источника в данных появляются **дубликаты** строк; бывает нужно оставить только **уникальные** строки или по одному представителю на ключ. В PySpark для этого используются **distinct()** и **dropDuplicates()**. В этом разделе рассмотрим оба метода и когда какой применять. С [§8.1](chapter-08-01.md) начинается глава 8 — Spark Streaming. См. [Глоссарий](glossary.md).

---

## 7.4.1. distinct(): уникальные строки по всем столбцам

Метод **distinct()** (или **dropDuplicates()** без аргументов) возвращает DataFrame, в котором **все строки различаются**: сравнивается полная строка по всем столбцам, повторяющиеся строки удаляются, остаётся по одной. См. [Глоссарий](glossary.md).

```python
df_unique = df.distinct()
# то же:
df_unique = df.dropDuplicates()
```

Эквивалент в SQL — **SELECT DISTINCT ...** или **SELECT ... GROUP BY col1, col2, ...** по всем столбцам. Операция требует shuffle по всем столбцам для сведения одинаковых строк в одну партицию и последующего удаления дубликатов. См. [§2.3](chapter-02-03.md), [§7.1](chapter-07-01.md).

---

## 7.4.2. dropDuplicates(subset): уникальность по подмножеству столбцов

Метод **dropDuplicates(subset=None)** при **subset**, заданном списком имён столбцов (или одним именем), оставляет **по одной строке на каждую комбинацию значений** этих столбцов. Из группы строк с одинаковым ключом остаётся **первая** встречающаяся строка; порядок строк в DataFrame до вызова dropDuplicates не гарантирован (если не применяли orderBy), поэтому «первая» — в смысле порядка обработки партиций, а не логического порядка. См. [Глоссарий](glossary.md).

```python
# Одна строка на каждую пару (user_id, date)
df_one_per_user_date = df.dropDuplicates(["user_id", "date"])
```

Если нужно оставить не любую строку, а, например, «последнюю по времени», сначала задают порядок (**orderBy("date")**), затем используют **dropDuplicates** — но в Spark до 3.x порядок не гарантировался при dropDuplicates; надёжный способ «одна запись на ключ, выбранная по правилу» — оконная функция **row_number()** и фильтр (см. [§7.2](chapter-07-02.md)) или **groupBy** и **first()**/агрегат. См. [§7.1](chapter-07-01.md), [§7.2](chapter-07-02.md).

---

## 7.4.3. Когда использовать distinct и dropDuplicates

- **distinct()** — когда важна уникальность по **всей** строке (например, убрать полностью идентичные записи после join или после чтения сырых данных). Дороже по ресурсам, если столбцов много: ключ группировки включает все столбцы.
- **dropDuplicates(["col1", "col2"])** — когда дубликаты определяются по **ключу** (одна запись на пользователя, на дату и т.д.); остальные столбцы могут различаться, но нужна только одна строка на ключ. Дешевле, чем distinct по всем столбцам, если ключ короткий.

Оба метода возвращают новый DataFrame и не меняют порядок столбцов. См. [§6.2](chapter-06-02.md).

---

## Ключевое

- **distinct()** (или **dropDuplicates()** без аргументов) оставляет уникальные строки по **всем** столбцам; эквивалент SELECT DISTINCT.
- **dropDuplicates(subset)** оставляет по одной строке на каждую комбинацию значений столбцов из **subset**; какая строка остаётся в группе, не гарантируется без предварительного orderBy; для выбора по правилу (например, последняя по дате) надёжнее оконная функция или groupBy.
- Для удаления дубликатов по ключу **dropDuplicates([cols])** обычно эффективнее **distinct()**, так как сравнение идёт только по указанным столбцам.
