# §7.3 Соединения

В [§7.2](chapter-07-02.md) мы разобрали оконные функции. Чтобы объединить два DataFrame по ключу (как JOIN в SQL), в PySpark используется метод **join()**. В этом разделе рассмотрим синтаксис **join(other, on, how)**, типы соединений (**inner**, **left**, **right**, **full**), соединение по одному и по нескольким столбцам и кратко — **broadcast join**. В [§7.4](chapter-07-04.md) перейдём к уникальным значениям и дубликатам. См. [Глоссарий](glossary.md).

---

## 7.3.1. Синтаксис join(other, on, how)

Метод вызывается у «левого» DataFrame: **df_left.join(df_right, on=..., how=...)**. Возвращается новый DataFrame со столбцами обоих таблиц; строки формируются по правилу выбранного типа соединения. См. [Глоссарий](glossary.md).

- **other** — правый DataFrame (или таблица Spark SQL).
- **on** — условие соединения: имя столбца (строка), если столбец с таким именем есть в обоих DataFrame; список имён столбцов; либо выражение Column (например, df_left.col_a == df_right.col_a). При равенстве имён столбцов в обеих таблицах можно передать одну строку или список строк.
- **how** — тип соединения: **"inner"**, **"left"**, **"right"**, **"full"** (и варианты **"left_outer"**, **"right_outer"**, **"full_outer"**); по умолчанию **"inner"**.

Пример по одному столбцу с одинаковым именем в обеих таблицах:

```python
orders.join(customers, on="customer_id", how="left")
```

См. [§6.2](chapter-06-02.md).

---

## 7.3.2. Типы соединений: inner, left, right, full

Поведение совпадает с SQL:

| how | Название | Результат |
|-----|----------|-----------|
| **inner** | Внутреннее | Только строки, где ключ найден в обеих таблицах. |
| **left** / **left_outer** | Левое внешнее | Все строки левой таблицы; при отсутствии совпадения справа — null в столбцах правой. |
| **right** / **right_outer** | Правое внешнее | Все строки правой таблицы; при отсутствии совпадения слева — null в столбцах левой. |
| **full** / **full_outer** | Полное внешнее | Все строки обеих таблиц; при отсутствии совпадения — null со стороны недостающей таблицы. |

**cross** (декартово произведение) — каждая строка слева с каждой строкой справа; в Spark задаётся join без условия on (или с how="cross" в новых версиях). Обычно нужен только при явной необходимости. См. [Глоссарий](glossary.md).

## 7.3.3. Соединение по одному и по нескольким столбцам

Если ключевые столбцы называются одинаково в обоих DataFrame, **on** можно задать строкой (один столбец) или списком строк (несколько столбцов):

```python
df1.join(df2, on="id", how="inner")
df1.join(df2, on=["id", "date"], how="inner")
```

В результате столбцы ключа в результирующем DataFrame не дублируются. Если имена различаются, **on** задаётся выражением Column:

```python
from pyspark.sql.functions import col

df1.join(df2, col("df1_id") == col("df2_id"), how="left")
```

При использовании выражения оба столбца попадут в результат; при необходимости один можно удалить или переименовать. См. [§6.2](chapter-06-02.md).

---

## 7.3.4. Дубликаты имён столбцов после join

Если в левой и правой таблице есть столбцы с одинаковыми именами, не входящие в **on**, в результате появятся два столбца (например, **id** и **id**). Обращение по имени может быть неоднозначным. Варианты: выбирать столбцы через **df["col"]** или **df.col_name** после переименования; использовать алиасы для одного из DataFrame (**df.alias("left")**) и обращаться **left_df.col**. При **on** в виде списка имён общие ключевые столбцы в результате не дублируются. См. [Глоссарий](glossary.md).

---

## 7.3.5. Broadcast join (кратко)

При обычном join оба DataFrame участвуют в **shuffle** по ключу: данные перераспределяются между узлами (см. [§2.3](chapter-02-03.md)). Если одна из таблиц **мала**, её можно разослать на все узлы и избежать shuffle для неё — **broadcast join**. В PySpark малую таблицу оборачивают в **broadcast()** из **pyspark.sql.functions**:

```python
from pyspark.sql.functions import broadcast

df_large.join(broadcast(df_small), on="key", how="left")
```

Оптимизатор Spark может сам выбрать broadcast для маленьких таблиц; явный **broadcast()** задаёт подсказку. Не стоит broadcastить большую таблицу: все её данные копируются на каждый исполнитель. См. [Глоссарий](glossary.md).

---

## Ключевое

- **join(other, on, how)** — соединение двух DataFrame по условию **on** (столбец, список столбцов или выражение Column) и типу **how** (inner, left, right, full).
- **inner** — только совпадающие строки; **left** — все слева, справа null при отсутствии совпадения; **right** и **full** — по аналогии с SQL.
- При одинаковых именах ключей **on** задаётся строкой или списком; при разных — выражением Column; при выражении ключевые столбцы могут дублироваться в результате.
- При совпадающих именах неключевых столбцов в результате два столбца; для однозначности используют алиасы или явный выбор столбцов.
- **Broadcast join** — раздача малой таблицы по узлам; задаётся **broadcast(df)** в join; уменьшает shuffle для большой таблицы.

В [§7.4](chapter-07-04.md) мы разберём уникальные значения и дубликаты: distinct() и dropDuplicates().
