# §5.2 SparkSession

В [§5.1](chapter-05-01.md) мы разобрали установку PySpark и запуск оболочки и скриптов. В любом приложении на PySpark **точка входа** к движку — объект **SparkSession**: через него создаются DataFrame, выполняется чтение данных и SQL-запросы. В этом разделе рассмотрим создание SparkSession через **builder**, метод **getOrCreate()**, конфигурацию (память, число ядер, имя приложения) и основные возможности сессии (read, sql, catalog). В [§5.3](chapter-05-03.md) перейдём к созданию и просмотру DataFrame в PySpark. См. [Глоссарий](glossary.md).

---

## 5.2.1. SparkSession как точка входа

**SparkSession** объединяет ранее существовавшие отдельно **SparkContext** (доступ к кластеру и низкоуровневому API) и **HiveContext** (каталог, SQL). В современном API один объект SparkSession даёт доступ к:

- **чтению данных** — `spark.read` (DataFrameReader);
- **записи** — через методы DataFrame (df.write);
- **выполнению SQL** — `spark.sql()`;
- **каталогу** — `spark.catalog` (список таблиц, баз данных, кэширование);
- при необходимости к **SparkContext** — `spark.sparkContext` (для RDD, настроек и т.д.).

Весь код приложения, работающий с данными, обычно получает один экземпляр SparkSession и использует его для создания и обработки DataFrame. В интерактивной оболочке pyspark сессия создаётся автоматически и доступна в переменной **spark**. В скрипте сессию создают явно. См. [§2.1](chapter-02-01.md), [§3.2](chapter-03-02.md), [Глоссарий](glossary.md).

---

## 5.2.2. Создание через builder и getOrCreate()

Стандартный способ получить SparkSession — **builder**:

```python
from pyspark.sql import SparkSession

spark = SparkSession.builder \
    .appName("MyApp") \
    .getOrCreate()
```

**SparkSession.builder** — объект для настройки сессии; цепочкой вызовов задают имя приложения, мастер, конфигурацию и т.д. Завершающий вызов **getOrCreate()** создаёт сессию, если её ещё нет в текущем контексте, или возвращает существующую (например, уже созданную оболочкой pyspark). Так скрипт можно запускать и отдельно (сессия создаётся), и из оболочки (используется текущая сессия). См. [Глоссарий](glossary.md).

Явное создание без getOrCreate — через **`.getOrCreate()`** заменить на **`.create()`** (или устаревший метод в зависимости от версии). Тогда каждый вызов создаёт новую сессию; в одном приложении обычно достаточно одной. Закрыть сессию в конце скрипта: **`spark.stop()`**. См. [§2.1](chapter-02-01.md).

## 5.2.3. Конфигурация: имя приложения, мастер, память и ядра

Перед **getOrCreate()** можно задать параметры через методы builder:

- **`.appName("имя")`** — имя приложения; отображается в Spark UI и в логах кластера (YARN, Kubernetes), помогает идентифицировать джобу.
- **`.master("url")`** — URL мастера: **`local`**, **`local[N]`**, **`local[*]`** для локального режима (N потоков или по числу ядер); **`spark://host:7077`** для standalone; **`yarn`** для YARN; **`k8s://...`** для Kubernetes. Если не указать, в скрипте может использоваться значение по умолчанию (часто local) или из конфигурации. См. [§2.5](chapter-02-05.md), [Глоссарий](glossary.md).
- **`.config("key", "value")`** — произвольная конфигурация Spark. Часто задают:
  - **`spark.driver.memory`** — память драйвера (например, `"2g"`);
  - **`spark.executor.memory`** — память исполнителя (для локального режима может трактоваться как общая память процесса);
  - **`spark.sql.shuffle.partitions`** — число партиций после shuffle по умолчанию (например, `200` или меньше для малых данных).

Пример с конфигурацией для локального режима:

```python
spark = SparkSession.builder \
    .appName("ETL") \
    .master("local[*]") \
    .config("spark.driver.memory", "2g") \
    .config("spark.sql.shuffle.partitions", "8") \
    .getOrCreate()
```

В кластере часть параметров (число исполнителей, память исполнителей) часто задают через spark-submit или конфигурацию кластера, а в коде оставляют только appName и при необходимости конфиги, специфичные для приложения. См. [§2.5](chapter-02-05.md), [Глоссарий](glossary.md).

## 5.2.4. spark.read и spark.sql

После создания сессии основные операции:

- **`spark.read`** — объект DataFrameReader; далее вызывают `.format(...).load(path)` или короткие методы `.parquet(path)`, `.csv(path, ...)`, `.json(path)` и т.д. Возвращается DataFrame. См. [§4.1](chapter-04-01.md), [§6.1](chapter-06-01.md).
- **`spark.sql("SELECT ...")`** — выполнение SQL-запроса; возвращается DataFrame. Таблицы в запросе должны быть зарегистрированы (createOrReplaceTempView) или существовать в каталоге. См. [§3.3](chapter-03-03.md).

Пример:

```python
df = spark.read.parquet("/data/events")
df.createOrReplaceTempView("events")
summary = spark.sql("SELECT date, COUNT(*) AS cnt FROM events GROUP BY date")
summary.show()
```

См. [Глоссарий](glossary.md).

## 5.2.5. Каталог и завершение сессии

**`spark.catalog`** даёт доступ к списку баз данных, таблиц и представлений, к кэшированию таблиц и т.д. (см. [§3.4](chapter-03-04.md)). Для повседневных скриптов чаще используют только read, sql и методы DataFrame.

В конце приложения (скрипта) сессию рекомендуется **остановить**, чтобы освободить ресурсы JVM: **`spark.stop()`**. В интерактивной оболочке это делают перед выходом или при перезапуске ядра. После stop использовать объект spark нельзя; для новых операций нужна новая сессия. См. [§2.1](chapter-02-01.md).

---

## Ключевое

- **SparkSession** — единая точка входа: read, sql, catalog, при необходимости sparkContext; в оболочке pyspark создаётся автоматически (переменная `spark`), в скрипте — явно через builder.
- **Создание:** `SparkSession.builder.appName(...).master(...).config(...).getOrCreate()`; getOrCreate возвращает существующую сессию или создаёт новую.
- **Конфигурация:** appName (имя в UI), master (local, local[*], yarn, spark://...), config (driver.memory, executor.memory, sql.shuffle.partitions и др.); в кластере часть настроек задаётся через spark-submit.
- Через **spark.read** читают данные в DataFrame; через **spark.sql** выполняют SQL; результат в обоих случаях — DataFrame.
- В конце скрипта вызывать **spark.stop()** для освобождения ресурсов.

В [§5.3](chapter-05-03.md) мы разберём создание DataFrame в PySpark из списка словарей и из файла, просмотр схемы и первые операции: выбор столбцов и фильтрация.
