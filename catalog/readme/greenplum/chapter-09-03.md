# §9.3 Форматы: Parquet, ORC, Avro

В [§9.2](chapter-09-02.md) мы разобрали доступ к HDFS и облачным хранилищам через серверы PXF. Данные во внешних источниках хранятся в разных **форматах**; от выбора формата зависят объём передаваемых данных и возможность переноса фильтрации в источник. В этом разделе — три распространённых формата: **Parquet**, **ORC** и **Avro** (колоночное и бинарное хранение), поддержка в PXF **predicate pushdown** и **column projection**, и краткие рекомендации по выбору формата. Создание внешних таблиц под эти форматы — в [§9.4](chapter-09-04.md). По [Tanzu Greenplum PXF — Filter Pushdown](https://techdocs.broadcom.com/us/en/vmware-tanzu/data-solutions/tanzu-greenplum-platform-extension-framework/6-10/gp-pxf/filter_push.html), [Column Projection](https://techdocs.broadcom.com/us/en/vmware-tanzu/data-solutions/tanzu-greenplum-platform-extension-framework/6-10/gp-pxf/col_project.html), [Reading and Writing HDFS Parquet Data](https://techdocs.broadcom.com/us/en/vmware-tanzu/data-solutions/tanzu-greenplum-platform-extension-framework/6-10/gp-pxf/hdfs_parquet.html).

## 9.3.1. Parquet

**Parquet** — колоночный бинарный формат: данные по каждому столбцу хранятся отдельно, что хорошо для аналитических запросов с выборкой немногих столбцов и для сжатия (повторяющиеся значения в колонке эффективно сжимаются). Файл содержит встроенную схему (типы столбцов), разбит на **row groups** и **страницы** (pages); поддерживаются словарное кодирование и сжатие (snappy, gzip, lzo). См. документацию PXF и Apache Parquet.

В PXF для Parquet используются профили **hdfs:parquet**, **s3:parquet**, **wasbs:parquet**, **adl:parquet**, **gs:parquet** (в зависимости от коннектора). Формат задаётся как **CUSTOM** с форматтером **pxfwritable_import** (чтение) или **pxfwritable_export** (запись). PXF поддерживает чтение и запись примитивных типов Parquet и одномерных массивов (LIST); маппинг типов Parquet и Greenplum описан в документации (например, INT32 → integer, INT64 → bigint, UTF8 → text). При записи можно задать код сжатия (COMPRESSION_CODEC), размер row group (ROWGROUP_SIZE), версию Parquet (v1/v2) и другие опции в LOCATION. См. документацию PXF по hdfs:parquet и объектным хранилищам.

**Column projection** и **predicate pushdown** для профилей **\*:parquet** в PXF поддерживаются: запрос возвращает только нужные столбцы, а условия WHERE могут применяться на стороне чтения (по статистике в файле), что снижает объём данных, передаваемых в Greenplum. Параметр **gp_external_enable_filter_pushdown** (по умолчанию on) включает или отключает pushdown для всех внешних таблиц. Для Parquet pushdown поддерживается по типам и операторам, указанным в документации PXF (сравнения, IS NULL, IN, AND, OR, NOT); для отдельных типов (например, fixed_len_byte_array, int96) pushdown может быть недоступен. См. документацию PXF по filter pushdown.

## 9.3.2. ORC

**ORC** (Optimized Row Columnar) — колоночный формат из экосистемы Hadoop/Hive: данные разбиты на **stripes**, внутри полосы — колоночное хранение с индексами и статистикой (min/max по столбцам), что позволяет пропускать целые полосы при фильтрации. Поддерживаются сжатие (ZLIB, Snappy и др.) и сложные типы. См. документацию Apache ORC и PXF.

В PXF профили **hdfs:orc**, **s3:orc**, **wasbs:orc**, **adl:orc**, **gs:orc**, а также **hive:orc** и **hive** (для таблиц Hive в формате ORC). Формат задаётся как CUSTOM (pxfwritable_import/export). **Column projection** поддерживается для перечисленных коннекторов и профилей. **Predicate pushdown** для **\*:orc** поддерживается: фильтрация по статистике на уровне файла, полосы (stripe) и при необходимости строк; для **hive:orc** и **hive** (ORC) поддерживаются сравнения, IS NULL, IN, AND, OR; при использовании Hive возможно **partition pruning** по ключу партиции. См. документацию PXF по ORC и filter pushdown.

Выбор между **hdfs:orc** и **hive:orc**: если данные — файлы ORC в HDFS с известным путём и без метаданных Hive, используют hdfs:orc; если данные хранятся в таблице Hive (в том числе партиционированной) или нужны сложные типы и метаданные Hive — hive или hive:orc. См. [§9.2](chapter-09-02.md).

## 9.3.3. Avro

**Avro** — бинарный формат с явной схемой (JSON): каждая запись может содержать вложенные структуры; схема хранится в файле или передаётся отдельно. Данные часто хранятся построчно (row-based), хотя возможна и колоночная компоновка. Avro удобен для обмена данными и стриминга (Kafka и др.). См. документацию Apache Avro.

В PXF профили **hdfs:avro**, **s3:avro**, **wasbs:avro**, **adl:avro**, **gs:avro** — чтение и запись. Формат задаётся как CUSTOM с соответствующим форматтером. **Predicate pushdown** для профилей **\*:avro** в PXF **не поддерживается**: условия WHERE применяются после передачи данных в Greenplum. **Column projection** для Avro в документации PXF указан для коннектора HDFS (hdfs:avro); для остальных коннекторов и сценариев данные могут читаться целиком. Поэтому при больших объёмах и сильной фильтрации предпочтительны Parquet или ORC, где pushdown и проекция уменьшают объём передаваемых данных. См. документацию PXF по Avro и filter pushdown.

## 9.3.4. Predicate pushdown и column projection: сводка

**Predicate pushdown** (filter pushdown) — перенос условий WHERE в внешний источник: PXF передаёт предикат коннектору, и коннектор (или сам формат) отфильтровывает данные до отправки в Greenplum. Это сокращает объём данных по сети и ускоряет запросы. Включается параметром **gp_external_enable_filter_pushdown** (по умолчанию on). Работает только если источник и профиль поддерживают pushdown; для *:text, *:csv, *:json, *:avro (в общем случае) pushdown не поддерживается. Поддерживаемые типы данных и операторы (сравнение, IN, IS NULL, AND, OR, NOT) зависят от профиля; детали — в документации PXF. См. [§9.1](chapter-09-01.md).

**Column projection** в PXF включена по умолчанию: в Greenplum возвращаются только столбцы, указанные в SELECT. Если коннектор и формат поддерживают проекцию (Parquet, ORC на HDFS и объектных хранилищах, Hive, JDBC), с источника читаются только нужные колонки, что особенно выгодно для колоночных форматов. Если источник не поддерживает проекцию, PXF читает все столбцы и отбрасывает лишние после передачи. См. документацию PXF по column projection.

## 9.3.5. Выбор формата

- **Parquet** — универсальный колоночный формат для аналитики; хорошая поддержка в PXF (чтение/запись, pushdown, проекция) на HDFS и объектных хранилищах; широко используется в Hadoop и облаке. Выбирают для новых датасетов и запросов с фильтрацией и выборкой части столбцов.
- **ORC** — колоночный формат с сильной интеграцией в Hive; stripe-структура и статистика дают эффективный pushdown; подходит для данных в Hive и для запросов с фильтрами по ключам партиций и столбцам.
- **Avro** — схема и вложенные структуры; удобен для событийных и потоковых данных; в PXF без pushdown по предикатам, поэтому для тяжёлой аналитики по большим объёмам менее выгоден, чем Parquet/ORC. Используют когда данные уже в Avro или нужна совместимость с Kafka/стриминговыми конвейерами.
- **Текст (text, csv)** — простой обмен и отладка; pushdown и проекция не поддерживаются, весь объём читается и фильтруется в Greenplum. Подходит для малых объёмов и простых загрузок.

---

## Ключевое

- **Parquet** и **ORC** — колоночные форматы; в PXF поддерживаются **column projection** и **predicate pushdown** для профилей *:parquet и *:orc (и hive:orc), что снижает объём передаваемых данных.
- **Avro** — бинарный формат со схемой; в PXF pushdown по предикатам для *:avro не поддерживается; проекция поддерживается для hdfs:avro.
- **Predicate pushdown** управляется параметром **gp_external_enable_filter_pushdown**; для аналитических запросов по большим внешним данным предпочтительны Parquet или ORC.

В [§9.4](chapter-09-04.md) мы разберём **CREATE EXTERNAL TABLE** и **LOCATION** в деталях: синтаксис, примеры для PXF, запросы к внешним данным как к обычным таблицам.
