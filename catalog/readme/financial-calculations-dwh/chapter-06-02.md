# §6.2 Факты: обороты, остатки, движения

В [§6.1](chapter-06-01.md) мы ввели звёздную схему и фактовую таблицу движений (проводок). В моделировании DWH различают **типы фактов**: транзакционные (каждая строка — одно событие), **периодические снимки** (состояние на дату) и **накопительные снимки**. Здесь мы разберём, как обороты, остатки и движения представлены в этих типах: транзакционный факт проводок, периодический снимок остатков на конец периода и при необходимости накопительный снимок. Измерения и слои — в [§6.3](chapter-06-03.md) и [§6.4](chapter-06-04.md). См. [Глоссарий](glossary.md).

---

## 6.2.1. Транзакционные факты (движения, проводки)

**Транзакционный факт** — таблица, в которой **одна строка соответствует одному событию** (одна проводка, одна операция). Каждая запись добавляется при появлении события и не обновляется (append-only в идеале). Меры — суммы дебет/кредит, количество; ключи измерений — счёт, контрагент, дата и т.д.

Для финансов это **факт движений (проводок)** из §6.1: каждая строка — одна проводка. Из него считаются обороты за период (SUM по дате и счёту), остатки на дату (начальное сальдо + оборот) и нарастающий итог ([§4.1](chapter-04-01.md)–[§4.3](chapter-04-03.md)). Детализация максимальная; объём данных растёт с каждой проводкой. Хранение сумм — NUMERIC ([§2.3](chapter-02-03.md)).

Транзакционный факт — **источник истины** для расчёта оборотов и остатков; снимки остатков и агрегаты по периодам могут быть производными (витрины, материализованные представления или отдельные таблицы снимков для ускорения). См. [Глоссарий](glossary.md).

---

## 6.2.2. Периодический снимок остатков

**Периодический снимок** (periodic snapshot) — таблица фактов, в которой **одна строка — состояние на конец периода** по одному объекту (счёт, контрагент). Например, одна строка = остаток по счёту на конец месяца. Меры: остаток (сальдо), при необходимости оборот за период; ключи измерений: счёт, дата снимка (конец месяца), при необходимости контрагент.

Такую таблицу заполняют **регулярно** (ежедневно, ежемесячно) расчётом из транзакционного факта проводок или из операционной системы. Запросы «остаток на дату» по снимкам выполняются без перебора всех проводок до этой даты — достаточно выбрать снимок на нужную дату (или ближайшую предшествующую). Минус: дублирование логики расчёта остатка (источник истины — по-прежнему проводки или регламент загрузки снимка); нужно следить за согласованностью снимка с проводками. См. [§4.2](chapter-04-02.md) (остатки на дату).

Типичная структура снимка остатков:

| Поле        | Тип           | Описание                    |
|-------------|---------------|-----------------------------|
| account_id  | INT           | Счёт (FK)                   |
| snapshot_date | DATE        | Дата снимка (конец периода) |
| balance     | NUMERIC(18,2) | Остаток на дату             |
| turnover_dt | NUMERIC(18,2) | Оборот по дебету за период (опционально) |
| turnover_ct | NUMERIC(18,2) | Оборот по кредиту за период (опционально) |

Период снимка (день, месяц) задаётся регламентом; ключ строки — (account_id, snapshot_date) при одном снимке на счёт на дату. См. [Глоссарий](glossary.md).

## 6.2.3. Обороты за период как агрегат или как снимок

**Обороты за период** ([§4.1](chapter-04-01.md)) можно получать двумя способами:

1. **На лету из транзакционного факта:** GROUP BY account_id, period; SUM(amount_dt), SUM(amount_ct). Актуально всегда, но при больших объёмах и частых запросах может быть дорого.
2. **Из предвычисленной таблицы (агрегат/снимок):** таблица «обороты по счёту по месяцу» — одна строка на (счёт, месяц), меры — оборот дебет, оборот кредит. Заполняется пайплайном (из факта проводок); запросы к оборотам обращаются к этой таблице. Плюс — скорость; минус — нужно поддерживать актуальность при поступлении новых проводок.

Выбор зависит от объёма данных, частоты обновления и требований к актуальности. Для отчётности «на конец месяца» часто достаточно ежемесячного снимка оборотов и остатков; для оперативных дашбордов — расчёт из транзакционного факта или инкрементальное обновление агрегатов. См. [§6.4](chapter-06-04.md) (слои: где считаются обороты и остатки).

## 6.2.4. Накопительный снимок

**Накопительный снимок** (accumulating snapshot) — таблица, в которой **одна строка — один объект (например, договор, заявка)**, а колонки — даты и меры на ключевых этапах жизненного цикла. Строка обновляется при переходе объекта на следующий этап. В контексте финансов накопительный снимок применяется реже, чем транзакционный факт и периодический снимок; пример — заявка на кредит: дата подачи, дата одобрения, дата выдачи, суммы на каждом этапе.

Для оборотов и остатков по счетам накопительный снимок обычно не используют; достаточно транзакционного факта проводок и при необходимости периодического снимка остатков. Упоминаем для полноты типов фактов. См. [Глоссарий](glossary.md).

## 6.2.5. Сводка: какой тип факта для чего

| Потребность              | Тип факта              | Строка =                          |
|--------------------------|------------------------|------------------------------------|
| Проводки, детальные движения | Транзакционный         | Одна проводка                     |
| Остаток на конец периода | Периодический снимок   | Остаток по счёту на дату снимка   |
| Обороты за период        | Транзакционный (на лету) или агрегат | Оборот по счёту за период (агрегат) |
| Жизненный цикл объекта   | Накопительный снимок   | Один объект, обновляется по этапам |

Транзакционный факт проводок — основа для финансовых расчётов в DWH; периодический снимок остатков и таблицы оборотов по периодам — производные для ускорения отчётов и согласованы с правилами расчёта из глав 1–5. См. [§6.4](chapter-06-04.md).

## 6.2.6. Типичные ошибки

- **Считать снимок остатков источником истины без привязки к проводкам:** при расхождении снимка и суммы проводок до даты снимка непонятно, что править; источник истины — проводки или явный регламент загрузки снимка с проверкой.
- **Дублировать проводки в снимке:** в снимке должны быть только агрегированные остатки (и при необходимости обороты за период), а не копия каждой проводки.
- **Хранить обороты и остатки в одной таблице без разделения по типу:** транзакционный факт (проводки) и периодический снимок (остатки) лучше разделять по таблицам или по слоям, чтобы не смешивать «одна строка = событие» и «одна строка = состояние на дату».

## Ключевое

- **Транзакционный факт** — одна строка = одно событие (проводка); из него считаются обороты, остатки и нарастающий итог; источник истины для движений.
- **Периодический снимок** — одна строка = состояние на конец периода (остаток по счёту на дату); ускоряет запросы «остаток на дату»; должен быть согласован с проводками или с регламентом загрузки.
- **Обороты за период** — либо на лету из транзакционного факта (GROUP BY), либо из предвычисленной таблицы оборотов по периодам; выбор по объёму и частоте запросов.
- **Накопительный снимок** — одна строка на объект, обновляется по этапам; для оборотов/остатков по счетам обычно не используется.

В [§6.3](chapter-06-03.md) мы разберём измерения: справочники счетов, контрагентов, периоды, иерархия и SCD для истории изменений.
