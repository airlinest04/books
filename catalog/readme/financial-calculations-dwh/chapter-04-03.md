# §4.3 Нарастающий итог (cumulative sum)

В [§4.2](chapter-04-02.md) мы разобрали расчёт остатков на дату через начальное сальдо и обороты. **Нарастающий итог** (cumulative sum) — это сумма значений по строкам с накоплением: для каждой строки результат равен сумме всех предыдущих (в заданном порядке) плюс текущая строка. В SQL его удобно считать **оконной функцией** SUM() OVER (ORDER BY ...). Здесь мы вводим нарастающий итог, синтаксис с PARTITION BY и рамкой окна и применение к оборотам и остаткам в отчётах. Сравнение с GROUP BY и производительность — в [§4.4](chapter-04-04.md).

---

## 4.3.1. Что такое нарастающий итог

**Нарастающий итог** (cumulative sum, running total) — для упорядоченного набора строк сумма некоторого числового поля по «текущей и всем предыдущим» строкам. В каждой строке вы получаете не итог по группе, а **накопленную** сумму на момент этой строки. См. [Глоссарий](glossary.md).

Пример: таблица оборотов по месяцам (январь 100, февраль 50, март 80). Нарастающий итог: январь — 100, февраль — 150, март — 230. Такой ряд нужен для графиков «оборот с начала года», для расчёта остатка по счёту по месяцам без отдельного подзапроса за каждый период и для отчётов «план/факт с накоплением».

---

## 4.3.2. SUM() OVER (ORDER BY ...)

В стандарте SQL и в Oracle, PostgreSQL нарастающий итог задаётся оконной функцией:

```sql
SUM(amount) OVER (ORDER BY date_col)
```

Для каждой строки окно — это **текущая строка и все строки с меньшим (или равным) значением** `date_col`. Порядок строк по `date_col` определяет, что считается «предыдущим». Результат SUM — сумма `amount` по этому окну. Если порядок не уникален (несколько строк с одной датой), все они получают один и тот же нарастающий итог на эту дату (сумма по всем строкам до этой даты включительно по порядку).

Пример (PostgreSQL): проводки по счёту, нарастающий итог оборота (дебет − кредит) по дате.

```sql
SELECT
    account_id,
    post_date,
    amount_dt - amount_ct AS movement,
    SUM(amount_dt - amount_ct) OVER (
        PARTITION BY account_id
        ORDER BY post_date, id
    ) AS balance_running
FROM ledger.postings
WHERE account_id = :account_id
ORDER BY post_date, id;
```

`PARTITION BY account_id` — нарастающий итог считается **отдельно по каждому счёту**; порядок внутри партиции задаётся `ORDER BY post_date, id` (при равных датах — по id для детерминированности). В каждой строке `balance_running` — остаток по счёту на момент этой проводки (при нулевом начальном сальдо). Среда: PostgreSQL 15, Oracle 21c (синтаксис тот же).

## 4.3.3. Рамка окна: ROWS BETWEEN и RANGE

По умолчанию при `ORDER BY` в оконной функции рамка окна в стандарте SQL — «от начала партиции до текущей строки» (RANGE UNBOUNDED PRECEDING или эквивалент). То есть нарастающий итог «с начала» до текущей строки включительно.

Явно рамку можно задать так:

- **ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW** — все строки от первой в партиции до текущей (в порядке ORDER BY). Итог нарастающий.
- **RANGE BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW** — то же по значению порядка: все строки с значением ORDER BY не больше текущего. При одном значении даты у нескольких строк все они включаются в окно.

Для «классического» нарастающего итога достаточно `SUM(...) OVER (PARTITION BY ... ORDER BY ...)` без явной рамки — по умолчанию будет от начала партиции до текущей строки. Если нужна **скользящая** сумма только за последние N строк или за последние N дней, задают рамку, например ROWS BETWEEN N PRECEDING AND CURRENT ROW. См. [§4.4](chapter-04-04.md).

## 4.3.4. Применение к оборотам и остаткам

**Обороты по периодам с нарастающим итогом:** таблица уже агрегирована по счёту и месяцу (обороты за месяц); нужна колонка «оборот с начала года». Добавляем SUM(turnover) OVER (PARTITION BY account_id, year ORDER BY month).

**Остаток по проводкам без отдельного подзапроса:** каждая строка — проводка; нарастающий итог (дебет − кредит) по ORDER BY post_date даёт остаток после каждой проводки (при нулевом начальном сальдо). Если начальное сальдо ненулевое, прибавляем его к первому значению или добавляем «виртуальную» строку с начальным сальдо и датой начала периода.

**Отчёты «план/факт с накоплением»:** по месяцам хранятся плановые и фактические обороты; нарастающий итог по каждому показателю — через SUM() OVER (ORDER BY month).

Во всех случаях порядок (ORDER BY) должен быть **детерминированным**: при равных датах — дополнительный ключ (id, id проводки), иначе порядок строк и нарастающий итог могут «плыть» между запусками.

## 4.3.5. Начальное сальдо и нарастающий итог

Если у счёта есть **начальное сальдо** на дату \(S_0\), остаток после каждой проводки = начальное сальдо + нарастающий итог оборотов от \(S_0\). Варианты реализации:

1. В подзапросе оставить только проводки с датой > \(S_0\); в наружном запросе к нарастающему итогу прибавить начальное сальдо (одно для всех строк партиции).
2. Добавить в набор строк «искусственную» строку с датой \(S_0\) и суммой = начальное сальдо (остальные поля движения = 0); ORDER BY по дате; нарастающий итог тогда сразу даёт остаток на каждую дату.

Пример (идея): CTE с проводками + одна строка с начальным сальдо, затем SUM(...) OVER (ORDER BY post_date). Среда и типы — как в витрине (NUMERIC для сумм).

## 4.3.6. Типичные ошибки

- **Не задать PARTITION BY при нескольких счетах:** без PARTITION BY нарастающий итог считается по всему набору строк; нужен PARTITION BY account_id (или по другой группировке), чтобы итог был свой у каждого счёта.
- **Неоднозначный ORDER BY:** при равных датах порядок может меняться; добавить в ORDER BY уникальный ключ (id проводки).
- **Путать «нарастающий итог» и «итог по группе»:** GROUP BY даёт одну строку на группу с общей суммой; оконная функция оставляет все строки и добавляет колонку с накопленной суммой.

---

## Ключевое

- **Нарастающий итог** (cumulative sum) — сумма значений по текущей и всем предыдущим строкам в заданном порядке; в SQL задаётся **SUM(...) OVER (PARTITION BY ... ORDER BY ...)**.
- **PARTITION BY** разбивает строки на группы (например, по счёту); внутри каждой группы нарастающий итог считается отдельно. **ORDER BY** задаёт порядок накопления (дата, id).
- По умолчанию рамка окна — от начала партиции до текущей строки; при необходимости её задают явно (ROWS/RANGE BETWEEN).
- Применение: обороты с накоплением за год, остаток по счёту после каждой проводки, отчёты план/факт с накоплением. При ненулевом начальном сальдо его прибавляют к нарастающему итогу или вводят отдельной строкой в набор.

В [§4.4](chapter-04-04.md) мы сравним паттерны с оконными функциями и с GROUP BY и разберём примеры на Oracle и PostgreSQL.
