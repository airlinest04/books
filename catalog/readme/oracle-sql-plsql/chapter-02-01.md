# §2.1 CREATE TABLE

В [§1.4](chapter-01-04.md) мы выполнили первый запрос SELECT к таблицам и представлениям. Чтобы хранить свои данные, нужно создавать **таблицы** — определять их имена, имена столбцов и типы данных. В этом разделе мы разберём оператор **CREATE TABLE**: базовый синтаксис, **правила именования** таблиц и столбцов в Oracle, а также **кавычки и регистр** — почему имена по умолчанию оказываются в верхнем регистре и когда уместно использовать двойные кавычки. Типы данных столбцов (NUMBER, VARCHAR2, DATE и др.) подробно рассмотрены в [§2.2](chapter-02-02.md); ограничения целостности (PRIMARY KEY, NOT NULL и т.д.) — в [§2.3](chapter-02-03.md). См. [Глоссарий](glossary.md).

---

## 2.1.1. Базовый синтаксис CREATE TABLE

Оператор **CREATE TABLE** создаёт таблицу в текущей схеме (под пользователем, от имени которого выполняется запрос). Минимальная форма:

```sql
CREATE TABLE имя_таблицы (
  имя_столбца1 тип_данных,
  имя_столбца2 тип_данных,
  ...
);
```

В скобках перечисляются столбцы через запятую; у каждого столбца указывается имя и тип данных. Типы данных (NUMBER, VARCHAR2, DATE и т.д.) задают, какие значения можно хранить в столбце; их мы разберём в [§2.2](chapter-02-02.md). Здесь достаточно примера с простыми типами:

```sql
CREATE TABLE persons (
  id    NUMBER,
  name  VARCHAR2(100),
  birth DATE
);
```

Таблица `persons` создаётся в вашей схеме с тремя столбцами. После выполнения таблица появляется в USER_TABLES; к ней можно обращаться в SELECT, INSERT, UPDATE, DELETE. Создание таблицы в другой схеме возможно при наличии привилегии CREATE ANY TABLE и указании имени схемы: `CREATE TABLE другая_схема.имя_таблицы (...)`; для обычной разработки таблицы создают в своей схеме. См. [Глоссарий](glossary.md).

## 2.1.2. Правила именования: некавычковые идентификаторы

Имена таблиц и столбцов в Oracle задаются **идентификаторами**. Если идентификатор не заключён в двойные кавычки (**некавычковый**, unquoted), действуют следующие правила (по документации Oracle). См. [Глоссарий](glossary.md).

- **Длина:** не более **30 байт** (в версиях с параметром COMPATIBLE 12.2 и выше допускается до 128 байт для части объектов; для таблиц и столбцов в типичных установках по-прежнему часто ограничение 30 символов). Один символ в кодировке базы (например, один байт в AL32UTF8 для символов Latin) считается как один байт; многобайтовые символы увеличивают длину на несколько байт.
- **Первый символ:** должен быть **буквой** (латинская A–Z, a–z или символ из набора языка базы в зависимости от настроек).
- **Остальные символы:** только буквы, цифры и три специальных символа: **подчёркивание (_)**, **доллар ($)**, **решётка (#)**. Пробелы и дефис в некавычковом имени недопустимы.
- **Зарезервированные слова:** имя не должно совпадать с зарезервированным словом SQL или PL/SQL (SELECT, TABLE, NUMBER, DATE, ORDER и т.д.). Список зарезервированных слов приведён в документации Oracle (Oracle Database SQL Language Reference). При необходимости использовать такое слово — только в кавычках (см. ниже).

Примеры допустимых некавычковых имён: `persons`, `MY_TABLE`, `emp_2024`, `tab$tmp`. Недопустимые без кавычек: `my-table` (дефис), `2nd_column` (начинается с цифры), `first name` (пробел). Имена вида `First_Name` допустимы: они трактуются так же, как `FIRST_NAME`, потому что некавычковые идентификаторы в Oracle **не чувствительны к регистру** и при хранении приводятся к **верхнему регистру**.

## 2.1.3. Регистр и хранение: некавычковые идентификаторы в верхнем регистре

В Oracle **некавычковые идентификаторы** (имена таблиц, столбцов и других объектов) **не различают регистр**: `persons`, `Persons` и `PERSONS` считаются одним и тем же именем. В словаре данных и во всех системных представлениях такие имена **хранятся в верхнем регистре**. Поэтому после создания таблицы `CREATE TABLE persons (...)` в USER_TABLES вы увидите `TABLE_NAME = 'PERSONS'`, а в запросах можно писать `SELECT * FROM persons`, `FROM PERSONS` или `FROM Persons` — все варианты корректны.

Практический вывод: при обращении к объектам, созданным без кавычек, удобно использовать верхний регистр в запросах (например, `SELECT * FROM USER_TABLES WHERE TABLE_NAME = 'PERSONS'`), чтобы не путать с регистрозависимыми именами, созданными в кавычках. В условиях сравнения с данными словаря (USER_TABLES, USER_TAB_COLUMNS) имена объектов обычно сравнивают в верхнем регистре: `TABLE_NAME = 'MY_TABLE'` или `UPPER(table_name) = 'my_table'`.

## 2.1.4. Кавычковые идентификаторы: сохранение регистра и чувствительность к регистру

Если имя таблицы или столбца заключить в **двойные кавычки** при создании, Oracle сохраняет **точный регистр** и при дальнейшем обращении к такому объекту кавычки **обязательны**. Такие имена называют **кавычковыми идентификаторами** (quoted identifiers). См. [Глоссарий](glossary.md).

Пример:

```sql
CREATE TABLE "MyTable" (
  "id"    NUMBER,
  "Name"  VARCHAR2(100)
);
```

Таблица будет храниться под именем `MyTable` (с заглавной M и T), столбцы — `id` (строчные) и `Name` (с заглавной N). Обращение без кавычек к такому объекту приведёт к ошибке или к поиску другого объекта: Oracle ищет некавычковый идентификатор, приводит его к верхнему регистру и находит `MYTABLE`, а не `MyTable`. Поэтому после создания с кавычками обращаться нужно так:

```sql
SELECT "id", "Name" FROM "MyTable";
```

Правила для кавычковых идентификаторов: внутри кавычек допустимы любые буквы, цифры и специальные символы, допустимые в строке идентификатора (кавычка внутри имени экранируется удвоенной кавычкой). Первый символ по-прежнему должен быть буквой или подчёркиванием. Длина ограничена тем же лимитом (30 или 128 байт в зависимости от версии и параметров).

Когда кавычки уместны: если требуется строгое соответствие внешним системам (например, выгрузка с именами в нижнем регистре) или необходимо использовать слово, совпадающее с зарезервированным (например, `"SELECT"` как имя столбца — не рекомендуется, но возможно). В большинстве случаев в Oracle принято **не использовать кавычки** для имён таблиц и столбцов и писать имена в верхнем или смешанном регистре при создании, зная, что они всё равно сохранятся в верхнем регистре. Это избавляет от необходимости везде указывать кавычки при обращении.

## 2.1.5. Примеры: таблица без кавычек и проверка в словаре

Создаём таблицу с некавычковыми именами:

```sql
CREATE TABLE products (
  id          NUMBER,
  product_name VARCHAR2(200),
  price       NUMBER(10,2),
  created_at  DATE
);
```

Проверка в словаре данных — имена хранятся в верхнем регистре:

```sql
SELECT column_name, data_type
  FROM user_tab_columns
 WHERE table_name = 'PRODUCTS'
 ORDER BY column_id;
```

Результат покажет столбцы `ID`, `PRODUCT_NAME`, `PRICE`, `CREATED_AT` и их типы. Условие `table_name = 'PRODUCTS'` корректно, потому что имя таблицы в словаре в верхнем регистре. Если бы таблица была создана как `"Products"`, в USER_TABLES было бы `TABLE_NAME = 'Products'`, и обращаться к ней пришлось бы как `FROM "Products"`.

Удаление таблицы (если нужно пересоздать): `DROP TABLE products;` (или `DROP TABLE "MyTable";` для кавычковой таблицы). Подробнее изменение и удаление структур — в [§2.4](chapter-02-04.md).

## 2.1.6. Типичные ошибки при именовании таблиц и столбцов

- **Использовать дефис в имени без кавычек:** `my-table` недопустимо; Oracle воспримет минус как оператор. Нужно `my_table` или `"my-table"` (тогда везде с кавычками).
- **Начинать имя с цифры без кавычек:** `2nd_column` недопустимо. Варианты: `col_2nd` или `"2nd_column"` (с кавычками).
- **Ожидать сохранение нижнего регистра без кавычек:** `CREATE TABLE mytable (...)` сохранит таблицу как `MYTABLE`. Нижний регистр в запросах допустим при обращении, но в словаре данных имя будет в верхнем регистре.
- **Забыть кавычки при обращении к объекту, созданному с кавычками:** если создали `"MyTable"`, то `SELECT * FROM MyTable` приведёт к поиску объекта `MYTABLE` и ошибке «table or view does not exist», если такой таблицы нет. Нужно писать `FROM "MyTable"`.
- **Превысить длину идентификатора:** имя длиннее 30 символов (в обычных настройках) приведёт к ORA-00972. Сократите имя или используйте допустимую длину для вашей версии.
- **Использовать зарезервированное слово без кавычек:** имя вроде `TABLE` или `NUMBER` как имя таблицы или столбца вызовет ошибку или неоднозначность. Либо переименуйте (например, `tables_list`), либо используйте кавычки (`"TABLE"`), но предпочтительнее избегать зарезервированных слов в именах.

## Ключевое

- **CREATE TABLE имя_таблицы (столбец тип, ...);** — создание таблицы в текущей схеме. Имена столбцов и типы данных задаются в списке через запятую; типы данных подробно в §2.2.
- **Некавычковые идентификаторы:** до 30 байт (в части версий — больше), первый символ — буква, далее буквы, цифры, _, $, #; **регистр не различается**, при хранении приводятся к **верхнему регистру**.
- **Кавычковые идентификаторы** (в двойных кавычках): **сохраняют точный регистр**; при любом обращении к объекту кавычки **обязательны**. Используйте кавычки только при необходимости (совместимость с внешними системами, обход зарезервированного слова).
- В запросах к словарю данных (USER_TABLES, USER_TAB_COLUMNS) имена объектов сравнивайте в верхнем регистре, если объекты созданы без кавычек.
- Избегайте дефиса и пробелов в именах без кавычек; не начинайте с цифры; не используйте зарезервированные слова без кавычек.

В [§2.2](chapter-02-02.md) мы разберём типы данных Oracle: NUMBER, VARCHAR2, CHAR, DATE, TIMESTAMP, CLOB, BLOB и различие VARCHAR и VARCHAR2.
