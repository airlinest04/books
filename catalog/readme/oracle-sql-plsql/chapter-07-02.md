# §7.2 UNION, UNION ALL, INTERSECT, MINUS

В [§7.1](chapter-07-01.md) мы разобрали CTE (WITH) — именованные подзапросы. Операции **UNION**, **UNION ALL**, **INTERSECT** и **MINUS** объединяют результаты двух или более запросов **SELECT** в один набор строк: объединение, пересечение или разность множеств. В этом разделе — правила совместимости столбцов, различие **UNION** и **UNION ALL**, смысл **INTERSECT** и **MINUS**, порядок выполнения и скобки. Иерархические запросы (CONNECT BY) — в [§7.3](chapter-07-03.md). См. [Глоссарий](glossary.md).

---

## 7.2.1. Операции над множествами строк

Каждая из операций связывает два запроса SELECT: левый и правый. Оба должны возвращать **одинаковое число столбцов**, а типы данных соответствующих столбцов должны быть **совместимы** (Oracle приводит при необходимости, например число к строке). Имена столбцов результирующего набора берутся из **первого** запроса. См. [Глоссарий](glossary.md).

- **UNION** — объединение: все строки из обоих запросов, **дубликаты удаляются** (как DISTINCT по всей строке).
- **UNION ALL** — объединение **с сохранением дубликатов**; выполняется быстрее, если дубли не мешают.
- **INTERSECT** — пересечение: только строки, которые есть **и в первом, и во втором** результате.
- **MINUS** — разность: строки из **первого** результата, которых **нет во втором**.

Синтаксис:

```sql
SELECT ... [UNION | UNION ALL | INTERSECT | MINUS] SELECT ... [ORDER BY ...];
```

ORDER BY допускается только в конце всего выражения и применяется к итоговому набору; в нём указывают имя или номер столбца из первого SELECT. Среда: Oracle Database.

## 7.2.2. UNION и UNION ALL

**UNION** объединяет два набора строк и убирает повторяющиеся строки (сравнение по всем столбцам). **UNION ALL** объединяет без удаления дубликатов. Если гарантировано, что дублей нет (например, из разных таблиц по разным ключам), UNION ALL предпочтительнее по производительности — не требуется сортировка/хеширование для устранения дубликатов. См. [Глоссарий](glossary.md).

Пример: список идентификаторов клиентов, которые делали заказы в январе или в феврале (без дубликатов — один раз клиент):

```sql
SELECT customer_id FROM orders WHERE TO_CHAR(order_date, 'YYYY-MM') = '2024-01'
UNION
SELECT customer_id FROM orders WHERE TO_CHAR(order_date, 'YYYY-MM') = '2024-02'
ORDER BY 1;
```

Тот же запрос с **UNION ALL** вернёт клиента столько раз, сколько у него заказов в обоих месяцах суммарно. Количество и типы столбцов в обоих SELECT должны совпадать; при несовпадении используют явное приведение (TO_CHAR, TO_NUMBER) или константы (NULL, ''). Пример объединения двух списков с одной колонкой:

```sql
SELECT employee_id FROM employees WHERE department_id = 10
UNION ALL
SELECT employee_id FROM job_history WHERE department_id = 10;
```

## 7.2.3. INTERSECT и MINUS

**INTERSECT** возвращает только те строки, которые есть в результате **обоих** запросов. Удобно для задач вида «клиенты, которые заказывали и в январе, и в феврале», «сотрудники, которые и в отделе 10, и в проекте X» (если каждый запрос даёт один столбец или одинаковый набор столбцов). Дубликаты в итоге не повторяются. См. [Глоссарий](glossary.md).

**MINUS** возвращает строки из **первого** запроса, которых **нет во втором**. Порядок запросов важен: A MINUS B и B MINUS A дают разные результаты. Применение: «клиенты января, которые не заказывали в феврале», «коды отделов без сотрудников».

Пример INTERSECT: идентификаторы отделов, в которых есть и сотрудники с зарплатой > 10000, и сотрудники с комиссией (commission_pct не NULL). Упрощённо — два набора department_id по разным условиям, пересечение:

```sql
SELECT department_id FROM employees WHERE salary > 10000
INTERSECT
SELECT department_id FROM employees WHERE commission_pct IS NOT NULL;
```

Пример MINUS: отделы из справочника departments, в которых нет ни одного сотрудника:

```sql
SELECT department_id FROM departments
MINUS
SELECT department_id FROM employees;
```

## 7.2.4. Порядок операций и скобки

Несколько операций в одном выражении выполняются **слева направо**, если не заданы скобки. Приоритет у INTERSECT выше, чем у UNION и MINUS в части стандарта SQL; в Oracle для однозначности лучше явно расставлять **скобки**. См. [Глоссарий](glossary.md).

Пример: (запрос1 UNION запрос2) MINUS запрос3 — сначала объединение, затем вычитание из результата третьего набора. Без скобок запрос1 UNION запрос2 MINUS запрос3 может трактоваться как запрос1 UNION (запрос2 MINUS запрос3) в зависимости от реализации; скобки устраняют неоднозначность.

Итоговый ORDER BY — один на всё выражение, в конце:

```sql
(SELECT a FROM t1 UNION SELECT a FROM t2)
MINUS
SELECT a FROM t3
ORDER BY 1;
```

## Ключевое

- **UNION** — объединение двух наборов строк с удалением дубликатов. **UNION ALL** — объединение с сохранением дубликатов; быстрее, когда дубли не нужны. См. [Глоссарий](glossary.md).
- **INTERSECT** — только строки, присутствующие в обоих результатах. **MINUS** — строки первого результата, которых нет во втором; порядок запросов важен.
- Оба SELECT должны иметь одинаковое число столбцов; типы соответствующих столбцов совместимы. Имена столбцов результата — из первого SELECT. ORDER BY только в конце всего выражения.
- При нескольких операциях используйте скобки для явного порядка: (A UNION B) MINUS C.
