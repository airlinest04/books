# §7.1 WITH (CTE)

В [§6.3](chapter-06-03.md) мы завершили главу об агрегации и оконных функциях. В [§4.3](chapter-04-03.md) подзапрос в **FROM** использовался как «встроенное представление» — запрос в скобках с псевдонимом. **CTE (Common Table Expression)** — именованный подзапрос, заданный в начале запроса через **WITH**; он повышает читаемость и позволяет ссылаться на один и тот же набор несколько раз без дублирования. В этом разделе рассмотрим синтаксис **WITH ... AS**, несколько CTE подряд, использование CTE в основном запросе и кратко — **рекурсивный CTE**. Иерархические запросы (дерево, CONNECT BY) — в [§7.3](chapter-07-03.md). См. [Глоссарий](glossary.md).

---

## 7.1.1. Синтаксис: WITH имя AS (подзапрос)

**CTE** (Common Table Expression, обобщённое табличное выражение) — подзапрос, которому в начале запроса даётся имя; далее в основном запросе к нему обращаются по этому имени, как к таблице или представлению. В Oracle CTE задаётся предложением **WITH**. См. [Глоссарий](glossary.md).

Синтаксис одного CTE:

```sql
WITH имя_cte [(столбец1, столбец2, ...)] AS (
  подзапрос
)
SELECT ... FROM имя_cte [JOIN ...] [WHERE ...] ...;
```

Имя CTE — идентификатор (например, `recent_orders`, `dept_summary`). В скобках после имени можно перечислить **имена столбцов** результата; если не указывать, используются имена столбцов из подзапроса. Подзапрос — любой допустимый SELECT (с JOIN, WHERE, GROUP BY и т.д.). Основной запрос (SELECT, INSERT, UPDATE, DELETE, MERGE) идёт после закрывающей скобки CTE и обращается к CTE по имени в FROM или в JOIN.

Пример: отобрать заказы за последний месяц и из них выбрать те, у которых сумма больше 500:

```sql
WITH recent_orders AS (
  SELECT order_id, customer_id, order_date, total
    FROM orders
   WHERE order_date >= ADD_MONTHS(SYSDATE, -1)
)
SELECT order_id, customer_id, total
  FROM recent_orders
 WHERE total > 500
 ORDER BY total DESC;
```

Подзапрос «заказы за месяц» вынесен в CTE `recent_orders`; основной запрос читается как «из recent_orders выбрать по условию». Среда: Oracle 9i и новее (поддержка WITH).

## 7.1.2. Несколько CTE

В одном запросе можно объявить **несколько CTE** подряд: после первого блока `имя AS (подзапрос)` ставится **запятая**, затем следующее имя и подзапрос, и так далее. Последний блок перед основным запросом запятой не отделяется. Порядок объявления может быть важен, если один CTE ссылается на другой — тогда тот, на кого ссылаются, должен быть объявлен раньше. См. [Глоссарий](glossary.md).

Пример: первый CTE — сводка по отделам (сумма зарплат), второй — отделы с суммой больше 50000; основной запрос соединяет второй CTE с таблицей отделов:

```sql
WITH dept_totals AS (
  SELECT department_id, SUM(salary) AS total_sal
    FROM employees
   GROUP BY department_id
),
big_depts AS (
  SELECT department_id, total_sal
    FROM dept_totals
   WHERE total_sal > 50000
)
SELECT d.department_name, b.total_sal
  FROM departments d
  JOIN big_depts b ON d.department_id = b.department_id
 ORDER BY b.total_sal DESC;
```

Здесь `big_depts` использует результат `dept_totals`; поэтому `dept_totals` объявлен первым. В основном запросе доступны оба имени: `dept_totals` и `big_depts`.

## 7.1.3. Зачем использовать CTE

CTE не добавляет новой логики по сравнению с подзапросом в FROM, но упрощает запрос:

- **Читаемость:** сложная логика разбивается на шаги с понятными именами (recent_orders, dept_totals); основной запрос короче и яснее.
- **Повторное использование:** один и тот же CTE можно указать в FROM и в JOIN несколько раз (Oracle вычисляет его в рамках запроса один раз, если оптимизатор не решит иначе).
- **Отладка:** подзапрос из CTE легко выполнить отдельно, проверив промежуточный результат.
- **Рекурсия:** рекурсивный CTE (см. ниже) позволяет выражать иерархии и «зацикленные» зависимости в стандартном синтаксисе.

Ограничение: CTE видим только в том запросе, в котором объявлен; он не сохраняется в базе как представление. Для переиспользования между запросами создают представление (VIEW) или материализованное представление ([§7.4](chapter-07-04.md)).

## 7.1.4. Рекурсивный CTE

**Рекурсивный CTE** состоит из двух частей, объединённых **UNION ALL**: **якорная** (anchor) часть — начальный набор строк; **рекурсивная** часть — запрос, который ссылается на имя того же CTE и добавляет строки на основе уже полученных. Выполнение: сначала вычисляется якорь, затем рекурсивная часть применяется к результату, затем снова к новому результату, пока не будет пустого набора или пока не сработает ограничение глубины. См. [Глоссарий](glossary.md).

Упрощённая форма (стандарт SQL, Oracle 11g R2 и новее):

```sql
WITH rec (столбец1, столбец2, ...) AS (
  SELECT ...   -- якорь: начальные строки
  UNION ALL
  SELECT ...   -- рекурсивный член: из rec и таблиц
  FROM rec JOIN таблица ON ...
)
SELECT * FROM rec;
```

Типичное применение — обход иерархии (дерево подчинённых, цепочка предков). В Oracle для иерархий традиционно используется **CONNECT BY** ([§7.3](chapter-07-03.md)); рекурсивный WITH даёт альтернативу в стандартном стиле. При написании рекурсивного CTE важно обеспечить условие остановки в рекурсивном члене, иначе возможен бесконечный цикл или ограничение по глубине (Oracle ограничивает глубину рекурсии).

---

## Ключевое

- **CTE** (Common Table Expression) — именованный подзапрос в начале запроса: **WITH имя AS (подзапрос)**; в основном запросе к нему обращаются по имени в FROM/JOIN. Повышает читаемость и позволяет переиспользовать один набор. См. [Глоссарий](glossary.md).
- Несколько CTE задаются через запятую; CTE, на который ссылается другой, должен быть объявлен раньше.
- CTE действует только в рамках одного запроса; для постоянного переиспользования используют представления или материализованные представления (§7.4).
- **Рекурсивный CTE** — якорная часть UNION ALL рекурсивная часть, ссылающаяся на тот же CTE; применяется для иерархий и обхода графов. В Oracle иерархии также реализуются через CONNECT BY (§7.3).

В [§7.2](chapter-07-02.md) мы разберём операции над множествами строк: UNION, UNION ALL, INTERSECT, MINUS.
