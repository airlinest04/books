# §6.1 Групповые функции

В [§5.4](chapter-05-04.md) мы завершили главу о DML (INSERT, UPDATE, DELETE, MERGE). Теперь переходим к **агрегации** и группировке: запросы, которые возвращают не построчные данные, а сводки по группам строк. В этом разделе рассмотрим **групповые функции** (COUNT, SUM, AVG, MIN, MAX), предложение **GROUP BY** для разбиения строк на группы и **HAVING** для фильтрации групп. Оконные функции (агрегация без «схлопывания» строк в одну на группу) — в [§6.2](chapter-06-02.md). См. [Глоссарий](glossary.md).

---

## 6.1.1. Групповые функции: COUNT, SUM, AVG, MIN, MAX

**Групповые функции** (агрегатные функции) вычисляют одно значение по множеству строк: количество, сумму, среднее, минимум, максимум. Они применяются к столбцу или выражению и возвращают один результат для набора строк (или для каждой группы, если используется GROUP BY). См. [Глоссарий](glossary.md).

Основные групповые функции в Oracle:

| Функция | Назначение | NULL |
|--------|------------|------|
| **COUNT(** expr **)** | Число строк, для которых expr не NULL | NULL не учитываются |
| **COUNT(\*)** | Число строк (включая с NULL) | Все строки |
| **SUM(** expr **)** | Сумма значений expr | NULL пропускаются |
| **AVG(** expr **)** | Среднее арифметическое | NULL пропускаются |
| **MIN(** expr **)** | Минимальное значение | NULL пропускаются |
| **MAX(** expr **)** | Максимальное значение | NULL пропускаются |

Пример без группировки — одна строка результата по всей таблице:

```sql
SELECT COUNT(*) AS cnt,
       COUNT(commission_pct) AS cnt_comm,
       SUM(salary) AS total_sal,
       AVG(salary) AS avg_sal,
       MIN(hire_date) AS first_hire,
       MAX(hire_date) AS last_hire
  FROM employees;
```

Здесь `COUNT(*)` — число всех строк; `COUNT(commission_pct)` — число строк, где комиссия не NULL; SUM и AVG по зарплате; MIN/MAX по дате найма. Все групповые функции, кроме COUNT(\*), игнорируют NULL в аргументе: AVG(salary) считает среднее только по непустым зарплатам. Среда: Oracle Database.

## 6.1.2. GROUP BY: разбиение на группы

Чтобы получить сводки **по группам** (например, по отделам, по категориям товаров), используется предложение **GROUP BY**. После него перечисляют столбцы или выражения, по значениям которых строки объединяются в группы; для каждой группы вычисляются свои групповые функции. В списке SELECT при наличии GROUP BY допускаются только: (1) столбцы (или выражения), входящие в GROUP BY, и (2) групповые функции. Любой другой столбец без групповой функции приведёт к ошибке ORA-00979: not a GROUP BY expression. См. [Глоссарий](glossary.md).

Синтаксис:

```sql
SELECT столбец_группы, групповая_функция(столбец_или_выражение), ...
  FROM таблица
 [WHERE условие_на_строки]
 GROUP BY столбец_группы [, столбец2, ...]
 [HAVING условие_на_группы]
 [ORDER BY ...];
```

Пример: количество сотрудников и средняя зарплата по каждому отделу:

```sql
SELECT department_id,
       COUNT(*) AS emp_count,
       ROUND(AVG(salary), 2) AS avg_salary
  FROM employees
 GROUP BY department_id
 ORDER BY department_id;
```

Строки разбиваются по `department_id`; для каждого отдела выводится одна строка с количеством сотрудников и средней зарплатой. В SELECT указаны только `department_id` (есть в GROUP BY) и групповые функции — запрос корректен. Если бы мы добавили, например, `employee_id` в SELECT без оборачивания в групповую функцию, Oracle вернул бы ошибку: для группы из нескольких строк нельзя вывести одно значение employee_id.

## 6.1.3. HAVING: фильтрация групп

**WHERE** отбирает **строки до** группировки. Чтобы отфильтровать **уже сформированные группы** (например, «только отделы с числом сотрудников больше 5» или «только категории с суммой продаж выше порога»), используется **HAVING**. Условие в HAVING может опираться на групповые функции и на столбцы из GROUP BY. См. [Глоссарий](glossary.md).

Порядок выполнения логически такой: FROM → WHERE (отбор строк) → GROUP BY (формирование групп) → вычисление групповых функций → HAVING (отбор групп) → SELECT → ORDER BY.

Пример: отделы, в которых больше трёх сотрудников и средняя зарплата не менее 6000:

```sql
SELECT department_id,
       COUNT(*) AS emp_count,
       ROUND(AVG(salary), 2) AS avg_salary
  FROM employees
 GROUP BY department_id
HAVING COUNT(*) > 3 AND AVG(salary) >= 6000
 ORDER BY avg_salary DESC;
```

В HAVING можно использовать псевдонимы из SELECT в части групповых выражений, но в Oracle традиционно в HAVING пишут саму функцию (COUNT(\*), AVG(salary)), чтобы условие было явным. Фильтр по «обычным» столбцам группы (например, только department_id < 100) можно задать и в WHERE (до группировки), и в HAVING; для производительности предпочтительнее WHERE, если логика позволяет.

## 6.1.4. Примеры: сводки по категориям и по датам

Типичные сценарии: число записей по категории, сумма и среднее по группе, минимум/максимум. Ниже — пример по таблице заказов: количество заказов и сумма по каждому клиенту, только клиенты с суммой заказов больше 1000.

```sql
SELECT customer_id,
       COUNT(*) AS order_count,
       SUM(total) AS total_amount
  FROM orders
 GROUP BY customer_id
HAVING SUM(total) > 1000
 ORDER BY total_amount DESC;
```

Ещё пример — сводка по году и месяцу (дата приведена к началу месяца через TRUNC или аналогичную функцию):

```sql
SELECT TO_CHAR(order_date, 'YYYY-MM') AS year_month,
       COUNT(*) AS orders_count,
       SUM(total) AS revenue
  FROM orders
 GROUP BY TO_CHAR(order_date, 'YYYY-MM')
 ORDER BY year_month;
```

В GROUP BY должно стоять то же выражение, что и в SELECT (или эквивалентное), чтобы каждая уникальная комбинация даты образовывала одну группу. См. [Глоссарий](glossary.md).

## Ключевое

- **Групповые функции** (COUNT, SUM, AVG, MIN, MAX) вычисляют одно значение по набору строк. COUNT(\*) считает все строки; COUNT(expr) — строки, где expr не NULL; остальные функции игнорируют NULL в аргументе. См. [Глоссарий](glossary.md).
- **GROUP BY** разбивает строки на группы по значениям указанных столбцов или выражений. В SELECT допустимы только столбцы из GROUP BY и групповые функции.
- **HAVING** фильтрует группы после группировки (условие по групповым функциям или по столбцам группы). WHERE фильтрует строки до группировки.
- Порядок: FROM → WHERE → GROUP BY → групповые функции → HAVING → SELECT → ORDER BY. Не путайте WHERE и HAVING.
- В одной группе не может быть «разных» значений столбца, не входящего в GROUP BY — поэтому такой столбец в SELECT без групповой функции запрещён.

В [§6.2](chapter-06-02.md) мы рассмотрим оконные функции: агрегация и ранжирование без схлопывания строк в одну на группу.
