# §4.1 INNER JOIN, LEFT/RIGHT/FULL OUTER JOIN

В [§3.4](chapter-03-04.md) мы завершили главу о выборке и фильтрации. Когда данные разнесены по **нескольким таблицам** (например, заказы и клиенты, товары и категории), нужно **соединять** их по связующим столбцам. Для этого в SQL служат **JOIN**. В этом разделе рассмотрены **INNER JOIN** (только совпадающие строки), **LEFT**, **RIGHT** и **FULL OUTER JOIN** (сохранение несовпадающих строк с NULL) и синтаксис **ON**. Кратко упомянем старый синтаксис Oracle с **(+)**. Подзапросы в WHERE — в [§4.2](chapter-04-02.md). См. [Глоссарий](glossary.md).

---

## 4.1.1. Зачем нужно соединение таблиц

В реляционной модели данные часто разбиты по таблицам: в одной — заказы (order_id, customer_id, order_date), в другой — клиенты (customer_id, name). Чтобы в одном результате получить заказ и имя клиента, нужно **соединить** строки из двух таблиц по общему полю (customer_id): для каждой строки заказа найти строку клиента с тем же customer_id и вывести их вместе. Без JOIN пришлось бы делать несколько запросов или подставлять данные в приложении; JOIN выполняет связывание на стороне базы. См. [Глоссарий](glossary.md).

Условие, по которому соединяют таблицы (например, orders.customer_id = customers.customer_id), называют **условием соединения (join condition)**. В стандартном синтаксисе оно задаётся в предложении **ON** после имени второй таблицы. Раньше соединение часто писали в WHERE (FROM orders, customers WHERE orders.customer_id = customers.customer_id); современный стиль — явный JOIN ... ON, чтобы отделить условие соединения от фильтра по строкам (WHERE).

---

## 4.1.2. INNER JOIN и синтаксис ON

**INNER JOIN** (внутреннее соединение) возвращает только те строки, для которых **условие соединения истинно в обеих таблицах**: из первой таблицы берётся строка, из второй — строка с совпадающим значением по связующему столбцу; если совпадения нет, строка первой таблицы в результат не попадает. См. [Глоссарий](glossary.md).

Синтаксис:

```sql
SELECT список_столбцов
  FROM таблица1
  INNER JOIN таблица2 ON условие_соединения
  [WHERE фильтр];
```

Слово **INNER** можно опустить: **JOIN** без указания типа по умолчанию означает INNER JOIN. Условие в ON обычно имеет вид «столбец_таблицы1 = столбец_таблицы2»; можно указывать несколько условий через AND. Пример:

```sql
SELECT o.order_id, o.order_date, c.name AS customer_name
  FROM orders o
  INNER JOIN customers c ON o.customer_id = c.customer_id
 WHERE o.status = 'CONFIRMED';
```

Здесь каждая строка заказа соединяется с клиентом по customer_id; в результат попадают только заказы со статусом CONFIRMED и только если у заказа есть соответствующий клиент. Столбцы с одинаковыми именами в разных таблицах различают префиксом (псевдонимом таблицы): o.order_id, c.name. Псевдонимы таблиц рассмотрены в подразделе 4.1.6.

---

## 4.1.3. LEFT OUTER JOIN

**LEFT OUTER JOIN** (левое внешнее соединение) сохраняет **все строки левой** (первой) таблицы. Для каждой строки левой таблицы ищется совпадение в правой по условию ON; если совпадение есть — строки соединяются; если нет — в результирующей строке столбцы правой таблицы заполняются **NULL**. См. [Глоссарий](glossary.md).

Синтаксис:

```sql
FROM таблица1
LEFT [OUTER] JOIN таблица2 ON условие_соединения
```

Ключевое слово **OUTER** необязательно; **LEFT JOIN** и **LEFT OUTER JOIN** равнозначны. Пример: список всех заказов и имена клиентов, при этом заказы без клиента (или с несуществующим customer_id) тоже вывести, с NULL в имени:

```sql
SELECT o.order_id, o.order_date, c.name AS customer_name
  FROM orders o
  LEFT JOIN customers c ON o.customer_id = c.customer_id;
```

LEFT JOIN удобен, когда «главная» сущность — левая таблица (заказы), а справочная (клиенты) может отсутствовать для части строк.

---

## 4.1.4. RIGHT OUTER JOIN

**RIGHT OUTER JOIN** (правое внешнее соединение) симметричен LEFT: сохраняются **все строки правой** (второй) таблицы. Для каждой строки правой таблицы ищется совпадение в левой; при отсутствии совпадения столбцы левой таблицы в результате заполняются NULL. См. [Глоссарий](glossary.md).

```sql
FROM таблица1
RIGHT [OUTER] JOIN таблица2 ON условие_соединения
```

Любой RIGHT JOIN можно переписать как LEFT JOIN, поменяв порядок таблиц и условие местами. Поэтому на практике часто достаточно LEFT JOIN; RIGHT используют для удобства чтения или когда запрос уже задан в таком виде.

---

## 4.1.5. FULL OUTER JOIN

**FULL OUTER JOIN** (полное внешнее соединение) сохраняет **все строки обеих** таблиц. Строка из первой без совпадения во второй идёт в результат с NULL справа; строка из второй без совпадения в первой — с NULL слева; совпадающие строки соединяются как при INNER JOIN. См. [Глоссарий](glossary.md).

```sql
FROM таблица1
FULL [OUTER] JOIN таблица2 ON условие_соединения
```

Пример: полный список клиентов и заказов — и клиенты без заказов, и заказы без клиента (если такие есть):

```sql
SELECT o.order_id, c.name
  FROM orders o
  FULL OUTER JOIN customers c ON o.customer_id = c.customer_id;
```

FULL OUTER JOIN применяют реже, чем INNER и LEFT; он нужен для сравнения двух наборов или когда важно видеть «несовпадения» с обеих сторон.

---

## 4.1.6. Псевдонимы таблиц

При соединении нескольких таблиц имена столбцов могут совпадать (например, id, name). Чтобы однозначно указать таблицу, используют **псевдоним таблицы (table alias)**: после имени таблицы через пробел задаётся короткое имя (или **AS** псевдоним). Далее в запросе к столбцам обращаются через этот псевдоним: **псевдоним.имя_столбца**. См. [Глоссарий](glossary.md).

Пример:

```sql
SELECT o.order_id, c.customer_id, c.name
  FROM orders o
  JOIN customers c ON o.customer_id = c.customer_id;
```

Псевдонимы делают запрос короче и яснее. В Oracle псевдоним таблицы нельзя использовать в предложении WHERE для ссылки на столбцы из того же уровня FROM (ограничение касается только порядка разбора); на практике псевдонимы в WHERE работают для столбцов соединённых таблиц. В одном запросе псевдоним должен быть уникален.

---

## 4.1.7. Старый синтаксис Oracle: (+) для внешнего соединения

В старом коде Oracle встречается **внешнее соединение через (+) в WHERE**. Символ **(+)** ставится рядом со столбцом той таблицы, со стороны которой **допускается отсутствие совпадения**: для этой таблицы будут подставлены NULL, а все строки **противоположной** таблицы сохраняются. То есть **(+)** на стороне правой таблицы в условии даёт по смыслу **LEFT OUTER JOIN** (сохраняются все строки левой таблицы). См. [Глоссарий](glossary.md).

Пример эквивалента LEFT JOIN:

```sql
SELECT o.order_id, c.name
  FROM orders o, customers c
 WHERE o.customer_id = c.customer_id (+);
```

Здесь (+) у customers: сохраняются все заказы, при отсутствии клиента в customers подставляется NULL. Эквивалент RIGHT JOIN — (+) у левой таблицы: `o.customer_id (+) = c.customer_id`. FULL OUTER JOIN через (+) выразить нельзя; для него нужен синтаксис JOIN. Oracle рекомендует использовать стандартный **JOIN ... ON** вместо (+): он переносим и явно разделяет условие соединения и фильтр WHERE.

---

## 4.1.8. Несколько таблиц и порядок JOIN

К одному запросу можно подключить более двух таблиц, последовательно указывая JOIN:

```sql
SELECT o.order_id, c.name, p.product_name
  FROM orders o
  JOIN customers c ON o.customer_id = c.customer_id
  JOIN order_items i ON o.order_id = i.order_id
  JOIN products p ON i.product_id = p.product_id;
```

Порядок перечисления JOIN влияет на то, как оптимизатор строит план (и в сложных случаях на результат при смешении типов соединений); логически условие ON задаёт связь между парами таблиц. Условия фильтрации (не относящиеся к связыванию) выносят в **WHERE**.

---

## 4.1.9. Типичные ошибки при использовании JOIN

- **Путать LEFT и RIGHT:** LEFT — сохраняем все строки **первой** (левой) таблицы; RIGHT — второй (правой). При сомнении можно переписать RIGHT как LEFT, поменяв таблицы местами.
- **Писать условие соединения в WHERE при использовании JOIN:** условие связи таблиц задаётся в **ON**; в WHERE — только фильтр по уже соединённому набору. Смешение усложняет чтение и может привести к неверному результату при внешних соединениях (фильтр в WHERE по столбцу правой таблицы отсекает строки с NULL и превращает LEFT JOIN по эффекту в INNER).
- **Забыть псевдонимы при одинаковых именах столбцов:** если в обеих таблицах есть, например, id, нужно указывать o.id и c.id (или таблица.id), иначе ошибка «column ambiguously defined».
- **Использовать (+) для FULL OUTER JOIN:** в синтаксисе (+) нет эквивалента FULL OUTER JOIN; нужен явный FULL OUTER JOIN ... ON.
- **Соединять по несовместимых типах или по полям без логической связи:** условие ON должно сравнивать совместимые типы и реально связывать сущности (обычно внешний ключ с первичным); иначе получается декартово произведение или неверные пары.

---

## Ключевое

- **INNER JOIN** — только строки, где условие ON истинно в обеих таблицах. **JOIN** без слова LEFT/RIGHT/FULL по умолчанию означает INNER.
- **LEFT OUTER JOIN** — все строки левой таблицы; при отсутствии совпадения справа — NULL. **RIGHT OUTER JOIN** — то же для правой таблицы. **FULL OUTER JOIN** — все строки обеих таблиц, несовпадающие с NULL с другой стороны.
- Условие соединения задаётся в **ON**; фильтр по строкам — в **WHERE**. Псевдонимы таблиц (o, c и т.д.) устраняют неоднозначность имён столбцов.
- Старый синтаксис Oracle **(+)** в WHERE задаёт внешнее соединение: (+) у столбца той таблицы, со стороны которой допускается «нет совпадения» (LEFT — (+) справа). Рекомендуется использовать JOIN ... ON.
- Несколько таблиц соединяют последовательными JOIN ... ON. Условие связи — в ON, общий фильтр — в WHERE.

В [§4.2](chapter-04-02.md) мы разберём подзапросы в WHERE: скалярный подзапрос, IN, EXISTS и сравнения с подзапросом.
