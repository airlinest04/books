# §13.3 Обработка исключений

В [§13.2](chapter-13-02.md) мы разобрали курсорные переменные. Секция **EXCEPTION** в блоке PL/SQL ([§9.1](chapter-09-01.md)) перехватывает ошибки: при возникновении исключения управление переходит в соответствующий обработчик **WHEN**, после чего блок завершается или выполняется код обработчика. Здесь рассмотрим **предопределённые** исключения Oracle (NO_DATA_FOUND, TOO_MANY_ROWS, DUP_VAL_ON_INDEX и др.), **пользовательские** исключения (**DECLARE** ... **EXCEPTION**, **RAISE**), привязку к коду ошибки (**PRAGMA EXCEPTION_INIT**) и повторное возбуждение (**RAISE**). Транзакции в PL/SQL — в [§13.4](chapter-13-04.md). См. [Глоссарий](glossary.md).

---

## 13.3.1. Секция EXCEPTION и предопределённые исключения

**Исключение** — условие ошибки, прерывающее нормальное выполнение блока. В секции **EXCEPTION** перечисляют обработчики: **WHEN** имя_исключения **THEN** операторы **;** При совпадении выполняется соответствующий блок; затем выполнение блока заканчивается (или выполняется код в обработчике и выход). **WHEN OTHERS** перехватывает любое исключение, не обработанное выше. См. [Глоссарий](glossary.md).

Предопределённые исключения Oracle имеют стандартные имена и соответствуют кодам ORA-xxxxx. Часто используемые:

| Исключение        | Описание (приблизительно)        |
|-------------------|-----------------------------------|
| **NO_DATA_FOUND** | SELECT INTO не вернул ни одной строки |
| **TOO_MANY_ROWS** | SELECT INTO вернул больше одной строки |
| **DUP_VAL_ON_INDEX** | Нарушение уникальности (дубликат ключа) |
| **INVALID_CURSOR**   | Недопустимая операция с курсором (например, FETCH из закрытого) |
| **VALUE_ERROR**      | Ошибка преобразования или выхода за границы (например, переполнение) |
| **ZERO_DIVIDE**      | Деление на ноль |

Пример: перехват NO_DATA_FOUND и OTHERS с выводом SQLCODE и SQLERRM:

```plsql
BEGIN
  -- какой-то код
  NULL;
EXCEPTION
  WHEN NO_DATA_FOUND THEN
    DBMS_OUTPUT.PUT_LINE('Данные не найдены');
  WHEN DUP_VAL_ON_INDEX THEN
    DBMS_OUTPUT.PUT_LINE('Дубликат ключа');
  WHEN OTHERS THEN
    DBMS_OUTPUT.PUT_LINE('Ошибка ' || SQLCODE || ': ' || SQLERRM);
END;
/
```

**SQLCODE** — код ошибки (число). **SQLERRM** — текст сообщения. В OTHERS их используют для логирования; затем при необходимости выполняют **RAISE** для передачи исключения выше. См. [Глоссарий](glossary.md).

## 13.3.2. Пользовательское исключение и RAISE

**Пользовательское исключение** объявляется в DECLARE: **имя EXCEPTION;** Оно не связано с кодом ORA автоматически. Возбуждение: **RAISE** имя**;** Выполнение переходит в EXCEPTION текущего блока; если там есть **WHEN** имя **THEN**, выполняется этот обработчик, иначе исключение передаётся вызывающему. См. [Глоссарий](glossary.md).

Пример:

```plsql
DECLARE
  e_bad_value EXCEPTION;
  v_x NUMBER := -1;
BEGIN
  IF v_x < 0 THEN
    RAISE e_bad_value;
  END IF;
EXCEPTION
  WHEN e_bad_value THEN
    DBMS_OUTPUT.PUT_LINE('Недопустимое значение');
END;
/
```

**RAISE** без аргументов допустим только внутри обработчика **WHEN OTHERS**: повторно возбуждает то же исключение для передачи наверх. См. [Глоссарий](glossary.md).

## 13.3.3. PRAGMA EXCEPTION_INIT

Исключения Oracle с кодами ORA-xxxxx по умолчанию обрабатываются только через **WHEN OTHERS** (по имени доступны лишь предопределённые). Чтобы дать **имя** произвольному коду ошибки и обрабатывать его в **WHEN** имя **THEN**, используют **PRAGMA EXCEPTION_INIT**(имя_исключения, код_ошибки). См. [Глоссарий](glossary.md).

Код ошибки — отрицательное число (например, -1 для ORA-00001, -2291 для ORA-02291). Пример: привязка к нарушению внешнего ключа (ORA-02291):

```plsql
DECLARE
  e_fk_violation EXCEPTION;
  PRAGMA EXCEPTION_INIT(e_fk_violation, -2291);
BEGIN
  INSERT INTO orders (customer_id, ...) VALUES (99999, ...);  -- несуществующий customer
EXCEPTION
  WHEN e_fk_violation THEN
    DBMS_OUTPUT.PUT_LINE('Нарушение внешнего ключа');
END;
/
```

См. [Глоссарий](glossary.md). Среда: Oracle PL/SQL.

## Ключевое

- В секции **EXCEPTION** обработчики **WHEN** имя **THEN** ... **WHEN OTHERS THEN** ... Предопределённые исключения: NO_DATA_FOUND, TOO_MANY_ROWS, DUP_VAL_ON_INDEX и др. **SQLCODE**, **SQLERRM** — код и текст ошибки. См. [Глоссарий](glossary.md).
- **Пользовательское исключение**: в DECLARE **имя EXCEPTION;** Возбуждение: **RAISE** имя**;** В обработчике **RAISE;** (без аргументов) — повторное возбуждение текущего исключения.
- **PRAGMA EXCEPTION_INIT**(имя, код_ORA) привязывает имя к коду ошибки Oracle; затем исключение обрабатывается в **WHEN** имя **THEN**.
- Обработка в EXCEPTION не отменяет транзакцию автоматически; при необходимости выполняют ROLLBACK в обработчике (см. §13.4).

В [§13.4](chapter-13-04.md) мы рассмотрим транзакции в PL/SQL: COMMIT и ROLLBACK в блоках, автономные транзакции (кратко).
