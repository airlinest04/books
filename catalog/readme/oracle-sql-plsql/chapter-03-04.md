# §3.4 Специфика Oracle: ROWNUM, FETCH FIRST, OFFSET

В [§3.3](chapter-03-03.md) мы разобрали DISTINCT для уникальных строк. Часто нужно ограничить результат запроса **первыми N строками** или пропустить несколько строк (постраничный вывод). В Oracle для этого исторически использовался псевдостолбец **ROWNUM**; начиная с **Oracle 12c** добавлено стандартизированное предложение **FETCH FIRST** и **OFFSET**. В этом разделе рассмотрим **ROWNUM** (как он присваивается и как им ограничивать выборку до 12c), а затем **FETCH FIRST** и **OFFSET** в 12c и новее. Глава 3 на этом завершается; соединение таблиц (JOIN) — в [§4.1](chapter-04-01.md). См. [Глоссарий](glossary.md).

---

## 3.4.1. Псевдостолбец ROWNUM

**ROWNUM** — псевдостолбец Oracle, который возвращает **порядковый номер строки** в наборе результатов. Нумерация начинается с 1: первая выбранная строка получает ROWNUM = 1, вторая — 2 и т.д. Важно: ROWNUM присваивается **до сортировки** (ORDER BY) и до группировки. Строки получают номера в том порядке, в котором они отбираются из таблицы (порядок по умолчанию не гарантирован), а не в порядке итоговой сортировки. См. [Глоссарий](glossary.md).

ROWNUM можно использовать в SELECT и в WHERE. Типичное использование — ограничить число строк:

```sql
SELECT * FROM products WHERE ROWNUM <= 10;
```

В результате будет не более 10 строк (какие именно — зависит от порядка выборки, без ORDER BY он не определён). Условие **ROWNUM <= N** или **ROWNUM < N+1** ограничивает выборку; **ROWNUM = 1** даёт одну строку; **ROWNUM > 1** в простом запросе **никогда не истинно**: первая строка получает 1, и отбрасывается, следующая снова получает 1, и так далее — в результат не попадёт ни одна строка. Поэтому для «пропустить первые K строк» или «взять строки с N по M» в старом стиле используют подзапрос (см. ниже).

## 3.4.2. Ограничение числа строк до Oracle 12c: ROWNUM в подзапросе

Чтобы получить **первые N строк после сортировки** (например, «10 самых дорогих товаров»), недостаточно написать ORDER BY и ROWNUM <= 10 в одном запросе: ROWNUM присваивается до ORDER BY, поэтому отсекаются первые 10 строк в «сыром» порядке, а затем они сортируются — итог не совпадает с «топ-10 по цене». Правильный приём — **подзапрос**: внутренний запрос с ORDER BY, внешний — с условием по ROWNUM. См. [Глоссарий](glossary.md).

Пример: 10 самых дорогих товаров:

```sql
SELECT * FROM (
  SELECT * FROM products ORDER BY price DESC
) WHERE ROWNUM <= 10;
```

Внутренний запрос возвращает все строки, отсортированные по price по убыванию; внешний отбирает первые 10. Псевдоним для подзапроса в Oracle обязателен (можно написать `) t WHERE ROWNUM <= 10`). Для **постраничной выборки** (пропустить K строк, взять следующие M) до 12c использовали два уровня подзапросов: внутренний с ORDER BY и ROWNUM, средний — нумерация через ROWNUM, внешний — условие «номер между K+1 и K+M». В 12c это заменяется на OFFSET и FETCH FIRST (см. ниже).

## 3.4.3. Oracle 12c и новее: FETCH FIRST и OFFSET

Начиная с **Oracle 12c Release 1** в запрос можно добавить **предложение ограничения строк (row limiting clause)**. Оно записывается **после ORDER BY** и позволяет указать, сколько строк вернуть и сколько пропустить. Синтаксис (упрощённо): См. [Глоссарий](glossary.md).

```sql
[ OFFSET n { ROW | ROWS } ]
[ FETCH { FIRST | NEXT } m { ROW | ROWS } { ONLY | WITH TIES } ]
```

- **OFFSET n ROWS** — пропустить первые n строк (n — неотрицательное целое или выражение). Если n = 0 или опущено, пропуска нет.
- **FETCH FIRST m ROWS ONLY** — вернуть ровно m строк. **FIRST** и **NEXT** равнозначны; **ROW** и **ROWS** тоже. **ONLY** — строго m строк; **WITH TIES** — если последняя строка по ORDER BY имеет те же значения, что и следующие, они тоже включаются (удобно для «топ-N с одинаковыми значениями»).
- Предложение **требует ORDER BY** в том же запросе: без сортировки порядок не определён, и OFFSET/FETCH дают непредсказуемый результат.

Примеры:

```sql
-- первые 10 строк по цене (убывание)
SELECT * FROM products ORDER BY price DESC
FETCH FIRST 10 ROWS ONLY;

-- пропустить 20 строк, затем взять 10 (страница 3 при размере страницы 10)
SELECT * FROM products ORDER BY id
OFFSET 20 ROWS FETCH NEXT 10 ROWS ONLY;
```

Для совместимости со старыми версиями или если 12c недоступен, по-прежнему используют ROWNUM в подзапросе. См. [Глоссарий](glossary.md).

---

## 3.4.4. FETCH FIRST с процентом и WITH TIES

В предложении ограничения строк можно задать количество не числом, а **процентом** от полного набора (до применения OFFSET): **FETCH FIRST n PERCENT ROWS ONLY**. Oracle вычисляет, сколько строк составляют n процентов, и возвращает не более этого числа. См. [Глоссарий](glossary.md).

**WITH TIES** полезен, когда по ORDER BY несколько строк имеют одинаковое значение в сортировочном столбце и вы хотите включить все такие «последние» строки. Например, «не более 10 строк, но если на 10-м месте несколько с одной ценой — взять все с этой ценой»:

```sql
SELECT * FROM products ORDER BY price DESC
FETCH FIRST 10 ROWS WITH TIES;
```

Тогда в результате может быть больше 10 строк, если у 10-й и следующих цена совпадает.

## 3.4.5. Типичные ошибки при ограничении строк

- **ROWNUM = 2 или ROWNUM > 1 в одном запросе:** такие условия не выполняются ни для одной строки (после отбрасывания первой следующая снова получает ROWNUM = 1). Для «второй строки» или «пропустить первые» до 12c нужен подзапрос с нумерацией; в 12c — OFFSET.
- **ORDER BY и ROWNUM <= N в одном запросе для «топ-N»:** порядок строк для ROWNUM определяется до ORDER BY. Нужен подзапрос: внутренний с ORDER BY, внешний с ROWNUM <= N (или в 12c — FETCH FIRST после ORDER BY).
- **OFFSET/FETCH без ORDER BY в 12c:** синтаксически допустимо, но порядок строк не определён, поэтому «пропустить 10, взять 5» даёт непредсказуемый результат. Всегда задавайте ORDER BY при использовании OFFSET и FETCH FIRST.
- **Забыть, что ROWNUM — не столбец таблицы:** его нельзя использовать в подзапросе в UPDATE/DELETE так же просто, как в SELECT; для обновления/удаления «первых N строк» по порядку нужен подзапрос с фиксированным порядком (например, по первичному ключу) и ROWNUM во внешнем запросе или использование rowid/первичного ключа из подзапроса.

## Ключевое

- **ROWNUM** — псевдостолбец: порядковый номер строки в наборе (начиная с 1). Присваивается **до** ORDER BY. Условие ROWNUM <= N ограничивает результат N строками; ROWNUM > 1 в одном запросе не выполняется ни для одной строки.
- **«Топ-N по сортировке» до 12c:** подзапрос с ORDER BY, снаружи WHERE ROWNUM <= N. Для постраничной выборки (OFFSET + LIMIT) — два уровня подзапросов с ROWNUM.
- **Oracle 12c и новее:** предложение **OFFSET n ROWS FETCH FIRST m ROWS ONLY** (после ORDER BY) — пропустить n строк, вернуть m. **FETCH FIRST m ROWS ONLY** без OFFSET — первые m строк. Требуется **ORDER BY** для предсказуемого порядка.
- **FETCH FIRST n PERCENT ROWS** — ограничение по проценту строк. **WITH TIES** — включать все строки с тем же значением порядка, что и последняя отобранная.
- Для постраничного вывода и «топ-N» в новых версиях предпочтительно использовать FETCH FIRST и OFFSET; ROWNUM оставлять для совместимости со старыми версиями или особых сценариев.
