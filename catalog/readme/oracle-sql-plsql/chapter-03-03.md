# §3.3 DISTINCT

В [§3.2](chapter-03-02.md) мы разобрали фильтрацию строк по условию WHERE. Запрос может возвращать **одинаковые строки** несколько раз (например, при выборке неключевых столбцов из таблицы с повторяющимися комбинациями или после JOIN). Чтобы в результате остались только **уникальные строки**, в SELECT указывают **DISTINCT**. В этом разделе рассмотрим синтаксис **SELECT DISTINCT**, как определяется уникальность (по всей строке результата), использование с выражениями и связь с NULL. Специфика Oracle по ограничению числа строк (ROWNUM, FETCH FIRST) — в [§3.4](chapter-03-04.md). См. [Глоссарий](glossary.md).

---

## 3.3.1. Синтаксис и смысл DISTINCT

Ключевое слово **DISTINCT** ставится сразу после **SELECT** (перед списком столбцов и выражений). Oracle устраняет из набора результатов **дубликаты**: оставляет по одной строке для каждой уникальной комбинации значений в выбранных столбцах. См. [Глоссарий](glossary.md).

Синтаксис:

```sql
SELECT DISTINCT список_столбцов_или_выражений FROM таблица [WHERE ...];
```

Без DISTINCT запрос возвращает все строки, удовлетворяющие WHERE (и другим предложениям); с DISTINCT — только уникальные комбинации значений. Пример: в таблице заказов много строк с одним и тем же customer_id; чтобы получить список идентификаторов клиентов без повторов:

```sql
SELECT DISTINCT customer_id FROM orders;
```

Если бы в таблице были customer_id 1, 1, 2, 2, 3, результат без DISTINCT содержал бы шесть строк, с DISTINCT — три: 1, 2, 3 (порядок не гарантируется, если нет ORDER BY).

---

## 3.3.2. Уникальность по всей строке результата

Уникальность считается по **всей строке** результата: по совокупности всех выбранных столбцов и выражений. Две строки считаются одинаковыми, только если **все** значения в них совпадают (с учётом правил сравнения типов; для NULL в SQL два NULL при сравнении «равны» в контексте DISTINCT — обе строки с NULL в одном столбце считаются одинаковыми и сводятся к одной). См. [Глоссарий](glossary.md).

Пример с несколькими столбцами:

```sql
SELECT DISTINCT status, customer_id FROM orders;
```

В результате не будет двух строк с одной и той же парой (status, customer_id). Если нужны уникальные значения только по одному столбцу, в списке SELECT указывают только этот столбец (как в примере с customer_id выше). Если указать несколько столбцов, уникальность — по комбинации всех их.

---

## 3.3.3. DISTINCT с выражениями

В списке после DISTINCT могут быть не только столбцы, но и **выражения**. Уникальность тогда определяется по результату выражения для каждой строки. См. [Глоссарий](glossary.md).

Примеры:

```sql
SELECT DISTINCT UPPER(status) FROM orders;

SELECT DISTINCT price * 1.2 FROM products;
```

В первом случае в результате — уникальные значения статуса в верхнем регистре; во втором — уникальные значения «цены с коэффициентом». Одна и та же исходная цена даёт одно значение выражения, поэтому дубликаты по выражению устраняются. Если в списке несколько выражений или столбцов, снова уникальность по **всей строке** (по всем выражениям и столбцам).

---

## 3.3.4. NULL и DISTINCT

В наборе результатов несколько строк с **NULL** в одном и том же столбце (или с одинаковыми NULL во всех выбранных столбцах) при **DISTINCT** сводятся к **одной** строке: Oracle трактует NULL как равный NULL для целей устранения дубликатов. Поэтому запрос вида `SELECT DISTINCT nullable_column FROM t` вернёт одну строку с NULL, если в таблице было несколько строк с NULL в этом столбце. См. [Глоссарий](glossary.md).

---

## 3.3.5. Типичные ошибки при использовании DISTINCT

- **Ожидать уникальность по одному столбцу при нескольких в SELECT:** DISTINCT убирает дубликаты по **всей строке**. Чтобы получить уникальные значения одного столбца, в списке SELECT должен быть только этот столбец (или только нужное выражение).
- **Путать DISTINCT с GROUP BY:** DISTINCT просто убирает одинаковые строки результата; GROUP BY группирует строки и обычно используется с агрегатными функциями (COUNT, SUM и т.д.). Для «уникальных значений одного столбца» достаточно SELECT DISTINCT столбец; для подсчёта количества заказов по клиентам нужен GROUP BY (см. гл. 6).
- **Думать, что DISTINCT ускоряет запрос:** устранение дубликатов требует сравнения строк и может увеличивать нагрузку (сортировка или хэширование). Применяйте DISTINCT только когда действительно нужны уникальные строки.
- **Использовать DISTINCT с неоднозначным списком:** например, SELECT DISTINCT col1, col2 при JOIN может дать неочевидный результат, если ожидалась уникальность только по col1. Следите за тем, по какой комбинации столбцов считается уникальность.

---

## Ключевое

- **SELECT DISTINCT** — в результате остаются только **уникальные строки**; дубликаты по выбранным столбцам и выражениям устраняются.
- Уникальность определяется по **всей строке** результата (по всем столбцам и выражениям в списке SELECT). Для уникальных значений одного столбца в списке указывают только этот столбец.
- DISTINCT применим к выражениям: уникальность по результату выражения. Несколько столбцов/выражений — уникальность по комбинации.
- В контексте DISTINCT несколько NULL считаются одинаковыми и сводятся к одной строке с NULL.
- DISTINCT не заменяет GROUP BY; для агрегации по группам используется GROUP BY (гл. 6).
