# §6.2 Оконные функции

В [§6.1](chapter-06-01.md) мы разобрали групповые функции и GROUP BY: результат «схлопывается» до одной строки на группу. **Оконные функции** позволяют вычислять агрегаты и ранги по набору строк (по «окну»), сохраняя при этом все строки результата — каждая строка получает своё значение функции, рассчитанное в контексте окна. В этом разделе рассмотрим синтаксис **OVER**, разбиение окна по **PARTITION BY**, порядок внутри окна (**ORDER BY** в OVER), а также типичные функции: агрегаты с окном и **ROW_NUMBER**, **RANK**, **DENSE_RANK**. Специфика Oracle (LISTAGG, NTH_VALUE и др.) — в [§6.3](chapter-06-03.md). См. [Глоссарий](glossary.md).

---

## 6.2.1. Окно и предложение OVER

**Оконная функция** — функция, вызываемая с предложением **OVER**, которое задаёт **окно**: набор строк, по которому вычисляется результат. В отличие от групповой функции с GROUP BY, строки не объединяются в одну на группу: в результирующей таблице остаётся столько же строк, сколько было, и у каждой в дополнительном столбце — значение функции для её окна. См. [Глоссарий](glossary.md).

Общая форма:

```sql
функция_окна([аргументы]) OVER (
  [PARTITION BY столбец1 [, столбец2, ...]]
  [ORDER BY столбец_или_выражение [ASC|DESC] [, ...]]
  [окно_кадра — ROWS или RANGE ...]
)
```

- **PARTITION BY** разбивает строки на партиции (подмножества); функция вычисляется отдельно внутри каждой партиции. Если PARTITION BY опущен, окно — все строки результата запроса.
- **ORDER BY** внутри OVER задаёт порядок строк внутри партиции. Для агрегатных функций (SUM, AVG и т.д.) при наличии ORDER BY по умолчанию используется **нарастающий итог** (от начала партиции до текущей строки), если не задан явный кадр (frame). Для ранжирующих функций (ROW_NUMBER, RANK) ORDER BY определяет, по какому полю ранжировать.
- **Окно кадра** (ROWS BETWEEN ... AND ... или RANGE ...) ограничивает, какие строки внутри партиции участвуют в расчёте; разбирается ниже.

Пример: для каждой строки таблицы employees вывести зарплату сотрудника и среднюю зарплату по его отделу (строки не группируются, у каждой — своя зарплата и одно и то же среднее по отделу).

```sql
SELECT employee_id, last_name, department_id, salary,
       AVG(salary) OVER (PARTITION BY department_id) AS dept_avg_salary
  FROM employees
 ORDER BY department_id, salary;
```

Среда: Oracle Database (оконные функции поддерживаются с Oracle 8i для аналитических функций, полная поддержка OVER — с 9i и далее).

## 6.2.2. PARTITION BY и ORDER BY в окне

**PARTITION BY** в OVER разбивает результирующий набор на независимые партиции; функция считается заново для каждой партиции. Аналог «GROUP BY по партициям», но без уменьшения числа строк. См. [Глоссарий](glossary.md).

**ORDER BY** в OVER задаёт порядок строк внутри партиции. Для **ранжирующих** функций (ROW_NUMBER, RANK, DENSE_RANK) он определяет, по какому полю присваивать номера. Для **агрегатных** (SUM, AVG, COUNT и т.д.) при наличии ORDER BY без явного кадра в Oracle по умолчанию используется окно от начала партиции до текущей строки (нарастающий итог).

Пример нарастающего итога: сумма зарплат по отделу «нарастающим итогом» при сортировке по salary:

```sql
SELECT department_id, last_name, salary,
       SUM(salary) OVER (PARTITION BY department_id ORDER BY salary) AS running_total
  FROM employees
 ORDER BY department_id, salary;
```

В каждой партиции (отдел) первая по salary строка получает свою зарплату как running_total, вторая — сумму первых двух зарплат, и т.д. Если нужна сумма по всей партиции в каждой строке (одно и то же значение), ORDER BY в OVER для этой цели не задают (как в примере с AVG в 6.2.1).

## 6.2.3. ROW_NUMBER, RANK, DENSE_RANK

**ROW_NUMBER()** присваивает уникальный порядковый номер строке внутри партиции (1, 2, 3, …) согласно ORDER BY в OVER. При равных значениях порядка порядок между строками не гарантирован — номера всё равно разные.

**RANK()** присваивает ранг: равные по ORDER BY получают один и тот же ранг, следующие номера пропускаются (1, 2, 2, 4, …).

**DENSE_RANK()** — ранг без пропусков: равные — один ранг, следующие идут подряд (1, 2, 2, 3, …).

Все три вызываются без аргументов: **ROW_NUMBER() OVER (...)** , **RANK() OVER (...)** , **DENSE_RANK() OVER (...)**. ORDER BY в OVER обязателен для определения порядка нумерации. См. [Глоссарий](glossary.md).

Пример: топ-3 по зарплате в каждом отделе (с подзапросом или WITH для фильтрации по rn):

```sql
SELECT department_id, last_name, salary,
       ROW_NUMBER() OVER (PARTITION BY department_id ORDER BY salary DESC) AS rn,
       RANK()       OVER (PARTITION BY department_id ORDER BY salary DESC) AS rk,
       DENSE_RANK() OVER (PARTITION BY department_id ORDER BY salary DESC) AS dr
  FROM employees
 ORDER BY department_id, salary DESC;
```

Чтобы оставить только первые три по зарплате в отделе: обернуть в подзапрос и взять WHERE rn <= 3 (или WHERE dr <= 3, если нужны «все с рангом не хуже 3» с учётом равенства).

## 6.2.4. Окно кадра (ROWS BETWEEN, RANGE)

Для агрегатных оконных функций можно сузить **кадр** — какие строки внутри партиции участвуют в расчёте. Задаётся после ORDER BY в OVER:

```sql
ROWS BETWEEN начало AND конец
-- или
RANGE BETWEEN начало AND конец
```

Типичные варианты начала и конца:

- **UNBOUNDED PRECEDING** — от первой строки партиции (по ORDER BY).
- **CURRENT ROW** — до/включая текущую строку.
- **UNBOUNDED FOLLOWING** — до последней строки партиции.
- **n PRECEDING** / **n FOLLOWING** — n строк до/после текущей (для ROWS).

Пример: скользящее среднее по трём строкам (текущая и две предыдущие по ORDER BY):

```sql
SELECT id, dt, value,
       AVG(value) OVER (ORDER BY dt ROWS BETWEEN 2 PRECEDING AND CURRENT ROW) AS moving_avg_3
  FROM sensor_readings;
```

Без указания кадра при наличии ORDER BY в Oracle для агрегатов по умолчанию используется RANGE BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW (нарастающий итог). Чтобы получить одно значение на всю партицию (например, SUM по отделу в каждой строке), либо не указывать ORDER BY в OVER, либо задать кадр **ROWS BETWEEN UNBOUNDED PRECEDING AND UNBOUNDED FOLLOWING**. См. [Глоссарий](glossary.md).

## Ключевое

- **Оконная функция** вычисляется по набору строк (окну), заданному в **OVER**, при этом все строки результата сохраняются; каждая строка получает значение функции для своего окна. См. [Глоссарий](glossary.md).
- **PARTITION BY** в OVER разбивает строки на партиции; функция считается отдельно по каждой партиции. **ORDER BY** в OVER задаёт порядок внутри партиции (для ранжирования и для нарастающего итога при агрегатах).
- Агрегатные функции (SUM, AVG, COUNT, MIN, MAX) с OVER работают как оконные; при ORDER BY без кадра по умолчанию — нарастающий итог от начала партиции до текущей строки.
- **ROW_NUMBER()** — уникальный номер строки в партиции; **RANK()** — ранг с пропусками при равенстве; **DENSE_RANK()** — ранг без пропусков. Для них в OVER обязателен ORDER BY.
- **Окно кадра** (ROWS/RANGE BETWEEN ... AND ...) ограничивает строки партиции для расчёта агрегата (например, скользящее среднее по N строкам).

В [§6.3](chapter-06-03.md) рассмотрим функции, специфичные для Oracle: LISTAGG, NTH_VALUE и другие аналитические возможности.
