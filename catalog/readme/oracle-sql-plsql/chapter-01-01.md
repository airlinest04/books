# §1.1 Экосистема Oracle

Этот раздел открывает книгу «Oracle SQL и PL/SQL» и задаёт общий контекст: из каких частей состоит экосистема Oracle, с чем вы будете работать при изучении SQL и PL/SQL. Мы введём ключевые понятия — **СУБД Oracle Database**, **схема (schema)**, **пользователь**, **табличное пространство (tablespace)** — и кратко опишем основные клиентские средства (SQL*Plus, SQL Developer и другие), через которые выполняются запросы и скрипты. Понимание этой картины нужно, чтобы осознанно подключаться к базе (§1.2), ориентироваться в объектах схемы (§1.3) и выполнять первый запрос (§1.4). См. [Глоссарий](glossary.md).

---

## 1.1.1. Oracle Database как СУБД

**Oracle Database** — реляционная система управления базами данных (СУБД), разрабатываемая и поставляемая корпорацией Oracle. Она хранит данные в таблицах, поддерживает язык SQL для выборки и изменения данных и язык PL/SQL для процедурной логики на стороне сервера. В контексте этой книги под «Oracle» или «базой Oracle» мы подразумеваем именно серверную СУБД Oracle Database (а не, например, прикладные продукты вроде Oracle Applications). См. [Глоссарий](glossary.md).

Сервер Oracle Database работает как отдельный процесс (или набор процессов в зависимости от конфигурации и платформы). Клиентские приложения подключаются к нему по сети по протоколу, использующему, в частности, **Oracle Net** (ранее — SQL*Net): указывают хост, порт, имя службы (service name) или SID и учётные данные пользователя. После установления соединения клиент отправляет SQL-запросы и PL/SQL-блоки; сервер выполняет их и возвращает результаты. Таким образом, экосистема складывается из **сервера** (сама СУБД и экземпляр базы данных) и **клиентов** (инструменты и приложения, с помощью которых пользователь или программа обращаются к базе). Роли и привилегии пользователей, а также способ задания строки подключения мы разберём в [§1.2](chapter-01-02.md).

## 1.1.2. Схемы и пользователи

В Oracle понятия **пользователь (user)** и **схема (schema)** тесно связаны. См. [Глоссарий](glossary.md).

**Пользователь** — учётная запись, под которой выполняется вход в базу данных. Пользователь имеет имя и пароль (или другой способ аутентификации, например через внешние директории или сертификаты). При создании пользователя администратор задаёт ему по умолчанию табличное пространство для хранения объектов, табличное пространство для временных данных (temp), квоты по табличным пространствам и роли/привилегии.

**Схема** — совокупность объектов базы данных, принадлежащих данному пользователю. К объектам схемы относятся таблицы, представления (views), индексы, последовательности (sequences), синонимы (synonyms), процедуры, функции, пакеты, триггеры и др. В Oracle **имя схемы совпадает с именем пользователя-владельца**: при создании пользователя автоматически создаётся схема с тем же именем, и все объекты, созданные этим пользователем по умолчанию, попадают в его схему. Поэтому в документации и в обиходе часто говорят «схема SCOTT» или «пользователь SCOTT» — имея в виду и учётную запись, и набор принадлежащих ей объектов. Обращение к объекту из другой схемы выполняется в форме `schema_name.object_name`, например `HR.EMPLOYEES`.

Важно: один и тот же физический сервер Oracle Database может обслуживать множество пользователей и схем. Каждый пользователь видит свои объекты по умолчанию без префикса; объекты других схем — только если ему выданы соответствующие привилегии (SELECT, INSERT и т.д. на таблицы, EXECUTE на процедуры и т.п.). Каталог объектов (представления словаря данных USER_*, ALL_*, DBA_*) мы рассмотрим в [§1.3](chapter-01-03.md).

## 1.1.3. Табличные пространства

**Табличное пространство (tablespace)** — логический контейнер для хранения данных в Oracle. Оно не «привязано» к одному пользователю или схеме: в одном табличном пространстве могут храниться сегменты (таблицы, индексы) разных схем. С точки зрения администратора табличные пространства позволяют управлять размещением данных на диске: например, вынести тяжёлые таблицы в отдельное табличное пространство на быстрых дисках или ограничить квоту пользователя по объёму в конкретном табличном пространстве. См. [Глоссарий](glossary.md).

По документации Oracle ([Logical Storage Structures](https://docs.oracle.com/en/database/oracle/oracle-database/19/cncpt/logical-storage-structures.html)):

- **Табличное пространство** — единица логического хранения, объединяющая один или несколько **сегментов**. Сегмент — объект, занимающий место (таблица, индекс и т.п.). Каждый сегмент состоит из **экстентов** (наборов логически последовательных блоков данных), а данные хранятся в **блоках данных (data blocks)** — минимальных единицах ввода-вывода Oracle.
- На физическом уровне табличное пространство хранит данные в одном или нескольких **файлах данных (data files)** (или temp files для временных табличных пространств). То есть табличное пространство связывает логический уровень (сегменты, экстенты, блоки) с физическим (файлы на диске).

Типичные табличные пространства в созданной по умолчанию базе:

| Табличное пространство | Назначение |
|------------------------|------------|
| SYSTEM | Служебные объекты СУБД, словарь данных. Пользовательские объекты в нём создавать не рекомендуется. |
| SYSAUX | Вспомогательные объекты Oracle (статистика, логи и т.п.). Также не предназначено для пользовательских таблиц. |
| USERS | Часто используется по умолчанию для объектов пользователей (таблицы, индексы учебных и рабочих схем). |
| TEMP | Временные данные (сортировки, временные таблицы в рамках сессии). |

При создании пользователя обычно указывают DEFAULT TABLESPACE (например, USERS) и TEMPORARY TABLESPACE (TEMP). Все созданные этим пользователем таблицы и индексы по умолчанию будут размещаться в его DEFAULT TABLESPACE, если при CREATE TABLE не указано иное. Для разработчика и написания SQL/PL-SQL достаточно понимать, что данные хранятся в табличных пространствах в виде файлов на диске и что у пользователя есть квота по табличному пространству; тонкости управления экстентами и локально управляемые табличные пространства остаются в зоне ответственности администратора.

## 1.1.4. Клиенты: SQL*Plus, SQL Developer и другие

Чтобы выполнять SQL и PL/SQL, нужен **клиент** — программа, которая устанавливает соединение с сервером Oracle и отправляет ему команды. Ниже перечислены основные варианты. См. [Глоссарий](glossary.md).

**SQL*Plus** — классический консольный клиент Oracle. Поставляется вместе с Oracle Database (на сервере) и с Oracle Instant Client (на рабочей машине). Запуск из командной строки, например: `sqlplus username/password@host:port/service_name`. Внутри SQL*Plus вводятся SQL-запросы и PL/SQL-блоки; результат выводится в консоль. Поддерживает выполнение скриптов из файлов (`@script.sql`), настройку формата вывода (COLUMN, PAGESIZE и т.д.) и базовые команды (DESCRIBE, SPOOL, EXIT). Удобен для быстрых проверок, автоматизации в скриптах и работы в терминале без графического интерфейса.

**Oracle SQL Developer** — бесплатная графическая среда от Oracle. Редактор запросов с подсветкой синтаксиса, список соединений, браузер объектов по схемам (таблицы, представления, процедуры и т.д.), отладчик PL/SQL, экспорт данных. Работает на любой платформе (Java). Часто используется как основной инструмент разработки и обучения: удобно просматривать структуру таблиц, выполнять запросы по частям и сохранять скрипты.

**Другие клиенты:** существуют сторонние и корпоративные инструменты (DBeaver, Toad, Oracle SQL Developer Web в облаке и др.), а также драйверы для приложений (OCI, JDBC, ODP.NET и т.п.), через которые приложение подключается к Oracle и выполняет SQL из кода. Для прохождения материала книги достаточно одного из SQL*Plus или SQL Developer; подключение и первый запрос мы выполним в [§1.2](chapter-01-02.md) и [§1.4](chapter-01-04.md).

## 1.1.5. Как связаны компоненты экосистемы

Кратко сведём в одну картину:

1. **Сервер Oracle Database** — хранит данные, выполняет SQL и PL/SQL. Данные логически организованы в табличных пространствах; физически — в файлах данных на диске.
2. **Пользователи и схемы** — каждый пользователь имеет схему с тем же именем; в ней лежат его таблицы, представления, процедуры и прочие объекты. Объекты размещаются в табличных пространствах (чаще всего в том, что задан как DEFAULT для пользователя).
3. **Клиент** — подключается к серверу по сети, передаёт учётные данные пользователя, отправляет запросы и получает результаты. SQL*Plus и SQL Developer — два основных способа интерактивной работы с базой в рамках этой книги.

Администратор создаёт пользователей, табличные пространства и выдаёт привилегии; разработчик или обучающийся подключается под своим пользователем через клиент и работает с объектами своей схемы (и при необходимости с объектами других схем при наличии прав). В следующем разделе мы разберём, как именно задаётся строка подключения и какие параметры влияют на успешное подключение к базе.

## 1.1.6. Типичные ошибки при первом знакомстве с экосистемой

- **Путать пользователя и схему в других СУБД:** в Oracle схема и пользователь — одна сущность по имени; в некоторых других СУБД «схема» может быть отдельным пространством имён при одном пользователе. В Oracle при обращении к объекту другой схемы всегда используйте префикс `schema_name.object_name` и учёт привилегий.
- **Создавать пользовательские объекты в SYSTEM/SYSAUX:** системные табличные пространства предназначены для служебных объектов Oracle. Создавайте таблицы и индексы в USERS или в выделенном для вас табличном пространстве, иначе возможны проблемы с производительностью и рекомендациями Oracle.
- **Не различать сервер и клиент:** сервер — это экземпляр Oracle Database (процесс(ы) на хосте). SQL*Plus и SQL Developer — клиенты; они только передают запросы на сервер. Установка только клиента без доступа к серверу не даёт «базы» — нужен доступ к работающему серверу (локально или по сети).
- **Игнорировать имя службы при подключении:** в современных установках часто используется **service name** (например, из listener’а), а не только SID. Неверный сервис или хост/порт приводят к ошибке подключения; параметры нужно уточнять у администратора или в конфигурации окружения.

## Ключевое

- **Oracle Database** — реляционная СУБД Oracle; сервер принимает подключения по сети и выполняет SQL и PL/SQL.
- **Пользователь** — учётная запись для входа; **схема** — набор объектов, принадлежащих пользователю. В Oracle имя схемы совпадает с именем пользователя.
- **Табличное пространство (tablespace)** — логический контейнер для сегментов (таблиц, индексов); физически данные хранятся в файлах данных (data files). Типичные пространства: SYSTEM, SYSAUX (служебные), USERS (пользовательские объекты), TEMP (временные данные).
- **Клиент** — программа для подключения к серверу и выполнения запросов. **SQL*Plus** — консольный клиент; **SQL Developer** — графическая среда. Оба подходят для изучения SQL и PL/SQL по этой книге.
- Объекты другой схемы указываются как `schema_name.object_name`; доступ к ним возможен только при наличии соответствующих привилегий.

В [§1.2](chapter-01-02.md) мы разберём подключение к базе: строку подключения, имя службы (service name), роли и привилегии, необходимые для работы с объектами схемы.
