# §5.1 INSERT

В [§4.4](chapter-04-04.md) мы завершили главу о соединениях и подзапросах. Теперь переходим к **изменению данных**: вставке, обновлению и удалению. Оператор **INSERT** добавляет строки в таблицу. В этом разделе рассмотрим **вставку одной строки** (VALUES), **вставку нескольких строк** и **вставку из результата запроса** (INSERT ... SELECT), а также предложение **RETURNING INTO** в PL/SQL для получения сгенерированных значений (например, из последовательности). UPDATE и DELETE — в [§5.2](chapter-05-02.md) и [§5.3](chapter-05-03.md). См. [Глоссарий](glossary.md).

---

## 5.1.1. Вставка одной строки (VALUES)

Синтаксис вставки **одной строки** с явным перечислением значений:

```sql
INSERT INTO имя_таблицы [(столбец1, столбец2, ...)] VALUES (значение1, значение2, ...);
```

Список столбцов необязателен: если его опустить, значения задаются **в порядке столбцов таблицы** (как в словаре данных) и их должно быть столько, сколько столбцов в таблице. Если список столбцов указан, значения задаются **в том же порядке**; столбцы, не перечисленные в списке, получают значение по умолчанию (DEFAULT) или NULL (если столбец допускает NULL). См. [Глоссарий](glossary.md).

Пример (таблица products с столбцами id, name, price, created_at):

```sql
INSERT INTO products (id, name, price) VALUES (1, 'Keyboard', 29.99);
```

Столбец created_at не указан — в него подставится NULL или DEFAULT, если он задан при создании таблицы. Другой вариант — указать все столбцы и для части использовать DEFAULT или явный NULL:

```sql
INSERT INTO products VALUES (2, 'Mouse', 19.99, DEFAULT);
```

Строковые и датные литералы — в одинарных кавычках; числа — без кавычек. Типы значений должны быть совместимы с типами столбцов. Одна команда INSERT ... VALUES добавляет **одну строку**; для нескольких строк в Oracle выполняют несколько INSERT или используют INSERT ... SELECT (см. ниже).

---

## 5.1.2. Вставка с последовательностью (NEXTVAL)

Если первичный ключ или другой столбец заполняется из **последовательности**, в списке значений указывают **имя_последовательности.NEXTVAL**. См. [Глоссарий](glossary.md) и [§2.5](chapter-02-05.md).

Пример:

```sql
INSERT INTO products (id, name, price) VALUES (products_seq.NEXTVAL, 'Monitor', 199.00);
```

При каждой вставке NEXTVAL выдаёт следующее значение. Для столбца с датой по умолчанию можно использовать SYSDATE или, например, DEFAULT, если для столбца задано DEFAULT SYSDATE.

---

## 5.1.3. Вставка нескольких строк

В Oracle один оператор **INSERT ... VALUES** вставляет **только одну строку**. Чтобы вставить несколько строк одним оператором, используют **INSERT ... SELECT**: подзапрос или объединение запросов (UNION ALL) возвращает несколько строк, и каждая вставляется в таблицу. См. [Глоссарий](glossary.md).

Пример вставки нескольких строк через SELECT из DUAL с UNION ALL:

```sql
INSERT INTO products (id, name, price)
SELECT 10, 'Item1', 10.00 FROM DUAL
UNION ALL
SELECT 11, 'Item2', 20.00 FROM DUAL
UNION ALL
SELECT 12, 'Item3', 30.00 FROM DUAL;
```

Либо вставка из другой таблицы или подзапроса (см. 5.1.4). Альтернатива — выполнить несколько отдельных INSERT ... VALUES в цикле в PL/SQL или из приложения.

---

## 5.1.4. INSERT ... SELECT: вставка из результата запроса

Синтаксис **INSERT ... SELECT** позволяет вставить в таблицу **все строки**, возвращаемые запросом SELECT. Число и типы столбцов в SELECT должны соответствовать списку столбцов в INSERT (или порядку столбцов таблицы, если список столбцов опущен). См. [Глоссарий](glossary.md).

Пример: копирование части данных из одной таблицы в другую (или в ту же с другой структурой):

```sql
INSERT INTO products_archive (id, name, price, archived_at)
SELECT id, name, price, SYSDATE FROM products WHERE status = 'DISCONTINUED';
```

Другой пример — перенос данных из одной схемы в другую, из представления, из подзапроса с вычислениями. Подзапрос может содержать выражения, функции, JOIN; главное — количество и совместимость типов столбцов с целевой таблицей.

## 5.1.5. RETURNING INTO в PL/SQL

После INSERT (а также UPDATE и DELETE) можно указать предложение **RETURNING** — перечислить столбцы, значения которых нужно вернуть (например, сгенерированный первичный ключ или значение по умолчанию). В **PL/SQL** эти значения принимаются через **RETURNING INTO** в переменные. См. [Глоссарий](glossary.md).

Синтаксис (в контексте PL/SQL):

```sql
INSERT INTO таблица (...) VALUES (...) RETURNING столбец1, столбец2 INTO переменная1, переменная2;
```

Пример: вставка строки с последовательностью и получение вставленного id:

```sql
DECLARE
  v_id NUMBER;
BEGIN
  INSERT INTO products (id, name, price) VALUES (products_seq.NEXTVAL, 'New Product', 99.00)
  RETURNING id INTO v_id;
  -- v_id содержит значение, записанное в id
  DBMS_OUTPUT.PUT_LINE('Inserted id: ' || v_id);
END;
/
```

Для **одной** вставленной строки RETURNING INTO передаёт значения в скалярные переменные. Если INSERT ... SELECT вставляет **несколько строк**, в одном операторе RETURNING INTO с обычными переменными можно получить только **одну** строку (Oracle вернёт ошибку при нескольких). Для множественной вставки в PL/SQL используют **RETURNING ... BULK COLLECT INTO** в коллекцию (массив). Детали PL/SQL — в части II книги. В чистом SQL (без PL/SQL) RETURNING просто возвращает результат в консоль или в интерфейс клиента, если он это поддерживает. См. [Глоссарий](glossary.md).

## 5.1.6. Типичные ошибки при использовании INSERT

- **Несовпадение числа или порядка столбцов и значений:** в VALUES должно быть столько значений, сколько столбцов в списке (или в таблице при отсутствии списка); порядок должен совпадать. Иначе ORA-00913 (too many values) или ORA-00947 (not enough values).
- **Нарушение ограничений целостности:** дубликат первичного ключа или уникального ключа, нарушение внешнего ключа, NOT NULL для столбца без значения и без DEFAULT. Oracle вернёт соответствующую ошибку (ORA-00001, ORA-02291 и т.д.). Проверьте данные и ограничения.
- **Неверный тип или формат:** строка в числовой столбец, неверный формат даты при неявном преобразовании. Используйте явное преобразование (TO_DATE, TO_NUMBER) или литералы правильного формата.
- **INSERT ... SELECT: разное число столбцов:** список столбцов в INSERT и список в SELECT должны соответствовать по количеству и по типам. Иначе синтаксическая ошибка или ORA-00932.
- **RETURNING INTO при множественной вставке в скалярные переменные:** при вставке нескольких строк через INSERT ... SELECT с RETURNING INTO скалярные переменные использовать нельзя — нужен BULK COLLECT INTO в коллекцию.
- **Забыть COMMIT:** INSERT меняет данные в рамках транзакции; изменения видны другим сессиям только после COMMIT. В некоторых клиентах при выходе выполняется откат (ROLLBACK), если COMMIT не был выполнен.

## Ключевое

- **INSERT INTO таблица [(столбцы)] VALUES (значения)** — вставка одной строки. Порядок значений соответствует порядку столбцов. Неуказанные столбцы получают DEFAULT или NULL.
- Для **нескольких строк** в одном операторе используют **INSERT ... SELECT** (подзапрос или UNION ALL). Один INSERT ... VALUES в Oracle вставляет одну строку.
- **INSERT INTO таблица [(столбцы)] SELECT ...** — вставка всех строк из результата запроса. Число и типы столбцов SELECT должны соответствовать целевым столбцам.
- **NEXTVAL** в VALUES подставляет следующее значение последовательности (для первичного ключа и т.п.).
- **RETURNING столбцы INTO переменные** в PL/SQL возвращает значения вставленных строк (например, id) в переменные. При вставке нескольких строк — **BULK COLLECT INTO** в коллекцию.
- После INSERT для сохранения изменений в базе выполните **COMMIT** (если не используете авто-коммит).
