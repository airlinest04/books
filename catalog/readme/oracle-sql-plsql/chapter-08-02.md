# §8.2 Уровни изоляции

В [§8.1](chapter-08-01.md) мы разобрали транзакции, COMMIT и ROLLBACK. **Уровень изоляции** определяет, какие изменения других транзакций видит текущая сессия и какие аномалии чтения допускаются (грязное чтение, неповторяемое чтение, фантомы). В Oracle по умолчанию используется **READ COMMITTED**; при необходимости можно установить **SERIALIZABLE**. В этом разделе — понятия грязного, неповторяемого и фантомного чтения, уровни READ COMMITTED и SERIALIZABLE в Oracle, а также установка уровня (**SET TRANSACTION**). SAVEPOINT — в [§8.3](chapter-08-03.md). См. [Глоссарий](glossary.md).

---

## 8.2.1. Аномалии чтения: грязное, неповторяемое, фантом

**Грязное чтение** (dirty read) — чтение строки, изменённой другой транзакцией, которая ещё **не сделала COMMIT**. Если та транзакция затем сделает ROLLBACK, мы увидели данные, «не существовавшие» в итоге. В Oracle **грязное чтение не допускается**: незакоммиченные изменения других сессий не видны. См. [Глоссарий](glossary.md).

**Неповторяемое чтение** (non-repeatable read) — в одной транзакции дважды прочитали одну и ту же строку (по одному ключу) и получили **разные значения**: между чтениями другая транзакция сделала UPDATE и COMMIT. Уровень READ COMMITTED это допускает; SERIALIZABLE — нет (текущая транзакция видит снимок данных на момент своего начала).

**Фантомное чтение** (phantom read) — в одной транзакции дважды выполнили один и тот же запрос с условием (например, SELECT ... WHERE dept_id = 10) и получили **разное число строк**: между запросами другая транзакция вставила или удалила строки и закоммитила. READ COMMITTED допускает фантомы; SERIALIZABLE их устраняет (в рамках видимости сериализуемой транзакции).

Уровень изоляции задаёт, какие из этих аномалий запрещены. Чем строже изоляция, тем меньше «чужих» изменений видно, но тем выше риск ожиданий и откатов из-за конфликтов. См. [Глоссарий](glossary.md).

---

## 8.2.2. READ COMMITTED (по умолчанию в Oracle)

В Oracle **уровень изоляции по умолчанию — READ COMMITTED**. Это значит: транзакция видит только **закоммиченные** данные других транзакций; грязное чтение исключено. Каждый запрос в рамках транзакции видит снимок данных на момент **начала этого запроса** (statement-level consistency): если между двумя SELECT в одной транзакции другая сессия закоммитила изменения, второй SELECT может увидеть новые данные — возможны неповторяемое и фантомное чтение. См. [Глоссарий](glossary.md).

Поведение при изменении строки другой сессией: если наша сессия пытается прочитать или изменить строку, заблокированную другой сессией (ещё не COMMIT), наша сессия **ждёт** снятия блокировки (или таймаута). После COMMIT другой сессии мы видим обновлённые данные. Так достигается баланс между согласованностью и параллелизмом: длинные транзакции не блокируют чтение уже закоммиченного.

---

## 8.2.3. SERIALIZABLE

Уровень **SERIALIZABLE** даёт изоляцию «как будто транзакции выполнялись строго по очереди». Транзакция видит только данные, закоммиченные **до её начала**; все последующие COMMIT других сессий для неё невидимы. Исключаются неповторяемое и фантомное чтение: повторный запрос в той же транзакции вернёт тот же результат (в пределах снимка на начало транзакции). См. [Глоссарий](glossary.md).

Недостаток: если наша сессия в режиме SERIALIZABLE попытается изменить строку, которую уже изменила и закоммитила другая сессия после начала нашей транзакции, Oracle вернёт ошибку **ORA-08177: can't serialize access for this transaction**. Транзакцию придётся повторить (откат и новая попытка). SERIALIZABLE используют, когда нужна строгая повторяемость чтения и готовы к повторным попыткам при конфликтах; для большинства приложений достаточно READ COMMITTED.

---

## 8.2.4. Установка уровня изоляции (SET TRANSACTION)

Уровень изоляции задаётся в начале транзакции командой **SET TRANSACTION**:

```sql
SET TRANSACTION ISOLATION LEVEL READ COMMITTED;
-- или
SET TRANSACTION ISOLATION LEVEL SERIALIZABLE;
```

**SET TRANSACTION** действует на **текущую** транзакцию; транзакция при этом должна быть «пустой» (до первого DML или сразу после COMMIT/ROLLBACK). Если транзакция уже начата (есть незакоммиченный DML), выполнить SET TRANSACTION нельзя — сначала COMMIT или ROLLBACK. После установки уровень действует до конца транзакции; следующая транзакция снова по умолчанию READ COMMITTED, если не задать иное. См. [Глоссарий](glossary.md).

Дополнительно: **SET TRANSACTION READ ONLY** — транзакция только для чтения (никакой DML); видимость как у READ COMMITTED по закоммиченным данным, но явно запрещены изменения. **SET TRANSACTION READ WRITE** — явно разрешить запись (по умолчанию и так).

---

## Ключевое

- **Уровень изоляции** определяет, видит ли транзакция незакоммиченные изменения других (грязное чтение) и могут ли меняться результаты повторных запросов (неповторяемое и фантомное чтение). См. [Глоссарий](glossary.md).
- В Oracle по умолчанию **READ COMMITTED**: видны только закоммиченные данные; грязного чтения нет; неповторяемое и фантомное чтение возможны.
- **SERIALIZABLE** — снимок данных на начало транзакции; неповторяемое и фантомное чтение исключены; при конфликте записи — ORA-08177, нужен откат и повтор.
- Уровень задаётся в начале транзакции: **SET TRANSACTION ISOLATION LEVEL READ COMMITTED | SERIALIZABLE** (транзакция должна быть пустой).

В [§8.3](chapter-08-03.md) мы рассмотрим SAVEPOINT: откат к именованной точке внутри транзакции без отмены всей транзакции.
