# §8.1 Транзакции

В [§7.4](chapter-07-04.md) мы завершили главу о представлениях и материализованных представлениях. Операции **INSERT**, **UPDATE**, **DELETE**, **MERGE** меняют данные; до явного подтверждения изменения видны только в текущей сессии и могут быть отменены. **Транзакция** — логическая единица работы: последовательность операций, которая либо целиком фиксируется (**COMMIT**), либо целиком отменяется (**ROLLBACK**). В этом разделе — границы транзакции в Oracle, **COMMIT** и **ROLLBACK**, неявное завершение транзакции (отключение, DDL), а также зачем явно завершать транзакции. Уровни изоляции — в [§8.2](chapter-08-02.md). См. [Глоссарий](glossary.md).

---

## 8.1.1. Что такое транзакция

**Транзакция** — последовательность одного или нескольких операторов SQL (DML и при необходимости DDL), которая рассматривается как одно целое: либо все изменения сохраняются в базе, либо ни одно не применяется. Oracle обеспечивает свойства ACID: атомарность (всё или ничего), согласованность (ограничения не нарушаются после коммита), изолированность (другие сессии не видят незакоммиченные изменения в обычном режиме), долговечность (после COMMIT данные сохранены). См. [Глоссарий](glossary.md).

Транзакция **начинается** неявно: при первом выполнении DML (или при подключении к сессии, в зависимости от трактовки) после предыдущего COMMIT или ROLLBACK, либо сразу после подключения. Транзакция **заканчивается** явной командой **COMMIT** (зафиксировать) или **ROLLBACK** (отменить все изменения с начала транзакции), либо неявно — при отключении сессии, при выполнении DDL (CREATE, ALTER, DROP и т.д.: Oracle выполняет неявный COMMIT до и после DDL) и в ряде других случаев. См. [Глоссарий](glossary.md).

---

## 8.1.2. COMMIT и ROLLBACK

**COMMIT** — команда завершения транзакции с сохранением всех изменений. После COMMIT все сделанные в этой транзакции INSERT, UPDATE, DELETE, MERGE становятся постоянными; другие сессии видят новые данные; откатить их уже нельзя. В Oracle по умолчанию **автокоммита выключен**: каждая команда не завершает транзакцию сама по себе — нужно явно вызвать COMMIT. См. [Глоссарий](glossary.md).

**ROLLBACK** — команда отмены транзакции: все изменения текущей транзакции отменяются, данные возвращаются к состоянию на момент начала транзакции (или на последний COMMIT). Блокировки, удерживаемые сессией по изменённым строкам, освобождаются. См. [Глоссарий](glossary.md).

Пример: обновить цену и зафиксировать; при ошибке в следующем шаге — откатить.

```sql
UPDATE products SET price = 19.99 WHERE id = 5;
-- проверка результата
COMMIT;

UPDATE orders SET status = 'SHIPPED' WHERE order_id = 100;
-- если что-то пошло не так:
ROLLBACK;
-- иначе:
COMMIT;
```

SELECT не меняет данные и не обязан завершать транзакцию; транзакция может оставаться открытой, пока вы не выполните COMMIT, ROLLBACK или не завершите сессию. Долго открытая транзакция без COMMIT удерживает блокировки и может мешать другим сессиям; не оставляйте транзакции «висящими» без необходимости. Среда: Oracle Database.

## 8.1.3. Неявное завершение транзакции

В Oracle транзакция неявно завершается (как правило, **COMMIT**) в следующих случаях:

- **Нормальное отключение сессии** (закрытие окна SQL*Plus/SQL Developer, разрыв соединения) — Oracle выполняет COMMIT, если не было явного ROLLBACK. При **аварийном обрыве** соединения (сбой сети, падение клиента) сервер выполняет **ROLLBACK** незакоммиченной транзакции этой сессии.
- **Выполнение DDL** (CREATE TABLE, ALTER TABLE, DROP VIEW и т.д.) — перед выполнением DDL Oracle делает COMMIT текущей транзакции; после успешного выполнения DDL — снова COMMIT. Поэтому DDL нельзя откатить вместе с предшествующим DML в одной транзакции.
- В **SQL*Plus** можно включить **SET AUTOCOMMIT ON** (или коммит после каждой команды) — тогда после каждого успешного DML/DDL будет неявный COMMIT. По умолчанию AUTOCOMMIT OFF.

Учёт этих правил важен при скриптах: несколько DML подряд образуют одну транзакцию до явного COMMIT/ROLLBACK; вставленный DDL «разрежет» её неявным COMMIT. См. [Глоссарий](glossary.md).

---

## 8.1.4. Зачем явно завершать транзакции

Явный **COMMIT** после логически завершённой группы операций (например, «оформили заказ и обновили остатки») даёт предсказуемое состояние: данные зафиксированы, блокировки сняты, другие пользователи видят изменения. Явный **ROLLBACK** при ошибке или отмене действия отменяет только текущую транзакцию и не задевает уже закоммиченные данные.

Рекомендации: завершайте транзакцию (COMMIT или ROLLBACK) по завершении логической единицы работы; не держите длинные транзакции без необходимости; в скриптах с несколькими шагами решайте, коммитить после каждого шага или один раз в конце (с учётом риска частичного выполнения при сбое). Уровни изоляции и видимость изменений других сессий — в [§8.2](chapter-08-02.md).

---

## Ключевое

- **Транзакция** — логическая единица работы: последовательность DML (и при необходимости DDL), которая завершается **COMMIT** (сохранить все изменения) или **ROLLBACK** (отменить все изменения с начала транзакции). См. [Глоссарий](glossary.md).
- **COMMIT** фиксирует изменения; после него откат невозможен, блокировки освобождаются. **ROLLBACK** отменяет все изменения текущей транзакции. В Oracle по умолчанию автокоммит выключен — транзакцию нужно завершать явно.
- Транзакция неявно завершается при отключении сессии (обычно COMMIT), при аварийном обрыве (ROLLBACK), при выполнении DDL (неявный COMMIT до и после DDL).
- Долгая открытая транзакция без COMMIT удерживает блокировки; завершайте транзакции по завершении логической единицы работы.

В [§8.2](chapter-08-02.md) мы разберём уровни изоляции транзакций: как одна сессия видит изменения других и что такое «грязное» чтение и неповторяемое чтение.
