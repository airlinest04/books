# §6.3 Дашборды и отчётность

В [§6.2](chapter-06-02.md) мы разобрали пороги и алерты — реакцию на нарушение качества. Метрики и их тренды нужно не только собирать и сравнивать с порогами, но и **визуализировать** для оперативного обзора и отчётности. В этом разделе мы разберём **дашборды и отчётность** по качеству данных: какие метрики отображать, с какой периодичностью обновлять и для какой аудитории готовить представления. Интеграция проверок и метрик с Airflow и ETL — в [§6.4](chapter-06-04.md).

---

## 6.3.1. Зачем дашборды и отчётность

Метрики качества ([§6.1](chapter-06-01.md)), записанные в таблицу или в логи, сами по себе не дают быстрого обзора: нужно открыть отчёт или запрос. **Дашборд** — сводный экран с ключевыми метриками и трендами, обновляемый по расписанию или по запросу. **Отчётность** — периодические сводки (ежедневный, еженедельный отчёт по качеству) для руководства, владельцев данных или регуляторов. Цели: оперативно видеть состояние качества по пайплайнам и витринам; выявлять тренды и аномалии до срабатывания алертов; отчитываться перед заинтересованными сторонами и аудиторами. См. [Глоссарий](glossary.md).

---

## 6.3.2. Какие метрики отображать

На дашборде и в отчётах обычно показывают метрики, которые уже собираются ([§6.1](chapter-06-01.md)), сгруппированные по смыслу:

**Сводка по пайплайнам (или по витринам):**

- Текущее состояние за последний срез/день: % валидных записей, число отклонённых, факт выполнения SLA (загрузка к дедлайну), расхождение контрольных сумм (да/нет).
- Индикатор относительно порога: зелёный/жёлтый/красный или «в норме» / «предупреждение» / «инцидент» по каждому пайплайну.

**Тренды:**

- График % валидных записей по дням (или по прогонам) за последние N дней.
- График числа отклонённых по дням; при детализации — по правилам или по измерениям качества.
- График выполнения SLA (доля дней с загрузкой в срок) за месяц.

**Детализация при инциденте:**

- По выбранному пайплайну и дате: разбивка отклонённых по правилам, топ причин отклонения, ссылка на кварантин или журнал ошибок.
- Контрольные суммы по этапам (extract, transform, load) для разбора расхождений.

Выбор метрик зависит от аудитории (см. ниже): операционный дашборд для инженеров — больше деталей по пайплайнам и правилам; дашборд для руководства — сводка по витринам и тренд за период. См. [Глоссарий](glossary.md).

## 6.3.3. Периодичность обновления

**Периодичность** — как часто обновляются данные на дашборде или как часто формируется отчёт.

- **Дашборд в реальном времени или с задержкой в минуты:** метрики подтягиваются из таблицы метрик или из логов после каждого прогона пайплайна; подходит для операционного мониторинга инженерами. Обновление — по расписанию (каждые 5–15 минут) или по событию (после завершения пайплайнов).
- **Ежедневный дашборд/отчёт:** сводка за прошедший день (или за последний завершённый срез); утром следующего дня актуальная картина за вчера. Подходит для ежедневного обзора владельцами данных и аналитиками.
- **Еженедельный или ежемесячный отчёт:** агрегаты за неделю/месяц — тренды, количество инцидентов, % выполнения SLA; для руководства и для аудита.

Периодичность задаётся исходя из частоты загрузок (если пайплайны раз в день — ежедневный обзор достаточен) и от потребностей аудитории. См. [Глоссарий](glossary.md).

## 6.3.4. Аудитория

Разные роли смотрят на качество с разных сторон; дашборды и отчёты можно разделить по аудитории.

| Аудитория | Что им нужно | Типичное представление |
|-----------|--------------|-------------------------|
| **Инженеры данных, разработчики пайплайнов** | Детали по пайплайнам: метрики за последние прогоны, причины отклонений, контрольные суммы по этапам, ссылки на логи и кварантин. | Операционный дашборд с фильтром по пайплайну и дате; обновление после прогонов. |
| **Владельцы данных, аналитики** | Сводка по витринам: пригодны ли данные за вчера, тренд % валидных и числа отклонённых, выполнение SLA. | Ежедневный дашборд по витринам; еженедельный краткий отчёт. |
| **Руководство, регуляторика, аудит** | Сводные показатели за период: количество инцидентов качества, % выполнения SLA, тренд по ключевым витринам; без избыточной технической детализации. | Еженедельный или ежемесячный отчёт; дашборд «только ключевые метрики» с фильтром по периоду. |

Один и тот же источник данных (таблица метрик) может питать несколько представлений: операционный дашборд в Grafana или в внутреннем инструменте, еженедельный PDF или сводка в Confluence — разная фильтрация и агрегация под аудиторию. См. [Глоссарий](glossary.md).

---

## 6.3.5. Формат и инструменты

Формат представления зависит от возможностей организации:

- **Интерактивный дашборд:** Grafana, Metabase, Tableau, облачные BI-инструменты, внутренние порталы. Подключение к таблице метрик или к хранилищу логов; графики и таблицы с фильтрами по дате, пайплайну, витрине.
- **Периодический отчёт:** автоматически генерируемый документ (PDF, HTML, письмо со сводкой) по расписанию — например, ежедневно в 08:00 сводка за вчера по ключевым пайплайнам.
- **Лог и таблица метрик как «отчёт»:** для малых команд достаточно таблицы метрик и запросов по ней; «дашборд» — сохранённый запрос с параметрами.

Книга не привязана к конкретному инструменту; важно, чтобы метрики были доступны для визуализации (данные в таблице или в системе, из которой можно строить графики и отчёты). См. [Глоссарий](glossary.md).

## 6.3.6. Сводка: что отображать и для кого

| Элемент | Рекомендация |
|---------|--------------|
| Метрики на дашборде | % валидных, число отклонённых, выполнение SLA, расхождение контрольных сумм; тренды по дням; при детализации — по правилам и по измерениям качества. |
| Периодичность | Операционный дашборд — обновление после прогонов или каждые N минут; сводка за день — утром следующего дня; отчёт за неделю/месяц — по расписанию. |
| Аудитория | Инженеры — детали по пайплайнам и прогонам; владельцы данных — сводка по витринам за день; руководство и аудит — сводка за период без избыточной техники. |
| Формат | Интерактивный дашборд (Grafana, BI) или периодический отчёт (PDF, письмо); источник — таблица метрик и логи. |

Дашборды и отчётность опираются на собранные метрики ([§6.1](chapter-06-01.md)) и на пороги ([§6.2](chapter-06-02.md)); без стабильного сбора метрик дашборд не будет содержательным. См. [Глоссарий](glossary.md).

## 6.3.7. Типичные ошибки

- **Показывать всё подряд:** перегруженный дашборд с десятками метрик по всем пайплайнам затрудняет обзор; лучше иерархия: сводный экран → детализация по клику или по выбору пайплайна.
- **Игнорировать аудиторию:** один дашборд «для всех» часто не устраивает ни инженеров (мало деталей), ни руководство (много техники); целесообразно отдельные представления или фильтры под роли.
- **Не обновлять данные:** дашборд, питаемый устаревшим срезом или без расписания обновления, создаёт иллюзию актуальности; нужно явное расписание или триггер обновления.
- **Отчётность без связи с действиями:** отчёт «качество за месяц» полезен, если по нему принимают решения (пересмотр правил, приоритеты исправлений); иначе отчётность становится формальной.

---

## Ключевое

- **Дашборды и отчётность** дают визуальный обзор метрик качества: оперативное состояние по пайплайнам и витринам, тренды, выявление аномалий и основа для отчётности перед аудиторией.
- **Метрики на дашборде:** % валидных, число отклонённых, выполнение SLA, расхождение контрольных сумм; тренды по дням; при детализации — по правилам и по измерениям качества.
- **Периодичность:** операционный дашборд — обновление после прогонов или по интервалу; ежедневная сводка — утром за вчера; еженедельный/ежемесячный отчёт — по расписанию.
- **Аудитория:** инженеры — детали по пайплайнам; владельцы данных — сводка по витринам; руководство и аудит — сводка за период без избыточной техники.
- Формат — интерактивный дашборд (Grafana, BI) или периодический отчёт; источник — таблица метрик; дашборды опираются на стабильный сбор метрик и пороги.

В [§6.4](chapter-06-04.md) мы разберём **интеграцию с Airflow и ETL**: проверки качества как таски, условное продолжение при ошибке, логи и уведомления.
