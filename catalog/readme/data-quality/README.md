## Подробное содержание

### Глава 1. Что такое качество данных

* **1.1 Определение качества данных** — данные пригодны для использования; соответствие требованиям; «фитнес для цели».
* **1.2 Зачем измерять качество** — снижение рисков; доверие к отчётам; регуляторика; затраты на исправление.
* **1.3 Связь с ETL и DWH** — качество на каждом этапе пайплайна; проверки до и после загрузки; связь с книгами по ETL, DWH, сверке.
* **1.4 Качество vs тестирование** — качество: непрерывные проверки, мониторинг; тестирование: проверка корректности пайплайна; связь с книгой по тестированию.
* _Ключевое:_ определение качества, ETL, DWH, отличие от тестирования. _Задания:_ выделить точки проверки в пайплайне.

***

### Глава 2. Измерения качества (Data Quality Dimensions)

* **2.1 Полнота (Completeness)** — отсутствие null, обязательные поля заполнены; доля заполненных полей; пропуски по партициям.
* **2.2 Точность (Accuracy)** — данные соответствуют реальности; корректные значения, форматы; сравнение с эталоном.
* **2.3 Согласованность (Consistency)** — одинаковые данные в разных источниках; ссылочная целостность; консистентность бизнес-правил.
* **2.4 Своевременность (Timeliness)** — данные актуальны; задержка загрузки; SLA.
* **2.5 Уникальность (Uniqueness)** — нет дубликатов; уникальные ключи; детекция дублей.
* **2.6 Валидность (Validity)** — значения в допустимом диапазоне; соответствие формату; справочники.
* _Ключевое:_ шесть измерений, примеры, связь с проверками. _Задания:_ для сценария определить релевантные измерения.

***

### Глава 3. Профилирование данных

* **3.1 Что такое профилирование** — анализ структуры и содержимого; выявление аномалий до загрузки; первичная оценка качества.
* **3.2 Статистики и распределения** — COUNT, MIN, MAX, AVG; гистограммы; частота значений; паттерны.
* **3.3 Null, дубликаты, выбросы** — доля null по полям; детекция дублей по ключу; выбросы (статистические, доменные).
* **3.4 Профилирование в SQL** — запросы для профилирования; примеры на PostgreSQL/Oracle; скрипты.
* _Ключевое:_ профилирование, статистики, null, дубликаты, SQL. _Задания:_ написать запросы профилирования для таблицы.

***

### Глава 4. Правила валидации

* **4.1 Типы правил** — бизнес-правила; технические правила; правила соответствия.
* **4.2 Правила на уровне поля** — NOT NULL; диапазон; формат; справочник; регулярное выражение.
* **4.3 Правила на уровне записи и таблицы** — уникальность ключа; сумма частей = целому; баланс дебет/кредит.
* **4.4 Референциальная целостность и кросс-проверки** — FK; сироты; кросс-проверка между таблицами; контрольные итоги.
* _Ключевое:_ типы правил, примеры, SQL. _Задания:_ сформулировать правила для сценария; реализовать проверки в SQL.

***

### Глава 5. Проверки в пайплайне ETL

* **5.1 Проверки на этапе извлечения** — полнота среза; отсутствие пропусков; контрольные суммы источника; row count.
* **5.2 Проверки при преобразовании** — валидация после маппинга; бизнес-правила; отклонение невалидных записей.
* **5.3 Проверки при загрузке** — row count до/после; контрольные суммы; дубликаты в целевой таблице.
* **5.4 Контрольные суммы и сверка** — хеш по строкам; сумма по числовым полям; сверка с источником; связь с книгой по финансовым расчётам.
* _Ключевое:_ проверки на этапах ETL, контрольные суммы. _Задания:_ спроектировать проверки для пайплайна.

### Глава 6. Метрики и мониторинг

* **6.1 Метрики качества** — процент валидных записей; количество отклонённых; тренд по дням; метрики по измерениям.
* **6.2 Пороги и алерты** — когда считать качество неприемлемым; алерты при превышении порога; эскалация.
* **6.3 Дашборды и отчётность** — какие метрики отображать; периодичность; аудитория.
* **6.4 Интеграция с Airflow и ETL** — проверки как таски; условное продолжение при ошибке; логи и уведомления.
* _Ключевое:_ метрики, пороги, алерты, Airflow. _Задания:_ определить метрики и пороги для пайплайна.

### Глава 7. Обработка ошибочных данных

* **7.1 Отклонение vs исправление** — когда отклонять запись; когда пытаться исправить; политика организации.
* **7.2 Кварантин и журнал ошибок** — таблица отклонённых записей; причина отклонения; возможность повторной обработки.
* **7.3 Автоматические исправления** — тримминг, приведение регистра; default values; правила без ручного вмешательства.
* **7.4 Эскалация и ответственность** — кто исправляет; процесс уведомления; SLA.
* _Ключевое:_ отклонение, кварантин, исправление, эскалация. _Задания:_ спроектировать поток обработки ошибок.

### Глава 8. Качество данных в DWH

* **8.1 Качество по слоям** — Raw: минимальные проверки; Staging: валидация; Core: полнота и согласованность; Mart: готовность для отчётов.
* **8.2 Raw, Staging, Core, Mart** — что проверять на каждом слое; деградация качества по цепочке.
* **8.3 Связь со сверкой и реконсиляцией** — сверка слоёв; источник vs витрина; связь с книгой по финансовым расчётам.
* **8.4 Качество витрин и отчётов** — проверки перед потреблением; контрольные итоги; регрессия.
* _Ключевое:_ качество по слоям, сверка, витрины. _Задания:_ определить проверки для каждого слоя.
