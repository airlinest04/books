# §12.2 Пакет (package)

В [§12.1](chapter-12-01.md) мы разобрали триггеры. В [§11.4](chapter-11-04.md) пакет был введён как спецификация и тело с подпрограммами. Здесь рассмотрим пакет подробнее: **публичные переменные и константы** в спецификации, **приватные** объекты в теле, **секция инициализации** тела пакета (выполняется один раз за сессию при первом обращении к пакету) и хранение **состояния пакета** между вызовами. Перегрузка подпрограмм в пакете — в [§12.3](chapter-12-03.md). См. [Глоссарий](glossary.md).

---

## 12.2.1. Публичные объекты в спецификации

В **спецификации пакета** (CREATE PACKAGE) помимо заголовков процедур и функций можно объявлять **переменные**, **константы**, **типы** и **курсоры**. Они видны всем, кто имеет право использовать пакет (вызов подпрограммы или обращение к переменной): имя_пакета.имя_переменной. Такие объекты называются **публичными**: они входят в интерфейс пакета. См. [Глоссарий](glossary.md).

Пример: константа и переменная-счётчик в спецификации:

```plsql
CREATE OR REPLACE PACKAGE pkg_util AS
  c_max_retry   CONSTANT PLS_INTEGER := 3;
  g_call_count  PLS_INTEGER := 0;   -- счётчик вызовов (состояние пакета)
  PROCEDURE do_something;
  FUNCTION get_count RETURN PLS_INTEGER;
END pkg_util;
/
```

Переменные пакета сохраняют значение между вызовами подпрограмм в рамках одной сессии (и до перекомпиляции пакета). Разные сессии имеют свои копии пакетных переменных. См. [Глоссарий](glossary.md).

---

## 12.2.2. Приватные объекты в теле пакета

В **теле пакета** (CREATE PACKAGE BODY) после заголовка можно объявлять **локальные** (приватные) переменные, константы, типы и курсоры: они видны только внутри тела пакета (всем подпрограммам этого тела). Снаружи к ним обратиться нельзя. Приватные объекты не объявляются в спецификации. См. [Глоссарий](glossary.md).

Пример: в теле объявлена приватная константа и переменная; процедура их использует:

```plsql
CREATE OR REPLACE PACKAGE BODY pkg_util AS
  c_debug   CONSTANT BOOLEAN := FALSE;   -- приватная константа
  v_buffer  VARCHAR2(4000);               -- приватная переменная

  PROCEDURE do_something IS
  BEGIN
    g_call_count := g_call_count + 1;     -- публичная переменная из spec
    IF c_debug THEN
      v_buffer := 'trace';
    END IF;
  END do_something;

  FUNCTION get_count RETURN PLS_INTEGER IS
  BEGIN
    RETURN g_call_count;
  END get_count;
END pkg_util;
/
```

Спецификация для этого примера должна объявлять g_call_count, do_something и get_count; c_debug и v_buffer только в теле. См. [Глоссарий](glossary.md).

## 12.2.3. Секция инициализации тела пакета

В конце тела пакета (после всех объявлений подпрограмм) можно разместить **секцию инициализации** — блок **BEGIN** ... **END** без имени. Он выполняется **один раз** за сессию при первом обращении к пакету (вызов подпрограммы или обращение к публичной переменной). В нём обычно инициализируют пакетные переменные, открывают курсоры, выполняют разовый запрос. См. [Глоссарий](glossary.md).

Пример:

```plsql
CREATE OR REPLACE PACKAGE BODY pkg_util AS
  g_initialized BOOLEAN := FALSE;
  PROCEDURE do_something IS
  BEGIN
    NULL;
  END do_something;
  FUNCTION get_count RETURN PLS_INTEGER IS
  BEGIN
    RETURN 0;
  END get_count;
BEGIN
  -- инициализация при первом обращении к пакету
  g_initialized := TRUE;
  g_call_count := 0;
END pkg_util;
/
```

Если в секции инициализации произойдёт необработанное исключение, при первом обращении к пакету сессия получит ошибку; последующие вызовы в этой сессии также могут завершаться ошибкой (пакет остаётся в неинициализированном состоянии). См. [Глоссарий](glossary.md).

---

## Ключевое

- В **спецификации** пакета объявляют подпрограммы и **публичные** переменные, константы, типы, курсоры — к ним обращаются как имя_пакета.имя. **Состояние** пакетных переменных сохраняется между вызовами в рамках сессии. См. [Глоссарий](glossary.md).
- В **теле** пакета — реализация подпрограмм и **приватные** объявления (переменные, константы, типы, курсоры), видимые только внутри тела.
- **Секция инициализации** — блок BEGIN ... END в конце тела без имени; выполняется один раз при первом обращении к пакету в сессии. Используется для начальной настройки пакетных переменных и разовой логики.
- Разные сессии имеют свои экземпляры пакетного состояния; перекомпиляция пакета сбрасывает состояние в текущей сессии.

В [§12.3](chapter-12-03.md) мы разберём перегрузку в пакете: несколько подпрограмм с одним именем и разными сигнатурами.
