# §4.2 Подзапросы в WHERE

В [§4.1](chapter-04-01.md) мы разобрали соединение таблиц через JOIN. Условие отбора в WHERE может зависеть от результата **другого запроса** — **подзапроса (subquery)**. Подзапрос в WHERE возвращает значения, с которыми сравнивается строка внешнего запроса. В этом разделе рассмотрим **скалярный подзапрос** (одна строка, один столбец), подзапросы с **IN** и **NOT IN**, с **EXISTS** и **NOT EXISTS**, а также **сравнения** с подзапросом (с операторами сравнения и с ALL/ANY). Подзапросы в FROM (подзапрос как таблица) — в [§4.3](chapter-04-03.md). См. [Глоссарий](glossary.md).

---

## 4.2.1. Что такое подзапрос в WHERE

**Подзапрос (subquery)** — запрос SELECT, вложенный в другой запрос. Он записывается в **скобках** и выполняется в контексте внешнего запроса (для каждой строки внешнего запроса или один раз — в зависимости от типа подзапроса и оптимизатора). В предложении WHERE подзапрос задаёт множество значений или одно значение, с которыми сравнивается выражение внешнего запроса. См. [Глоссарий](glossary.md).

Пример: «заказы, оформленные клиентами из Москвы». Список customer_id московских клиентов можно получить подзапросом; затем отобрать заказы, у которых customer_id входит в этот список:

```sql
SELECT * FROM orders
 WHERE customer_id IN (SELECT customer_id FROM customers WHERE city = 'Moscow');
```

Внутренний запрос возвращает столбец customer_id; условие IN проверяет, входит ли значение customer_id из текущей строки orders в этот набор. Подзапрос может ссылаться на столбцы внешнего запроса (коррелированный подзапрос) или быть независимым; ниже приведены оба варианта.

---

## 4.2.2. Скалярный подзапрос

**Скалярный подзапрос** возвращает **ровно одно значение** (одна строка, один столбец). Его можно использовать в выражениях и в условиях сравнения: =, <>, <, >, <=, >=. Подзапрос пишется в скобках на месте значения. См. [Глоссарий](glossary.md).

Пример: заказы, сумма которых выше средней по всем заказам:

```sql
SELECT * FROM orders
 WHERE total > (SELECT AVG(total) FROM orders);
```

Подзапрос `(SELECT AVG(total) FROM orders)` возвращает одно число — среднее значение total. Если подзапрос вернёт **ноль строк**, он трактуется как NULL; сравнение с NULL даёт UNKNOWN, строка не попадёт в результат. Если подзапрос вернёт **больше одной строки**, Oracle выдаст ошибку ORA-01427: single-row subquery returns more than one row. Поэтому скалярный подзапрос должен гарантированно возвращать не более одной строки (например, с агрегатной функцией без GROUP BY или с условием по первичному ключу).

---

## 4.2.3. IN и NOT IN с подзапросом

Условие **выражение IN (подзапрос)** истинно, если значение выражения **равно одному из** значений, возвращаемых подзапросом. Подзапрос должен возвращать **один столбец**. См. [Глоссарий](glossary.md).

Пример: заказы клиентов с определённым статусом (подзапрос возвращает список customer_id):

```sql
SELECT * FROM orders
 WHERE customer_id IN (SELECT customer_id FROM customers WHERE status = 'ACTIVE');
```

**NOT IN (подзапрос)** истинно, когда значение **не равно ни одному** из результатов подзапроса. Важно: если подзапрос возвращает **хотя бы один NULL**, то NOT IN для любой строки внешнего запроса даёт UNKNOWN (сравнение с NULL не даёт TRUE), и такие строки не попадают в результат. Поэтому при использовании NOT IN убедитесь, что подзапрос не возвращает NULL (например, в подзапросе указать WHERE column IS NOT NULL) или используйте альтернативу (NOT EXISTS, см. ниже).

---

## 4.2.4. EXISTS и NOT EXISTS

**EXISTS (подзапрос)** возвращает TRUE, если подзапрос **вернул хотя бы одну строку**; иначе FALSE. Содержимое строк подзапроса не используется — важен только факт наличия строк. Поэтому в подзапросе после SELECT часто пишут константу (1 или NULL): `EXISTS (SELECT 1 FROM ... WHERE ...)`. Условие в подзапросе обычно **связывает** его с внешним запросом (коррелированный подзапрос): для каждой строки внешней таблицы проверяется своё условие. См. [Глоссарий](glossary.md).

Пример: клиенты, у которых есть хотя бы один заказ:

```sql
SELECT * FROM customers c
 WHERE EXISTS (SELECT 1 FROM orders o WHERE o.customer_id = c.customer_id);
```

Для каждого клиента c подзапрос ищет заказы с тем же customer_id; если найден хотя бы один — EXISTS истинно. **NOT EXISTS** истинно, когда подзапрос **не возвращает ни одной строки**. Пример: клиенты без заказов:

```sql
SELECT * FROM customers c
 WHERE NOT EXISTS (SELECT 1 FROM orders o WHERE o.customer_id = c.customer_id);
```

EXISTS и NOT EXISTS не чувствительны к NULL в результате подзапроса (в отличие от NOT IN при наличии NULL в списке). Для «нет совпадений» часто предпочитают NOT EXISTS.

---

## 4.2.5. Сравнение с подзапросом: ALL и ANY (SOME)

Если подзапрос возвращает **несколько значений** (один столбец), его можно сравнивать с помощью **ALL** и **ANY** (или **SOME**; в Oracle SOME и ANY синонимы). См. [Глоссарий](glossary.md).

- **выражение оператор ALL (подзапрос)** — условие истинно, если сравнение с **каждым** значением подзапроса истинно. Например, `price > ALL (SELECT ...)` — цена больше всех значений из подзапроса.
- **выражение оператор ANY (подзапрос)** — условие истинно, если сравнение **хотя бы с одним** значением подзапроса истинно. Например, `price > ANY (SELECT ...)` — цена больше хотя бы одного значения.

Пример: товары, цена которых выше **всех** цен в категории 1:

```sql
SELECT * FROM products
 WHERE price > ALL (SELECT price FROM products WHERE category_id = 1);
```

Если подзапрос возвращает пустой набор, ALL даёт TRUE (сравнение с пустым множеством «истинно для всех»), ANY даёт FALSE. При наличии NULL в подзапросе семантика усложняется (сравнение с NULL даёт UNKNOWN); на практике часто используют IN или EXISTS вместо ANY/ALL для наглядности.

---

## 4.2.6. Коррелированный и некоррелированный подзапрос

**Некоррелированный подзапрос** не ссылается на столбцы внешнего запроса; его можно выполнить один раз, результат подставляется в условие. Пример: `WHERE total > (SELECT AVG(total) FROM orders)`.

**Коррелированный подзапрос** ссылается на столбец внешней таблицы (например, `o.customer_id = c.customer_id` в подзапросе). Он логически выполняется для каждой строки внешнего запроса (реально оптимизатор может переписать запрос). EXISTS и NOT EXISTS часто используют именно с коррелированными подзапросами. См. [Глоссарий](glossary.md).

---

## 4.2.7. Типичные ошибки при использовании подзапросов в WHERE

- **Скалярный подзапрос возвращает несколько строк:** при использовании в сравнении (=, <, > и т.д.) подзапрос должен возвращать не более одной строки. Иначе ORA-01427. Решение: добавить условие, ограничивающее одну строку (например, по первичному ключу), или использовать агрегатную функцию, или перейти на IN/EXISTS.
- **NOT IN при NULL в подзапросе:** если подзапрос возвращает NULL, NOT IN не вернёт ни одной строки. Исключите NULL в подзапросе (WHERE column IS NOT NULL) или замените на NOT EXISTS с коррелированным условием.
- **Путать IN и EXISTS:** IN проверяет вхождение значения в набор; EXISTS — наличие хотя бы одной строки, удовлетворяющей условию (часто с корреляцией). Для «есть совпадение» оба применимы; для «нет совпадения» NOT EXISTS ведёт себя предсказуемо при NULL.
- **Забыть связать коррелированный подзапрос:** в EXISTS подзапрос должен содержать условие, связывающее его с внешней таблицей (например, o.customer_id = c.customer_id), иначе логика будет неверной (подзапрос вернёт все строки или ни одной).
- **Подзапрос в скобках:** подзапрос всегда заключается в круглые скобки; без скобок синтаксическая ошибка.

---

## Ключевое

- **Подзапрос в WHERE** — запрос SELECT в скобках, результат которого участвует в условии отбора. Может быть скалярным (одно значение), списком для IN или предикатом для EXISTS.
- **Скалярный подзапрос** — одна строка, один столбец. Используется в сравнениях (=, <, > и т.д.). При нуле строк — NULL; при нескольких строках — ошибка ORA-01427.
- **IN (подзапрос)** — значение входит в набор, возвращаемый подзапросом. **NOT IN** — не входит; при NULL в подзапросе результат может быть неожиданным, предпочтительно NOT EXISTS.
- **EXISTS (подзапрос)** — истинно, если подзапрос вернул хотя бы одну строку. **NOT EXISTS** — истинно, если не вернул ни одной. Часто с коррелированным подзапросом (ссылка на внешнюю таблицу).
- **ALL** — сравнение со всеми значениями подзапроса; **ANY (SOME)** — хотя бы с одним. Пустой подзапрос: ALL даёт TRUE, ANY — FALSE.
- **Коррелированный подзапрос** ссылается на столбцы внешнего запроса; выполняется в контексте каждой строки внешней таблицы.

В [§4.3](chapter-04-03.md) мы разберём подзапросы в FROM: подзапрос как источник строк (вложенный запрос вместо таблицы) и псевдоним для подзапроса.
