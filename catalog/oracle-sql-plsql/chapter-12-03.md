# §12.3 Перегрузка в пакете

В [§12.2](chapter-12-02.md) мы разобрали публичные и приватные объекты пакета и секцию инициализации. **Перегрузка** (overloading) — объявление в одном пакете нескольких процедур или функций с **одним и тем же именем**, но с **разными списками параметров** (число или типы). При вызове компилятор выбирает подпрограмму по фактическим аргументам. Перегрузка допустима только **в пакете** (и в типах объектов); standalone-процедуры и функции не перегружаются. В этом разделе — правила перегрузки, выбор версии по аргументам и ограничения. Глава 12 на этом завершается; далее [глава 13](chapter-13-01.md): курсоры и обработка исключений. См. [Глоссарий](glossary.md).

---

## 12.3.1. Одно и то же имя, разная сигнатура

**Сигнатура** подпрограммы — имя пакета (или подпрограммы), имя подпрограммы и список типов параметров по порядку (без имён параметров). Две подпрограммы в одном пакете могут иметь одно имя, если их **сигнатуры различаются**: разное число параметров или разные типы параметров на одной позиции. См. [Глоссарий](glossary.md).

Пример: в пакете две процедуры log_msg — одна с одним параметром (сообщение), вторая с двумя (сообщение и уровень):

```plsql
CREATE OR REPLACE PACKAGE pkg_log AS
  PROCEDURE log_msg(p_msg IN VARCHAR2);
  PROCEDURE log_msg(p_msg IN VARCHAR2, p_level IN VARCHAR2);
END pkg_log;
/

CREATE OR REPLACE PACKAGE BODY pkg_log AS
  PROCEDURE log_msg(p_msg IN VARCHAR2) IS
  BEGIN
    INSERT INTO app_log (msg, level) VALUES (p_msg, 'INFO');
  END log_msg;
  PROCEDURE log_msg(p_msg IN VARCHAR2, p_level IN VARCHAR2) IS
  BEGIN
    INSERT INTO app_log (msg, level) VALUES (p_msg, p_level);
  END log_msg;
END pkg_log;
/
```

Вызов **pkg_log.log_msg('Done')** выберет первую версию; **pkg_log.log_msg('Error', 'ERROR')** — вторую. См. [Глоссарий](glossary.md).

## 12.3.2. Выбор перегруженной версии

Компилятор PL/SQL определяет, какую перегруженную подпрограмму вызвать, по **типам фактических аргументов** (и их количеству). Если подходит ровно одна версия — вызов корректен. Если не подходит ни одна (несовместимые типы, лишние или недостающие аргументы) — ошибка компиляции. Если подходят **несколько** версий (неоднозначность) — тоже ошибка: компилятор не выбирает «на свой вкус». См. [Глоссарий](glossary.md).

Неоднозначность часто возникает при неявном приведении типов: например, вызов с числовым литералом может подойти и для NUMBER, и для PLS_INTEGER. В таких случаях помогает явное приведение (TO_NUMBER, CAST) или именованная передача параметров. См. [Глоссарий](glossary.md).

## 12.3.3. Ограничения перегрузки

- **Только в пакете (и в объектных типах).** Standalone-процедура и функция не могут иметь то же имя при разных параметрах — в схеме один объект с одним именем.
- **Функции:** две функции не могут различаться **только типом возврата** при одинаковых параметрах. Компилятор выбирает версию по аргументам, а не по контексту присваивания (типу переменной слева). Поэтому перегружать по RETURN нельзя. См. [Глоссарий](glossary.md).
- Параметры по умолчанию могут усложнить разрешение вызова: вызов с одним аргументом может подойти и для версии с одним параметром, и для версии с двумя (второй по умолчанию). Следует избегать таких пересечений или вызывать с именованной передачей.

Перегрузка упрощает API пакета: одно имя для логически одной операции с разными вариантами ввода (например, log с уровнем и без). См. [Глоссарий](glossary.md).

---

## Ключевое

- **Перегрузка** в пакете — несколько подпрограмм с одним именем и разными **сигнатурами** (число или типы параметров). Выбор версии при вызове — по фактическим аргументам. Допускается только в пакете (и в объектных типах). См. [Глоссарий](glossary.md).
- Компилятор выбирает единственную подходящую версию; при неоднозначности или отсутствии подходящей версии — ошибка компиляции.
- Функции не могут различаться только типом возврата при одинаковых параметрах. Параметры по умолчанию могут привести к неоднозначности — осторожность при проектировании.
