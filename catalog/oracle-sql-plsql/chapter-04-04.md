# §4.4 Подзапросы в SELECT

В [§4.3](chapter-04-03.md) мы разобрали подзапросы в FROM — подзапрос как источник строк. В списке **SELECT** (в перечне столбцов и выражений) тоже можно указать **подзапрос в скобках**. Он должен быть **скалярным**: возвращать **одну строку и один столбец**. Результат подзапроса подставляется в результирующую строку как значение ещё одного столбца. В этом разделе рассмотрим синтаксис подзапроса в SELECT, коррелированные подзапросы в списке столбцов и типичные сценарии. Глава 4 на этом завершается; далее — [глава 5](chapter-05-01.md): INSERT, UPDATE, DELETE. См. [Глоссарий](glossary.md).

---

## 4.4.1. Скалярный подзапрос в списке столбцов

В списке SELECT после запятой (наряду со столбцами и выражениями) можно указать **подзапрос в скобках**. Такой подзапрос должен возвращать **одно значение** (одна строка, один столбец). Для каждой строки результата внешнего запроса подзапрос вычисляется (если он коррелированный — с учётом текущей строки), и возвращённое значение становится значением дополнительного столбца в этой строке. См. [Глоссарий](glossary.md).

Синтаксис:

```sql
SELECT столбец1, (подзапрос) [AS псевдоним], столбец2
  FROM таблица ...;
```

Псевдоним задаёт имя столбца в результате; без псевдонима Oracle выведет что-то вроде подзапроса или сгенерирует имя. Пример: для каждого заказа вывести имя клиента из таблицы customers по customer_id:

```sql
SELECT order_id, customer_id, total,
       (SELECT name FROM customers c WHERE c.customer_id = o.customer_id) AS customer_name
  FROM orders o;
```

Подзапрос **коррелированный**: он ссылается на o.customer_id из текущей строки заказа. Для каждой строки orders выполняется поиск клиента с таким customer_id; возвращается один столбец (name). Если клиент не найден, подзапрос вернёт ноль строк — в таком случае в скалярном контексте подставляется **NULL**. Если найдено несколько строк (при нарушении уникальности), Oracle вернёт ошибку ORA-01427: single-row subquery returns more than one row.

## 4.4.2. Когда подзапрос в SELECT возвращает одно значение

Подзапрос в списке SELECT должен быть скалярным, то есть возвращать не более одной строки и ровно один столбец. Это гарантируется, если:

- подзапрос обращается к строке по **первичному ключу** или **уникальному ключу** (например, WHERE customer_id = o.customer_id при уникальном customer_id в customers);
- в подзапросе используется **агрегатная функция** без GROUP BY или с GROUP BY по полю, однозначно определяющему одну группу для текущей строки внешнего запроса.

Пример с агрегатом: для каждого заказа вывести общую сумму заказов того же клиента (одно число на строку):

```sql
SELECT order_id, customer_id, total,
       (SELECT SUM(total) FROM orders o2 WHERE o2.customer_id = o.customer_id) AS customer_total
  FROM orders o;
```

Подзапрос для каждой строки o считает SUM(total) по заказам с тем же customer_id; возвращается одна строка с одним столбцом. См. [Глоссарий](glossary.md).

---

## 4.4.3. Ноль строк: подстановка NULL

Если скалярный подзапрос **не возвращает ни одной строки**, в выражении он трактуется как **NULL**. Соответственно, в результирующей строке в этом столбце будет NULL. Это удобно для «дополнительного столбца» из связанной таблицы: при отсутствии связи просто получится пустое значение. См. [Глоссарий](glossary.md).

Пример: список заказов с именем клиента; если customer_id не найден в customers (устаревшие данные или удалённый клиент), в customer_name будет NULL:

```sql
SELECT order_id,
       (SELECT name FROM customers c WHERE c.customer_id = o.customer_id) AS customer_name
  FROM orders o;
```

Явно обрабатывать «нет строки» через NVL в таком случае можно во внешнем SELECT: NVL((SELECT name ...), 'Unknown').

## 4.4.4. Несколько подзапросов в одном SELECT

В списке SELECT может быть несколько подзапросов — каждый даёт свой столбец. Каждый должен быть скалярным (одна строка, один столбец). Пример: заказ, имя клиента и количество заказов этого клиента:

```sql
SELECT o.order_id,
       (SELECT name FROM customers c WHERE c.customer_id = o.customer_id) AS customer_name,
       (SELECT COUNT(*) FROM orders o2 WHERE o2.customer_id = o.customer_id) AS customer_order_count
  FROM orders o;
```

Оба подзапроса коррелированы по o.customer_id. Для больших таблиц учтите, что каждый такой подзапрос может выполняться для каждой строки; при необходимости оптимизации часто переходят к JOIN или подзапросу в FROM с группировкой. См. [Глоссарий](glossary.md).

## 4.4.5. Типичные ошибки при использовании подзапроса в SELECT

- **Подзапрос возвращает несколько строк:** в списке SELECT подзапрос должен быть скалярным. Несколько строк приводят к ORA-01427. Нужно гарантировать единственность: условие по первичному ключу, агрегатная функция (MAX, MIN, SUM и т.д.) или ограничение по ROWNUM (например, подзапрос с ORDER BY и ROWNUM = 1 в Oracle до 12c — через вложенный FROM).
- **Подзапрос возвращает несколько столбцов:** в скалярном контексте допустим только один столбец. Несколько столбцов — синтаксическая ошибка. Нужно оставить в подзапросе один столбец или объединить значения (например, конкатенацией) в одно выражение.
- **Производительность при большом числе строк:** коррелированный подзапрос в SELECT выполняется для каждой строки результата. При больших объёмах данных предпочтительнее JOIN или подзапрос в FROM с последующим соединением — оптимизатор часто строит более эффективный план.
- **Путать подзапрос в SELECT и в WHERE:** в SELECT подзапрос даёт **значение столбца**; в WHERE — участвует в **условии отбора** строк. Один и тот же подзапрос может использоваться и там и там, но смысл разный.

---

## Ключевое

- **Подзапрос в SELECT** — подзапрос в скобках в списке столбцов; он должен быть **скалярным** (одна строка, один столбец). Результат подставляется как значение дополнительного столбца для каждой строки.
- При **нуле строк** подзапрос в скалярном контексте даёт **NULL**. При **нескольких строках** — ошибка ORA-01427. Однозначность обеспечивают условие по первичному/уникальному ключу или агрегатная функция.
- **Коррелированный подзапрос** в SELECT ссылается на столбцы внешнего запроса; для каждой строки внешнего запроса подзапрос вычисляется заново.
- В одном SELECT может быть несколько скалярных подзапросов — каждый добавляет свой столбец. Для тяжёлых запросов с корреляцией часто эффективнее JOIN или подзапрос в FROM.
- Псевдоним для столбца-подзапроса задаётся через AS после скобок; без него имя столбца в результате может быть неочевидным.
