# §5.2 schedule_interval

В [§5.1](chapter-05-01.md) мы разобрали паттерны графа. Порядок выполнения задач задаётся зависимостями; **момент создания** каждого DAG Run задаётся расписанием. В [§4.2](chapter-04-02.md) параметр **schedule_interval** уже упоминался; здесь разберём его подробнее: **cron-выражения**, **timedelta** и значение **None** для запуска только вручную. Как Airflow по расписанию и start_date генерирует логические даты запусков — в [§5.3](chapter-05-03.md).

---

## 5.2.1. Назначение schedule_interval

**schedule_interval** задаёт, как часто планировщик создаёт новые DAG Run для этого DAG. Передаётся в конструктор `DAG()`; может быть строкой (cron), объектом `timedelta` или `None`. Планировщик по этому интервалу и по **start_date** строит ряд логических дат (например, «за 2025-02-01», «за 2025-02-02») и для каждой даты создаёт один run, если он ещё не создан. Само **время** фактического запуска (в какой час и минуту «сработает» cron) зависит от настроек планировщика и нагрузки; в задачах пайплайна обычно опираются на **логическую дату** run, а не на текущее время. См. [§5.3](chapter-05-03.md).

---

## 5.2.2. Cron-выражения

Строка в формате **cron** из пяти полей задаёт момент срабатывания по минуте, часу, дню месяца, месяцу и дню недели. Синтаксис (стандартный для cron):

```text
минута  час  день_месяца  месяц  день_недели
  0-59   0-23    1-31      1-12    0-6 (0 = воскресенье)
```

Типичные примеры:

| Выражение | Значение |
|-----------|----------|
| `"0 2 * * *"` | Каждый день в 02:00 |
| `"0 0 * * *"` | Каждый день в полночь (00:00) |
| `"0 0 * * 1"` | Каждый понедельник в 00:00 |
| `"0 3 * * 1-5"` | В 03:00 по будням (пн–пт) |
| `"0 0 1 * *"` | Первый день каждого месяца в 00:00 |
| `"30 1 * * *"` | Каждый день в 01:30 |
| `"0 */6 * * *"` | Каждые 6 часов (00:00, 06:00, 12:00, 18:00) |

В Airflow 2.x для DAG по умолчанию используется такой же пятиполевой cron; в конфиге можно задать таймзону (например, `default_timezone` или параметр у DAG). Подстановки вроде `@daily`, `@hourly` в части версий поддерживаются; при сомнении сверяйтесь с документацией вашей версии.

Пример в коде:

```python
with DAG(
    dag_id="daily_report",
    schedule_interval="0 2 * * *",  # ежедневно в 02:00
    start_date=datetime(2025, 1, 1),
) as dag:
    ...
```

## 5.2.3. timedelta (интервал)

Вместо cron можно задать **интервал** с помощью `timedelta` из модуля `datetime`: например, каждые 6 часов, раз в день. Планировщик будет создавать run с шагом в этот интервал, начиная от start_date.

Примеры:

```python
from datetime import datetime, timedelta
from airflow import DAG

# Каждые 6 часов
with DAG(
    dag_id="hourly_ingest",
    schedule_interval=timedelta(hours=6),
    start_date=datetime(2025, 1, 1),
) as dag:
    ...

# Раз в день (эквивалент «один run в сутки», но привязка к интервалу, а не к фиксированному часу)
with DAG(
    dag_id="daily_ingest",
    schedule_interval=timedelta(days=1),
    start_date=datetime(2025, 1, 1),
) as dag:
    ...
```

Различие с cron: cron задаёт **конкретное время** (например, 02:00), а timedelta — **шаг по времени** от start_date. Для «каждый день в 02:00» чаще используют cron `"0 2 * * *"`; для «каждые N часов» удобен timedelta.

---

## 5.2.4. None — только ручной запуск

Если **schedule_interval=None**, планировщик **не создаёт** DAG Run по расписанию. Запуски возможны только вручную (Trigger DAG в UI или CLI) или по API/внешнему триггеру. Удобно для пайплайнов «по требованию», тестовых DAG и сценариев, где момент запуска задаётся другой системой.

```python
with DAG(
    dag_id="on_demand_only",
    schedule_interval=None,
    start_date=datetime(2025, 1, 1),
) as dag:
    ...
```

---

## 5.2.5. Краткая сводка

| Значение | Поведение |
|----------|------------|
| Строка cron (например, `"0 2 * * *"`) | Запуск в заданные минута/час/день по правилам cron. |
| `timedelta(hours=6)` и т.п. | Запуск с заданным интервалом от start_date. |
| `None` | Запуск только вручную или по внешнему триггеру. |

В [§5.3](chapter-05-03.md) разберём, как по **start_date** и **schedule_interval** получается логическая дата (logical date) каждого run и почему её не стоит путать с временем фактического выполнения.

---

## Ключевое

- **schedule_interval** задаёт, как часто планировщик создаёт DAG Run: по **cron** (строка из пяти полей), по **timedelta** (интервал) или **None** (только ручной запуск).
- **Cron:** минута, час, день месяца, месяц, день недели; примеры: ежедневно в 02:00, понедельник в полночь, первый день месяца, каждые 6 часов.
- **timedelta** — шаг по времени (hours=6, days=1); cron — фиксированное время суток.
- При **None** run создаются только по Trigger DAG или внешнему триггеру.

В [§5.3](chapter-05-03.md) — start_date и то, как формируется логическая дата запуска (logical date).
