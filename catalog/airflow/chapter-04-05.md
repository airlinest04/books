# §4.5 Запуск и просмотр в UI

В [§4.4](chapter-04-04.md) мы задали зависимости между тасками. Чтобы увидеть DAG в работе, его нужно **запустить** и посмотреть результат в веб-интерфейсе. В этом разделе — ручной запуск (Trigger DAG), просмотр **графа** и **дерева** выполнения, а также **логи задачи**. В конце главы 4 — выводы и задание. Детали расписания и логической даты — в [главе 5](chapter-05-01.md).

---

## 4.5.1. Ручной запуск (Trigger DAG)

DAG с `schedule_interval=None` не запускается по расписанию; запуск только **вручную** или по API. Даже у DAG с расписанием часто нужен разовый ручной прогон для проверки.

**В веб-интерфейсе:**

1. Откройте список DAG (главная страница Airflow, обычно `http://localhost:8080`).
2. Включите DAG переключателем (toggle) слева от имени, если он выключен.
3. Справа нажмите кнопку **Trigger DAG** (иконка «play»). При необходимости задайте конфигурацию запуска (Configuration) — JSON с параметрами; для простого прогона можно оставить пустым.
4. Подтвердите запуск. Планировщик создаст новый **DAG Run** с логической датой (обычно текущее время или следующая дата по расписанию) и начнёт ставить задачи в очередь.

После триггера в списке DAG появится новый run; статус можно смотреть в колонке «Last Run» или перейдя в представление по этому DAG. Запуск из CLI: `airflow dags trigger <dag_id>`.

---

## 4.5.2. Граф выполнения (Graph View)

В карточке DAG откройте представление **Graph** (или **Graph View**). На экране отображается граф задач: вершины — задачи, рёбра — зависимости. Цвет или форма вершины показывает статус выбранного DAG Run (success, failed, running, pending и т.д.). Выбор run — по логической дате (run date) в выпадающем списке или по списку запусков.

Graph View удобен, чтобы увидеть структуру пайплайна и текущее состояние каждой задачи в конкретном запуске: какая выполнилась, какая в процессе, какая ждёт предшественников или упала. Клик по задаче открывает меню с быстрыми действиями (логи, повтор, очистка состояния).

---

## 4.5.3. Дерево выполнения (Tree View)

**Tree View** показывает те же задачи, но в виде **дерева по датам запусков**: по одной строке на DAG Run (логическая дата), в строке — ячейки по задачам. Цвет ячейки соответствует статусу задачи в этом run (success, failed, running, skipped). Удобно сравнивать несколько запусков подряд: какие даты отработали успешно, в каком run и какая задача упала.

Как и в Graph View, можно выбрать run по дате и перейти к логам или действиям по задаче через клик по ячейке.

---

## 4.5.4. Логи задачи (Log)

Когда задача выполнилась (успешно или с ошибкой), полезно посмотреть её **логи** — вывод в stdout/stderr и служебные сообщения Airflow.

**Как открыть логи:**

1. В Graph View или Tree View кликните по задаче (вершине или ячейке).
2. В появившемся меню выберите **Log** (или аналогичный пункт).
3. Откроется страница с логами этого **Task Instance** (задача в конкретном DAG Run). Отображается вывод команды или функции, трассировка при исключении, попытки retry при сбое.

По логам можно понять, почему задача упала (файл не найден, таймаут, ошибка в коде), проверить переданную логическую дату и вывод скрипта. Логи хранятся в метаданных или во внешнем хранилище (в зависимости от конфигурации); доступ к ним возможен и через UI, и при необходимости через CLI/API.

---

## 4.5.5. Действия с задачей и run

Через контекстное меню задачи (клик по задаче в Graph/Tree) или через отдельные экраны доступны, в зависимости от версии и прав:

- **Clear** — сбросить состояние задачи (и при необходимости следующих по графу) для выбранных run, чтобы планировщик перезапустил их.
- **Mark success / failed** — принудительно пометить задачу как успешную или проваленную (для обхода сломанной задачи или ручной разблокировки).
- **Retry** — повторить только эту задачу в этом run.
- **Trigger DAG** (для всего DAG) — создать новый run, как в п. 4.5.1.

Использовать Mark success/failed и Clear стоит аккуратно: они меняют состояние без реального выполнения кода и могут нарушить консистентность данных, если задача не идемпотентна.

## Ключевое по главе 4 и задание

**Выводы главы 4:**

1. **DAG** — направленный ациклический граф задач; задаётся в Python через `with DAG(...)` и уникальный `dag_id`. Параметры: schedule_interval, start_date, tags, catchup.
2. **Task** — экземпляр оператора (BashOperator, PythonOperator и др.) с уникальным `task_id` в рамках DAG; привязка к DAG через контекст или `dag=...`.
3. **Зависимости** задаются оператором **>>**: A >> B, цепочки (A >> B >> C), ветвление (A >> [B, C]) и сведение ([B, C] >> D). Альтернатива — set_downstream / set_upstream.
4. **Запуск и UI:** ручной **Trigger DAG** создаёт DAG Run; **Graph View** и **Tree View** показывают граф и статусы по run; **Log** у задачи — вывод и диагностика выполнения.

**Задание:**

- **Создать DAG с 3–4 тасками и зависимостями.** Напишите один Python-файл в каталоге DAG с DAG (schedule_interval=None или по расписанию), 3–4 задачами (например, BashOperator с разными `echo`) и заданными зависимостями (линейная цепочка или ветвление). Сохраните файл, дождитесь появления DAG в UI, выполните Trigger DAG и проверьте выполнение в Graph View и логи одной из задач.

В [главе 5](chapter-05-01.md) разберём линейные и параллельные ветки подробнее, расписание (cron, timedelta), start_date и логическую дату запуска, catchup и backfill.
