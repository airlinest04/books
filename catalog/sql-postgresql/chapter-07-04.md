# §7.4 Порядок выполнения

В [§7.3](chapter-07-03.md) мы рассмотрели HAVING. Логический **порядок выполнения** предложений SELECT определяет, на каком этапе доступны те или иные данные. Понимание порядка помогает правильно писать условия, предсказывать ошибки и оптимизировать запросы. В этом разделе разберём последовательность FROM, WHERE, GROUP BY, HAVING, SELECT, ORDER BY, LIMIT/OFFSET и вытекающие из неё следствия. Ошибки при использовании групповых функций — в гл. 8. См. [документацию SELECT](https://www.postgresql.org/docs/current/sql-select.html).

---

## 7.4.1. Последовательность этапов

PostgreSQL обрабатывает SELECT в логическом порядке (по [документации](https://www.postgresql.org/docs/current/sql-select.html)):

1. **FROM** — формирование набора строк (таблицы, JOIN, подзапросы).
2. **WHERE** — отбор строк по условию.
3. **GROUP BY** — группировка и вычисление агрегатов.
4. **HAVING** — отбор групп по условию.
5. **SELECT** — вычисление выходных выражений (включая псевдонимы).
6. **DISTINCT** — устранение дубликатов (если указано).
7. **ORDER BY** — сортировка.
8. **LIMIT / OFFSET** — ограничение числа строк.

Фактический план выполнения может отличаться (оптимизатор переупорядочивает шаги), но семантика соответствует этому порядку.

---

## 7.4.2. Схема и пример

```text
FROM orders                    -- все заказы
  -> WHERE status = 'paid'     -- только оплаченные
  -> GROUP BY customer_id      -- по клиентам, считаем агрегаты
  -> HAVING count(*) > 1       -- клиенты с более чем 1 заказом
  -> SELECT customer_id, count(*) AS cnt, sum(total) AS total  -- выходные столбцы
  -> ORDER BY total DESC       -- по убыванию суммы
  -> LIMIT 10                  -- первые 10
```

---

## 7.4.3. Следствия порядка

**Почему агрегаты нельзя использовать в WHERE.** WHERE выполняется до GROUP BY. На этапе WHERE ещё нет групп и агрегатов — только отдельные строки. Для фильтрации по агрегату используется HAVING (см. [§8.2](chapter-08-02.md)).

**Почему псевдонимы из SELECT недоступны в WHERE и HAVING.** Псевдонимы задаются в SELECT, который идёт после WHERE и HAVING. В WHERE и HAVING можно ссылаться только на столбцы из FROM и результаты агрегации.

**Почему в ORDER BY можно использовать псевдонимы.** ORDER BY идёт после SELECT; к этому моменту псевдонимы уже вычислены.

---

## 7.4.4. WITH (CTE)

Предложение **WITH** вычисляется до основного запроса. Его результат можно использовать в FROM как временную таблицу:

```sql
WITH paid_orders AS (
  SELECT * FROM orders WHERE status = 'paid'
)
SELECT customer_id, count(*) FROM paid_orders GROUP BY customer_id;
```

С точки зрения порядка: сначала выполняется запрос в WITH, затем основной запрос, где `paid_orders` участвует в FROM. WITH подробнее рассматривается в гл. 9 и далее.

---

## 7.4.5. Подзапросы

Подзапрос в FROM выполняется на этапе FROM — его результат формирует виртуальную таблицу для внешнего запроса. Подзапрос в WHERE вычисляется при проверке условия для каждой строки (или один раз, если оптимизатор это допустит). Подзапрос в HAVING — при фильтрации каждой группы. В каждом случае важно, на каком этапе доступны данные внешнего запроса.

---

## Ключевое

- Логический порядок: **FROM → WHERE → GROUP BY → HAVING → SELECT → DISTINCT → ORDER BY → LIMIT/OFFSET**.
- WHERE работает со строками до группировки; HAVING — с группами после агрегации.
- Агрегаты недоступны в WHERE, потому что WHERE выполняется до GROUP BY.
- Псевдонимы из SELECT недоступны в WHERE и HAVING; в ORDER BY — доступны.
- WITH вычисляется до основного запроса; подзапросы — в контексте того предложения, где они указаны.

В [§8.1](chapter-08-01.md) разберём типичную ошибку: использование в SELECT столбцов, не входящих в GROUP BY.
