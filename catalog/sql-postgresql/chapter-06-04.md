# §6.4 Опасность без WHERE

В [§6.2](chapter-06-02.md) и [§6.3](chapter-06-03.md) мы рассмотрели UPDATE и DELETE. Без предложения WHERE эти команды затрагивают **все** строки таблицы. Одна опечатка или невнимательность может привести к массовой потере или порче данных. В этом разделе разберём типичные ситуации, меры предосторожности и использование транзакций для безопасности. MERGE (UPSERT) рассматривается в [§6.5](chapter-06-05.md). Транзакции подробнее — в гл. 11. См. [документацию UPDATE](https://www.postgresql.org/docs/current/sql-update.html) и [DELETE](https://www.postgresql.org/docs/current/sql-delete.html).

---

## 6.4.1. Что происходит без WHERE

- **UPDATE таблица SET столбец = значение** — обновляются **все** строки. Один запрос может изменить миллионы записей.
- **DELETE FROM таблица** — удаляются **все** строки. Таблица остаётся пустой (структура сохраняется).

PostgreSQL не запрашивает подтверждение и не предлагает «пробный режим». Команда выполняется сразу. В режиме autocommit (по умолчанию в psql и большинстве клиентов) откат уже невозможен.

---

## 6.4.2. Типичные причины ошибок

- **Забыли WHERE** — написали `UPDATE users SET active = false` вместо `... WHERE id = 5`.
- **Неправильное условие** — `WHERE status = 'active'` вместо `WHERE status = 'inactive'`; затронуты не те строки.
- **Скопировали чужой запрос** — в нём не было WHERE, и вы не заметили.
- **Выполнили не тот фрагмент** — выделили и выполнили только `UPDATE users SET active = false`, без строки с WHERE.
- **Опечатка в имени таблицы** — обновлена или очищена не та таблица.

---

## 6.4.3. Проверка через SELECT

Перед массовым UPDATE или DELETE выполните **SELECT** с тем же условием и проверьте результат:

```sql
-- Сначала смотрим, что попадёт под действие
SELECT id, name, status FROM users WHERE status = 'inactive';

-- Если список верный — выполняем DELETE
DELETE FROM users WHERE status = 'inactive';
```

Для UPDATE можно вывести «до» и «после»:

```sql
SELECT id, price, price * 1.1 AS new_price FROM products WHERE category_id = 1;
-- Проверяем, затем:
UPDATE products SET price = price * 1.1 WHERE category_id = 1;
```

---

## 6.4.4. Транзакция для безопасности

Для критичных операций используйте **транзакцию**: оберните команды в `BEGIN` и `COMMIT` и проверьте результат перед подтверждением. При ошибке или сомнении выполните `ROLLBACK`.

```sql
BEGIN;

UPDATE products SET price = price * 1.1 WHERE category_id = 1;
-- Проверяем результат
SELECT id, name, price FROM products WHERE category_id = 1 LIMIT 5;

-- Если всё верно:
COMMIT;
-- Если нет:
-- ROLLBACK;
```

Аналогично для DELETE:

```sql
BEGIN;
DELETE FROM logs WHERE created_at < '2023-01-01';
SELECT count(*) FROM logs;  -- проверка
COMMIT;  -- или ROLLBACK
```

Транзакции подробнее рассматриваются в гл. 11.

---

## 6.4.5. RETURNING как проверка

RETURNING показывает, какие строки были изменены или удалены. Для небольшого числа строк это удобная проверка:

```sql
DELETE FROM orders WHERE id = 999
RETURNING *;
```

Если RETURNING пуст — ни одна строка не затронута (например, неверный id). При массовой операции RETURNING может быть большим; тогда ограничьте число строк через подзапрос или используйте LIMIT в стиле, описанном в документации UPDATE.

---

## 6.4.6. Сообщение о числе затронутых строк

После UPDATE и DELETE PostgreSQL выводит `UPDATE n` или `DELETE n`. Всегда смотрите на это число. Если ожидали одну строку, а `n` равно 10000 — что-то не так. Прервите сессию (если в транзакции — сделайте ROLLBACK) и разберитесь.

---

## 6.4.7. Резервные копии

Для продакшена регулярные **бэкапы** обязательны. При случайном массовом UPDATE или DELETE восстановление возможно только из резервной копии или журнала репликации. Настройка pg_dump, WAL-архивирование и точка восстановления — тема отдельной документации по администрированию.

---

## 6.4.8. Чек-лист перед массовым UPDATE/DELETE

1. Выполнить SELECT с тем же WHERE и проверить выборку.
2. По возможности выполнить операцию в транзакции (BEGIN ... COMMIT/ROLLBACK).
3. Проверить вывод «UPDATE n» / «DELETE n» после выполнения.
4. При сомнениях — ROLLBACK и повторная проверка условия.

---

## Ключевое

- Без WHERE команды UPDATE и DELETE затрагивают **все** строки таблицы.
- PostgreSQL не запрашивает подтверждение; откат возможен только внутри транзакции до COMMIT.
- Перед массовой операцией выполняйте SELECT с тем же условием.
- Для критичных изменений используйте транзакции: BEGIN → UPDATE/DELETE → проверка → COMMIT или ROLLBACK.
- Обращайте внимание на число затронутых строк в выводе.
- Резервные копии — основа восстановления после серьёзных ошибок.

В [§6.5](chapter-06-05.md) рассмотрим MERGE (UPSERT) — вставку или обновление в зависимости от наличия строки.
