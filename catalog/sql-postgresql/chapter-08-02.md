# §8.2 Фильтрация по агрегату в WHERE

В [§8.1](chapter-08-01.md) мы рассмотрели ошибку с незагруппированными столбцами. Другая типичная ошибка — использовать агрегатную функцию в **WHERE**. Условие WHERE выполняется до группировки и агрегации, поэтому агрегаты там недоступны. В этом разделе разберём текст ошибки, причину и два способа исправления: **HAVING** (при наличии GROUP BY) и **подзапрос** (когда нужен один глобальный агрегат). Вложенные агрегаты — в [§8.3](chapter-08-03.md). См. [документацию SELECT](https://www.postgresql.org/docs/current/sql-select.html) и [туториал по агрегатам](https://www.postgresql.org/docs/current/tutorial-agg.html).

---

## 8.2.1. Текст ошибки

При попытке использовать агрегат в WHERE:

```sql
SELECT city FROM weather WHERE temp_lo = max(temp_lo);
```

PostgreSQL выдаёт:

```text
ERROR:  aggregate functions are not allowed in WHERE
LINE 1: SELECT city FROM weather WHERE temp_lo = max(temp_lo);
```

Аналогичная ошибка при любом агрегате в WHERE: `count(*)`, `sum(...)`, `avg(...)` и т.д.

---

## 8.2.2. Почему агрегаты недоступны в WHERE

Порядок выполнения (см. [§7.4](chapter-07-04.md)): **WHERE → GROUP BY → HAVING → SELECT**. WHERE обрабатывает **отдельные строки** до группировки. Агрегат вычисляется по множеству строк (по группе или по всей таблице), то есть после того, как WHERE уже отработал. На этапе WHERE агрегата ещё нет — поэтому ссылаться на него нельзя.

---

## 8.2.3. Исправление: HAVING при GROUP BY

Если нужно отфильтровать **группы** по результату агрегации (например, клиентов с более чем 3 заказами), условие переносят в **HAVING**:

```sql
-- Ошибочно:
SELECT customer_id, count(*) FROM orders
WHERE count(*) > 3
GROUP BY customer_id;  -- ошибка

-- Правильно:
SELECT customer_id, count(*) AS order_count
FROM orders
GROUP BY customer_id
HAVING count(*) > 3;
```

HAVING выполняется после GROUP BY и вычисления агрегатов, поэтому в нём можно использовать результаты агрегации.

---

## 8.2.4. Исправление: подзапрос без GROUP BY

Если агрегат вычисляется по **всей таблице** (без группировки), а нужно отобрать строки по этому значению, используют **подзапрос**. Агрегат считается в подзапросе отдельно; во внешнем WHERE сравнивают с его результатом.

Пример: город с максимальной минимальной температурой (из туториала PostgreSQL):

```sql
-- Ошибочно:
SELECT city FROM weather WHERE temp_lo = max(temp_lo);  -- ошибка

-- Правильно:
SELECT city FROM weather
WHERE temp_lo = (SELECT max(temp_lo) FROM weather);
```

Подзапрос `(SELECT max(temp_lo) FROM weather)` возвращает одно значение; внешний запрос выбирает строки, у которых `temp_lo` равно этому значению.

---

## 8.2.5. Комбинирование WHERE и HAVING

WHERE и HAVING можно использовать вместе: WHERE отбирает строки до группировки, HAVING — группы после:

```sql
SELECT customer_id, count(*) AS order_count, sum(total) AS total_spent
FROM orders
WHERE status = 'paid'           -- только оплаченные заказы
GROUP BY customer_id
HAVING sum(total) > 1000;       -- клиенты с суммой оплаченных заказов > 1000
```

Сначала отбираются оплаченные заказы, затем группировка по клиентам, затем оставляются только клиенты с суммой больше 1000.

---

## 8.2.6. Подзапрос с группой

Если нужно найти строки, у которых значение совпадает с агрегатом **по своей группе**, используют коррелированный подзапрос или оконную функцию. Один из вариантов — подзапрос в WHERE, возвращающий агрегат для «текущей» группы; синтаксис усложняется. Более простой путь — GROUP BY с HAVING, а затем JOIN с исходной таблицей для получения остальных столбцов, если нужно. Оконные функции рассматриваются в гл. 12.

---

## Ключевое

- Агрегаты нельзя использовать в WHERE: порядок выполнения — WHERE до GROUP BY и агрегации.
- Для фильтрации **групп** по агрегату — **HAVING**.
- Для фильтрации **строк** по глобальному агрегату (всей таблицы) — **подзапрос** в WHERE.
- WHERE и HAVING совместно: WHERE — до группировки, HAVING — после.

В [§8.3](chapter-08-03.md) разберём вложенные агрегаты — где они допустимы и где нет.
