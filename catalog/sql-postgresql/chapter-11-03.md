# §11.3 Уровни изоляции

В [§11.2](chapter-11-02.md) мы рассмотрели READ COMMITTED — уровень по умолчанию. SQL определяет **четыре** уровня изоляции; PostgreSQL реализует три с разным поведением. В этом разделе кратко перечислим уровни, аномалии и как задать уровень. Глава 12 — оконные функции ([§12.1](chapter-12-01.md)). См. [документацию Transaction Isolation](https://www.postgresql.org/docs/current/transaction-iso.html) и [SET TRANSACTION](https://www.postgresql.org/docs/current/sql-set-transaction.html).

---

## 11.3.1. Аномалии при параллельном выполнении

Стандарт SQL описывает явления, которые уровни изоляции должны исключать:

| Явление | Описание |
|---------|----------|
| **Грязное чтение** (dirty read) | Транзакция читает данные, записанные другой, ещё не завершённой транзакцией |
| **Неповторяемое чтение** (non-repeatable read) | Повторное чтение тех же строк даёт другие данные — другая транзакция закоммитила изменения |
| **Фантомное чтение** (phantom read) | Повторное выполнение запроса возвращает другой набор строк — появились или исчезли строки из-за другой транзакции |
| **Аномалия сериализации** | Результат параллельного выполнения не соответствует никакому последовательному порядку |

---

## 11.3.2. Уровни изоляции в PostgreSQL

По [документации](https://www.postgresql.org/docs/current/transaction-iso.html):

| Уровень | Грязное чтение | Неповторяемое | Фантомное | Аномалия сериализации |
|---------|----------------|---------------|-----------|------------------------|
| READ UNCOMMITTED | В PG как READ COMMITTED | Возможно | Возможно | Возможно |
| **READ COMMITTED** | Нет | Возможно | Возможно | Возможно |
| REPEATABLE READ | Нет | Нет | В PG нет | Возможно |
| SERIALIZABLE | Нет | Нет | Нет | Нет |

- **READ UNCOMMITTED** в PostgreSQL ведёт себя как READ COMMITTED — отдельной реализации нет.
- **REPEATABLE READ** в PostgreSQL сильнее стандарта: фантомное чтение также исключено.

---

## 11.3.3. READ COMMITTED и REPEATABLE READ

**READ COMMITTED** (по умолчанию): каждая команда видит снимок на момент **своего** начала. Неповторяемое и фантомное чтение возможны.

**REPEATABLE READ**: снимок делается при **первой** команде транзакции и не меняется. Все последующие SELECT видят одни и те же данные. Если другая транзакция изменила строку, которую пытается изменить REPEATABLE READ, возникает ошибка:

```text
ERROR:  could not serialize access due to concurrent update
```

Транзакцию нужно откатить (ROLLBACK) и повторить. Подробнее — в [документации](https://www.postgresql.org/docs/current/transaction-iso.html#XACT-REPEATABLE-READ).

---

## 11.3.4. SERIALIZABLE

**SERIALIZABLE** — максимальная изоляция: результат параллельного выполнения эквивалентен какому-то последовательному. Исключаются все описанные аномалии.

При конфликте читающих и пишущих транзакций возможна ошибка:

```text
ERROR:  could not serialize access due to read/write dependencies among transactions
```

Приложения должны перехватывать такие ошибки, делать ROLLBACK и повторять транзакцию.

---

## 11.3.5. Задание уровня изоляции

Уровень задаётся в начале транзакции:

```sql
BEGIN ISOLATION LEVEL REPEATABLE READ;
-- или
BEGIN;
SET TRANSACTION ISOLATION LEVEL REPEATABLE READ;
```

`SET TRANSACTION` должен быть первой командой в транзакции — до любых SELECT, INSERT и т.д.

Параметр сессии `default_transaction_isolation` задаёт уровень по умолчанию для новых транзакций (в `postgresql.conf` или через `ALTER DATABASE` / `SET`).

---

## 11.3.6. Когда какой уровень использовать

- **READ COMMITTED** — по умолчанию, подходит большинству приложений. Быстрее, меньше конфликтов.
- **REPEATABLE READ** — когда нужна стабильная картина данных в рамках одной транзакции (отчёты, проверки). Готовность к retry при `concurrent update`.
- **SERIALIZABLE** — когда критична полная сериализуемость. Требует обработки ошибок сериализации и повторных попыток.

---

## Ключевое

- Уровни: READ UNCOMMITTED (= READ COMMITTED в PG), READ COMMITTED, REPEATABLE READ, SERIALIZABLE.
- READ COMMITTED — по умолчанию; REPEATABLE READ и SERIALIZABLE исключают неповторяемое и фантомное чтение.
- REPEATABLE READ и SERIALIZABLE могут завершаться ошибкой сериализации — нужны ROLLBACK и повтор транзакции.
- Уровень задаётся через `BEGIN ISOLATION LEVEL ...` или `SET TRANSACTION ISOLATION LEVEL ...` в начале транзакции.

В [§12.1](chapter-12-01.md) начнём главу об оконных функциях — расчётах без свёртки строк.
