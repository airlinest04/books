# §6.6 Представления

В [§6.5](chapter-06-05.md) мы рассмотрели MERGE и UPSERT. **Представление (view)** — сохранённый запрос, к которому можно обращаться как к таблице. Оно не хранит данные физически: при каждом SELECT запрос выполняется заново. В этом разделе разберём CREATE VIEW, обновляемые представления, WITH CHECK OPTION, временные представления и **материализованные представления** — представления с физическим хранением результата. Массовая загрузка (COPY) — в [§6.7](chapter-06-07.md). См. [документацию CREATE VIEW](https://www.postgresql.org/docs/current/sql-createview.html), [CREATE MATERIALIZED VIEW](https://www.postgresql.org/docs/current/sql-creatematerializedview.html) и [REFRESH MATERIALIZED VIEW](https://www.postgresql.org/docs/current/sql-refreshmaterializedview.html).

---

## 6.6.1. Что такое представление

Представление — именованный запрос. При обращении `SELECT * FROM имя_представления` PostgreSQL подставляет определение представления и выполняет лежащий в его основе запрос. Данные не копируются: представление — виртуальная таблица.

Зачем нужны представления:
- Упрощение сложных запросов — сохраняем JOIN или подзапрос, обращаемся коротко.
- Скрытие структуры — пользователь видит только нужные столбцы и строки.
- Разграничение доступа — можно выдать права на представление, не выдавая их на базовую таблицу.

---

## 6.6.2. CREATE VIEW — синтаксис

По [документации](https://www.postgresql.org/docs/current/sql-createview.html):

```sql
CREATE [ OR REPLACE ] [ TEMP | TEMPORARY ] [ RECURSIVE ] VIEW имя [ (столбец1, столбец2, ...) ]
  [ WITH ( view_option_name = value [, ...] ) ]
  AS запрос
  [ WITH [ CASCADED | LOCAL ] CHECK OPTION ];
```

Минимальная форма:

```sql
CREATE VIEW имя AS SELECT ...;
```

Столбцы наследуются из запроса. Пример:

```sql
CREATE VIEW comedies AS
  SELECT * FROM films WHERE kind = 'Comedy';
```

Обращение как к таблице:

```sql
SELECT * FROM comedies LIMIT 5;
```

Если в запросе используется `*`, столбцы представления совпадают со столбцами таблицы на момент создания. Добавленные в таблицу позже столбцы не попадут в представление — нужно пересоздать представление.

---

## 6.6.3. Обновляемые представления

Простое представление может быть **автоматически обновляемым**: INSERT, UPDATE, DELETE и MERGE преобразуются в соответствующие операции над базовой таблицей. Условия (по [документации](https://www.postgresql.org/docs/current/sql-createview.html)):

- Один источник в FROM — одна таблица или другое обновляемое представление.
- Нет `WITH`, `DISTINCT`, `GROUP BY`, `HAVING`, `LIMIT`, `OFFSET` на верхнем уровне.
- Нет операций над множествами (`UNION`, `INTERSECT`, `EXCEPT`).
- В списке SELECT нет агрегатов, оконных и возвращающих набор функций.

Пример обновляемого представления:

```sql
CREATE VIEW active_users AS
  SELECT id, name, email FROM users WHERE status = 'active';
```

Можно выполнять `UPDATE active_users SET name = '...' WHERE id = 1` — обновление попадёт в таблицу `users`. Вычисляемые столбцы (выражения, подзапросы) в представлении только для чтения; присваивать им значения нельзя.

---

## 6.6.4. WITH CHECK OPTION

Для представлений с WHERE можно указать **WITH CHECK OPTION**: INSERT и UPDATE не должны создавать строки, невидимые через представление. То есть новые строки обязаны удовлетворять условию WHERE.

- **WITH LOCAL CHECK OPTION** — проверяется только условие самого представления.
- **WITH CASCADED CHECK OPTION** — проверяются условия этого и всех нижележащих представлений. По умолчанию при указании CHECK OPTION используется CASCADED.

Пример:

```sql
CREATE VIEW pg_comedies AS
  SELECT * FROM films WHERE kind = 'Comedy' AND classification = 'PG'
  WITH CASCADED CHECK OPTION;
```

Попытка вставить фильм с `kind = 'Drama'` или `classification = 'R'` будет отклонена.

---

## 6.6.5. CREATE OR REPLACE VIEW и DROP VIEW

**CREATE OR REPLACE VIEW** изменяет существующее представление. Новый запрос должен возвращать тот же набор столбцов (имена и типы в том же порядке); можно добавить столбцы в конец. По [документации DROP VIEW](https://www.postgresql.org/docs/current/sql-dropview.html):

```sql
DROP VIEW [ IF EXISTS ] имя [ CASCADE | RESTRICT ];
```

`CASCADE` удалит зависящие объекты (другие представления); `RESTRICT` (по умолчанию) запретит удаление при наличии зависимостей.

---

## 6.6.6. Временные представления

С указанием **TEMP** или **TEMPORARY** представление создаётся во временной схеме сессии и автоматически удаляется при её завершении:

```sql
CREATE TEMP VIEW session_data AS
  SELECT * FROM logs WHERE created_at > current_date;
```

Временные таблицы, используемые в запросе представления, делают представление временным автоматически.

---

## 6.6.7. Материализованные представления

**Материализованное представление (materialized view)** хранит результат запроса физически, как таблица. Запрос выполняется при создании и при явном REFRESH; SELECT читает сохранённые данные. По [документации](https://www.postgresql.org/docs/current/sql-creatematerializedview.html):

```sql
CREATE MATERIALIZED VIEW [ IF NOT EXISTS ] имя [ (столбец1, ...) ]
  [ WITH ( storage_parameter = value [, ...] ) ]
  AS запрос
  [ WITH [ NO ] DATA ];
```

`WITH DATA` (по умолчанию) — запрос выполняется сразу, данные доступны. `WITH NO DATA` — представление создаётся пустым и недоступно для чтения до REFRESH.

Пример:

```sql
CREATE MATERIALIZED VIEW order_summary AS
  SELECT customer_id, count(*) AS order_count, sum(total) AS total_amount
  FROM orders
  GROUP BY customer_id;
```

Данные зафиксированы на момент создания. Для обновления:

```sql
REFRESH MATERIALIZED VIEW order_summary;
```

Старое содержимое заменяется результатом запроса. **REFRESH MATERIALIZED VIEW CONCURRENTLY** обновляет без блокировки чтения, но требует уникальный индекс на материализованном представлении. См. [документацию REFRESH](https://www.postgresql.org/docs/current/sql-refreshmaterializedview.html).

Материализованные представления не поддерживают INSERT, UPDATE, DELETE — только SELECT.

---

## 6.6.8. Обычное и материализованное представление: когда что использовать

| Критерий | Обычное представление | Материализованное представление |
|----------|------------------------|---------------------------------|
| Хранение данных | Нет, запрос каждый раз | Да, результат сохраняется |
| Актуальность | Всегда текущие данные | На момент REFRESH |
| Производительность SELECT | Зависит от сложности запроса | Быстрее, данные предвычислены |
| INSERT/UPDATE/DELETE | Возможно для простых представлений | Нет |
| Обновление | Не требуется | REFRESH MATERIALIZED VIEW |

Обычное представление — для упрощения запросов, сокрытия структуры, доступа к актуальным данным. Материализованное — для тяжёлых агрегаций, отчётов и дашбордов, где допустима задержка обновления и важна скорость чтения.

---

## Ключевое

- **Представление (view)** — сохранённый запрос, обращение к которому как к таблице; данные не хранятся.
- **CREATE VIEW имя AS запрос** — создание; столбцы берутся из запроса.
- Простое представление может быть обновляемым (INSERT/UPDATE/DELETE на базовую таблицу).
- **WITH CHECK OPTION** — запрет строк, невидимых через представление; LOCAL — только своё условие, CASCADED — все вложенные.
- **CREATE OR REPLACE VIEW** — изменение; **DROP VIEW** — удаление.
- **Материализованное представление** — физическое хранение результата; **REFRESH MATERIALIZED VIEW** — обновление данных.
- Обычное представление — актуальные данные, гибкость; материализованное — скорость чтения при допустимой задержке.

В [§6.7](chapter-06-07.md) рассмотрим массовую загрузку данных командой COPY.
