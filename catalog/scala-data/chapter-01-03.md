## 1.3.1. sbt: сборка и зависимости

**sbt** (Scala Build Tool) — стандартный инструмент сборки для Scala-проектов. Он управляет зависимостями (подключение библиотек из Maven Central и других репозиториев), компилирует код, запускает тесты и собирает JAR-архивы. Для Spark jobs и серьёзных приложений sbt — обычный выбор. См. [Глоссарий](glossary.md).

**Структура проекта sbt**

По умолчанию sbt ожидает структуру каталогов, аналогичную Maven:

```
my-project/
  build.sbt
  project/
    build.properties
  src/
    main/
      scala/
        Main.scala
      resources/
    test/
      scala/
        MainSpec.scala
      resources/
  target/
```

- **build.sbt** — основной файл конфигурации: версия Scala, зависимости, настройки компиляции.
- **project/** — файлы, описывающие сам sbt-проект (в том числе `build.properties` с версией sbt).
- **src/main/scala/** — исходный код приложения.
- **src/main/resources/** — ресурсы (конфиги, данные), попадающие в JAR.
- **src/test/scala/** — тесты; **src/test/resources/** — ресурсы для тестов.
- **target/** — скомпилированные классы, JAR-архивы, кэш; обычно добавляют в `.gitignore`.

**Минимальный build.sbt**

```scala
ThisBuild / scalaVersion := "3.3.1"
ThisBuild / organization := "com.example"

lazy val root = (project in file("."))
  .settings(
    name := "my-project",
    libraryDependencies += "org.scalatest" %% "scalatest" % "3.2.18" % Test
  )
```

- `scalaVersion` — версия Scala (2.13.x или 3.x).
- `name`, `organization` — идентификаторы проекта.
- `libraryDependencies` — список зависимостей; `%` — одно артефакт, `%%` — артефакт, собранный под вашу версию Scala; `% Test` — зависимость только для тестов.

**Основные команды sbt**

В каталоге проекта запустите `sbt`. Откроется интерактивная консоль с приглашением `sbt:my-project>`. Доступны команды:

| Команда    | Описание                                               |
|------------|--------------------------------------------------------|
| `compile`  | Компиляция исходников в `target/`                      |
| `run`      | Компиляция и запуск главного класса (main)             |
| `test`     | Запуск тестов                                          |
| `clean`    | Удаление содержимого `target/`                         |
| `reload`   | Перезагрузка `build.sbt` после изменений               |
| `console`  | Запуск REPL с подключёнными зависимостями проекта      |
| `package`  | Сборка JAR-архива                                      |
| `exit`     | Выход из sbt (или Ctrl+D)                              |

При первом `compile` или `run` sbt скачает указанные зависимости — это может занять время.

**sbt для работы с данными и Spark**

В [Главе 8](chapter-08-01.md) мы добавим в `build.sbt` зависимости Spark (`spark-core`, `spark-sql`) и настроим сборку для Spark jobs. Пока достаточно понимать, что sbt — центральный инструмент для проектов на Scala.

## 1.3.2. IDE: IntelliJ IDEA и VS Code

Среда разработки даёт автодополнение, переход к определению, подсветку ошибок и навигацию по проекту. Для Scala распространены два варианта.

**IntelliJ IDEA с плагином Scala**

IntelliJ IDEA (Community или Ultimate) — полнофункциональная IDE с отличной поддержкой Scala через плагин **Scala**.

- **Установка плагина:** File → Settings → Plugins → поиск «Scala» → Install. После установки перезапустите IDE.
- **Импорт проекта:** File → Open → выберите каталог с `build.sbt`. IntelliJ распознает sbt-проект и предложит загрузить его; после индексации доступны автодополнение, рефакторинг и запуск через кнопку Run.
- **Компиляция и run:** правый клик по `src/main/scala` или по файлу с `@main` — Run. Либо через sbt-панель (View → Tool Windows → sbt).

Рекомендуется включить «Build project automatically» в настройках (Build, Execution, Deployment → Compiler) и «Delegate build to sbt» (Build, Execution, Deployment → Build Tools → sbt), чтобы IDE использовала sbt для сборки.

**VS Code с расширением Metals**

**Metals** — language server для Scala: обеспечивает автодополнение, навигацию, диагностику и интеграцию с sbt. Работает в VS Code, Vim, Emacs и других редакторах.

- **Установка:** в VS Code откройте Extensions (Ctrl+Shift+X), найдите «Metals» и установите. При первом открытии Scala-проекта Metals предложит импортировать проект (Build Import); это может занять несколько минут.
- **Запуск:** Metals использует sbt или Bloop под капотом. Запуск main-класса — через панель Run and Debug или через sbt в терминале.

VS Code легче IntelliJ и подходит тем, кто привык к минималистичному редактору; IntelliJ даёт более богатый набор инструментов отладки и рефакторинга.

**Общие советы**

- Убедитесь, что JDK в настройках IDE совпадает с той, что использует sbt (`JAVA_HOME` или настройки проекта).
- При изменении `build.sbt` выполните в sbt команду `reload` (или переимпортируйте проект в IDE), чтобы подтянуть новые зависимости.
- Кодировка файлов — UTF-8; в настройках IDE проверьте, что исходники сохраняются в UTF-8.

## 1.3.3. REPL для экспериментов

**REPL** (Read–Eval–Print Loop) — интерактивная оболочка Scala. Вы вводите выражение, нажимаете Enter, интерпретатор вычисляет результат и выводит его. Удобно проверять синтаксис, вызывать методы и экспериментировать с небольшими фрагментами без создания файла. См. [Глоссарий](glossary.md).

**Запуск REPL**

- **Глобальная установка:** команда `scala` без аргументов в терминале.
- **С зависимостями проекта:** в каталоге sbt-проекта выполните `sbt console`. REPL будет иметь доступ к классам и библиотекам, объявленным в `build.sbt`.
- **Через scala-cli:** `scala-cli repl` или `scala-cli repl --dependency org::lib:version` для REPL с дополнительными зависимостями.

**Полезные команды REPL**

Внутри REPL (приглашение `scala>`) доступны команды, начинающиеся с двоеточия:

| Команда     | Описание                                              |
|-------------|-------------------------------------------------------|
| `:help`     | Список команд                                         |
| `:quit`     | Выход (или Ctrl+D)                                    |
| `:type` expr| Показать тип выражения без вычисления                 |
| `:load` путь| Загрузить и выполнить файл .scala                     |
| `:paste`    | Режим вставки нескольких строк; завершить Ctrl+D      |
| `:history`  | История введённых выражений                           |
| `:reset`    | Сбросить состояние (удалить все объявленные значения) |

Пример: `:type List(1, 2, 3)` выведет тип без вычисления выражения.

**Многострочный ввод**

При вводе незавершённой конструкции (например, объявление объекта или функции) приглашение сменится на `|` — вводите продолжение. Пустая строка завершает блок и запускает компиляцию. Для вставки готового блока кода используйте `:paste`: вставьте текст, нажмите Ctrl+D — REPL выполнит блок целиком.

**REPL и данные**

Для разведки данных REPL удобен: загрузите небольшую выборку, примените преобразования, посмотрите результат. В [§7.1](chapter-07-01.md) мы будем читать файлы; тот же код можно выполнять по шагам в REPL. Для Spark доступна оболочка `spark-shell` — REPL с предзагруженным `SparkSession`; подробнее в [§8.1](chapter-08-01.md).

**Jupyter с ядром Almond (опционально)**

Если вы привыкли к Jupyter для анализа данных, можно использовать **Almond** — Jupyter-ядро для Scala. Установка: `curl -L -o coursier https://github.com/coursier/coursier/releases/latest/download/cs-x86_64-pc-linux.gz && gzip -d coursier && chmod +x coursier && ./coursier launch --fork almond -- --install`. После этого в Jupyter будет доступно ядро Scala. Для книги достаточно REPL и запуска файлов; Almond упоминается как альтернатива для тех, кто предпочитает ноутбуки.

## Ключевое

- **sbt** — инструмент сборки: структура `src/main/scala`, `build.sbt`, команды `compile`, `run`, `test`, `console`. Стандарт для проектов на Scala и Spark.
- **IntelliJ IDEA** с плагином Scala — полнофункциональная IDE; **VS Code** с Metals — легковесная альтернатива с language server.
- **REPL** — интерактивная оболочка (`scala` или `sbt console`); команды `:help`, `:type`, `:load`, `:paste`, `:quit`. Удобен для экспериментов и проверки фрагментов кода.

В [§1.4](chapter-01-04.md) мы напишем первую программу: объект с методом main, компиляция и запуск через sbt и scala-cli, а также выполнение в REPL.
