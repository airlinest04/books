# §3.2 Создание DataFrame

В [§3.1](chapter-03-01.md) мы разобрали DataFrame как табличную абстракцию со схемой и оптимизацию через Catalyst. Чтобы работать с данными, DataFrame нужно **создать**. В этом разделе рассмотрим три основных способа: создание **из RDD с заданной схемой**, создание **из источников данных** через `spark.read` и создание **из коллекции** (списка строк или структур) через `SparkSession.createDataFrame`. Детали чтения из файлов (форматы, опции) и примеры в PySpark — в главе 4 и главе 6; здесь — общая модель и типичные сценарии. В [§3.3](chapter-03-03.md) перейдём к Spark SQL: регистрация DataFrame как таблицы и выполнение запросов через `spark.sql()`. См. [Глоссарий](glossary.md).

---

## 3.2.1. Чтение из источников: spark.read

Самый частый способ получить DataFrame в приложении — **прочитать** данные из внешнего хранилища: файловой системы (локальной, HDFS, S3), базы данных по JDBC или из каталога Spark (таблицы, зарегистрированные в Hive Metastore). Для этого используется объект **DataFrameReader**, который возвращает метод **`spark.read`** (или `SparkSession.read`).

Общий вид вызова:

```
spark.read.format("формат").option("ключ", "значение").load("путь")
```

или короткие методы для популярных форматов:

- `spark.read.parquet("path")` — Parquet;
- `spark.read.json("path")` — JSON;
- `spark.read.csv("path", header=True, inferSchema=True)` — CSV с заголовком и выводом схемы по данным;
- `spark.read.jdbc(url, table, properties)` — таблица из СУБД по JDBC.

Чтение **ленивое**: при вызове `load` (или `parquet`, `json`, `csv` и т.д.) создаётся DataFrame, описывающий источник; данные не загружаются до первого действия. Схема либо задаётся форматом (Parquet, ORC хранят схему в файле), либо выводится из данных (JSON, CSV с `inferSchema=True`), либо задаётся явно через `.schema(...)`. Подробнее форматы, опции и пути (HDFS, S3) — в [§4.1](chapter-04-01.md) и [§6.1](chapter-06-01.md). См. [Глоссарий](glossary.md).

## 3.2.2. Создание из коллекции: createDataFrame

Когда данные уже есть в памяти драйвера (список словарей, список кортежей, список объектов `Row`), DataFrame можно создать через **`spark.createDataFrame(data)`**. SparkSession передаёт данные исполнителям и строит партиции; схема выводится из структуры данных (имена ключей словарей или атрибуты Row, типы — по первым элементам или по переданной схеме).

Типичные варианты:

- **Список словарей (Python):** `spark.createDataFrame([{"name": "Alice", "age": 30}, {"name": "Bob", "age": 25}])` — имена столбцов и типы выводятся из ключей и значений.
- **Список кортежей или списков:** нужно передать схему отдельно, так как по кортежам имена столбцов неизвестны: `spark.createDataFrame(data, schema)`, где `schema` — строка с именами столбцов через запятую или объект `StructType` с полным описанием типов.
- **Список Row (или аналог в Scala/Java):** `Row(name="Alice", age=30)` — схема может быть выведена из полей Row.

Если схему не задать явно при кортежах/списках, Spark попытается вывести её из данных; для надёжности и корректных типов (например, целое число, а не строка) лучше задавать схему явно. Создание из коллекции удобно для тестов, небольших справочников и для объединения с данными из файлов (например, broadcast-таблица для join). Большие коллекции не стоит передавать в `createDataFrame`: они проходят через драйвер и могут вызвать нехватку памяти. См. [§5.3](chapter-05-03.md), [§6.1](chapter-06-01.md).

## 3.2.3. Создание из RDD с заданной схемой

Если данные уже представлены как **RDD** (например, после чтения текстового файла и парсинга строк, или после сложной RDD-трансформации), из RDD можно получить DataFrame, задав **схему**. Такой способ нужен, когда источник не имеет встроенной схемы (сырой текст, нестандартный формат) или когда логика получения данных проще выразить через RDD (map, flatMap), а дальше хочется работать табличным API.

Два варианта:

1. **RDD из Row (или кортежей) + схема:** схема задаётся объектом `StructType` с перечислением полей и типов (`StructField("name", StringType())`, и т.д.). В PySpark: `spark.createDataFrame(rdd, schema)`. Элементы RDD должны соответствовать схеме (то же число полей, совместимые типы).
2. **RDD из структур с выводом схемы (например, Row с именами полей):** `spark.createDataFrame(rdd)` — схема выводится из первого элемента или из типа элементов. Подходит, когда RDD уже содержит типизированные объекты (Row, case class в Scala).

Пример цепочки: прочитать файл как RDD строк, в `map` разобрать каждую строку (split, парсинг), получить RDD кортежей или Row, затем `createDataFrame(rdd, schema)`. После этого можно применять DataFrame API и Spark SQL. См. [§2.2](chapter-02-02.md), [§6.1](chapter-06-01.md).

## 3.2.4. Явное задание схемы

Схему можно задать **явно** при любом способе создания, когда нужно зафиксировать типы и имена столбцов:

- При чтении: `spark.read.schema(schema).csv("path")` — данные интерпретируются по заданной схеме; вывод схемы из файла не выполняется, что ускоряет чтение и избегает неверного вывода типов.
- При `createDataFrame(rdd, schema)` или `createDataFrame(rows)` с передачей схемы — полный контроль над типами (IntegerType, LongType, StringType, TimestampType, DecimalType и т.д.).

В PySpark схема задаётся через `pyspark.sql.types`: `StructType([StructField("col1", StringType()), StructField("col2", IntegerType())])`. Явная схема полезна при неоднородных или «грязных» данных (например, числа в CSV в виде строк — задаём нужный тип и при необходимости приведение в запросе). См. [§6.3](chapter-06-03.md).

## 3.2.5. Проверка схемы и превью данных

После создания DataFrame полезно проверить схему и убедиться, что данные читаются корректно:

- **`df.printSchema()`** — выводит в консоль дерево схемы: имена столбцов и типы (и вложенные структуры, если есть).
- **`df.show(n, truncate=True)`** — выводит первые n строк (по умолчанию 20) в табличном виде; при truncate длинные строки обрезаются. Это **действие**: запускает выполнение до момента, когда получены n строк.
- **`df.take(n)`**, **`df.head(n)`** — вернуть первые n строк на драйвер (как список Row); для больших n осторожно с памятью драйвера.

Имена столбцов используются в `select`, `filter`, `groupBy` и в SQL-запросах; опечатка в имени приведёт к ошибке на этапе анализа плана или выполнения. См. [§3.3](chapter-03-03.md), [§5.3](chapter-05-03.md).

## Ключевое

- **Чтение из источников:** `spark.read.format(...).load(path)` или `spark.read.parquet/json/csv/jdbc(...)`; создаётся DataFrame с схемой из формата или из опции inferSchema; чтение ленивое. Детали — в §4.1 и §6.1.
- **Из коллекции:** `spark.createDataFrame(list_of_dicts)` или `createDataFrame(rdd, schema)`; схема выводится из данных или задаётся явно. Подходит для малых данных и тестов; большие коллекции через драйвер не передавать.
- **Из RDD:** `spark.createDataFrame(rdd, schema)` при RDD из кортежей/списков; при RDD из Row схема может выводиться. Удобно после парсинга текста или кастомных RDD-трансформаций.
- **Явная схема** задаётся через `StructType`/`StructField` (в PySpark — `pyspark.sql.types`); при чтении — `.schema(schema)`; при createDataFrame — вторым аргументом. Обеспечивает корректные типы и ускоряет чтение при отключении вывода схемы.
- После создания — `printSchema()` и `show(n)` для проверки схемы и превью данных.

В [§3.3](chapter-03-03.md) мы разберём Spark SQL: регистрацию DataFrame как временной таблицы и выполнение запросов через `spark.sql()`.
