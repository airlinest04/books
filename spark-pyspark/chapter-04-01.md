# §4.1 Чтение и запись

В [§3.4](chapter-03-04.md) мы разобрали каталог и метаданные: базы данных, таблицы, представления и интеграцию с Hive Metastore. Данные в каталоге ссылаются на файлы в хранилище; сами файлы читаются и записываются через единый API. В этом разделе рассмотрим **чтение и запись** данных в Spark: общий механизм (`spark.read` и `df.write`), **форматы** Parquet, ORC, JSON, CSV и **опции** сжатия и партиционирования. Пути к данным (HDFS, S3) и настройка доступа — в [§4.2](chapter-04-02.md); детали партиционирования при записи — в [§4.3](chapter-04-03.md); примеры в PySpark — в [§6.1](chapter-06-01.md) и [§6.4](chapter-06-04.md). См. [Глоссарий](glossary.md).

---

## 4.1.1. Чтение: spark.read

Чтение выполняется через **DataFrameReader**, доступный как **`spark.read`**. Общий вид:

```
spark.read.format("формат").option("ключ", "значение").load("путь")
```

Короткие методы для распространённых форматов:

- **`spark.read.parquet("path")`** — Parquet;
- **`spark.read.orc("path")`** — ORC;
- **`spark.read.json("path")`** — JSON (строки или файлы);
- **`spark.read.csv("path", header=True, inferSchema=True, sep=",")`** — CSV.

Путь может быть файлом или каталогом; для каталога Spark читает все подходящие файлы (по расширению или по формату). Путь задаётся строкой: локальный `file:///...`, **`hdfs://...`** или **`s3a://...`** (см. [§4.2](chapter-04-02.md)). Чтение **ленивое**: при вызове `load` создаётся DataFrame с логическим планом «читать из источника»; данные подгружаются при первом действии. Схема берётся из формата (Parquet, ORC хранят схему в данных), выводится из данных (JSON, CSV с `inferSchema=True`) или задаётся явно через `.schema(schema)`. См. [§3.2](chapter-03-02.md), [Глоссарий](glossary.md).

---

## 4.1.2. Запись: df.write

Запись выполняется через **DataFrameWriter**, доступный как **`df.write`**. Общий вид:

```
df.write.format("формат").option("ключ", "значение").mode("overwrite").save("путь")
```

Короткие методы:

- **`df.write.parquet("path")`** — запись в Parquet;
- **`df.write.orc("path")`** — в ORC;
- **`df.write.json("path")`** — в JSON;
- **`df.write.csv("path", header=True, sep=",")`** — в CSV.

**Режим записи (mode):** определяет поведение, если путь уже существует. Часто используемые: **`overwrite`** — перезаписать каталог; **`append`** — добавить данные (новые файлы в тот же каталог); **`error`** или **`errorifexists`** — ошибка при существующем пути (по умолчанию в части версий); **`ignore`** — не писать, если путь существует. Запись — **действие**: при вызове `save` выполняется весь граф от корня до этого DataFrame и данные записываются на исполнителях. Партиционирование по столбцам задаётся через **`.partitionBy("col1", "col2")`** перед `save`; структура каталога и влияние на чтение — в [§4.3](chapter-04-03.md). См. [Глоссарий](glossary.md).

## 4.1.3. Формат Parquet

**Parquet** — колоночный бинарный формат, широко используемый в экосистеме больших данных. Схема хранится в метаданных файла; данные сжаты по столбцам, что даёт хорошее сжатие и быструю выборку по отдельным столбцам. Spark читает и пишет Parquet нативно; при чтении схема подхватывается автоматически.

Типичные опции при записи: **`compression`** — алгоритм сжатия (`snappy`, `gzip`, `none` и др.; по умолчанию часто `snappy`). При чтении опции обычно не требуются; при необходимости можно задать схему явно или отключить вывод схемы. Для партиционированных данных путь указывает на корневой каталог; подкаталоги вида `col=value` интерпретируются как партиции (см. [§4.3](chapter-04-03.md)). Parquet — рекомендуемый формат по умолчанию для промежуточных и итоговых данных в пайплайнах Spark. См. [Глоссарий](glossary.md).

---

## 4.1.4. Формат ORC

**ORC (Optimized Row Columnar)** — колоночный формат с оптимизациями для чтения и сжатия; исторически тесно связан с Hive. Spark поддерживает чтение и запись ORC. Как и Parquet, ORC хранит схему и поддерживает сжатие (например, snappy, zlib). Выбор между Parquet и ORC часто зависит от стека: если кластер уже использует Hive с ORC, удобно сохранять совместимость; в остальных случаях Parquet распространён не меньше. Опции сжатия задаются при записи через `.option("compression", "snappy")` (или аналог для ORC). См. [Глоссарий](glossary.md).

---

## 4.1.5. Форматы JSON и CSV

**JSON:** каждый файл может содержать один JSON-объект, массив объектов или по одному объекту на строку (JSON Lines). При чтении схема выводится из данных, если не задана явно; опция **`inferSchema`** (или многострочный режим) влияет на вывод типов. Запись: по умолчанию один файл на партицию в виде строк JSON. JSON удобен для обмена и отладки, но обычно уступает Parquet по сжатию и скорости при больших объёмах.

**CSV:** текстовый формат с разделителями. При чтении важны опции: **`header`** — первая строка как имена столбцов; **`sep`** — разделитель (по умолчанию запятая); **`inferSchema`** — вывод типов из данных (иначе все столбцы строками); **`encoding`**, **`quote`** и др. При записи: **`header`** — выводить заголовок; **`sep`** — разделитель. CSV не хранит типы в файле; при повторном чтении схему лучше задавать явно или стабильно использовать inferSchema. См. [§6.1](chapter-06-01.md), [§6.4](chapter-06-04.md).

---

## 4.1.6. Сжатие

При записи можно задать **алгоритм сжатия** для уменьшения объёма данных. Опция обычно называется **`compression`** (или формат-специфичная, например для Parquet). Распространённые значения:

- **`snappy`** — быстрый, умеренная степень сжатия; часто по умолчанию в Parquet/ORC;
- **`gzip`** — лучшее сжатие, выше нагрузка на CPU;
- **`none`** — без сжатия.

Выбор зависит от соотношения «место на диске / пропускная способность» и нагрузки на CPU. При чтении сжатые данные распаковываются автоматически по метаданным формата. См. [Глоссарий](glossary.md).

---

## 4.1.7. Партиционирование при записи (кратко)

При записи DataFrame можно **разбить вывод по значениям столбцов** — **партиционирование по данным** (partition by column). Вызов **`df.write.partitionBy("col1", "col2").format(...).save("path")`** создаёт под каталогом `path` структуру вида `col1=value1/col2=value2/` с файлами внутри. Каждая комбинация значений партиционных столбцов даёт отдельный подкаталог; это ускоряет последующее чтение с фильтром по этим столбцам (партиционный pruning: читаются только нужные подкаталоги). Детали структуры, число файлов на партицию и влияние на чтение — в [§4.3](chapter-04-03.md); в PySpark — в [§6.4](chapter-06-04.md) и [§6.6](chapter-06-06.md). См. [Глоссарий](glossary.md).

## Ключевое

- **Чтение:** `spark.read.format(...).load(path)` или короткие методы parquet, orc, json, csv; путь — файл или каталог (локальный, hdfs://, s3a://); чтение ленивое; схема из формата, из вывода или задаётся явно.
- **Запись:** `df.write.format(...).mode(...).save(path)` или короткие методы; режимы overwrite, append, error, ignore; запись — действие, выполняется на исполнителях.
- **Форматы:** Parquet и ORC — колоночные, со схемой и сжатием; JSON и CSV — текстовые, схема при чтении часто через inferSchema; для больших данных предпочтителен Parquet (или ORC в Hive-стеках).
- **Сжатие:** опция compression при записи (snappy, gzip, none); при чтении распаковка по метаданным.
- **Партиционирование при записи:** `.partitionBy("col1", ...)` создаёт подкаталоги по значениям; удобно для последующей фильтрации; подробнее — в §4.3.

В [§4.2](chapter-04-02.md) мы разберём пути к данным: HDFS и объектные хранилища (S3 и совместимые), настройку доступа.
