# §3.3 Spark SQL

В [§3.2](chapter-03-02.md) мы разобрали создание DataFrame из источников, из коллекций и из RDD. Полученный DataFrame можно не только обрабатывать методами API (select, filter, join), но и представлять как **таблицу** для SQL-запросов. В этом разделе рассмотрим **Spark SQL**: регистрацию DataFrame как временной таблицы (или представления), выполнение запросов через **`spark.sql()`** и использование в запросах подзапросов и соединений. Один и тот же движок и оптимизатор Catalyst обрабатывают и API, и SQL; результат запроса — снова DataFrame. В [§3.4](chapter-03-04.md) перейдём к каталогу и метаданным: базы данных, таблицы, представления и интеграция с Hive Metastore. См. [Глоссарий](glossary.md).

## 3.3.1. Регистрация DataFrame как временной таблицы (представления)

Чтобы обращаться к DataFrame из SQL, его нужно **зарегистрировать** как именованную таблицу в каталоге Spark. Регистрация не копирует данные — она лишь даёт имя логическому плану (и схеме) этого DataFrame, чтобы на него можно было ссылаться в SQL.

- **`df.createOrReplaceTempView("имя_таблицы")`** — создаёт **временное представление** (view), видимое только в рамках текущей сессии Spark (текущего SparkSession). Запросы вида `SELECT ... FROM имя_таблицы` будут обращаться к данным этого DataFrame. Если представление с таким именем уже было, оно заменяется. Временные представления не сохраняются в каталоге между перезапусками приложения.
- **`df.createGlobalTempView("имя")`** — создаёт **глобальное временное** представление в базе `global_temp`; к нему можно обращаться как `global_temp.имя`. Удобно, когда несколько SparkSession в одном приложении должны видеть одну и ту же таблицу.

После регистрации таблица участвует в разрешении имён при разборе SQL: движок подставляет соответствующий логический план (ваш DataFrame) в место FROM. Схема таблицы совпадает со схемой DataFrame (имена и типы столбцов). См. [§3.4](chapter-03-04.md), [Глоссарий](glossary.md).

## 3.3.2. Выполнение запросов: spark.sql()

Запросы к зарегистрированным таблицам (и к таблицам из каталога Spark, если он настроен) выполняются через **`spark.sql("SQL-запрос")`**. Аргумент — строка с SQL-запросом в диалекте Spark SQL (подмножество стандартного SQL с расширениями). Возвращаемое значение — **DataFrame**: результат запроса можно сохранить в переменную, применить к нему методы API (filter, select, join с другим DataFrame) или снова зарегистрировать как представление для последующих запросов.

Пример логики (псевдокод):

```
df = spark.read.parquet("/path/to/data")
df.createOrReplaceTempView("events")
result = spark.sql("SELECT user_id, COUNT(*) AS cnt FROM events WHERE date >= '2024-01-01' GROUP BY user_id")
result.show()
```

Запрос разбирается, оптимизируется Catalyst и выполняется так же, как цепочка операций DataFrame API; разница только в способе задания (текст SQL вместо вызовов методов). Запрос **ленивый**: при вызове `spark.sql(...)` строится план; выполнение — при вызове действия над возвращённым DataFrame (show, count, write и т.д.). См. [Глоссарий](glossary.md).

## 3.3.3. Подзапросы и соединения в SQL

Spark SQL поддерживает **подзапросы** (вложенные SELECT в FROM, в WHERE, в качестве таблицы для JOIN) и **соединения** (JOIN) в стандартном синтаксисе SQL.

- **Подзапрос в FROM:** `SELECT ... FROM (SELECT ... FROM table1 WHERE ...) AS t WHERE ...` — внутренний запрос даёт производную таблицу с псевдонимом; Catalyst может объединять и оптимизировать такие запросы вместе с внешним.
- **Подзапрос в выражении (скалярный):** в допустимых контекстах можно использовать подзапрос, возвращающий одно значение (например, для сравнения в WHERE). Поддержка зависит от версии и контекста.
- **JOIN:** `SELECT ... FROM a JOIN b ON a.id = b.id` (INNER, LEFT, RIGHT, FULL OUTER, CROSS). Имена таблиц — зарегистрированные представления или таблицы из каталога. Условие соединения задаётся в ON или в WHERE; движок выбирает стратегию выполнения (sort-merge, broadcast hash join при подходящем размере).

Имена столбцов в SQL должны совпадать со схемой таблицы; при неоднозначности используется префикс имени таблицы или алиаса (`a.id`, `b.name`). Детали соединений в PySpark (в том числе broadcast join) — в [§7.3](chapter-07-03.md); здесь важно, что тот же функционал доступен и через SQL. См. [Глоссарий](glossary.md).

## 3.3.4. Комбинирование SQL и DataFrame API

Результат `spark.sql(...)` — DataFrame. Его можно:

- передать в следующий SQL-запрос, предварительно зарегистрировав: `result.createOrReplaceTempView("agg"); spark.sql("SELECT * FROM agg WHERE cnt > 10")`;
- обработать методами API: `result.filter(result["cnt"] > 10).select("user_id", "cnt")`;
- записать во внешнее хранилище: `result.write.parquet("...")` или в таблицу каталога.

Таким образом, в одном приложении удобно сочетать: загрузку и первичную обработку через API, сложные агрегации или соединения — через SQL (если команде так привычнее), а финальную запись или передачу в другой сервис — снова через API. Единая схема и единый оптимизатор гарантируют согласованность. См. [§3.1](chapter-03-01.md), [§6.1](chapter-06-01.md).

## 3.3.5. Синтаксис и функции Spark SQL

Spark SQL опирается на диалект, близкий к Hive SQL и к стандарту SQL: SELECT, FROM, WHERE, GROUP BY, HAVING, ORDER BY, JOIN, подзапросы, алиасы таблиц и столбцов (AS). Поддерживаются типичные агрегатные функции (COUNT, SUM, AVG, MIN, MAX), строковые (SUBSTR, CONCAT, UPPER, LOWER), математические, функции даты и времени (YEAR, MONTH, DATE_ADD и т.д.), а также оконные функции (ROW_NUMBER, RANK, SUM() OVER (...)). Полный список — в документации Spark SQL; в PySpark те же функции доступны и в API через `pyspark.sql.functions`. См. [§7.1](chapter-07-01.md), [§7.2](chapter-07-02.md).

Имена таблиц и столбцов при необходимости экранируются (например, обратные кавычки в Hive-стиле); регистр имён может зависеть от конфигурации (case sensitive / insensitive). Для переносимого кода лучше придерживаться единого стиля имён. См. [§3.4](chapter-03-04.md).

## Ключевое

- **Временное представление:** `df.createOrReplaceTempView("name")` регистрирует DataFrame как таблицу в текущей сессии; к ней можно обращаться в SQL как `FROM name`. Глобальное представление — `createGlobalTempView` в базе `global_temp`.
- **Выполнение запросов:** `spark.sql("SELECT ...")` принимает строку с SQL и возвращает **DataFrame**; выполнение ленивое (до действия). Один движок и Catalyst для SQL и API.
- **Подзапросы и JOIN** в стандартном виде поддерживаются; имена таблиц — зарегистрированные представления или таблицы каталога; стратегия join выбирается оптимизатором.
- SQL и API можно комбинировать: результат `spark.sql()` — DataFrame, его можно снова регистрировать, обрабатывать методами API или записывать.
- Синтаксис Spark SQL близок к Hive SQL и стандарту; агрегаты, строковые и оконные функции доступны и в SQL, и в `pyspark.sql.functions`.
