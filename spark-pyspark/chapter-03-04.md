# §3.4 Каталог и метаданные

В [§3.3](chapter-03-03.md) мы разобрали Spark SQL: регистрацию DataFrame как временного представления и выполнение запросов через `spark.sql()`. Временные представления живут только в сессии. Для постоянного хранения метаданных о таблицах и базах данных Spark предоставляет **каталог** (catalog) и при необходимости интеграцию с **Hive Metastore**. В этом разделе рассмотрим структуру каталога: базы данных, таблицы, представления — и как Spark работает с внешними таблицами (данные в HDFS или S3, метаданные в Hive). Детали чтения и записи файлов и партиционирования — в главе 4; здесь — организация метаданных и доступ к ним через API и SQL. См. [Глоссарий](glossary.md).

---

## 3.4.1. Каталог Spark (spark.catalog)

**Каталог** в Spark SQL — это реестр метаданных: список баз данных, таблиц, представлений и функций. Доступ к нему даёт объект **`spark.catalog`** (или `SparkSession.catalog`). Через него можно:

- перечислять базы данных: `spark.catalog.listDatabases()`;
- перечислять таблицы в базе: `spark.catalog.listTables("db_name")`;
- получать описание таблицы (схема, тип: таблица или представление): `spark.catalog.listColumns("table_name")`, с указанием базы при необходимости;
- кэшировать таблицу, снимать с кэша, проверять, закэширована ли таблица.

Каталог используется движком при разборе SQL: запрос `SELECT ... FROM db.table` разрешает имя через каталог — в какой базе искать таблицу, какая у неё схема, это таблица или представление. По умолчанию Spark использует **встроенный каталог в памяти**; при включении поддержки Hive каталог может быть связан с **Hive Metastore**, и тогда таблицы, созданные в Hive или зарегистрированные в Metastore, видны в Spark. См. [Глоссарий](glossary.md).

---

## 3.4.2. Базы данных и таблицы

В каталоге данные организованы иерархически: **база данных (database)** → **таблица (table)**. По умолчанию есть база **`default`**; в ней создаются временные представления (createOrReplaceTempView), если не указана другая база. Пользователь может создавать базы данных через SQL: `CREATE DATABASE IF NOT EXISTS my_db;` и переключать текущую базу: `USE my_db;` — тогда неквалифицированные имена таблиц будут искаться в этой базе.

**Таблица** в каталоге — это именованная сущность с метаданными (схема, тип таблицы, при необходимости путь к данным и формат). Различают:

- **Управляемые таблицы (managed tables):** данные и метаданные под контролем Spark (или Hive при использовании Metastore). При удалении таблицы (`DROP TABLE`) удаляются и данные в каталоге хранения.
- **Внешние таблицы (external tables):** метаданные в каталоге, а данные лежат во внешнем месте (каталог в HDFS, S3 и т.д.), заданном при создании. При `DROP TABLE` метаданные удаляются, но данные во внешнем пути остаются.

Создание таблиц через SQL: `CREATE TABLE ... USING parquet LOCATION 'path'` (внешняя по сути, если путь внешний), `CREATE TABLE ... AS SELECT ...` и т.д. Чтение такой таблицы в Spark: `spark.table("db_name.table_name")` или в SQL `SELECT ... FROM db_name.table_name`. Запись в таблицу — через `df.write.saveAsTable("db_name.table_name")` (управляемая) или запись в путь и при необходимости регистрация в каталоге. См. [§4.1](chapter-04-01.md), [§4.3](chapter-04-03.md).

## 3.4.3. Представления (views)

**Представление** — именованный запрос (SELECT); при обращении к нему выполняется сохранённый запрос, данные не копируются. В Spark различают:

- **Временное представление (temp view):** создаётся через `df.createOrReplaceTempView("name")`; видно только в текущей сессии; не сохраняется в каталоге между перезапусками. Метаданные хранятся во встроенном каталоге сессии.
- **Глобальное временное представление:** `createGlobalTempView("name")`; видно из любой сессии в приложении через `global_temp.name`.
- **Постоянное представление (persistent view):** создаётся через SQL `CREATE VIEW db.view_name AS SELECT ...` при использовании каталога с персистентным хранилищем (например, Hive Metastore). Метаданные представления сохраняются; при следующем запуске приложения представление снова доступно.

В каталоге представления отображаены как объекты с типом «view»; `spark.catalog.listTables()` показывает и таблицы, и представления. См. [§3.3](chapter-03-03.md), [Глоссарий](glossary.md).

## 3.4.4. Интеграция с Hive Metastore

**Hive Metastore** — сервис экосистемы Hadoop, хранящий метаданные таблиц и баз данных (схема, путь к данным, формат, партиции). Многие кластеры уже используют Hive или совместимые движки (например, Trino, Presto), и таблицы зарегистрированы в Metastore. Spark может подключаться к тому же Metastore и **видеть те же таблицы**: читать их по имени, записывать в них (или в новые таблицы в том же каталоге), создавать представления.

Для включения поддержки Hive в Spark задают конфигурацию: адрес Metastore (`spark.sql.hive.metastore.jars` или использование встроенных Hive-библиотек, `spark.sql.hive.metastore.uris` и т.д. в зависимости от версии). После этого `spark.catalog.listDatabases()` и `spark.table("db.table")` могут возвращать таблицы из Hive; запросы `SELECT ... FROM hive_db.hive_table` выполняются над данными по пути, указанному в Metastore (HDFS, S3 и т.д.). Формат данных (Parquet, ORC и др.) определяется метаданными таблицы. Таким образом, Spark выступает ещё одним движком поверх тех же данных и того же каталога, что и Hive или другие инструменты. См. [§4.2](chapter-04-02.md), [Глоссарий](glossary.md).

## 3.4.5. Встроенный каталог без Hive

Если Hive Metastore **не** настроен, Spark использует **встроенный каталог в памяти**. В нём хранятся только объекты, созданные в рамках текущей сессии: временные представления (createOrReplaceTempView, createGlobalTempView). Постоянных баз данных и таблиц между перезапусками нет. Это типичный режим для приложений, которые не используют Hive: данные читаются напрямую из путей (spark.read.parquet(...)), обрабатываются и записываются в пути (df.write.parquet(...)); именованные таблицы в каталоге используются только как временные представления для SQL внутри сессии. Для персистентного каталога (таблицы и базы, сохраняющиеся между запусками) нужен либо Hive Metastore, либо внешний каталог (например, Spark 3.x с поддержкой pluggable catalog). См. [§4.1](chapter-04-01.md).

---

## Ключевое

- **Каталог (spark.catalog)** — реестр метаданных: базы данных, таблицы, представления; доступ через listDatabases, listTables, listColumns и т.д.; используется при разборе SQL.
- **Базы данных и таблицы:** иерархия database → table; управляемые таблицы (данные под контролем Spark/Hive) и внешние таблицы (данные во внешнем пути); создание через SQL, чтение через spark.table(), запись через df.write.saveAsTable() или в путь.
- **Представления:** временные (createOrReplaceTempView, только сессия), глобальные временные (global_temp), постоянные (CREATE VIEW при каталоге с персистентным хранилищем).
- **Hive Metastore:** при подключении Spark видит таблицы и базы из Metastore; те же данные доступны для Hive и Spark; конфигурация через параметры Spark для адреса и библиотек Metastore.
- Без Hive каталог в памяти хранит только временные представления сессии; для постоянных таблиц между запусками нужен Metastore или внешний каталог.

В [§4.1](chapter-04-01.md) мы перейдём к главе 4: чтение и запись данных — форматы (Parquet, ORC, JSON, CSV), опции сжатия и партиционирования.
