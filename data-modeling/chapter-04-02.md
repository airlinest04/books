# §4.2 Типы индексов

В [§4.1](chapter-04-01.md) мы разобрали, зачем нужны индексы — ускорение поиска и сортировки при цене в виде замедления записи и расхода места. СУБД поддерживают **разные типы индексов**, каждый из которых оптимален для определённого класса запросов и типов данных. В этом разделе мы рассмотрим основные типы: **B-tree** (по умолчанию в большинстве СУБД), **hash**, **GiST** и **GIN** — в контексте PostgreSQL и общих представлений о реляционных СУБД; укажем, когда какой тип использовать. Составные индексы и порядок столбцов в них разбираются в [§4.3](chapter-04-03.md).

---

## 4.2.1. B-tree (дерево поиска)

**B-tree** (B-дерево) — сбалансированное дерево поиска; значения ключа упорядочены, что позволяет эффективно искать по равенству, по диапазону и использовать индекс для сортировки. В PostgreSQL и во многих других СУБД B-tree — **индекс по умолчанию**: при создании индекса без указания типа создаётся именно B-tree. См. [Глоссарий](glossary.md).

**Поддерживаемые операции:**

- Равенство: `col = value`
- Диапазон: `col < value`, `col > value`, `col BETWEEN a AND b`
- Сортировка: `ORDER BY col` (и по префиксу составного индекса)
- Префикс строки: `col LIKE 'prefix%'` (для строковых типов; суффикс `%suffix` по обычному B-tree не поддерживается)

**Когда использовать:** универсальный выбор для числовых, датовых, строковых столбцов при условиях сравнения и сортировке. Подходит для первичных и внешних ключей, для полей в WHERE и ORDER BY. Если нет специальных требований (только точное равенство без диапазонов — см. hash; полнотекст, массивы, JSON — см. GIN/GiST), B-tree — предпочтительный тип.

**Ограничения:** не подходит для полнотекстового поиска, поиска по containment в массивах/JSONB, сложных геометрических и специализированных операторов без соответствующих расширений.

---

## 4.2.2. Hash (хеш-индекс)

**Hash-индекс** хранит значения ключа в виде хеш-таблицы: по хешу значения быстро находится запись. Поддерживается **только поиск по равенству** (`col = value`); диапазоны и сортировка по такому индексу невозможны. См. [Глоссарий](glossary.md).

**Когда использовать:** когда запросы к столбцу — исключительно проверка на равенство (например, поиск по коду, по идентификатору) и не нужны диапазоны и ORDER BY по этому столбцу. В части СУБД hash может быть компактнее или быстрее B-tree для точечного поиска при очень больших таблицах; в PostgreSQL до версии 10 hash-индексы не были WAL-логируемыми и редко рекомендовались; в современных версиях они пригодны для сценариев «только равенство».

**Когда не использовать:** если возможны запросы с `<>`, `<`, `>`, BETWEEN, ORDER BY по этому столбцу — нужен B-tree. Для большинства приложений B-tree достаточно даже для равенства и даёт запас на диапазоны и сортировку; hash имеет смысл рассматривать при доказанной выгоде в узком сценарии.

---

## 4.2.3. GiST (Generalized Search Tree)

**GiST** (Generalized Search Tree) — обобщённое дерево поиска; тип индекса, позволяющий реализовать разные стратегии доступа под разные типы данных и операторы. В PostgreSQL GiST используется для геометрических типов (PostGIS), диапазонов (range), полнотекстового поиска (tsvector), а также для специализированных расширений. См. [Глоссарий](glossary.md).

**Типичные применения:**

- **Геометрия:** поиск пересечений, вхождений, ближайших объектов (операторы `&&`, `@>`, `<->` и др.).
- **Диапазоны (range):** пересечение и вложение диапазонов (`&&`, `@>`, `@>` и т.д.).
- **Полнотекстовый поиск:** поиск по лексемам (tsvector); альтернатива GIN с другими компромиссами (GiST меньше по размеру, но может быть медленнее при большом числе совпадений).

**Когда использовать:** когда данные и запросы требуют операторов, для которых B-tree не подходит — геометрия, диапазоны, полнотекст. Выбор между GiST и GIN для полнотекста зависит от соотношения объёма индекса и скорости запросов; GiST часто выбирают при ограничении по месту.

---

## 4.2.4. GIN (Generalized Inverted Index)

**GIN** (Generalized Inverted Index) — инвертированный индекс: для каждого значения (или элемента) ключа хранится список ссылок на строки, где это значение встречается. Подходит для структур, где **одна строка содержит много значений** (массив, документ, лексемы полнотекста). См. [Глоссарий](glossary.md).

**Типичные применения:**

- **Массивы:** оператор `@>` (содержит), `&&` (пересекается); запросы вида «найти строки, где массив содержит элемент X».
- **JSONB:** операторы `@>`, `?`, `?|`, `?&` (содержание ключей и структур); поиск по полям внутри JSON.
- **Полнотекстовый поиск (tsvector):** поиск по лексемам; GIN обычно быстрее GiST при большом числе документов и сложных запросах, но индекс больше.

**Когда использовать:** столбцы типа массив, JSONB, tsvector; запросы на «содержит», «есть такой элемент/ключ». Для обычных скалярных столбцов с равенством и диапазонами GIN не нужен — достаточно B-tree.

**Компромисс:** GIN-индексы обычно больше B-tree и могут медленнее обновляться (вставка/обновление строки затрагивает много записей в индексе при большом массиве или документе). Применять когда запросы реально используют containment/полнотекст.

---

## 4.2.5. Другие типы (BRIN, SP-GiST)

**BRIN** (Block Range INdex) — индекс по диапазонам значений в последовательных блоках таблицы. Хранит минимум и максимум (или сводку) по каждому диапазону блоков. Очень компактный; подходит для **естественно упорядоченных** данных (например, время вставки, дата события), когда строки с близкими значениями лежат рядом на диске. Поддерживает только сканирование диапазонов блоков; для случайного порядка данных мало полезен.

**SP-GiST** (Space-Partitioned GiST) — дерево с разбиением пространства ключей; используется для небалансированных структур (например, префиксные деревья, деревья квадрантов). Применяется реже; актуален для специализированных типов данных и операторов.

В повседневном моделировании чаще всего достаточно B-tree; при необходимости — hash для «только равенство», GIN для массивов и JSONB, GiST для геометрии и диапазонов.

---

## 4.2.6. Сводная таблица: тип индекса и применение

| Тип | Поддерживаемые операции | Типичное применение |
|-----|-------------------------|----------------------|
| **B-tree** | Равенство, диапазон, сортировка, LIKE 'prefix%' | Универсально: ключи, даты, числа, строки в WHERE и ORDER BY |
| **Hash** | Только равенство | Точечный поиск по коду/ID без диапазонов и сортировки |
| **GiST** | Зависит от типа (геометрия, range, полнотекст) | Геометрия, диапазоны, полнотекст (альтернатива GIN) |
| **GIN** | Содержание (массив, JSONB), полнотекст по лексемам | Массивы, JSONB, полнотекстовый поиск |
| **BRIN** | Диапазон по блокам | Крупные таблицы с естественным порядком (время, дата) |

Выбор типа делается по типу данных столбца и по операторам в запросах; при сомнении для скалярных столбцов используют B-tree.

---

## 4.2.7. Типичные ошибки при выборе типа индекса

- **Использовать hash там, где возможны диапазоны или ORDER BY:** hash не поддерживает эти операции; оптимизатор не сможет использовать индекс. Выбрать B-tree.
- **Индексировать JSONB/массив B-tree:** для условий «содержит ключ» или «содержит элемент» B-tree не подходит; нужен GIN (или GiST для части сценариев).
- **Создавать GIN для обычного столбца с = и <:** GIN предназначен для составных значений и операторов containment; для скаляров — B-tree.
- **Игнорировать ограничения СУБД:** не все СУБД поддерживают все типы индексов (например, в MySQL исторически только B-tree и hash для части движков). Свериться с документацией своей СУБД.

---

## Ключевое

- **B-tree** — индекс по умолчанию; поддерживает равенство, диапазон, сортировку, LIKE 'prefix%'. Универсальный выбор для скалярных столбцов (ключи, даты, числа, строки).
- **Hash** — только равенство; уместен при чистом точечном поиске без диапазонов и сортировки. Часто B-tree предпочтительнее из-за гибкости.
- **GiST** — обобщённое дерево для специализированных типов: геометрия, диапазоны (range), полнотекст. **GIN** — инвертированный индекс для массивов, JSONB, полнотекста; операции «содержит», поиск по элементам/ключам.
- Выбор типа — по типу данных и операторам в запросах. Для скаляров и обычных сравнений — B-tree; для массивов/JSONB/полнотекста — GIN (или GiST); для геометрии и range — GiST.
